Agents study plan · Day 2

What the model sees, and what it may do

Day 2 of the agents study path: what goes into every call (context engineering), the pieces modern harnesses add on top of the loop (skills, MCP, subagents and hooks), and what an agent should be allowed to do. It follows stations 3, 4 and 5 of the Agents field guide. Tick things off as you go; your progress stays in this browser.

By the end of all of this, you'll be able to
  • List what goes into each call, in order, and say why the order decides how much of it is cached.
  • Say what compaction keeps and what it throws away, and when a longer context lowers accuracy rather than only raising cost.
  • Tell a skill, an MCP tool, a subagent and a hook apart by what each one adds to the loop and what it costs.
  • State the lethal trifecta and remove one of its legs for a coding task.
  • Find where every part of your own Claude Code context comes from.
The same routine every phase
  1. Prime (5 min): read the phase's questions below its intro. Nothing else yet.
  2. Pretest: try the phase's checkpoint cold, without opening the answers.
  3. Read in order, with the questions in mind. The phase opens with a card from this hub; the readings after it open in new tabs.
  4. Take the checkpoint for real. For each miss, reopen only the source its answer points to.

  7. Checkpoint: contextFrom the Agents guide's closed-book check for station 3. Take a break after.

    1. A harness writes the current timestamp at the top of its system prompt. Trace what happens to cache reads and cost over a 14-call task, and say where the timestamp should go.

      Show the answer
      • Every call's prefix differs from the start of system onward, so only the tool definitions before it can still be read from cache
      • With automatic caching each call writes instead of reads: the trace task would cost about $0.615 instead of $0.164 (F05)
      • The symptom is cache_read_input_tokens near 0 on every call
      • Move volatile values into the last user message, after the cached prefix

      Missed it? Agents failure F05 · Prompt caching · Context Engineering for AI Agents: Lessons from Building Manus

    2. Manus restricts which tools the model may pick instead of adding and removing tool definitions mid-task. Give the cache reason and the model reason.

      Show the answer
      • Tool definitions sit at the very start of the prefix, so changing them invalidates the cache for everything after
      • Earlier turns refer to tools that would no longer be defined, which confuses the model about its own past calls
      • Masking keeps the definitions byte-identical and restricts the choice at decode time instead

      Missed it? Context Engineering for AI Agents: Lessons from Building Manus · Agents principle 6

    3. A long run nears the window. Clearing old tool results, summarizing older turns, or server-side compaction: which do you try first, and what does each cost?

      Show the answer
      • Clearing old tool results is the lightest, since the model rarely needs raw output again; each clear rewrites the cache from that point, so clear in large chunks
      • Summarizing keeps decisions and open bugs but can drop the detail the next step needs, so say what must survive (paths, failing test names, the next step)
      • Server-side compaction replaces everything it summarized with one block; images and documents in that range are gone, and a pending tool step must finish first
      • Measure each as its own row on the same long tasks: pass rate and total tokens

      Missed it? Agents failure F06 · Compaction on demand (and the compaction overview) · Effective context engineering for AI agents

  6. Checkpoint: extensionsFrom the Agents guide's closed-book check for station 4.

    1. Anthropic's code-execution-with-MCP example went from about 150,000 tokens to 2,000. Where did the tokens go before, and what changed?

      Show the answer
      • Before, every tool definition sat in context up front and every intermediate result passed through the model
      • After, tools are files the agent imports from code and loads only when needed, and intermediate data stays in the sandbox
      • It is the same pressure that let 566 MCP tools (about 208,000 tokens) overflow a 200k-token subagent (F17)

      Missed it? Code execution with MCP: building more efficient agents · Agents principle 15 · Agents failure F17

    2. A search subagent keeps the parent's context small. What does it cost, and under what condition does it pay for itself on your tasks?

      Show the answer
      • A second context with its own prefix and reads, so total tokens usually rise rather than fall
      • A new failure path: an empty or oversized report, or a child error that gets swallowed
      • It pays when the search would read many files (the course's signal is 10 or more, or independent pieces of work) and the parent can work from a short report
      • Measure it as a row: pass rate, total tokens, and how often the subagent was actually called

      Missed it? Create custom subagents · Agents failure F17 · The Context Course (Units 0-6)

    3. Test files must never be edited during a run. Why does an instruction in the system prompt not guarantee that, and what does a hook do differently?

      Show the answer
      • An instruction is text the model weighs against the rest of its context, so a long run or an injected file can override it
      • A PreToolUse hook is code the harness runs before every tool call, whatever the model decided
      • Exit 2 blocks the call, and an 'allow' decision in JSON can't override it; the reason goes back to the model
      • So rules that must hold go in hooks; instructions carry preferences

      Missed it? Hooks reference · Agents failure F04

  4. Checkpoint: safetyFrom the Agents guide's closed-book check for station 5. Take a break after.

    1. State the lethal trifecta, then remove one leg for your benchmark runner without breaking the tasks.

      Show the answer
      • Access to private data, exposure to untrusted content, and a way to send data out; with all three, an injection can exfiltrate
      • For the runner, --network none removes the way out while planted-bug tasks still run
      • Untrusted content (issue text, repo files) can't be removed from a coding task, so the other legs are the ones to cut

      Missed it? The lethal trifecta for AI agents: private data, untrusted content, and external communication · Agents failure F15

    2. An allowlist permits 'docker exec *'. Why does that permit everything, and where does the check have to live instead?

      Show the answer
      • A runner such as docker exec or npx passes any inner command through a prefix rule
      • The rule sees only the outer command; the real action is an argument
      • Enforce in the sandbox, by what the container can reach and write, rather than by matching the command string
