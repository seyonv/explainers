Test-suite reduction (greedy set cover, HumanEval+-mini)

EvalPlus's optional speed-up (section 2.2): greedy set covering over branch coverage, killed mutants and killed LLM samples shrinks HumanEval+'s 764.1 tests per task to 16.1 — 47× smaller — while keeping nearly the same pass@1★ drop.

Reduction assumes each test fulfils a set of testing requirements, and asks for the smallest subset of tests that still fulfils every requirement the full suite did. Written out, that is exactly the set covering problem, which the paper solves greedily: repeatedly take the test covering the most still-uncovered requirements.

reduce T to Tred such that  ∀r ∈ R ( ∃t ∈ T, t satisfies r  ⇒  ∃t′ ∈ Tred, t′ satisfies r )

Why it beats the alternatives

×Run the whole HumanEval+ suite

All ~764 tests per task, every time.

Correct but, in the paper's words, costly to execute — which is the reason reduction exists at all.

×Randomly sample N tests

Keep a fixed random fraction of the generated tests.

No guarantee any particular requirement survives; the one test that caught a given bug may simply not be drawn.

×Exact minimum set cover

Solve for the provably smallest covering subset.

NP-hard, and the paper cites Feige's ln n inapproximability threshold — the greedy algorithm is essentially the best practical option anyway.

✓Greedy set cover over merged requirements

One pass, always taking the test that adds the most uncovered branches, mutants and sample kills.

47× fewer tests with almost the same verdict, and by construction every requirement the full suite met is still met.

Is HumanEval+-mini just as good as HumanEval+?

Close, not identical — the paper says "similar", and the numbers show mini is slightly lenient: GPT-4 scores 78.0 on mini versus 76.2 on the full suite, ChatGPT 65.2 versus 63.4. StarCoder happens to match exactly at 29.3. If you want the strict number, run the full suite; mini is for when execution cost matters.

The preservation guarantee is also only as good as the requirements you chose. Nothing promises mini catches a bug that no branch, no seeded mutant and no other model's wrong sample ever exposed. And the sample-killing requirement is validated by leave-one-out cross validation over a subset of models, so a genuinely novel failure mode from a new model is outside what was tested.
