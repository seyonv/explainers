Type-aware input mutation (type-aware mutation, mutation-based fuzzing)

EvalPlus's scaling step: starting from about 30 ChatGPT-written seed inputs per task (produced with 3 separate prompts), per-type mutation rules generate 1,000 more inputs per task inside a one-hour budget.

Instead of inventing test inputs from nothing, the generator repeatedly picks an existing valid input and perturbs it using a rule chosen by the input's type — bump an int, drop a list element, splice a substring. Because the rule respects the type, the mutant is still a structurally legal input for the same function.

The loop (section 2.1)

1. Seed the pool
~30 ChatGPT inputs per task bootstrap the seed pool.
→
2. Pick and mutate
A random seed is selected and one type-appropriate rule is applied.
→
3. Check the contract
Mutants that satisfy the task's precondition go back into the pool; the rest are dropped.
↶

Step 3 feeds step 2, so later mutants are mutations of mutations. An "ingredient mechanism" also collects data fragments seen in valid inputs and reuses them during mutation, to avoid breaking subtle semantic constraints.

Why it beats the alternatives

×Classic black-box fuzzing (random bytes)

Feed random data to the function with no knowledge of its source or its types.

The paper calls this inapplicable for semantically meaningful inputs in a dynamically typed language — almost every input is rejected before it reaches real logic.

×Ask ChatGPT for every input

Keep querying the LLM until you have a thousand inputs per task.

The paper rules it out on "undesired speed and cost of querying such a large model" — 164 tasks × 1,000 inputs is far too many calls.

×Symbolic execution

Solve path constraints on the source to reach deep branches.

Strong on coverage, but the paper groups it with the traditional methods that cannot produce semantically meaningful inputs for arbitrary dynamically typed problems.

✓Type-aware mutation on LLM seeds

ChatGPT supplies semantically valid, structurally correct seeds; cheap local mutation multiplies them.

Gets the LLM's semantic understanding once per task, then scales to 1,000 inputs per task in an hour with no further model calls.

Does type-aware mean the mutants are always valid?

No. Type-awareness only guarantees the shape is legal — a list of ints stays a list of ints. Semantic requirements such as "the string must be a palindrome" or "n must be positive" can still be broken, which is exactly why every mutant is checked against the task's program contract before it is kept, and why the ingredient mechanism reuses fragments from inputs already known to be valid.

It is also not magic at finding bugs: mutation is random, with no coverage feedback loop described here, so it is bulk rather than targeted. Its job is quantity on top of ChatGPT's quality, not cleverness of its own.
