Leave-one-out cross validation (leave-one-model-out)

The guard on EvalPlus's third reduction requirement (section 2.2): the reduced test-suite used to score a model is built from the other models' sample-kill results only, never its own. Every pass@1★ in table 4 is produced this way, once per model.

Prime · 2 minutes before you read

The problem: The sample-killing requirement keeps tests that caught real wrong programs. If those wrong programs include the model you're about to score, the reduced suite is guaranteed to catch it, and "mini is as good as the full suite" becomes true by construction.

Where it fits: Test-suite reduction merged three requirements; this card guards the third. It is the same idea as holding out validation data, applied to models instead of examples.

One of the three testing requirements is empirical: keep the tests that actually caught wrong programs. But "wrong programs" have to come from somewhere, and if they come from the model you are about to score, the test-suite has been fitted to its mistakes. Leave-one-out removes that model from the pool before reducing, then scores it on the result — the same trick used to estimate generalisation in statistics.

for each model m:  Tred(m) = greedy_cover( kills from all models except m )  then score m on Tred(m)

Why the guard matters, by construction: if GPT-4's own kills were left in, every test that ever caught a GPT-4 mistake would be a requirement the cover must satisfy,
so its reduced score would be pinned near the full HumanEval+ value of 76.2 rather than the honestly-measured 78.0 — and the 1.8-point gap would vanish by definition, not by evidence.

That argument follows from how set cover works; the paper does not report the circular variant as a measured number.

Why it beats the alternatives

×Reduce using every model's kills, then score them all

One suite, built from the full pool including the model under test.

Circular: the suite is guaranteed to retain the tests that catch this model, so "mini is as effective as the full suite" becomes true by construction.

×Drop the sample-killing requirement entirely

Reduce on coverage and mutants alone, which involve no model outputs.

No circularity, but much weaker: GPT-4 scores 86.0 and 82.9 under those, against 78.7 for sample kills and 76.2 on the full suite.

×A single train/test split of models

Reduce on half the models, evaluate on the other half.

Fewer models feed each suite and each model is scored once against one arbitrary split, so the estimate is noisier. Not considered in the paper.

✓Leave-one-out

n reductions, each omitting one model, each scored on the model it never saw.

Keeps the maximum amount of evidence in every suite while still never letting a model's own failures select the tests that judge it.

Does leave-one-out prove mini will work on a new model?

It is the right check, but it is not a guarantee. The paper is explicit about the underlying situation: "for a new LLM under evaluation, we do not have any test execution results for its code samples". HumanEval+-mini is reduced once, from a fixed pool of models available in 2023, and then applied to whatever comes next. A model failing in a way none of those 19 ever exhibited may have nothing in mini to catch it.

Two further limits on the evidence: table 4 covers a subset of the 26 models in table 3, chosen for time and space, and the whole exercise is about the reduced suite. Full HumanEval+ needs none of this, since it does not consult model outputs at all when deciding which tests exist.

Understand and remember

  • Sample-kill requirements come from models' wrong outputs → including the scored model forces every test that caught it to survive → its reduced score matches the full suite by construction → the validation proves nothing
  • Exclude the scored model's kills → reduce with the others' only → score it on a suite fitted to other models' mistakes → a gap from the full suite (GPT-4 78.0 vs 76.2) is honest evidence of what mini misses
  • Each model gets its own reduced suite built from all the others → every suite keeps as much evidence as possible → but the cost is one reduction per model (19)
  • A released mini is reduced once from a fixed 2023 pool → a new model's unique failure modes may have no catching test → leave-one-out estimates this risk but can't remove it
  • detail that matters Coverage and mutant requirements never look at model outputs → they need no guard → which is also why they give model-independent guarantees for failure modes no model has shown

Reference only

  • the 19 models in table 4 vs 26 in table 3
  • the four-model illustration grid
  • the paper's quote about new LLMs having no execution results

5 · Predict commit to an answer before revealing

Toy pool: tests t1–t4 and three models, each with one wrong sample. A's is caught only by t4, B's by t1 and t2, C's by t2 and t3. Commit: with leave-one-out, what reduced suite scores A, and does it catch A's wrong sample? What would the circular version keep?

Reveal

Leave-one-out for A uses B's and C's kills: t2 covers both, so the suite is {t2}, and A's wrong sample passes it: A is over-credited on mini. The circular version must also cover A's sample, so it keeps {t2, t4} and catches it. Leave-one-out exposes that mini would miss A's unique failure; the circular version hides it.

Extend the toy: add model D whose wrong sample is caught by t3 and t4. Redo leave-one-out for each of A, B, C and D (greedy, ties broken toward the lower test number). For each model, list its reduced suite and whether it catches that model's wrong sample. Count how many of the four models mini would over-credit.

Done when: A: the others' samples are B (t1, t2), C (t2, t3), D (t3, t4); greedy takes t2 (B, C) then t3 (D) → {t2, t3}, which misses A (t4 only). B: t3 and t4 tie at 2; t3 (C, D), then t4 (A) → {t3, t4}, misses B. C: t4 (A, D), then t1 (B) → {t1, t4}, misses C. D: t2 (B, C), then t4 (A) → {t2, t4}, catches D. Three of four models are over-credited: with so few models, each one's failure is often unique, which is why the paper's pool of 19 matters.
