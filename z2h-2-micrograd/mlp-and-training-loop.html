From neuron to MLP to a training loop

Also called: a multi-layer perceptron, a fully connected net, gradient descent. Lecture 1 · building out a neural net library (multi-layer perceptron) in micrograd · 1:43:55, through training the network · 2:01:12

Prime · 2 minutes before you read

The problem: You can now get exact gradients for any expression, but an expression that just sits there learns nothing. To make a net fit data you need a way to build many neurons at once, one number that says how wrong they are, and a repeatable step that makes that number smaller.

Where it fits: This is the payoff of the whole lecture. The single neuron and the automatic backward() from earlier cards become the building blocks; the one manual nudge from the one-step card becomes a loop that runs itself.

In one breath: stack tanh neurons into layers and layers into an MLP, and you get one big expression of Values. Add a loss (one number saying how wrong the four predictions are) and repeat four moves: forward, reset the gradients to zero, backward, nudge every parameter a little against its gradient. The loss falls from 6.0054 to 0.0178 in 20 steps.

Predict first: you delete the line that resets every p.grad to 0 before loss.backward(). Same seed, same 20 steps. Does the final loss end higher or lower than the correct loop's 0.0178?

Lower: 0.000000 at step 19. That's the trap. Gradients add up with +=, so without the reset each step pushes with the sum of every gradient so far, which works like a growing step size. This 4-example problem is easy enough to survive it, so the bug hides. The "Forgetting zero_grad" section below shows where it bites.

Neuron → Layer → MLP

A Neuron holds a list of weights w (one per input) and a bias b, all random in [−1, 1]. Calling it on an input list x computes tanh(w·x + b). A Layer is a list of independent neurons that all see the same input. An MLP (multi-layer perceptron) feeds each layer's outputs into the next. The parameters are every weight and bias: the numbers training is allowed to change.

parameters = (3*4 + 4) + (4*4 + 4) + (4*1 + 1) = 16 + 20 + 5 = 41 n.parameters() returns all 41 Value objects in one flat list

▶ Build itruns on your M3 · under 1 s

When: pause the video at 1:43:55 and write the three classes; pause again at 2:01:12 and write the loop. Import your Value (with tanh, __radd__ and backward()) from the earlier cards.

import random
class Neuron:
    def __init__(self, nin):
        self.w = [Value(random.uniform(-1,1)) for _ in range(nin)]
        self.b = Value(random.uniform(-1,1))
    def __call__(self, x):   # tanh(w . x + b)
        act = sum((wi*xi for wi, xi in zip(self.w, x)), self.b)
        return act.tanh()
    def parameters(self):
        return self.w + [self.b]
class Layer:
    def __init__(self, nin, nout):
        self.neurons = [Neuron(nin) for _ in range(nout)]
    def __call__(self, x):
        outs = [n(x) for n in self.neurons]
        return outs[0] if len(outs) == 1 else outs
    def parameters(self):
        return [p for n in self.neurons for p in n.parameters()]

class MLP:
    def __init__(self, nin, nouts):   # MLP(3, [4, 4, 1])
        sz = [nin] + nouts
        self.layers = [Layer(sz[i], sz[i+1]) for i in range(len(nouts))]
    def __call__(self, x):
        for layer in self.layers:
            x = layer(x)                  # each layer feeds the next
        return x
    def parameters(self):
        return [p for l in self.layers for p in l.parameters()]
random.seed(1337); n = MLP(3, [4, 4, 1])     # xs, ys as above
for k in range(20):
    ypred = [n(x) for x in xs]                          # forward
    loss = sum((yout - ygt)**2 for ygt, yout in zip(ys, ypred))
    for p in n.parameters():
        p.grad = 0.0                                       # zero_grad
    loss.backward()                                        # backward
    for p in n.parameters():
        p.data += -0.1 * p.grad                            # update
    print(k, loss.data)

Forgetting zero_grad

Every _backward adds into .grad (the += fix from the accumulate-gradients card). That's right within one backward pass. Across steps it's wrong: without the reset, step k's gradient is the sum of every step's gradient so far. Karpathy made exactly this mistake on camera at 2:10:28.

Losses at steps 2, 5, 10, 19 from the lab. Steps 6, 7, 11 and the last column are computed by re-running the same seeded loop and comparing the length (square root of the sum of squares over all 41 grads) of the piled-up gradient with that step's fresh one. Near a perfect fit the fresh gradient is tiny but the stale sum still pushes hard, so the loss jumps 560-fold at step 7 (0.000311 → 0.174190) and to 3.783671 at step 11. The final 0.000000 is every output saturated at exactly ±1 (computed: [1.0, −1.0, −1.0, 1.0]). Right answers, but the gradient is exactly 0, so this net can no longer learn anything.

Why the loop is written this way

✗ Stepping by hand

In the video Karpathy first runs forward, backward and update one cell at a time and reads the loss each time. It works, but it's the loop typed out by hand: fine for five steps, hopeless for thousands.

✗ Skipping the reset

Gradients pile up across steps. Here it happens to reach a lower loss, but it's a hidden, ever-growing step size that throws the net off (steps 7 and 11 above) and ends in saturated tanhs with zero gradient. Karpathy: it only "worked" because the problem is so easy.

✗ A step size that's too small

Same seed, lr 0.01 instead of 0.1: the loss is still 2.5453 after 20 steps (computed). Too large is also bad, as the Apply exercise below shows.

✓ Forward → zero_grad → backward → update

Each step gets a fresh, exact gradient for all 41 parameters and moves each one a small, fixed fraction against it. Every training loop in the rest of the series has this same shape.

Is this how real nets train?

The shape, yes; the details, no. Karpathy's summary at 2:14:03: GPT-style models run this same loop, but with billions of parameters, cross-entropy loss instead of squared error, and a fancier update than plain "subtract lr × grad". They also compute the loss on a random minibatch of examples, not the whole dataset.

micrograd's own nn.py differs from the video's version: it uses ReLU, starts biases at 0, leaves the last layer linear, and puts zero_grad() on a Module base class, the way PyTorch's nn.Module does. And one Python object per number is far too slow for real work: z2h-3 moves to tensors.

Understand and remember

  • Neuron = tanh(w·x + b) → a Layer is independent neurons sharing one input → an MLP chains layers → the whole net is one big Value expression → one loss.backward() reaches all 41 parameters
  • Loss = sum of squared misses → one number that is 0 only when every prediction hits its target → its gradient with respect to each parameter says which way that knob raises the loss → stepping by -lr × grad lowers it
  • _backward adds into .grad (needed for reused nodes) → without a reset, step k uses the sum of all earlier gradients → an ever-growing, stale step size → loss can jump (0.000311 → 0.174190 at step 7) or diverge; on this easy problem it hides
  • lr sets the step length → too small crawls (lr 0.01: 2.5453 after 20 steps) → too big overshoots and can saturate tanh (lr 0.5: stuck at 3.9999) → you pick it by watching the loss
  • detail that matters tanh on the output neuron too → predictions are trapped in (−1, 1) → fine here because the targets are ±1, but a saturated output has almost no gradient, which is how lr 0.5 gets stuck

Reference only

  • random.uniform(-1, 1) init and random.seed(1337) (the lab's seed, taken from micrograd's demo.ipynb)
  • sum(..., self.b) uses the bias as the start value of the sum
  • Layer returns outs[0] when it has a single neuron
  • micrograd's nn.py: ReLU, bias 0, linear last layer, Module.zero_grad()
  • the exact printed digits (they can vary in the last place)
