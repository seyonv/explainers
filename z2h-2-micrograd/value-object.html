The Value object: numbers that remember

Also called: a node in the computation graph, an autograd scalar. Lecture 1 · starting the core Value object of micrograd and its visualization · 0:19:09

In one breath: a Value wraps one number. When you combine two Values with + or *, the result records which Values it came from and which operation made it. After you compute an expression, you're left holding a graph of the whole computation, which is exactly what backpropagation needs to walk backwards.

Predict first: after running L = (a*b + c) * f, how many Value objects exist, and how many of them have an empty _prev?

Seven Values, four with an empty _prev. You typed four (a, b, c, f), which are the leaves. Every * or + made one new Value (e, d, L), and each of those remembers its two parents.

The graph one line of arithmetic builds

e = a*b → a.__mul__(b) → Value( 2.0 × −3.0 = −6.0, _prev={a, b}, _op='*') d = e + c → e.__add__(c) → Value(−6.0 + 10.0 = 4.0, _prev={e, c}, _op='+') L = d * f → d.__mul__(f) → Value( 4.0 × −2.0 = −8.0, _prev={d, f}, _op='*')

Python turns a*b into the method call a.__mul__(b). That hook is where each result gets to write down its parents.

class Value:
    def __init__(self, data, _children=(), _op='', label=''):
        self.data = data
        self.grad = 0.0            # filled in by backprop later
        self._prev = set(_children)
        self._op = _op
        self.label = label
    def __repr__(self):
        return f"Value(data={self.data})"
    def __add__(self, other):
        return Value(self.data + other.data, (self, other), '+')
    def __mul__(self, other):
        return Value(self.data * other.data, (self, other), '*')
a = Value(2.0, label='a'); b = Value(-3.0, label='b')
c = Value(10.0, label='c'); f = Value(-2.0, label='f')
e = a*b; e.label = 'e'
d = e + c; d.label = 'd'
L = d * f; L.label = 'L'
print(L, L._op, sorted(p.label for p in L._prev))

How it differs from related ideas

✗ A plain float

L = (2.0*-3.0 + 10.0) * -2.0 gives −8.0 and forgets how it got there, so there is nothing to walk back through for gradients.

✗ Nudging every input

Numerical derivatives need one extra forward pass per input. The small net at the end of this lecture has 41 parameters, so that's 41 passes; GPT-2 would need 124 million.

✗ Symbolic math (e.g. SymPy)

Builds a formula for each derivative. Exact, but the formulas balloon for deep nets, and training only needs the gradient's value at the current numbers.

✓ A recorded graph of Values

One forward pass records the graph. One backward pass then fills in every grad at once. This is reverse-mode automatic differentiation.

Is this how PyTorch does it?

In spirit, yes. A PyTorch tensor with requires_grad=True also records the operation that produced it (its grad_fn) and links back to its inputs, and .backward() walks that graph. The difference is granularity. micrograd has one Python object per number, which is perfect for learning and hopeless for speed. PyTorch has one node per whole tensor operation, run in C++/CUDA. Karpathy notes the math is identical; everything else is efficiency.

A scalar graph is not what you'd use to train a real network. You'd switch to tensors, which is exactly what z2h-3 does next.
