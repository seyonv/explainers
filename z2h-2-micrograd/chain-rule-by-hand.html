Backprop by hand with the chain rule

Also called: manual backpropagation, reverse-mode differentiation by hand. Lecture 1 · manual backpropagation example #1: simple expression · 0:32:10

Prime · 2 minutes before you read

The problem: You have a recorded graph and L = −8, but every grad is still 0. Without a rule for passing sensitivity backwards, the only way to get gradients is to nudge each input and re-run the whole expression.

Where it fits: Builds on the Value graph from the last card and the partial-derivative nudges before it. Here you fill every grad by hand; the next cards take one step with those grads and then automate the walk.

  2. Why does the × node hand each input the other input's value, while the + node hands both the same number?
  3. Why must e.grad be known before you can compute a.grad or b.grad?

  5. What in this walk would break if c fed into two different operations instead of one?

In one breath: start at the output L with L.grad = 1 and walk the graph backwards. Each node's gradient is the gradient of the node it feeds, times one small local derivative of that single operation. For + the local derivative is 1, so plus copies the gradient to both inputs. For × it is the other input, so times swaps the inputs' values in.

Predict first: in L = d * f with d = 4.0 and f = −2.0, which of the two gets .grad = 4.0: d or f?

f gets 4.0, and d gets −2.0. Nudging f by a little moves L by d times that nudge, so dL/df = d = 4. Each input of a multiply is scaled by the other input's value. That swap is the whole trick of the × node.

The walk back, one node at a time

Karpathy's expression from the last card: a = 2, b = −3, c = 10, f = −2, with e = a·b = −6, d = e + c = 4 and L = d·f = −8. A node's grad means dL/d(node): how much L moves per unit nudge of that node.

Every step uses the same rule, the chain rule: to get from a node to L, multiply the node's local derivative by the gradient already found one step closer to L.

The Wikipedia chain rule page Karpathy shows puts it as speeds: a car 2× as fast as a bicycle, a bicycle 4× as fast as a walker, so the car is 2 × 4 = 8× as fast as the walker. Rates multiply along a chain.

Why is the local derivative of a·b with respect to a just b? Nudge a by h and see how far the product moves (the limit definition from the first card):

((a + h)·b − a·b) / h = (a·b + h·b − a·b) / h = h·b / h = b with a = 2, b = −3, h = 0.001: ((2.001)(−3) − (−6)) / 0.001 = −3.0000000000001137 ≈ b

L.grad = 1.0
d.grad = f.data * L.grad   # L = d*f: times swaps

Then check one gradient numerically, like Karpathy's lol(): rebuild the expression with b bumped by h and measure how far L moves.

def build(db=0.0):
    a = Value(2.0); b = Value(-3.0)
    b.data += db              # bump only b
    c = Value(10.0); f = Value(-2.0)
    return (a*b + c) * f

def lol(h=0.001):
    L1 = build().data
    L2 = build(db=h).data
    print((L2 - L1)/h)        # should be close to b.grad

lol()

Why it beats the alternatives

✗ Nudge every input

Run lol() once per node: six extra forward passes here, one per parameter in a real net, and every answer is approximate (6.000000000000227, not 6).

✗ Expand into one formula

L = (a·b + c)·f = a·b·f + c·f, so dL/da = b·f = 6. Fine for four leaves; for a deep net the expanded formula explodes, and you'd differentiate it once per input.

✗ Chain rule, but forwards

Start at one input and push its derivative forward to L. Exact, but one sweep gives the gradient for only that one input, so you'd repeat it for every input.

✓ Chain rule, backwards

One sweep from L fills in every grad exactly. Each node's grad is computed once and reused: e.grad = −2 serves both a and b.

Does plus always copy and times always swap?

Those two rules are the local derivatives of + and × only. Every other operation brings its own local derivative (tanh brings 1 − tanh², on the neuron card), but the chain-rule step around it stays the same: local derivative × grad from above.

The walk also assumed each node feeds exactly one place. If a node is used twice, say b = a + a, its gradients from both uses must be added, not overwritten; that is the += bug card. And you would never do this by hand for a real net: the next cards store each rule in a _backward function and let backward() do the walk. Keep the numerical check only as a test, since it's slow and approximate.

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • L depends on c only through d → a nudge of c moves d by (dd/dc)·nudge → which moves L by (dL/dd) times that → so dL/dc = dL/dd · dd/dc: one multiplication per step
  • + has local derivative 1 for both inputs → each input gets the output's grad unchanged → plus copies the gradient (c.grad = e.grad = −2)
  • × has local derivative equal to the other input (limit: ((a+h)·b − a·b)/h = b) → each input gets (other input's data) × out.grad → times swaps (a gets −3·−2 = 6, b gets 2·−2 = −4)
  • Each step needs the grad of the node one step closer to L → so the walk must run from L backwards → each grad is computed once and reused by everything below it, which is why one backward sweep gives all gradients
  • detail that matters The numerical check lol() rebuilds the whole expression per bumped node → cost grows with the number of nodes and answers carry rounding error (−3.9999999999995595) → use it to test backprop, never to replace it

Reference only

  • the lol() helper name and h = 0.001
  • writing each .grad assignment manually (replaced by _backward next)
  • the car/bicycle speed analogy for the chain rule

5 · Predict commit to an answer before revealing

Change the expression to L = (a*b + c) * a, reusing a in place of f (a = 2, b = −3, c = 10). Walking back, a now receives a gradient along two paths. What is each path's contribution, and what is the true dL/da?

Reveal

L = (a·b + c)·a = 4 · 2 = 8. Path through the final ×: a gets d = a·b + c = 4. Path through e: d.grad = a = 2, e.grad = 2, and a gets b · 2 = −6. The true gradient is the sum: 4 + (−6) = −2 (check: L = a²b + ca, so dL/da = 2ab + c = −12 + 10 = −2). Writing a.grad = twice would keep only one path; that's the += bug card.
