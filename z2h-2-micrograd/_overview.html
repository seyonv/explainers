In one breath: wrap every number in a Value that remembers how it was made, so a neural net's arithmetic becomes a graph ending in one loss number. Walk that graph backwards with the chain rule to get the gradient of the loss for every weight, step each weight a little against its gradient, and repeat. Everything else in the lecture is making that walk automatic and correct.

p.grad = sum over the paths from p to L of (product of local derivatives) the chain rule multiplies along a path; += adds the paths one real update: w = 0.2355, w.grad = −0.4537 w ← 0.2355 − 0.1 × (−0.4537) = 0.2809

The minus sign is the whole of "learning": the gradient points toward more loss, so each step goes the other way. The first half of the lecture is how to get ∂L/∂p; the last part is this line in a loop. Update from the training-loop card (layer 0, neuron 0, w[0]).

Open each step in order · why this works
1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • A slope is a nudge ratio → estimating it per input costs one extra forward pass each and is approximate → record the forward pass as a graph of Values instead → the chain rule walked back from L.grad = 1 gives every gradient exactly in one pass
  • Each op knows only its local derivative (+ → 1, × → the other input, tanh → 1 − o²) → store it as a _backward closure → reverse topological order guarantees a node's grad is complete before it is passed on → one backward() call works for any graph
  • A node reached by several paths needs the sum of their gradients → closures use += onto grads that start at 0 → grads never reset themselves → the loop must zero_grad before every backward, or stale gradients act like a growing step size
  • The gradient points toward more loss → step every parameter by −lr × grad → forward, zero_grad, backward, update, repeated → loss 6.0054 → 0.0178 in 20 steps with lr 0.1 on MLP(3, [4, 4, 1])
  • detail that matters One Python object per scalar → every step is visible and PyTorch still agrees to 6 decimals → but the per-node overhead makes it hopeless beyond toy nets → the same math moves to tensors next

Reference only

  • the chapter timestamps and the card-by-card numbers (L = −8, o = 0.7071)
  • the lever values in the table (h = 0.001, b = 6.8813735870195432, seed 1337)
  • Python hooks: __add__, __rmul__, __pow__, build_topo
  • PyTorch spellings: .double(), requires_grad, .item()

3 · Retrieve from memory, card closed
  1. concept Explain to a programmer who has never trained a net why the whole lecture reduces to the single line p.data += -lr * p.grad, and what the other two hours are for.
    Check
    • the line is gradient descent: step each parameter against the direction that increases the loss
    • everything before it exists to compute p.grad = ∂L/∂p for every parameter
    • exactly and in one backward pass: Value graph, chain rule, closures, topological order, +=
    • the MLP and loss only turn a question (fit these 4 targets) into one number L to differentiate
  2. mechanism Walk through one iteration of the training loop on MLP(3, [4, 4, 1]) and say, at each step, which card's machinery runs and what state changes.
    Check
    • forward: the MLP's Neuron/Layer calls build a fresh graph of Values ending in L (value-object, a-neuron, mlp)
    • zero_grad: all 41 p.grad set to 0, clearing the last step's sums
    • backward: L.grad = 1, reverse topological order, each _backward adds local derivative × out.grad (automatic-backward, accumulate-gradients)
    • update: each p.data moves by −0.1 × p.grad; only parameters change, never the data xs
  3. tradeoff Across the levers table, a wrong =, a missing zero_grad and a too-small h all give numbers without crashing. Rank them by how hard they are to notice, and say which check catches each.
    Check
    • h too small: visibly wrong only if you compare with the exact rule (10.66 vs 14); keep h near 0.001
    • = instead of +=: forward values are all correct and the error depends on graph shape; a numerical gradient check or PyTorch comparison catches it
    • missing zero_grad: the hardest, because on an easy problem the loss can even end lower (0.000000); watch for jumps (3.78 at step 11) or compare with and without the reset
    • general lesson: check gradients against an independent source, not against "it trains"
  4. concept Why can you split tanh into exp, −, +, ÷ and get the same gradients, and what do you pay for doing so?
    Check
    • the chain rule multiplies local derivatives along the path, and the product over the pieces equals tanh's own slope 1 − o² = 0.5
    • node e feeds two branches, so += is needed for the pieces to add up correctly
    • the cost is bookkeeping: 18 nodes instead of 10 to store and walk
    • a single op with a hand-written backward is shorter and faster, which is why PyTorch ships one

4 · Compare against what you already know

vs The six big ideas of the toolkit: The toolkit's first big idea says slopes multiply along a chain and add across paths. This course builds an engine around that one sentence. Which parts of micrograd implement the multiply half and which the add half, and what would break if either were missing?

Check
  • multiply: each _backward does local derivative × out.grad, applied in reverse topological order
  • add: += onto grads that start at 0, for nodes reached by several paths
  • without multiply there is no backprop at all; without add, reused nodes get one share (b = a + a gives 1, not 2)
  • the toolkit states the math on paper; micrograd makes it run for any graph without you choosing the order

vs The six big ideas of micrograd: The big-ideas card states six claims; this overview gives one formula and a loop. Which claims does the formula p ← p − lr · ∂L/∂p already contain, and which ones only show up in the loop or the levers table?

Check
  • contained: a net is an expression ending in L (the loss), the derivative as sensitivity (∂L/∂p), backprop computes it
  • only in the loop: zero_grad, and why accumulated grads make it necessary
  • only in the levers and checks: that micrograd and PyTorch agree, that = vs += matters

Why this step?

5 · Predict commit to an answer before revealing

The next lecture trains on 228,146 character pairs with 27 × 27 = 729 weights. If you built each example's 27 logits as micrograd dot products (27 multiplies and 27 adds per logit), roughly how many Value objects would a single forward pass over the data create, and what does that tell you the next course must change?

Reveal

27 logits × (27 + 27) = 1,458 multiply/add nodes per example, before the softmax and loss. Times 228,146 examples = 332,636,868, about 3.3 × 10⁸ Python objects for one forward pass. That is why z2h-3 moves to tensors: one graph node per whole matrix operation, with the same gradients (this course's PyTorch check already showed the math doesn't change).
