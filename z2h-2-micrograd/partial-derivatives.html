Partial derivatives: one knob at a time

Also called: partials, ∂d/∂a ("the partial of d with respect to a"), the components of the gradient. Lecture 1 · derivative of a function with multiple inputs · 0:14:12

Prime · 2 minutes before you read

The problem: Real expressions have many inputs. "The slope" stops making sense when three numbers feed one output: you need to know how the output responds to each input on its own, or you can't tell which knob to turn, or which way.

Where it fits: The previous card measured a slope for a function of one input. This card does the same nudge for d = a·b + c, one input at a time. The next card records that expression as a graph so the slopes can later be computed automatically.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. Bumping a moves d at −3 per unit, although a itself is +2. Where does the −3 come from?
  2. c = 10 is the largest input but gets the smallest slope. What sets the size of a partial, if not the input's own value?
  3. Bump a, b and c together and d barely moves. Why do three real effects vanish?
  4. If b changed from −3 to 5, which of the three partials would change, and which would stay put?

In one breath: when an output depends on several inputs, nudge one input while holding the rest still, and measure the output's rise over run as before. That number is the partial derivative for that input. Do it for every input and you get one slope per knob: together they're the gradient.

Predict first: d = a·b + c with a = 2, b = −3, c = 10, so d = 4. You nudge a up by 0.0001. Does d go up or down, and at what rate?

Down, at −3 per unit: d becomes 3.9997. The input a is positive, but that doesn't matter: a is multiplied by b = −3, so every bit you add to a adds −3 times that bit to d. The rate for a is set by the other input.

Three knobs, one output

The rule behind the numbers

d=a·b+c ∂d∂a=b= −3 ∂d∂b=a= 2 ∂d∂c=1= 1
∂"partial": a derivative taken while every other input is frozenread "del" or "partial" ∂d/∂ahow much d moves per unit nudge of a, with b and c held still−3 hthe size of the nudge0.0001 (−3, 2, 1)all three partials together: the gradient of d
nudge a by h: (a+h)·b + c = a·b + c + b·h → d moves by b·h, rate b nudge b by h: a·(b+h) + c = a·b + c + a·h → d moves by a·h, rate a nudge c by h: a·b + (c+h) = a·b + c + 1·h → d moves by h, rate 1

Freeze the others and a·b is just "a times a constant", so its slope is that constant. That's the whole trick: in a product, each input's slope is the other input; a sum passes a nudge through unchanged.

▶ Build itruns on your M3 · under 1 s

When: pause the video at 0:14:12 and type this before watching on. Karpathy's cell bumps only c; this loop does all three.

h = 0.0001
for knob in ['a', 'b', 'c']:
    a, b, c = 2.0, -3.0, 10.0          # reset every knob first
    d1 = a*b + c
    if knob == 'a': a += h
    if knob == 'b': b += h
    if knob == 'c': c += h
    d2 = a*b + c
    print(f'bump {knob}:  d1 {d1}  d2 {d2}  slope {(d2 - d1)/h}')

Ways to ask "which input matters?"

✗ Bump all three at once

d goes from 4 to 4.00000001, a ratio of about 0.0001. The −3, +2 and +1 cancel, so it looks as if nothing matters, when every knob does.

✗ Judge by the input's size

c = 10 is the biggest input yet has the smallest slope (1). a's slope comes from b, not from a. Size tells you nothing.

✗ Nudge every knob in turn

What the lab does. It works, but costs one extra run of the expression per input (41 for the net at the end of this lecture) and gives −3.000000000010772, not −3.

✓ The local rule per operation

× gives each input the other's value, + gives 1. Exact (−3, 2, 1) from numbers you already have, no extra runs. Backprop chains exactly these rules.

What a partial doesn't tell you

A partial holds only here, with the others frozen. ∂d/∂a = b, so if b changes to 5 the slope for a becomes 5 (the bump gives 5.000000000023874). That's why training recomputes the gradient after every step.

When several inputs move together, d moves by roughly the sum of each partial times its nudge: (−3 + 2 + 1) × 0.0001 = 0. The all-at-once bump above saw exactly that; its leftover 0.00000001 is h × h from the product. And if one input feeds the expression in two places, its partials from both places add up, which is the += bug card.

Understand and remember

  • Bump one input and freeze the rest → any change in d comes from that input alone → (d2 − d1) / h is the partial derivative for that input → one number per knob: −3 for a, 2 for b, 1 for c
  • In a·b, a is multiplied by b → a nudge h in a moves the product by b·h → ∂(a·b)/∂a = b and ∂(a·b)/∂b = a → each input's slope is set by the other input's current value
  • In a + c, c passes straight through → a nudge h in c moves d by exactly h → ∂d/∂c = 1 → a + node copies the change along unchanged (the rule backprop uses at every +)
  • Partials hold only at the current point, with the others frozen → when several inputs move, d moves by about the sum of partial × nudge → (−3 + 2 + 1)·h ≈ 0, so an all-at-once bump hides that every knob matters, and a change in b changes ∂d/∂a
  • detail that matters Numerical partials cost one extra evaluation of the whole expression per input → 3 here, 41 for the lecture's small net → fine as a check, far too slow as the method → backprop gets every partial from the local rules instead

Reference only

  • the ∂ symbol, read "partial" or "del"
  • h = 0.0001 in Karpathy's cell
  • the exact printed values 3.999699999999999 and −3.000000000010772 (float rounding)
  • Karpathy's notebook cell bumps only c
