Big idea 1: A neural net is just one big math expression

Data and weights go in, a single number (the loss) comes out, and every step in between is a plain operation like +, × or tanh.

“just a certain class of mathematical expressions” · Karpathy, 0:00:25

Why it matters: GPT is the same kind of expression with far more weights and a cross-entropy loss instead of squared error. PyTorch records it as a graph exactly like this one.

Big idea 2: A derivative is a nudge ratio

Nudge the input by a tiny h and divide the change in the output by h. That ratio says how strongly, and in which direction, the input pushes the output.

the derivative is how sensitive the output is to a tiny nudge of the input · Karpathy, paraphrased, 0:08:08

Why it matters: Every .grad PyTorch hands you is this ratio for one weight and the loss, which is why training steps each weight against its gradient.

Big idea 3: Backprop is the chain rule, applied backwards through the graph

Start with L.grad = 1 at the output and walk back one node at a time. Each node multiplies the gradient arriving from above by its own small local derivative.

“just a recursive application of chain rule backwards through the computation graph” · Karpathy, 0:32:10

Why it matters: loss.backward() in PyTorch is this walk, done for every weight in one pass. That one pass is what makes training a net with millions of weights, like GPT, affordable.

Big idea 4: A value used twice gets both gradients, added

When one node feeds two paths, each path sends a gradient back. They must be summed with +=; writing = keeps only the last one.

when a value is used more than once, the gradients from each branch have to add up · Karpathy, paraphrased, 1:22:28

Why it matters: PyTorch accumulates into .grad the same way. That is why reused weights, like GPT-2's tied embeddings, just work, and why .grad must be zeroed each step.

Big idea 5: micrograd and PyTorch do the same math

Build the same neuron both ways and you get the same output and the same gradients. PyTorch adds speed (tensors, compiled kernels, GPUs), not new math.

“none of the math changes” · Karpathy, 0:00:25

Why it matters: Once micrograd makes sense, PyTorch is micrograd with tensors. In the next lecture the same backward pass runs on tensors, and nothing about the math changes.

Big idea 6: Training is forward, zero_grad, backward, update, on repeat

Four lines in a loop: compute the loss, clear old gradients, backprop, step every parameter a little against its gradient. Skip the clearing and the gradients pile up.

forgetting to zero the gradients is one of the most common neural-net bugs, and an easy problem trains anyway · Karpathy, paraphrased, 2:10:28

Why it matters: In PyTorch this is optimizer.zero_grad(), loss.backward(), optimizer.step(): the loop that trains GPT, where forgetting the first line fails just as quietly.

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • A net is an expression of data and weights ending in one loss number → every step is a simple op with a known local derivative → the loss can be differentiated with respect to every weight
  • Each node's grad = (grad arriving from above) × (its local derivative) → start from L.grad = 1 and walk the graph in reverse topological order → one backward pass fills every gradient
  • A node used on two paths receives two gradient contributions → they must be summed with += → grads must start at 0 → so every training step must zero them first, or old gradients leak into the new step
  • Gradient points toward more loss → update p.data += -lr * p.grad → repeat forward, zero_grad, backward, update → loss falls (6.005 → 0.018 in 20 steps in the lab)
  • detail that matters micrograd has one Python object per number, PyTorch one node per tensor op run in compiled kernels → same output and gradients, orders of magnitude less overhead → that is the only reason not to train GPT with micrograd

Reference only

  • the method names (__add__, _backward, build_topo, parameters())
  • the exact numbers of the running example (L = −8, o = 0.7071)
  • PyTorch spellings: requires_grad, .double(), optimizer.zero_grad()

3 · Retrieve from memory, card closed
  1. concept Explain, without code, why being able to write a neural net as one mathematical expression is what makes training possible at all.
    Check
    • an expression is built from ops whose local derivatives are known
    • so the loss can be differentiated with respect to every weight
    • gradients say which way to move each weight to lower the loss
  2. mechanism Walk through what L.backward() does on L = (a·b + c)·f, node by node, and name the value each .grad ends with.
    Check
    • sort nodes topologically, set L.grad = 1
    • L = d·f: d.grad = f = −2, f.grad = d = 4
    • d = e + c: e.grad = c.grad = −2 (plus passes it through)
    • e = a·b: a.grad = b·(−2) = 6, b.grad = a·(−2) = −4
  3. tradeoff micrograd uses += in every _backward. What does that choice buy, and what does it cost you in the training loop?
    Check
    • buys: correct gradients when a node is used more than once (b = a + a gives 2, not 1)
    • costs: grads never reset themselves, so each step must set them to 0 first
    • forget it and gradients from earlier steps pile up, acting like a growing step size
  4. tradeoff The lab's forgot-zero_grad run reached a lower loss than the correct loop at step 5 (0.0016 vs 0.70). Why is that not evidence the bug is harmless?
    Check
    • piled-up grads act like a larger, growing learning rate, which happens to help on a 4-example problem
    • the buggy loss is not monotonic (0.0099 by step 10)
    • on a real problem the growing steps overshoot; the easy task hides the bug

Why this step?

4 · Compare against what you already know

vs The chain rule: The toolkit chain rule multiplies derivatives along one chain of functions. What does backprop add to make it work on a whole graph, and where would a pure chain-of-functions view give a wrong answer?

Check
  • backprop applies it at every node, in reverse topological order, reusing each node's grad once
  • at a node with several consumers the chain rule has several terms, which must be summed
  • treating the graph as one chain misses that sum: the b = a + a bug

vs A derivative is a nudge ratio: Nudging each input numerically and running backprop both give gradients. What is fundamentally different about how they get them, and when would you still use the nudge?

Check
  • the nudge needs one extra forward pass per input and is approximate (h too small breaks it)
  • backprop gets every gradient exactly in one backward pass using local derivatives
  • you still use the nudge as a gradient check when you write a new op's backward

vs More operations, and PyTorch agrees: micrograd and PyTorch give the same gradients for the tanh neuron. Which design choice makes micrograd readable and PyTorch fast, and how would each fail if you tried to train GPT-2 with it?

Check
  • micrograd: one Python object per scalar; PyTorch: one node per tensor op in compiled code
  • micrograd would need a Python object per number, far too slow and memory-hungry for 124M parameters
  • PyTorch hides the backward code, so a wrong custom backward is harder to see; the fix is the same gradient check

Why this step?

5 · Predict commit to an answer before revealing

You build L = a*a*a with a = Value(2.0) (Python groups it as (a*a)*a) and call L.backward(). Commit first: what is a.grad, and how many separate contributions add up to it?

Reveal

12.0, from three contributions of 4 each. The outer × sends a.grad += (a·a) × 1 = 4. The inner node b = a·a gets b.grad = a = 2, and since both of its inputs are a, it sends a.grad += 2·2 = 4 twice. 4 + 4 + 4 = 12 = 3a², the power rule. With = instead of += you would get 4.
