A derivative is a nudge ratio

Also called: the slope, the rate of change, the sensitivity; estimated this way it's a numerical derivative or finite difference. Lecture 1 · derivative of a simple function with one input · 0:08:08

Prime · 2 minutes before you read

The problem: Training means changing a number so that a loss goes down. Without a way to say "if I push this input up, the output moves this way, this much", you'd be changing weights blindly.

Where it fits: This is the first idea of the micrograd lecture and the meaning behind every .grad that follows. It builds on the derivative rules from the toolkit, but asks you to measure a slope instead of deriving it.

Builds on: Derivatives: the rules you'll actually use

You'll meet: the nudge ratio (f(x+h) − f(x)) / h sign and size of a slope why the estimate overshoots by a bit floating-point rounding when h is too small

By the end: Read any derivative as "output moved ÷ input moved", estimate one numerically in two lines of Python, and pick an h that gives a trustworthy answer.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. At x = 2/3 the true slope is 0, yet the h = 0.001 ratio says 0.003. Where does the extra come from?
  2. What does the sign of the slope at x = −3 tell you to do with x if you want f smaller?
  3. Why does shrinking h help at first and then, somewhere below 1e−9, start making the answer worse?
  4. If the nudge ratio already gives about 14, what does backprop add that makes it worth building?

In one breath: nudge the input by a tiny amount h, see how far the output moves, and divide. That ratio is the derivative: it says which way the output goes when you push the input up, and how hard. Every .grad in micrograd means exactly this.

Predict first: f(x) = 3x² − 4x + 5 bottoms out at x = 2/3, where the true slope is 0. Nudge x by h = 0.001 and compute the ratio. Do you get 0?

No: you get 0.003. The ratio measures the average slope across the whole step from x to x + h, and the curve is already rising by the end of that step. For this f the overshoot is always exactly 3h, so it is 0.003 at every x (14.003 instead of 14 at x = 3). Shrinking h shrinks the error, up to a point (below).

The definition: rise over run, with a tiny run

f′(x)= limh→0 f(x+h)−f(x)rise: how far the output moved hrun: the nudge
f(x)the function; here Karpathy's 3x² − 4x + 5f(3) = 20 xthe input you nudge3 hthe size of the nudge0.001 f′(x)the derivative (read "f prime"): output moved ÷ input moved14 lim h→0"what the ratio settles on as h shrinks toward 0"

The same thing in plain arithmetic, at x = 3 with h = 0.001:

f(3.001) = 3·3.001² − 4·3.001 + 5 = 27.018003 − 12.004 + 5 = 20.014003 f(3) = 3·3² − 4·3 + 5 = 27 − 12 + 5 = 20 ratio = (20.014003 − 20) / 0.001 = 0.014003 / 0.001 = 14.003 exact = 6x − 4 = 6·3 − 4 = 14 (the power rule: 3x² → 6x, −4x → −4)

Read 14 as: near x = 3, the output moves 14 times as far as the input. Nudge x up by 0.001 and f goes up by about 0.014.

Three points, three stories

xf(x)ratio, h = 0.001exact 6x − 4What the sign and size say
32014.00314positive: push x up, f goes up, 14× as fast
−344−21.997−22negative: push x up, f goes down, 22× as fast
2/33.6670.0030about 0: the bottom of the bowl, a nudge barely moves f

Every ratio is 0.003 too high. Expanding the rise shows why:

f(x+h) − f(x) = 3(x+h)² − 4(x+h) + 5 − (3x² − 4x + 5) = 6xh + 3h² − 4h ÷ h = (6x − 4) + 3h 3h = 3 × 0.001 = 0.003

The ratio equals the true slope plus 3h. So a smaller h should mean a smaller error, but only until the computer's rounding takes over.

Too small an h breaks it

hratio at x = 3error vs 14What dominates
1e−314.003000+0.003the 3h overshoot
1e−614.000003+0.0000033h, now tiny
1e−914.0000012+0.0000012rounding (3h would be only 0.000000003)
1e−1214.0012+0.0012rounding, getting worse
1e−1510.66−3.34rounding: the answer is wrong

A Python float can't store 3 + 1e−15; the nearest one is 3 + 0.00000000000000089. Floats near 20 are spaced 0.0000000000000036 apart, so the "rise" comes out as three of those steps (1.07e−14), and 1.07e−14 ÷ 1e−15 = 10.66. h = 0.001 or 0.000001 is plenty.

When: pause the video at 0:08:08 and type this before watching on.

def f(x):
    return 3*x**2 - 4*x + 5

print('f(3.0) =', f(3.0))

h = 0.001
for x in [3.0, -3.0, 2/3]:
    slope = (f(x + h) - f(x))/h       # rise over run
    print(f'x = {x:.4f}   slope (h={h}) = {slope:.6f}')

h = 0.000001                          # Karpathy's cell
x = 2/3
print('x = 2/3, h = 1e-6:', (f(x + h) - f(x))/h)

Ways to get the slope at x = 3

✗ A big nudge (h = 1)

(f(4) − f(3)) / 1 = 37 − 20 = 17. That's the average slope over a wide step, and the curve bends inside it: the 3h overshoot is now 3.

✗ A tiny nudge (h = 1e−15)

Gives 10.66. The rise is smaller than the gaps between floats, so rounding decides the answer, not the function.

✗ Nudge both ways (central difference)

(f(3.001) − f(2.999)) / 0.002 = 13.999999999999346: the 3h overshoot cancels. Much better, but it still costs two evaluations of f per input, and it's still an estimate.

✓ The exact rule, 6x − 4

14, with no h to tune and no rounding trap. Backprop gets exact slopes like this by chaining each operation's rule. The nudge ratio stays on as the checker.

So why not just nudge every input of a network?

The nudge ratio is the meaning of a derivative, not the way you compute it for training. A network has many inputs (the small net at the end of this lecture has 41 parameters), and nudging costs one extra run of the whole expression per input, and each result is only approximate. Backprop gets all of them exactly, in one backward pass.

Use nudging to check your gradients, the way Karpathy's lol() function does on the chain-rule card, with h around 0.001, never tiny. Also note that f′ is the slope at one point only: 14 at x = 3 says nothing about x = 5, which is why training takes small steps and recomputes.

Understand and remember

  • Nudge x by h → f moves by roughly f′(x)·h → so (f(x+h) − f(x)) / h ≈ f′(x) → the sign says which way f goes and the size says how strongly: 14 at x = 3, −22 at x = −3, 0 at the bottom
  • The ratio averages the slope over the whole step → a curved f bends inside the step → for 3x² − 4x + 5 the ratio is exactly (6x − 4) + 3h → the error shrinks with h (0.003 at h = 0.001)
  • Floats have fixed spacing (about 3.6e−15 near 20) → when the true rise f′·h is near that spacing, rounding decides the rise → a tiny h gives garbage (10.66 at h = 1e−15) → use h around 1e−3 to 1e−6
  • Each nudge costs one extra evaluation of the whole expression per input and is only approximate → hopeless for a network with many parameters → backprop computes exact slopes for all of them, and nudging becomes the gradient check
  • detail that matters Nudging both ways, (f(x+h) − f(x−h)) / 2h, cancels the 3h term → 13.999999999999346 at h = 0.001 instead of 14.003 → the better choice for a gradient check, at two evaluations per input

Reference only

  • the exact function 3x² − 4x + 5 and its rule 6x − 4
  • np.arange(-5, 5, 0.25) and plt.plot for the parabola
  • the notebook's value 2.999378523327323e−06 at x = 2/3, h = 1e−6
  • f(3) = 20, f(−3) = 44

Check
  • the chain rule gives exact values from each operation's local rule, all inputs in one backward pass
  • the nudge ratio is approximate and needs one evaluation per input
  • the chain rule fails silently if a local rule is coded wrong; nudging fails from a bad h
  • so the nudge ratio (lol()) is used to catch chain-rule bugs

Why this step?

5 · Predict commit to an answer before revealing

At x = 3, nudge the other way: h = −0.001. What ratio do you get, and what happens if you average it with the forward ratio 14.003?

Reveal

The backward ratio is (6x − 4) + 3h with h = −0.001, so 13.997 (Python prints 13.996999999996262). Averaging 14.003 and 13.997 gives 14: the ±3h errors cancel. That is the central difference, (f(x+h) − f(x−h)) / 2h, which gives 13.999999999999346.
