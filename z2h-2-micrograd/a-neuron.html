A neuron, backpropagated

Also called: an artificial neuron, a unit, a tanh neuron. Lecture 1 · manual backpropagation example #2: a neuron · 0:52:52

Prime · 2 minutes before you read

The problem: The expression card only had + and ×. A real neuron ends in a squashing function, and backprop stalls at that node unless you know how much gradient it lets through.

Where it fits: It reuses the manual backprop from the chain-rule card on a bigger graph, adding one new operation, tanh. Its hand-filled grads are what the automatic-backward card then automates.

  1. Why does tanh's backward step need only the output o, not the input n?
  2. Why does the zero input make w2.grad vanish but leave x2.grad at 0.5?

In one breath: a neuron multiplies each input by a weight, adds them up with a bias, and squashes the sum through tanh. Backpropagating through it is the expression card again with one new step. tanh passes back its own local slope, 1 − o², and after that the plus and times rules you already know finish the job.

Predict first: the input x2 is 0 and its weight w2 is 1. After backprop, which one has a gradient of exactly 0: x2.grad or w2.grad?

w2.grad = 0, and x2.grad = 0.5. A times node hands each input the other input's value. w2 gets x2.data × 0.5 = 0 × 0.5: wiggling a weight that multiplies zero changes nothing. x2 gets w2.data × 0.5 = 1 × 0.5, so nudging the input would still move the output.

Forward: weighted sum, then squash

o=tanh( x1w1+x2w2+bn: the weighted sum (preactivation) )
x1, x2the inputs: data coming into the neuron2.0, 0.0 w1, w2the weights: how strongly each input counts (the "synapse strengths")−3.0, 1.0 bthe bias: a constant added regardless of the inputs (Karpathy: the neuron's "trigger happiness")6.8813735870195432 tanhthe activation: squashes any number into the range −1 to 1one op othe neuron's output0.7071
n = x1·w1 + x2·w2 + b = 2·(−3) + 0·1 + 6.8813735870195432 = −6 + 0 + 6.8813735870195432 = 0.8813735870195432 o = tanh(0.8814) = 0.7071067811865476 ≈ 1/√2 = 0.7071067811865475

The odd bias is picked so the numbers come out nice: 6 + atanh(1/√2) = 6.8814, so o lands on 1/√2 and o² = 0.5 (our arithmetic). With b = 8, n is 2 and o = 0.9640, the "0.96" Karpathy shows first. tanh is written as one operation, (e2x − 1)/(e2x + 1). Any function can be a single node, as long as you know its local derivative.

Backward: tanh, then the rules you know

dodn= 1−tanh2(n)= 1−o2tanh's local slope =1−0.70712=0.5

The derivative of tanh is a standard calculus result (Karpathy reads it off the hyperbolic functions page). It only needs the output o, which the forward pass already computed.

o.grad = 1.0 start: do/do = 1 n.grad = (1 − o²) × o.grad = 0.5 × 1.0 = 0.5 tanh b.grad = n.grad = 0.5 + copies x1w1.grad = x2w2.grad = 0.5 (via the sum) + copies x1.grad = w1.data × 0.5 = −3 × 0.5 = −1.5 × swaps w1.grad = x1.data × 0.5 = 2 × 0.5 = 1.0 x2.grad = w2.data × 0.5 = 1 × 0.5 = 0.5 w2.grad = x2.data × 0.5 = 0 × 0.5 = 0.0

Check by nudging (h = 0.001, computed): w1 0.9986, x1 −1.5032, x2 0.4996, w2 0.0. Read w1.grad = 1.0 as "raise w1 a little and o rises about as much". That's the number training will use to adjust the weight.

Our neuron passes half of the gradient through. With b = 8 it would pass 0.0707, about 7× less, so every grad upstream shrinks by the same factor. Past n ≈ 3 the neuron is saturated (grey): its output hardly moves, and almost no gradient gets back to its weights.

When: pause the video at 0:52:52 and type this before watching on. Add tanh to the Value class you wrote on the value-object card.

import math
# add inside class Value (from the value-object card)
    def tanh(self):
        x = self.data
        t = (math.exp(2*x) - 1)/(math.exp(2*x) + 1)
        return Value(t, (self,), 'tanh')
x1 = Value(2.0, label='x1'); x2 = Value(0.0, label='x2')
w1 = Value(-3.0, label='w1'); w2 = Value(1.0, label='w2')
b = Value(6.8813735870195432, label='b')
x1w1 = x1*w1; x2w2 = x2*w2
x1w1x2w2 = x1w1 + x2w2
n = x1w1x2w2 + b; n.label = 'n'
o = n.tanh(); o.label = 'o'
print(n.data, o.data)

Now fill in every grad by hand, from the output back:

o.grad = 1.0
n.grad = 1 - o.data**2           # tanh's local slope
x1w1x2w2.grad = b.grad = n.grad  # + copies the grad
x1w1.grad = x2w2.grad = x1w1x2w2.grad
x1.grad = w1.data * x1w1.grad    # * swaps in the other
w1.grad = x1.data * x1w1.grad
x2.grad = w2.data * x2w2.grad
w2.grad = x2.data * x2w2.grad
for v in [n, x1, w1, x2, w2]:
    print(v.label, v.grad)

Why tanh as one node with a known slope

✗ No activation at all

Without the squash, a neuron is just a weighted sum. Stacking such layers gives another weighted sum, so depth adds nothing a single layer couldn't do.

✗ A hard on/off step

Output 1 if n > 0, else 0. Its slope is 0 everywhere except at the jump, so backprop sends zero gradient to every weight and nothing can learn.

✗ tanh spelled out from exp, +, ÷

Works, and gives the same grads (the more-ops card does it). But the graph grows from 10 nodes to 18, and you backprop through each piece instead of one known formula.

✓ tanh as one op, slope 1 − o²

Smooth, so every weight gets a useful gradient; one node, whose backward step reuses the output it already computed. Any function can be packaged this way if you know its derivative.

Is tanh what real networks use?

Not usually any more. Karpathy's own micrograd repo uses ReLU (max(0, n), engine.py L45–L52) instead of tanh, and modern nets mostly use ReLU-like functions. One reason is the table above: tanh saturates, and a saturated neuron passes back almost no gradient. The z2h-5 cards show that problem in a real network.

A common confusion: backprop computed x1.grad and x2.grad too, but training never changes the inputs, which are fixed data. Only the weights and the bias get updated. The input grads matter when the neuron's inputs are other neurons' outputs, because that is how the gradient keeps flowing back.

Understand and remember

  • tanh squashes n into (−1, 1) → its local slope is 1 − o² → every gradient flowing back through the neuron is multiplied by that factor (0.5 here) before reaching the weights
  • a × node hands each input the other input's data times the grad above → an input of 0 makes its weight's grad 0 (w2.grad = 0), while the input's own grad is set by its weight (x2.grad = 0.5)
  • n far from 0 → o near ±1 → 1 − o² near 0 (0.0707 at n = 2, 0.0099 at n = 3) → the neuron is saturated and its weights barely learn
  • any function with a known derivative can be one graph node → backprop only needs its local slope → tanh as one op gives the same grads as tanh rebuilt from exp, + and ÷, with fewer nodes
  • detail that matters the local slope is written with the forward output (1 − t**2, using the stored t) → backward reuses a number already computed instead of evaluating tanh again

Reference only

  • the bias value 6.8813735870195432 (chosen so o = 1/√2)
  • tanh's formula (e2x − 1)/(e2x + 1)

  1. concept Explain what the bias and the tanh each add to a plain weighted sum, and what would go wrong for learning if the tanh were replaced by a hard 0/1 step.
    Check
    • bias shifts where the neuron switches, independent of the inputs
    • tanh squashes the output into (−1, 1) and makes the neuron nonlinear
    • a step has slope 0 almost everywhere, so backprop would pass zero gradient to every weight
  2. mechanism Walk the gradient from o to x1: which nodes does it pass, which local rule applies at each, and what number results?
    Check
    • o.grad = 1
    • tanh: × (1 − o²) = 0.5 → n.grad 0.5
    • + (n = sum + b) copies 0.5, + (sum = x1w1 + x2w2) copies 0.5 to x1w1
    • × swaps: x1.grad = w1.data × 0.5 = −3 × 0.5 = −1.5
  3. tradeoff You can make tanh one node with a hand-written derivative, or build it from exp, +, − and ÷ and let each piece backprop. What does each choice cost, and when would you pick the second?
    Check
    • one node: fewer nodes (10 vs 18 for this neuron) and one formula, but you must derive and code the slope correctly
    • composed: no new derivative to get wrong, same grads, but a bigger graph and more work per pass
    • pick composed when the derivative is messy or you're testing; one op when it's common and has a clean slope
  4. mechanism Set b = 8 so n = 2. By roughly what factor do all the upstream grads change, and why?
    Check
    • o = tanh(2) = 0.9640, so 1 − o² = 0.0707
    • 0.5 / 0.0707 ≈ 7, so every grad upstream shrinks about 7×
    • only the tanh factor changed; the + and × rules are the same

5 · Predict commit to an answer before revealing

Change the neuron's weights to w1 = 3 (instead of −3) and keep x1 = 2, x2 = 0, w2 = 1, b = 6.8814. Before computing: will w1.grad go up, go down, or stay near 1.0? Commit, then check.

Reveal

It collapses to about 0. Now n = 6 + 6.8814 = 12.8814, so o = tanh(12.8814) = 0.99999999999 and 1 − o² ≈ 2.6 × 10−11. So w1.grad = x1 × (1 − o²) ≈ 5.2 × 10−11 (computed). Flipping one weight's sign pushed the neuron deep into saturation: the input is the same, but the gradient signal is gone.
