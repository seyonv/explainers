Checkpoint 1: from three characters to one loss number

Ties together why counts explode, the rolling-window dataset, the embedding lookup, .view, the hidden and output layers and F.cross_entropy, plus the bigram lecture's one-hot layer and loss: the whole forward pass of Bengio's MLP, before any training.

What this ties together, and why now. Six cards built one forward pass. A count table can't hold three characters of context (19,683 rows, only 28.9% ever seen), so each name becomes fixed-size (context → next char) rows. Each character becomes a learned point C[ix], and view lays a row's three points side by side at no cost. A tanh layer and an output layer then turn them into 27 logits, and F.cross_entropy grades the logits. Bengio's Fig. 1 is the map of all this. The next card starts training. Before it does, check that you can run the pipeline in your head, shape by shape, and say why each step is there.

Comes back from earlier courses: one-hot inputs and a linear layer, the negative log likelihood, the keepdim trap, broadcasting rules and matmul by shapes. Several questions reach back to them without saying so.

How to use this page. Close the cards. Write a full answer to each question before you open its Check. A wrong or shaky answer tells you exactly which section to reopen. The questions are mixed on purpose, so part of the work is spotting which idea applies.

1 · Mixed retrieval

  1. which idea?You switch to 10-number embeddings, C (27, 10) and W1 (30, 200), but leave emb.view(-1, 6) as it was. The forward pass stops with RuntimeError: mat1 and mat2 shapes cannot be multiplied (160x6 and 30x200). Where does the 160 come from, and which idea makes the fix a one-number change?
    Check
    • emb = C[X] is now (32, 3, 10), which is 960 numbers. view(-1, 6) reads them as 960 / 6 = 160 rows of 6. That is a legal view with the wrong grouping: -1 means "whatever makes the count work"
    • a view only puts a new shape and new strides over the same storage. Nothing checks that the rows mean "one example each"
    • the fix is view(-1, 30) (3 characters × 10), or emb.view(emb.shape[0], -1) as the labs write it, so the width is never hard-coded
    • it can be worse: with a (6, 200) W1 the matmul runs, and the crash only comes at the loss, as Expected input batch_size (160) to match target batch_size (32) (computed)

    If you missed it, reopen .view, "Why the MLP needs it: (32, 3, 2) → (32, 6)", and the note under the Build it box of hidden and output.

  2. The first five names are emma, olivia, ava, isabella and sophia. How many rows do they give with block_size = 3? How many with block_size = 8? And what is special about the rows whose context is ...?
    Check
    • a name of n letters gives n + 1 rows, one per letter plus the closing dot: 5 + 7 + 4 + 9 + 7 = 32, so X is (32, 3)
    • still 32 with block_size = 8. The row count depends only on how many characters there are; block_size changes the width of X to (32, 8). For all words it stays 228,146 (with block_size 4, X is (228146, 4), computed)
    • ... appears once per name, with five different labels: e, o, a, i, s. The same input has five right answers, which matters as soon as you train

    If you missed it, reopen the rolling-window dataset, "Counting the rows" and "What this dataset does not do".

  3. On a copy of the logits, you set row 0's logit for its correct character to 100. The hand-written exp → normalise → pick → −log → mean now prints nan. F.cross_entropy prints 16.7754, lower than the 17.7697 before. Explain both numbers.
    Check
    • float32 tops out near 3.4 × 1038 = e88.7, so exp(100) is inf. The row sum is inf as well, inf / inf is nan, and one nan makes the mean nan
    • F.cross_entropy subtracts each row's largest logit first. Adding a constant to a whole row doesn't change the softmax, and now the biggest exponent is e0 = 1
    • row 0's correct character now gets a probability of about 1, so −log ≈ 0. Before, that row cost 31.82: (32 × 17.7697 − 31.82) / 32 ≈ 16.775 (computed; the run prints 16.7754)
    • put the 100 in a wrong column instead and the hand-written loss is inf (the right character's probability rounds to 0), while F.cross_entropy says 20.2129 (measured in the build below)

    If you missed it, reopen logits to loss, "Why the hand-written version breaks at 100".

  4. which idea?You want 4 characters of context instead of 3. What happens to a smoothed count table, and what changes in the MLP? Give numbers for both.
    Check
    • count table: 274 = 531,441 contexts. Only 4.2% occur in names.txt, which works out to 0.43 examples per possible row. With 0.1 fake counts the dev loss gets worse: 2.1018 at n = 3, 2.1522 at n = 4
    • MLP: X becomes (N, 4), emb (N, 4, 2), view(-1, 8) and W1 (8, 100). That's 200 more weights: 54 + 800 + 100 + 2,700 + 27 = 3,681 instead of 3,481 (computed)
    • the row count doesn't change (228,146). An extra character adds one slice of W1, not 27× more rows, and every context shares the same weights

    If you missed it, reopen why counts explode, "More context helps, then hurts", and Bengio 2003, "Why points in space generalize".

  5. emb.view(-1, 6) @ W1 is (32, 100) and b1 is (100,). Say exactly what + b1 does. Then say what would go wrong, silently, if you had created b1 as (32, 1).
    Check
    • broadcasting lines shapes up from the right and treats a missing dimension as 1. (100,) acts as (1, 100) and is copied down all 32 rows, so every example gets the same bias b1[j] for neuron j. That's what you want
    • (32, 1) broadcasts too, to (32, 100). But now each example gets its own bias, shared by all 100 neurons. It has the wrong meaning, raises no error, and only works for batches of exactly 32
    • it's the same kind of bug as the bigram lecture's keepdim trap: the shapes line up, the meaning doesn't

    If you missed it, reopen hidden and output, "The + b1 broadcast, checked", broadcasting rules, "The two rules", and the keepdim trap, "What each version computes".

  6. debugYour loss at step 0 is 17.7697 on the 32 rows, but guessing uniformly over 27 characters would score 3.2958. A teammate says the loss code must be broken. Is it? If not, what's wrong?
    Check
    • the loss code is fine: the hand-written version and F.cross_entropy both give 17.7697
    • the model is confidently wrong. Row 0's correct character e gets probability 1.52 × 10−14, which is −log = 31.82 for that row alone
    • the cause is the careless init. Plain randn weights give preactivations with std 2.84, so 32.7% of the hidden values sit at |h| > 0.99 (saturated tanh), and the logits range from −24.6 to 27.9
    • a net whose 27 logits were all equal would score exactly 3.2958 (F.cross_entropy of all-zero logits, computed). Scaling the weights down is the next lecture's first fix (the expected initial loss)

    If you missed it, reopen hidden and output, "Is this hidden layer finished?", and logits to loss, "The formula, then the five steps".

  7. which idea?A teammate embeds with F.one_hot(X, 27).float() @ C, just like the bigram lecture's xenc @ W. Their tensor equals your C[X] exactly. Which idea says to switch anyway, what does switching save, and does C still learn if you only index into it?
    Check
    • a one-hot row times a matrix picks out one row of the matrix. In the bigram lecture xenc @ W equalled W[xs], and here F.one_hot(X, 27).float() @ C equals C[X] (max difference 0.0 over all 96 lookups, measured in the build below)
    • work: 96 × 54 = 5,184 multiply-adds, most of them times 0, against 192 numbers copied. You also skip a (32, 3, 27) one-hot tensor of 2,592 floats. For Bengio's 17,000-word vocabulary the gap is 510,000 multiply-adds per word against 30 copies
    • yes, C still learns: indexing is the matmul in disguise, so gradients flow into the rows that were used (4 of 27 on emma's first five rows) and add up when a row is used several times

    If you missed it, reopen the embedding lookup, "Two ways to get row 5" and "If it's only indexing, how does C learn?", and one-hot and a linear layer, "Isn't multiplying by 26 zeros wasteful?".

  8. Write the shape after every step of the forward pass for the 32 rows, from X to the loss. Then say which parameter tensor holds most of the 3,481 numbers, and why.
    Check
    • X (32, 3) int64 → C[X] (32, 3, 2) → view(-1, 6) (32, 6) → @ W1 + b1 (32, 100) → tanh (32, 100) → @ W2 + b2 (32, 27) → F.cross_entropy gives one number
    • in (a, b) @ (b, c) the inner sizes must match, and the result is (a, c)
    • 54 + 600 + 100 + 2,700 + 27 = 3,481. W2 holds 2,700 of them (77.6%), because it connects every hidden unit to every character in the vocabulary. In Bengio's word model the output layer is 1,717,000 of 2,236,100, which is why Karpathy calls it "the expensive layer" (chapter from 0:01:48)

    If you missed it, reopen hidden and output, "The forward pass, shape by shape" and "Where the 3,481 parameters live", and matmul by shapes, "The shape rule".
