Names into (context → next char) pairs

Also called: a rolling (sliding) window, building X and Y, the training set of an n-gram-style model. Lecture 3 · (re-)building our training dataset · 0:09:03

Prime · 2 minutes before you read

The problem: A neural net takes a fixed number of inputs and needs a target to compare against. A file of names of different lengths is neither, so without a conversion step there is nothing to train on.

Where it fits: The bigram lecture turned names into (char → next char) pairs. This card widens the left side to three characters, which is the input the Bengio-style MLP in the rest of this course expects.

Needs first: The dataset: 32,033 names

In one breath: pad each name with three dots, slide a window three characters wide across it, and write down one row per position: the three characters in the window (the context, stored in X) and the character right after it (the label, stored in Y). Every character of every name, plus the closing dot, becomes the label of exactly one row.

Predict first: the first five names are emma, olivia, ava, isabella and sophia. How many rows do they give, and how many of those rows have the context ...?

32 rows, and 5 of them start from .... A name of n letters gives n + 1 rows (one per letter, plus the end dot): 5 + 7 + 4 + 9 + 7 = 32. Every name starts from the same all-dots context, so ... appears once per name, with five different labels: e, o, a, i, s.

The window, one step at a time

Two words first. block_size is the context length: how many previous characters the model gets to see (3 here). stoi ("string to integer") is the bigram lecture's table that turns a character into its number: . is 0, a is 1, e is 5, m is 13. itos goes back the other way.

For emma the loop reads e, m, m, a, . and saves five rows. Grey dots are padding, green is the label:

rowcontext (chars)X row (ints)Yread as
0...[0, 0, 0]5nothing yet → e
1..e[0, 0, 5]13e → m
2.em[0, 5, 13]13em → m
3emm[5, 13, 13]1emm → a
4mma[13, 13, 1]0mma → end of name

Row 0 is what lets the model learn which letters start a name. Row 4 is what lets it learn when to stop.

Counting the rows

Each character read gives one row, so the row count only depends on how many characters there are, not on block_size:

▶ Build itruns on your M3 · about 1 s

When: pause the video at 0:09:03 and write this before watching on. It reuses words, stoi and itos from the bigram lecture.

block_size = 3  # context length: chars used to predict the next one
def build_dataset(words):
    X, Y = [], []
    for w in words:
        context = [0] * block_size          # start as '...'
        for ch in w + '.':
            ix = stoi[ch]
            X.append(context); Y.append(ix)
            context = context[1:] + [ix]    # crop and append
    return torch.tensor(X), torch.tensor(Y)
for x, y in zip(*build_dataset(words[:1])):   # emma's rows
    print(''.join(itos[i] for i in x.tolist()), '--->', itos[y.item()])
X, Y = build_dataset(words[:5])
print('X.shape', tuple(X.shape), X.dtype,
      '| Y.shape', tuple(Y.shape), Y.dtype)
print('X.shape == (32, 3):', tuple(X.shape) == (32, 3))

torch.int64 means the tensors hold whole numbers (character ids), not floats. context[1:] + [ix] builds a new list each time, so every row appended to X stays as it was.

Why it beats the alternatives

✗ A count table over 3-char contexts

Needs 27³ = 19,683 rows, and only 5,686 of those contexts (28.9%) ever occur in names.txt. Most rows get too few counts to trust.

✗ Windows without the dot padding

Only real 3-letter windows count, so the first letters are never predicted. Rows drop from 228,146 to 132,047, and the 65 two-letter names (an, jo, …) give none at all.

✗ The whole name as one input

Names run from 2 to 15 letters, but a layer of weights needs the same number of inputs every time. You'd also get one example per name instead of one per character.

✓ Padded rolling window

Every row has exactly 3 inputs, every character (plus each end) is predicted once, and the model learns how names start and stop. 228,146 fixed-size rows, ready for a neural net.

Row counts computed from names.txt; 5,686 and 28.9% are from the course's why-counts-explode lab.

What this dataset does not do

It doesn't remove ambiguity. The same context can have different labels: in the 5-name set, ... is followed by e, o, a, i and s. No model can get all five right, which is why the overfitting run on these 32 rows can't reach a loss of 0 (the overfit-one-batch card).

It isn't how big models store data. Neighbouring rows overlap by two characters, so X holds each character up to three times (all words: 228,146 × 3 int64s = 5.5 MB, fine here). The GPT lecture keeps the text as one long tensor and cuts random chunks out of it at training time instead. Also shuffle and split by name before building rows, as the notebook does: build_dataset is called once per split.

Understand and remember

  • Every name starts from the all-dots context → the first letter becomes the label of a ... row → the model learns how names start, and sampling can begin from ...
  • One row per character read (letters plus the end dot) → rows = Σ(len(w) + 1) → 32 rows for 5 names, 228,146 for all, independent of block_size → a longer context widens X, it doesn't lengthen it
  • context[1:] + [ix] drops the oldest id and appends the newest → every row has exactly block_size inputs → a fixed-width X that a weight matrix can multiply
  • The same context can come with different labels (... → e, o, a, i, s) → no model can fit every row → even a perfect fit to these 32 rows keeps a loss above 0
  • detail that matters context[1:] + [ix] creates a new list → the list already appended to X is never changed → an in-place context.pop(0); context.append(ix) would make every row of X point at the same final list

Reference only

  • stoi['.'] = 0, a = 1 … z = 26, and itos for the reverse
  • torch.tensor(X) gives torch.int64
  • the lab prints rows as ctx ---> ch
  • names.txt: 32,033 names, 2 to 15 letters, 196,113 letters in total
