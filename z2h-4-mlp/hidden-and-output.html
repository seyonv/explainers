Hidden tanh layer and output logits

Also called: the rest of the MLP (multi-layer perceptron), a two-layer neural net, a fully connected (linear) layer plus tanh. Lecture 3 · implementing the hidden layer · 0:18:35 · the output layer · 0:29:15

Prime · 2 minutes before you read

The problem: After the lookup you hold three separate 2-number embeddings per row. Nothing yet combines them, and nothing turns them into 27 scores for the next character, so there is no prediction to train.

Where it fits: This finishes the forward pass of Bengio's MLP. It takes emb.view(-1, 6) from the view card and applies the layer idea from micrograd's neuron card, now as whole matrices, so the cross-entropy card can turn its logits into a loss.

In one breath: lay each row's three character embeddings side by side (6 numbers), multiply by a weight matrix to get 100 mixed numbers, squash each with tanh, then multiply by a second matrix to get 27 scores, one per possible next character. Two matrix multiplies, two bias vectors and one squash: that is the whole network between the lookup table and the loss.

Predict first: the net has five parameter tensors, C, W1, b1, W2 and b2, with 3,481 numbers in total. Which one holds the most, and roughly what share?

W2, with 2,700 of the 3,481 (78%). It connects 100 hidden neurons to 27 outputs, so 100 × 27 = 2,700. The hidden layer W1 is only 6 × 100 = 600, because each row has just 6 input numbers. The output layer is the big one because it must score every character in the vocabulary; Bengio's paper, with 17,000 words, calls it the expensive layer.

The forward pass, shape by shape

A neuron takes a weighted sum of its inputs plus a bias (a constant it learns), as in micrograd. A layer is many neurons reading the same inputs. Stacking their weights as columns of a matrix lets one @ (matrix multiply) compute all 100 neurons for all 32 rows at once.

h=tanh(xW1+b1)hidden layer logits=hW2+b2output layer

Shapes chain like dominoes: in (a, b) @ (b, c) the inner sizes must match and the result is (a, c). So (32, 6) @ (6, 100) gives (32, 100), and (32, 100) @ (100, 27) gives (32, 27). The 100 is a hyperparameter: a size you choose, not something the net learns.

One row through the hidden layer

row 0, context '...' → x[0] = [1.5674, -0.2373, 1.5674, -0.2373, 1.5674, -0.2373] neuron 0: hpreact = x[0] · W1[:, 0] + b1[0] = -1.6952 → tanh = -0.9348 neuron 1: hpreact = x[0] · W1[:, 1] + b1[1] = 8.5502 → tanh = 1.0000 over all 32 × 100 = 3,200 values: hpreact std 2.84, range -11.33 .. 10.56 |h| > 0.99 for 1,046 of them = 0.327

Computed with the lab's seed (2147483647). Row 0 is ..., so C[0] = (1.5674, −0.2373) repeats three times. A preactivation of 8.55 lands on tanh's flat top: that neuron is saturated.

The + b1 broadcast, checked

emb.view(-1, 6) @ W1 is (32, 100) but b1 is (100,). Broadcasting lines shapes up from the right and treats a missing dimension as size 1, so b1 acts as a (1, 100) row copied down all 32 rows: every example gets the same bias for neuron j. That is what we want. Had b1 been (32, 1) by mistake, each example would get its own bias instead, and PyTorch would not complain.

(32, 100) emb.view(-1, 6) @ W1 ( 100) → (1, 100) → copied to (32, 100) b1

When: pause the video at 0:32:17 (summary of the full network) and type this before watching on. It reuses X from build_dataset(words[:5]).

g = torch.Generator().manual_seed(2147483647)
C = torch.randn((27, 2), generator=g)
W1 = torch.randn((6, 100), generator=g)
b1 = torch.randn(100, generator=g)
W2 = torch.randn((100, 27), generator=g)
b2 = torch.randn(27, generator=g)
parameters = [C, W1, b1, W2, b2]
emb = C[X]                                   # (32, 3, 2)
h = torch.tanh(emb.view(-1, 6) @ W1 + b1)    # (32, 100)
logits = h @ W2 + b2                         # (32, 27)
print('h.shape', tuple(h.shape), '| logits.shape', tuple(logits.shape))
sat = (h.abs() > 0.99).float().mean().item()
print('fraction of |h| > 0.99:', round(sat, 3))
print('total parameters:', sum(p.nelement() for p in parameters))
pre = emb.view(-1, 6) @ W1                   # check the + b1 broadcast
out = pre + b1                               # (100,) acts as (1, 100)
print(tuple(pre.shape), '+', tuple(b1.shape), '->', tuple(out.shape))
print(torch.equal(out, pre + b1.view(1, 100).expand(32, 100)))

Why it beats the alternatives

✗ No hidden layer

logits = x @ W + b with W (6, 27): 54 + 162 + 27 = 243 parameters. Each context character adds its own fixed vote to the scores, so it can't express "m is likely only if the character before it was also m".

✗ Hidden layer without tanh

Two linear layers collapse into one: (x@W1 + b1)@W2 + b2 equals x@(W1@W2) + (b1@W2 + b2), a single (6, 27) layer. Checked on the 32 rows: max difference 5.3e-5, float rounding. 3,481 parameters, the power of 243.

✗ A count table over 3-char contexts

27³ × 27 = 531,441 counts, and only 28.9% of the 19,683 contexts ever occur in names.txt. Nothing is shared between similar contexts.

✓ Embeddings → tanh hidden layer → logits

3,481 parameters. Each of the 100 neurons reads all three characters together, tanh keeps the layers from collapsing, and every weight is shared across all contexts, so similar contexts get similar scores.

243 and 531,441 computed; 28.9% from the why-counts-explode lab; the collapse check ran in the scratch script with the lab's seed.

Is this hidden layer finished?

No: this init is careless, and the numbers show it. With plain randn weights, the preactivations have a spread (std) of 2.84, so 32.7% of the hidden values sit at |h| > 0.99. There tanh's local gradient, 1 − h², is below 1 − 0.99² = 0.0199, so those neurons barely learn. The logits are wild too (range −24.6 to 27.9), which is why the first loss is about 17 instead of 3.3. Karpathy leaves this for Lecture 4, which scales the weights down (the saturated-tanh and kaiming-init cards).

tanh isn't the modern default. It's what Bengio 2003 used. Most networks today use ReLU or GELU (GPT uses GELU in its feed-forward block), which don't flatten out for large positive inputs.

Understand and remember

  • a row's 3 embeddings laid side by side → one 6-number input x → x @ W1 lets every one of the 100 neurons weigh all three characters together → the hidden layer can react to combinations of characters, not just each one alone
  • no nonlinearity between two matmuls → (x@W1 + b1)@W2 + b2 equals one (6, 27) layer → 3,481 parameters with the power of 243 → tanh is what makes the hidden layer worth having
  • output layer must score every vocab entry → W2 is n_hidden × 27 = 2,700 of 3,481 (78%) → the output layer is the expensive one, and with Bengio's 17,000 words it dominates even more
  • plain randn weights + a sum over 6 inputs → preactivations with std 2.84 → 32.7% of h stuck near ±1 where the gradient 1 − h² is under 0.02 → those neurons barely learn (fixed by scaling the init in Lecture 4)
  • detail that matters + b1 broadcasts (100,) as a (1, 100) row copied down the batch → one bias per neuron, shared by all examples; a (32, 1) bias would also broadcast silently but give one bias per example, a bug with no error

4 · Compare against what you already know

vs One-hot inputs and a linear layer: The bigram net was one linear layer (27 × 27 weights) on a one-hot input. What is fundamentally different here, which design choice causes it, and how does each one fail?

Check
  • bigram: one layer, no hidden units, sees 1 character; its logits are just a looked-up row
  • MLP: 3 embedded characters, a tanh hidden layer, then an output layer
  • the hidden nonlinearity plus more context is what lets it combine characters
  • bigram fails by seeing too little context; the MLP fails by saturating (bad init) or by a too-small embedding

vs A neuron, backpropagated: micrograd built a neuron as a Python loop over inputs. How does x @ W1 + b1 relate to 100 of those neurons applied to 32 rows, and what do you gain and lose?

Check
  • each column of W1 is one neuron's weights, each entry of b1 its bias
  • the matmul computes all 32 × 100 weighted sums in one call
  • gain: speed and short code; lose: you no longer see individual neurons, so shape bugs replace logic bugs

5 · Predict commit to an answer before revealing

Keep the same plain randn init but grow the net to 10-number embeddings with 200 hidden neurons (W1 (30, 200)). On the same 32 rows, does the fraction of |h| > 0.99 go up, down, or stay near 0.327?

Reveal

Up, to 0.650. Each preactivation now sums 30 products instead of 6, so its spread grows: std 5.81 instead of 2.84 (computed with the lab's seed). Bigger inputs mean more saturation, which is why Lecture 4 scales W1 by gain/√(fan-in) (Kaiming init).
