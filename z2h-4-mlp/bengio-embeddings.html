Bengio 2003: characters as points in space

Also called: a neural probabilistic language model, an MLP language model, learned embeddings (the paper says "distributed feature vectors"). Lecture 3 · Bengio et al. 2003 (MLP language model) paper walkthrough · 0:01:48

Prime · 2 minutes before you read

The problem: A count table gives every context its own row, and the rows multiply as 27ⁿ. At 3 characters most rows are empty or nearly so, and nothing learned about one row helps any other.

Where it fits: The previous card showed the count table running out of data. This card is the fix Karpathy follows for the rest of the lecture: the one-hot-times-W idea from the bigram course, turned into a small learned table of points shared by every context.

  2. Which layer's size grows with the vocabulary, and why does that make it the expensive one?
  3. How can seeing .an during training change the prediction for .on, when the count table can't?
  4. Who decides where a and o sit in space, and what would put them close together?
  5. What does the tanh add that the lookup table alone could not?

In one breath: instead of a table with one row per possible context, give every token (a word in the paper, a character here) a short list of learned numbers, its embedding: a point in space. A small neural network reads the points of the last few tokens and predicts the next one. Training pulls tokens that behave alike close together, so what the model learns about one of them carries over to its neighbours, even in contexts it has never seen.

Predict first: Karpathy's walkthrough sizes are 17,000 words, 30 numbers per word, 3 context words and 100 hidden units. Which part holds the most parameters: the embedding table C, the hidden layer, or the output layer?

The output layer, by far: 1,717,000 of 2,236,100 (77%). It needs one weight from each of 100 hidden units to each of 17,000 words (100 × 17,000 = 1,700,000) plus 17,000 biases. C is 17,000 × 30 = 510,000, and the hidden layer only 90 × 100 + 100 = 9,100. Karpathy calls the output "the expensive layer". The character model has the same shape: 2,727 of its 3,481 parameters (78%) sit in the output layer.

Why points in space generalize

A count table treats every context as its own row. With 3 characters there are 27³ = 19,683 possible contexts, so a count table needs 19,683 × 27 = 531,441 cells, and in names.txt only 5,686 contexts (28.9%) ever occur, 3,374 of them fewer than 10 times (measured, why-counts-explode). What the table learns about .an says nothing about .on.

In the network, every context goes through the same weights, and the output changes smoothly as the input points move. If a and o end up close together, the network gives .an and .on similar predictions, so evidence for one helps the other. The paper's example is words: having seen "The cat is walking in the bedroom" should make "A dog was running in a room" more likely, because cat/dog, the/a and walking/running sit near each other (page 1140; 0:04:25). Nobody places the points. C starts random, and backprop moves each row along with the other weights.

count table, 3 chars: 19,683 rows × 27 = 531,441 cells this network: 54 + 700 + 2,727 = 3,481 parameters 531,441 / 3,481 ≈ 153× fewer numbers, shared by every context

Measured on your M3 later in this course (embeddings-scale-sample, 2-D model): after training, a sits 0.16 from o and 0.22 from e, while u sits 1.38 from the centre, the farthest of all 27.

Why it beats the alternatives

The paper scores models by test perplexity: e to the power of the average negative log likelihood, roughly how many words the model is torn between at each step. Lower is better. Numbers below are from its Table 1 (Brown corpus, page 1149).

✗ A longer count table

Rows grow as 27ⁿ (words: 17,000ⁿ). At 3 characters, 71% of the rows never get a single count, so the table has nothing to say about them.

✗ Smoothing and back-off n-grams

Fall back to shorter contexts when a row is empty. Better, but a and o are still unrelated symbols. Best Kneser-Ney back-off: test perplexity 321.

✗ Fixed word classes

Put each word in one hard cluster and count classes. Some sharing, but a word gets one class, chosen before training. Best: 500 classes, 312.

✓ Learned embeddings + MLP

Each token's position is learned with the predictor, and similarity is continuous. Test perplexity 252, about 24% below the best n-gram (that MLP is averaged with a trigram; alone it scored 276).

Does the model know what a vowel is?

No. Nothing tells it which characters are vowels. Two characters end up close only because they appear in similar contexts and push the loss the same way, so the layout depends on the data, the seed and the size. In 2-D it is rough: the video shows the vowels clustered with q and . as outliers, while this course's run on torch 2.14 puts u farthest out and . only fifth. The paper itself suggests trying 2 features "which can be more easily displayed" (page 1152); Karpathy then moves to 10 for accuracy.

It isn't always the right tool. With one character of context all 27 contexts are well covered, so the bigram count table is exact and instant. The MLP still sees a fixed window of 3 tokens, and its output layer gets expensive as the vocabulary grows: the paper's AP News run took about three weeks on 40 CPUs for 5 epochs. Longer contexts need the later models: WaveNet and then attention.

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • Count table: one independent row per context → rows grow as 27ⁿ → most rows see few or no examples (71% of 3-char contexts never occur) → no way to share what one row learned with another
  • Each token becomes a learned point in C → every context goes through the same smooth function of those points → tokens used alike get pushed close together by backprop → evidence about one context transfers to its neighbours, including unseen ones
  • Parameters scale with vocab × layer width, not with the number of contexts → the output layer (hidden × vocab) dominates: 1,717,000 of 2,236,100 for words, 2,727 of 3,481 for characters → the softmax over the vocabulary is where the cost goes
  • detail that matters C is shared by all 3 slots → the table stays 27 × 2 however long the context → but the slot a token arrived in is kept only by its position in the concatenated x, so W1 must learn a separate block per slot

Reference only

  • the paper's letters: y = b + Wx + U tanh(d + Hx), with W (direct connections) set to 0
  • the paper's column-vector Hx vs Karpathy's row-vector x @ W1 (W1 is H transposed)
  • Karpathy's walkthrough sizes: 17,000 words, 30 features, 3 context words, 100 hidden units
  • Table 1 perplexities: 252 (MLP mixed with a trigram), 276 (MLP alone), 312 (best n-gram), 321 (best Kneser-Ney)

  3. tradeoff You double the vocabulary but keep 30 features and 100 hidden units. Which parameter counts change, roughly by how much, and what does that say about scaling this model to big vocabularies?
    Check
    • C doubles (vocab × 30) and the output layer doubles (100 × vocab + vocab)
    • the hidden layer does not change (it depends on context × features and hidden size)
    • the output layer was already about 77% of the model, so cost grows almost linearly with the vocabulary; the paper needed about three weeks on 40 CPUs for 5 epochs of AP News
  4. tradeoff Why does a 3-character count table need 531,441 cells while the network needs 3,481 parameters, and what does the network give up in exchange?
    Check
    • the table stores 19,683 contexts × 27 next characters, one number per pair
    • the network reuses the same 3,481 weights for every context
    • in exchange it can't memorize each context exactly; it has to generalize through the shared points and may blur rare contexts

4 · Compare against what you already know

vs One-hot inputs and a linear layer: The bigram network multiplied a one-hot vector by W. How is looking up a row of C the same operation, and what changes when three looked-up rows go through a hidden layer instead of straight to the logits?

Check
  • one-hot(i) @ C picks row i of C, so the lookup is a linear layer with no bias and no nonlinearity
  • in the bigram, W is 27 × 27 and each row is directly the logits for one context char
  • here each row is only 2 numbers and a tanh layer mixes three of them, so the model can combine context and share structure between characters
  • cost: more to train, and a bad hidden layer can underfit where the bigram table was exact

vs Why a bigger count table fails: Both models predict the next character from 3 previous ones. Where does each one store what it learned, and how does each fail on a context seen only once?

Check
  • the count table stores one row of counts per context; the network stores shared weights and points
  • the table's row for a once-seen context is a single count, so it's all-or-nothing unless smoothed
  • the network predicts from nearby points, so a rare context borrows from similar ones; it can be wrong when the neighbours behave differently
