Seeing the embeddings, scaling up, sampling

Also called: plotting the embedding space, widening the embedding, generating (autoregressive sampling). Lecture 3 · visualizing the character embeddings · 1:05:27 · larger embedding size · 1:07:16 · sampling from the model · 1:13:24

Prime · 2 minutes before you read

The problem: A loss number tells you the model is better but not what it learned or where it is stuck. Without looking inside, you'd keep growing the wrong part of the network, and without sampling you never see what the model actually produces.

Where it fits: This closes Lecture 3. The splits card showed train ≈ dev (underfitting) and that 300 hidden neurons barely helped; here you find the real bottleneck in the embedding table C from the Bengio card, scale it, and reuse the multinomial sampling loop from the bigram course.

In one breath: after training, plot the 2-D table C and you can see what the network learned: vowels sit together, odd letters sit apart. Two numbers per character turn out to be the bottleneck, so give each character 10 numbers and the dev loss drops from 2.30 to 2.17. Then generate names by feeding the model its own output one character at a time.

Predict first: growing the hidden layer from 100 to 300 neurons (3,481 → 10,281 parameters) moved the dev loss only from 2.3279 to 2.2976, a drop of 0.03. Now use 10-number embeddings and 200 neurons instead: 11,897 parameters, just 16% more. Trained for the same 50,000 steps, does the dev loss drop by more or less than another 0.03?

More: about twice as much, to 2.2376 (a drop of 0.060). Tripling the neurons did little because every neuron still reads only 3 × 2 = 6 input numbers. The squeeze was in C, not in the hidden layer. Trained for the full 200,000 steps, the same net reaches dev 2.1698. (The 50,000-step 10-D run was computed in a scratch script with the lab's code and seeds.)

Step 1: look at what C learned

An embedding is the row of C that stands for one character; here each row has 2 numbers, so each character is a point on a plane. Nobody told the network which letters are alike. If two characters get used in similar contexts, the gradient nudges their rows the same way, and they drift together.

Step 2: widen the bottleneck

Every character's 2 numbers are all the hidden layer ever sees of it. Train and dev loss were nearly equal, which means the model is underfitting: too small to fit even the training data. Karpathy's guess is that 2 dimensions can't hold enough about each character, so he widens C to 10 columns. W1 must then take 3 × 10 = 30 inputs, and he trims the hidden layer to 200.

Step 3: sample names from the model

Sampling means generating text: start from ..., get the 27 probabilities for the next character, draw one at random in proportion to them (torch.multinomial), slide the 3-character window, and repeat until the model draws '.'. Each draw is fed back in as input, which is why this is called autoregressive.

When: pause the video at 1:11:46 (summary of the final code) and type this before watching the sampling part. It reuses Xtr, Ytr, Xdev, Ydev and itos from the splits card (seed 42 shuffle).

g = torch.Generator().manual_seed(2147483647)
C = torch.randn((27, 10), generator=g)       # was (27, 2)
W1 = torch.randn((30, 200), generator=g)     # 3 chars x 10 = 30 inputs
b1 = torch.randn(200, generator=g)
W2 = torch.randn((200, 27), generator=g)
b2 = torch.randn(27, generator=g)
parameters = [C, W1, b1, W2, b2]
for p in parameters: p.requires_grad = True
for i in range(200000):
    ix = torch.randint(0, Xtr.shape[0], (32,), generator=g)
    h = torch.tanh(C[Xtr[ix]].view(-1, 30) @ W1 + b1)   # (32, 200)
    loss = F.cross_entropy(h @ W2 + b2, Ytr[ix])
    for p in parameters: p.grad = None
    loss.backward()
    lr = 0.1 if i < 100000 else 0.01               # step decay
    for p in parameters: p.data += -lr * p.grad
@torch.no_grad()
def split_loss(X, Y):
    h = torch.tanh(C[X].view(-1, 30) @ W1 + b1)
    return F.cross_entropy(h @ W2 + b2, Y).item()
tr, dev = split_loss(Xtr, Ytr), split_loss(Xdev, Ydev)
print(f'train {tr:.4f} | dev {dev:.4f}')
g = torch.Generator().manual_seed(2147483647 + 10)
for _ in range(20):
    out, context = [], [0] * 3               # start from '...'
    while True:
        emb = C[torch.tensor([context])]     # (1, 3, 10)
        h = torch.tanh(emb.view(1, -1) @ W1 + b1)
        probs = F.softmax(h @ W2 + b2, dim=1)
        ix = torch.multinomial(probs, num_samples=1,
                               generator=g).item()
        context = context[1:] + [ix]         # slide the window
        out.append(ix)
        if ix == 0:
            break
    print(''.join(itos[i] for i in out))

Why it beats the alternatives

✗ More hidden neurons

100 → 300 neurons adds 6,800 parameters and cuts dev by only 0.03 (2.3279 → 2.2976). Each neuron still reads the same 6 numbers, so the extra neurons have nothing new to work with.

✗ Just train the 2-D net longer

200k steps instead of 50k takes the 2-D, 300-neuron net to dev 2.2283. A real gain, but the 10-D net trained for the same 200k steps reaches 2.1698.

✗ Back to counting 3-char contexts

A count table has 27³ = 19,683 rows and only 28.9% of them ever occur in names.txt, so most contexts have nothing to count. Nothing learned about one context helps a similar one.

✓ Wider embeddings (2 → 10)

11,897 parameters, 16% more than 10,281, and 0.06 lower dev at both training lengths. Each character now carries 10 learned numbers into the hidden layer.

28.9% is from the why-counts-explode lab. Karpathy's video reaches about 2.23 / 2.24 with the 300-neuron net after longer training; the 2.2144 / 2.2283 here agrees.

Can you trust the picture and the samples?

The picture is of the 2-D model, not the final one. A 10-D C can't be scattered directly, and its clusters needn't match. In the trained 10-D model, e, i, o and u are each other's nearest neighbours (distances 0.69–0.98), but a sits far from all of them (its nearest is b, at 3.07). Different seeds and torch versions also move the points, as u did here. Read the plot as a sanity check that similar characters were grouped, not as the model's truth.

Nice samples don't prove a good model. 6 of the 20 (amorie, rey, kaeli, kaleigh, quint, jace) are names straight from names.txt, and wazthoniearyxi. shows the 3-character window forgetting the start of a long name. The dev loss is the real score. Beating 2.17 needs other changes: Karpathy lists the hidden size, embedding size, context length, steps, learning rate schedule and batch size. The next lecture starts by fixing the initialization: the first minibatch loss here is 27.88, where a uniform guess would give 3.30.

Understand and remember

  • characters used in similar contexts → receive similar gradients on their rows of C → their embeddings drift together → the model can reuse what it learned about one for the other (vowels cluster)
  • every hidden neuron reads only the 3 × d embedding numbers → with d = 2 that's 6 numbers, whatever H is → more neurons (100 → 300) gain only 0.03 dev → widening C to d = 10 (30 inputs) gains 0.06 at the same step count with 16% more parameters
  • train ≈ dev → underfitting → grow capacity; after scaling, train 2.1268 vs dev 2.1698 → a gap opens → the model is starting to overfit, so further growth needs more data or regularisation, not just size
  • sampling draws ix from the model's own probabilities → appends it and slides the 3-char window → the next prediction conditions on its own output → names emerge one character at a time, and anything older than 3 characters is forgotten (wazthoniearyxi.)
  • detail that matters torch.multinomial draws in proportion to the probabilities instead of taking the argmax → low-probability picks happen (p('c') = 0.043 at step 1) → variety; argmax would give the same name every time

Reference only

  • the seeds 2147483647 (init) and 2147483647 + 10 (sampling)
  • the exact per-tensor counts 270 + 6,000 + 200 + 5,400 + 27
  • the schedule 100k steps at lr 0.1 then 100k at 0.01, batch 32
  • plt.scatter(C[:, 0].data, C[:, 1].data) and plt.text for labels
  • notebook numbers 2.1260 / 2.1701 vs torch 2.14's 2.1268 / 2.1698
