Checkpoint 1: what one decode step costs

Ties together sampling and the KV cache, the roofline, linear layers and the critical batch size, attention's arithmetic intensity and the step-time formula: why a decode step is bound by bytes, which bytes are shared and which aren't, and how that becomes the one equation of LLM serving.

How to use this page. Close the five cards. Answer each question in writing, in full sentences, before opening its Check. A wrong or shaky answer isn't a failure; it tells you exactly which section to reopen. The questions are mixed on purpose, so you have to work out which idea applies before you can answer.

1 · Mixed retrieval

  1. which concept?A team serves Llama-3.1-8B at batch 1 on an H100 and sees the MLP matmuls using about 0.3% of peak FLOPs. They switch the matmuls to fp8 but keep the weights in bf16, and expect each token to arrive faster. Which idea predicts what happens, and what should they have changed instead?
    Check
    • at batch 1 the step is bound by reading the weights (35 µs of bytes vs 0.12 µs of math on one MLP matrix), so faster math changes nothing
    • faster math on the same bytes doubles the ridge (295 → ≈ 591): the step is further from compute-bound
    • fix: quantize the weights (fp8 × fp8 halves the bytes and the step; weight-only fp8 also lowers Bcrit to ≈ 148)

    Missed it? Reopen linear layers and the critical batch size, "Precision changes Bcrit (β)".

  2. A bf16 matmul X[1,024, 4,096] · Y[4,096, 4,096] runs on one TPU v5e. Give Tmath, Tcomms, the lower and upper bound on its time, and the regime.
    Check
    • FLOPs 2·1024·4096·4096 = 3.436e10 → Tmath = 174.4 µs at 1.97e14
    • bytes 2(BD + DF + BF) = 5.033e7 → Tcomms = 61.4 µs at 8.2e11
    • lower bound max = 174.4 µs, upper bound sum = 235.8 µs; compute-bound (intensity 682.7 > 240)

    Missed it? Reopen the roofline, worked example 2.

  3. which concept?On one H100 at 2k context, raising the decode batch from 32 to 64 sequences takes throughput from 4,349 to 6,450 tokens/s: 1.48×, not 2×. The weights didn't change. Which idea explains the missing half, and would the gap shrink or grow at 8k context?
    Check
    • each sequence reads its own KV cache; attention's intensity doesn't rise with batch, so the KV term grows linearly with B (2.56 → 5.13 ms)
    • only the 4.79 ms weight read is shared, so the step goes 7.36 → 9.92 ms
    • at 8k each sequence brings 4× the KV bytes, so the gap grows (and B = 64 no longer even fits)

    Missed it? Reopen attention's arithmetic intensity, "Running example: which bytes dominate", and the step-time formula, the H100 table.

  4. Llama-3.1-8B has 32 query heads sharing 8 KV heads. What is its decode attention intensity at 8k context, why doesn't a bigger batch change it, and how far is it from the H100's ridge?
    Check
    • with GQA, decode intensity → G = N/K = 4 (3.998 at S = 8,192)
    • B cancels: every sequence adds FLOPs and KV bytes at the same rate
    • about 74× below 295, so decode attention is memory-bound at any batch

    Missed it? Reopen attention's arithmetic intensity, "With GQA: intensity → G".

  5. which concept?A colleague says: the KV cache cut the FLOPs for a 1,000-token prompt plus 200 generated tokens by 183×, so generation must be about 183× faster. Which idea shows why that's wrong, and roughly what is the real speedup on an H100?
    Check
    • FLOPs fell 183×, but each cached generation step still streams all 16.06 GB of weights for ≈ 16 GFLOP of work: memory-bound
    • time is set by max(FLOPs ÷ peak, bytes ÷ bandwidth), and the bytes didn't fall 183×
    • floors: 3.57 s naive vs 0.979 s cached, about 3.6×

    Missed it? Reopen sampling and the KV cache, "But wall-clock time doesn't fall 183×".

  6. Work the book's Pop Quiz at batch 4: a 30B dense model in int8 with bf16 math on a TPU v5e 4x4 (16 chips), 8,192 context, 100 kB of KV per token. Which term dominates?
    Check
    • W = 16 × 8.2e11 = 1.312e13 B/s; KV per sequence 819 MB
    • KV 4 × 819 MB ÷ W = 0.25 ms; MLP max(math 0.08 ms, weights 30 GB ÷ W = 2.29 ms)
    • ≈ 2.54 ms (book: 2.5 ms); the weight read dominates at this small batch

    Missed it? Reopen the step-time formula, "The book's Pop Quiz, worked".

  7. Prefill of a 1,000-token prompt and decode at batch 1 both run through the same weight matrices. Why is the first compute-bound and the second memory-bound, and at what prompt length does prefill attention (plain MHA) turn compute-bound on an H100?
    Check
    • prefill puts all 1,000 tokens in one step, so B = 1,000 > Bcrit = 295 for the linear layers
    • decode puts one token per sequence in the step: B = 1, intensity ≈ 1
    • prefill attention has intensity T/2, which passes 295 at T ≈ 590 (480 on v5e)

    Missed it? Reopen the critical batch size, "What batch means", and attention's intensity, "Intensity vs the ridge".

3 · Project: build and validate a step-time calculator

What it reinforces: Tmath vs Tcomms (the roofline), the weight read shared by the batch and Bcrit (critical batch size), the per-sequence KV read that never turns compute-bound (attention's intensity), KV bytes per token (the KV cache), and the whole formula (step time).

In about 30 lines of Python, with no lab code copied:

  1. Inputs. A function step(params, bytes_per_weight, kv_bytes_per_token, context, B, chips, flops_per_chip, bw_per_chip) that returns the KV term, the weight term, the math term, the step and tokens/s.
  2. Validate on the book. Reproduce the Pop Quiz: 30B int8, 100 kB/token, 8,192 context, 16 v5e chips, B = 4 and B = 256.
  3. Validate on the H100. Llama-3.1-8B bf16 (8.03e9 params, 131,072 B/token), 2,048 context, B = 1, 128 and 238.
  4. Add a memory check. Refuse any B whose weights plus KV exceed 80 GB, and report the largest B that fits.
  5. Find the crossovers. Solve for the B where the KV term equals the weight term, and the B where the math term equals the weight term. Which one does HBM let you reach?
  6. One what-if. Halve the KV bytes (FP8 KV) at 8k context and full batch. What happens to the batch and to tokens/s?
Done when: your calculator reproduces the Pop Quiz and the H100 rows within 1%, rejects B = 256 at 2k, prints both crossovers, and you can say in one sentence why the FP8-KV what-if roughly doubles throughput without shortening the step. Then compare with the check.
Check: the numbers (from the cards' labs)
  • Pop Quiz: B = 4 → 0.25 + max(0.08, 2.29) ≈ 2.54 ms. B = 256 → 15.98 + max(4.87, 2.29) ≈ 20.86 ms (book: 2.5 and 21 ms).
  • H100, 2k: B = 1 → 4.87 ms, 205 tok/s; B = 128 → 10.26 + 4.79 = 15.05 ms, 8,505 tok/s; B = 238 → 23.86 ms, 9,973 tok/s. B = 256 needs 68.7 + 16.06 = 84.8 GB: rejected.
  • KV = weights at B = 16.06 GB ÷ 268.4 MB ≈ 59.8 (2k) and ≈ 15.0 (8k). Math = weights at B ≈ 295, but HBM stops you at 238 (2k) or 59 (8k).
  • FP8 KV at 8k: KV per sequence 1.07 → 0.54 GB, so 119 sequences fit instead of 59; HBM is still full, so the step stays ≈ 23.9 ms, and throughput goes 2,489 → ≈ 4,986 tok/s.
