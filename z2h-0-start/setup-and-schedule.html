Setup and study schedule

Also called: the shifts table, the time budget. How to set up once, then how long each lecture really takes: video time × 2–3 for coding along, plus the real run times measured on an M3.

Prime · 2 minutes before you read

The problem: A course sized by its video length (18 h 38 min) gets planned as two weekends and falls behind from the first lecture. And a laptop plan that doesn't know which run needs a GPU either stalls at the last lecture or rents hardware that sits idle for weeks.

Where it fits: Second card of the series map. It turns the loop from How to use this course into hours and sittings, and it summarises the setup card in the toolkit (z2h-1) that every lab depends on.

In one breath: build one Python 3.10 environment with torch 2.14 and prove it works in one two-second run. Then plan on about 37.3–55.9 hours for the 18 h 38 min of video. Only one run in the whole series, the full GPT-2 training, needs a rented GPU (about 1–2 h, about $10).

Predict first: which lecture's own code takes longest to run on a laptop: micrograd, WaveNet, GPT or GPT-2? And by roughly how much?

GPT-2, by a factor of thousands. Every micrograd lab finishes in under 2 s, and WaveNet's final model takes 147 s. The full GPT-2 run is 10.00B tokens at about 1,300 tokens/s on the M3, which is about 89 days. That's the one run you rent a GPU for.

The one run that needs a rented GPU

In the last lecture, the real training run is 19,073 steps of 219 tokens = 10.00B tokens. Everything else in that lecture (writing the model, loading OpenAI's weights, sampling, a short --quick training run, the HellaSwag eval) runs on the M3.

The M3 speed was measured by the z2h-10 labs (1,100–1,550 tok/s across runs). The day and hour figures are 10.00B ÷ speed, computed in labs/results.py, which prints 89.0 days and 1.9 h without evals. The $10 is the README's figure, and it's the one the z2h-10 cards cite. For a second source, llm.c's write-up of the same model is titled "Reproducing GPT-2 (124M) in llm.c in 90 minutes for $20" (May 2024). Prices change, so check your provider's current hourly rate.

Why it beats the alternatives

✗ Budget by video length

18 h 38 min sounds like two weekends. Typing along makes it roughly 2–3×, so a plan built on the video length falls behind from the first lecture.

✗ Rent a GPU from day one

Pointless for L1–L6: those nets are tiny, and on the CPU the seeded numbers match the notebooks. You'd pay for idle time while you type.

✗ Use Colab for everything

Fine for a single lecture, but you lose the local environment the labs' outputs were measured on, and a different torch or device changes the numbers you see.

✓ Laptop first, GPU for one run

All 9 lectures run on the M3 except one training run, which costs about $10 on a rented 8×A100. Rent it only after the laptop --quick run works end to end.

When the times won't match yours

Timings depend on what else your machine is doing. The same lab ran 56 s alone and over 8 min on a heavily loaded machine. Losses and parameter counts don't depend on load, so treat those as exact and the times as guides. For the long runs (the full gpt.py, the HellaSwag eval, the 200k-step makemore runs), start them before a break.

5 · Predict commit to an answer before revealing

Suppose the rented node were 8×H100 instead of 8×A100, and it ran the same script at about twice the tokens per second. Before computing: would you expect the cost of the run to halve, stay the same, or something else?

Reveal

Not necessarily halve: the time halves (about 1 h instead of about 2 h), but an H100 node usually rents for more per hour than an A100 node, so the cost depends on the price ratio. Roughly, cost = hours × hourly rate, so it comes down only if the rate less than doubles. For comparison, nanochat's README prices an 8×H100 node at about $24/h.
