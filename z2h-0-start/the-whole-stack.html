The whole stack in one sketch

Also called: the factory line, the series map. The whole series as one assembly line, from a single number that remembers its history to a GPT-2 you trained yourself. Each station is a course.

Prime · 2 minutes before you read

The problem: Nine lectures in a row can feel like nine separate topics. Without the line that connects them, you can't say why BatchNorm comes before WaveNet, or what GPT-2 reuses from micrograd, and each new lecture feels like starting over.

Where it fits: Third card of the series map. It places every course on one factory line, so each later course's Prime ("where it fits") points back to a station you've seen here.

In one breath: each lecture adds one idea on top of the last. The first four stations build an autograd engine on single numbers. The next five move to tensors and grow a character-level language model from a table of counts to a Transformer. The last two turn it into a real GPT-2: real tokens and a real training run.

Predict first: the bigram model, the MLP, WaveNet and the Transformer all predict the next character. What is the one thing that changes most from station to station?

How much context the model uses, and how it combines it. The bigram sees 1 previous character. The MLP sees 3, concatenated. WaveNet fuses 8 in a tree. The Transformer lets each of 256 positions look back at all the earlier ones with attention. The loss, the training loop and backprop stay the same throughout.

Three threads that run the whole length

1 · Backprop never changes

The chain rule you do by hand at z2h-2 is what loss.backward() does at z2h-10. z2h-6 makes you prove it on tensors.

2 · The loss keeps falling

On names: 2.454 (counts) → 2.1701 (MLP) → 2.1057 (BatchNorm) → 1.9937 (WaveNet). Each drop comes from one change you can name.

3 · Context keeps growing

1 character → 3 → 8 → 256 characters → 1,024 tokens. Most of the architecture is about how to combine more context.

✓ The payoff

At z2h-10 nothing is new in principle. It's the same loop, run at scale, with engineering to make it fast. That's why the order matters.

What the sketch leaves out

The line looks straight, but the dependencies aren't all linear. The tokenizer (z2h-9) needs only z2h-8's first cards, so it can come earlier, and z2h-6 (backprop by hand) is recommended rather than required for z2h-7. The line also stops at pretraining: turning GPT-2 into a chat assistant (finetuning, RL) is outside this series. Where next points to it.

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • Every station keeps the same loop (forward → loss → backward → update) → only the model or its conditioning changes → each loss drop can be traced to one named change
  • More context per prediction → better next-character guesses → 2.454 (1 char, counts) → 2.1701 (3 chars, MLP) → 1.9937 (8 chars, WaveNet) → the Transformer's attention lets every position use all earlier ones
  • Deeper nets train badly at init → Kaiming init and BatchNorm (z2h-5) keep activations healthy → the deeper WaveNet and Transformer become trainable
  • The micrograd graph and loss.backward() compute the same thing → z2h-6 proves it on tensors → at z2h-10 backprop is taken for granted and the work is speed and scale
  • detail that matters The tokenizer is its own stage with its own training → it decides what a "token" is before the GPT sees anything → which is why it can be studied right after z2h-8's first cards

3 · Retrieve from memory, card closed
  1. concept Explain why the series starts with an engine for single numbers instead of going straight to tensors, even though nobody trains real nets on scalars.
    Check
    • each scalar op has a derivative you can check by hand
    • backprop is the same algorithm on tensors, just batched
    • so every later loss.backward() is something you've already built and understood
  2. mechanism Trace one training step's journey along the line from the MLP language model (z2h-4) to WaveNet (z2h-7): what gets added to the model, and what stays the same?
    Check
    • z2h-4: embeddings, a tanh hidden layer, 3 characters of context
    • z2h-5: Kaiming init and a BatchNorm layer, plus diagnostics
    • z2h-6: the same net, backprop by hand (the model doesn't change)
    • z2h-7: 8 characters of context fused in a tree, torch.nn-style layers
    • the same: cross-entropy loss, minibatch SGD, the names dataset
  3. tradeoff Someone wants to skip z2h-5 and z2h-6 to reach GPT sooner. What would they lose, and which of the two is the safer skip?
    Check
    • z2h-5: why deep nets fail at init and how normalisation fixes it, which the Transformer's LayerNorm and init rely on
    • z2h-6: fluency with tensor gradients, which you rarely need to write once autograd exists
    • z2h-6 is the safer skip (the series marks it recommended, not required, for z2h-7)

Why this step?

5 · Predict commit to an answer before revealing

Imagine a 13th station after GPT-2 that just makes the model 10× bigger with the same data and code. Commit first: which part of the line would you have to revisit, and which would you not touch?

Reveal

You'd revisit the speed and scale parts of z2h-10 (memory, batch size, multi-GPU, the learning-rate recipe) and possibly init, because deeper and wider nets are exactly what z2h-5's lessons are about. You wouldn't touch backprop (z2h-2, z2h-6), the loss, or the tokenizer. The architecture stays a Transformer (z2h-8), just with more layers and heads. That's why the line is worth learning in order: scaling reuses it rather than replacing it.
