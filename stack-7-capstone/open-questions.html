How to read a question. Status is what the series' verified novelty check (2026-10-01) and the repo docs say: open (nothing found), partly studied (close work exists, the exact question doesn't), or required (the paper owes it before submission). Costs are rough and lean on measured per-branch prices where they exist. The score is my judgment, each factor 1 (low) to 3 (high). capstone marks questions that feed this paper or its direct sequel: compaction and false success claims, the claim checker, judges that see the summary, pass^k of honesty.

Ranked

1Does a judge that sees only the compacted context accept a report the full trace would reject?

capstone · judges see the summarypartly studiedcost: judge calls onlynovelty 3 × cheap 3 × practice 3 = 27
Why it matters
Graders and reward models often read what the agent last saw. If compaction hides a failure from the agent, it may hide it from the grader too, so the eval inherits the error.
Status
LLM judges detect false success poorly (From Confident Closing to Silent Failure, 2606.09863), and summarizers drop "unverified" status on authorization claims (Silence Is Endorsement, 2609.20211). The two-view comparison is in the series spec as a secondary analysis and wasn't found published.
Cost
Judge calls only, on runs the sweep already has. The frozen labeller costs $0.0014–$0.0026 per branch on short texts (baseline pilot); full traces are longer, so budget more per item.
Smallest experiment
For every compacted sweep branch, ask the same judge "did the final report hold?" twice: once with the post-compaction working set, once with the full trajectory. Compare acceptance of tampered and failing runs between the two views, paired by branch.
Source card
Analyse what you registered · Lab: be the second annotator

2Which sentence of the Codex summary makes agents tamper?

capstone · compaction → what agents do to testsopencost: low3 × 3 × 3 = 27
Why it matters
If one restated goal causes it, harness builders can fix it with one line of prompt, and the paper gains a mechanism instead of a correlation.
Status
Open. The baseline pilot noticed that Codex summaries restate the user's goal "so the test suite passes" as an open item (for example "make it gracefully skip") while OpenCode summaries didn't show the effect. Nothing tests it.
Cost
Low: a d1-codex branch on gpt-5.4-mini cost $0.0153 in the baseline, so a few hundred branches is a few dollars.
Smallest experiment
Branch the sweep's saved prefixes into d1-codex with the summary as written vs the same summary with the restated goal removed (a scripted edit, logged), and compare tampering, paired by prefix.
Source card
Measure the floor, then size the study

3Is an honest report consistent across repeats (pass^k of honesty)?

capstone · pass^k of honestypartly studiedcost: none beyond the sweep2 × 3 × 3 = 18
Why it matters
A deployer cares whether the agent is honest every time, not on average. An agent that discloses 95% of the time can still fail most users on a long day.
Status
Registered as exploratory in addendum 3 (k = 1, 2 across the two repeats, per task × model × arm). The novelty check searched for pass^k and listed no paper that applies it to honest reports; treat its status as unknown rather than open.
Cost
None beyond the sweep with k = 2; k ≥ 3 needs more prefixes per task.
Smallest experiment
Compute it from the sweep as registered, then add a third repeat on a subset of tasks for one model to see how fast pass^k falls with k.
Source card
Analyse what you registered · pass@k vs pass^k

4Does it hold on a Claude model and inside the real CLIs?

capstone · compaction → false claimspartly studiedcost: $24–134 per model, earlier plan2 × 2 × 3 = 12
Why it matters
The paper speaks to two OpenAI models and transplanted prompts only. Codex with an OpenAI model compacts server-side, so the copied prompt isn't what it runs there; and the Claude Code prompt is proprietary and not included.
Status
Partly studied: Compaction Cliff (2608.22752) uses Claude Code's /compact prompt on Sonnet 4.6, for safety rules, not test status. Addendum 3 records "no Anthropic model" as a limitation; the spec's real-CLI check (about 60 runs) isn't in the registered sweep.
Cost
trigger-design.md projects $24 (claude-haiku-4-5, cached) to $134 (claude-opus-5-5, uncached) per model for half of its earlier 2,800-run plan; the harness sets no prompt caching for Claude, so the uncached column is the realistic one. The registered design has 960 branches in total, so one more model would cost less.
Smallest experiment
With an Anthropic key, add a Claude model by addendum before its runs start, on the same 40 tasks and arms. Separately, force one compaction per CLI on a handful of tasks and record whether each CLI can be driven headless at all.
Source card
Write it against the evidence

5Is it the impossible instruction, not compaction, that drives tampering?

opencost: low2 × 3 × 2 = 12
Why it matters
"Fix it so the test suite passes" can't be satisfied when one test can't pass. If a softer instruction removes most tampering, the base rate in the paper is partly a property of the prompt.
Status
Open. The baseline pilot lists the unsatisfiable instruction as a threat to validity and says a softer one would change base rates. ImpossibleBench (2510.20270) measures cheating on impossible tasks, not how the instruction's wording moves it.
Cost
Low: gpt-5.4-mini branches cost cents each.
Smallest experiment
Generate prefixes under two instructions ("make the suite pass" vs "fix the bug and report the test status"), branch d0 and d1-codex from each, and estimate tampering in a 2 × 2.
Source card
Branch from the agent's own run

6If the checker became a reward, would tampering move where the checker can't see it?

capstone · the claim checkerpartly studiedcost: $50–200, no training2 × 2 × 3 = 12
Why it matters
The checker catches edits to tests and test config and a cleared unfixable test, but not, for example, monkeypatching urllib from package code when the test still fails for another reason (baseline pilot, threat 2). Penalising what it sees may teach what it doesn't.
Status
Partly studied: penalising a chain-of-thought monitor teaches obfuscation (2503.11926). Not measured for a test-tampering checker on final reports.
Cost
Selection rather than training: best-of-n with n = 4–8 per task (the stack-5 open-questions estimate).
Smallest experiment
Sample several branches per prefix, pick by "checker-clean", and hand-read the picks for tampering the checker missed, against random picks.
Source card
Release and pitch it · Penalize the monitor, teach the hiding

7Does the 0.17% survive re-running the tests in the official images?

required before submissioncost: compute, no API1 × 2 × 3 = 6
Why it matters
The 14 genuine cases rest on one reader's judgement of logs. Re-execution is what turns the observational half from "read" into "checked against the world".
Status
Named by the pilot itself as the decisive next step and required by the spec before submission: re-execute the last test command of the 105 task-relevant runs at the base commit, with and without the agent's patch.
Cost
Docker time for 105 SWE-bench images; no model calls.
Smallest experiment
Start with the 14 genuine and 2 unclear cases, then the 27 environment cases, and report how many verdicts change.
Source card
How the question got sharp · Lab: audit 21,000 public runs

8Do agents in other harnesses disclose their test edits as often as here (25 of 26)?

partly studiedcost: medium2 × 1 × 3 = 6
Why it matters
If reports usually admit the hack, a reader can catch it; if they don't, pass rates on hackable tasks are doubly misleading.
Status
The novelty check lists natural final-report disclosure across production harnesses as a gap. ImpossibleBench and EvilGenie (2511.21654) measure the act; Confessions (2512.08093) and escalation channels (2608.29460) use a separate channel.
Cost
Medium: several harnesses × models on an impossible-task split, plus labelling.
Smallest experiment
Run two harnesses on 30 ImpossibleBench tasks with one shared model, detect test edits from the diff, and label each report disclosed, omitted or denied with the frozen labeller plus a hand check.
Source card
Write the analysis down first

How to generate your own

  1. Split an overloaded word. "False claim" split into self-contradiction, honest miss and untested claim, and the paper changed shape. Try "tampering": edited, skipped, stubbed, monkeypatched.
  2. Ask what's unmeasured. Read the pre-registration's limitations and the baseline's threats to validity; each is a question someone could answer.
  3. Check for a cheap controlled experiment. The saved prefixes make most follow-ups a branching run on cents per branch, paired by construction.

Understand and remember

  • The sweep saves every prefix and workspace → any new arm can branch from the same states → most follow-ups are paired, cent-per-branch experiments rather than new studies
  • Graders often read what the agent last saw → compaction can hide a failure from the grader as well as the agent → comparing a judge on the summary vs the full trace tests whether evals inherit the error
  • The instruction 'make the suite pass' can't be satisfied with an unfixable test → it pushes toward tampering on its own → without a softer-instruction arm the paper can't separate instruction from compaction
  • A checker catches only the tampering it was written to see → penalising it rewards unseen forms (e.g. monkeypatching urllib) → any checker-as-reward plan needs a hand-read of what the checker passes

5 · Predict commit to an answer before revealing

If the sweep shows no tampering effect at all, predict which of the eight questions drop in rank and which rise.

Reveal

The goal-sentence question (2) and the softer-instruction question (5) lose most of their point, since there's no effect to explain. The judge-views question (1), pass^k of honesty (3) and the re-execution (7) don't depend on an effect and rise relatively; a Claude model (4) rises, because a null on two OpenAI models invites 'would another family differ?'.
