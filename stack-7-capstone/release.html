Release and pitch it

Step 8 of the capstone, also called the artifact release or the data and code statement. You sort every file into "publish", "point to" and "keep", check that the labels you release hold ids rather than other people's text, size the run tarball, and write the one-paragraph pitch plus three figures you'd show a lab researcher. Posting anything is the author's decision; this card prepares it, it doesn't do it.

Prime · 2 minutes before you read

The problem: A paper whose code and data can't be checked is hard to trust, but a release that pushes everything can redistribute other people's data without permission. Without sorting files by who made them and under what terms, you either hide your evidence or ship something you had no right to ship.

Where it fits: The last step of the capstone. It takes the licensing caveat first met in Lab: audit 21,000 public runs and the figures from Write it against the evidence, and turns them into a release list and a pitch.

In one breath

A paper's release is three piles. You publish what you made: code, aggregate numbers, per-submission rates, the task generator and your own labels keyed by ids. You point to what others made and didn't license for redistribution: the public SWE-bench trajectories, through the fetch script that downloads them. You keep anything whose terms you can't confirm. Then you say the result in one paragraph a lab researcher can check against three figures. Whether and when it goes to arXiv or a public GitHub repo is the author's call.

Step 2 · Check the labels hold ids, not text

Every label keyed by (submission, instance_id)5 min

The licensing position only works if what you release can't reconstruct the trajectories. Print each block of the label file with its key format and value types.

cd /tmp/rel/cc && python3 - <<'EOF'
import json
from collections import Counter
d = json.load(open("pilot/handlabels.json"))
for name, block in d.items():
    if not isinstance(block, dict):
        print(f"{name:28} note, {len(block)} chars")
        continue
    vals = Counter(type(v).__name__ for v in block.values())
    ok = all("|" in k for k in block)
    print(f"{name:28} {len(block):3} keys  id-keyed {ok}  {dict(vals)}")
EOF

Step 3 · Size the run tarball

Compress runs without writing a file5 min

Each run folder keeps a copy of the agent's workspace (work/, and prefix_work/ for prefixes). Those are regenerable from the task and the diff, so leave them out and stream the archive to wc to measure it.

cd ~/Desktop/repos/compaction-claims/runs
du -sh pilot-baseline-20261001-161616
tar czf - --exclude work --exclude prefix_work \
    pilot-baseline-20261001-161616 | wc -c |
  awk '{printf "%.1f MB compressed, workspaces excluded\n", $1/1e6}'

Step 4 · Write the pitch and the three figures

A lab researcher reads one paragraph and looks at the figures. The paragraph says what's new, what you found, and what a harness builder should change. Two of its sentences are ready now; one waits for the sweep.

Coding agents' "done, tests pass" is wrong for many reasons, and we split them: in 21,438 public SWE-bench Verified runs, honest misses (15.6% of success claims) outnumber genuine self-contradiction (0.17%) about 90 to 1, and 36.7% of claims follow no test run at all. We then test one cause directly: we branch each agent from its own run at a failing test it cannot fix, compact the history with Codex's or OpenCode's real prompt, and compare with the same state uncompacted, under a pre-registered analysis. Why three piles beat the alternatives

✗ Push everything

Redistributes 7.1 GB of trajectories from a repo with no licence and an unanswered redistribution issue, plus text dumps quoted from them.

✗ Release only the PDF

No one can check the 14 hand-verified cases or re-run the sweep, which defeats the point of pre-registering it.

✗ Ship the Claude Code prompt too

It's proprietary and lives only in a compiled binary; including it would put the whole code release at risk for one arm the study doesn't have.

✓ Publish, point to, keep

Everything you made is checkable, everything others made is one fetch.py away, and the labels join the two by id.

Honest caveat. This is a practical position, not legal advice: it follows what pilot/results.md §6 recorded on 2026-10-01, and the terms can change (issue #462 may get an answer). Short quotations of agent messages in the paper are fine under that position; longer excerpts are not. And the pitch is only as strong as its pending sentence: if the sweep is null, the paragraph leads with the decomposition and states the bound, rather than reaching for the exploratory tampering lead.
