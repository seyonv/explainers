Checkpoint 1: what one token costs

Ties together the transformer forward pass, attention and GQA and FLOPs per token: from a model's config to the parameters it stores, the KV cache each request carries, and the arithmetic each token costs.

How to use this page. Close the three cards. Answer each question in writing, in full sentences, before opening its Check. A wrong or shaky answer isn't a failure; it tells you exactly which section to reopen. The questions are mixed on purpose, so you have to work out which idea applies before you can answer.

1 · Mixed retrieval

  1. which concept?Your 8k-context chat service on one H100 fits only 14 concurrent users with a model you trained in-house. A colleague's model, same size and also with 32 query heads, fits 59. Which idea explains the difference, and can your serving engine close the gap with a setting?
    Check
    • the KV-head count: yours is MHA (32 KV heads, 512 KiB per token), theirs GQA-8 (128 KiB)
    • an 8k sequence is 4.29 GB vs 1.07 GB, so 63.9 GB of free HBM holds 14 vs 59
    • no engine setting: the KV-head count is architectural, so the model has to be uptrained into GQA (mean-pool each group's K/V projections, then about 5% more pretraining in the paper's recipe)

    Missed it? Reopen attention, "Heads, and why the KV head count sets memory" and "What GQA does not do".

  2. Recompute the "cat" row of the attention worked example (dk = 4): the scaled and masked scores, the weights, and the output vector.
    Check
    • raw scores against The, cat, sat: 0, 1, 2; ÷ √4 → 0.0, 0.5, and "sat" is masked to −∞
    • softmax over the two visible scores: 0.378 and 0.622
    • output = 0.378·V[The] + 0.622·V[cat] = [0.378, 1.245, 0.000, 0]

    Missed it? Reopen attention, the worked example, steps ② to ④.

  3. One token goes through Llama-3.1-8B's Wdown (14336 × 4096). How many FLOPs is that, and why does the sum over every matrix in the model come to 93.5% of 2N rather than 100%?
    Check
    • 2 · 1 · 14,336 · 4,096 = 117.44 MFLOP: exactly 2 × its 58.72M parameters
    • all matmuls together: 15.01 GFLOP against 2N = 16.06 GFLOP
    • the gap is the 525M-parameter embedding table: a row lookup costs no FLOPs, but it still counts in N

    Missed it? Reopen FLOPs per token, steps 1 and 2.

  4. which concept?A startup budgets training for a DeepSeek-V3-like model as 6 × 671B × tokens, and plans its serving memory as 37B × 2 bytes. Which idea did they apply backwards, and what should each budget use?
    Check
    • total vs active parameters in a mixture of experts
    • compute follows the active parameters: 6 × 37B per training token, 2 × 37B = 74 GFLOP per served token (not 1,342, an 18× overcount)
    • memory follows the total: all 671B must be stored, because any token can be routed to any expert

    Missed it? Reopen FLOPs per token, "Total vs active params", and the forward pass, the MoE box.

  5. Llama-3.1-8B holds 70.2% of its weights in the MLP. So why does most of a busy server's memory belong to attention?
    Check
    • weights are one shared copy (16.06 GB); attention also stores k and v for every token of every request, 128 KiB per token
    • the MLP works on each token alone, so it needs nothing from earlier tokens and stores nothing per request
    • 59 sequences of 8k tokens fill the 63.9 GB left: about 4× the whole model, all of it attention's

    Missed it? Reopen the forward pass, "Most parameters live in the MLP. Is that where the cost is?"

  6. which concept?A benchmark serves Llama-3.1-8B at 32k context and reports "16.06 GFLOP per token, same as at 1k". Which idea says the number is wrong, and roughly how wrong is it at 32,768 tokens?
    Check
    • 2N counts only weight matmuls; attention's q·Kᵀ and scores·V multiply cached activations and grow with context
    • at S = 32,768: 32 layers × 4·S·4,096 = 17.18 GFLOP, 107% of 2N
    • so about 33.24 GFLOP per token, roughly 2× the claim

    Missed it? Reopen FLOPs per token, step 3, and attention, the T² score grid.

  7. A 1,000-token prompt gets 200 output tokens. How many forward passes run, and what is the input shape of the first pass and of every later one?
    Check
    • one prefill pass over [1000, 4096] produces the first output token (only the last row's logits are sampled)
    • then 199 decode passes, each over [1, 4096]: the sampled token is fed back in
    • 200 passes in all, and every one of them reads all 8.03B weights

    Missed it? Reopen the forward pass, the diagram's prefill and decode notes and the shapes table.

3 · Project: a model cost calculator

What it reinforces: the parameter formula (forward pass), the KV-cache formula and what KV heads do (attention), and 2N plus the attention term (FLOPs per token). Every model-side number the machine cards need comes out of this one function.

config = dict(L=32, D=4096, F=14336, N=32, K=8, H=128, V=128256) # Llama-3.1-8B tiny = dict(L=2, D=64, F=224, N=4, K=2, H=16, V=100) # the lab's toy

In about 40 lines of Python, stdlib only:

  1. Parameters. Write params(cfg) from the formula L·(2D(N+K)H + 3DF + 2D) + 2VD + D. Print the total and the MLP, attention and embedding + head shares, for both configs.
  2. KV cache. Write kv_bytes(cfg, bytes_per_value=2) per token. Then fits(cfg, S, hbm=80e9): how many sequences of S tokens fit beside the BF16 weights.
  3. FLOPs. Write flops(cfg, S) = 2 × (parameters that do matmuls) + L·4·S·D. Print it at S = 0, 8,192 and 131,072.
  4. Variants. Rerun steps 1–3 with K = 32 (MHA) and K = 1 (MQA). Which outputs change, and which don't?
  5. Crossovers. Solve for two context lengths: where one sequence's KV cache equals the weight bytes, and where attention FLOPs per token equal 2N.
Done when: your program prints all of the numbers below for Llama-3.1-8B and the tiny model, the variant runs show that the attention parameters, their share of the matmul FLOPs and the KV cache move, while the context term L·4·S·D doesn't, and you can say in one sentence why the second crossover sits a little below the book's 8D = 32,768. Then compare with the check.
Check: the numbers (computed with a Python version of this exact calculator)
  • Llama-3.1-8B: 8,030,261,248 parameters (MLP 70.2%, attention 16.7%, embedding + head 13.1%), 16.06 GB in BF16. Tiny model: 123,712 parameters, of which the norms are 320 (0.26%).
  • KV per token: 131,072 B (128 KiB) for Llama, 256 B for the tiny model. Fits on an H100 at S = 8,192: 59 sequences; at S = 32,768: 14.
  • FLOPs per token: 15.01 GFLOP of matmuls at S = 0 (93.5% of 2N; the embedding lookup does none); attention adds 4.29 GFLOP at 8,192 and 68.72 GFLOP at 131,072. The tiny model: 233,984 FLOPs of matmuls per token.
  • MHA: 8,835,567,616 parameters, 512 KiB per token, 14 sequences at 8k. MQA: 7,795,380,224, 16 KiB, 476. The attention FLOPs term L·4·S·D is the same in all three: it depends on query heads (N·H = D), not KV heads.
  • Crossovers: one sequence's KV equals 16.06 GB at about 122,500 tokens; attention equals 2N at about 30,600 tokens. The book's T/(8D) shortcut assumes F = 4D and plain MHA projections, so its matmul count is larger than Llama's and its break-even (32,768) later.
