In one breath

A coding agent is a model in a loop, run by a program called the harness. Each turn, the harness sends the model everything it should know; the model asks for a tool; the harness runs it and appends the result. Three choices in the harness decide how well and how cheaply the agent works: what the tools send back, what goes into each call, and how the loop ends. A fourth decides whether you can tell: measuring on fixed tasks, with repeats.

∑k=1N ( Pstable prefix + Δ·(k−1)history so far ) = N·P+ Δ·N(N−1)2
Nmodel calls in the run, set by how the loop endsthe agent loop Ptools, system prompt, repo instructions: re-sent every callwhat the model sees Δtokens added per turn: the model's call plus the tool's resulttool call

Total input tokens for a run. Filled in with the agent-loop example: 6 × 4,500 + 1,800 × (6 × 5 ÷ 2) = 27,000 + 27,000 = 54,000 tokens. The second term grows with the square of the calls, which is why the tool output (Δ) and the call count (N) matter so much, and why caching the prefix pays.

Plain text: total input = N × P + Δ × N(N − 1) ÷ 2

The mental model

Skills and MCP tools ride in the request's prefix. A subagent is a whole second loop whose report comes back as one result. A hook is harness code the model never chooses.

The words people use

Model vs harness

The model predicts text. The harness (Claude Code, Codex CLI, your own script) calls it, runs tools and decides when to stop.

Workflow vs agent

A workflow follows steps you wrote in code. An agent lets the model pick its own steps. Use a workflow when you know the steps.

Agent-computer interface

SWE-agent's name for tools designed for a model: what they show, how much, and what their errors say.

✓ Context engineering

Choosing what goes into each call: the smallest set of useful tokens, a stable prefix, and nothing the next step doesn't need. Anthropic frames it as spending a limited attention budget.

The takeaway

The model is fixed; the harness is yours. Most of what makes an agent good or bad is in the harness: tools that answer briefly and clearly, a request that keeps its stable part first and loads the rest just in time, a loop that handles every way a run can end, and an eval that tells a real win from luck. Change one of these at a time and measure it.

This isn't always the right frame. For a one-shot question, one model call beats any loop. When you know the steps in advance, a fixed workflow is cheaper and easier to test than an agent. And the numbers here are for coding tasks that tests can check; for fuzzy tasks, grading is harder and the evals card's advice about model graders applies.

5 · Predict commit to an answer before revealing

Keep P = 4,500 and N = 6 but double Δ from 1,800 to 3,600 (bigger tool outputs). Predict the new total input before computing: about 1.5× or about 2× the 54,000?

Reveal

6 × 4,500 + 3,600 × 15 = 27,000 + 54,000 = 81,000 tokens, 1.5×. Only the history term doubles; the prefix term stays at 27,000. On a longer run the history term dominates, so doubling Δ would get closer to 2×.
