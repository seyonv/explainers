Median of two sorted arrays

Also called binary search on the partition, or on the cut. The source guide lists it first under Binary Search and asks for Θ(log min(m, n)) time. Its answer is a 10-line Python function built on bisect_left with a key=.

In one breath

Don't merge the arrays. Choose how many items the left half takes from the shorter array; that fixes how many it takes from the other. Binary search that one number until every item on the left is ≤ every item on the right. The median then sits next to the cut.

Worked example: A = [1, 3, 8, 9, 15], B = [7, 11, 18, 19, 21, 25] → 11

Grey = left of the cut; outlined = the four boundary values. Both crossings hold, so every grey item is ≤ every white one, and the cut through A and B is the same as the cut through the merged array.

Grey chip = the last item left of the cut, white = the first item right of it. ✗ means B gave too many to the left (its last left item is bigger than A's first right item), so take more from A.

The loop only checks one crossing. It finds the smallest i where A[i] ≥ B[j−1]. At i − 1 that test failed, so A[i−1] < B[j]: the other crossing holds for free. That's why one comparison per probe is enough.

In Python

def median_two(a, b):
    if len(a) > len(b):
        a, b = b, a                  # search the shorter array
    m, n = len(a), len(b)
    k = (m + n - 1) // 2             # items left of the cut
    lo, hi = 0, min(m, k)
    while lo < hi:
        i = (lo + hi) // 2           # take i from a, k - i from b
        if a[i] >= b[k - 1 - i]:     # enough from a: go left
            hi = i
        else:                        # b's last left item too big
            lo = i + 1
    i, j = lo, k - lo
    right = sorted(a[i:i + 2] + b[j:j + 2])   # 2 smallest are here
    if (m + n) % 2:
        return right[0]
    return (right[0] + right[1]) / 2

print(median_two([1, 3, 8, 9, 15], [7, 11, 18, 19, 21, 25]))
print(median_two([1, 2], [3, 4]))
# → 11

The source writes the same search as one bisect_left(range(m), True, key=…) over the test x > j or nums1[x] >= nums2[j - x], with j = k − 1. It is correct: it makes the same three probes here and agreed with sorted(a + b) on 10,000 random pairs. But key= needs Python 3.10+, and (m + n) & 1 ^ 1 parses as ((m + n) & 1) ^ 1. This card spells the loop out.

Time O(log min(m, n)) · Space O(1). Each probe halves the range of possible cuts in the shorter array, so there are at most ⌊log₂ w⌋ + 1 probes for a range w wide: 3 here, 20 for m = n = 10⁶. The final sorted sees at most 4 items. Slicing the right side is enough because its two smallest items must be among the first two of each array.

Why it beats the alternatives

✗ sorted(a + b)

Two lines and hard to get wrong. It copies all m + n items, though: 2,000,000 for m = n = 10⁶. Timsort spots the two sorted runs, so this is a linear merge, not n log n, but still O(m + n).

✗ Merge to the middle

Two pointers, stop halfway. No copy, but 1,000,001 steps to reach both middle items for m = n = 10⁶. O(m + n), which misses the source's log bound.

✗ Binary search on the value

Guess x, count items ≤ x with two bisects. About 32 rounds for 32-bit integers × 2 × 20 compares ≈ 1,280 compares. It works for k arrays, but it's clumsy for floats and even totals.

✓ Binary search on the cut

At most 20 probes of one comparison each for m = n = 10⁶, no copy, O(1) space. And it only searches the shorter array: at most 3 probes for m = 5 however long B is.

Is it always the tool?

Only when both arrays are already sorted and you need one order statistic. The same code finds any k-th smallest if you set k yourself. For small inputs, or in production code, sorted(a + b) or statistics.median is clearer and fast enough.

It's the wrong tool if the data is unsorted: quickselect finds the median in expected O(n), which beats sorting first. For a median over a stream or a sliding window, use two heaps. With many sorted arrays, binary search on the value (or a heap merge) generalises and this cut trick doesn't. These alternatives are standard practice, not from the source.
