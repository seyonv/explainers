Choosing an algorithm

The overview for course 2 of the cheat-sheet series. It ties together the 21 cards on the cheat-sheet's Sorting and Algorithms pages: every sort, binary search in its disguises, the string-matching classics and greedy proofs. It covers what each one costs, why the shortcut is safe, and how many steps it saves on real inputs.

In one breath

Count the passes you make over the data and the work in each pass, then cut one of them. There are three ways to do that: halve what's left each pass (binary search, merge sort, divide and conquer), make one pass whose pointers never move back (two pointers, KMP, Manacher), or stop comparing and look inside the keys (radix sort, hashing). Each shortcut is only allowed once you can say why it's safe: an invariant, a monotone test, or an exchange argument.

The words people use

Worst case vs expected

Worst case bounds every input; expected averages over the algorithm's own random choices. Quicksort, quickselect and rolling hash are fast in expectation only; heapsort, KMP and Manacher promise the worst case.

Comparison sort

A sort that learns about keys only by asking "x < y?". It can't beat log₂ n! compares. Radix sort reads digits instead, so the bound doesn't apply to it.

Stable, in place

Stable: equal keys keep their input order (merge, Timsort, insertion, LSD radix). In place: O(1) or O(log n) extra memory (heapsort, quicksort). Between sorts that tie on speed, these two decide.

✓ Invariant

A fact that stays true at every step: "the answer is in [lo, hi]", "tails is sorted", "[1, miss) is covered". It's what lets an algorithm throw work away safely, and it's the first thing an interviewer asks you to state.

When this advice doesn't apply

Big-O counts steps, not time. np.sort and sorted() are both n log n, yet 0.031 s against 0.130 s on 10⁶ floats. Small inputs flip the ranking too: Timsort sorts runs under 64 items with insertion sort, and CPython only switches to Karatsuba multiplication above 70 internal digits (about 632 decimal digits).

In Python, a built-in usually beats the algorithm you'd write: sorted() over any hand-written sort, s.find(p) over KMP or Rabin–Karp, np.partition over quickselect. Write the algorithm when you need a guarantee the built-in doesn't give (a linear worst case, a stream you can't rewind) or when the interview asks for it. And greedy is only right with a proof: coins {1, 3, 4} for 6 fool it, and that problem needs DP (course 3).

Insertion sortAlso called the card-player's sort; in Timsort it runs as binary insertion sort. The cheat-sheet gives it first under Sorting, as a three-line C++ loop that swaps each new element left until it fits.In one breathKeep the left part of the array sorted. Take the next element (the key) and swap it leftwards past every bigger neighbour; when the neighbour is not bigger, it has landed. Each swap fixes exactly one out-of-order pair, so the work is the number of such pairs: none for sorted input, all of them for reversed input.
