Quickselect

Also called Hoare's selection algorithm or partial quicksort; np.partition uses a variant (introselect). The source guide gives it under Quicksort as a five-line recursive Python function: split around arr[0] into smaller, equal and larger, then keep only the side that holds the k-th smallest.

Prime · 2 minutes before you read

The problem: To find the median or the 95th percentile you don't need the whole order, yet sorting pays n log n for all of it. The question is how to use a partition to discard most of the data without losing the answer.

Where it fits: Right after quicksort, and built from its partition. The only change is recursing into one side instead of two, which divide and conquer later shows is the difference between n log n and n.

In one breath

Partition once, exactly as quicksort does, and look at where the pivot lands. If k falls among the smaller items, the answer is in there; if it falls past the pivot and its equals, it's in the larger items; otherwise the pivot is the answer. Quicksort recurses into both sides; quickselect throws one away, so the work shrinks level by level instead of staying n per level.

Why it's linear on average

If every pivot landed in the middle, each level would scan half of the one before, and the scans add up to a geometric series. Real random pivots miss the middle, so the exact expectation (Knuth's formula, which the code checks against an exact recurrence) is higher, but still a constant times n:

n+n2+n4+⋯=2nperfect halving (intuition) E[C]≤2(1+ln2)n≈3.39nrandom pivot, worst k (the median)

In Python

import random

def quickselect(arr, k, pick=random.choice):  # k = 1 is the min
    while True:
        p = pick(arr)
        smaller = [x for x in arr if x < p]
        larger = [x for x in arr if x > p]
        n = len(arr) - len(larger)        # how many are <= p
        if k <= len(smaller):
            arr = smaller                 # answer is left of p
        elif k > n:
            arr, k = larger, k - n        # skip n items on the left
        else:
            return p                      # p itself is k-th

print(quickselect([38, 27, 43, 3, 9, 82, 10], 3))  # → 10

The source's version recurses with pivot arr[0], so on sorted input each level drops one item: range(1000) with k = 1000 raises RecursionError (Python's limit is 1,000 frames). Corrected here with a loop and a random pivot.

Time O(n) expected, O(n²) worst · Space O(n). Each level scans only the side that survived, and a random pivot makes that side shrink by a constant fraction on average. The list version copies each level; an in-place Lomuto or Hoare partition gets extra space down to O(1).

Why it beats the alternatives (for one k-th value)

✗ Sort, then index

sorted(a)[k - 1] is O(n log n): it orders all n items to read one. Simple and fast in C (0.130 s for 10⁶ floats on an M3), but it does work the question never asked for.

✗ A heap of size k

heapq.nsmallest(k, a)[-1] is O(n log k). Great for k = 10, but at the median k = n/2, so it is no better than sorting.

✗ Median of medians

Pivot on the median of the medians of groups of 5. That guarantees O(n) even in the worst case, but the extra recursion makes it slower than a random pivot in practice, so it's rarely run on its own.

✓ Quickselect, random pivot

≈ 3.39n compares or fewer on average, for any k, and a few lines of code. 12 compares on a, and 11.19 expected with a random pivot.

Is it always the tool?

Use it for one order statistic, once, on data you can hold: the median, the 95th percentile, the k-th largest. It also leaves the array split around the answer, so "the k smallest in any order" comes free with an in-place partition.

Skip it when you need the k items in order (heap or sort), when the data streams in (keep a size-k heap, or two heaps for a running median), or when you'll ask many ranks of the same data (sort once, then each query is O(1)). If an adversary chooses the input, a fixed pivot like arr[0] can be forced into the O(n²) case; introselect, which np.partition uses by default, starts as quickselect and falls back to median of medians when progress stalls.

Understand and remember

  • Partition around p → p's rank among the items is known → k falls left, in the equal block, or right → recurse into one side only (k − n when going right) → the other side is discarded for good
  • Only the surviving side is scanned next → sizes n, ≈ n/2, ≈ n/4 … → total ≈ 2n with perfect halving, ≤ 2(1 + ln 2)n ≈ 3.39n expected with random pivots → O(n), versus quicksort's n per level for log n levels
  • A fixed pivot on sorted input keeps only one item off each level → n(n − 1)/2 (21 on sorted a, k = 7) → random pivot in practice, or median of medians / introselect for a worst-case O(n) guarantee
  • detail that matters Three-way split puts all copies of p in the middle → duplicates end in one level (999 compares for [5] × 1,000 vs 499,500 with a two-way split)
