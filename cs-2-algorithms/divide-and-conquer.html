Divide and conquer and the master theorem

Also called split–solve–combine, or D&C; the master theorem is the shortcut for its running time. The source guide's Divide-and-conquer heading is empty, so this card supplies the idea behind merge sort, binary search, quickselect and Karatsuba multiplication.

Prime · 2 minutes before you read

The problem: Merge sort, binary search, quickselect and the median cut all split a problem and recurse, yet their costs are n log n, log n, n and log n. Without a rule, every recursive algorithm needs its own ad-hoc analysis, and you can't tell in advance whether a new split will pay off.

Where it fits: The first Paradigms card brings the course's recursive algorithms back under one lens: merge sort, quickselect, binary search and the median of two arrays, plus Karatsuba as a new example where cutting the number of calls is the whole win.

In one breath

Split a problem of size n into a pieces of size n/b, solve each piece the same way, then stitch the answers together in f(n) work. The running time depends on one contest: does the stitching at the top cost more than all the tiny pieces at the bottom, less, or the same at every level?

In Python: Karatsuba, counting one-digit multiplications

calls = 0

def karatsuba(x, y, n):        # n digits, a power of two
    global calls
    if n == 1:
        calls += 1
        return x * y
    m = n // 2
    a, b = divmod(x, 10 ** m)          # x = a·10^m + b
    c, d = divmod(y, 10 ** m)          # y = c·10^m + d
    ac = karatsuba(a, c, m)
    bd = karatsuba(b, d, m)
    # ad + bc = ac + bd + (a - b)(d - c); |a - b| < 10^m fits
    s = (1 if a >= b else -1) * (1 if d >= c else -1)
    mid = ac + bd + s * karatsuba(abs(a - b), abs(d - c), m)
    return ac * 10 ** (2 * m) + mid * 10 ** m + bd

# two random 1,024-digit numbers (seed 0)
assert karatsuba(x, y, 1024) == x * y
print(f"{calls:,} vs {1024 * 1024:,}")
# → 59,049 vs 1,048,576   (3^10 vs 4^10, 17.76x fewer)

Time Θ(nlog₂ 3) ≈ Θ(n1.585) · Space O(n). Three half-size products per call is case 1 of the master theorem; the difference form (a − b)(d − c) keeps every piece at m digits, so the count is exactly 310. Recursion is only log₂ n = 10 deep, and the live pieces sum to O(n) digits.

Why it beats the alternatives

✗ Schoolbook multiplication

Every digit of x times every digit of y: n² = 1,048,576 one-digit products for 1,024 digits.

✗ Split into four half-products

ac, ad, bc, bd is 4T(n/2) + n: leaves nlog₂ 4 = n², so still 410 = 1,048,576. Splitting alone buys nothing; cutting a does.

✗ Split unevenly

Peel one element per call and you get T(n − 1) + n = Θ(n²); the master theorem doesn't even apply. Quicksort with a last-element pivot on sorted input does this: 28 comparisons for n = 8.

✓ Balanced split, fewer calls

Halve the size and make 3 calls, not 4: 310 = 59,049 products, 17.76× fewer at 1,024 digits, and the gap widens as (4/3)depth.

The same lens everywhere: merge sort is case 2; quickselect is case 3 on average; median of two sorted arrays halves the shorter array, T(m/2) + 1 = Θ(log min(m, n)); closest pair of points splits by x and merges a strip in O(n), 2T(n/2) + n = Θ(n log n) (re-sorting the strip every call adds a log: n log² n, case 2 with k = 1).

Does the master theorem always apply?

No. It needs equal-sized pieces n/b and an f that's polynomially above or below the leaves. T(n − 1) + n (worst-case quicksort) has no b: unroll it to n(n + 1)/2. T(n/3) + T(2n/3) + n has uneven pieces: draw the recursion tree (each level ≤ n, about log3/2 n levels, so Θ(n log n)) or use Akra–Bazzi. 2T(n/2) + n / log n falls in the gap between cases 1 and 2; the answer is Θ(n log log n), which the three cases can't give.

And divide and conquer itself isn't always right. If the pieces overlap, as in naive Fibonacci's T(n − 1) + T(n − 2), memoize them and it becomes dynamic programming. Small inputs favour the simple method too: CPython only switches its int multiply to Karatsuba when both numbers have more than 70 internal digits (30 bits each, about 632 decimal digits); below that, schoolbook's lower overhead wins.

Understand and remember

  • Level i has aⁱ calls of size n/bⁱ → work per level aⁱ·f(n/bⁱ) → the total is dominated by whichever end of the tree is biggest → compare f(n) with the leaf count n^(log_b a)
  • Leaves win (f smaller) → Θ(n^(log_b a)), e.g. Karatsuba 3T(n/2) + n → n^1.585; tie (equal) → every level costs the same → Θ(n^(log_b a) log n), e.g. merge sort n log n, binary search log n; root wins (f bigger, regular) → Θ(f(n)), e.g. quickselect's expected n
  • Leaves = n^(log_b a) depend on a, not on how clever the split is → four half-products still give n² → cutting a to 3 gives 3¹⁰ = 59,049 vs 4¹⁰ = 1,048,576 one-digit products at 1,024 digits (17.76×)
  • detail that matters The theorem needs equal pieces n/b and a polynomial gap between f and the leaves → T(n − 1) + n, T(n/3) + T(2n/3) + n and 2T(n/2) + n / log n fall outside → unroll, draw the recursion tree, or use Akra–Bazzi
