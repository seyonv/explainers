Greedy I: wildcard matching and text justification

Wildcard matching is also called glob matching (? and *, as in shell file names); the greedy version is the "last star" or star-backtracking two-pointer. Text justification is greedy line packing with full justification. The source guide files both under Greediness, with a C++ matcher and a Python justifier.

Prime · 2 minutes before you read

The problem: Wildcard matching with several * looks like it must try every way of splitting the string among the stars: plain recursion makes 34,091 calls on a 20-character example. Text justification looks like it needs a global plan. In both, a local rule that never looks back turns out to be enough, but only with a proof.

Where it fits: First greedy card. It uses two pointers from the Searching part (i in s, j in p, plus saved indices) and sets up Greedy II's proof techniques. Its failure cases point to cs-3's DP string matching.

In one breath

A greedy algorithm makes the obvious local choice and almost never takes it back. In wildcard matching, each * first matches nothing; on a mismatch, only the most recent star is allowed to swallow one more character, and every earlier star is frozen for good. In justification, each line takes as many words as fit, then the leftover spaces are shared out, with the extra ones going to the leftmost gaps.

In Python

def is_match(s, p):
    i = j = 0
    star, k = -1, 0          # last '*' in p; s index after its run
    while i < len(s):
        if j < len(p) and p[j] in (s[i], "?"):
            i, j = i + 1, j + 1
        elif j < len(p) and p[j] == "*":
            star, k, j = j, i, j + 1       # '*' eats nothing
        elif star != -1:
            k += 1                         # last '*' eats one more
            i, j = k, star + 1
        else:
            return False
    while j < len(p) and p[j] == "*":
        j += 1                    # trailing stars match empty
    return j == len(p)

def full_justify(words, width):
    lines, line, letters = [], [], 0
    for w in words:
        if letters + len(line) + len(w) > width:   # len(line) = gaps
            lines.append(spread(line, letters, width))
            line, letters = [], 0
        line.append(w)
        letters += len(w)
    return lines + [" ".join(line).ljust(width)]   # last line: left

def spread(line, letters, width):
    if len(line) == 1:
        return line[0].ljust(width)
    q, r = divmod(width - letters, len(line) - 1)
    gaps = [q + 1] * r + [q] * (len(line) - 1 - r) + [0]
    return "".join(w + " " * g for w, g in zip(line, gaps))

print(is_match("adceb", "*a*b"), is_match("acdcb", "a*c?b"))

Both source versions are correct: they agree with an O(m·n) DP table and a plain reference justifier on 5,000 random cases each (checked in code/). The justifier is reshaped here only for readability.

Wildcard: Time O(m·n) worst, usually near O(m + n) · Space O(1). Each backtrack moves k forward one place and rescans at most the pattern after the star, so at most m backtracks × n steps. Worst case s = "a"×1000, p = "*" + "a"×500 + "b": 251,001 loop steps (computed), against 503,503 cells for the DP table.

Justify: Time O(total characters) · Space O(width) per line. Each word is looked at once to pack it and once to write it out.

Why the greedy choice is safe

Wildcard: between two stars sits a fixed block of letters and ?s. If any match exists, the one that places every block at its earliest possible spot also works, since sliding a block left only hands more of s to the stars after it, and a star can eat anything. So once a later star is reached, the earlier star's choice never needs revisiting. Justify: packing each line as full as possible never leaves a later line worse off, so greedy uses the fewest lines. Both arguments are standard (exchange / "greedy stays ahead"), not spelled out in the source.

Why it beats the alternatives (wildcard)

✗ Plain recursion

Every star tries every split. s = "a"×20, p = "*a*a*a*a*b" makes 34,091 calls to answer False; the greedy loop takes 25 steps.

✗ DP table

Correct and the standard fallback, but always fills (m+1)(n+1) cells: 231 for that same case, 503,503 for the worst case above, and O(m·n) memory unless you keep two rows.

✗ fnmatch.fnmatchcase

One line, and it agreed on all 20,000 random ?/* cases. But [ab] is a character class there, so "x[ab]" does not match itself. It compiles to a regex behind the scenes.

✓ Last-star greedy

Two pointers and two saved indices: O(1) extra space, 7 steps on the example, and it never revisits a frozen star.

Create Maximum NumberEmpty in the source. The usual approach (not from the source): for each split i + (k − i), take the best i digits of one array with a monotonic stack, merge greedily by comparing the remaining suffixes, keep the best. [3,4,6,5], [9,1,2,5,8,3], k = 5 → [9,8,6,5,3] (checked by brute force).

Find the Closest PalindromeEmpty in the source. The usual approach (not from the source): mirror the first half with prefix −1, 0, +1, add 10L−1−1 and 10L+1, pick the nearest (smaller on ties). "123" → candidates 99, 111, 121, 131, 1001 → 121.

Is greedy always enough?

No. It works here because * is unconstrained. In regular-expression matching, a* means "zero or more a's", so what a star may eat depends on the letter before it and an earlier choice can matter; that one needs DP (see DP string matching). The same goes for patterns with character classes or several kinds of star.

For text, greedy packing minimises the number of lines, not how even they look. Width 6, words "aaa bb cc ddddd": greedy gives "aaa bb / cc / ddddd" with slack 0, 4, 1; "aaa / bb cc / ddddd" has slack 3, 1, 1, and a sum of squares (last line excluded) of 10 instead of 16 (illustrative words, computed). TeX's Knuth–Plass algorithm minimises a badness like that with DP over the whole paragraph. The interview problem asks for greedy, so greedy is the right answer there.

4 · Compare against what you already know

vs DP on two strings: Wildcard * and regex a* look alike. Why is greedy enough for one and DP needed for the other?

Check
  • wildcard * matches any sequence, so earliest placement of the next fixed block is always safe
  • regex a* can only eat a's; how many it eats changes what the rest can match, so an early choice may need undoing
  • DP keeps every (i, j) state instead of committing, at O(m·n)

vs Two pointers and intervals: The matcher walks i over s and j over p like a two-pointer scan, but it can move i back to k. Why isn't it O(n) like the two-pointer card, and what bounds it instead?

Check
  • a backtrack resets i to k and j to star + 1, so i is not monotone
  • only k is monotone: each backtrack moves it forward by one
  • so at most n backtracks × up to m steps each: O(m·n) worst case

Reveal
