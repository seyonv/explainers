Suffix automaton

Also called a DAWG (directed acyclic word graph), or the minimal automaton of all substrings. The cheat-sheet uses one, in Python, for Longest Duplicate Substring. It's filed under Data Structures › Graphs, but it's a string algorithm.

In one breath

A small graph that spells every substring of s along some path from the start, built one character at a time. Substrings that always end at the same positions share one state, so there are at most 2n − 1 states. Each state keeps a suffix link to the longest suffix of its strings that shows up in more places. The link from the newest state lands on the longest suffix that has been seen before. The longest of those, over all steps, is the longest repeated substring.

Worked example: s = "banana" → "ana"

Solid arrows are the 11 transitions; read letters along a path from state 0 to spell a substring. The top row is the chain for "banana" itself. States 5, 7 and 9 were created as clones. Dashed arrows are the suffix links from the last state: 8 ⇢ 9 ⇢ 5 ⇢ 0, which is "banana" ⇢ "ana" ⇢ "a" ⇢ "". The green path a, n, a ends at state 9 (len 3): the answer.

The ten states

A state is a set of substrings that end at exactly the same positions (their endpos, 1-indexed ends in "banana"). Its strings are suffixes of each other, one of each length from len(link) + 1 up to len.

Hand trace: add one character at a time

For each character c: make a state for the whole prefix, then walk suffix links from the previous last state, adding a c-arrow to each state that lacks one. Stop at the first state p that already has one, pointing to q. If q is exactly one longer than p, link to q. If not, clone q down to len(p) + 1 and redirect.

"Longest repeat ending here" = the longest string of the new state's link = the longest suffix of the prefix that also ended earlier. Its length is len(link). The answer is the best over all six steps: len 3, ending at position 6, so s[3:6] = "ana".

In Python

def longest_dup_substring(s):
    length, link, nxt = [0], [-1], [{}]   # state 0 = ""
    last, best, end = 0, 0, 0
    for i, c in enumerate(s):
        cur = len(length)                 # state for s[:i+1]
        length.append(length[last] + 1)
        link.append(0)
        nxt.append({})
        p = last
        while p != -1 and c not in nxt[p]:
            nxt[p][c] = cur               # suffixes lacking c get it
            p = link[p]
        if p != -1:
            q = nxt[p][c]
            if length[q] == length[p] + 1:
                link[cur] = q             # q fits exactly: reuse
            else:                         # q too long: clone it
                clone = len(length)
                length.append(length[p] + 1)
                link.append(link[q])
                nxt.append(dict(nxt[q]))
                while p != -1 and nxt[p].get(c) == q:
                    nxt[p][c] = clone
                    p = link[p]
                link[q] = link[cur] = clone
        last = cur
        rep = length[link[cur]]           # longest suffix seen before
        if rep > best:
            best, end = rep, i + 1
    return s[end - best:end]

words = ["banana", "mississippi", "abcd"]
print([longest_dup_substring(w) for w in words])
# → ['ana', 'issi', '']

The source's version stores each state's whole string (self.word), built by concatenation: on "a" × 30,000 that is 1 + 2 + … + 30,000 = 450,015,000 characters. Corrected here to store only len and remember where the best repeat ends. Its logic is otherwise right: it matches brute force on 3,000 random strings.

Time O(n) · Space O(n) for a fixed alphabet (dict lookups). Each step creates at most 2 states, and the suffix-link walks add up to O(n) over the whole build (amortized; the proof tracks how len(link(last)) changes). "banana": 10 states ≤ 2n − 1 = 11, 11 transitions ≤ 3n − 4 = 14. A random a–z string of 30,000 characters: 40,366 states and 70,128 transitions (computed in code/).

Why it beats the alternatives

✗ Try every length

For L = n − 1 down to 1, put every window of length L in a set. Each window costs O(L) to hash, so the worst case is O(n³). On "abcd" it checks all 9 windows of lengths 3, 2 and 1 to return "".

✗ Rolling hash + binary search

"A length-L repeat exists" is monotone, so binary search L and hash windows in O(n) each: O(n log n) expected. Easier to write, but it needs collision checks or two moduli to be safe.

✗ Suffix array + LCP

Sort the suffixes: a, ana, anana, banana, na, nana. Neighbours share 1, 3, 0, 0, 2 characters; the max, 3, gives "ana". Deterministic, but the simple build is O(n log² n), and it isn't incremental.

✓ Suffix automaton

One O(n) online pass, no hashing, no sort. The same structure also counts distinct substrings (15 for "banana"), tests "is t a substring?" in O(|t|), and finds the longest common substring of two strings.

Is it always the tool?

No. In an interview, rolling hash + binary search is shorter and easier to get right under time pressure, and the interviewer usually expects it. The automaton is the one to know when the string arrives one character at a time, or when you need several substring queries on the same text. Those are our recommendations, not the source's.

It's the wrong tool for finding many patterns in one text (use Aho–Corasick) or one pattern in a text (KMP is simpler). In Python it's also memory-heavy: a dict per state, up to 2n − 1 of them. With a big alphabet and huge n, a suffix array (arrays of ints) is lighter.
