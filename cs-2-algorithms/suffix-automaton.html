Suffix automaton

Also called a DAWG (directed acyclic word graph), or the minimal automaton of all substrings. The source guide uses one, in Python, for Longest Duplicate Substring. It's filed under Data Structures › Graphs, but it's a string algorithm.

Prime · 2 minutes before you read

The problem: A string of length n has up to n(n + 1)/2 substrings. To answer "what's the longest repeat?", "is t a substring?" or "how many distinct substrings?" without hashing, you need a structure that represents all of them in O(n) space, and can be built one character at a time.

Where it fits: Last Strings card: the deterministic, online alternative to rolling hash + binary search for Longest Duplicate Substring. It reuses KMP's idea of falling back through suffixes, here as suffix links between states.

Builds on: Rolling hash (Rabin–Karp) · Knuth–Morris–Pratt · Tries and segment trees

You'll meet: endpos: where a substring ends state = substrings with equal endpos len and suffix link clone when a state splits ≤ 2n − 1 states, ≤ 3n − 4 transitions

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. Why can all substrings with the same set of end positions share one state?
  2. Why are the strings in one state suffixes of each other, with every length from len(link) + 1 to len?
  3. When adding a character, why do you walk suffix links from the last state, and why stop at the first state that already has the arrow?
  4. When is a clone needed, and what goes wrong if you redirect to q without cloning?
  5. Why does len(link(cur)) after each step give the longest repeat ending there?

In one breath

A small graph that spells every substring of s along some path from the start, built one character at a time. Substrings that always end at the same positions share one state, so there are at most 2n − 1 states. Each state keeps a suffix link to the longest suffix of its strings that shows up in more places. The link from the newest state lands on the longest suffix that has been seen before. The longest of those, over all steps, is the longest repeated substring.

Worked example: s = "banana" → "ana"

Solid arrows are the 11 transitions; read letters along a path from state 0 to spell a substring. The top row is the chain for "banana" itself. States 5, 7 and 9 were created as clones. Dashed arrows are the suffix links from the last state: 8 ⇢ 9 ⇢ 5 ⇢ 0, which is "banana" ⇢ "ana" ⇢ "a" ⇢ "". The green path a, n, a ends at state 9 (len 3): the answer.

The ten states

A state is a set of substrings that end at exactly the same positions (their endpos, 1-indexed ends in "banana"). Its strings are suffixes of each other, one of each length from len(link) + 1 up to len.

Hand trace: add one character at a time

For each character c: make a state for the whole prefix, then walk suffix links from the previous last state, adding a c-arrow to each state that lacks one. Stop at the first state p that already has one, pointing to q. If q is exactly one longer than p, link to q. If not, clone q down to len(p) + 1 and redirect.

"Longest repeat ending here" = the longest string of the new state's link = the longest suffix of the prefix that also ended earlier. Its length is len(link). The answer is the best over all six steps: len 3, ending at position 6, so s[3:6] = "ana".

In Python

def longest_dup_substring(s):
    length, link, nxt = [0], [-1], [{}]   # state 0 = ""
    last, best, end = 0, 0, 0
    for i, c in enumerate(s):
        cur = len(length)                 # state for s[:i+1]
        length.append(length[last] + 1)
        link.append(0)
        nxt.append({})
        p = last
        while p != -1 and c not in nxt[p]:
            nxt[p][c] = cur               # suffixes lacking c get it
            p = link[p]
        if p != -1:
            q = nxt[p][c]
            if length[q] == length[p] + 1:
                link[cur] = q             # q fits exactly: reuse
            else:                         # q too long: clone it
                clone = len(length)
                length.append(length[p] + 1)
                link.append(link[q])
                nxt.append(dict(nxt[q]))
                while p != -1 and nxt[p].get(c) == q:
                    nxt[p][c] = clone
                    p = link[p]
                link[q] = link[cur] = clone
        last = cur
        rep = length[link[cur]]           # longest suffix seen before
        if rep > best:
            best, end = rep, i + 1
    return s[end - best:end]

words = ["banana", "mississippi", "abcd"]
print([longest_dup_substring(w) for w in words])
# → ['ana', 'issi', '']

The source's version stores each state's whole string (self.word), built by concatenation: on "a" × 30,000 that is 1 + 2 + … + 30,000 = 450,015,000 characters. Corrected here to store only len and remember where the best repeat ends. Its logic is otherwise right: it matches brute force on 3,000 random strings.

Time O(n) · Space O(n) for a fixed alphabet (dict lookups). Each step creates at most 2 states, and the suffix-link walks add up to O(n) over the whole build (amortized; the proof tracks how len(link(last)) changes). "banana": 10 states ≤ 2n − 1 = 11, 11 transitions ≤ 3n − 4 = 14. A random a–z string of 30,000 characters: 40,366 states and 70,128 transitions (computed in code/).

Why it beats the alternatives

✗ Try every length

For L = n − 1 down to 1, put every window of length L in a set. Each window costs O(L) to hash, so the worst case is O(n³). On "abcd" it checks all 9 windows of lengths 3, 2 and 1 to return "".

✗ Rolling hash + binary search

"A length-L repeat exists" is monotone, so binary search L and hash windows in O(n) each: O(n log n) expected. Easier to write, but it needs collision checks or two moduli to be safe.

✗ Suffix array + LCP

Sort the suffixes: a, ana, anana, banana, na, nana. Neighbours share 1, 3, 0, 0, 2 characters; the max, 3, gives "ana". Deterministic, but the simple build is O(n log² n), and it isn't incremental.

✓ Suffix automaton

One O(n) online pass, no hashing, no sort. The same structure also counts distinct substrings (15 for "banana"), tests "is t a substring?" in O(|t|), and finds the longest common substring of two strings.

Is it always the tool?

No. In an interview, rolling hash + binary search is shorter and easier to get right under time pressure, and the interviewer usually expects it. The automaton is the one to know when the string arrives one character at a time, or when you need several substring queries on the same text. Those are our recommendations, not the source's.

It's the wrong tool for finding many patterns in one text (use Aho–Corasick) or one pattern in a text (KMP is simpler). In Python it's also memory-heavy: a dict per state, up to 2n − 1 of them. With a big alphabet and huge n, a suffix array (arrays of ints) is lighter.

Understand and remember

  • Substrings that end at exactly the same positions behave identically for every future extension → merge them into one state → at most 2n − 1 states for all n(n + 1)/2 substrings → any substring is a path from the start
  • Suffix link → the state of the longest suffix that ends in more places → after adding a character, link(last) is the longest suffix of the prefix that occurred before → the max of len(link) over all steps is the longest repeated substring ("ana" in banana)
  • Adding c: walk suffix links adding c-arrows until a state p already has one to q → if len(q) = len(p) + 1, q fits exactly → otherwise q mixes strings that just gained an end position with longer ones that didn't → clone q at len(p) + 1 and redirect → endpos stays consistent
  • detail that matters Distinct substrings = Σ (len − len(link)) over states → each state contributes one string per length in its range → 15 for banana without listing them
  • detail that matters The source stored each state's whole string → O(n²) memory (450,015,000 characters on a × 30,000) → store only len and remember where the best repeat ends

    Check

  2. mechanism Walk through step 4 of building "banana" (adding the second 'a'): the new state, the link walk, the clone and the resulting links.

    Check
    • KMP per query: O(|S| + |t|) each, 10⁵ × 10⁶: far too slow
    • rolling hash: needs prefix hashes of S and a set per length; awkward for arbitrary |t|
    • suffix automaton: O(|S|) once, then O(|t|) per query by walking arrows; memory-heavy in Python (a dict per state)

4 · Compare against what you already know

vs Rolling hash (Rabin–Karp): Both solve Longest Duplicate Substring. What is fundamentally different in how each detects a repeat, which choice makes one deterministic and the other easier to write, and how does each fail?

Check
  • hash: fingerprints of all windows of one length L, with binary search over L
  • automaton: repeats show up structurally as suffix links to states with several end positions
  • the automaton needs no luck but has a tricky clone step; the hash is short but probabilistic
  • hash fails on collisions or adversarial (B, p); the automaton fails on memory in Python for large alphabets and n

vs Tries and segment trees: A suffix trie and a suffix automaton both spell every substring along a path. Why can the trie need O(n²) nodes while the automaton needs O(n)?

Check
  • the trie gives every distinct substring its own node
  • the automaton merges substrings with equal endpos and shares their futures
  • it's the minimal automaton for the language of all substrings, a DAG rather than a tree

Reveal

5 states (0 plus one per character), no clone: at every step the stopping state's arrow leads to a state exactly one longer, so it can be reused. Links: 3 → 1 ("a"), 4 → 2 ("ab"). Longest repeat "ab" (len(link(4)) = 2). Distinct substrings: Σ (len − len(link)) = 1 + 2 + 2 + 2 = 7 (a, b, ab, ba, aba, bab, abab).
