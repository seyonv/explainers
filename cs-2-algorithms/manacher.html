Manacher's algorithm

Also called Manacher's longest-palindrome algorithm, or the palindromic radius array. Finds the longest palindrome centred at every position of a string in one linear pass. The source guide uses it for Longest Palindromic Substring, under Searching, with a second radius-array version in code/manacher.cpp.

In one breath

Put a # between every letter so every palindrome has odd length and a single centre. Walk the centres left to right, remembering the palindrome that reaches furthest right. A centre inside it sees its own neighbourhood reflected on the other side, so it can copy that mirror's radius for free and only compare characters past the known right edge.

Worked example: s = "babad" → "bab"

p[i] is the radius in the # string, which equals the palindrome's length in s. The largest, p[3] = 3, is "bab" (p[5] = 3, "aba", ties it). At i = 7 the mirror j = 3 has radius 3, but part of it hangs past c's palindrome, so only r − i = 1 is guaranteed.

In Python

def manacher(s):
    t = "#" + "#".join(s) + "#"      # 'babad' -> '#b#a#b#a#d#'
    n = len(t)
    p = [0] * n        # p[i] = radius in t = palindrome length in s
    c = r = 0          # centre and right edge of rightmost palindrome
    for i in range(n):
        if i < r:                    # inside it: copy the mirror
            p[i] = min(r - i, p[2 * c - i])
        while (i - p[i] > 0 and i + p[i] + 1 < n
               and t[i - p[i] - 1] == t[i + p[i] + 1]):
            p[i] += 1                # expand past what is known
        if i + p[i] > r:
            c, r = i, i + p[i]       # new rightmost palindrome
    return p

def longest_palindrome(s):
    p = manacher(s)
    i = max(range(len(p)), key=p.__getitem__)   # first maximum
    start = (i - p[i]) // 2          # t index -> s index
    return s[start:start + p[i]]

print(manacher("babad"))           # → [0, 1, 0, 3, 0, 3, 0, 1, 0, 1, 0]
print(longest_palindrome("babad")) # → bab

Both source versions (the C++ Longest Palindromic Substring and manacher.cpp, which never builds t and treats even positions as implicit separators) matched a brute force on 20,000 and 30,000 random strings respectively in our Python ports; no fix needed.

Time O(n) · Space O(n). A position whose mirror fits strictly inside makes one check, which must fail. Every successful check pushes r one step right, and r never moves left, so there are at most 2n successes and 2n + 1 failures in total. On "a" × 1,000 that is 1,999 checks; the same loop without the mirror makes 1,000,000.

Why it beats the alternatives

✗ Check every substring

n(n + 1)/2 = 500,500 substrings for n = 1,000, each reversed and compared: O(n³).

✗ Expand around each centre

Simple, O(1) extra space, but it forgets everything between centres: O(n²), 1,000,000 checks on "a" × 1,000.

✗ DP table is_pal[i][j]

s[i..j] is a palindrome if the ends match and s[i+1..j−1] is one. O(n²) time and O(n²) memory: 500,500 cells for n = 1,000.

✓ Manacher

Reuses the rightmost palindrome's mirror, so r only moves forward. O(n) always: 1,999 checks on "a" × 1,000, and the radius at every centre, not just the longest.

Is it always the tool?

In an interview, expand-around-centre is often the expected answer: it's short, hard to get wrong, and slow only when palindromes are long, as in runs of repeats. Reach for Manacher when n is large, the input may be adversarial ("aaaa…"), or you need every centre's radius: counting all palindromic substrings is sum((x + 1) // 2 for x in p), and the longest palindromic prefix (Shortest Palindrome, "aacecaaa" → "aaacecaaa") is the largest p[i] with i − p[i] = 0. That prefix problem is what Manacher's 1975 paper set out to solve; the source solves it with KMP instead.

It's the wrong tool for palindromic subsequences (letters need not be adjacent), which need an O(n²) DP, and for the longest repeated or common substring, where the mirror trick doesn't apply: use a rolling hash or a suffix automaton.
