The array as its own hash table

Also called cyclic sort, cyclic placement or in-place hashing; the standard problem is First Missing Positive (LeetCode 41). The source guide opens its Sorting page with it, before any sort, as a six-line C++ solution that must run in Θ(n) time and Θ(1) extra space.

Prime · 2 minutes before you read

The problem: First Missing Positive asks for O(n) time and O(1) extra space. Sorting is O(n log n), and a set is O(n) memory. Something has to play the role of a hash table without allocating one.

Where it fits: Closes the Sorting part. After the n log n card showed sorting's floor, this card beats it by using the value range: like radix sort, it computes each value's position from the value itself, but in one pass and in place.

Builds on: Hashing and buckets · Radix sort

You'll meet: home slot v − 1 pigeonhole: answer in 1 … n + 1 swap until home or out of range each swap settles one value for good duplicate guard

In one breath

The answer to "smallest missing positive" in an array of n numbers is always somewhere in 1 … n + 1, so only the values 1 … n matter. Give each such value v a fixed home, slot v − 1, and swap it there. Afterwards the first slot that doesn't hold its own number is the answer. The array is the hash table, and v − 1 is the hash function.

Worked example: nums = [3, 4, −1, 1] → 2

Green arrows: a value sent to its home slot. Grey: the out-of-range −1, which is never moved on purpose; it ends up wherever the swaps leave it, and that is exactly the slot whose number is missing.

Why it's O(n) despite the nested loop

A swap happens only when slot v − 1 does not already hold v, and afterwards it does. Nothing ever swaps a value out of its home: that would need a second copy of v elsewhere with slot v − 1 not holding v, which is false. So every swap settles one of the at most n values in 1 … n for good, and each check either swaps or advances i:

In Python

def first_missing_positive(nums):
    n = len(nums)
    for i in range(n):
        # v in range and its home slot doesn't hold v yet: send it home
        while 0 < nums[i] <= n and nums[nums[i] - 1] != nums[i]:
            j = nums[i] - 1              # read the home index first
            nums[i], nums[j] = nums[j], nums[i]
    for i in range(n):
        if nums[i] != i + 1:             # slot i should hold i + 1
            return i + 1
    return n + 1                         # 1..n all present

for xs in ([3, 4, -1, 1], [1, 2, 0], [7, 8, 9, 11, 12], [1, 1]):
    print(xs, "->", first_missing_positive(xs))
# → [1, -1, 3, 4] -> 2    (the list is changed in place)
#   [1, 2, 0] -> 3
#   [7, 8, 9, 11, 12] -> 1
#   [1, 1] -> 2

The source's C++ is correct. The Python trap is the one-line swap nums[i], nums[nums[i] - 1] = nums[nums[i] - 1], nums[i]: Python assigns nums[i] first, so the second target is computed from the new value. On [3, 4, −1, 1] it loops forever (checked). Read j first, as above.

Time O(n) · Space O(1). At most n swaps and 2n checks, then one scan of n. The only extra memory is i and j; the price is that the input list is reordered.

Why it beats the alternatives

✗ Sort, then scan

Simple and O(1) extra space with an in-place sort, but O(n log n): about 1.66 × 10⁶ comparisons for n = 10⁵ (n log₂ n). Breaks the Θ(n) requirement.

✗ Put the values in a set

O(n) time, then test 1, 2, 3, … Breaks the Θ(1) space rule: for 10⁵ values the set's table alone is 4.19 MB (sys.getsizeof).

✗ Try 1, 2, 3, … by scanning

O(1) space, but each candidate is a full scan: O(n²). On a shuffled 1 … 10⁵ that's n(n + 1)/2 + n ≈ 5 × 10⁹ comparisons on average.

✓ Cyclic placement

The set's O(n) lookup, with the input array as the table. At most n swaps and 2n checks: 3 swaps and 7 checks on the example, 99,988 swaps for a shuffled 10⁵.

When is it the right tool?

Whenever the values are (or should be) a permutation of 1 … n or 0 … n − 1 and you may reorder the input: first missing positive, find all duplicates, find all missing numbers, the set mismatch. After placement, every slot that doesn't hold its own number names a missing value, and the value sitting there is a duplicate. These relatives are standard practice, not from the source.

It's the wrong tool when the input is read-only or must keep its order (copying it costs O(n) space, so just use a set), when values aren't bounded by n, or when the answer is a single number that arithmetic finds without moving anything: one missing value in 0 … n is n(n + 1)/2 − sum. A sibling trick with the same O(1) space marks "v seen" by making nums[v − 1] negative, after first replacing non-positives with n + 1; it avoids the swaps but also mutates the input.

Understand and remember

  • n numbers can cover at most 1 … n → the answer is in 1 … n + 1 → only values in 1 … n matter → each has a unique home v − 1, so the array itself is a collision-free hash table
  • A swap happens only when slot v − 1 doesn't hold v, and afterwards it does → no swap ever evicts a value from its home → ≤ n swaps in total, ≤ 2n while-checks → O(n) despite the nested loop
  • After placement, the first slot i without i + 1 names the missing value → O(1) extra space → but the input is reordered, so it only fits when mutation is allowed
  • detail that matters Guard on the destination (nums[v − 1] != v) → a duplicate stops when its home is already taken → guarding on the source (v != i + 1) makes two equal values swap forever
  • detail that matters Python evaluates nums[i], nums[nums[i] - 1] = … left to right, so the second target uses the new nums[i] → read j = nums[i] − 1 first

4 · Compare against what you already know

vs Hashing and buckets: A Python set and this trick both answer "is v present?" in O(1). What does each use as the hash function and table, which design choice removes collisions here, and what does each cost?

Check
  • the set hashes arbitrary values into its own table, handling collisions; O(n) extra memory
  • here hash(v) = v − 1 and the input is the table; distinct values in 1 … n never collide
  • the trick needs a bounded value range and a mutable input; the set needs neither

vs Insertion sort: Both move values by swapping. Why is insertion sort's swap count up to n(n − 1)/2 while cyclic placement's is at most n?

Check
  • insertion sort moves a value one slot per swap, so a value far from home pays its whole distance
  • cyclic placement sends a value straight to its computed home in one swap
  • knowing the destination from the value itself is what removes the distance cost

5 · Predict commit to an answer before revealing

What does the algorithm return for [1, 1, 2, 2], and how many swaps does it make? Commit, then reveal.

Reveal

Answer 3, after 1 swap. At i = 0, 1 is home. At i = 1, v = 1 but slot 0 already holds 1: the guard stops (no swap). At i = 2, v = 2 and slot 1 holds 1 → swap → [1, 2, 1, 2]; now slot 2 holds 1, whose home is taken → stop. At i = 3, 2's home holds 2 → stop. Scan: slot 2 holds 1 ≠ 3 → return 3.
