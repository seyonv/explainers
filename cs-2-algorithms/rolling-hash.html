Rolling hash (Rabin–Karp)

Also called a polynomial rolling hash, Rabin–Karp fingerprinting, or a Karp–Rabin hash. The source has no section on it; this card adds it next to KMP and the suffix automaton, and uses it for the source's Longest Duplicate Substring.

Prime · 2 minutes before you read

The problem: KMP answers "where does this one pattern occur". Many string questions instead ask "are these two substrings equal?" thousands of times, for example to find any repeated substring. Comparing characters costs O(L) each time; you want an O(1) fingerprint per window.

Where it fits: Second Strings card, supplemented beside KMP. It reuses binary search on the answer ("a repeat of length L exists" is monotone) and hash sets from cs-1, and it is the interview alternative to the suffix automaton that follows.

In one breath

Read each length-m window of the text as an m-digit number in base B, reduced mod a prime p. Sliding one character right takes O(1): subtract the digit that leaves, shift by B, add the digit that enters. You compare two small numbers instead of two strings, and only check the actual characters when the numbers match.

Python's % always returns a value in 0 … p − 1, so the negative −8,532 needs no fix-up; in C or Java add p before taking the remainder.

Worked example: find "bra" in "abracadabra"

h("bra") = 30. Every window's hash, each computed from the one before by the slide:

Green = hash equals 30, characters checked, real match. Answer: [1, 8]. Seven windows are rejected by one integer comparison each.

With p = 101 there are only 101 possible hashes, so different strings must share them: of the 26³ = 17,576 lowercase three-letter strings, 172 hash to 30 (a random spread would give 17,576 / 101 ≈ 174). One is "ahw". Searching "xahwx" for "bra" gets a hash hit at i = 1 that the character check rejects: a spurious hit. Real code uses p ≈ 10⁹ or 2⁶¹ − 1.

In Python

def rabin_karp(text, pat, base=256, mod=101):
    m = len(pat)
    if m == 0 or m > len(text):
        return []
    top = pow(base, m - 1, mod)   # weight of the char that leaves
    hp = ht = 0
    for i in range(m):            # hash the pattern and first window
        hp = (hp * base + ord(pat[i])) % mod
        ht = (ht * base + ord(text[i])) % mod
    hits = []
    for i in range(len(text) - m + 1):
        if ht == hp and text[i:i + m] == pat:   # verify every hit
            hits.append(i)
        if i + m < len(text):     # slide: drop text[i], add text[i+m]
            ht = ((ht - ord(text[i]) * top) * base
                  + ord(text[i + m])) % mod
    return hits

print(rabin_karp("abracadabra", "bra"))  # → [1, 8]
print(rabin_karp("xahwx", "bra"))        # → [] (hit at 1 rejected)

Time O(n + m) expected, O(nm) worst · Space O(1) beyond the output. Each slide is O(1) and a character check only runs on a hash hit; with p ≫ n spurious hits are rare, so the checks add up to about m per real match. The worst case is many real matches ("aaa" in "aaaa…aaa") or an adversary who knows B and p.

Longest Duplicate Substring: "banana" → "ana"

The source solves this with a suffix automaton. The standard alternative: if some substring of length L repeats, so does its length-(L − 1) prefix, so "a repeat of length L exists" is monotone and you can binary search L. Each test hashes all n − L + 1 windows into a set, O(n).

def longest_dup_substring(s):
    lo, hi, best = 1, len(s) - 1, ""
    while lo <= hi:
        L = (lo + hi) // 2
        i = dup_of_length(s, L)   # start of a repeat, or -1
        if i >= 0:
            best, lo = s[i:i + L], L + 1
        else:
            hi = L - 1
    return best                   # "banana" → "ana"

Time O(n log n) expected · Space O(n). log n binary-search steps, each one O(n) pass of slides and set lookups. dup_of_length keys the set on a double hash (mod 2⁶¹ − 1 and mod 10⁹ + 7, random base); it is in code/.

Why one modulus is not enough here: the birthday problem

pattern search, n = 10⁶ windows vs one pattern hash: n / p = 10⁶ / (10⁹ + 7) ≈ 0.001 spurious hits duplicate set, n = 10⁵ windows, every pair can collide: C(n, 2) / p = 4,999,950,000 / (10⁹ + 7) ≈ 5.0 colliding pairs same set, double hash with p₂ = 10⁹ + 9: C(n, 2) / (p₁ · p₂) ≈ 5.0 × 10⁻⁹

Computed, treating hash values as uniformly random (a heuristic, not a theorem). The proven version: for two fixed different strings of length m and a base drawn uniformly at random, their hashes collide with probability at most (m − 1)/p, because their difference is a nonzero polynomial in B of degree below m, which has at most m − 1 roots mod p.

Why it beats the alternatives

✗ Compare at every shift

Check up to m characters at each of n − m + 1 starts: O(nm). For Longest Duplicate Substring, comparing all substrings is O(n³).

✗ KMP

Deterministic O(n + m) for one pattern, with no false hits. But it answers "where does this pattern occur", not "are these two substrings equal", so it cannot fill a set of windows.

✗ Suffix automaton or suffix array

O(n) (automaton) or O(n log n) (array) and exact, and they answer every repeat question at once. Much harder to write correctly under interview time.

✓ Rolling hash

Any window's fingerprint in O(1), so substring equality becomes integer equality. Under 20 lines, and it works for many patterns of one length, 2-D grids, and repeat-finding.

Is it always the tool?

No. For a single pattern in Python, use text.find(pat) or the in operator: they are written in C and beat any pure-Python loop. For a guaranteed worst case, use KMP or a suffix structure; a hash has no worst-case promise, and contest judges publish inputs that break a known fixed (B, p).

Reach for it when you need equality of many substrings: repeat detection (binary search plus a hash set, as above), many same-length patterns at once, plagiarism fingerprinting, or comparing substrings after O(n) preprocessing with prefix hashes. Pick a random base, a large prime (or two), and always verify a hit when a false positive would change the answer.

Understand and remember

  • Read a window as an m-digit number in base B mod p → sliding right = remove the leaving digit's weight B^(m−1), shift by B, add the entering digit → each window's hash in O(1) → substring equality becomes integer equality
  • Different strings can share a hash (172 of the 17,576 three-letter strings share 30 mod 101) → a hash hit is only a candidate → verify characters on every hit → correctness is kept, and spurious hits only cost time
  • One pattern vs n windows: ≈ n/p false hits; a set of n windows vs itself: ≈ C(n, 2)/p colliding pairs (≈ 5 for n = 10⁵, p ≈ 10⁹) → the birthday effect → double hash (p₁p₂ ≈ 10¹⁸) or verify, with a random base against adversaries
  • A length-L repeat implies a length-(L − 1) repeat → monotone → binary search L with an O(n) hash-set pass per test → Longest Duplicate Substring in O(n log n) expected ("banana" → "ana" in two tests)
  • detail that matters Python's % returns a value in 0 … p − 1 even for negatives → the slide's negative intermediate needs no fix-up; in C or Java add p first
