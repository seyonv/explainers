Binary search on the answer

Also called parametric search, bisecting the answer space, or "binary search on a monotone predicate". The cheat-sheet's Binary Search section uses it for Find kth Smallest Pair Distance (search the distance itself) and Find Minimum in Rotated Sorted Array (search an index with duplicates), both in C++.

In one breath

You don't need a sorted array to binary search; you need a yes/no question whose answers go no, no, …, no, yes, …, yes as x grows. Keep a range [lo, hi] that always holds the first yes, ask the question at the middle, and throw away the half that can't hold it. For k-th pair distance the question is "are there at least k pairs within distance d?", and the first d that says yes is the answer.

The predicate: nums = [1, 6, 1], k = 3

Sorted a = [1, 1, 6]; the three pair distances are 0, 5, 5. Raising d can only add pairs, so the count never drops and ok flips from no to yes exactly once. Answer = the first yes = 5. The search only computes ok at 2 of these 6 columns.

The one template, and its invariant

def first_true(lo, hi, ok):
    # invariant: ok(hi) is True, ok(x) is False for every x < lo
    while lo < hi:
        mid = (lo + hi) // 2      # floor: mid < hi, so hi = mid shrinks
        if ok(mid):
            hi = mid              # mid works: answer is mid or left
        else:
            lo = mid + 1          # mid fails: answer is right of mid
    return lo                     # lo == hi: the first True

Why the answer is a real distance: count(d) only changes at actual pair gaps, so the first d where it reaches k is one of them.

In Python

def pairs_within(a, d):
    """Pairs i < j of sorted a with a[j] - a[i] <= d. Two pointers."""
    count = j = 0
    for i in range(len(a)):
        while j < len(a) and a[j] <= a[i] + d:
            j += 1
        count += j - i - 1        # partners of i: i+1 .. j-1
    return count

def smallest_distance_pair(nums, k):
    a = sorted(nums)
    return first_true(0, a[-1] - a[0],
                      lambda d: pairs_within(a, d) >= k)

print(smallest_distance_pair([1, 3, 1], 1))   # → 0
print(smallest_distance_pair([1, 6, 1], 3))   # → 5

The source starts its count at −n and adds j − i, which counts i as its own partner once per i; j − i − 1 is the same total. bisect.bisect_left(range(lo, hi + 1), True, key=ok) (Python 3.10+) is this template built in.

Time O(n log n + n log W) · Space O(n). W = max − min. Sorting is n log n; each of the log W probes is one two-pointer pass, and j only moves forward, so a pass is at most 2n steps. The sorted copy is the O(n).

Rotated minimum, and why duplicates cost O(n)

Here the predicate is "is index x at or past the drop?", and the test is to compare nums[mid] with nums[hi]: bigger means the drop is to the right of mid, smaller means mid..hi climbs so the minimum is mid or left. Equal tells you nothing, so the source shrinks hi by one.

Why it beats the alternatives (k-th pair distance)

✗ List every pair, sort

O(n² log n) time and O(n²) memory: n = 10⁴ makes 49,995,000 distances before you read one.

✗ Heap of pairs

Pop the smallest gap k times from a heap seeded with neighbours: O((n + k) log n). Fine for small k, but k can be ≈ 5·10⁷ at n = 10⁴.

✗ Try d = 0, 1, 2, …

Same count, but linear in the answer: up to 10⁶ + 1 passes of 2·10⁴ steps ≈ 2·10¹⁰ when values reach 10⁶.

✓ Bisect d

20 passes instead of 10⁶ + 1, each O(n), with O(1) extra memory past the sort: ≈ 4·10⁵ pointer moves for the same input.

When does it apply?

Look for "minimise the maximum", "maximise the minimum", "smallest x such that…", or a k-th smallest over something too big to list (pair distances, a sorted matrix, a multiplication table). If you can write a fast check for "is the answer ≤ x?" and that check is monotone, bisect x. Capacity to ship in D days and Koko eating bananas are the same shape (standard practice, not in the source).

It's the wrong tool when the check isn't monotone (count == k above, or a rotated array with duplicates, where it degrades to O(n)), when the check itself is as slow as solving directly, or when the answer is a real number: lo never meets hi, so run a fixed number of rounds for the precision you need, or use Newton's method when the function is smooth.
