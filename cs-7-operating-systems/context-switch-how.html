How a context switch works

Also called a task switch or process switch; a thread switch when both tasks share one address space. The source guide's "How it works" heading is empty, so this card follows OSTEP chapter 6 (limited direct execution) and measured Python runs on an Apple M3.

In one breath

A CPU core can run only one task at a time. To swap tasks, the kernel copies the running task's registers (its program counter, stack pointer and working values) into memory it keeps for that task, loads the registers it saved earlier for the next task, and, if that task is a different process, points the CPU at the other process's page table. The next task then carries on exactly where it stopped.

Worked example: a timer tick moves the core from A to B

What happensWho does it
①A timer (or a syscall, or a page fault) traps into the kernel. The core switches to kernel mode and to A's kernel stack.hardware
②A's user registers go onto A's kernel stack; the kernel's switch() then stores A's kernel-side registers in A's process control block (PCB).hardware, then kernel
③The scheduler chooses B from the ready queue.kernel
④Point the MMU at B's page table. Process switch only: threads of one process skip this, and their cached address translations stay valid.kernel
⑤–⑥Load B's registers from B's PCB and kernel stack, drop to user mode, and jump to B's saved program counter.kernel, then hardware

Two saves happen, as in OSTEP's figure 6.3: hardware saves user registers on the trap, and the OS saves kernel registers in switch(). Details vary by kernel; this is the textbook shape.

What "the registers" means on the M3

AArch64 state a switch must preserve (architectural registers): X0–X30 31 × 8 B = 248 B general-purpose (X30 = return address) SP, PC, PSTATE 3 × 8 B = 24 B stack pointer, program counter, flags V0–V31 32 × 16 B = 512 B floating-point and SIMD total = 784 B (plus FPSR/FPCR and the page-table base)

Computed from the register counts in Arm's calling standard (AAPCS64). Under a kilobyte: copying it is cheap. The expensive part is what the next task finds in the caches, shown below.

class PCB:                          # what the kernel keeps per task
    def __init__(self, name, pc, sp, space):
        self.name = name
        self.regs = {"pc": pc, "sp": sp, "r0": 0, "ptbr": space}

def switch(cur, nxt):
    cur.regs = dict(CPU)            # 1. save registers into PCB
    new_space = nxt.regs["ptbr"] != CPU["ptbr"]
    CPU.update(nxt.regs)            # 2. load next task's registers
    return new_space                # 3. new page table? (process)

Why save just the registers

✗ Never switch: run to completion

No overhead, but one long or stuck job holds the core and nothing else, including your shell, gets a turn.

✗ Only switch when a task yields

Cooperative switching (early Mac OS, asyncio inside one thread) is cheap, but a task that loops without yielding freezes all the others (OSTEP 6.2).

✗ Copy the whole memory image out

Swapping an entire process to disk works but costs time in proportion to its memory, not its registers. Kernels do it only under memory pressure.

✓ Save registers, swap a page-table pointer

Memory stays where it is; the page table decides what each process sees. The copy is under a kilobyte, and a timer makes it preemptive.

Is a context switch just a small copy?

The copy is, but the bill comes later. The next task finds caches and the TLB full of the previous task's data. Li, Ding and Shen measured a direct cost of 3.4 µs, then mean total costs of 4.1, 12.1 and 22.4 µs as each process's working set grew past the L1 and L2 caches, and up to 112 µs with scattered access. Tagged TLBs (ASIDs on ARM) avoid flushing translations on a process switch; see the hardware card.

So switching isn't always the right tool. For thousands of mostly waiting tasks, user-level switching (asyncio, green threads) avoids the kernel entirely: 10,000 concurrent asyncio.sleep(0.1) finished in 0.25 s total (measured, M3). For hot CPU-bound work, fewer threads than cores and pinning keep caches warm: Tsuna's pinned switches were roughly half the cost of unpinned ones (about 3.0–4.5 µs).
