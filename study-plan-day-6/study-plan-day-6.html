Study plan · Day 6

Memory is the product: attention and the KV cache

Day 6 of the inference study plan: how attention is computed without storing every score, how to make each token's KV smaller, how engines manage KV memory in pages, and how they reuse it across requests. It covers the Attention and the KV cache course and Serving station 4.

By the end of all of this, you'll be able to
  • Explain how FlashAttention computes exact attention without storing the full score matrix, and why that saves memory traffic rather than maths.
  • Compare grouped-query attention, multi-head latent attention and a quantized KV cache by bytes per token and what each costs.
  • Explain PagedAttention: KV memory as pages, sharing with copy-on-write, and why it lets a bigger batch fit.
  • Explain how RadixAttention and Mooncake reuse KV across requests, and when reuse pays for itself.
  • Say what changes for long contexts: sliding windows, ring attention and sparse attention.
The same routine every phase
  1. Prime (5–10 min): skim headings and each card's Prime box, nothing else.
  2. Pretest: try the phase's checkpoint cold. Getting it wrong tells your brain what to look for.
  3. Read in order, and do each card's Retrieve questions with the card closed.
  4. Take the checkpoint for real. Open “Go deeper” only for cards whose questions you missed.

Phase 2 · Smaller KV, fuller pool

~1.75 h · 0 / 7

Three ways to shrink each token's KV, then paging, which stops memory being wasted between requests.

Prime: skim the Prime box on each card below, then try Checkpoint 2 cold for 5 minutes before reading.

  1. Grouped-query attentionFewer key and value heads, shared by many query heads. Llama-3.1-8B uses it.
  2. Multi-head latent attention (DeepSeek)Store a small compressed version of K and V instead.
  3. Quantizing the KV cacheFewer bits per stored number, and what it can cost in quality.

  5. PagedAttention II: sharing, copy-on-write and preemptionPages shared between requests until one of them writes.
