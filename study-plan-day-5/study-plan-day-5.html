Study plan · Day 5

Build the scheduler

Day 5 of the inference study plan: the part of an engine that decides, on every step, which requests run and how much memory each gets. It covers Part 3 of the request-scheduler course, where you build one in Python, then maps it onto vLLM's real scheduler.

By the end of all of this, you'll be able to
  • State the interface of a request scheduler and the states a request moves through, from waiting to finished.
  • Walk through one call of step(): which requests run, how many tokens each gets, and what happens when memory runs out.
  • Explain how a paged block manager hands out KV memory, and why preemption can thrash.
  • Compare scheduling policies (first come first served, shortest job first, priority) on latency and fairness.
  • Explain prefix caching: how a shared prompt is found and reused instead of being prefilled again.
  • Map each part of vLLM's scheduler onto the reference solution.
The same routine every phase
  1. Prime (5–10 min): skim headings and each card's Prime box, nothing else.
  2. Pretest: try the phase's checkpoint cold. Getting it wrong tells your brain what to look for.
  3. Read in order, and do each card's Retrieve questions with the card closed.
  4. Take the checkpoint for real. Open “Go deeper” only for cards whose questions you missed.
