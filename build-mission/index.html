The mission · Build an LLM

Train a GPT from scratch, and find where it beats fine-tuned GPT-2

Find out how much domain text a tiny GPT trained from scratch needs before it beats fine-tuned GPT-2, measured in bits per byte on weather-service forecast discussions. This page is the finished result, written as the post you'll make at the end. Every day of the path fills in one rung.

Why this is worth posting

It answers a question people with niche data actually have

Fine-tune or train from scratch? Below some amount of text, a pretrained model's head start wins; above it, a small model that only ever saw your domain may win. The crossover is the useful number, and it depends on the domain, so it has to be measured, not looked up.

The test set can't have leaked

Training text is from 2018–24 and the test text from 2025–26, years after GPT-2's training data, which cuts off at the end of 2017. Every model is scored on the same 998,626 bytes; the file's SHA-256 is on this page.

Bits per byte puts every model on one scale

A byte model, GPT-2's tokenizer and a compressor all split text differently. Bits per byte divides the total surprise by the bytes of text, so the tokenizer can't flatter anyone.

Even a null result is a chart worth posting

If fine-tuned GPT-2 wins at every size up to 100 MB, that's the answer for anyone with this much text: fine-tune. The sweep also tests a published result at a tiny scale: Muennighoff et al. found that up to 4 epochs of repeated data changes the loss very little compared with unique data. The sweep checks 6.67 passes against 2, past that range.

What makes the comparison fair

  • Every model is scored on the same test file: 998,626 bytes of discussions from 7 days in 2025–26, SHA-256 7ad8c9d8cbc73a674d086d954b651903ba18ed52c61b16e82f1fa1c5cfd86b4c.
  • Copied-forward paragraphs are removed before splitting: an office's updated discussion repeats most of its earlier one, which would flatter every model.
  • Early stopping, every setting, and which run is drawn or named best are chosen on a separate validation file (discussions from 2024-12-10 and 2024-12-20), never on test.
  • GPT-2's fine-tune may use up to the training FLOPs of the largest from-scratch model on the same text, so the baseline is never short of compute. Three seeds for the runs you post.

Your first 15 minutes

Download the corpus (about 2 minutes on our connection), then score the compressors, a byte bigram and GPT-2 on the test file. No GPU, no account.

What could go wrong, and the fallback

  • Fine-tuned GPT-2 wins at every size. Leave the crossover empty and rewrite the tweet's two crossover lines as one: “up to 100 MB of this kind of text, fine-tune GPT-2”. It's still a crossover chart, with the crossover off the right edge, and the epochs question still has an answer.
  • The curves sit inside each other's noise. Run three seeds for the sizes near the crossover and show the spread. A crossover you can't separate from noise is reported as a range.
  • The archive changes and your test file differs. Compare your test file's SHA-256 with the one above. If it differs, your numbers are still internally fair, but say so before comparing with anyone else's.

What would make this wrong
  • Test text that leaked into training. Training days end in 2024 and test days start in 2025; say so, with the test file's SHA-256.
  • Copied-forward paragraphs left in. They make every model look better and the gap look smaller; the corpus script removes them, and the post should say how.
  • Settings tuned on the test file. Early stopping and every choice use the validation file only.
  • One seed near the crossover. Run three there and show the spread.
