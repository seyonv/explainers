A* search

Also called A-star, or best-first search on f = g + h. Dijkstra's algorithm with a sense of direction: it pops the node with the smallest cost-so-far plus estimated cost-to-go. The source guide's A* heading is empty, but its Shortest Path in Binary Matrix is A* in disguise: scipy's Dijkstra on edges reweighted by a Chebyshev potential.

In one breath

Dijkstra grows a circle of settled nodes around the start, because it only knows how far each node is from where it began. A* also adds a guess h of how far each node is from the target. As long as the guess never overestimates, the first time the target comes off the heap its cost is optimal, and nodes pointing away from the target mostly never get expanded.

Worked example: grid = [[0,0,0],[1,1,0],[1,1,0]] → 4

Moves go 8 ways, so the Chebyshev distance h = max(2 − i, 2 − j) is the number of king moves left if there were no walls. It can only underestimate. Green = the path, 3 moves = 4 cells; grey dashed = queued but never popped. BFS pops all 5 open cells; A* pops 4.

Why the source's reweighted Dijkstra is A*

The source never writes a heuristic. It changes every edge weight using a potential h, runs plain Dijkstra, and corrects the answer at the end:

w′(u,v)new weight = w(u,v)+h(v)−h(u) d′(u)what Dijkstra sorts by = g(u)+h(u)A*'s f(u) − h(s)same for every u
woriginal edge cost1 per move here hthe potential: Chebyshev distance to the targeth(s) = 2, h(t) = 0 g(u)true cost from start s to u3 at the target w′ ≥ 0needs h(u) ≤ w(u, v) + h(v): a consistent hChebyshev: w′ ∈ {0, 1, 2}
h terms cancel in pairs: w′(path) = w(path) + h(t) − h(s) (0,0)→(0,1): 1 + 2 − 2 = 1 (0,1)→(1,2): 1 + 1 − 2 = 0 (1,2)→(2,2): 1 + 0 − 1 = 0 d′(t) = 1 + 0 + 0 = 1 → d(t) = 1 + h(s) − h(t) = 1 + 2 − 0 = 3 moves = 4 cells

Every path from s to t shifts by the same constant, so the shortest path doesn't change. Dijkstra pops in order of d′ = f − h(s), which is A*'s order. This is also the reweighting in Johnson's algorithm (CLRS 25.3); calling the source's trick A* is our reading, since the source doesn't say so.

In Python

import heapq

def astar(grid):
    n = len(grid)
    if grid[0][0] or grid[-1][-1]:
        return -1
    h = lambda i, j: max(n - 1 - i, n - 1 - j)   # Chebyshev
    g = {(0, 0): 0}
    heap = [(h(0, 0), 0, (0, 0))]       # (f, -g, cell)
    done = set()
    while heap:
        _, neg_g, (i, j) = heapq.heappop(heap)
        if (i, j) in done:
            continue                    # stale entry
        done.add((i, j))
        if (i, j) == (n - 1, n - 1):
            return -neg_g + 1           # moves + 1 = cells
        for a in (i - 1, i, i + 1):
            for b in (j - 1, j, j + 1):
                if 0 <= a < n and 0 <= b < n and not grid[a][b]:
                    gv = -neg_g + 1
                    if gv < g.get((a, b), n * n):
                        g[(a, b)] = gv
                        f = gv + h(a, b)
                        heapq.heappush(heap, (f, -gv, (a, b)))
    return -1

print(astar([[0, 0, 0], [1, 1, 0], [1, 1, 0]]))   # → 4

Time O(E log V) · Space O(V) in the worst case, the same as Dijkstra: with h = 0 it is Dijkstra. A good h doesn't change the bound; it cuts how many nodes get expanded, from 400 to 20 on the open grid. Here V = n² cells and E ≤ 8V.

Why it beats the alternatives

✗ Breadth-first search

Right answer on unit weights, but no sense of direction: it popped all 400 cells of the open grid to find a 20-cell path.

✗ Dijkstra, or scipy's full run

Handles weights, still expands in a circle: 381 on the wall grid. The source's scipy call settles every reachable cell, even after the reweighting.

✗ Greedy best-first (f = h)

Chases the target and ignores the cost so far. On the wall grid it expanded 216 cells and returned a 36-cell path; the shortest is 30.

✓ A* with a consistent h

Optimal like Dijkstra, directed like greedy: 20 expanded on the open grid, 174 on the wall grid, both with the shortest path.

Is A* always the tool?

Only for one start and one target with a heuristic worth having. If you need distances to every node (Network Delay Time), there is no target to aim at, so use Dijkstra or BFS. If h is weak, A* expands about what Dijkstra does and pays for computing h on top; on unit-weight grids this small, BFS is simpler and fine.

A* also keeps the whole frontier in memory. On huge implicit graphs (puzzles like the 15-puzzle) people use IDA*, which trades repeated work for O(depth) memory. An inadmissible h, like Manhattan with diagonal moves, makes it faster but can return a longer path, as the 7-vs-6 grid shows. These points are standard practice, not from the source.
