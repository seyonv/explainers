Dijkstra's algorithm

Also called single-source shortest paths, or uniform-cost search when it stops at one target. It finds the cheapest route from one node to every other when no edge weight is negative. The source guide's Dijkstra's heading is empty; its Graphs › Distance section calls scipy's version for Network Delay Time and a missing Graph class for Shortest Path with Alternating Colors.

Prime · 2 minutes before you read

The problem: BFS counts hops, so on a weighted graph it returns A-C-E at cost 12 when a four-edge route costs 10. Trying every path is exponential, and relaxing every edge over and over (Bellman–Ford) costs O(V·E). With no negative weights there is a much cheaper safe order.

Where it fits: First card of the shortest-paths part. It is BFS from the layers card with the queue replaced by a heap from course 1, and it introduces the relax step that Bellman–Ford, Floyd and A* all share.

In one breath

Keep a min-heap of (distance so far, node). Pop the closest unfinished node: nothing still in the heap can beat its distance, because every other route has to leave the heap at a cost at least that big and weights only add. Mark it final, try each out-edge ("relax" it), push any improvement, and repeat.

In Python

import heapq
from collections import defaultdict
INF = float("inf")

def dijkstra(adj, source):
    dist = {source: 0}
    done = set()
    heap = [(0, source)]
    while heap:
        d, u = heapq.heappop(heap)
        if u in done:                  # stale entry: skip it
            continue
        done.add(u)                    # d is now final for u
        for v, w in adj.get(u, ()):
            if d + w < dist.get(v, INF):
                dist[v] = d + w        # relax: a shorter way to v
                heapq.heappush(heap, (d + w, v))
    return dist

def network_delay_time(times, n, k):
    adj = defaultdict(list)
    for u, v, w in times:
        adj[u].append((v, w))
    dist = dijkstra(adj, k)
    return max(dist.values()) if len(dist) == n else -1

print(network_delay_time([[2,1,1],[2,3,1],[3,4,1]], 4, 2))  # → 2

Time O((V + E) log V) · Space O(V + E). Each successful relaxation pushes once, so the heap sees at most E + 1 pushes and pops, each O(log E) = O(log V) since E < V². Every node's edge list is scanned once, when it becomes final. The code file checks this against Bellman–Ford on 2,000 random graphs.

Why it beats the alternatives

✗ BFS, counting hops

Ignores weights. On this graph it picks A-C-E, 2 hops but cost 2 + 10 = 12, not 10.

✗ Bellman–Ford

Relaxes every edge V − 1 times: O(V·E). For V = 10⁴, E = 5·10⁴ that is 5·10⁸ relaxations. Needed only if weights can be negative.

✗ Dijkstra with an array, no heap

Scan all V nodes for the closest each round: O(V²) = 10⁸ for V = 10⁴. Only wins on dense graphs where E is near V².

✓ Dijkstra with a heap

(V + E) log₂ V ≈ 6·10⁴ × 13.3 ≈ 8.0·10⁵ steps for the same sparse graph, and each node is finalised exactly once.

When does it give the wrong answer?

With a negative edge. Take A→B 2, A→C 3, C→B −2, B→D 1. Dijkstra pops B at 2 and finalises it, sets D = 3, then finds B = 3 − 2 = 1 via C. But B is already done, so its (1, B) entry is skipped and D stays at 3; the true answer is 2 (Bellman–Ford). Use Bellman–Ford, or reweight with Johnson's potentials, whenever a weight can be negative.

It's also not the fastest tool when weights are all equal (plain BFS, O(V + E)) or only 0 and 1 (0-1 BFS with a deque). For one known target on a map, A* adds a lower-bound estimate so it pops fewer nodes. With a hop limit, as in Cheapest Flights Within K Stops, the node alone isn't enough state; use Bellman–Ford rounds. These points are standard practice (CLRS ch. 24), not from the source.

Understand and remember

  • Pop the smallest tentative distance → every other route must leave the heap at a cost at least that big → weights only add (≥ 0) → nothing can beat it → mark it final and relax its out-edges once
  • A negative edge lets a later, longer-looking route become cheaper → a node already finalised can't be lowered → D stays 3 where the true answer is 2 on the card's example → use Bellman–Ford
  • heapq can't decrease a key → push a new (dist, node) pair and skip old ones when popped → at most one push per successful relax → O((V + E) log V)
  • If the node alone can't decide the future (colour of the next edge, stops used) → make the state (node, extra) → Dijkstra runs unchanged on the bigger graph
  • detail that matters Array-scan Dijkstra (no heap) costs O(V²) → better only when E is near V² → on a sparse 10⁴-node graph it's 10⁸ vs about 8.0 × 10⁵ steps
