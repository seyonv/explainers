Checkpoint 3: states, tables and search

Ties together recursion to DP, DP on two strings, grid DP, state-machine DP, reconstructing the path and backtracking: choosing the state, choosing the fill direction, getting the answer's path back, and knowing when no cache can help.

How to use this page. Close the six cards. Answer each question in writing, in full sentences, before opening its Check. A wrong or shaky answer isn't a failure; it tells you exactly which section to reopen. The questions are mixed on purpose, so you have to work out which idea applies before you can answer.

1 · Mixed retrieval

  1. which concept?Two interview questions on the same digit string: (a) list every way to put + or − between the digits so the result is 0; (b) say how many ways there are. Which one is backtracking and which one is DP, and what is the deciding difference?
    Check
    • (a) lists answers, and the output can be exponential: backtracking, with pruning
    • (b) only counts: the state shrinks to (position, running sum), which repeats, so DP (Target Sum)
    • listing vs counting decides whether a cache can merge branches

    Missed it? Reopen backtracking, "Is backtracking always the tool?".

  2. Naive fib(30) makes 2,692,537 calls; the memoized version makes 59. Where do the 59 come from, and what does one cache hit save?
    Check
    • 31 misses (states 0 … 30, each computed once) + 28 hits = 59
    • a hit returns at once, so the whole subtree under that call is never made
    • cost = states × work per state

    Missed it? Reopen recursion to DP, "How fast the repeats pile up".

  3. which concept?A knight crosses a grid of rooms moving right or down; some rooms drain health, some restore it, and health must never drop to 0. A colleague fills the table from the top-left keeping the most health per room. Which idea explains why this is wrong, and what is the fix?
    Check
    • a forward path's fitness is two numbers (lowest dip so far, health now); one cell can keep only one
    • keeping the most health gives 8 on the card's dungeon where 7 is right
    • fill backwards: need = max(1, min(down, right) − room) summarises the whole future in one number

    Missed it? Reopen grid DP, "Why filling it forwards fails".

  4. In the one-row version of distinct subsequences, why must j run from right to left, and what goes wrong on "rabbbit" / "rabbit" if it runs left to right?
    Check
    • dp[j] needs last row's dp[j − 1]; going right to left, dp[j − 1] hasn't been overwritten yet
    • left to right, a b first bumps dp[3] and then dp[4] reads that fresh value: one b is used twice
    • the answer comes out 6 instead of 3

    Missed it? Reopen DP on two strings, worked example 2.

  5. which concept?Stock prices for 10⁵ days, at most 3 buy-sell trades. A table with an inner loop over buy days is O(k·n²). What replaces the inner loop, and what is the new cost?
    Check
    • state-machine DP: keep cj (best cost while holding share j) and pj (best profit after j sells)
    • cj = min(cj, x − pj−1) is a running min: exactly the best earlier buy
    • 2k = 6 updates per day: 6 × 10⁵ in all, O(n·k) time, O(k) space

    Missed it? Reopen state-machine DP, "Why it beats the alternatives".

  6. which concept?Coin Path wants the cheapest route and, on ties, the lexicographically smallest one. Why does a forward fill with parent pointers get it wrong on four zero coins, and what fixes it?
    Check
    • a forward parent is the last step into a cell, so its tie-break settles the back of the path first
    • lexicographic order compares the front first; forward gives [1, 2, 4] instead of [1, 2, 3, 4]
    • fill backwards so next[i] is the first step, and keep the smallest j on ties (strict < with j rising)

    Missed it? Reopen reconstructing the path, "Why backwards makes the tie-break free".

  7. Top-down with @lru_cache works for fib(400) but raises RecursionError for fib(1000). Why, and what are two fixes?
    Check
    • a cold top-down call recurses n deep before anything is cached; the limit is 1,000 frames, and lru_cache's wrapper halves the reach (498 on the card)
    • fix 1: bottom-up table or two variables, no recursion
    • fix 2: warm the cache in increasing order first

    Missed it? Reopen recursion to DP, "The recursion limit".

3 · Project: an edit-script engine

What it reinforces: exponential recursion vs a cache (recursion to DP), a prefix table and rolling rows (two strings), a table as a DAG filled in the right direction (grid DP), pointers and a tie-break (reconstructing the path), and listing every optimal answer (backtracking). Edit distance with insert, delete and replace, each costing 1, from "intention" to "execution".

In about 60 lines of Python:

  1. Recursion, then cache. Write ed(i, j) on the prefixes: if the last characters match, recurse on (i − 1, j − 1) only; otherwise 1 + the min of the three moves. Count its calls. Add @lru_cache and read cache_info().
  2. Table. Fill the (m + 1) × (n + 1) table bottom-up, then redo it with one rolling row. Both must give the same answer.
  3. Backwards, with pointers. Fill a suffix table S[i][j] = distance from a[i:] to b[j:], from the bottom-right. Walk from (0, 0), and at each step take the first optimal move in the order keep/replace, delete, insert. Print the script.
  4. Count, then list. Count the optimal scripts with a DP over S (sum the counts of every optimal move). Then list them all with backtracking that only follows optimal moves, and count the states it visits.
Done when: the recursion, the cache, the full table, the rolling row and the suffix table all agree on the distance; your script has exactly that many non-keep steps; and your counting DP and your backtracking list agree on the number of optimal scripts. Then compare with the check.
Check: the numbers (computed with a Python version of exactly these steps)
  • Distance 5. Naive recursion: 1,709 calls. With the cache: 40 misses and 36 hits. The full table has 10 × 10 = 100 cells.
  • Script with keep/replace first: replace i→e, n→x, t→e, e→c, n→u, then keep t, i, o, n. Five edits, matching the distance.
  • Optimal scripts: 7, both by the counting DP and by listing. The backtracking that follows only optimal moves visits 55 states; without S to guide it, it would have to try every alignment.
  • Why pointers from the suffix table: S[i][j] is about the rest of the strings, so the first move of the walk is chosen first, the same reason Coin Path fills backwards for its lexicographic tie-break.
