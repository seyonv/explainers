Breadth-first search in layers

Also called BFS, level-order search, or the unweighted shortest path. It explores everything one hop away before anything two hops away, so the first time it reaches a node, it has used the fewest hops. The source guide uses it for Bus Routes, under Breadth-first Search, and for Jump Game III and Snakes and Ladders, under Distance.

In one breath

Put the start in a queue. Take nodes out in the order they went in, and add each unseen neighbour to the back. The queue then holds layer 0, then layer 1, then layer 2, and so on, so a node's layer number is its shortest hop count from the start.

Worked example: routes = [[1, 2, 7], [3, 6, 7]], stop 1 → stop 6 → 2 buses

The trick is the graph, not the search: stops and buses are both nodes, and a stop links to every bus that passes through it. Boarding a bus puts you one layer further out. Green = the path found, 1 → bus 0 → 7 → bus 1 → 6; grey = reached but not needed.

Green chip = the current frontier. Stops are marked seen when first discovered, so each one enters a frontier at most once. The source's version queues (stop, buses) pairs and checks the target when it pops them: (1, 0) (2, 1) (7, 1) (3, 2) (6, 2) → 2. It visits the same layers, one pair at a time.

Why the first arrival is the shortest

queue, front to back: d, d, …, d, d+1, …, d+1 (at most two layer numbers) a node found from u gets dist = dist[u] + 1, and u left the queue in layer order so every node at distance d is found before any node at distance d+1

Run it on the course's graph with weights ignored (A→B, A→C, C→B, B→D, C→D, C→E, D→E). BFS from A gives layers A | B C | D E, so E is 2 hops away (A-C-E). A depth-first search that follows neighbours in listed order goes A-B-D-E and first reaches E at depth 3. It found a path, but nothing tells it that path was the shortest.

In Python

from collections import defaultdict

def num_buses(routes, source, target):
    if source == target:
        return 0
    by_stop = defaultdict(list)          # stop -> buses through it
    for bus, route in enumerate(routes):
        for stop in route:
            by_stop[stop].append(bus)
    seen_stops, used_buses = {source}, set()
    frontier, buses = [source], 0
    while frontier:
        buses += 1                       # one more bus per layer
        nxt = []
        for stop in frontier:
            for bus in by_stop[stop]:
                if bus in used_buses:    # each bus boarded once
                    continue
                used_buses.add(bus)
                for s in routes[bus]:
                    if s == target:
                        return buses
                    if s not in seen_stops:
                        seen_stops.add(s)
                        nxt.append(s)
        frontier = nxt
    return -1

print(num_buses([[1, 2, 7], [3, 6, 7]], 1, 6))   # → 2

Time O(S) · Space O(S), where S is the total number of stops across all routes (6 here). Each bus is boarded at most once, so each route list is scanned at most once, and each stop joins a frontier at most once. The code file checks this version against the source's on 2,000 random inputs.

Why it beats the alternatives

✗ Depth-first search

Finds a path, not the shortest one. On the course's graph it reaches E at depth 3; BFS says 2. To be sure, DFS would have to try every path.

✗ Dijkstra with every weight 1

The source's route for the one-liners. The answer is right, but a heap costs O((V + E) log V) for what a plain queue does in O(V + E).

✗ Stop-to-stop edges

Link every pair of stops on a route and BFS over stops. One route of L stops becomes L(L − 1) edges: 9,999,900,000 for L = 100,000.

✓ BFS on stops and buses

A stop links to its buses, so that same route costs 100,000 links. Each bus is boarded once and each stop queued once: O(S) total.

Is BFS always the shortest-path tool?

Only when every edge costs the same. Put the weights back on the course's graph and BFS still picks A-C-E (2 hops, cost 2 + 10 = 12), while the cheapest route is A-C-B-D-E (4 hops, cost 2 + 1 + 5 + 2 = 10). For weights use Dijkstra; for weights of only 0 and 1, a deque that puts 0-cost neighbours at the front (0-1 BFS) keeps O(V + E).

BFS also holds a whole layer in memory, and with b choices per step layer d can hold bd nodes. When one start and one target are known, bidirectional BFS grows two smaller searches that meet in the middle. These points are standard practice, not from the source.
