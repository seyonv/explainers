Modular arithmetic essentials

Also called clock arithmetic, congruences, or "return the answer mod 10⁹ + 7". Four tools cover most interview uses: fast power, the Fermat inverse, n-choose-k from factorial tables, and the pigeonhole principle. The source guide's Discrete Math heading is empty, so this card is supplemented.

In one breath

Work with remainders instead of whole numbers. Adding, subtracting and multiplying commute with taking the remainder, so you can reduce after every step and the numbers never grow past the modulus. Dividing doesn't: to divide by a mod a prime p, multiply by ap−2 instead.

Why 10⁹ + 7: it's prime, so every a from 1 to p − 1 has an inverse, and (p − 1)² = 1,000,000,012,000,000,036 < 2⁶³, so one product fits in a signed 64-bit integer before you reduce it.

inverse, mod 7: 3⁵ = 243 = 34·7 + 5 → 3⁻¹ = 5; check 3·5 = 15 ≡ 1 inverse, mod p: pow(3, p−2, p) = 333333336 ; check 3·333333336 = p + 1 ≡ 1 divide, mod 7: 10/2 → (10 mod 7)·2⁻¹ = 3·4 = 12 ≡ 5 = 10//2 (3/2 isn't an integer) C(100, 50) mod p = fact[100]·inv[50]·inv[50] = 538992043 = math.comb(100, 50) % p

Floor division on reduced numbers is the classic trap: running c = c*(n-i)//(i+1) % p for C(100, 50) returns 307876912, not 538992043.

Worked example 3: pigeonhole on prefix sums

Claim: any n integers contain a contiguous slice whose sum is divisible by n. There are n + 1 prefix sums (counting the empty one) but only n remainders, so two prefixes share one, and the slice between them sums to a multiple of n. For nums = [3, 1, 4, 1, 5], n = 5:

prefix index012345 prefix sum0348914 sum mod 5034344

Prefixes 1 and 3 both land in box 3, so nums[1:3] = [1, 4] sums to 8 − 3 = 5. The principle guarantees a repeat among 6 prefixes; it doesn't say where.

In Python

P = 1_000_000_007

def pow_mod(a, e, m):          # built in: pow(a, e, m)
    result, base = 1, a % m
    while e:
        if e & 1:
            result = result * base % m   # bit is 1: multiply in
        base = base * base % m           # square for next bit
        e >>= 1
    return result

def comb_table(n, p=P):
    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % p
    inv = [1] * (n + 1)
    inv[n] = pow(fact[n], p - 2, p)      # the only Fermat call
    for i in range(n, 0, -1):
        inv[i - 1] = inv[i] * i % p      # 1/(i-1)! = i/i!
    return fact, inv

fact, inv = comb_table(100_000)
comb = lambda n, k: fact[n] * inv[k] % P * inv[n - k] % P
print(pow_mod(3, 200, P), pow(3, P - 2, P))
print(comb(100, 50), comb(100_000, 50_000))
# → 136318165 333333336
# → 538992043 149033233

Time O(log e) for the power · O(n + log p) to build the tables, then O(1) per n-choose-k · Space O(n). The power does one squaring per bit of e. The tables need only one Fermat call, because 1/(i − 1)! = i · 1/i! walks the inverses back down.

Why factorial tables beat the alternatives

The job: many C(n, k) mod p queries with n up to 10⁵.

✗ math.comb, then % p

Exact, but C(100000, 50000) has 99,992 bits (about 30,100 digits) before you reduce, and every query redoes it. Printing it in 3.10 raised ValueError (4,300-digit limit).

✗ Pascal's triangle mod p

Only additions, so it works for any modulus, prime or not. But rows 0 to 10⁵ hold 5,000,150,001 cells: O(n²) time and memory.

✗ Multiplicative formula with //

Fine on exact integers, wrong once reduced: after % p the division is no longer exact. It gives 307876912 for C(100, 50).

✓ Factorials + one inverse

2 × 10⁵ multiplies and one pow to build, then 2 multiplies per query. Every number stays below p.

Does this always work?

Only for a prime modulus larger than n. If p ≤ n, then n! contains p and becomes 0 mod p, so the table breaks: use Lucas's theorem to split n and k into base-p digits. If the modulus isn't prime (say 10⁹ or 2⁶⁴), Fermat's trick gives wrong answers. Use pow(a, -1, m) instead (Python 3.8+, extended Euclid), which raises ValueError when gcd(a, m) ≠ 1, as with 2 mod 4.

For one small query, math.comb(n, k) % p is simpler and exact. And pow(a, e, m) is built in: write the loop by hand only when an interviewer asks for it, or to get the trace.
