Palindrome partitioning II

Also called minimum palindrome cuts or palindromic factorization (LeetCode 132). The source guide solves it in C++ under Recursion › Palindrome Partitioning with a one-array DP that grows palindromes outward from each centre.

In one breath

Cut a string into pieces that each read the same both ways, using as few cuts as possible. Let cut[e] be the fewest cuts for the first e letters. Every palindrome s[b:e] you find offers a deal: take the best cuts for s[:b], then one more cut before the palindrome. Grow palindromes outward from every centre, and each one found updates one cut[e].

In Python

def min_cut(s):
    n = len(s)
    cut = list(range(-1, n))       # cut[e]: min cuts for s[:e]
    for c in range(n):             # centre c
        for k in (0, 1):           # k=0 odd length, k=1 even
            lo, hi = c, c + k      # s[lo..hi] is the window
            while lo >= 0 and hi < n and s[lo] == s[hi]:
                # s[lo:hi+1] is a palindrome: cut before it
                cut[hi + 1] = min(cut[hi + 1], cut[lo] + 1)
                lo, hi = lo - 1, hi + 1
    return cut[n]

print(min_cut("aab"))      # → 1   aa | b
print(min_cut("abccbc"))   # → 2   a | bccb | c

The source packs the update into the for-loop's increment, cut[i + j] = min(cut[i - j + k] + 1, cut[i + ++j]), which reads and increments j in one expression (clang: "unsequenced modification and access to 'j'"). It's right only if min's arguments run left to right, which C++ doesn't promise; clang 17 happens to, and gives 1 and 2. Here the update and the step are separate lines.

Time O(n²) · Space O(n). Each of the 2n − 1 centres grows at most about n/2 steps, and every step is one palindrome and one O(1) update. It's quadratic only when the string is full of palindromes: 2,000 a's hold 2,000 × 2,001 / 2 = 2,001,000 of them. There's no n × n palindrome table, only the n + 1 cuts.

Why it beats the alternatives

✗ Try every way to cut

Each of the n − 1 gaps is cut or not: 2n−1 partitions. 32 for "abccbc", 536,870,912 for n = 30.

✗ Greedy longest prefix

Bite off the longest palindrome at the front, repeat. The shortest a/b string it gets wrong is "aaba": aa | b | a is 2 cuts, but a | aba is 1.

✗ Palindrome table, then DP

Fill isPal[b][e] first, then run the same recurrence. Also O(n²) time and correct, but it stores n² booleans: 4,000,000 for n = 2,000.

✓ Expand around centres

Each palindrome is used the moment it's found and never stored, so memory is the n + 1 cuts: 7 numbers for "abccbc". Same O(n²) time, O(n) space.

Is this always how to do it?

For the fewest cuts, yes: it's the standard answer. It works because cut[b] is final before any palindrome starting at b is found: every palindrome ending at b − 1 has a centre left of the current one. That order argument is ours; the source gives only the code.

It's not the tool when you need every partition (Palindrome Partitioning I): the output itself can be exponential, so backtrack over the palindromic prefixes instead. To print the pieces, store which b won for each e and walk back, as in the path reconstruction card. And a faster palindrome finder such as Manacher doesn't change the O(n²) worst case here, because the DP still visits all 2,001,000 palindromes in the 2,000 a's.
