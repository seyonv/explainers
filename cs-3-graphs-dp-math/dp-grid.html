Grid DP, forwards and backwards

Also called path DP or DP on a DAG of cells. Moves only go right or down, so every cell's answer depends on its neighbours in one direction. The source guide's Recursion page has two hard cases: Dungeon Game, filled backwards from the princess, and Cherry Pickup, filled forwards with two walkers at once.

Prime · 2 minutes before you read

The problem: On a right/down grid the table can be filled from either corner, and picking the wrong one silently gives wrong answers: a forward Dungeon table says 8 where 7 is right. Cherry Pickup's two trips, solved one after the other, can strand cherries that one coordinated plan would collect.

Where it fits: Fourth DP card. The state question from the recursion-to-DP card ("what must I remember to finish optimally?") now decides both the direction of the fill and, for Cherry Pickup, a state with two walkers in it.

In one breath

On a right/down grid you can fill a table from either corner, but the table must hold everything the rest of the problem needs in one number per state. Pick the direction and the state that make that true: backwards when the answer is "what must I bring", forwards with both walkers side by side when two paths share cells.

Why filling it forwards fails

Walking forwards, one path's fitness is two numbers: the lowest point it dipped to so far (sets the start health, need = 1 − lowest running sum) and the health it has now (decides the future). A forward table that keeps one path per cell must rank by one of them, and each ranking loses on some grid.

Worked example 2: Cherry Pickup, [[0, 1, −1], [1, 0, −1], [1, 1, 1]] → 5

A trip there and back equals two trips there (reverse the return). Run both walkers at once: after k steps each sits on anti-diagonal i + j = k, so the state is just their two rows (r1, r2). When they stand on the same cell its cherry counts once, which is exactly what two separate trips can't coordinate.

In Python

import itertools

def min_hp(dungeon):
    m, n = len(dungeon), len(dungeon[0])
    need = [float("inf")] * (n + 1)  # row below, then this row
    need[n - 1] = 1                  # seed: survive with 1
    for i in range(m - 1, -1, -1):
        for j in range(n - 1, -1, -1):
            best_next = min(need[j], need[j + 1])  # down, right
            need[j] = max(best_next - dungeon[i][j], 1)
    return need[0]

def cherry_pickup(grid):
    n = len(grid)
    dp = [[-1] * n for _ in range(n)]  # dp[r1][r2], -1 = unreachable
    dp[0][0] = grid[0][0]
    for k in range(1, 2 * n - 1):
        new = [[-1] * n for _ in range(n)]
        for r1, r2 in itertools.product(range(n), repeat=2):
            c1, c2 = k - r1, k - r2
            if not (0 <= c1 < n and 0 <= c2 < n): continue
            if -1 in (grid[r1][c1], grid[r2][c2]): continue
            prev = max(dp[a][b] for a in (r1, r1 - 1)
                       for b in (r2, r2 - 1) if a >= 0 and b >= 0)
            if prev < 0: continue
            got = grid[r1][c1] + (grid[r2][c2] if r1 != r2 else 0)
            new[r1][r2] = prev + got
        dp = new
    return max(dp[n - 1][n - 1], 0)

print(min_hp([[-2, -3, 3], [-5, -10, 1], [10, 30, -5]]))  # → 7
print(cherry_pickup([[0, 1, -1], [1, 0, -1], [1, 1, 1]]))  # → 5

Both source solutions are correct (checked against brute force on 300 random grids each). The Dungeon code is rewritten from the source's C++; the source's Python Cherry Pickup updates one table in place by looping rows downwards, and a fresh table per diagonal is used here for readability.

Dungeon: Time O(mn) · Space O(n). Each room is filled once from two neighbours, and only the row below is ever read. Cherry Pickup: Time O(n³) · Space O(n²). 2n − 1 diagonals × n² row pairs × 4 predecessors; one diagonal's table at a time.

Why it beats the alternatives

✗ Forward DP on the dungeon

One number per cell can't hold both "lowest dip" and "health now". Keeping the most health says 8 on the source's grid; the answer is 7.

✗ Two greedy trips

The best single trip can strand the leftovers on opposite sides. 5 instead of 6 on the 4×4 grid above, even trying every best first trip.

✗ Try every path

An n × n grid has C(2n−2, n−1) right/down paths: 6 for n = 3, about 2.5 × 1028 for n = 50. Cherry Pickup would need every pair of them.

✓ Right direction, right state

Dungeon: 2,500 rooms for a 50 × 50 grid, one pass. Cherry Pickup: (2n − 1) × n² = 99 × 2,500 = 247,500 states for n = 50.

Does direction always matter?

No. For plain sums and counts (minimum path sum, unique paths) forwards and backwards give the same answer, so pick whichever is easier to code. Direction matters when the quantity isn't additive, like a minimum over prefixes: go backwards so it's always "what the rest needs". The alternative is binary-searching the start health and checking it forwards, O(mn log H). These are our reading and standard practice; the source gives only the code.

Grid DP needs moves that never return: right and down only, so the cells form a DAG. With four-way moves there are cycles and no fill order, so use BFS, Dijkstra or a binary search plus flood fill instead.

Understand and remember

  • A forward path's fitness is two numbers (lowest dip so far, health now) → one cell must rank paths by one of them → each ranking loses on some grid (8 vs 7; 3 vs 2) → go backwards: need[i][j] summarises the whole future in one number
  • need = max(1, min(down, right) − room) → a later big orb can't cancel an earlier deficit → the floor at 1 makes the quantity non-additive → which is exactly why direction matters
  • Two trips there and back = two walkers there at once → after k steps both sit on diagonal i + j = k → state (k, r1, r2) → a shared cell counts once → O(n³) instead of two greedy trips that can strand cherries (5 vs 6)
  • Right/down moves never return → cells form a DAG → a fill order exists; four-way moves create cycles → no fill order → BFS or Dijkstra
  • detail that matters The column follows from the row (c = k − r) → state (k, r1, r2) instead of (r1, c1, r2, c2) → n³ states instead of n⁴

Cherry Pickup on a 3 × 3 grid of all 1s (no thorns). Predict the maximum before computing: can the two walkers collect all 9 cherries?

Reveal

8, not 9. Each walker visits 5 cells, and both must use the start and end corners, so together they cover at most 5 + 5 − 2 = 8 distinct cells. The DP returns 8; the ninth cherry is always left behind.
