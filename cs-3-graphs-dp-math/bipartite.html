Bipartite graphs

Also called two-colourable graphs, or graphs whose nodes split into two sides with every edge crossing between them. The source guide lists them under Graphs › Cycle Detection, with Is Graph Bipartite? and Possible Bipartition as one-line calls to its Graph class.

Prime · 2 minutes before you read

The problem: "Split these people into two groups so no two rivals share a group" has 2ⁿ possible splits: over a billion at n = 30. You need a way to build the split directly, and a proof when none exists.

Where it fits: Seventh graph card. It is BFS from the layers card with one extra field per node, a colour, and the layer parity is exactly that colour.

Needs first: Breadth-first search in layers

You'll meet: 2-colouring BFS colours from an already-coloured neighbour the odd-cycle theorem a conflict edge as a certificate

By the end: Decide bipartiteness in O(V + E), and when the answer is no, produce the odd cycle that proves it.

In one breath

Colour any node A, then walk outward giving every neighbour the opposite colour. If you ever find an edge whose two ends already share a colour, no split exists, and that edge plus the search tree hands you an odd cycle as proof. A graph is bipartite exactly when it has no odd cycle.

Why an odd cycle is the only obstacle

colour(v)A or B = d(v)mod2parity of the BFS layer d(u)+d(v)−2d(w)+1length of the cycle a conflict edge u–v closes
d(v)BFS layer of v: hops from the start noded(1) = 0, d(2) = d(3) = 1 u–va conflict edge: same colour, so d(u) and d(v) have the same parity2–3 wwhere the tree paths from u and v first meet (lowest common ancestor)1
same parity => d(u) + d(v) is even => even − 2·d(w) + 1 is odd triangle: 1 + 1 − 2·0 + 1 = 3 edges, the cycle 2-1-3-2

The other direction is shorter: around any cycle the colours must alternate A, B, A, B…, so you only get back to the starting colour after an even number of steps. An odd cycle can never be coloured, and if BFS finishes with no conflict, its colouring is the proof there is none. The course's running graph (directions ignored) is not bipartite: A→B, A→C, C→B close the triangle B-A-C-B.

In Python

from collections import deque

def possible_bipartition(n, dislikes):
    adj = [[] for _ in range(n + 1)]
    for a, b in dislikes:                # undirected: store both ways
        adj[a].append(b)
        adj[b].append(a)
    colour = [None] * (n + 1)
    for s in range(1, n + 1):            # every component
        if colour[s] is not None:
            continue
        colour[s] = 0
        queue = deque([s])
        while queue:
            u = queue.popleft()
            for v in adj[u]:
                if colour[v] is None:
                    colour[v] = 1 - colour[u]    # opposite side
                    queue.append(v)
                elif colour[v] == colour[u]:
                    return False                 # odd cycle
    return True

print(possible_bipartition(4, [[1, 2], [1, 3], [2, 4]]))  # → True
print(possible_bipartition(3, [[1, 2], [1, 3], [2, 3]]))  # → False

The source calls Graph(...).bipartite() from code/graph.py, which is missing from the repo, and its Possible Bipartition stores each dislike one way (E[u][v] = 1), trusting directed=False to add the reverse. Written out here with both directions stored. The code file also returns the odd cycle and runs Is Graph Bipartite? (LeetCode 785 ex. 1 → False, ex. 2 → True).

Time O(V + E) · Space O(V + E). Each node is coloured and queued once, and each edge is looked at twice, once from each end. The outer loop restarts BFS in every component, so a graph with no edges still gets every node coloured.

Why it beats the alternatives

✗ Try every split

Check all 2n ways to put people in two groups. 16 for n = 4, but 1,073,741,824 for n = 30, each checked against every edge.

✗ Colour edges in input order

No search, just fix colours as edges arrive. On [[1,2],[3,4],[1,3]] it colours 1 and 3 both A, then says False for the bipartite path 2-1-3-4. Components start with an arbitrary colour and can't flip later.

✗ Recursive DFS

Correct, same O(V + E), but one call per node on the path. Python's default recursion limit is 1,000, so a 2,000-node chain raises RecursionError.

✓ BFS 2-colouring

O(V + E) with a queue, no recursion, and it colours each node from an already-coloured neighbour, so nothing is guessed. On failure the conflict edge gives an odd cycle as proof.

Is it always this easy?

Only for two groups. Deciding whether k colours are enough is NP-complete for every k ≥ 3, so "split into three teams with no rivals together" has no known linear algorithm; people use backtracking or a SAT solver. Likewise, if some dislikes may be broken and you want to break as few as possible, that is max-cut, which is also NP-hard.

For the yes/no question, union–find works too: union each node's neighbours together and fail if a node lands in its neighbour's set. It fits when edges arrive one at a time. Once a graph is known to be bipartite, the usual next step is matching on it (Hopcroft–Karp, or max flow). These points are standard practice, not from the source.

Understand and remember

  • Colour a start node → every neighbour must be the opposite colour → BFS forces every colour in the component → a same-colour edge means no 2-colouring exists
  • BFS colour = layer parity → a conflict edge u–v has d(u), d(v) of equal parity → the cycle through their meeting point has length d(u) + d(v) − 2d(w) + 1, which is odd → an odd cycle is the only obstacle
  • 2 colours: forced choices → O(V + E); 3 or more: choices are no longer forced → k-colouring is NP-complete for k ≥ 3 → backtracking or a SAT solver
  • detail that matters Colouring edges in input order without a search fails on disconnected pieces → [[1,2],[3,4],[1,3]] colours 1 and 3 alike and says False for a bipartite path → colour from an already-coloured neighbour only

Reference only

  • adjacency list built both ways for undirected input
  • LeetCode 785 and 886 input formats
  • Hopcroft–Karp matching as the usual next step
  • union–find as an incremental alternative

Reveal

Still bipartite: the new edge closes the cycle 1-2-4-3-1, which has 4 edges, an even cycle. BFS gives 1 A, 2 B, 3 B, 4 A, and the new edge 3–4 joins B to A, so no conflict. Groups {1, 4} and {2, 3}, unchanged.

The source guide files it under Stacks, as…In one breathAn Eulerian path exists when every node's in-edges and out-edges balance, except that the start may have one extra out and the end one extra in. To find it, walk along unused edges until you're stuck, write down where you're stuck, back up one step and keep walking. The list you wrote, reversed, is the path.
