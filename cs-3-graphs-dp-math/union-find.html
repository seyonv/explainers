Union–find

Also called disjoint-set union (DSU) or a merge–find set. Keeps groups that only ever merge, and says in near-constant time whether two items are in the same group. The source guide uses it under Connectivity for Number of Islands II: add land one cell at a time and report the island count after each add.

Prime · 2 minutes before you read

The problem: When land appears one cell at a time and you need the island count after every addition, rerunning a flood fill each time costs O(k·mn). You need a structure that merges groups and answers "same group?" in near-constant time.

Where it fits: Fifth graph card. It answers incrementally what the flood-fill card answers in one shot, and it becomes Kruskal's cycle test on the minimum spanning tree card.

Builds on: Depth-first search and flood fill · Big-O and amortized O(1)

In one breath

Every item points at a parent, and each group has one root that points at itself, so the root is the group's name. Find follows the pointers up to the root. Union finds both roots and, if they differ, hangs one under the other. Two tricks keep the trees flat: hang the smaller tree under the bigger one, and repoint every item you walk past straight at the root.

Worked example: m = 3, n = 3, positions [[0,0],[0,1],[1,2],[2,1]] → [1, 1, 2, 3]

Each land cell shows its island's root: A = (0,0), B = (1,2), C = (2,1). Green = the cell just added. Steps 1–4 are the source's example; step 5 adds (1,1), our own extra step to show several merges at once.

The four words, two examples each

Think of clubs where each member knows one person closer to the president. To ask "same club?", both walk up to their president and compare.

In Python

def num_islands2(m, n, positions):
    parent, size = {}, {}

    def find(x):
        root = x
        while parent[root] != root:     # walk up to the root
            root = parent[root]
        while parent[x] != root:        # path compression:
            nxt = parent[x]             # point every cell on the
            parent[x] = root            # path straight at the root
            x = nxt
        return root

    def union(a, b):                    # True if two islands merged
        ra, rb = find(a), find(b)
        if ra == rb:
            return False
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra                 # small tree under big root
        size[ra] += size[rb]
        return True

    islands, answer = 0, []
    for r, c in positions:
        if (r, c) not in parent:        # repeats change nothing
            parent[(r, c)], size[(r, c)] = (r, c), 1
            islands += 1
            for nb in [(r-1, c), (r, c-1), (r, c+1), (r+1, c)]:
                if nb in parent and union(nb, (r, c)):
                    islands -= 1
        answer.append(islands)
    return answer

pos = [[0, 0], [0, 1], [1, 2], [2, 1]]
print(num_islands2(3, 3, pos))              # → [1, 1, 2, 3]
print(num_islands2(3, 3, pos + [[1, 1]]))   # → [1, 1, 2, 3, 1]

The source's find(self, x) has a stray self and reads cell_root, which lives inside numIslands2, so it raises NameError; numIslands2 is also missing its colon. It has no size check either, so it relies on path compression alone: O(log n) amortized per operation instead of α(n). Corrected here: closures plus union by size. Off-grid neighbours need no bounds check because they are never in parent.

Time O(k · α(mn)) · Space O(k) for k adds. Each add does at most 4 unions, each union 2 finds, and with both tricks a find costs α(n) amortized, the inverse Ackermann function, which is at most 4 for any n up to A₄(1), a number far beyond 10⁸⁰ (CLRS §21.4). Only land cells are stored, so space tracks k, not m · n.

Why it beats the alternatives

✗ Recount after every add

A flood fill per add is O(k · mn). Filling a 100 × 100 grid cell by cell visits 1 + 2 + … + 10,000 = 50,005,000 land cells; union–find does at most 4 unions per add.

✗ An island id per cell

"Same island?" is O(1), but a merge rewrites every cell of one island, up to n − 1 writes. Relabelling the smaller side gets it to O(n log n) total, at the cost of a member list per island.

✗ Parent pointers, no tricks

Union in the wrong order builds a chain. For 10,000 items: depth 9,999, and finding every item costs 49,995,000 hops, which is n(n − 1)/2.

✓ Union by size + compression

Size alone caps depth at log₂ n (13 for 8,192). Adding compression makes each operation α(n) ≤ 4 amortized. Same 10,000-item unions: depth 1, 9,999 hops for all finds.

Hop counts from code/union-find.py (counted, not timed): the chain comes from calling union(i + 1, i) for i = 0 … 9,998, then find on every item.

Is it always the right tool?

Use it when groups only ever merge and the questions arrive along the way: islands appearing, Kruskal's minimum spanning tree (skip an edge whose ends already share a root), redundant connection, accounts merge. For one static grid (plain Number of Islands) a DFS flood fill is just as fast and simpler, which is what the source's one-liner count_components() does.

It's the wrong tool when things split: union–find can't undo a union, so deleting land or edges needs another approach, for example processing the operations backwards so deletions become additions. It also knows nothing about direction or distance: directed reachability needs DFS or strongly connected components, and "how far?" needs BFS or Dijkstra.

Understand and remember

  • Each group has one root that points at itself → find walks parent pointers to it → two items are connected exactly when their roots match → union only relinks one root
  • Hang the smaller tree under the bigger root → a node's depth grows only when its group at least doubles → depth ≤ log₂ n (13 for 8,192); add path compression → α(n) ≤ 4 amortized per operation
  • Without either trick, unions in the wrong order build a chain → finding all 10,000 items costs n(n − 1)/2 = 49,995,000 hops vs 9,999 with the tricks
  • Unions only merge → no way to split a group → deletions need another approach (process the operations backwards so they become additions)
  • detail that matters Only land cells enter the parent dict → off-grid and water neighbours are simply absent → no bounds checks needed, and space is O(k) not O(m·n)

Reference only

  • union by rank (height) as the textbook alternative to size
  • the exact α(n) bound and CLRS §21.4
  • the source's stray self and missing colon
  • path halving as a one-pass variant
