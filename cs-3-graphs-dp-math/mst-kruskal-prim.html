Minimum spanning trees

Also called an MST; the two standard ways to build one are Kruskal's algorithm and Prim's (or Jarník's) algorithm. The source guide's Connectivity section lists kruskal() and prim() as methods of its Graph class, each returning the tree as a defaultdict(dict), but gives no code, so this card writes both.

In one breath

Given an undirected, connected graph with weighted edges, pick V − 1 edges that connect every vertex with no cycle, at the lowest total weight: the cheapest way to wire everything together. Both algorithms are greedy and both are correct for the same reason. Kruskal takes the cheapest edge anywhere that doesn't close a cycle. Prim grows one tree from a start vertex, always adding the cheapest edge that leaves it.

Why greedy is safe: the two rules, two examples each

Think of wiring six towns: whatever split of the towns into two groups you draw, the cheapest cable between the groups is worth laying, and the priciest cable in any loop is never needed.

In Python

import heapq
from collections import defaultdict

def kruskal(vertices, edges):
    parent = {v: v for v in vertices}
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]   # path halving
            x = parent[x]
        return x
    tree = []
    for u, v, w in sorted(edges, key=lambda e: e[2]):
        ru, rv = find(u), find(v)
        if ru != rv:                 # different pieces: no cycle
            parent[ru] = rv          # merge the two pieces
            tree.append((u, v, w))
    return tree

def prim(edges, start):
    adj = defaultdict(list)
    for u, v, w in edges:
        adj[u].append((w, u, v))
        adj[v].append((w, v, u))
    seen, tree = {start}, []
    heap = list(adj[start])          # edges leaving the tree
    heapq.heapify(heap)
    while heap:
        w, u, v = heapq.heappop(heap)
        if v in seen:                # both ends inside: stale
            continue
        seen.add(v)
        tree.append((u, v, w))
        for e in adj[v]:
            if e[2] not in seen:
                heapq.heappush(heap, e)
    return tree

# kruskal: ['CB 1', 'AC 2', 'DE 2', 'EF 3', 'BD 5'] total 13
# prim:    ['AC 2', 'CB 1', 'BD 5', 'DE 2', 'EF 3'] total 13

Kruskal: Time O(E log E) · Space O(V + E). Sorting the edges dominates; the union–find calls cost almost nothing each (inverse-Ackermann α(V) with union by rank too; path halving alone still keeps them O(log V) amortised). Prim with a heap: Time O(E log V) · Space O(V + E). Each edge is pushed at most once (from whichever end joins the tree first, and only if the other end is still outside), so there are O(E) pushes and pops; a lazy heap can hold O(E) entries, and log E ≤ log V² = 2 log V, so O(E log E) and O(E log V) are the same bound.

Why it beats the alternatives

✗ Try every spanning tree

55 trees here. A complete graph on n vertices has nn−2 (Cayley): 64 = 1,296 for 6 vertices, 2018 ≈ 2.6 × 1023 for 20.

✗ Just take the 5 cheapest edges

C–B 1, A–C 2, D–E 2, E–F 3, A–B 4 sum to 12, less than 13, but A–B closes the cycle A–B–C and nothing joins ABC to DEF. It isn't a tree.

✗ Dijkstra's shortest-path tree

Minimises each distance from A, not the total. It reaches F via C–F 9 (distance 11, vs 13 along the MST), so its 5 edges weigh 19.

✓ Kruskal or Prim

One greedy pass, provably optimal by the cut property. 13, found after 6 of 9 sorted edges (Kruskal) or 6 pops (Prim).

Which one, and when is an MST the wrong question?

Pick Kruskal when you already have an edge list or the graph is sparse; it also gives a minimum spanning forest if the graph is disconnected, where Prim covers only the start vertex's component. Pick Prim with a heap for adjacency lists, or the O(V²) array version (no heap) for dense graphs where E is close to V². Negative weights are fine for both, unlike Dijkstra; for a maximum spanning tree, negate the weights.

An MST is not a shortest-path structure. The source's Cheapest Flights Within K Stops calls prim() and sums the tree: on the Bellman–Ford card's example that gives 400, but the cheapest 0 → 3 route with at most 1 stop costs 700. For directed graphs the analogue is a minimum arborescence (Chu–Liu/Edmonds), which neither algorithm finds.

The source's findCheapestPrice(n, flights) also drops the src, dst and k parameters; solved correctly with Bellman–Ford on its own card.
