Bellman–Ford and Floyd–Warshall

Also called edge relaxation in rounds (Bellman–Ford) and all-pairs shortest paths (Floyd–Warshall, or Roy–Warshall). Both are dynamic programs over paths, and both allow negative edge weights. The source guide uses Floyd–Warshall for Find the City, under Graphs › Distance, and solves Cheapest Flights Within K Stops with Prim, which is the wrong algorithm: this card solves it with Bellman–Ford.

In one breath

Bellman–Ford keeps one best-known cost per node and, in each round, tries every edge once: "is going through u cheaper than what v has?" After round r, every path of up to r edges has been tried, so capping the rounds caps the number of flights. Floyd–Warshall fills a full distance table and, for each node k in turn, asks for every pair: "is going through k cheaper?"

In Python

INF = float("inf")

def cheapest_price(n, flights, src, dst, k):
    cost = [INF] * n
    cost[src] = 0
    for _ in range(k + 1):           # at most k + 1 flights
        prev = cost[:]               # read last round only
        for u, v, w in flights:
            if prev[u] + w < cost[v]:
                cost[v] = prev[u] + w
    return -1 if cost[dst] == INF else cost[dst]

def find_the_city(n, edges, threshold):
    d = [[0 if i == j else INF for j in range(n)] for i in range(n)]
    for u, v, w in edges:
        d[u][v] = d[v][u] = min(d[u][v], w)
    for k in range(n):               # allow k as a middle stop
        for i in range(n):
            for j in range(n):
                d[i][j] = min(d[i][j], d[i][k] + d[k][j])
    best, city = INF, -1
    for i in range(n):
        near = sum(d[i][j] <= threshold for j in range(n) if j != i)
        if near <= best:             # ties go to the larger i
            best, city = near, i
    return city

flights = [[0,1,100], [1,2,100], [2,0,100], [1,3,600], [2,3,200]]
print(cheapest_price(4, flights, 0, 3, 1))     # → 700
print(cheapest_price(4, flights, 0, 3, 2))     # → 400
print(find_the_city(4, [[0,1,3], [1,2,1], [1,3,4], [2,3,1]], 4))
# → 3

The source's Cheapest Flights builds an undirected graph, takes prim() and returns the MST's total weight; it never reads src, dst or k. Here that total happens to be 400 (100 + 100 + 200), which is the unlimited-stops answer, not 700. Its Find the City is missing the colon after def, uses maxsize without importing it (only sys is imported), and import scipy.sparse.csgraph.floyd_warshall fails because that is a function, not a module. Corrected here, in plain Python.

Bellman–Ford: time O(R · E) · space O(V), with R = k + 1 rounds here (2 × 5 = 10 relaxations) or |V| − 1 for plain shortest paths, O(V · E). Each round touches every edge once and keeps two cost lists. Floyd–Warshall: time O(V³) · space O(V²): three nested loops over nodes (4³ = 64 checks here, 10⁶ for 100 cities) and one table, updated in place because row and column k don't change during step k.

The code file prints both traces and checks cheapest_price against trying every path on 2,000 random flight maps (Python 3.10).

Why Bellman–Ford beats the alternatives for "at most k stops"

✗ Prim (the source)

A minimum spanning tree connects all cities as cheaply as possible; it isn't a route. It ignores direction, src, dst and k, and returns the tree's total: 400.

✗ Plain Dijkstra

Finds the cheapest route, 0-1-2-3 for 400, but that uses 2 stops. It keeps one cost per city, so it can't also keep a pricier route with fewer stops.

✗ Relax in place

Bellman–Ford without the snapshot. Costs written early in a round get reused in the same round, so paths grow by several flights per round: 400 for k = 1, and 400 for k = 0.

✓ Bellman–Ford, k + 1 rounds

Round r covers exactly the paths of ≤ r flights, so stopping after k + 1 rounds enforces the limit: 700. O(k · E), no heap.

Which one, and when not to use them

With non-negative weights and one source, Dijkstra is faster: O((V + E) log V) against Bellman–Ford's O(V · E). Use Bellman–Ford when edges can be negative (and to detect a negative cycle, with one extra round) or when the number of edges is capped, as here. Dijkstra can also handle the stop limit if its state becomes (city, stops used) instead of just city; that is a standard alternative, not from the source.

Floyd–Warshall is the simple choice for all pairs on a small or dense graph: a few hundred nodes, like Find the City. On a big sparse graph with non-negative weights, running Dijkstra from every node, O(V (V + E) log V), beats O(V³); with negative edges, Johnson's algorithm reweights once with Bellman–Ford and then does the same. This comparison is textbook (CLRS ch. 24–25), not from the source.
