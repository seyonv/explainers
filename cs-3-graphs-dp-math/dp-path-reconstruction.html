Reconstructing the path

Also called path recovery, backpointers, parent or choice pointers, argmin tracking. The source guide's example is Coin Path (C++): pay coins[i] at each index you land on, jump at most B ahead, and return the cheapest route from index 1 to n, the lexicographically smallest one on ties.

Prime · 2 minutes before you read

The problem: A DP table gives you the best cost (7 for Coin Path) but not the route, and problems like Coin Path want the route itself, the lexicographically smallest one on ties. Storing a whole path per cell costs O(n²) memory, and a forward fill with parent pointers returns the wrong path on 392 of 3,000 random cases.

Where it fits: Seventh DP card. It finishes the Coin Path example from the recursion-to-DP card, adding a pointer next to each cost, and shows why the backward fill direction from the grid card makes the tie-break free.

In one breath

A DP table tells you the best cost, not how you got it. So next to each cost, store the choice that produced it, then follow those pointers from the start. Filling the table from the end backwards makes each pointer the first step of the best route, which is exactly what a lexicographic tie-break compares first.

Why backwards makes the tie-break free

Lexicographic order is decided at the front of the path: the first index where two routes differ. Backward DP's pointer at i is the first step from i, so picking the smallest j at a tie picks the smaller first difference; the rest of the route is the smallest route from j, by the same argument one cell later. Forward DP's pointer at j is the last step into j, so its tie-break settles the back of the path first, which lex order looks at last.

coins = [0, 0, 0, 0], B = 2Pointer meansTies resolvedResult
Backward, smallest nextfirst step out of inext[1]=2, next[2]=3, next[3]=4[1, 2, 3, 4] ✓
Forward, smallest parentlast step into jparent[4]=2, parent[2]=1[1, 2, 4] ✗

[1, 2, 3, 4] < [1, 2, 4] because they first differ at position 3, and 3 < 4. On 3,000 random cases the forward version returns the wrong path 392 times; the backward one matches brute force every time. One route can't be a prefix of another here, since every route ends at n.

In Python

INF = float("inf")

def cheapest_jump(coins, max_jump):
    n = len(coins)
    cost = [INF] * n                 # cost[i]: cheapest i -> end
    nxt = [-1] * n                   # nxt[i]: first step of it
    if coins[-1] != -1:
        cost[-1] = coins[-1]
    for i in range(n - 2, -1, -1):
        if coins[i] == -1:
            continue                 # blocked: stays INF
        for j in range(i + 1, min(i + max_jump, n - 1) + 1):
            if coins[i] + cost[j] < cost[i]:   # strict <: a tie
                cost[i] = coins[i] + cost[j]   # keeps the
                nxt[i] = j                     # smaller j
    if cost[0] == INF:
        return []
    path, i = [], 0
    while i != -1:                   # walk the pointers
        path.append(i + 1)           # answer is 1-indexed
        i = nxt[i]
    return path

print(cheapest_jump([1, 2, 4, -1, 2], 2))
print(cheapest_jump([0, 0, 0, 0], 2))
print(cheapest_jump([1, 2, 4, -1, 2], 1))  # B = 1 hits cell 4
# → [1, 3, 5]
#   [1, 2, 3, 4]
#   []

Same algorithm as the source's C++, which is correct: its strict < over rising j is the tie-break. INF = float("inf") replaces INT_MAX, so no overflow guard is needed.

Time O(n·B) · Space O(n). Each of the n cells looks at up to B later cells once; the pointers add one integer per cell, and the walk is at most n steps.

Why it beats the alternatives

✗ Try every route

Sort all routes by (cost, path). Exponential: with B = 2 the count is Fibonacci, 55 routes for n = 10 and 832,040 for n = 30.

✗ Forward DP, smallest parent

Right cost, wrong path: returns [1, 2, 4] instead of [1, 2, 3, 4] on four 0 coins, and misses on 392 of 3,000 random cases.

✗ Forward DP storing whole paths

Keep the best path list per cell and compare lists on ties. Correct, but each compare and copy is O(n), so O(n²·B) time and O(n²) memory.

✓ Backward DP + next pointer

O(n·B) time, one integer per cell. The pointer is the first step, so "smallest j on ties" is the whole lexicographic rule.

Do you always fill it backwards?

No. Without a tie rule, either direction works: forward DP with parent pointers, walked back from the end and reversed, is the usual way to rebuild a shortest path (Dijkstra's prev[]), a longest increasing subsequence or an edit script. The direction only matters when ties are broken by the order of the path: point your pointers away from the end that the comparison reads first. If the rule were "lexicographically smallest when read from n", forward would be the natural fill.

If the tie rule is something else, such as fewest jumps, put it in the compared value instead: compare (cost, jumps) tuples. When even O(n) pointers per row are too much, as in a two-string table with n·m cells, Hirschberg's divide and conquer rebuilds the alignment in linear space. These points are standard practice, not from the source.

Understand and remember

  • Store the argmin next to each min → one integer per state → walk the pointers from the start → the path in O(n) extra memory and O(length) time
  • Backward fill: next[i] is the first step of the best route from i → lexicographic order compares first steps first → picking the smallest j at a tie picks the smaller first difference, and the rest is the smallest route from j by the same argument
  • Forward fill: parent[j] is the last step into j → its tie-break decides the back of the path first → lexicographic order reads the back last → [1, 2, 4] instead of [1, 2, 3, 4] on four zero coins
  • Strict < while j rises keeps the first (smallest) j among equal costs → the tie rule costs nothing extra
  • detail that matters When ties are broken by another number (fewest jumps), put it in the compared value → compare (cost, jumps) tuples instead of changing the fill direction
