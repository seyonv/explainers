Weighted random choice

Also called the alias method (Walker's alias method, or Vose's version of it) or a discrete distribution sampler. Pick index i with probability w[i] / sum(w) in O(1) per pick. The source guide solves Random Pick with Weight this way, under Probability, rather than with the usual prefix sums and binary search.

Prime · 2 minutes before you read

The problem: Picking index i with probability w[i] / sum(w) by prefix sums and binary search costs O(log n) per draw, about 20 comparisons at n = 10⁶; repeating each index w[i] times makes a pick O(1) but costs sum(w) memory. For many draws from fixed weights there is an O(1)-per-pick table of only n columns.

Where it fits: Sixth maths card. It is a precomputation trade like the factorial tables on the modular card: pay O(n) once, then answer each query in O(1). It connects to the random-pick structures in course 1.

In one breath

Scale the weights so their average is exactly one "column" tall. Then cut the tall ones down to fill the short ones, so that every column is full and holds at most two indexes. To pick, choose a column uniformly at random, then flip one biased coin to decide which of its two indexes you get.

Worked example: w = [1, 3, 2, 4] → P = 0.1, 0.3, 0.2, 0.4

Index 3 (green) started at 16, six over the line. It gave 2 to column 0 and 6 to column 1, and its remaining 8 became column 2's bottom. Every column is exactly 10 tall.

Why the probabilities come out right

P(i)= 1npick a column × ∑c hc(i)Tcoin lands on i = n·w[i]n·T = w[i]T
nnumber of indexes, and so of columns4 Tsum(w): every column's height after scaling by n10 hc(i)height of i's piece in column c (0 if absent); i's pieces add up to n · w[i]3: 2 + 6 + 8 = 16
P(i) = sum(height of i in column c for all c) / (n * T) P(3) = (2 + 6 + 8) / (4 * 10) = 16 / 40 = 0.4 = w[3] / sum(w)

Building never creates or destroys height, it only moves it between columns, so each index keeps its total of n · w[i]. Checked for all four: 4/40, 12/40, 8/40, 16/40.

Hand trace: building the table

Two stacks: small (height < 10) and large (height ≥ 10). Each step pops one of each, and the small index keeps its height as its column's bottom. The large index fills the rest of that column and goes back on whichever stack its new height belongs to.

The three words, two examples each

Think of pouring four glasses of juice evenly by topping up the short glasses from the full ones, never using more than two jugs per glass.

WordWhat it isExample A: w = [1, 3, 2, 4]Example B: w = [1, 3] (the source's)
ColumnOne of n equal slots, each T tall, holding one or two indexes. Picked uniformly. 4 columns, T = 10chance of each column: ¼ 2 columns, T = 4n·w = 2, 6: [0 : 2 | 1 : 2] and [1 : 4]
KeepThe bottom index's height. Draw r in 0 … T − 1; r < keep gives the bottom index. col 1: keep 4r in 0–3 gives index 0, a 4/10 chance col 0: keep 2r in 0–1 gives index 0: ½ × 2/4 = 0.25
AliasThe index that fills the rest of the column: the "otherwise" answer. col 1: alias 3r in 4–9, a 6/10 chance col 0: alias 1½ × 2/4 + ½ × 4/4 = 0.75

In Python

import random

class AliasTable:
    def __init__(self, w):
        n, total = len(w), sum(w)
        self.total = total
        h = [x * n for x in w]          # scaled: columns hold total
        small = [i for i, x in enumerate(h) if x < total]
        large = [i for i, x in enumerate(h) if x >= total]
        self.cols = []                  # (keep, low index, alias)
        while small and large:
            s, g = small.pop(), large.pop()
            self.cols.append((h[s], s, g))
            h[g] -= total - h[s]        # g fills the rest of s's column
            (small if h[g] < total else large).append(g)
        for g in large:                 # leftovers are exactly full
            self.cols.append((total, g, g))

    def pick(self):
        keep, low, alias = random.choice(self.cols)
        r = random.randrange(self.total)    # exact integer coin
        return low if r < keep else alias

t = AliasTable([1, 3, 2, 4])
print(t.cols)
random.seed(0)
counts = [0] * 4
for _ in range(100_000):
    counts[t.pick()] += 1
print(counts)
# → [(8, 2, 3), (4, 0, 3), (8, 3, 1), (10, 1, 1)]
# → [9941, 29736, 20104, 40219]
#   expected 10,000 / 30,000 / 20,000 / 40,000; all within 1.9 sd,
#   chi-square 4.41 on 3 df (5% cutoff 7.81)

The source's version is correct and builds the same four columns. This rewrite swaps its two dicts and popitem() for two lists (same pop order), and its random.uniform(0, sum_w) > alias for an integer randrange, so each coin is exactly keep / T.

Time O(n) build · O(1) pick · Space O(n). Each loop step finishes one column for good, so there are at most n steps. A pick is one random column plus one comparison, whatever n is.

Why it beats the alternatives

✗ Linear scan

Draw r, walk the weights subtracting until r goes negative. No setup, but O(n) per pick: 2.9 steps on average here, and about n/2 for equal weights.

✗ Repeat each index w[i] times

[0, 1, 1, 1, 2, 2, 3, 3, 3, 3] and random.choice: O(1) per pick, but memory is sum(w), not n. Weights 99,999 and 1 need 100,000 slots for two indexes.

✗ Prefix sums + bisect

cum = [1, 4, 6, 10], r = randrange(10), bisect_right(cum, r). The usual answer, and what random.choices does, but O(log n) per pick: about 20 comparisons at n = 10⁶.

✓ Alias table

O(n) memory and build, then O(1) per pick: one uniform column and one integer compare, the same 2 random draws at n = 4 or n = 10⁶.

Is it always the right tool?

No. It pays off when the weights are fixed and you draw many times. If a weight changes, the whole table has to be rebuilt in O(n). Prefix sums in a Fenwick tree handle an update and a pick in O(log n) each. For a handful of draws, random.choices(range(n), weights=w, k=…) is one line of standard library, and O(1) versus O(log n) is not automatically faster in CPython (not measured here).

With float probabilities, rounding can leave an index in the wrong stack at the end. Vose's version sets any leftover's keep to 1, and Schwarz's write-up notes this only happens because of numerical error. The source's trick of scaling integer weights by n avoids the issue entirely.

Understand and remember

  • Scale heights to n·w[i] → they average exactly T = sum(w) → a short column (< T) pairs with a tall one → the tall one tops it up → every column ends exactly T tall with at most two indexes
  • Building only moves height between columns → index i keeps total height n·w[i] → P(i) = (1/n)·Σ hc(i)/T = w[i]/T
  • Remaining heights always average T → if any is short, another is tall → the loop never gets stuck; integer scaling means no rounding leftovers
  • O(n) build once → each pick is one uniform column + one comparison → O(1), independent of n; but any weight change forces an O(n) rebuild → Fenwick prefix sums for changing weights (O(log n) update and pick)
  • detail that matters An integer coin randrange(T) < keep makes each column's split exactly keep/T → a float uniform coin is only approximately right

5 · Predict commit to an answer before revealing

Build the table for w = [1, 1, 1, 5] in your head. Predict how many of the 4 columns contain index 3, and check P(3) = 5/8 from them.

Reveal

All 4. Heights are 4, 4, 4, 20 with T = 8: index 3 tops up each of the three short columns by 4 and keeps a full column of 8 for itself. P(3) = (1/4)·(4/8 + 4/8 + 4/8 + 8/8) = (1/4)·2.5 = 0.625 = 5/8.
