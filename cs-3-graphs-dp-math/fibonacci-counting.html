Fibonacci counting

Also called the Fibonacci recurrence, or the 1-and-2 tiling count. The source guide's Mathematics page solves Climbing Stairs with Binet's closed form, and Non-negative Integers without Consecutive Ones with a table of Fibonacci numbers walked bit by bit.

In one breath

Whenever the first choice is "a short piece or a long piece" (one step or two; a 0, or a 1 that forces a 0 next), the number of ways to fill length k is the ways to fill k − 1 plus the ways to fill k − 2. That is the Fibonacci recurrence, so both problems are Fibonacci numbers in disguise.

One recurrence, two problems

Think of tiling a strip with 1-wide and 2-wide tiles: whichever tile goes first, the rest is a smaller strip.

Where float64 breaks

φ is stored with a relative error of 3.36 × 10⁻¹⁷. Raising it to the n-th power multiplies that error by n, so the absolute error is about n × 3.36 × 10⁻¹⁷ × F(n). Rounding fails once that passes 0.5.

First wrong at F(71), i.e. climbStairs(70). It's not a storage problem: F(71) is below 2⁵³, so a double could hold it exactly; the error comes from φ. The source's C++ returns int, which overflows even earlier, at climbStairs(46) = 2,971,215,073 > 2³¹ − 1.

Counting integers in [0, n] with no "11", bit by bit

Walk n's bits from the top. At each 1 bit k, count everything that matches n above k and has a 0 at k: the k free bits below can be any of f(k) strings. If that 1 follows another 1, n's prefix already contains "11", so no larger number can count: stop. If the walk finishes, n itself is valid: add 1.

In Python

def find_integers(n):
    f = [1, 2]                      # f[k]: k-bit strings, no "11"
    while len(f) < n.bit_length():
        f.append(f[-1] + f[-2])
    count, prev = 0, 0
    for k in range(n.bit_length() - 1, -1, -1):
        if n >> k & 1:
            count += f[k]           # put 0 here, k free bits below
            if prev:                # n has "11": nothing more fits
                return count
            prev = 1
        else:
            prev = 0
    return count + 1                # n itself has no "11"

def climb_stairs(n):                # exact: Python ints never round
    a, b = 1, 1                     # ways(0), ways(1)
    for _ in range(n - 1):
        a, b = b, a + b
    return b

print(find_integers(5), find_integers(13), climb_stairs(10))
# → 5 8 89
print(f"{find_integers(10**9):,}")
# → 2,178,309

The source's C++ decrements its global log_max on every call (i = --log_max), so each call scans one bit fewer: by the third call, n = 2²⁹ returns 1 instead of 1,346,270 (simulated in the code file). Corrected here by sizing the table from n.bit_length().

Time O(log n) · Space O(log n). One table entry and at most one step per bit of n: 30 of each for n = 10⁹. climb_stairs is O(n) additions, exact at any size.

Why it beats the alternatives

✗ Test every number

Count x in [0, n] with x & (x >> 1) == 0. Correct and simple, but O(n): 10⁹ checks for n = 10⁹ to find 2,178,309 survivors.

✗ Plain recursion for f(k)

f(k) = f(k−1) + f(k−2) without a table recomputes the same values: naive fib(30) makes 2,692,537 calls where 31 would do.

✗ Binet in floats

O(1) and elegant, as the source uses it, but round(φⁿ/√5) is first wrong at F(71), and the C++ int overflows at n = 46 before that.

✓ Integer table + bit walk

Exact integer adds, O(log n): 30 table entries and at most 30 steps for n = 10⁹. The table is the same Fibonacci numbers, built once.

Is Binet ever the right call?

For growth rates, yes: F(n) ≈ φⁿ/√5 says the count of k-bit strings with no "11" grows like 1.618ᵏ, so each such bit carries log₂ φ ≈ 0.694 bits of information. For exact values, no. Python's integers make the loop exact at any n; for F(n) mod p with n near 10¹⁸, use matrix powers or fast doubling in O(log n) steps.

The Fibonacci numbers are specific to forbidding "11". Forbid "111" and the recurrence gains a third term (tribonacci); forbid a pattern like "101" and you need digit DP with a small automaton as the state. These generalisations are standard practice, not from the source.
