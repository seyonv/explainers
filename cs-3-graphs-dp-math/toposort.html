Topological sort and cycle detection

Also called topological order, dependency order or a linear extension; the queue method is Kahn's algorithm. The source guide uses it for Alien Dictionary (via Python's graphlib, under Cycle Detection) and for Course Schedule I and II (via its Graph.toposort(), under Depth-first Search).

Prime · 2 minutes before you read

The problem: Build steps, course prerequisites and an alien alphabet all say "this must come before that". You need one listing that respects every such rule, and when the rules contradict each other you need to notice instead of printing a wrong order.

Where it fits: Sixth graph card. It is BFS's queue applied to in-degrees, and it names the idea the DP cards rely on later: a DP's fill order is a topological order of its subproblems.

In one breath

A topological order lists the nodes of a directed graph so every edge points forward: each thing comes after everything it depends on. Kahn's algorithm builds it by repeatedly taking a node with nothing left pointing into it. If the nodes run out of candidates before all are placed, the leftovers sit on a cycle, and no order exists.

Worked example: words = ["wrt", "wrf", "er", "ett", "rftt"] → "wertf"

Step 1: read edges off neighbouring words. The dictionary is sorted, so the first letter where two neighbours differ tells you which letter comes first. Everything after that letter says nothing.

In-degree = how many edges point into a letter, that is, how many letters must come before it. Only w starts at 0, so it goes first.

In Python

from collections import deque
from itertools import pairwise              # Python 3.10+

def alien_order(words):
    succ = {c: [] for w in words for c in w}   # letter -> later letters
    indeg = dict.fromkeys(succ, 0)
    for a, b in pairwise(words):
        for x, y in zip(a, b):
            if x != y:                   # first difference = one edge
                succ[x].append(y)
                indeg[y] += 1
                break
        else:
            if len(a) > len(b):          # "abc" before "ab": invalid
                return ""
    queue = deque(c for c in indeg if indeg[c] == 0)
    order = []
    while queue:
        c = queue.popleft()
        order.append(c)
        for d in succ[c]:
            indeg[d] -= 1                # one prerequisite done
            if indeg[d] == 0:
                queue.append(d)
    return "".join(order) if len(order) == len(indeg) else ""

print(alien_order(["wrt", "wrf", "er", "ett", "rftt"]))  # → wertf
print(repr(alien_order(["abc", "ab"])))                # → ''
print(repr(alien_order(["z", "x", "z"])))              # → ''

The source hands the same graph to graphlib.TopologicalSorter, keyed the other way round (each letter maps to the letters before it) and catching CycleError. It's correct; code/ checks both against brute force on 2,000 random word lists.

Time O(C + V + E) · Space O(V + E). C is the total number of letters, read once while building edges (15 here). Each letter is queued once and each edge decremented once, with V ≤ 26 letters and E ≤ n − 1 edges, one per neighbouring pair (5 and 4 here).

Why it beats the alternatives

✗ Order by first appearance

Gives "wrtfe". It looks plausible but puts r before e, so ett / rftt is out of order. Where a letter first shows up says nothing about its rank.

✗ Compare every pair of words

Correct, but 10 pairs for 5 words instead of 4, and O(n²) in general. The extra edges are already implied by chaining the neighbouring ones.

✗ DFS with a plain visited set

Can't tell a cycle from a diamond. In 0 → 1 → 3, 0 → 2 → 3, node 3 is seen twice with no cycle. You need a third colour for "on the current path".

✓ Kahn's algorithm

One queue, no recursion, O(V + E). The order and the cycle check come from the same pass: placed < letters means a cycle.

Is Kahn always the tool?

It's one of two standard methods. A three-colour DFS (white, grey for on the current path, black for done) is just as fast: reaching a grey node means a cycle, and the reverse of the finishing order is a topological order. It also gives "wertf" here. Pick DFS when you need the cycle itself, since the grey path is the cycle; graphlib does this for its error message and reports ['z', 'x', 'z']. Pick Kahn when you want the ready set at each moment, for example to run independent jobs in parallel.

Not the right tool for undirected graphs: every edge would be a 2-cycle, so detect cycles there with union–find or a DFS that ignores its parent. If a graph has cycles and you still need an order, first collapse each strongly connected component into one node (Tarjan or Kosaraju). And if the problem wants the alphabetically smallest valid order, swap the deque for a heap, at O(V log V + E). These points are standard practice, not from the source.

Understand and remember

  • In-degree counts prerequisites not yet placed → a node at 0 can go now → placing it removes one prerequisite from each successor → repeat → every edge ends up pointing forward
  • A cycle's nodes each wait for another node in the cycle → none ever reaches in-degree 0 → the queue empties early → placed < total is the cycle test, at no extra cost
  • A sorted dictionary's neighbouring words differ first at one position → that pair gives exactly one edge → later letters say nothing → n − 1 comparisons suffice (4 edges for 5 words), not all pairs
  • DFS needs three states (unvisited, on the current path, done) → reaching an on-path node is a cycle; a finished node reached twice is just a diamond → reverse finishing order is a topological order
  • detail that matters Swap the deque for a heap → the smallest ready node goes first → lexicographically smallest valid order, at O(V log V + E)

Reference only

  • graphlib.TopologicalSorter and CycleError
  • itertools.pairwise (3.10+)
  • Tarjan/Kosaraju for strongly connected components

Check
  • each cell depends on smaller cells; those are the edges
  • filling small to large places every cell after its dependencies
  • a cycle means no valid fill order, so the problem must be solved as a search (or iterated to a fixed point)

Reveal

The new pair rftt / te differs first at position 0, giving r → t, which is already an edge. succ[r] now lists t twice and t's in-degree is 2, but popping r decrements it twice, so t still reaches 0 at the right moment. The answer stays "wertf".
