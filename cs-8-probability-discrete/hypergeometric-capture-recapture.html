Hypergeometric and capture–recapture

Also called sampling without replacement, the mark–recapture model, or the Lincoln–Petersen method. The source guide tags 20 animals, later catches 30, finds 7 tagged, and asks for the most likely population size. It states the problem but doesn't solve it: the answer is N = 85.

Prime · 2 minutes before you read

The problem: Drawing without replacement changes the odds after every draw, so the binomial is wrong. And estimating an unknown population from a recapture means running the pmf backwards, as a likelihood in N.

Where it fits: After the binomial: the same 'how many marked ones?' question, but the pool shrinks with each draw. The counting cards' C(K, k)C(N − K, n − k) is exactly this pmf, and the Bayes table's habit of holding the data fixed while the unknown varies is what capture–recapture does.

In one breath

A pond holds N animals and K of them carry a tag. Scoop out n without putting any back, and count the tagged ones, k. The chance of each k is the hypergeometric distribution. Capture–recapture runs it backwards: you know K, n and k, and you pick the N that makes the k you saw most likely.

The (N − n)/(N − 1) factor is the finite-population correction: not replacing animals makes the count less spread out than a binomial with p = K/N (55/84 = 0.655 of it here).

Worked example: which N makes "7 of 30" most likely?

Fix K = 20, n = 30, k = 7 and treat P(k) as a function of N: the likelihood L(N). N can't be below 20 + 23 = 43, or there wouldn't be 23 untagged animals to catch.

Exact values from the Python below (Fractions). The peak is very flat: every N from 65 to 122 (grey band) is at least half as likely as N = 85.

You don't need to scan. Compare neighbours: the likelihood goes up from N − 1 to N while the ratio is at least 1.

L(N) / L(N−1) = (N − K)(N − n) / (N · (N − K − n + k)) = (N − 20)(N − 30) / (N · (N − 43)) ratio ≥ 1 ⇔ N² − 50N + 600 ≥ N² − 43N ⇔ 7N ≤ 600 ⇔ N ≤ 85.71 so L rises up to N = 85 and falls after: N̂ = ⌊K·n / k⌋ = ⌊600/7⌋ = 85

Where the ratio formula comes from: C(N−20, 23)/C(N−21, 23) = (N−20)/(N−43) and C(N−1, 30)/C(N, 30) = (N−30)/N. A 10⁵-catch simulation at N = 85 gives P(7 tagged) = 0.2085 (seed 0) vs 0.2104 exact, 1.5 standard errors (±0.0013) away.

In Python

from fractions import Fraction as F
from math import comb

K, n, k = 20, 30, 7            # tagged, recaptured, tagged in catch

def hyper_pmf(N, K, n, k):
    """P(k tagged in a catch of n | N animals, K tagged)."""
    return F(comb(K, k) * comb(N - K, n - k), comb(N, n))

def ratio(N):
    """L(N) / L(N-1) = (N-K)(N-n) / (N (N-K-n+k))."""
    return F((N - K) * (N - n), N * (N - K - n + k))

def mle(K, n, k):
    """Largest N with ratio(N) >= 1, i.e. floor(K n / k)."""
    return K * n // k

lo = K + n - k                  # 43: fewer is impossible
best = max(range(lo, 1000), key=lambda N: hyper_pmf(N, K, n, k))
print(best, mle(K, n, k), F(K * n, k))
# → 85 85 600/7
print(float(hyper_pmf(85, K, n, k)), float(ratio(86)))
# → 0.21043077876516958 0.9994591671173607

Time O(1) · Space O(1) for the closed form ⌊Kn/k⌋: one multiply and one integer divide. The brute-force scan checks it with one exact pmf per candidate N, which is why it needs an upper bound (1,000 here).

Why it beats the alternatives

✗ Round Lincoln–Petersen

Match proportions: 7/30 = 20/N gives 85.71, and rounding says 86. But L(86) = 0.21032 < L(85) = 0.21043. The most likely N is the floor, not the nearest integer.

✗ Scan every N

Correct, but you have to pick where to stop, and C(N, 30) has 23 digits already at N = 85. Fine in Python with exact integers; slow and overflow-prone by hand or in floats.

✗ Binomial model

Pretend each recaptured animal is tagged with chance 20/N, independently. That's sampling with replacement; maximised over real N it lands on a non-integer 85.71, and its variance (5.40) overstates the real 3.53.

✓ The neighbour-ratio test

L(N)/L(N−1) ≥ 1 reduces to one linear inequality, 7N ≤ 600. The exact integer answer, ⌊Kn/k⌋ = 85, with no big numbers and a proof that it's the global peak.

Is 85 "the" population size?

It's the single most likely value, but only barely: L(85) is 0.14% above L(84) and 0.05% above L(86), and the half-peak band runs from 65 to 122. With k = 7 recaptures the data can't pin N down. Report a range, or catch more.

The ratio estimate K·n/k is biased upward in small samples and blows up if k = 0. Ecologists often use Chapman's version, (K+1)(n+1)/(k+1) − 1 = 643/8 ≈ 80.4, which is defined for k = 0. And every assumption the source lists (closed population, no lost tags, equal catchability) matters: trap-shy tagged animals make k too small and N̂ too big. For open populations, use Jolly–Seber models instead.

Understand and remember

  • Draw n without replacement from N, with K marked → every catch equally likely → P(k) = C(K, k)C(N − K, n − k)/C(N, n); each draw changes the pool → the variance is the binomial's × (N − n)/(N − 1) (3.53 against 5.40)
  • k is observed and N unknown → L(N) = P(k | N) → compare neighbours: L(N)/L(N − 1) = (N − K)(N − n)/(N(N − K − n + k)) ≥ 1 ⇔ kN ≤ Kn → L rises up to ⌊Kn/k⌋ = 85, then falls
  • Only 7 recaptures → L is flat (the half-peak band runs from 65 to 122) → the MLE is barely likelier than its neighbours → report a range, or catch more
  • detail that matters Kn/k blows up at k = 0 and is biased upward in small samples → Chapman's (K + 1)(n + 1)/(k + 1) − 1 = 80.4 is defined even for k = 0

Reference only

  • C(85, 30) ≈ 8.36 × 10²²
  • Jolly–Seber models for open populations
  • the likelihood values at N = 60, 84, 85, 86, 100, 150

5 · Predict commit to an answer before revealing

Your recapture finds k = 0 tagged animals (K = 20, n = 30). What does ⌊Kn/k⌋ say, what does Chapman's estimator give, and what does the likelihood do as N grows? Commit first.

Reveal

⌊Kn/k⌋ divides by zero. The likelihood P(0 tagged | N) = C(N − 20, 30)/C(N, 30) keeps rising toward 1 as N grows (0.0003 at N = 100, 0.54 at 1,000, 0.94 at 10,000), so there is no finite MLE. Chapman gives 21 × 31/1 − 1 = 650: a finite number, but really a sign that you need to catch more.

6 · Apply use the model, don't restate it

A second survey tags K = 50, recaptures n = 40 and finds k = 10. Compute N̂ with the neighbour-ratio rule, check it with mle and with a scan over N using hyper_pmf, and compute Chapman's estimate.
