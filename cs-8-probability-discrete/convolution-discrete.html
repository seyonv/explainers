Adding random variables: convolution

Also called the convolution sum, or the distribution of a sum. The cheat-sheet's weekly-claims problem: each week brings N claims with P(N = n) = 1/2n+1, weeks are independent, and the question is the chance of exactly 7 claims in two weeks. Its answer, 1/64, is correct.

In one breath

To get the chance that two independent counts add up to 7, list every way to split 7 between them (0 + 7, 1 + 6, …, 7 + 0), multiply the two probabilities for each split, and add the products. That sum over splits is the convolution. For many terms, the quicker route is to multiply generating functions, because multiplying power series does the same split-and-sum for every total at once.

The rule

P(X+Y=s)the total = ∑k=0severy split P(X=k)first part P(Y=s−k)the rest
X, Yindependent counts, each 0, 1, 2, …week 1, week 2 sthe total you ask about7 claims khow much of the total the first variable takes0 … 7: eight splits productP(both parts) = P(first) × P(rest), which needs independence1/512 each here
P(S = s) = sum(p_X(k) * p_Y(s - k) for k in range(s + 1))

Filled in: every split gives 1/2k+1 × 1/2(7−k)+1 = 1/29 = 1/512, and there are 8 splits, so 8/512 = 1/64.

The generating-function view

Encode a pmf as a power series whose coefficient of zn is P(N = n). Multiplying two series collects, for each power zs, exactly the products whose exponents add to s: the convolution sum, done for every s at once.

GN(z)= ∑n=0∞ zn2n+1 =12−z GS(z)= GN(z)2= 1(2−z)2 = ∑s=0∞ s+12s+2P(S = s) zs
1/(2 - z)^2 = (1/4) * 1/(1 - z/2)^2 = (1/4) * sum((s + 1) * (z/2)^s) coefficient of z^7 = (1/4) * 8 / 2^7 = 8/512 = 1/64

The step uses 1/(1 − x)2 = Σ (s + 1) xs. Setting z = et gives the MGF, MS(t) = 1/(2 − et)2: the same "multiply to add" rule.

The sum S is a named distribution: 2 failures-before-success geometrics with p = 1/2 add to a negative binomial, NB(r = 2, p = 1/2). Its strip, from the formula above and from E[N] = 1, Var[N] = 2:

The three words, two examples each

Think of making change for 7 with two coins of unknown value: convolution counts every pair that works, weighted by how likely each coin is.

In Python

from fractions import Fraction as F
import numpy as np

def pmf_N(n):
    return F(1, 2 ** (n + 1))           # claims in one week, n >= 0

def convolve(p, q, s):
    """P(X + Y = s) for independent X, Y >= 0 with pmfs p, q."""
    return sum(p(k) * q(s - k) for k in range(s + 1))

def pmf_S(s):
    """Coefficient of z**s in G(z)**2 = 1/(2 - z)**2."""
    return F(s + 1, 2 ** (s + 2))

print(convolve(pmf_N, pmf_N, 7), pmf_S(7))
p = np.array([0.5 ** (n + 1) for n in range(60)])
print(np.convolve(p, p)[7])            # all totals at once
# → 1/64 1/64
# → 0.015625

Time O(s) for one total · O(nm) for the full pmf. One total needs s + 1 products; np.convolve of supports of size n and m does every total in nm multiplies (60 terms here cover all but 2−60 of the mass).

Why it beats the alternatives

✗ Double one week

"Two weeks = 2N." That treats both weeks as identical, not independent: 2N is always even, so P(2N = 7) = 0, not 1/64.

✗ Add the pmfs

P(N₁ = 7) + P(N₂ = 7) = 1/128 answers "did either week alone hit 7?", and it misses the 6 splits where both weeks share the 7 claims.

✗ Normal approximation

Mean 2, sd 2, continuity-corrected: P(6.5 < S < 7.5) = 0.00924, 41% below 1/64. A sum of two skewed counts is nowhere near normal.

✓ Convolution

Exact: 8 products, 1/64. The generating function gives every P(S = s) in one closed form, (s + 1)/2s+2, and names the result NB(2, 1/2).

Does this always work?

Only for independent summands. If a bad week makes the next one worse, P(N₁ = k, N₂ = 7 − k) is no longer a product; you need the joint table and sum its diagonal instead.

For sums of many variables, don't convolve by hand: raise the generating function or MGF to a power, or check whether the family is closed under addition (Poissons add to a Poisson, geometrics to a negative binomial). For long pmfs on a computer, an FFT does the whole convolution in O(n log n) instead of O(n²). For continuous variables the sum becomes an integral of densities, and for many i.i.d. terms the normal approximation from the CLT takes over, which is what fails here with only two skewed terms.
