Choosing without conflicts, and bridge hands

Also called non-attacking rooks (for the grid) and "at least one" counting by inclusion–exclusion (for the cards). The source guide states three exam-P problems of this kind, a 6-by-5 grid and two 13-card bridge hands, and solves none of them; all three are solved here.

In one breath

When choices block each other, count the structure, not the picks. For the grid: first choose which rows get used, then hand those rows different columns one at a time. For "at least one suit" or "at least one rank": add the chance of each single event, subtract the overlaps you counted twice, add back the triples, and stop when a term can't happen.

In Python

from fractions import Fraction as F
from math import comb, perm

def rook_ways(rows, cols, k):
    """Pick k cells, no two sharing a row or a column."""
    # choose the k rows, then give them distinct columns in order
    return comb(rows, k) * perm(cols, k)

def at_least_one(groups, size, hand=13, deck=52):
    """P(hand holds every card of at least one block)."""
    total = F(0)
    for j in range(1, groups + 1):         # j blocks forced in
        if j * size > hand:
            break
        rest = comb(deck - j * size, hand - j * size)
        term = F(comb(groups, j) * rest, comb(deck, hand))
        total += (-1) ** (j + 1) * term    # +, -, +, -
    return total

print(rook_ways(6, 5, 3))
for g, s in [(4, 2), (13, 4)]:   # ace+king x 4 suits; quads x 13
    p = at_least_one(g, s)
    print(p, f"{float(p):.6f}")
# → 1200
# → 9895443/45023650 0.219783
# → 1357355571/39688347475 0.034200

Time O(m) big-integer terms · Space O(1). One binomial per inclusion–exclusion term instead of looking at 635 billion hands; the grid formula is two small products. The saved file also brute-forces the grid and simulates 10⁵ deals.

Why it beats the alternatives

✗ Count the picks in order

30 × 20 × 12 = 7,200 is right for ordered picks, but each set of 3 cells shows up 3! = 6 times. Forget to divide and you are off by 6×.

✗ Add the single events

4 × 1/17 = 0.2353 counts a hand with A+K in two suits twice. It overshoots by 0.0155; it's only an upper bound on the answer.

✗ Treat suits as independent

1 − (16/17)⁴ = 0.2153 undershoots. In a 13-card hand, holding one suit's A+K uses up slots, so the events are not independent.

✓ Structure, then correct

Choose rows, then columns: no double counting by design. For "at least one", inclusion–exclusion with Fractions gives the exact answer in 3 or 4 terms, and each partial sum brackets it.

Is inclusion–exclusion always the way?

No. It shines when every intersection has the same simple size, as here, where any j blocks leave C(52 − js, 13 − js) hands. When the blocks overlap unevenly, count the complement directly or use a DP. For placing rooks on a board with forbidden squares (not a full grid), the standard tool is the rook polynomial or a bitmask DP over columns; that's general practice, not from the source.

Stopping early is often enough: after the singles the sum is an upper bound, after the pairs a lower bound (the Bonferroni inequalities), so (b) is pinned to 0.034200–0.034334 after two terms. Use Fractions, not floats, when the terms are close in size, because the alternating signs cancel and floats lose the digits.
