First-step analysis

Also called one-step analysis, or conditioning on the first move. The source guide has two problems it solves: craps (stated with no answer) and a "Markov" thief escaping a dungeon (answered: 18 hours).

Prime · 2 minutes before you read

The problem: Games that can loop, like craps' neutral rolls or the thief's doors that lead back to the start, have infinitely many paths. Summing them is a series you have to spot, and simulation is never exact.

Where it fits: The fourth conditioning card: condition on the first move. It is the Bayes table's total row again with one twist: the value of a case can be the unknown itself. Markov chains, next, generalise it to many states.

Builds on: Bayes' theorem as a table

You'll meet: v(s) = r(s) + Σ P(s → s′) v(s′) boundaries: win 1, lose 0, free 0 h point before 7: P(pt)/(P(pt) + P(7)) memorylessness makes the loops solvable

By the end: Set up and solve one equation per state for a win probability or an expected time, exactly.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  2. Where does the ratio P(pt)/(P(pt) + P(7)) come from, and why don't the other 27/36 rolls matter?

  4. What unstated assumption about E lets you solve E = 6 + 2E/3?

In one breath

When a game can loop back to where it started, don't try to follow every path. Name the unknown (the chance of winning, or the expected time) for each state, then ask what happens after one move. The unknown shows up on both sides of that equation, and solving it counts every path at once.

The method

v(s) = r(s)cost of this step + ∑s′P(s→s′)v(s′)average over the first move
v(s)the unknown you want, starting from state sP(win) or E[time] r(s)what one step costs; 0 when v is a probabilityhours per tunnel P(s→s′)chance the first move lands in s′dice sums, 1/3 per door v(end)known values where the game stopswin 1, lose 0, free 0 h
v[s] = r[s] + sum(P[s][t] * v[t] for every next state t) if t == s appears on the right, move it left and divide

It works because the process has no memory: after a move back to s, the future looks exactly as it did the first time, so it's worth the same v(s).

Worked example 1: craps → 244/495

The first roll decides the game or sets a point. Once a point is set, only two sums matter, the point and a 7; every other roll returns you to the same state. So the first-step equation gives P(point before 7) = P(point) / (P(point) + P(7)).

The house edge is 1 − 2 × 0.4929 = 1.41% of an even-money bet. A simulation of 10⁶ games (seed 0) gives 0.4936, within 1.4 standard errors (SE 0.0005). The same method gives the expected length of a game: 1 + Σ P(pt) / (P(pt) + P(7)) = 557/165 ≈ 3.38 rolls.

Worked example 2: the Markov thief → 18 h

E = 1/3 · 6 + 1/3 · (3 + E) + 1/3 · (9 + E) = (6 + 3 + 9)/3 + 2E/3 = 6 + 2E/3 E/3 = 6 → E = 18 hours (source: 18 ✓)

Check another way: he takes 1 / (1/3) = 3 doors on average (geometric), so 2 bad ones, averaging (3 + 9)/2 = 6 h each, then 6 h out: 2 × 6 + 6 = 18. A simulation of 10⁵ escapes (seed 0) averages 17.92 h (SE ≈ 0.05).

In Python

from fractions import Fraction as F
from itertools import product

P = {s: F(0) for s in range(2, 13)}   # P(sum of two dice)
for a, b in product(range(1, 7), repeat=2):
    P[a + b] += F(1, 36)

def point_win(pt):
    # w = P[pt]*1 + P[7]*0 + (1 - P[pt] - P[7]) * w
    return P[pt] / (P[pt] + P[7])

def craps():
    win = P[7] + P[11]                 # decided on the first roll
    for pt in (4, 5, 6, 8, 9, 10):
        win += P[pt] * point_win(pt)   # first roll sets the point
    return win

def thief():
    # E = 1/3*6 + 1/3*(3 + E) + 1/3*(9 + E)   ->   E = a + b*E
    a, b = F(6 + 3 + 9, 3), F(2, 3)
    return a / (1 - b)

print(craps(), float(craps()), thief())
# → 244/495 0.49292929292929294 18

Time O(k) · Space O(k) for k states when each equation mentions only itself and the ends, as here. When states feed each other you solve k linear equations together, O(k³) by elimination.

Why it beats the alternatives

✗ Add up every path

Point 4 wins after k neutral rolls with chance (27/36)k · 3/36; the series sums to 1/3, but only if you spot it. Ten terms reach just 0.3146. With several looping states the paths tangle.

✗ Treat the point as a coin flip

"Point or 7 next, 50/50" gives 8/36 + 24/36 × 1/2 = 5/9 = 0.556, a player's edge. A 7 is more likely than any point, so the true answer is below a half.

✗ Just simulate

10⁶ games give 0.4936 ± 0.0005: good enough to check, never exact, and each extra digit costs 100× the games.

✓ First-step analysis

One equation per state, solved exactly: 244/495 and 18 h from a few lines of Fractions. The loop is handled by the unknown appearing on both sides.

Does it always work?

Only when the state really has no memory. If the thief could remember (never reuse a bad door), "in the dungeon" is no longer a full state: you would track which doors he has tried. Averaging over the 6 door orders gives 12 h instead of 18 (computed; the source's "doors lock behind him" wording hints at this variant, but its answer is the memoryless one).

Two more catches. Solving E = 6 + 2E/3 quietly assumes E is finite; here it is, because the number of tries is geometric, but a fair random walk to a far target can have an infinite expected time. And with many states that feed each other, write the equations as a matrix and solve them together (the fundamental matrix (I − Q)⁻¹), as on the Markov chains card.

Understand and remember

  • The future depends only on the current state → after one move, what remains is worth v(next state) → v(s) = cost of the step + Σ P(move) v(next) → a loop puts v(s) on both sides → solve the linear equation
  • In craps, once a point is set, a neutral roll returns you to the same state → w = P(pt) + (1 − P(pt) − P(7)) w → w = P(pt)/(P(pt) + P(7)) → P(win) = 244/495
  • The thief's state has no memory → E = 6 + 2E/3 → E = 18 h; if he remembered doors, the state would have to include which doors he'd tried → 12 h
  • detail that matters Solving v = r + Pv assumes v is finite → true for the thief (his number of tries is geometric) → false for a fair walk to a far target, where the expected time is infinite

Reference only

  • the dice-sum probabilities 1/36 … 6/36
  • the house edge, 1.41%
  • the expected length of a craps game, 557/165

5 · Predict commit to an answer before revealing

A fair $1 game: you start with $3 and stop at $0 or $10. Using only first-step thinking, guess P(reach $10) and the expected number of bets. Commit before revealing.

Reveal

3/10 and 21. First step gives hi = ½hi+1 + ½hi−1, so h is a straight line from h0 = 0 to h10 = 1, and h3 = 0.3. For the time, Ei = 1 + ½Ei+1 + ½Ei−1 gives Ei = i(10 − i) = 21. The next card gets both in one line with martingales.

Change the thief's doors: the 6 h exit now has probability ½, and the 3 h and 9 h tunnels ¼ each. Write the first-step equation, solve for E, then check it with the 'number of doors × average hours' route.

Hint
