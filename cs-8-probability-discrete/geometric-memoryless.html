Geometric distribution

Also called the waiting-time distribution, or "trials until the first success". The source guide's one problem is an insurance model where each extra claim is 5 times less likely than the one before; that ratio makes the claim count geometric.

Prime · 2 minutes before you read

The problem: The source's claims rule pn+1 = pn/5 hides a named distribution. 'Wait for the first success' questions need a tail formula and a clear convention (trials or failures), or you end up off by one.

Where it fits: After the binomial and the Poisson: instead of counting successes in a fixed number of trials, count how long until the first one. The first-step card has already used it (the thief tries a geometric number of doors), and the negative binomial adds r of them.

Builds on: First-step analysis

You'll meet: qⁿp and the tail qᵏ trials (mean 1/p) against failures (mean q/p) memorylessness: P(N ≥ m + n | N ≥ m) = P(N ≥ n) the only memoryless distribution on the whole numbers

In one breath

Repeat an independent yes/no trial with success chance p until the first success. The number of trials (or of failures before it) is geometric. Each extra count is a fixed factor q = 1 − p less likely than the last, so the pmf is a pure geometric series, and the tail is simply "the first k all failed": qk.

Filled in for the claims problem: P(more than one claim) = (1/5)² = 1/25 = 0.04.

Reference strip: the two conventions

Same coin flips, two ways to count. The variance is the same; the mean and support shift by one. The claims problem uses the failures form (0 claims is allowed).

MGFs exist for t < −ln q. Tails: P(X > k) = qk and P(Y ≥ k) = qk. numpy's rng.geometric(p) counts trials (its smallest draw from 10⁵ at p = 0.8 is 1), so subtract 1 for the failures form.

Memoryless, proven in one line

P(N≥m+n∣N≥m) = qm+nqm = qn=P(N≥n)m drops out

The event {N ≥ m + n} sits inside {N ≥ m}, so the conditional is a ratio of tails, and powers of q divide cleanly. Claims: P(N ≥ m + 2 | N ≥ m) = 1/25 for m = 0, 1, 2, 3 (computed). In the trials form the same line reads P(X > m + n | X > m) = P(X > n); mixing ">" with the failures form breaks it.

The four words, two examples each

A geometric count is a coin you keep tossing until heads: the coin never remembers how many tails came first.

In Python

import random
from fractions import Fraction as F

def claims_pmf(ratio, n_max):
    """p_{n+1} = ratio * p_n. Normalise, return p_0..p_n."""
    p0 = 1 - ratio            # p0 * sum(ratio**n) = p0 / (1 - ratio)
    return [p0 * ratio**n for n in range(n_max + 1)]

def tail(q, k):
    """P(N >= k) for N = failures before the first success."""
    return q**k               # the first k trials all failed

def simulate(p, trials=10**6, seed=0):
    rng = random.Random(seed)
    counts = []
    for _ in range(trials):
        n = 0
        while rng.random() >= p:      # failure with prob 1 - p
            n += 1
        counts.append(n)
    return counts

q = F(1, 5)
p = claims_pmf(q, 1)
print(1 - p[0] - p[1], tail(q, 2))  # → 1/25 1/25
print([str(tail(q, m + 2) / tail(q, m)) for m in range(4)])
# → ['1/25', '1/25', '1/25', '1/25']   memoryless
c = simulate(0.8)
print(sum(x >= 2 for x in c) / len(c))  # → 0.040037

The simulation loop does about 1.25 × 10⁶ draws, since each count averages 1/p = 1.25 trials; exact answers come from Fraction, not the simulation.

How it differs from related ideas

Four claim-count models, all with mean 1/4. Memoryless means P(N ≥ 2 | N ≥ 1) equals P(N ≥ 1): one claim in, a second is exactly as likely as the first was.

✗ Poisson(1/4)

P(N ≥ 1) = 0.2212, but P(N ≥ 2 | N ≥ 1) = 0.1198. Having one claim makes a second less likely: the tail falls faster than geometric.

✗ Negative binomial(2, 8/9)

A sum of two geometrics. P(N ≥ 1) = 0.2099 vs 0.1634 given one claim. Only r = 1 (the geometric itself) is memoryless.

✗ Binomial(2, 1/8)

Fixed number of trials, so it runs out: 0.2344 vs 0.0667, and P(N ≥ 3 | N ≥ 2) = 0. Bounded support can never be memoryless.

✓ Geometric(4/5)

P(N ≥ 1) = 0.2 and P(N ≥ 2 | N ≥ 1) = 0.2. It is the only memoryless distribution on the whole numbers; the exponential is its continuous twin.

Is geometric the right model?

Only when the chance of "one more" really doesn't depend on how many came before. The source calls pn+1 = pn/5 a "simplifying assumption", and it is one. Real claim counts usually use Poisson or negative binomial, which follow the wider rule pn/pn−1 = a + b/n (the (a, b, 0) class, used in actuarial loss models). The geometric is the special case b = 0, a = q (inferred here: it is the negative binomial with r = 1).

Memorylessness is also wrong for anything that wears out or warms up: a disk more likely to fail as it ages, a candidate more likely to pass on the third interview. There the hazard changes with time, and you want a negative binomial, a Weibull-style model, or a Markov chain with state. And check the convention before you plug in: a mean of 1/p versus q/p is the classic off-by-one.

Understand and remember

  • Each extra count is a fixed factor q as likely as the last → pₙ = p0qⁿ → normalise: p0/(1 − q) = 1 → p0 = p = 4/5
  • N ≥ k means the first k trials all failed → P(N ≥ k) = qᵏ → P(more than one claim) = (1/5)² = 1/25
  • Tails are powers of q → P(N ≥ m + n)/P(N ≥ m) = qⁿ → the past drops out: memoryless. Anything whose chance of stopping changes with time (wear-out, bounded support) fails this
  • detail that matters numpy's geometric counts trials (smallest draw 1) → subtract 1 for the failures form → mean 1/p against q/p is the classic off-by-one

Reference only

  • both MGFs
  • the (a, b, 0) recursion pₙ/pₙ₋₁ = a + b/n
  • the MGF exists for t < −ln q

5 · Predict commit to an answer before revealing

Two fair dice are rolled together each round until at least one shows a 6. What is the distribution of the number of rounds, and its mean? Commit first.

Reveal

Geometric (trials form) with p = 1 − (5/6)² = 11/36, so the mean is 36/11 ≈ 3.27 rounds. 'No 6 this round' needs both dice to miss, so q = 25/36: the minimum of two independent geometric waits is itself geometric.
