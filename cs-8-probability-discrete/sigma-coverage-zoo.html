How much lies within kσ?

Also called the 68–95–99.7 rule, the empirical rule, or kσ coverage. The source guide lists six discrete distributions and asks, for each one, how much probability sits within 1, 2 and 3 standard deviations of the mean. It gives no answers, so this card works out all eighteen exactly.

In one breath

Work out the mean μ and standard deviation σ, mark the interval from μ − kσ to μ + kσ, and add up the probabilities of the whole numbers that fall strictly inside it. For a discrete variable that's a short, finite sum. The normal curve's 68/95/99.7 is one particular answer, and Chebyshev's 1 − 1/k² is the lowest any distribution can go.

Filled in for NB(3, 0.5), k = 1: 6 ± 2.449 = (3.551, 8.449), so x = 4…8, and 0.1875 + 0.1875 + 0.1563 + 0.1172 + 0.0820 = 187/256 = 0.7305.

Two things that change the answer, and one that doesn't

On a lattice, a probability jumps whenever an interval edge crosses a whole number, so it matters exactly where the edges fall.

In Python

from fractions import Fraction as F
from math import ceil, comb, erf, floor, sqrt

def coverage(pmf, mu, var, k, strict=True):
    """P(|X - mu| < k*sigma): sum pmf over the integers inside."""
    # squares compared as Fractions: exact even when mu +- k*sigma
    # is an integer, as for Poisson(4)
    r = k * sqrt(var)                       # only to bound the loop
    lo, hi = floor(mu - r) - 1, ceil(mu + r) + 1
    inside = [x for x in range(lo, hi + 1) if pmf(x) and (
              (x - mu) ** 2 < k * k * var if strict
              else (x - mu) ** 2 <= k * k * var)]
    return sum(pmf(x) for x in inside), inside

nb = lambda x: comb(x - 1, 2) * F(1, 2) ** x if x >= 3 else 0
for k in (1, 2, 3):                     # NB(3, 0.5): mu 6, var 6
    p, xs = coverage(nb, F(6), F(6), k)
    print(k, f"{xs[0]}..{xs[-1]}", p, f"{float(p):.4f}",
          f"normal {erf(k / sqrt(2)):.4f}",
          f"cheb {1 - 1 / k**2:.4f}")
# → 1 4..8 187/256 0.7305 normal 0.6827 cheb 0.0000
#   2 3..10 121/128 0.9453 normal 0.9545 cheb 0.7500
#   3 3..13 2025/2048 0.9888 normal 0.9973 cheb 0.8889

Time O(kσ) · Space O(kσ) per call: only the whole numbers within kσ of μ are visited, so even an infinite support such as Poisson is a sum of about 2kσ terms. The full file builds all six pmfs and prints both tables.

Why it beats the alternatives

✗ Quoting 68–95–99.7

That's the normal curve's answer. Here the true k = 1 values run from 0.547 (Poisson) to 0.867 (geometric), so the rule is off by up to 0.18.

✗ Chebyshev's bound

It always holds, but it's loose: it promises nothing at k = 1 and 0.75 at k = 2, where every distribution here gives at least 0.93.

✗ Simulating

It works, but it's noisy: 10⁶ draws still leave about ±0.0005 of error (one standard error), and you need an exact tie rule anyway for Poisson's edge bars.

✓ Sum the pmf inside

At most 14 terms here, exact as a fraction, and the < versus ≤ decision is explicit instead of hidden in a float comparison.

So is 68–95–99.7 ever right for these?

Only approximately, and only when the distribution is close to normal: many trials, a mean far from any boundary. That's why the binomial and hypergeometric land within 0.02 of the normal at k = 1, while the skewed geometric misses it by 0.18 at k = 1. Bigger n pulls them closer, as in the normal approximation to the binomial, but the lattice jumps never fully go away.

Use Chebyshev when all you know is μ and σ. It can't be improved without more information: the three-point variable X = ±k with probability 1/(2k²) each and 0 otherwise has σ = 1 and P(|X| < k) = 1 − 1/k² exactly (3/4 at k = 2). If you only care about one tail, Cantelli's one-sided bound is tighter.
