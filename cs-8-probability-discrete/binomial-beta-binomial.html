Binomial and beta-binomial

Bin(n, p): successes in n independent trials that share one success rate p. The beta-binomial (also called the Pólya urn distribution, or a beta mixture of binomials) is what you get when p is itself uncertain and drawn from a beta distribution. The source guide asks for its pmf and gives no answer; it's derived here.

Prime · 2 minutes before you read

The problem: One binomial with a pooled rate assumes every unit (batch, school, user) shares the same p. When the rates differ, it badly understates the spread and flags ordinary units as rare.

Where it fits: The first distribution after the MGF card. The binomial is the course's basic count, and the beta-binomial is part 2's conditioning move applied to a continuous hidden rate: the judges' two worlds become a Beta density.

In one breath

Draw a success rate p from a Beta(α, β), then run n trials at that rate and count the successes. Averaged over every possible p, the count has the same mean as a binomial at the average rate, but a much wider spread: batches whose p happens to be high or low produce extreme counts far more often than one fixed p ever would.

Worked example: same mean, 2.8× the variance

Bin(10, ½) against BB(10, 2, 2). Both are centred on 5, but the beta-binomial moves mass from the middle out to the tails.

Bin(10, ½)BB(10, 2, 2)x-axis: k successes · y-axis: P(X = k)
p ~ Beta(2,2): E[p] = 1/2, Var p = αβ/((α+β)²(α+β+1)) = 1/20 E[p²] = 1/20 + 1/4 = 3/10 Var X = E[Var(X | p)] + Var(E[X | p]) (total variance) = E[n p (1−p)] + Var(n p) = 10 · (1/2 − 3/10) + 100 · 1/20 = 2 + 5 = 7 vs binomial 2.5 Shortcut: 2.5 · (α+β+n)/(α+β+1) = 2.5 · 14/5 = 7 → ×2.8

Middle vs tails: P(3 ≤ X ≤ 7) is 57/64 = 0.891 for the binomial but 85/143 = 0.594 for the beta-binomial, and P(X = 0) is 1/26 against 1/1024, which is 512/13 ≈ 39× larger. A simulation of 10⁶ draws (draw p, then X; seed 0) gives mean 4.9997, variance 6.9938, P(X = 0) = 0.0384.

The words, two examples each

Think of factory batches. Within a batch every item has the same defect rate, but the rate varies from batch to batch. The binomial describes one batch; the beta-binomial describes a batch picked at random.

In Python

from fractions import Fraction as F
from math import comb, factorial as fact
import numpy as np

def B(a, b):
    """Beta function for integer a, b: (a-1)!(b-1)!/(a+b-1)!."""
    return F(fact(a - 1) * fact(b - 1), fact(a + b - 1))

def binom_pmf(n, k, p):
    return comb(n, k) * p**k * (1 - p)**(n - k)

def betabinom_pmf(n, k, a, b):
    # integrate Bin(n, p) against the Beta(a, b) density over p
    return comb(n, k) * B(k + a, n - k + b) / B(a, b)

def mean_var(pmf):
    m = sum(k * q for k, q in enumerate(pmf))
    return m, sum((k - m)**2 * q for k, q in enumerate(pmf))

def simulate(n, a, b, trials=10**6, seed=0):
    rng = np.random.default_rng(seed)
    x = rng.binomial(n, rng.beta(a, b, trials))  # draw p, then X
    return x.mean(), x.var(), (x == 0).mean()

n, a, b = 10, 2, 2
bi = [binom_pmf(n, k, F(1, 2)) for k in range(n + 1)]
bb = [betabinom_pmf(n, k, a, b) for k in range(n + 1)]
print("Bin     mean, var:", *mean_var(bi))
print("BetaBin mean, var:", *mean_var(bb))
print("P(X=0) ratio BetaBin/Bin:", bb[0] / bi[0])
m, v, p0 = simulate(n, a, b)
print(f"sim: mean {m:.4f}  var {v:.4f}  P(X=0) {p0:.4f}")
# → Bin     mean, var: 5 5/2
#   BetaBin mean, var: 5 7
#   P(X=0) ratio BetaBin/Bin: 512/13
#   sim: mean 4.9997  var 6.9938  P(X=0) 0.0384

Time O(n) to build the whole pmf · Space O(n): one beta-function ratio per k. Fractions keep it exact for whole-number α, β; for real-valued ones use math.lgamma, since B(a, b) = Γ(a)Γ(b)/Γ(a+b). The saved file also prints both pmfs as fractions and the variance split 2 + 5 = 7.

Why it beats the alternatives

For counts out of n where the rate differs between units (batches, users, pages):

✗ One pooled binomial

Uses p = ½ for every unit. It claims variance 2.5 when it's 7 and puts P(X = 0) at 1/1024 instead of 1/26, so ordinary units get flagged as 39× rarer than they are.

✗ A separate k/n per unit

No pooling at all. With n = 10, a unit at 0/10 gets rate 0, "never fails", from ten trials. Nothing is learned from the other units.

✗ Poisson

Its variance equals its mean, 5, so it's still too narrow here, and it gives probability to X > n, which can't happen.

✓ Beta-binomial

Keeps the mean, fits the extra spread, stays on 0 … n and has an exact pmf. Each unit's rate updates to Beta(α + k, β + n − k), pulled toward the shared average.

Is the beta-binomial always the better model?

No. If every trial really shares one rate (one coin, one machine), the extra parameter only fits noise. As α + β grows with α/(α+β) fixed, it collapses to the binomial (×1.022 at α = β = 200). The factor (α+β+n)/(α+β+1) is never below 1, so it can't model counts that are less spread than binomial.

If the rate splits into a few distinct groups (two suppliers, as in the vaccine problem), a two-component mixture fits better than one smooth beta. If the rate depends on known features, use logistic regression, adding random effects for what's left. And for n = 1 the beta-binomial is just Bernoulli(p̄): with a single trial per unit, the variation in p can't be seen at all.

Understand and remember

  • p is drawn once per unit, then n trials run at that p → the trials are dependent through p → averaging over p keeps the mean at np̄ but adds Var(np) → Var = E[np(1 − p)] + Var(np) = 2 + 5 = 7
  • Binomial × Beta(α, β) density → pk+α−1(1 − p)n−k+β−1 is an unnormalised Beta → its integral is B(k+α, n−k+β) → a closed-form pmf
  • Overdispersion factor (α+β+n)/(α+β+1) = 1 + (n − 1)ρ → a large α + β (a confident prior) sends the factor to 1 → the binomial is the limiting case
  • detail that matters Pooling across units → each unit's rate updates to Beta(α + k, β + n − k) → extreme k/n values are pulled toward the shared mean, which a separate k/n per unit never does

Reference only

  • B(a, b) = (a−1)!(b−1)!/(a+b−1)! for whole numbers
  • the ₂F₁ MGF
  • math.lgamma for non-integer α, β

5 · Predict commit to an answer before revealing

Start from a Beta(2, 2) prior and observe one unit with 0 successes in 10 trials. What is that unit's updated mean rate, and how does it compare with the naive 0/10? Commit first.

Reveal

1/7 ≈ 0.143. The posterior is Beta(2, 2 + 10) = Beta(2, 12), with mean 2/14. The naive estimate says 'never succeeds'; the prior pulls it toward the shared ½, as if the unit had two extra successes and two extra failures.
