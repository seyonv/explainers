Negative binomial

Also called the Pascal distribution, or the gamma–Poisson (Pólya) mixture. The cheat-sheet gives one problem: read the distribution off M(t) = (0.70 / (1 − 0.3et))5, answer NB(5, 0.70). This card opens that answer up: what NB(5, 0.7) counts, why it is five geometrics added together, and why actuaries use it for claim counts.

In one breath

Repeat a trial that succeeds with probability p until you have r successes, and count the failures along the way. That count is NB(r, p). It is r geometric waits laid end to end, and it is also what you get when each person has their own Poisson rate: counts that spread out more than a Poisson with the same mean.

The source's answer is right, but it doesn't say which convention. No et in the numerator means X counts failures (0, 1, 2, …). The trials form Y = X + 5 has MGF (0.7et/(1 − 0.3et))⁵ and mean 50/7 ≈ 7.143.

Why it is five geometrics added together

Cut the run of trials after each success. Each piece is "failures, then one success", which is one geometric wait. The pieces don't share trials, so they are independent. One run, made up for illustration:

one geometric G: mean q/p = 0.3/0.7 = 3/7 var q/p² = 0.3/0.49 = 30/49 five of them: mean 5 × 3/7 = 15/7 ✓ var 5 × 30/49 = 150/49 ✓ MGFs multiply: (0.7/(1 − 0.3eᵗ)) × … five times = the source's M(t)

Independent parts add their means and their variances, and multiply their MGFs. That last line is exactly why the source's M(t) is a fifth power.

The over-dispersed Poisson, and what r does

Picture a book of drivers. Each driver files claims as a Poisson process, but careful and careless drivers have different rates. If the rates follow a gamma distribution (shape r, scale q/p), the claim count of a driver picked at random is exactly NB(r, p). The driver story is illustrative; the gamma-mixing result is a standard identity, and the simulation below confirms it for these numbers.

In Python

from fractions import Fraction as F
from math import comb
import numpy as np

def nb_pmf(k, r, p):
    """P(X = k), X = failures before the r-th success."""
    return comb(k + r - 1, k) * p**r * (1 - p) ** k

def sum_of_geometrics(r, p, kmax):
    """pmf of G1 + ... + Gr by convolution, each G ~ geometric."""
    geo = [p * (1 - p) ** k for k in range(kmax + 1)]
    dist = [F(1)] + [F(0)] * kmax        # the sum of zero geometrics
    for _ in range(r):
        dist = [sum(dist[j] * geo[k - j] for j in range(k + 1))
                for k in range(kmax + 1)]
    return dist

r, p = 5, F(7, 10)
conv = sum_of_geometrics(r, p, 8)
print(all(nb_pmf(k, r, p) == conv[k] for k in range(9)))
# → True

rng = np.random.default_rng(0)                # 10^6 drivers
rate = rng.gamma(r, 3 / 7, size=10**6)       # shape r, scale q/p
claims = rng.poisson(rate)
print(f"{claims.mean():.4f} {claims.var():.4f}"
      f" {np.mean(claims == 0):.4f}")
# → 2.1434 3.0689 0.1681   (exact 2.1429 3.0612 0.1681)

The full file then sums 10⁶ × 5 geometrics from the same generator: mean 2.1419, var 3.0598, P(0) 0.1678. Every simulated value is within 1.4 standard errors of the exact one (one SE ≈ 0.0017 on the mean, 0.0057 on the variance, 0.0004 on P(0)).

Time O(1) per pmf value · the convolution is O(r · k²) · Space O(k). The closed form is one binomial coefficient and two powers; the convolution redoes the sum-of-geometrics argument numerically, k terms for each of k values, r times.

Why it beats the alternatives (for claim counts)

✗ Poisson

One parameter forces variance = mean. On NB(5, 0.7) data it underrates both no-claim drivers (0.1173 vs 0.1681) and 6+ claims (0.0223 vs 0.0473, half the true tail).

✗ Binomial

Variance np(1 − p) is below the mean, and counts are capped at n. Right for "k of n policies claim", wrong for claims per driver.

✗ Geometric

It is NB with r = 1, so the spread is locked: variance = μ + μ². Matching mean 15/7 would give variance 6.73, over twice the 3.061 here.

✓ Negative binomial

Two knobs: the mean, and r for the extra spread (variance μ + μ²/r). It has a closed-form pmf, a story (gamma-mixed Poisson), and contains the Poisson (r → ∞) and the geometric (r = 1) as edge cases.

Is it always the right count model?

No. If the variance is at or below the mean, NB has nothing to add: use the Poisson, or the binomial when there is a fixed number of chances. If the data have far more zeros than any single NB can produce (most drivers never claim, a few claim a lot), people fit a zero-inflated or hurdle model instead. And if rates vary in a way that isn't gamma-shaped, the mixture is some other distribution, not NB.

Watch the convention before you plug in. numpy's negative_binomial(r, p) counts failures like this card, but numpy.random.geometric counts trials (1, 2, …), which is why the full code file subtracts 1. Some textbooks use trials for NB too, so the mean is r/p = 7.143 instead of rq/p = 2.143. The MGF settles it: et on top means trials. And r doesn't have to be a whole number: the gamma-mixture reading works for any r > 0, which is how regression software fits it.
