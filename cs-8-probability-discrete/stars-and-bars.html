Stars and bars

Also called balls into bins, or counting weak compositions. It counts the ways to split n identical units among k labelled bins. The source guide uses it for $20k in $1k units across 4 investments with minimums of 2, 2, 3 and 4 (thousand); the source states the problem without solving it.

In one breath

Line the n identical units up as stars and drop k − 1 bars among them: everything before the first bar goes to bin 1, between the first and second bar to bin 2, and so on. Every split is exactly one arrangement, so the count is just "which of the n + k − 1 slots hold bars". A minimum is handled by handing it out first and splitting only what is left.

The rule

#{ x1+⋯+xk=n, xi≥mi } = ( n−∑mi+k−1slots: leftover stars + bars k−1bars )
nidentical units to hand out; all of them must be used20 (thousand dollars) klabelled bins; bins can differ, units can't4 opportunities miminimum for bin i; with no minimums, mi = 02, 2, 3, 4 n − Σmithe stars: units left after every minimum is paid20 − 11 = 9
count(n, mins) = comb(n - sum(mins) + k - 1, k - 1) # 0 if n < sum(mins)

Filled in for part 1 of the source: C(20 − 11 + 4 − 1, 3) = C(12, 3) = 12·11·10 / 3! = 220.

Worked example: why it's C(12, 3)

Pay the minimums first (2 + 2 + 3 + 4 = 11), leaving 9 identical $1k units. Any row of 9 stars and 3 bars, 12 slots in all, is one strategy, and every strategy is one row. Here is one:

Green = the bars, the only thing you choose. Two bars side by side (slots 8, 9) mean opportunity #3 gets no extra, only its minimum of 3. Bars at slots 3, 8, 9 ↔ this strategy; any other 3 of the 12 slots ↔ a different one.

The four moving parts, two examples each

Think of cutting a baguette with 9 equal slices into 4 labelled bags: you only decide where the 3 knife cuts go, and two cuts in the same gap leave a bag empty.

Part 2: at least three of the four, case by case

"At least 3" means exactly 3 or all 4. Each case has a different set of bins with different minimums, so count each with the rule and add. The cases don't overlap, since each fixes exactly which bins are empty.

Answers: part 1 = 220, part 2 = 572 (exact, math.comb). A brute force over all 21⁴ = 194,481 tuples (x1, …, x4) with 0 ≤ xi ≤ 20 finds the same 220 and 572. The source has no answer to check against; like the usual textbook reading, this assumes all $20k is invested and a skipped opportunity gets $0.

In Python

from itertools import combinations
from math import comb

def stars_and_bars(n, k):
    """Ways to put n identical units into k bins (each >= 0)."""
    return comb(n + k - 1, k - 1)

def with_minimums(total, mins):
    extra = total - sum(mins)            # hand out the minimums first
    return stars_and_bars(extra, len(mins)) if extra >= 0 else 0

def at_least(total, mins, r):
    """Ways where at least r of the bins are used (the rest get 0)."""
    k = len(mins)
    return sum(with_minimums(total, [mins[i] for i in used])
               for size in range(r, k + 1)
               for used in combinations(range(k), size))

mins = [2, 2, 3, 4]
print(with_minimums(20, mins), at_least(20, mins, 3))
# → 220 572
#   brute force: 220 572        (code/stars-and-bars.py)

Time O(2k · k) · Space O(k) for at_least: one comb per subset of used bins, and here that is only 5 subsets (sizes 3 and 4). The count itself is O(1) arithmetic on n; the brute force is O((n + 1)k).

Why it beats the alternatives

✗ Nested loops over every split

Check all 21⁴ = 194,481 tuples to find 220. Fine for a check, but it grows as (n + 1)k: 10 bins of $20k is 21¹⁰ ≈ 1.7 × 10¹³ tuples.

✗ A DP table

ways[bin][amount] gets 220 and 572 too, in O(k · n²) steps. It's the right move when bins have odd rules, but here it hides a one-line closed form.

✗ Forgetting the minimums

Splitting all 20 freely gives C(23, 3) = 1,771, which counts strategies that give #4 only $1k or nothing. Pay the minimums first, then count.

✓ Stars and bars

Shift out the minimums, then choose bar positions: C(12, 3) = 220 in one line, and "at least 3" is just 5 such terms. You can redo it on paper in an exam.

Does it always apply?

No. It needs identical units and labelled bins with only lower limits. If the units are distinct (20 named employees into 4 teams), each picks a bin: 4²⁰ ways. If the bins are identical too, you are counting integer partitions, which has no closed form like this. With an upper cap, subtract the overflows with inclusion–exclusion: capping every opportunity at $8k leaves 220 − (10 + 10 + 20 + 35) = 145 strategies (brute force agrees).

In a probability question, the C(n + k − 1, k − 1) splits are not equally likely when each unit picks its bin at random: the 20-0-0-0 split then arises one way, and an even 5-5-5-5 split arises 20!/(5!)⁴ ways. Use stars and bars to count outcomes, and use the multinomial to weight them.
