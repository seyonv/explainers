Ten stops from text to answer

The course map · tokenize, embed, positions, attention, feed-forward, logits, softmax, decode, loop · BPE, word2vec, RoPE, Switch Transformers, nucleus sampling, GPT-3 (2013–2021) · measured on Qwen2.5-0.5B

The problem: Most people start with Attention Is All You Need, and its Q, K and V float with nothing attached: the paper assumes you already know what a token is, where its vector comes from and how an answer comes out. The famous transformer paper explains the middle of the model and assumes you know the rest: where the numbers come from, and how an answer comes out. This course follows one question, What is the capital of India?, through all ten stops of a real model, in the order the data meets them. This page is the map: the stops, the shape of the data between them, the card for each one and the paper behind it.

Try this first

Guess first: the model answers ␣The capital of India is New Delhi. How many times does the data go round all ten stops to write that: once, twice (question, then answer), or 9 times?

Show the answer

9 times. Each trip ends with exactly one new token: eight for the answer, and a ninth that picks end-of-text and stops the loop. Stop 10 is just "append the token and go round again".

Three words first

Stop

One step the data passes through, like "cut the text into tokens" or "turn scores into probabilities". Each stop has an input and an output you can print.

Shape

How many numbers pass from one stop to the next, as rows × columns. Our 7 tokens become 7 × 896: one row of 896 numbers per token.

Block

Stops 4 to 6 bundled together. The model runs the same kind of block 24 times in a row, each with its own weights, and the shape stays 7 × 896 throughout.

The stops fall into four stretches

Text into integers · stops 1–2

In → out: 29 characters → 7 tokens → 7 integers, [3838, 374, 279, 6722, 315, 6747, 30].

Keep: the model never sees letters. The cut is learned from data (byte-pair encoding, BPE), and the leading space belongs to the token.

Hub: Why tokenization · BPE by hand · Tiktokenizer tour

Integers into vectors · stop 3

In → out: 7 IDs → 7 × 896 numbers, one row each from a 151,936 × 896 table.

Keep: an ID is only a label. The row is what training can move, so tokens used alike end up pointing alike: India·China 0.449, India·banana 0.013.

Card: Similar words end up close together

The block, 24 times · stops 4–6

In → out: 7 × 896 → 7 × 896, run through 24 blocks.

Keep: attention is the only place tokens read each other, and it can't see order unless RoPE writes position into its queries and keys. The feed-forward part works on each token alone and holds 63.5% of the weights.

Cards: Attention can't tell first from last · Most of the model is the feed-forward part · hub: One self-attention head · GQA

Scores into an answer · stops 7–10

In → out: the last row, 1 × 896 → 151,936 scores → probabilities → one token → append it and go round again.

Keep: the model hands back a distribution, not a word. The decoder picks, and the loop repeats once per token until end-of-text.

Cards: How an LLM turns text into an answer · Choosing the next token is a choice · One token at a time

The weights aren't spread evenly along the route. The feed-forward parts hold 63.5%, the embedding table 27.6% (and it's used twice, at stop 3 and again at stop 7), and attention only 8.9%. The norms hold the last 43,904.

Start with the route, not with Attention Is All You Need

Start with the famous paper

Its model section covers attention (§3.2), the feed-forward part (§3.3), embeddings and softmax (§3.4) and positions (§3.5): stops 3 to 8. It assumes tokens, decoding and the loop, and it describes a 2017 translation model with an encoder and a decoder, not a chat model.

Q, K and V arrive with nothing to attach to. Starting from trending papers is worse: FlashAttention and GQA speed up a stop you can't place yet.

Follow one question first

Every stop has an input and an output you can check: 7 tokens, 7 × 896, 151,936 scores, one token.

Then each paper answers a question you already have. "Where does word order go back in?" is RoFormer. "Why does greedy text loop?" is Holtzman et al. Read the famous paper after the route, and each of its sections lands on a stop you know.

Why this order and not build order. Zero to Hero builds a model from the bottom up, so you meet each piece when you need it to train. This course is data-flow order: the order an input meets the pieces when the model is already trained and answering. It's the order you debug in, too. When an answer is wrong, you print the tokens, then the top probabilities, then the decoder's choice, stop by stop.

Principle

To understand a model, follow one input and write down its shape at every stop

A shape turns a box on a diagram into something you can check. If 7 × 896 goes into a block and 7 × 896 comes out, you can predict what a longer question changes (the 7) and what it doesn't (the 896, the 494,032,768 weights, the 151,936 scores).

Buys you: a place to hang every later paper, and a way to check your own code against a real model.

Where this map simplifies

  1. Stops 4–6 aren't passed once. They form one block that runs 24 times, and each part adds its output back onto the token's running vector (the residual stream) instead of replacing it.
  2. In Qwen, stop 4 has no place of its own. RoPE acts inside every attention layer, on the queries and keys. It gets its own stop because older models added a position vector once, before the first block, and because the question "where does order go in?" deserves its own card.
  3. Attention weight isn't interest. Layers 6, 12 and 18 each sent 35–63% of the last token's attention to the first token, What: a learned parking spot, not interest in the word.
  4. A base model isn't a chat model. Ours only continues text, which is why its first answer token got just 0.277. A Q: … A: wrapper raised the first token to 0.797. The route is identical for a chat model; the weights and the wrapper differ.
  5. Two stops are taught elsewhere on the hub. Tokens and attention already have good cards in other courses, so the map links to them instead of repeating them.

The order is wrong for some goals. If you write GPU kernels, start at FlashAttention; if you serve models, the inference path starts from latency and works inward.

Check yourself

1. Which stops change the shape of the data, and which leave it alone?

Show the answer

Stops 1–3 build it (29 characters → 7 tokens → 7 IDs → 7 × 896). Stops 4–6 keep 7 × 896 through all 24 blocks. Stop 7 keeps the last row and turns it into 151,936 scores; softmax keeps that length; the decoder collapses it to one token; the loop makes the input one token longer.

2. The embedding table appears at two stops. Which, and why is it one table?

Show the answer

Stop 3 reads one row per input token. Stop 7 multiplies the last vector by the whole table to score every possible next token. Qwen2.5-0.5B ties (shares) the two, so those weights are paid once: the table is 136,134,656 weights, 27.6% of the model.

3. Why read Attention Is All You Need after the route rather than before?

Show the answer

Its model sections cover stops 3–8 and assume the rest: tokens before, decoding and the loop after. With the route in hand, §3.2–3.5 each land on a stop whose input and output shape you already know.

Open each step in order · why this works
1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • The model only computes with numbers → text is cut into tokens and each token's ID picks a learned row → 29 characters become a 7 × 896 matrix before any block runs
  • Attention is the only stop where tokens read each other, and a weighted sum ignores order → position has to be written in (RoPE turns queries and keys) → the feed-forward part then works on each token alone and holds 63.5% of the weights
  • Only the last row is scored, against the same table as stop 3 → 151,936 scores → softmax gives a distribution and the decoder picks one token → the choice of decoder changes the answer you read
  • Each pass yields one token → the token is appended and the whole route runs again → 9 passes for our answer, whose probability is the product of its steps (about 0.11)

Reference only

  • the token IDs [3838, 374, 279, 6722, 315, 6747, 30]
  • Qwen2.5-0.5B's config: 24 layers, hidden size 896, 14 query heads, 2 key/value heads, FFN 4,864
  • the weight split: feed-forward 63.5%, embedding table 27.6%, attention 8.9%
  • the paper sections per stop listed in the table

Why this step?

5 · Predict commit to an answer before revealing

Swap Qwen2.5-0.5B for a chat-tuned model of the same size and ask the same question. Which stops on the map change, and what happens to the first answer token's probability of 0.277? Commit before revealing.

Reveal

No stop changes: the route, the shapes and the decoder are the same. The weights differ, and a chat template wraps the question. The whole-route card says a chat model's template would make the first token near-certain. Our base model gives a hint: a plain Q/A wrapper already raised the first token to 0.797. The course didn't measure the chat model.
