Primer

Read these in order. Each block is short on purpose: the diagram and the “best first” link carry the idea; “Go deeper” is only for when a block doesn't land.

  1. The tools the classes assume

    15 min

Every class uses the same six tools, and they each do one job. TRL is Hugging Face's post-training library: SFTTrainer, GKDTrainer, GRPOTrainer. PEFT adds LoRA adapters. Hugging Face Jobs runs a script on a rented GPU and bills by the minute. Trackio is a free, local-first experiment tracker (like Weights & Biases) that syncs its dashboard to a Hugging Face Space. vLLM is the fast generation engine used for evals and RL rollouts. Inspect (from the UK AI Security Institute) runs the evals.

Each class script is a single Python file with its dependencies written in a comment block at the top (PEP 723). uv run script.py builds the right environment on the fly; hf jobs uv run --flavor a100-large script.py does the same thing on a cloud GPU. So you never install PyTorch by hand.

Set up and run one thing on every tool

Time 45 minCost $0

Do this once. Every later stage assumes it works.

  1. Make a Hugging Face account and a write token, then log in
    brew install uv
uv tool install huggingface_hub
hf auth login          # paste a token with write access
hf auth whoami
    You should see your username. Jobs also needs a payment method or prepaid credits on your billing page↗; add $10–20 when you reach stage 4, not before.
  2. Clone the series repo and skim its tutorials
    git clone https://github.com/burtenshaw/training-agents
ls training-agents/tutorials
    You should see 01-sft-on-traces 02-distillation 03-reinforcement-learning 04-environments. You'll run a file from each.
  3. Log a fake run to Trackio and open the dashboard
    uv run --python 3.12 --with trackio python - <<'EOF'
import trackio, math
trackio.init(project="base-camp")
for step in range(100):
    trackio.log({"loss": 2.5 * math.exp(-step / 30) + 0.3})
trackio.finish()
EOF
uv run --python 3.12 --with trackio trackio show --project base-camp
    You should see a local dashboard with one falling loss curve. Every class dashboard is this, with real numbers.
  4. Run the 10-second RL demo in your own mini-suey-rl repoIn ~/Desktop/repos/extending_coding_agents_rl. No GPU, no account.
    cd ~/Desktop/repos/extending_coding_agents_rl
make demo
make demo-broken
    You should see a policy going from 5.6% to about 81% correct, and a “steps that taught nothing” line: 2/40 with the graded reward vs 16/40 with pass/fail. Don't worry about why yet; stage 1 explains it.
  5. Optional: run a 1-minute CPU job on HF Jobs to see the flow
    hf jobs run --flavor cpu-basic --timeout 5m python:3.12 python -c "print('hello from HF Jobs')"
hf jobs ps -a
    You should see the job's logs streaming back, then COMPLETED. A GPU job is the same command with --flavor a100-large and your script.

Checkpoint

Closed book. Write your answer before you open each one. If you miss one, reread the block it names, not the whole stage.

  1. What's the difference between uv run train.py and hf jobs uv run --flavor a100-large train.py?

    Answer

    Nothing about the script. The first builds its environment and runs it on your Mac; the second does exactly the same on a rented A100 and bills per minute until it finishes or hits --timeout.

    Reread: The tools the classes assume

  2. In make demo-broken, the pass/fail reward wasted 16 of 40 steps. Guess why before stage 1 tells you.

    Answer

    With a pass/fail reward, many groups of attempts are all-fail (or all-pass). When every attempt scores the same, there's nothing to compare, so the update is zero. Stage 1 and stage 6 make this precise.

    Reread: Stage 6 · The group is the baseline
