Primer

  1. Soft labels and the two KLs

    ~2 h

You need this because if you take the optional rung, you copy a frontier model's winning games into your small model.

SFT learns from hard labels: the one token the teacher wrote. Logit distillation learns from soft labels: the teacher's whole probability distribution over the next token. It needs white-box access to the teacher and the same vocabulary (Qwen3-0.6B and Qwen3-4B share 151,936 tokens; Qwen2.5-0.5B and 7B don't).

The gap between two distributions is measured with KL divergence. Teacher T = [0.7, 0.2, 0.1], student S = [0.4, 0.4, 0.2]. Forward KL, KL(T‖S) = Σ T·ln(T/S) ≈ 0.184, punishes the student for missing anything the teacher likes, so it spreads out (mean-seeking). Reverse KL, KL(S‖T) ≈ 0.192, punishes the student for putting mass where the teacher wouldn't, so it commits to the teacher's main mode (mode-seeking). JSD sits between them. In GKDTrainer, beta picks: 0 forward, 0.5 JSD, 1 reverse.

  1. Off-policy, on-policy, self

    ~1.5 h

You need this because it decides whether your small model learns from the teacher's games or from its own.

Off-policy (--lmbda 0): train on fixed dataset text. In Class 2 that's the Pi traces themselves, scored token by token by the teacher's logits (Qwen3-4B never writes anything). Cheap and fast, but the student only ever sees the teacher's paths, so at test time it drifts into states it never practised. That's exposure bias.

On-policy (--lmbda 1): the student writes, the frozen teacher reads the student's text in one prefill pass and scores every token, and the student moves toward the teacher per token. It's like RL with a dense reward at every token instead of one at the end, and it's generation-bound, which is why Class 2 caps it at 60 steps and 128 new tokens.

Self-distillation uses the same model as its own teacher, given privileged context the student side doesn't see (a hint, a solution, feedback). TRL ships SDPO and SDFT trainers for this; the class covers them at 48:37. A student is capped by its teacher; RL is capped by its environment and reward. That's the bridge to stage 6.

Class 2's train_gkd.py (TRL's GKD example with two bug fixes). Student Qwen3-0.6B, teacher Qwen3-4B, data sergiopaniego/pi-mono-chat. One learning rate each is enough; the class swept three.

  1. Compute the two KLs in Python first (Mac)
    python3 -c "import math;T=[.7,.2,.1];S=[.4,.4,.2];print('fwd',sum(t*math.log(t/s) for t,s in zip(T,S)),'rev',sum(s*math.log(s/t) for t,s in zip(T,S)))"
    You should see fwd ≈ 0.184, rev ≈ 0.192.
  2. Off-policy logit KD (lmbda 0, beta 0), 3 epochs
    cd training-agents/tutorials/02-distillation
hf jobs uv run --flavor a100-large --secrets HF_TOKEN -d --timeout 1h train_gkd.py \
  --model_name_or_path Qwen/Qwen3-0.6B --teacher_model_name_or_path Qwen/Qwen3-4B \
  --dataset_name sergiopaniego/pi-mono-chat --lmbda 0.0 --beta 0.0 --dtype bfloat16 --bf16 True \
  --learning_rate 2e-5 --per_device_train_batch_size 2 --gradient_accumulation_steps 8 \
  --num_train_epochs 3 --eval_strategy steps --eval_steps 10 --logging_steps 1 \
  --report_to trackio --project off-policy --run_name logit-kd-lr2e-5 \
  --trackio_space_id <you>/c2-trackio --output_dir qwen3-0.6b-kd --push_to_hub --hub_model_id <you>/qwen3-0.6b-pimono-kd
    You should see a few minutes of training and a falling eval/loss.
  3. On-policy GKD (lmbda 1), capped at 60 steps. Run it with --beta 0.5, then again with --beta 1 (change the run name, output dir and Hub ID so it doesn't overwrite)
    hf jobs uv run --flavor a100-large --secrets HF_TOKEN -d --timeout 1h train_gkd.py \
  --model_name_or_path Qwen/Qwen3-0.6B --teacher_model_name_or_path Qwen/Qwen3-4B \
  --dataset_name sergiopaniego/pi-mono-chat --lmbda 1.0 --beta 0.5 --temperature 0.9 --max_new_tokens 128 \
  --dtype bfloat16 --bf16 True --learning_rate 2e-5 --per_device_train_batch_size 2 --gradient_accumulation_steps 8 \
  --max_steps 60 --eval_strategy steps --eval_steps 10 --logging_steps 1 \
  --report_to trackio --project on-policy --run_name gkd-b05 \
  --trackio_space_id <you>/c2-trackio --output_dir qwen3-0.6b-gkd --push_to_hub --hub_model_id <you>/qwen3-0.6b-pimono-gkd
    You should see slower steps than off-policy (the student generates every step). Put each method in its own Trackio project: their losses measure different things (forward KL on fixed data vs JSD on the student's own text).
  4. Evaluate base vs distilled with Inspect
    hf jobs uv run --flavor a100-large --secrets HF_TOKEN -d --timeout 1h eval_inspect.py \

    You should see general coding drifting slightly down: the class saw 0.457/0.395 → 0.427/0.380. The target task's signal is the held-out eval/loss, not HumanEval. Say that sentence out loud; it's the honest reading.

Checkpoint

Closed book. Write your answer before you open each one. If you miss one, reread the block it names, not the whole stage.

  1. What do lmbda and beta control in GKDTrainer?

    Answer

    lmbda is the fraction of batches where the student generates its own text (0 = off-policy on the dataset, 1 = fully on-policy). beta picks the divergence: 0 forward KL, 0.5 JSD, 1 reverse KL.

    Reread: Soft labels and the two KLs

  2. Why must the student and teacher share a vocabulary for logit distillation?

    Answer

    The loss compares their probability distributions position by position over the same token IDs. Different vocabularies mean the distributions aren't over the same things.

    Reread: Soft labels and the two KLs

  3. Why is on-policy distillation slower per step than off-policy?

    Answer

    The student has to generate text every step (decoding is slow), and then the teacher prefills it. Off-policy just reads fixed data.

    Reread: Off-policy, on-policy, self

  4. HumanEval dropped slightly after distillation. Did distillation fail?

    Answer

    Not necessarily. It targeted Pi-harness traces, not general coding; some drift on unrelated skills is expected. Judge it by held-out loss on the target task, and treat the HumanEval drop as the cost.

    Reread: Lab
