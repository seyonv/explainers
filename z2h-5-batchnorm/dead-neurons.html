Dead neurons across nonlinearities

Also called: dying ReLU, dead units, saturated neurons, vanishing local gradient. Lecture 4 · fixing the saturated tanh · 0:12:59

Prime · 2 minutes before you read

The problem: A neuron can stop learning with no error or warning. Nothing crashes and the loss still goes down, but some units never change again, so the net quietly trains with fewer neurons than you paid for.

Where it fits: The saturated-tanh card showed tanh units stuck at ±1 in your MLP. This card asks the same question of every common nonlinearity, using the local-gradient idea from micrograd's tanh backward.

In one breath: a neuron's weights learn only from the gradient that squeezes back through its nonlinearity, and that gradient gets multiplied by the curve's slope. Where the curve is flat, the slope is about 0 and nothing gets through. A neuron that sits on a flat part for every training example is dead: its weights never change again. tanh and sigmoid flatten out in both tails, ReLU is exactly flat for every negative input, and Leaky ReLU is never flat.

Predict first: on inputs from −5 to 5, rank tanh, sigmoid and ReLU by how much of that range is flat (local gradient below 0.01). Which one is flattest?

ReLU 50.0%, tanh 40.1%, sigmoid only 8.3%. ReLU is exactly flat for every negative input. tanh saturates quickly, past |x| ≈ 3. Sigmoid reaches the flat tails only past |x| ≈ 4.6, because it bends more slowly. But even its steepest slope is 0.25, so it always shrinks the gradient at least 4×.

What the nonlinearity does to the gradient

Every hidden neuron computes a preactivation hpreact (its weighted sum plus bias), then applies a nonlinearity f to get its output h. On the backward pass, the chain rule multiplies the incoming gradient by f's slope at that point, its local gradient. That's the (1 - t**2) * out.grad you wrote for tanh in micrograd.

hpreact.grad= f′(hpreact)local gradient × h.gradgradient arriving from above
tanhf′ = 1 − t², where t = tanh(x)1 at x = 0 · 0.001 at |x| = 4 sigmoid σf′ = σ(x)(1 − σ(x)); σ squashes into (0, 1)0.25 at x = 0 · 0.018 at |x| = 4 ReLUf = max(0, x); f′ = 1 if x > 0, else 0exactly 0 for x ≤ 0 Leaky ReLUf = x if x > 0, else 0.01x; f′ = 1 or 0.01never below 0.01

Anything multiplied by a local gradient near 0 is near 0, however big h.grad was. So W1 and b1, which get their gradient from hpreact.grad, stop moving.

From flat to dead

A flat slope for some examples is normal: in a healthy ReLU layer about half the units are off for any given input. A neuron is dead when it is on the flat part for all inputs. For tanh that's Karpathy's white column in plt.imshow(h.abs() > 0.99). After fix 1, 61.0% of one batch's activations are past 0.99 but no fully dead column (0 of 200, measured over all 182,625 training examples). For ReLU, dead means the preactivation is ≤ 0 for every example. Its local gradient is then exactly 0, so its column of W1 gets exactly 0 gradient and never moves. Karpathy names two causes: a bad init, or a learning rate so high that one update throws the neuron's weights off the data.

The lab tests the second cause. It trains a 200-unit ReLU MLP for 1000 steps at lr 0.1, takes one step at a "shock" learning rate, then trains another 1000 steps at lr 0.1, and counts units that are ≤ 0 on all 182,625 training examples:

The next few steps then saw losses in the thousands (38,537 two steps later), and those huge gradients shoved units below zero: 41 were dead by the third step. ▶ Build itruns on your M3 · about 3 s

When: pause the video at 0:12:59. Once he has shown the tanh backward formula and moves on to sigmoid and ReLU, compute each curve's local gradient with autograd instead of by hand.

import torch
import torch.nn.functional as F
acts = {'tanh': torch.tanh, 'sigmoid': torch.sigmoid,
        'relu': torch.relu,
        'leaky_relu': lambda x: F.leaky_relu(x, 0.01)}
xs = torch.tensor([-4., -2., -0.5, 0.5, 2., 4.], requires_grad=True)
grid = torch.linspace(-5, 5, 10001, requires_grad=True)
for name, f in acts.items():
    xs.grad = None; f(xs).sum().backward()      # local grads f'(x)
    grid.grad = None; f(grid).sum().backward()
    flat = (grid.grad.abs() < 0.01).float().mean().item() * 100
    df = ' '.join(f'{v:7.3f}' for v in xs.grad.tolist())
    print(f'{name:10s} df {df}')
    print(f'{"":10s} flat {flat:5.1f}% of [-5, 5]')

How the four compare

✗ tanh

Flat in both tails past |x| ≈ 3, so big preactivations stop learning. The slope is never above 1, so a gradient can only shrink through it. Fix the scale at init (the next card) and it behaves.

✗ Sigmoid

Only 8.3% of the range is flat, but its steepest slope is 0.25, so every layer cuts the gradient at least 4×. Stack a few and the gradient fades even with no saturation.

✗ ReLU

A slope of exactly 1 for positive inputs passes gradients through undamped. But it's exactly 0 for all negative inputs, so a unit pushed below zero on all data is gone for good (188 / 200 after one lr-100 step).

✓ Leaky ReLU

Keeps ReLU's slope of 1, but the negative side has slope 0.01 instead of 0. No input is fully flat, so no unit can die. After the lr-30 shock its loss was 2.4754, against 2.5262 for ReLU.

So should you always use Leaky ReLU?

No. With a sane init and learning rate, dead units are rare: the lab's ReLU net had 0 of 200 after 2001 steps at lr 0.1, and ResNets still use plain ReLU (the motif card). "Not dead" isn't the same as healthy, either. A Leaky unit stuck below zero learns at 1% speed. In a scratch rerun, 25 to 34 of them stayed all-negative for 5000 steps after the shock. Karpathy also notes that ELU has a flat part, so ELU doesn't fully escape this either.

The real fixes sit upstream, and they're the rest of this lecture: scale the weights so preactivations land on the steep part (Kaiming init), standardise them each step (BatchNorm), and watch the learning rate (update:data ratio). A one-hidden-layer net shrugs off a few bad units. Karpathy warns the damage compounds in a deep stack.

Understand and remember

  • Backward multiplies h.grad by the local gradient f′(hpreact) → on a flat part f′ ≈ 0 → hpreact.grad ≈ 0 → W1 and b1 for that unit get ≈ 0 gradient → the unit stops learning
  • ReLU's slope is exactly 0 for x ≤ 0 → a unit whose preactivation is ≤ 0 on every example gets exactly 0 gradient → its weights never move → it stays dead (a bad init or one oversized lr step can put it there)
  • tanh/sigmoid saturate in both tails, and sigmoid's slope is at most 0.25 → gradients shrink at every layer even when nothing is saturated → the damage compounds with depth
  • Leaky ReLU gives negative inputs slope 0.01 instead of 0 → no input is fully flat → units can't die, but a unit stuck below zero learns at only 1% speed
  • detail that matters Dead is judged over all training examples, not one batch → about half of a healthy ReLU layer is off for any single input, and that is fine → check dead units with (preact <= 0).all(0) over the whole set, not one batch's histogram

Reference only

  • the formulas: tanh′ = 1 − t², σ′ = σ(1 − σ), ReLU′ = 1[x > 0], Leaky′ = 1 or 0.01
  • F.leaky_relu(x, 0.01) and the default negative slope
  • the flat-share numbers on [−5, 5]: 40.1%, 8.3%, 50.0%, 0.0%
  • the --plot flag that saves labs/dead-neurons.png
