In one breath: real deep networks are built by repeating one small unit: a weight layer (Linear, or a convolution for images) with its bias switched off, then BatchNorm, then a nonlinearity such as tanh or ReLU. PyTorch ships each piece as a ready-made module, and its defaults are worth knowing because they differ from the choices you made by hand in this lecture.

Predict first: how many trainable parameters does Linear(30, 200, bias=False) → BatchNorm1d(200) → Tanh have? And how many if you leave the Linear's bias on?

6,400 without the bias, 6,600 with it. The weight matrix is 30 × 200 = 6,000; BatchNorm adds a gain γ and a shift β for each of the 200 columns, 400 more; tanh has none. A Linear bias would add 200 numbers that BatchNorm's mean subtraction wipes out straight away, so they get no gradient and never learn anything. The lab prints both counts.

The motif inside ResNet-50

Karpathy opens torchvision's ResNet, a deep image classifier. Its building block, Bottleneck, is three copies of the motif. A convolution (conv) is the image version of a Linear layer: the same W·x applied to small overlapping patches of the image. A residual (skip) connection adds the block's input back to its output, so the signal has a path around the block.

ResNet-50 = stem conv + 16 Bottleneck blocks × 3 convs + final Linear = 1 + 48 + 1 = 50 weight layers blocks per stage: [3, 4, 6, 3] → 3 + 4 + 6 + 3 = 16 (resnet.py, resnet50)

Every conv in the file is built with bias=False (the conv1x1 and conv3x3 helpers and the stem) for the same reason you dropped b1: the BatchNorm right after it subtracts any bias away.

How big is nn.Linear's default init?

A number drawn uniformly between −a and +a has standard deviation a/√3. PyTorch's bound is a = 1/√fan_in, so:

std(w)nn.Linear default = 13·nin =190=0.1054 vs 5/3ninKaiming, tanh gain =0.3043
n_infan_in, the inputs per neuron30 = 3 characters × 10-dim embedding 5/3the gain for tanh, from the Kaiming init cardnn.init.calculate_gain('tanh')

Measured on nn.Linear(30, 200): max |w| = 0.1825 (bound 0.1826) and std 0.1051 (formula 0.1054). So the default is 0.3043 / 0.1054 ≈ 2.9× smaller than Kaiming-tanh. Under BatchNorm that mostly doesn't matter, because BN rescales the preactivations anyway.

The last two lines compare the lecture's own BatchNorm1d class with PyTorch's on the same batch of 32. They normalise with slightly different variances: the lecture's x.var() divides by n − 1 = 31, while PyTorch divides by n = 32, so outputs differ by up to a factor √(32/31) = 1.016. Both store the n − 1 version in running_var, which is why that line agrees. The bessel-correction card in z2h-6 picks this up.

Why it beats the alternatives

✗ Keep the bias before BN

BN subtracts each column's batch mean, so a constant bias cancels. In the batchnorm-forward lab its gradient is 4.4e-10, zero up to rounding: 200 parameters that never learn.

✗ No norm, hand-tuned gains

Works for one hidden layer, but each layer's scale has to be set by hand and errors multiply with depth. Karpathy calls training before normalization layers "a total balancing act" (1:32:07).

✗ Trust every torch default

Momentum 0.1 at batch 32 makes the running stats jitter. On the trained MLP the running mean ends 0.0570 away from the calibrated one on average, vs 0.0076 with 0.001 (batchnorm-inference lab): 7.5× noisier.

✓ weight (bias=False) → BN → nonlinearity

BN hands each nonlinearity preactivations with a controlled scale, so the stack trains without per-layer tuning, and BN's β does the bias's job. You repeat one unit instead of balancing 50 scales.

Is this motif always the right choice?

No. BatchNorm needs a batch: in training each example's output depends on its batchmates, and a batch of one has no variance at all. Karpathy's own advice in the summary is to avoid it where you can; he has shot himself in the foot with it many times. Transformers such as GPT keep the same "weight, norm, nonlinearity" rhythm but use LayerNorm, which normalises each example on its own (z2h-8).

The order also varies. ResNet's third motif adds the skip connection before its ReLU, and some designs put the norm first. What stays constant is that a norm sits between the weights and the parts that are sensitive to scale.

Understand and remember

  • BN subtracts each column's batch mean → any constant added before it cancels → the bias gets zero gradient → real nets set bias=False and let BN's β be the bias
  • Weight layer → BN → nonlinearity → every nonlinearity sees preactivations of a controlled scale regardless of the weight init → one unit can be stacked 50 deep without per-layer gain tuning (ResNet-50 = 16 Bottlenecks × 3 motifs + 2)
  • PyTorch BN momentum defaults to 0.1 → each batch-32 mean gets 10% weight in the running estimate → the buffer tracks batch noise (0.0570 vs 0.0076 with 0.001) → set a smaller momentum for small batches
  • Lecture BN normalises with x.var() (divide by n − 1), PyTorch with divide by n → training outputs differ by up to √(32/31) = 1.016 → both store the n − 1 version in running_var, so eval mode agrees
  • detail that matters nn.Linear's default init is uniform in ±1/√fan_in → std 1/√(3·fan_in) = 0.1054 for fan_in 30, about 2.9× smaller than Kaiming-tanh → it matters in a net with no norm layer, much less when BN follows

Reference only

  • the full nn.BatchNorm1d signature: eps=1e-05, momentum=0.1, affine=True, track_running_stats=True, plus torch 2.14's keyword-only bias
  • BN buffer names: running_mean, running_var, num_batches_tracked; γ and β are .weight and .bias
  • torchvision helpers conv1x1/conv3x3, Bottleneck.expansion = 4, ResNet-50 stage sizes [3, 4, 6, 3]
  • ResNet's own conv init: kaiming_normal_(mode="fan_out", nonlinearity="relu")

5 · Predict commit to an answer before revealing

After training, you want to delete a BatchNorm layer at inference by folding it into the Linear before it (the lecture's exercise E02). With bias=False on that Linear, what new parameter must the folded Linear gain, and why?

Reveal

A bias. At eval time BN is a fixed affine map per column: γ·(z − running_mean)/√(running_var + eps) + β. Folding multiplies each weight column by γ/√(running_var + eps) and needs a new bias β − γ·running_mean/√(running_var + eps). The bias you removed for training comes back once the batch statistics are frozen.
