The loss you should see at step 0

Also called: the expected initial loss, the uniform-guess baseline, the step-0 sanity check. Lecture 4 · fixing the initial loss · 0:04:19

Prime · 2 minutes before you read

The problem: A freshly initialised net can start out confidently wrong, and a loss curve that still goes down hides it: you spend the first stretch of training just undoing the bad init, and you never notice.

Where it fits: First card of the BatchNorm lecture. It reuses the z2h-4 MLP and its cross-entropy loss, and turns that loss into a diagnostic you can read before training starts.

  2. In the 4-class toy, what makes [0, 0, 5, 0] cost more than [0, 0, 0, 0], when neither logit vector knows the answer?
  3. Which two parameters of the starter MLP set the scale of its logits, and why does std-1 randn make that scale about 13?
  4. Why can a step-0 loss near 3.30 still hide a badly initialised hidden layer?

In one breath: before training, a model knows nothing about which of the 27 characters comes next, so the most it should claim is "each is equally likely", which costs a loss of −ln(1/27) = 3.2958. The z2h-4 MLP prints about 28 at step 0 instead. That gap tells you the random init is confidently wrong, and you can see it before spending a single training step.

Predict first: the untrained MLP has 27 characters to choose from. What loss should its very first step print, and roughly what does it actually print?

It should print 3.2958; it prints 27.8817. Knowing nothing means giving every character probability 1/27, and the loss is −ln(1/27) = ln 27 = 3.2958. The starter net prints 27.8817 (Karpathy says "27" at 0:04:24), more than 8× the loss of a blind guess.

What "knowing nothing" should cost

The loss is the negative log likelihood from z2h-4: for each example, take the probability the model gave the correct next character, take its log, flip the sign, and average over the minibatch.

loss=−1N ∑i=1N lnpi,yilog prob of the right answer → −ln127=ln27=3.2958if every p is 1/27
Nexamples in the minibatch32 yiindex of the correct next character for example i (Yb[i])0 to 26 pi,yithe probability softmax gives that correct character (softmax turns the 27 logits, the raw output scores, into probabilities)uniform: 0.0370

If every probability is 1/27, every term in the sum is the same, so the average is just −ln(1/27). Any number of classes V works the same way: a blind guess costs ln V.

Karpathy's 4-class toy: confidence is what costs

Four classes, the correct one is class 0. Softmax computes p = elogit / sum of elogits. Equal logits (all zeros) give the uniform 1/4; a large logit on the wrong class makes the right one tiny.

Logits for classes 0–3p(class 0)LossWhat happened
[0, 0, 0, 0]1/4 = 0.251.3863uniform: ln 4, the know-nothing cost
[5, 0, 0, 0]148.41/151.41 = 0.9800.0200confident and right: nearly free
[0, 0, 5, 0]1/151.41 = 0.00665.0200confident and wrong: 3.6× the uniform cost
randn × 1mean of 10k draws1.7057small random logits: a bit worse than uniform
randn × 10mean of 10k draws10.3656big random logits: often confident, usually wrong
randn × 100mean of 10k draws103.0973the loss grows in step with the logit scale

e5 = 148.41, so the denominators are 148.41 + 3 = 151.41. Random logits don't know the answer, so the larger they are, the more confidently they bet on a wrong class. The loss has no ceiling: it keeps climbing as the scale grows.

The starter MLP at step 0

ModelStep-0 loss (same scale)Loss blind guess3.2958 starter MLP27.8817
guess: p(correct) = 1/27 = 0.0370 → loss 3.2958 starter: p(correct) ≈ e^−27.8817 = 7.8e-13 → loss 27.8817 measured median p(correct) = 6.08e-13 (32 examples) why: logits span −24.4 … 36.4 on example 0; their std is 12.75 ≈ √(200 · mean(h²) + 1) = √(200 · 0.846 + 1) = 13.0

The starter net draws W2 and b2 from randn (std 1), and each of the 200 hidden units h sits near ±1, so each logit is a sum of about 200 unit-sized terms. Its average top probability is 0.89, yet its top pick is right on only 2 of 32 examples: confidently wrong. The e−27.88 line is a geometric average (exp of the mean log), computed.

When: pause the video at 0:04:19, before he prints the first loss, and run one forward pass of the untrained net. Reuse Xtr, Ytr from your z2h-4 notebook (the random.seed(42) 80/10/10 split).

g = torch.Generator().manual_seed(2147483647)
C  = torch.randn((27, 10), generator=g)
W1 = torch.randn((30, 200), generator=g)
b1 = torch.randn(200, generator=g)
W2 = torch.randn((200, 27), generator=g)
b2 = torch.randn(27, generator=g)
ix = torch.randint(0, Xtr.shape[0], (32,), generator=g)
Xb, Yb = Xtr[ix], Ytr[ix]
h = torch.tanh(C[Xb].view(32, -1) @ W1 + b1)
logits = h @ W2 + b2
print(f'{F.cross_entropy(logits, Yb).item():.4f}')  # step 0
print(f'{-torch.tensor(1/27.).log().item():.4f}')   # the target

Why it beats the alternatives

✗ Just train and watch the curve

The loss does come down, so nothing looks broken. But the first steps only shrink the logits: on your M3 the mean loss over steps 0–999 is 5.9756, against 2.5134 once the init is fixed.

✗ Trust randn for every weight

Std-1 weights feeding a 200-unit layer give logits with std about 13, and that is what produces the 27.8817. Random is fine; random at the wrong scale is not.

✗ Set all the weights to zero

Every logit becomes 0, so the loss is exactly 3.2958, but identical units get identical gradients and never become different. Karpathy keeps small nonzero values to break that symmetry (exercise E01 explores it).

✓ Compute ln V, compare at step 0

One line, zero training cost. If step 0 is far above ln 27 = 3.2958, the init is confidently wrong, and you know to fix the output layer first (next card).

Is 3.2958 always the right target?

It's the right target for a model that knows nothing. A model that knew only how often each character appears (never the context) would do better: the entropy of the training set's next-character frequencies is 2.8226 (computed), below 3.2958 because ., the end-of-name token, alone is 14% of targets. So a step-0 loss a little above 3.2958, like the 3.32 the next card reaches, is healthy; one much higher is not.

Matching it is necessary, not sufficient. A step 0 of 3.3 says the output layer is humble, but says nothing about the hidden layer: in this same net most tanh units are still stuck near ±1 (the saturated-tanh card). The check carries to any classifier with V classes, including GPT's token vocabulary, where you'd expect ln V.

Understand and remember

  • Loss = −ln p(correct), averaged → a model with no information spreads p evenly → p = 1/V for every example → the step-0 target is ln V (ln 27 = 3.2958 here)
  • Large logits → softmax puts almost all probability on one class → without knowledge that class is usually wrong → p(correct) tiny → the loss grows with the logit scale (≈10 at ×10, ≈103 at ×100 in the toy) and has no ceiling
  • W2, b2 drawn with std 1 and 200 hidden units near ±1 → logit std ≈ √(200·0.846 + 1) ≈ 13 → confident random bets → step-0 loss 27.8817 instead of 3.2958 → early training is wasted shrinking logits
  • Step-0 loss ≫ ln V → the output layer is over-scaled → fix the init before training (next card); step-0 loss ≈ ln V → the output layer is fine, but the hidden layer still needs its own check
  • detail that matters The know-nothing baseline ignores class frequencies → a model that only learned character frequencies would score 2.8226 on this data → so a step 0 slightly above 3.2958 is healthy, and getting there is already easy progress for training

Reference only

  • -torch.tensor(1/27.).log() as the one-line check
  • the seed 2147483647 and the randn draw order that reproduce 27.8817
  • the exact toy values: 1.3863, 0.0200, 5.0200

  1. concept Explain why ln V is the loss of a model that knows nothing, using the definition of the loss rather than the number.
    Check
    • the loss is the average of −ln p(correct)
    • knowing nothing, the fairest prediction is equal probability 1/V per class
    • every term is then −ln(1/V) = ln V, so the average is ln V
  2. mechanism Walk through what happens in softmax and the loss when the logits for 4 classes are [0, 0, 5, 0] and the right class is 0.
    Check
    • exponentiate: e5 = 148.41, the others are 1
    • normalise: p(class 0) = 1/151.41 = 0.0066
    • loss = −ln 0.0066 = 5.0200, 3.6× the uniform 1.3863
  3. tradeoff Why not simply set W2 and b2 to exactly zero, which gives a perfect 3.2958 at step 0? What do you gain, and what do you risk?
    Check
    • gain: logits are exactly 0, so the loss is exactly ln 27
    • risk: identical parameters get identical gradients, so symmetry is never broken
    • Karpathy keeps small nonzero values (×0.01 gives 3.3221), which costs almost nothing in loss
  4. concept Your step-0 loss is 3.31 on a 27-class problem. What can you conclude, and what can't you?
    Check
    • can: the output logits are near zero, so the output layer isn't confidently wrong
    • can't: the hidden layer may still be saturated (tanh near ±1), which this check doesn't see
