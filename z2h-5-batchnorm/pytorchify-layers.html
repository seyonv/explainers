Rebuilding torch.nn: Linear, BatchNorm1d, Tanh

Also called: PyTorch-ifying the code, nn.Module-style layers, a layer API. Lecture 4 · just kidding: part2: PyTorch-ifying the code · 1:18:35

Prime · 2 minutes before you read

The problem: The one-hidden-layer MLP lives in one long block of named tensors (W1, bngain, bnmean_running...). Going deeper means editing the init, the forward pass, the parameter list and the inference code by hand, in step, for every layer, and the lecture's diagnostic plots need to see inside every layer.

Where it fits: It repackages everything so far (the Kaiming-scaled Linear, the BatchNorm forward and its running statistics, tanh) as classes shaped like torch.nn. It's the same idea as micrograd's Neuron/Layer/MLP classes, now on tensors. The diagnostic cards that follow depend on it.

In one breath: instead of one long forward pass full of named tensors (W1, b1, bngain, ...), you write each layer as a small class. Every class does the same three things: calling it on x computes the layer, .parameters() hands over the tensors gradient descent should move, and it stores its output in .out. A deep network is then just a Python list of layers, and the training loop never has to change when the list grows.

Predict first: the BatchNorm version drops every Linear bias but adds γ and β to each BatchNorm. Without BatchNorm (Linear layers with bias) the same stack has 46,497 parameters. Does the BatchNorm stack have more or fewer, and by how many?

More: 47,024, which is 527 extra. A hidden layer loses 100 biases but gains 100 γ and 100 β, so each of the five hidden layers nets +100. The output layer loses 27 biases and gains 27 + 27, so +27. That's 5 × 100 + 27 = 527, and 46,497 + 527 = 47,024.

The deep net is a list of 17 layers

Because every layer has the same interface, the whole forward pass becomes a loop, and Karpathy never has to touch it again when he changes the stack:

emb = C[Xb]                        # (32, 3, 10): look up embeddings
x = emb.view(emb.shape[0], -1)     # (32, 30): concatenate them
for layer in layers:
    x = layer(x)                   # Python calls layer.__call__(x)
loss = F.cross_entropy(x, Yb)

class Linear:
    def __init__(self, fan_in, fan_out, bias=True):
        w = torch.randn((fan_in, fan_out), generator=g)
        self.weight = w / fan_in**0.5       # Kaiming, gain 1
        self.bias = torch.zeros(fan_out) if bias else None
    def __call__(self, x):
        self.out = x @ self.weight
        if self.bias is not None:
            self.out += self.bias
        return self.out
    def parameters(self):
        return [self.weight] + ([] if self.bias is None
                                else [self.bias])
class BatchNorm1d:
    def __init__(self, dim, eps=1e-5, momentum=0.1):
        self.eps, self.momentum, self.training = eps, momentum, True
        self.gamma = torch.ones(dim)          # parameters: backprop
        self.beta = torch.zeros(dim)
        self.running_mean = torch.zeros(dim)  # buffers: moving avg
        self.running_var = torch.ones(dim)
    def parameters(self):
        return [self.gamma, self.beta]

class Tanh:
    def __call__(self, x): self.out = torch.tanh(x); return self.out
    def parameters(self): return []
    def __call__(self, x):            # still inside BatchNorm1d
        if self.training:
            xmean = x.mean(0, keepdim=True)   # batch mean
            xvar = x.var(0, keepdim=True)     # batch variance
        else:
            xmean, xvar = self.running_mean, self.running_var
        xhat = (x - xmean) / torch.sqrt(xvar + self.eps)
        self.out = self.gamma * xhat + self.beta
        if self.training:
            with torch.no_grad():
                m = self.momentum
                self.running_mean = (1-m)*self.running_mean + m*xmean
                self.running_var = (1-m)*self.running_var + m*xvar
        return self.out
n_embd, n_hidden = 10, 100
g = torch.Generator().manual_seed(2147483647)
C = torch.randn((vocab_size, n_embd), generator=g)
dims = [n_embd*block_size] + [n_hidden]*5 + [vocab_size]
layers = []
for k in range(6):                  # Karpathy types the 6 rows out
    layers.append(Linear(dims[k], dims[k+1], bias=False))
    layers.append(BatchNorm1d(dims[k+1]))
    if k < 5: layers.append(Tanh())
layers[-1].gamma *= 0.1              # last layer: less confident
parameters = [C] + [p for l in layers for p in l.parameters()]
for p in parameters: p.requires_grad = True
print(sum(p.nelement() for p in parameters))

Why it beats the alternatives

✗ One long forward with named tensors

What the earlier cards did: W1, bngain, bnmean_running... each in its own line. Going from one hidden layer to five means editing the init, the forward, the parameter list and the inference code, by hand, in step.

✗ Running stats in .parameters()

The update loop would try p.data += -lr * p.grad on them, but nothing gives them a gradient. And each step replaces running_mean with a new tensor, so the list would hold a stale copy.

✗ Importing torch.nn straight away

It works, but it hides the parts this lecture is about: where the batch statistics come from, why BatchNorm needs a mode flag, and what the init scale is.

✓ Small classes, one contract

The net is a list, the loop is fixed, and every layer's .out can be inspected. The names match torch.nn, so later you can swap in the real modules with almost no changes.

Is this how torch.nn really works?

The shape of the API is the same, but the details differ. A real nn.Module finds its parameters and buffers automatically when you assign them as attributes, and model.eval() / model.train() flip the training flag on every sub-module for you. nn.Linear stores its weight as (fan_out, fan_in), (100, 30) here, and initialises it uniformly in ±1/√fan_in instead of with a Gaussian. nn.BatchNorm1d normalises with the biased variance, while this class uses x.var, which is unbiased (see the torch.nn card).

The classic bug this design creates is forgetting the flag. Leave training = True, feed a single example while sampling, and its "batch variance" is undefined, so the logits come out nan. For real projects, use torch.nn; write your own classes to learn, or for a layer PyTorch doesn't have.

Understand and remember

  • Every layer implements the same contract (__call__, .parameters()) → the net is just a list → the forward pass is one loop and the parameter list is one comprehension → adding a layer means changing one line, not four places
  • Parameters get gradients from backprop, but the running stats are moving averages updated under no_grad → they must stay out of .parameters() → otherwise the SGD update has no gradient to apply, and the list would hold a tensor that is replaced every step
  • BatchNorm's output depends on the whole batch → a single example (or a different batch) gives different or undefined statistics → so it needs a .training flag that switches to the running buffers at inference → forget to flip it and sampling one name gives nan logits
  • BatchNorm follows every Linear → a Linear bias would be subtracted right back out → bias=False, and BN's β does the shifting → 100 biases out, 200 γ/β in per hidden layer → 47,024 parameters instead of 46,497
  • detail that matters Each layer stores self.out → you can call .retain_grad() on it and histogram activations and gradients per layer → this is what the diagnostic plots on the next cards read
  • detail that matters The output layer's γ is multiplied by 0.1 at init → the logits start near zero and the model starts out unsure → step-0 loss 3.2870, close to the uniform 3.2958 (the fix-1 idea, moved from W2 to γ)

Reference only

  • the BatchNorm1d(dim, eps=1e-5, momentum=0.1) defaults used by the class
  • shapes: C 27×10, Linear weights (30, 100), (100, 100) ×4, (100, 27); n_hidden is 100 in this deep net
  • the notebook's gain line is layer.weight *= 1.0 #5/3, so the measured run uses gain 1
  • real nn.Linear stores weight as (fan_out, fan_in) and uses a uniform init; model.eval() flips the flag on every sub-module

3 · Retrieve from memory, card closed
  1. concept Explain what a layer has to provide so that for layer in layers: x = layer(x) plus [p for l in layers for p in l.parameters()] is all the network code you need.
    Check
    • a __call__ that takes the previous output and returns this layer's output
    • a .parameters() that returns its trainable tensors, or [] for Tanh
    • consistent shapes between neighbours: (32, 30) → (32, 100) → ... → (32, 27)
  2. mechanism Walk through one call of BatchNorm1d.__call__ in training mode and then in inference mode: which statistics are used, what is written back, and what is returned?
    Check
    • training: mean and variance over dim 0 of this batch
    • normalise with sqrt(var + eps), then gamma * xhat + beta, stored in self.out
    • training only: under no_grad, blend the batch stats into running_mean/running_var with momentum
    • inference: use the running buffers and write nothing back
  3. tradeoff You add BatchNorm after every Linear. What does that cost and save in parameters, and why is the Linear bias dropped rather than kept alongside β?
    Check
    • the bias is wasted: BN subtracts the batch mean, which removes any constant added before it
    • per hidden layer: −100 biases, +200 γ/β, so net +100; output layer +27
    • 46,497 → 47,024 (+527), in exchange for normalised preactivations at every layer
  4. mechanism You finish training and sample a name without switching any layer to inference mode. What happens, and exactly why?
    Check
    • each forward is a batch of 1
    • the unbiased variance of one value is undefined, so BN divides by nan
    • the logits are nan, and torch.multinomial raises an error about nan probabilities

4 · Compare against what you already know

vs From neuron to MLP to a training loop: micrograd's Neuron/Layer/MLP classes vs these Linear/BatchNorm1d/Tanh classes: what is the same design idea, what is fundamentally different about what one object represents, and what new kind of state appears here that micrograd never needed?

Check
  • same: each object is callable and exposes .parameters(), so the training loop is generic
  • micrograd: one Value per scalar and one class per neuron; here one class holds a whole weight matrix and processes a batch at once
  • new: buffers and a mode flag, because BatchNorm's output depends on the other examples in the batch
  • micrograd fails by being too slow; these classes fail through wrong-mode bugs

vs BatchNorm at test time: running statistics: That card keeps bnmean_running as a loose tensor updated in the training loop; this card moves it inside BatchNorm1d as a buffer. What does the move buy you, and what new way to fail does it introduce?

Check
  • the layer owns its own statistics, so the loop no longer changes as layers are added
  • switching to inference becomes one flag per layer instead of a separate evaluation function
  • the new failure: forgetting to set training = False, which silently uses batch statistics

vs Embedding, Flatten, Sequential: rebuilding torch.nn: Here the net is a plain Python list and the forward pass is a hand-written loop. What would a Sequential-style container add, and when does a plain list stop being enough?

Check
  • a container is itself a layer: it's callable and collects its children's parameters
  • then you can nest blocks and flip every child's mode in one call
  • a plain list is fine for a flat stack, but awkward once layers need to be grouped or reused

5 · Predict commit to an answer before revealing

Keep BatchNorm after every Linear but change the hidden gain from 1 to 5/3, or even 3. Does the step-0 loss move from 3.2870? Commit to a guess, then run it.

Reveal

It doesn't move: gains 1, 5/3 and 3 all give 3.2870 at step 0. BatchNorm divides each Linear's output by its own batch standard deviation, so multiplying the weights by a constant is cancelled exactly (up to ε). Without BatchNorm the same three gains give 3.2988, 3.2962 and 3.2801. The gain still matters for training, though: it changes the size of the updates, which the update:data ratio card shows.
