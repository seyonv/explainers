Checkpoint 2: BatchNorm, a deep stack, and how to tell it's healthy

Ties together BatchNorm's forward pass, its running statistics, the Linear → BatchNorm → nonlinearity motif, rebuilding torch.nn, activation and gradient histograms and the update:data ratio, with Kaiming init, standardising and the learning-rate finder from earlier. Lecture 4, 0:40:40 to the end.

What this ties together, and why now. The second half of Lecture 4 stops balancing scales by hand. BatchNorm standardises every layer's preactivations on each forward pass, and that has consequences. Examples in a batch now depend on each other, so test time needs fixed statistics. A bias before BN is wasted, so real nets use bias=False. The layers become classes with parameters, buffers and a mode flag, stacked six deep. And you need new instruments to see inside that stack: per-layer histograms for the forward and backward pass, and the update:data ratio for the step size. Karpathy calls training before normalization layers "a total balancing act" (chapter at 1:32:07). This checkpoint checks you can say what BN takes off your hands and what it doesn't.

Comes back from earlier courses: BN is the standardising from the toolkit run down each column. The .parameters() contract is micrograd's Neuron → Layer → MLP on tensors. The update:data ratio is a per-layer reading of the lr you picked in z2h-4's learning-rate finder. Evaluating on the dev split is train/dev/test. And the gain every card here keeps using comes from Kaiming init (checkpoint 1).

How to use this page. Close the cards. Answer each question in writing, in full sentences, before you open its Check. The questions are mixed on purpose and don't say which card they come from, so part of the work is choosing the idea. A wrong or shaky answer points to the exact section to reopen.

1 · Mixed retrieval

  1. You keep the hidden bias b1 and put BatchNorm right after embcat @ W1 + b1. After one loss.backward(), how big is b1.grad, and why? What does ResNet's code do about the same fact, and how many parameters does Linear(30, 200) → BatchNorm1d(200) → Tanh have with and without the Linear's bias?
    Check
    • zero up to float rounding (the lab measures 4.4e-10): adding b1[j] to all 32 rows raises column j's batch mean by exactly b1[j], and BN subtracts that mean right back
    • nothing downstream depends on b1, so it never learns; BN's β (bnbias) does the bias's job
    • every conv in torchvision's resnet.py is built with bias=False for the same reason
    • 30 × 200 = 6,000 weights + 200 γ + 200 β = 6,400; with the useless bias, 6,600

    If you missed it, reopen BatchNorm forward, the "Predict first" answer and "Where it sits in the MLP", and the motif, "The motif inside ResNet-50".

  2. which idea?In the six-layer BatchNorm net you multiply every hidden weight matrix by 0.2 at init. The activation histograms don't change (1.6% saturated), but training is jumpier. Which plot shows the problem, by how much does it move, and why?
    Check
    • the update:data ratio, log10(std(lr·grad) / std(data)), per weight matrix
    • BN divides any weight scale c back out, so the loss can't see c: the gradient scales by 1/c and the data by c, so the ratio moves by 1/c²
    • Δud = −2 · log10 0.2 = +1.40: the first layer goes from −2.81 to −1.41 at step 0, a 25× bigger relative step
    • BN made the forward pass gain-proof, not the step size: a new init needs a new lr

    If you missed it, reopen the update:data ratio, "Why BatchNorm moves the ratio: the 1/c² rule".

  3. Why does BatchNorm take its mean and std down dim 0, over the 32 examples, for each of the 200 units? What does that do to the numbers at step 0, why does it then multiply by a learned γ and add a β, and what does it cost?
    Check
    • each unit (column) gets its own standardisation, like the toolkit's (x − mean)/std: column means −1.82 to +1.97 become 0, stds 0.63 to 2.45 become 1.0000
    • γ and β start at 1 and 0 ("do nothing") and let training move a unit away from unit Gaussian when that lowers the loss: after 200k steps the gains span 0.20 to 3.27
    • the cost: each example's output now depends on its 31 batchmates. The same example gets p(correct) from 0.0121 to 0.0268 in five batches (2.2×)
    • that jitter acts as a regulariser in training, but a deployed model needs one answer per input, so test time needs fixed statistics

    If you missed it, reopen BatchNorm forward, "The formula, one column at a time" and "Why keep a learned gain and bias?"; BatchNorm at test time, "The problem: an example's output depends on its batchmates"; and the toolkit's mean and variance, "Standardising: forcing mean 0, std 1".

  4. debugYou train the six-layer BN net for 1,001 steps, then sample one name at a time. The samples look fine. Then you evaluate on the dev split and get nan. Earlier the same evaluation printed 2.3982. What happened, and what line was missing?
    Check
    • the layers were still in training mode while sampling, so each BatchNorm1d computed a batch variance over one row: x.var(0) divides by n − 1 = 0, which gives nan
    • training mode also runs the EMA update, so that nan was written into running_mean and running_var; the buffers are now nan for good
    • every later eval-mode forward reads those buffers, so the dev loss is nan too. This checkpoint's build reproduces it: nan in running_var of first BN: True
    • missing: for layer in layers: layer.training = False (in torch.nn, model.eval()) before sampling or evaluating. To recover, reload the buffers from a checkpoint or recalibrate them over the training set

    If you missed it, reopen BatchNorm at test time, "The bug everyone hits", and rebuilding torch.nn, "Is this how torch.nn really works?".

  5. Keep the lecture's running statistics but change momentum from 0.001 to PyTorch's default 0.1, still at batch 32. Roughly how many recent batches does each estimate average over, which ends up closer to the true statistics, and would the answer change at a batch of 4,096?
    Check
    • the EMA keeps (1 − m) of the old estimate each step: half-life ln 0.5 / ln 0.999 ≈ 693 steps vs ln 0.5 / ln 0.9 ≈ 6.6 steps
    • a batch of 32 has a noisy mean, so the 0.1 estimate follows the last few noisy batches: 0.0570 average distance from the calibrated mean, vs 0.0076 for 0.001, 7.5× farther
    • with 0.001 the running stats match calibration: val 2.1057 vs 2.1056
    • a large batch has a steadier mean, so the default is fine there; Karpathy lowers it because his batch is small

    If you missed it, reopen BatchNorm at test time, "Option 2: keep a running estimate during training" and "Why momentum 0.001, not PyTorch's 0.1".

  6. which idea?A six-layer tanh stack with no BatchNorm, checked at init: layer 1's activations have std 0.41 and layer 5's have 0.02, and the gradient arriving at layer 1 is 16× smaller than at layer 5. Which instrument did this come from, what is the cause, and what two fixes do you know?
    Check
    • the per-layer activation and gradient statistics (viz #1 and #2): std of each Tanh's .out and .out.grad, with retain_grad()
    • the gain is 0.5: every layer halves the signal going forward and the gradient going back, 0.5⁴ = 1/16 (measured ratio 0.061)
    • fix 1: gain 5/3, tanh's Kaiming gain: act std 0.75 then steady near 0.66, layer-1/layer-5 grad ratio 1.35
    • fix 2: BatchNorm after each Linear: act std 0.63 to 0.65 at gain 1 or 5/3, since BN re-standardises every layer

    If you missed it, reopen activation and gradient histograms, "Viz #2: the same layers, backward" and "With BatchNorm: the forward pass stops caring about the gain".

  7. which idea?You train the BN net at lr 0.001. After 1,000 steps the mean loss is 3.243, barely below where it started, yet the activation and gradient histograms look perfectly healthy. What do you plot, what do you expect to see, and what lr do you try next? How is this different from the way you picked lr in z2h-4?
    Check
    • the update:data ratio: the weight matrices sit at −4.4 to −4.8 and C at −5.70, far below the −3 rule of thumb, so each step changes the weights by about 1/30,000 of their size
    • log10(lr) adds on, so each 10× in lr moves every curve up by exactly 1 at step 0. Try lr 0.1, the notebook's setting: after 1,000 steps it sits at −3.11 … −1.96, with a mean loss of 2.451
    • the histograms check the forward and backward shapes, not the size of the step, so they can't see this
    • z2h-4's finder swept lr by watching one number, the loss. The ratio gives a reading per weight matrix, so it also shows an outlier layer (the last layer is the highest at −1.96)

    If you missed it, reopen the update:data ratio, "The number you track" and "Seven settings of the same 6-layer net", and z2h-4's learning-rate finder, "Step 2: sweep lr in one run".

  8. Take the tanh layers out of the no-BN stack and keep gain 5/3. What happens to the activation std by layer 5, what gain is right for a purely linear stack, and if that fixes it, why keep tanh at all?
    Check
    • nothing squeezes the signal any more, so each layer multiplies the spread by about 5/3: 1.65, 2.72, 4.67, 7.50, 12.78
    • a linear stack needs gain exactly 1 (std 0.97 to 1.01 in every layer): 5/3 only made sense to undo tanh's squeeze
    • six matrices multiply into one (30, 27) matrix (the outputs differ by at most 2.6e-06), so without tanh the stack can only compute a linear function
    • tanh is what buys expressive power; Karpathy notes the training dynamics of a linear stack still differ from one matrix

    If you missed it, reopen activation and gradient histograms, "The fully linear case: remove every tanh", and Kaiming init, "The gain: make up for the nonlinearity".

3 · Build: a deep BN net, checked end to end, then BN folded away

runs on your M3 · about 3 sWhat it reinforces: the layer contract and the 47,024 count (rebuilding torch.nn), BN's forward and its buffers (forward, test time), the per-layer diagnostics (histograms, update:data), and why a bias before BN is redundant (the motif). The last step is Karpathy's exercise E02 for this lecture: fold each BatchNorm into the Linear before it, and check the net still gives the same answers.

  1. Build. Your Linear, BatchNorm1d and Tanh classes; 5 × (Linear(bias=False), BatchNorm1d, Tanh) + (Linear, BatchNorm1d), 100 hidden units, layers[-1].gamma *= 0.1, hidden gain 1 (the notebook's setting), seed 2147483647. Print the parameter count.
  2. Train 1,001 steps at lr 0.1, batch 32, appending the ud list every step and calling retain_grad() on each layer's .out.
  3. Diagnose. For the five Tanh layers after the last step, print act std, % with |t| > 0.97 and grad std. Average each 2-D weight's ud over steps 900 to 1000.
  4. Evaluate. Set training = False on every layer; print train and dev loss, and check that one dev example on its own gives no nan.
  5. Fold. For each Linear → BN pair, s = γ / √(running_var + ε), W′ = W · s, b′ = β − running_mean · s. Run the folded net (Linear with bias, then tanh) on the dev split and compare its logits with the BN net's.
  6. Break it. Switch back to training = True, forward one example, switch to eval, and evaluate dev again.
