Fix 1: make the output layer humble

Also called: fixing the initial loss, "softmax confidently wrong", output-layer init. Lecture 4 · fixing the initial loss · 0:04:19

Prime · 2 minutes before you read

The problem: An untrained network should be unsure about everything. The z2h-4 MLP isn't: its step-0 loss is 27.88, far above the 3.30 of a uniform guess, and the first stretch of training is spent undoing that overconfidence instead of learning names.

Where it fits: The previous card told you what loss to expect at step 0. This is the first of the lecture's init fixes; it reuses softmax and cross-entropy from z2h-4 and touches only the output layer. The next card fixes the hidden layer.

  2. Why does 10× smaller logits not mean a 10× smaller loss?

In one breath: at step 0 the untrained MLP from z2h-4 already produces logits (the raw scores, one per character, that softmax turns into probabilities) in the tens, so it bets about 89% on one arbitrary character and scores a loss of 27.88 instead of the 3.30 of an honest uniform guess. Multiply the output weights W2 by 0.01 and zero the output bias b2: the logits shrink to almost 0, softmax spreads evenly over the 27 characters, and training stops wasting its first thousand steps undoing the bad start.

Predict first: scaling W2 by 0.1 (and zeroing b2) makes every logit 10× smaller. Does the step-0 loss also fall 10×, from 27.88 to about 2.8?

No: it lands at 4.2326. The logit spread does fall exactly 10× (std 12.75 → 1.26), but the loss isn't proportional to it. With big logits the loss is roughly the gap between the top logit and the correct one. Once the logits are small, softmax is nearly uniform and the loss can only settle towards −ln(1/27) = 3.2958; a random init can't do better than that on average, because it doesn't know which character is right yet.

Where the 27 comes from

The output layer is one matrix multiply. Each character's logit adds up 200 terms, one per hidden unit:

logitsj= ∑i=1200hi·s·W2ij200 random-signed terms + b2jbias ⇒ std≈ s·200·E[h2]you control s
hihidden activation i, a tanh output between −1 and 1E[h²] = 0.846 at step 0 W2ijweight from hidden unit i to character j, drawn from N(0, 1) (mean 0, std 1)200 × 27 of them sthe scale you multiply W2 by at init1 → 0.01 b2joutput bias for character j, also N(0, 1) before the fix× 0 after stdstandard deviation: the typical size of a logitmeasured 12.75
s = 1 : std ≈ √(200 × 0.846 + 1) = √170.2 = 13.0 measured 12.75 (the +1 is b2) s = 0.01: std ≈ 0.01 × √(200 × 0.846) = 0.01 × 13.0 = 0.13 measured 0.126

Random signs don't cancel: a sum of 200 random terms grows like √200 ≈ 14. E[h²] is the average of h² over the step-0 batch (computed).

The hockey stick disappears

With the old init, the loss plunges for a few hundred steps and then bends into a slow slope: a "hockey stick". That plunge isn't learning names; it's gradient descent shrinking W2 until the logits are small, which the fix does for free.

Why it beats the alternatives

✗ Keep the init, just train

It gets there, but the first ~1,000 steps go on shrinking logits (mean loss 5.98 vs 2.51). With the same 200k-step budget it ends worse: val 2.1698 vs 2.1311.

✗ Only zero b2

The bias isn't the problem: step-0 loss is 27.9729, no better. The 200 summed h·W2 terms make the huge logits (computed).

✗ Shrink W2 by 0.1

Helps a lot, but logits still span −3.19 to 3.97, the model still bets 25% on its favourite, and the loss is 4.2326: 0.94 above the uniform floor.

✓ W2 × 0.01, b2 × 0

Loss 3.3221, within 0.03 of the ideal 3.2958. The weights stay small but random, so gradients reach W1 and C from step 0.

Why not exactly zero? And when is this not enough?

Zero gives the perfect 3.2958, so why 0.01? Karpathy keeps a small random value "for symmetry breaking". My own check shows what zero costs here: the gradient into h passes through W2, so with W2 = 0 no gradient at all reaches W1 on step 0 (largest W1.grad: 0.0). After one update W2 isn't zero any more, and in this net it recovers: after 20,000 steps val is 2.2073 vs 2.2065. The real trap is zeroing every weight, which the lecture leaves as exercise E01 ("the network trains but only partially").

Not the whole fix. This only tames the output layer. The hidden layer is still broken: 61% of the tanh outputs sit beyond ±0.99, where they barely pass gradient. That's the next card. And uniform isn't always the best start: predicting each character's training-set frequency would score 2.8226 (computed; not done in the lecture), which you'd get by setting b2 to the log of those frequencies.

Understand and remember

  • each logit sums 200 terms h·W2 with random signs → the spread grows like √200 (std 12.75 measured) → softmax puts ~89% on one arbitrary character → the correct one gets ~1e-13 → loss 27.88
  • scale W2 by s → logit std scales by s (12.75 → 0.126 at s = 0.01) → softmax ≈ uniform → loss ≈ −ln(1/27) = 3.30, the best a network that knows nothing can do on average
  • bad init → the first few hundred steps are spent shrinking W2 (the hockey stick) → fewer steps of real learning within a fixed budget → worse final val (2.1698 vs 2.1311)
  • W2 = 0 exactly → the gradient into h is dlogits @ W2ᵀ = 0 → no gradient reaches W1 or C on that step → keep W2 small but random
  • detail that matters zeroing only b2 does nothing useful (27.97): the bias has std 1 while the summed term has std ~13, so the fix must shrink the weights

Reference only

  • the exact constants 0.01 and 0 (any small scale gives a step-0 loss near 3.30)
  • the lab's printed format and the 100-step averaging used for the chart
  • the notebook's loss-log values (2.1245 / 2.1682) vs the torch 2.14 run (2.1268 / 2.1698)
