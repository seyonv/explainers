Activations, gradients and BatchNorm: the course on one page

Without the causal map that joins them, you can retype the code but can't say which fix to reach for when a new net won't train, or why BatchNorm makes some of the earlier fixes unnecessary and not others.

In one breath: a net trains well only if the numbers flowing through it keep a sensible size, forward and backward. The z2h-4 MLP starts with logits so big it is confidently wrong (loss 27.88 instead of ln 27 = 3.2958) and hidden units so big that 61% of its tanh outputs are stuck at ±1. The lecture fixes the scale three ways, each more automatic than the last: by hand, by the rule gain / √fan_in, and by BatchNorm, which simply standardises every layer's preactivations on each forward pass. Then it rebuilds the layers as classes and adds the probes that show whether a deep stack is healthy.

Understand and remember

  • Every unit sums fan_in random terms → with std-1 weights the spread grows by √fan_in per layer → logits of std 12.75 make softmax confidently wrong (27.8817 vs ln 27 = 3.2958) and hpreact of std 5.18 parks 61% of tanh outputs in their flat tails → shrink the output layer (W2 × 0.01, b2 × 0) and scale the hidden one by gain / √fan_in ((5/3)/√30 = 0.3043)
  • tanh's backward multiplies by 1 − t² → near ±1 it passes almost nothing (0.0199 at t = 0.99) → saturated units learn slowly and a unit flat on every example is dead → in a deep stack these gates compound → per-layer histograms must show similar std and few saturated units at every depth (gain 5/3: std ≈ 0.66, about 5%)
  • Init only sets step 0 and depth multiplies any error → BatchNorm standardises each unit over the batch on every forward pass, then γ and β give the freedom back → activations sit at std 0.63–0.65 whatever the gain, and a bias before BN is subtracted away (grad 4.4e-10) → bias=False, the ResNet motif
  • BN's statistics come from the batch → an example's output depends on its batchmates (2.2× swing) and a batch of 1 gives nan → running buffers (EMA, momentum 0.001), updated without gradients and used in eval mode (val 2.1057 vs calibrated 2.1056) → but BN divides out the weight scale, so the gradient scales by 1/c and the update:data ratio by 1/c² → the lr still has to be tuned, read off ud ≈ −3
  • detail that matters Layers written as classes with one contract (__call__, .parameters(), .out, .training) → the net is a list and every probe is a loop over it → a 6-layer, 47,024-parameter stack is as easy to inspect as the one-layer MLP, and the .training flag is where the BN test-time bug lives

  • the chapter timestamps and the loss log (2.1682 → 2.13 → 2.1027 → 2.1070 → 2.1048 in the notebook; the labs measure 2.1698, 2.1311, 2.1027, 2.1070, 2.1057)

3 · Retrieve from memory, card closed
  1. concept Explain to a programmer who knows the z2h-4 MLP why its step-0 loss is 27.88 and not 3.30, and why fixing that alone still leaves the net half broken.
    Check
    • a model that knows nothing should give every character 1/27, a loss of ln 27 = 3.2958
    • each logit sums 200 h·W2 terms with std-1 weights, std ≈ 13, so softmax bets hard on arbitrary characters: confidently wrong
    • W2 × 0.01, b2 × 0 gives 3.3221, but W1 is still std-1, so hpreact has std about 5 and 61% of tanh outputs sit beyond ±0.99
    • the loss reads only the output layer; the hidden layer's saturation needs a histogram of h
  2. mechanism Walk one minibatch through the BatchNorm MLP in training mode and then one example through it in eval mode. At each step, say which statistics are used, which tensors change, and which don't get gradients.
    Check
    • training: hpreact = embcat @ W1 (no b1), then the column mean and std over the 32 rows, standardise, γ·x̂ + β, tanh, W2, loss
    • under no_grad, the running mean and std move 0.1% toward this batch's (momentum 0.001); they are buffers and get no gradient
    • backward fills grads for C, W1, W2, b2, γ, β only; the update moves those
    • eval: the same example uses the running buffers instead of batch stats, so its output no longer depends on batchmates and a batch of 1 works (p(correct) 0.0129 instead of nan)
  3. tradeoff A colleague says: "We use BatchNorm, so init and learning rate don't matter any more." Using this course's measurements, say which half is right and which half is wrong.
    Check
    • right about the forward pass: with BN the activation histograms are the same at gain 1 or 5/3 (std 0.63–0.65, about 2% saturated), and no fan_in scaling still gives healthy activations
    • wrong about the step size: BN divides the weight scale c out, so the gradient shrinks by c and ud moves by −2·log10 c
    • gain 0.2 raises ud by +1.40 (25× bigger steps); no fan_in scaling drops it to −3.74 … −4.19 and needs lr 1.0 to reach about −2.6 … −3
    • so the lr must be re-read from the update:data plot whenever the init changes; and BN brings its own costs (batch coupling, the eval-mode bug)
  4. tradeoff Rank the three instruments in this course (the step-0 loss, per-layer histograms, the update:data ratio) by what each can and can't see, with one failure from the course that only that instrument catches.
    Check
    • step-0 loss: one number, catches a confidently wrong output layer (27.8817 vs 3.2958), blind to the hidden layers
    • histograms of act and grad per layer: catch a wrong gain (0.5 → layer-5 std 0.02, 16× smaller gradient at layer 1) and saturation, but not the step size
    • update:data: catches a step size off by orders of magnitude (lr 0.001 → about −4.5; BN with gain 0.2 → +1.40) and an outlier layer (the last layer), blind to saturation
    • use all three: they are cheap (one forward and backward pass, or one line in the loop)

Why this step?

5 · Predict commit to an answer before revealing

The next course writes every backward pass by hand. Before seeing BN's: for each hidden unit, what should the gradient of the loss with respect to the pre-BN value, summed over the 32 examples of a batch, come out to? Which number in this course already told you?

Reveal

Zero, up to float rounding. Adding the same constant to every row of a column raises the batch mean by exactly that constant, and BN subtracts it again, so the loss cannot change in that direction. The sum over the batch of that gradient is exactly what b1.grad would be, and the batchnorm-forward lab measured b1.grad at 4.4e-10. A hand-written BN backward that doesn't sum to zero per column is wrong: a free check for z2h-6.
