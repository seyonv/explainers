One-hot inputs and a linear layer

Also called: one-hot encoding, a linear (fully connected) layer without bias, xenc @ W. Lecture 2 · feeding integers into neural nets? one-hot encodings · 1:10:01

Prime · 2 minutes before you read

The problem: A neural net can only multiply inputs by weights and add them up. A character index like 13 is a label, not a quantity, so feeding it in raw tells the net that m is 13 times a, which is meaningless.

Where it fits: This is the first step of Part 2, the neural-net version of the bigram model. It reuses the neuron from micrograd (weighted sum of inputs) and matrix multiplication from the toolkit, and replaces the count table's row lookup with a weight matrix W.

In one breath: a neural net can only multiply and add numbers, so a character index like 13 has to become something it can multiply. One-hot encoding turns index 13 into a row of 27 zeros with a single 1 in slot 13. Multiplying a stack of those rows by a 27×27 weight matrix W runs 27 simple neurons on every input at once, in one matrix multiply.

Predict first: (xenc @ W)[3, 13] is a sum of 27 products. How many of those products can be non-zero, and which single number in W does the result equal?

Only one; it equals W[13, 13] = 0.0379 (lab). Row 3 of xenc is the one-hot for m (index 13): 26 zeros and one 1. Every product with a zero vanishes, so the sum is 1 × W[13, 13]. The same holds for all 27 columns: the whole output row is just row 13 of W.

The whole pipeline, for the word 'emma'

Step 1: one word becomes five (input, target) pairs

The counting model read every bigram in one go. A neural net wants a dataset: a list of inputs xs and, for each one, the right answer ys (the target or label). For a bigram, the input is the current character and the target is the character that follows it. Karpathy starts with only the first word, 'emma', so every number stays small enough to read.

Indexes from stoi: '.' = 0, a = 1 … z = 26, so e = 5 and m = 13. The lab prints xs: [0, 5, 13, 13, 1] ys: [5, 13, 13, 1, 0]. Build them with torch.tensor (lowercase), which keeps integers as int64; torch.Tensor (capital T) would turn them into float32.

Step 2: one-hot turns each index into a row of 27

You can't sensibly multiply a weight by "13": the size of an index means nothing, since m isn't 13 times a. So each index gets its own slot instead. F.one_hot(xs, num_classes=27) makes a row of 27 zeros per example and puts a 1 in the slot the index names. Stack the five rows and you have xenc ("x encoded"), shape (5, 27).

The real xenc for 'emma': blank = 0. The two m rows (examples 2 and 3) are identical, because the input is the same character. F.one_hot returns int64, and W will be float32, so add .float(); the lab prints xenc.shape: (5, 27) torch.float32.

Step 3: 27 neurons in one matrix multiply

A neuron here is the simplest kind: it multiplies each of its 27 inputs by its own weight and adds the results. There's no bias and no squashing function like the tanh in micrograd. Put one neuron's 27 weights in a column and you get W of shape (27, 1); xenc @ W then runs that neuron on all five inputs at once and gives shape (5, 1). Use 27 columns and you have 27 neurons, one per possible next character. @ is Python's matrix-multiply operator, and torch.randn fills W with random numbers from a standard normal distribution (mean 0, spread 1). Training will change them later.

import torch
import torch.nn.functional as F
xs, ys = [], []
for w in words[:1]:                    # just 'emma' for now
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        xs.append(stoi[ch1])
        ys.append(stoi[ch2])
xs = torch.tensor(xs); ys = torch.tensor(ys)   # lowercase t
print('xs:', xs.tolist(), 'ys:', ys.tolist())
xenc = F.one_hot(xs, num_classes=27).float()
print('xenc.shape:', tuple(xenc.shape), xenc.dtype)
g = torch.Generator().manual_seed(2147483647)
W = torch.randn((27, 27), generator=g)
out = xenc @ W
print('27 neurons, (xenc @ W).shape:', tuple(out.shape))
print('(xenc @ W)[3, 13] = %.4f' % out[3, 13])
print('(xenc[3] * W[:, 13]).sum() = %.4f' % (xenc[3] * W[:, 13]).sum())

Why it beats the alternatives

✗ Feed the index as a number

With one input x, each output is x · w. The start token . (0) then gets all-zero outputs whatever the weights are, and m's outputs are exactly 13× a's (computed). The net would be stuck with a meaningless ordering.

✗ Leave out num_classes

F.one_hot then guesses the width from the largest index it sees. For 'emma' that's 13, so you get shape (5, 14) (lab), which no longer fits a 27-row W, and the width changes from batch to batch.

✗ Skip .float()

one_hot returns int64 and takes no dtype argument. On torch 2.14, xenc @ W then stops with expected m1 and m2 to have the same dtype, but got: long long != float (computed).

✓ F.one_hot(xs, num_classes=27).float()

Every character gets its own input slot and so its own row of weights, with nothing implied about order. The width is always 27, the dtype matches W, and one @ runs 27 neurons on every example.

Isn't multiplying by 26 zeros wasteful?

Yes. Because each row of xenc has a single 1, row i of xenc @ W is just row xs[i] of W: for 'emma', xenc @ W equals W[xs] exactly (computed). That's 27 × 27 = 729 multiply-adds per example to copy 27 numbers. Karpathy makes this point at 1:47:49, and after training, each character's row of W ends up holding the log of its row in the count table (the training card shows this).

So one-hot times a matrix is the right mental model and fine for 27 characters, but it's not what you'd run at scale. The next lecture replaces it with direct indexing into a table (an embedding lookup). The 27 outputs per example aren't probabilities yet either: they can be negative and don't sum to 1. Turning them into probabilities is the softmax, on the next card.

Understand and remember

  • A neuron multiplies inputs by weights → a raw index would scale the weights by 0, 1 … 26 → '.' always outputs zeros and m is forced to be 13× a → one-hot gives each character its own input slot, so each gets its own independent row of weights
  • Each one-hot row has a single 1 at xs[i] → every product in the sum except slot xs[i] is zero → (xenc @ W)[i] = W[xs[i]] → the layer is a row lookup into W, the same shape of operation as reading row xs[i] of the count table
  • Stacking examples as rows and neurons as columns → (5, 27) @ (27, 27) → (5, 27) → one matmul evaluates 27 neurons on every example in parallel, with the inner 27 (input slots) summed away
  • The output depends only on the current character → identical inputs (the two m's) give identical rows → a bigram net, like the count table, can't use anything earlier than the last character
  • detail that matters F.one_hot returns int64 and guesses the width from the largest index unless you pass num_classes → forgetting .float() makes the matmul fail with a dtype error, and forgetting num_classes gives (5, 14) for 'emma', a width that changes with the batch

Reference only

  • torch.tensor (infers int64) vs torch.Tensor (always float32)
  • torch.randn((27, 27), generator=g) with seed 2147483647
  • import torch.nn.functional as F
  • the exact values W[13, 13] = 0.0379 and xs = [0, 5, 13, 13, 1]

5 · Predict commit to an answer before revealing

Karpathy's bigram model could instead take the two previous characters as input (a trigram). If you one-hot each of them and concatenate the two vectors, what shape is W for 27 outputs, and how many 1s are in each input row?

Reveal

Each input row is 27 + 27 = 54 wide with exactly two 1s, so W is (54, 27). Each output row becomes the sum of two rows of W, one chosen by each character. That's the first step toward the next lecture, where each character's row is looked up and the lookups are joined.
