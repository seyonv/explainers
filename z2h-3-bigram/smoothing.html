Model smoothing with fake counts

Also called: add-one (Laplace) smoothing, add-k smoothing, pseudo-counts. Lecture 2 · model smoothing with fake counts · 1:00:50

Prime · 2 minutes before you read

The problem: 102 of the 729 cells in the count matrix are zero. A model built straight from those counts says those pairs can never happen, so a single unseen pair in a name makes the loss infinite, and the sampler can never produce it.

Where it fits: The last card turned the model's probabilities into one loss number, the average negative log likelihood. This card fixes the one input that breaks that number (a zero probability) before the lecture switches to the neural-net version.

In one breath: 102 of the 729 cells in the count matrix N are zero, so the bigram model says those pairs are impossible. One of them in a name makes the loss infinite. The fix is to pretend every pair was seen k extra times (Karpathy uses N+1): no probability is ever zero again, and the model gets a knob that runs from "trust the counts" to "every letter is equally likely".

Predict first: after switching from N to N+1, does the average loss on the 228,146 training bigrams go down, stay the same, or go up?

It goes up, slightly: 2.4540 → 2.4546. Dividing the raw counts by their row totals already gives the probabilities that fit the training data best, so any change makes the training loss worse. Smoothing buys something the training loss can't see: a finite, sensible loss on names the model has never read, like "andrejq".

Where the infinity comes from

The loss is the average negative log likelihood (NLL): for each bigram, take the model's probability p of the second character given the first, and add up −log p, then divide by the number of bigrams. "andrejq" has 8 bigrams. j appears 2,900 times in names.txt, but never followed by q:

log 0 = −∞, and one infinite term makes the whole sum infinite. With N+1: (1.9835 + 1.8302 + 3.2594 + 2.5646 + 2.0143 + 5.9004 + 7.9817 + 2.3331) / 8 = 27.8672 / 8 = 3.4834. Computed from N; the two averages match the lab.

The fix: add k to every cell

P[i,j] = N[i,j]+k ∑j′N[i,j′]+27k
P[i, j]probability that character j comes next, given character iP[j, q] N[i, j]real count of the pair i→j in names.txtN[j, q] = 0 ∑j′ N[i, j′]row total: how often i is followed by anything2,900 for j kfake counts added to every one of the row's 27 cells, so the total grows by 27k1 in the video
k = 0: P[j, q] = 0 / 2,900 = 0 → −log = ∞ k = 1: P[j, q] = (0 + 1) / (2,900 + 27) = 1 / 2,927 = 0.000342 → −log = 7.98

In code this is one change: P = (N+1).float() instead of P = N.float(), then the same row normalisation as before.

Who pays for the fake counts

Every row gets the same 27·k extra counts, but rows have very different totals. With k = 1, fake counts are 27 / (33,885 + 27) = 0.08% of the 'a' row and 27 / (272 + 27) = 9.0% of the rare 'q' row. So the common rows barely move, and the rare rows get flattened: qu drops from 206 / 272 = 0.7574 to 207 / 299 = 0.6923. Smoothing matters most exactly where the data is thinnest.

▶ Build itruns on your M3 · about 4 s

When: pause the video at 1:00:50, right after "andrejq" comes out as inf. You need words, stoi and the count matrix N from the earlier cards. First wrap your NLL loop in a function:

def avg_nll(P, ws):
    log_likelihood, n = 0.0, 0
    for w in ws:
        chs = ['.'] + list(w) + ['.']
        for ch1, ch2 in zip(chs, chs[1:]):
            p = P[stoi[ch1], stoi[ch2]]
            log_likelihood += torch.log(p).item()  # log 0 = -inf
            n += 1
    return -log_likelihood / n

Then compare no fake counts with one:

for k in [0, 1]:
    P = (N + k).float()              # k fake counts in every cell
    P /= P.sum(1, keepdim=True)      # rows sum to 1 again
    pjq = P[stoi['j'], stoi['q']]
    print(f'fake counts +{k}: P[j,q]={pjq:.6f}  '
          f'andrejq={avg_nll(P, ["andrejq"]):.4f}  '
          f'all words={avg_nll(P, words):.4f}')

You should see (measured on your M3):

How it differs from related ideas

✗ Keep the raw counts

Best possible training loss (2.4540), but any name with an unseen pair, like "andrejq", scores ∞, and the sampler can never produce those 102 pairs.

✗ Skip impossible pairs in the loss

Hides the problem instead of fixing it. The model still claims "jq" can't happen, and the loss now flatters it on exactly the names it handles worst.

✗ Huge k

+100,000 fake counts drown the data: the loss is 3.2837, almost the uniform 3.2958. The model forgets which letters follow which.

✓ A small k (Karpathy: +1)

Every probability stays above zero, the loss on "andrejq" is finite (3.4834), and training loss only rises from 2.4540 to 2.4546.

Is +1 the right amount?

Not necessarily; 1 is just a convenient default. k is a hyperparameter: a setting you choose rather than learn from the counts. You can't pick it on the training loss, because that always prefers k = 0. You pick it on names the counts never saw (a held-out dev set; the MLP lecture sets one up), which is what Karpathy's exercise E03 asks for.

The same knob comes back in the neural net at 1:50:18. Pulling its weights toward zero pulls its output toward uniform, which acts like adding fake counts. That's regularisation, on the train-neural-bigram card.

Understand and remember

  • a pair never seen in names.txt → count 0 → P = 0 → −log P = ∞ → one unseen pair makes the average NLL of the whole name (or dataset) infinite
  • add k to every cell → every P is at least k / (row total + 27k) > 0 → the loss is always finite and every pair can be sampled
  • same 27k added to every row → a tiny share of a big row ('a': 0.08% at k = 1), a big share of a small row ('q': 9.0%) → smoothing mostly reshapes the rare rows, where the counts are least trustworthy
  • raw counts are the best fit to the training data → any k > 0 raises the training loss (2.4540 → 2.4546 at +1) → as k grows each row slides toward uniform (3.2837 at +100,000 vs log 27 = 3.2958) → k must be chosen on data the counts never saw
  • detail that matters Rows are renormalised after adding k (P /= P.sum(1, keepdim=True)) → the denominator grows by 27k, not by k → forgetting that step gives rows that no longer sum to 1

Reference only

  • P = (N+1).float() is the exact line in Karpathy's notebook
  • the names add-one / Laplace / add-k smoothing
  • the video's 2.47 and the notebook's 2.4765 vs the recomputed 2.4546

Reveal

With k = 0 the dev loss is infinite: some dev name contains a pair the train names never had. The best k is small but not zero. In one 80/10 random split (seed 42), dev loss is ∞ at k = 0, 2.4531 at k = 0.1, 2.4530 at k = 0.3, 2.4533 at k = 1 and 2.4627 at k = 10.
