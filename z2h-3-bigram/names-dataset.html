The dataset: 32,033 names

Also called: names.txt, the training set, a character-level corpus. Lecture 2 · reading and exploring the dataset · 0:03:03

Prime · 2 minutes before you read

The problem: A model can't learn from "a file of names" directly. It learns from individual predictions, so before any counting or training you have to decide what one example is. Get that wrong and the model can't start a name, can't stop one, or can only repeat names it has seen.

Where it fits: This is the first card of the bigram lecture. The toolkit gave you Python lists, zip and probability distributions; this card turns names.txt into the (given, next) pairs that every later card counts, samples from and trains on.

In one breath: makemore learns from one text file of 32,033 lowercase names, one per line. The model never sees a name as a whole. It sees bigrams: pairs of (this character, the character that comes next). With a '.' added at each end, a name of length n gives n + 1 of them, so the file holds 228,146 training examples.

Predict first: 'emma' has 4 letters. How many (given, next) examples does it give a bigram model: 3, 4 or 5?

Five. Inside the word there are only 3 pairs (em, mm, ma). The model also has to learn which letter starts a name and when a name stops, so both ends get a '.': .e em mm ma a.. Every name gives len + 1 examples.

One word, five examples

zip(w, w[1:]) → em mm ma 3 = len − 1 zip(chs, chs[1:]) with '.' → .e em mm ma a. 5 = len + 1

zip pairs items up and stops at the shorter input, so zip(w, w[1:]) gives each character with its right-hand neighbour. At 0:06:24 Karpathy pads with <S> and <E>; at 0:20:54 he swaps both for one '.', which this course uses throughout.

Each example predicts one character, so counting examples is counting the characters to predict: every letter plus one ending per name. 196,113 + 32,033 = 228,146.

Why it beats the alternatives

✗ Each whole name is one token

A word-level model can only pick from the 29,494 names it has seen. It can repeat names but never make a new one.

✗ Pairs with no boundary token

zip(w, w[1:]) gives 3 examples for emma, not 5. Nothing teaches which letter starts a name or when to stop, so sampling has no way to begin or end.

✗ Separate <S> and <E> tokens

This works, but it needs 28 tokens. Nothing ever comes after <E> and nothing comes before <S>, so a whole row and column of the count table stay zero.

✓ Characters, padded with one '.'

27 tokens, 228,146 examples, and the model learns starts and ends as ordinary predictions. Any string of letters is possible, so it can invent names.

Is 32,033 the size of the dataset?

Not for this model. The unit a model learns from is one prediction, and here that's a bigram: 228,146 of them, about 7.1 per name. Later models in the series keep this count and give each prediction more context: with 3 characters of context, '...' padding still gives len + 1 examples per name.

Two things this lecture does that you won't do later. It judges the model on the same names it trained on; train / dev / test splits arrive in z2h-4. And a bigram looks at only one previous character, which Karpathy calls "very simple and weak" (0:06:24). That is fine for learning the workflow and poor for making names.

Understand and remember

  • A model learns one prediction at a time → the unit of data is a (given, next) pair, not a name → 32,033 names become 228,146 examples, one per character to predict
  • No boundary token → zip(w, w[1:]) gives only len − 1 inner pairs → nothing teaches which letter starts a name or when to stop → pad with '.' at both ends to get len + 1 pairs
  • Tokens are characters, not whole names → any string of the 26 letters is reachable → the model can invent names instead of only repeating the 29,494 it has seen
  • '.' only ever appears as the given character at a start and as the next character at an end → one token can play both roles → 27 tokens instead of 28, with no always-empty row or column
  • detail that matters Each copy of a repeated name is counted (2,539 names appear twice) → those names' bigrams weigh double in every count and in the loss

  1. concept Explain why the number of training examples for this model is 228,146 and not 32,033.
    Check
    • the model makes one prediction per example
    • each name contributes one prediction per letter plus one for the ending
    • sum of (len + 1) over all names = 228,146
  2. mechanism Walk through what chs = ['.'] + list(w) + ['.'] and zip(chs, chs[1:]) produce for 'ava', and say what each pair teaches the model.
    Check
    • chs = . a v a .
    • pairs: .a av va a.
    • '.a' teaches that names often start with a; 'av' and 'va' teach inner transitions; 'a.' teaches that a name can end after a
    • 4 pairs = len 3 + 1
  3. tradeoff Karpathy first uses separate <S> and <E> tokens, then one '.'. What does each choice cost, and why is it safe to merge them?
    Check
    • two tokens: 28×28 table with a row (after <E>) and a column (before <S>) that are always zero
    • one token: 27×27 and no wasted cells
    • safe because '.' as the given character always means 'start', and as the next character always means 'end'; the two roles never collide
  4. tradeoff Someone proposes a model that treats each whole name as one token. What does it gain and what can it never do?
    Check
    • gain: every output is a real name
    • loss: it can only pick among the 29,494 names it has seen
    • it can't invent a new name, which is the point of makemore

  • Shakespeare is continuous text, so every position in a chunk is an example and there is no per-item boundary
  • bigrams fail by forgetting everything but the last character; chunked text can fail when a chunk starts mid-sentence with no earlier context
