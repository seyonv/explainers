makemore 1: the bigram language model, two ways

The overview for lecture 2 of Zero to hero: read it first as the map, or last as the recap. It ties together the ten bigram cards: counting letter pairs, sampling, scoring with the negative log likelihood, and then training a one-layer net that lands on the same table. Prime · 2 minutes before you read

The problem: Lecture 2 is two hours of small tensor steps that build the same model twice. Read card by card, it is easy to come away with a counting script and a training script and no map of how they connect: which parts define the model, which parts judge it, and why the slower route is the one the series keeps.

Where it fits: The front page of the bigram course. It builds on micrograd's update rule w ← w − lr · ∂L/∂w (lecture 1) and puts all ten bigram cards on one formula: a loss that judges P, and two ways to fill P.

In one breath: a bigram model predicts the next character of a name from the current one alone. Lecture 2 builds it twice. First it counts the 228,146 letter pairs in 32,033 names into a 27×27 table and divides each row by its total. Then it trains a 27×27 weight matrix W by gradient descent, with softmax turning each row into probabilities. Both are graded by one number, the average negative log likelihood, and both meet near 2.45: counting scores 2.4540, and the net climbs down from 3.7590 to 2.4729 in 100 steps. The counting route is exact but can't grow; the neural route is what the rest of the series keeps.

The core formula

Everything in the lecture is one of the two sides of this: the loss (how the model is judged) and P (what the model is). Route 1 fills P by counting; route 2 learns it.

loss=− 1naverage ∑i=1n log⁡P[xi,yi]log of the probability given to each real next character P[x,y]= N[x,y]+k∑jN[x,j]+27kroute 1: count, then normalise the row ≈ eW[x,y]∑jeW[x,j]route 2: softmax of row x of W, learned
nnumber of bigrams scored228,146 (5 for 'emma') xi, yibigram i: the current character and the one that really came next, as indexes ('.' = 0, a = 1 … z = 26).e → (0, 5) Nthe 27×27 count matrix: how often y followed x in names.txtN[e, m] = 769 kfake counts added to every cell (smoothing); 0 means raw counts1 in the lecture Wthe net's only parameters; one_hot(x) @ W is just row W[x], the logits729 numbers eWexp turns each logit into a positive fake count, so W plays log(N + k)e0 = 1
uniform guess, P = 1/27 everywhere : −log(1/27) = 3.2958 route 1, k = 0 : 559,873.59 / 228,146 = 2.4540 route 1, k = 1 : 2.4546 route 2, random W, step 0 : 3.7590 route 2, lr 50, step 99 : 2.4540 + 0.0189 gap = 2.4729 route 2, W set to log(N + 1) : 2.4546

Filled in on all 228,146 training bigrams, from the NLL, smoothing and training cards. 0 would be a perfect model. Neither route can go below 2.4540 on this data: the row-normalised counts are already the table that maximises the likelihood.

Where this sits. Lecture 1 built the update rule w ← w − lr · ∂L/∂w for a hand-made scalar engine (micrograd's training loop). This lecture keeps that rule and adds a dataset, a probability model and a loss for it, on tensors. What it leaves undone is the next lecture's job: a bigram sees one character, counting can't give it more context (a table for 3 characters of context needs 273 = 19,683 rows), and every loss here is measured on the training names. makemore part 2 fixes all three with embeddings, 3 characters of context and a train/dev/test split.

Understand and remember

  • One loss judges every model: average −log P[x, y] over the 228,146 real bigrams → 0 would be perfect and 1/27 everywhere scores log 27 = 3.2958 → the row-normalised counts maximise the likelihood → no bigram model goes below 2.4540 on these names
  • Route 1: count pairs into N → add k to every cell → divide each row by its own total (keepdim) → P; k = 0 leaves 102 zero cells and an infinite loss on unseen pairs, k = 1 fixes it for 2.4540 → 2.4546
  • Route 2: one-hot(x) @ W is row W[x] → softmax exponentiates and normalises it, so W plays log counts → gradient descent on the same loss walks W toward log(N + 1) (3.7590 → 2.4729 in 100 steps, from above)
  • Pulling W toward 0 makes every row uniform → the L2 term 0.01 · mean(W²) does in route 2 what k does in route 1 → both trade training loss for sane probabilities on rare or unseen pairs, so their strength must be tuned on names the model hasn't seen
  • detail that matters Counting needs a table row for every possible context (27ᵏ rows: 19,683 for 3 characters) → it can't grow → route 2 keeps the loss, backward and update and only changes how the logits are computed → the series keeps route 2 even though it is slower and no better here
  • detail that matters Rare rows get gradient only from their own examples (q starts 272 of 228,146) → they converge slowest → after 100 regularised steps the net's P[qu] is 0.3548 where smoothed counts give 0.6923

3 · Retrieve from memory, card closed
  1. concept Using only the core formula, explain why a model that learned nothing scores 3.2958 and why no bigram model can score below 2.4540 on the training names.
    Check
    • learned nothing = P is 1/27 everywhere, so every term is −log(1/27) = log 27 = 3.2958
    • the loss is minimised by the P that maximises the likelihood of the training bigrams
    • for a bigram that P is exactly the row-normalised counts, which score 2.4540, so both routes can only reach it
  2. mechanism Follow the first bigram of 'emma', .e, through both routes to the number it adds to the loss. Name each object and its shape.
    Check
    • route 1: row 0 of N (27 counts, summing to 32,033) → divide by 32,033 → P[0, 5] = 1,531 / 32,033 = 0.0478 → −log = 3.0408
    • route 2: x = 0 → one-hot row of 27 → @ W (27×27) gives the logits W[0] → exp and ÷ row sum → probs[0]
    • with the random W, probs[0, 5] = 0.0123 → −log = 4.3993; training moves it toward the counting value
  3. tradeoff A teammate proposes dropping route 2 from the course: counting is exact, one pass and has no learning rate. What does the course lose, and when are they right?
    Check
    • right for a true bigram: counting reaches 2.4540 exactly; the net only gets to 2.4729 in 100 steps and 2.4624 in 200
    • lost: the loop (forward, backward, update) that stays unchanged when the logits come from an MLP or a transformer
    • counting can't scale: 27ᵏ table rows for k characters of context, most of them empty
  4. tradeoff Both fake counts and the L2 term raise the training loss. How would you choose their strength, and why is the training loss the wrong judge?
    Check
    • on training names the loss always prefers none: k = 0 gives 2.4540, k = 1 gives 2.4546; the L2 net gives 2.4901 vs 2.4729
    • what they buy only shows on unseen names: 'andrejq' goes from ∞ to 3.4834
    • so tune the strength on a held-out dev split (Karpathy's E02 and E03)

5 · Predict commit to an answer before revealing

The next course gives the model 3 characters of context. Commit first: how many rows would a counting table need, and what would its loss on held-out names tell you that this course's 2.4540 can't?

Reveal

27³ = 19,683 rows of 27 cells each, most never seen, so counting is out and the MLP learns an embedding per character instead. A held-out (dev) loss shows whether the model generalises, which a training-set loss can't: the next course splits the names 80/10/10 and its final model reaches about 2.13 on train and 2.17 on dev (notebook values), well below the bigram's 2.45.

6 · Apply use the model, don't restate it

Score both routes with the same line of code. Count N over all 228,146 bigrams, then compute the counting loss vectorised as -P[xs, ys].log().mean() for k = 0 and k = 1. Then treat log(N + 1) as if it were a trained W: pass its rows torch.log((N + 1).float())[xs] as logits to F.cross_entropy with ys. Try log(N) too.

Done when: The vectorised counting loss prints 2.4540 (k = 0) and 2.4546 (k = 1); F.cross_entropy on log(N + 1) rows prints 2.4546 and on log(N) rows 2.4540 (computed on torch 2.14, under 1 s). That is the whole lecture in four numbers: counts as logits are the net's destination.

Hint

log(0) is −∞, but no real training bigram has a zero count, so the log(N) version still gives a finite loss.
