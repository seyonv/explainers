Sampling names from the table

Also called: generating, drawing from a categorical distribution, torch.multinomial. Lecture 2 · sampling from the model · 0:24:02

Prime · 2 minutes before you read

The problem: A count table tells you how often each pair occurred, but it doesn't produce anything. Without a way to turn counts into choices you can't see what the model learned, and you can't make a single new name.

Where it fits: This card follows the 27×27 count table N. The toolkit card on probability distributions showed how to sample from a list of probabilities; here that one draw goes into a loop that feeds each character back in as the next row to read.

In one breath: to make a new name, start at '.', turn that character's row of the count table into probabilities, and let a seeded random draw pick the next character in proportion to them. Then look up that character's row and draw again, until the draw lands on '.', which means "stop".

Predict first: no name in names.txt is shorter than 2 letters. If you sample 1,000 names from the bigram table, how many come out as a single letter: about 0, 10 or 100?

117 of 1,000 (measured). The model only knows the last character. It can pick a first letter from row '.' and then draw '.' from that letter's row, because plenty of real names end in that letter. Adding up P[.c] × P[c.] over all 26 letters gives 0.118, so about 118 per 1,000 (computed).

One row becomes a distribution

Row 0 of the count table N counts which letter each name starts with. Divide each count by the row total and you have a probability distribution: 27 numbers, each at least 0, adding to 1.

Filled in for the first letter a: p(a | '.') = N[0, 1] / N[0].sum() = 4410 / 32033 = 0.1377, the value the lab prints. p('.' | '.') = 0 / 32033 = 0, so an empty name is impossible.

▶ Build itruns on your M3 · about 1.5 s

When: pause the video at 0:24:02 and type this before watching on. It reuses N and itos from the counting card; replacement=True is required, because it defaults to False.

p = N[0].float()
p = p / p.sum()
g = torch.Generator().manual_seed(2147483647)
ix = torch.multinomial(p, num_samples=1, replacement=True,
                       generator=g).item()
print('first draw from row 0:', ix, repr(itos[ix]))
P = N.float()
P /= P.sum(1, keepdim=True)        # every row now sums to 1
def sample(get_p, n=5):
    g = torch.Generator().manual_seed(2147483647)
    names = []
    for i in range(n):
        out, ix = [], 0              # start at '.'
        while True:
            ix = torch.multinomial(get_p(ix), num_samples=1,
                    replacement=True, generator=g).item()
            out.append(itos[ix])
            if ix == 0:
                break
        names.append(''.join(out))
    return names
print('bigram samples :', sample(lambda ix: P[ix]))
print('uniform samples:', sample(lambda ix: torch.ones(27) / 27))

Why it beats the alternatives

✗ Uniform: every character 1/27

Ignores the data. Names average 26 letters, 30 in 1,000 are empty, and they read like sfcxvpubjtbhrmgotzx.. This is the baseline that shows the table learned something.

✗ Always take the most likely (argmax)

Row '.''s top pick is a, and row a's top pick is '.' (0.196). So every name is a., forever (computed).

✗ Replay names from the file

Every output is real, but it can never make a new name, and making more of them is the whole point of makemore.

✓ Draw in proportion to the row

Common continuations come up often and rare ones sometimes, so the names vary but keep the file's letter patterns: average length 6.31 against the real 6.12.

So are these good names?

No, and the sampler isn't the problem. Given an e, the table can't tell whether it's at the start of a name or eight letters in, because a bigram only ever sees the last character. That's why it makes one-letter names that never appear in the data, and names like momasurailezitynn.. In the video the samples are bad for the same reason (one of his is just h), and the uniform ones are worse still.

Every later model in the series keeps this exact sampling loop and only improves where p comes from: a neural net's softmax (end of this lecture), then an MLP, then GPT. The seed fixes the draws for one torch version only, so compare samples against your own lab output, not the video's.

Understand and remember

  • Divide a row of counts by its total → 27 non-negative numbers that sum to 1 → a distribution over the next character → torch.multinomial picks index j with probability p[j]
  • Each draw becomes the next row to read → the name is built one character at a time from only the last character → the loop ends when '.' is drawn, so length is decided by the data's ending counts
  • Only the last character is remembered → the table can't tell a first letter from a fifth → one-letter names (117 in 1,000, while P[.c]·P[c.] summed gives 0.118) and odd strings like 'momasurailezitynn.'
  • Drawing (not argmax) → rare continuations still happen sometimes → varied names that keep the data's statistics (mean length 6.31 vs real 6.12); argmax collapses to 'a.' every time and uniform to 26-letter noise
  • detail that matters The seed fixes the stream of random numbers for one torch version, not the samples forever → torch 2.14 draws 'c' first where the video drew 'm' → compare your output with your own lab, not with the video
  • detail that matters replacement defaults to False → you can't draw more samples than there are categories → Karpathy always passes replacement=True

Reference only

  • torch.multinomial(p, num_samples=1, replacement=True, generator=g).item()
  • g = torch.Generator().manual_seed(2147483647)
  • p['a'] for a first letter = 4410 / 32033 = 0.1377
  • the video's samples: mor., axx., minaymoryles., kondlaisah., anchshizarie.

  1. concept Explain what makes a row of N into something you can sample from, and what property both the counts and the result must have.
    Check
    • divide each count by the row's total
    • every entry is ≥ 0 and the row sums to 1
    • each probability is the fraction of times that character followed the current one
  2. mechanism Walk through the loop from an empty name to the first finished sample: which row is read first, what is appended, and when does it end?
    Check
    • ix starts at 0 ('.'), so row 0 (first letters) is read first
    • multinomial draws an index, and itos[ix] is appended
    • that index selects the next row
    • the loop breaks when the drawn index is 0, and the '.' is kept at the end of the string
  3. tradeoff You could generate by sampling, by argmax, or uniformly. What does each cost you, and which one shows whether the model learned anything?
    Check
    • argmax is deterministic and collapses to one name ('a.')
    • uniform ignores the data: about 26 letters per name and some empty names
    • sampling keeps variety and the data's statistics

Reveal

Only one name, 'a.', every time. Row '.' peaks at 'a' (0.1377), and row 'a' peaks at '.' (0.196), so the loop stops after one letter. Greedy picking throws away all the variety that sampling gives.
