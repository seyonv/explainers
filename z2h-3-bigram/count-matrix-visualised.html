Reading the count matrix

Also called: the bigram table, the imshow heatmap of N. Lecture 2 · visualizing the bigram tensor · 0:18:19, then the single '.' token at 0:20:54

Prime · 2 minutes before you read

The problem: You now hold a 27×27 tensor of 228,146 counts. Printed raw, it is 729 unlabelled integers, so you can't see what the model has learned or spot the cells that will cause trouble later.

Where it fits: It follows the counting card, where N[ix1, ix2] += 1 built the table. Here you learn to read it: which axis is which, what a row means, and why a single '.' token beats <S>/<E>. The next card turns one row into probabilities and samples from it.

In one breath: N is a 27×27 grid of counts. The row is the character you are on, the column is the character that came next, and the cell says how many times that pair appears in the 32,033 names. Read one row and you see everything the data says about "what follows this letter"; the '.' row tells you how names start, and the '.' column tells you how they end.

Predict first: out of all 729 cells, which pair of characters is the most common one in names.txt?

n., with 6,763: a name ending in n. Second is a. (6,640). Four of the top five cells touch the '.' token (n., a., .a, e.); only an (5,438) is two letters. Every name has exactly one start and one end, so those two boundaries pile up counts that pairs inside a name split across many rows.

How to find a cell

A bigram is a pair of neighbouring characters. stoi ("string to index") maps '.' to 0 and a…z to 1…26, and itos maps back. The pair (first, second) lives at N[stoi[first], stoi[second]]: row = first, column = second. Below is a 6×6 excerpt of the real matrix; darker means more pairs.

This row, divided by its total, is exactly the probability table the next card samples from. No cell in the 'e' row is zero: every character has followed 'e' at least once (eq only 14 times).

Rows and columns balance. Every character in a name is counted once as the first of a pair (in its row) and once as the second (in its column), and '.' is counted once per name as start and once as end:

∑jN[i,j] = ∑jN[j,i] = how often character i appears
N[i, j]how many times character i is followed by character je.g. N[e, l] = 3,248 ∑jadd up over every j: a whole row (left) or a whole column (middle)27 cells i = erow total = column total = 'e's in names.txt20,423 i = .row total = column total = number of names32,033

All cells together: N.sum() = 228,146 bigrams. 102 of the 729 cells are zero (14.0%), and 43 more hold a count of exactly 1. The busiest row is 'a' (33,885), not '.'.

Then read it with numbers instead of eyes:

def top(row, name, k=5):
    v, ix = row.float().topk(k)          # 5 largest + where
    return [(name(i.item()), c.item()) for c, i in zip(v, ix)]

e = N[stoi['e']]
print("'e' row, top 5 next chars:", top(e, lambda i: 'e' + itos[i]))
print("'e' row total:", e.sum().item())
print("'.' row (first letters), top 5:",
      top(N[0], lambda i: '.' + itos[i]))
print("'.' column (last letters), top 5:",
      top(N[:, 0], lambda i: itos[i] + '.'))
print('top 5 bigrams overall:',
      top(N.flatten(), lambda i: itos[i // 27] + itos[i % 27]))
print('cells that are zero:', (N == 0).sum().item(), 'of', N.numel())

How it differs from related ideas

✗ Printing the raw tensor

print(N) shows 729 unlabelled integers. You can't tell which cell is "en" without doing the index arithmetic in your head.

✗ A sorted list of counts

The dict version ranks pairs (n. 6,763 first), but it scatters each letter's options across the list, so "what follows e?" is not one place to look.

✗ The 28×28 table with <S> and <E>

Nothing ever follows <E> and nothing comes before <S>, so a full row and column are always zero: 28 + 28 − 1 = 55 wasted cells (157 zeros in all, vs 102).

✓ A labelled 27×27 heatmap

One row per current character, so each row reads as "what comes next". Dark cells jump out, and '.' puts starts and ends in the same grid.

Is a pale cell a rare pair?

Not necessarily. The colour scale is linear up to 6,763, so a cell with 14 looks as white as a cell with 0. The picture can't tell you which pairs are impossible and which are merely rare; (N == 0).sum() can. That difference matters two cards from now: a zero count gives a probability of 0 and an infinite loss.

Don't compare darkness across rows either. Rows have very different totals ('a' 33,885, 'q' only 272), so a dark cell in the 'a' row may be a smaller share than a lighter cell in a rare row. To compare rows you divide each by its own total, which turns the counts into probabilities (the next card).

Understand and remember

  • Counting uses N[stoi[ch1], stoi[ch2]] → the row is the current character and the column is the next one → one row holds everything the data says about "what follows this letter" → dividing a row by its total gives the next-character distribution the model samples from
  • Every name has exactly one start and one end → the '.' row and '.' column each collect 32,033 counts spread over only 26 letters → boundary pairs like n. (6,763) and a. (6,640) top the whole table
  • <E> is never followed by anything and <S> never follows anything → in the 28×28 layout a whole row and column are always zero (55 cells) → one '.' token plays both roles → 27×27 with only N[0,0] structurally zero
  • The colour scale is linear up to 6,763 → a count of 14 looks as blank as 0 → you can't see impossible pairs by eye → check (N == 0).sum() (102), because a zero count later becomes a probability of 0 and an infinite loss
  • detail that matters Each character is counted once as the first of a pair and once as the second → row total = column total = how often it appears (20,423 for 'e'; 32,033 names for '.') → a quick sanity check that your counting loop is right

  • .item() to turn a one-element tensor into a Python int

4 · Compare against what you already know

vs Counting bigrams in a 27×27 tensor: The dict of pair counts and the 27×27 tensor hold the same 228,146 counts. What does the grid layout make easy that the dict does not, and what does it cost?

Check
  • the grid puts all of a letter's successors in one row, ready to normalise and sample
  • it also makes zeros explicit: every one of the 729 possible pairs has a cell
  • the dict stores only pairs that occurred (627 with <S>/<E>) and ranks them easily
  • the grid costs a slot for every possible pair, which is fine at 27×27 and explodes when the context grows (the MLP course)

vs Sampling names from the table: This card reads a row of counts; the sampling card reads a row of probabilities. What changes when you divide by the row total, and what stays the same?

Check
  • the ranking within a row stays the same (e. is still first in the 'e' row)
  • rows become comparable because each sums to 1
  • zeros stay zero, so sampling can never produce an unseen pair

Why this step?

5 · Predict commit to an answer before revealing

The smoothing card adds 1 to every cell before normalising. After that, how many cells of N are zero, and what probability does the model now give to an empty name ('.' right after '.')?

Reveal

No cells are zero any more. N[0,0] becomes 1 and row 0 totals 32,033 + 27 = 32,060, so an empty name gets probability 1/32,060 ≈ 0.0000312: tiny, but no longer impossible. The same fix is what keeps the loss finite for pairs the data never showed.
