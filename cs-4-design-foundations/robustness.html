Robustness

Also called generality, resilience or graceful handling of bad input. The source guide uses the word four ways: an algorithm that handles diverse inputs, a system that keeps working under stress, code that adapts to new requirements, and a proof method that works on many recurrences. Its worked case is a tic-tac-toe winner check.

Prime · 2 minutes before you read

The problem: Code that hard-codes today's case breaks when the input, the load or the requirement moves a little: a 3 × 3 winner check can't do 4 × 4, a missing bounds check quietly wraps rows[-1], and a predictable hash lets crafted keys all collide.

Where it fits: Fourth framing card. Simplicity said to keep each piece to one job; robustness asks how general that job should be, and where to stop. The substitution proof is the same idea for mathematics: a method that works on many recurrences.

In one breath

Robust code keeps giving the right answer when the input, the load or the requirement moves a little. The cheap way to get there: turn hard-coded constants into parameters, reject input you can't handle loudly, and stop adding the moment the general version would cost more than the problem is worth.

Worked example: a winner check for any N × N board

The source: "just because you're asked to write code to check if a tic-tac-toe board has a winner doesn't mean you must assume a 3 × 3 board." Keep one counter per row, per column and per diagonal. X adds +1, O adds −1. A line is won the moment its counter hits ±N.

In Python

class Board:
    def __init__(self, n=3):            # n is a parameter, not a 3
        self.n = n
        self.rows, self.cols = [0] * n, [0] * n
        self.diag = self.anti = 0
        self.taken = set()

    def move(self, r, c, player):
        n = self.n
        if not (0 <= r < n and 0 <= c < n) or (r, c) in self.taken:
            raise ValueError(f"illegal move {(r, c)}")
        self.taken.add((r, c))
        d = 1 if player == "X" else -1
        self.rows[r] += d
        self.cols[c] += d
        if r == c:
            self.diag += d
        if r + c == n - 1:
            self.anti += d
        lines = (self.rows[r], self.cols[c], self.diag, self.anti)
        return player if n in map(abs, lines) else None

# 5 X(2,0) rows=[0, 0, 1] cols=[-1, 1, 1] diag=0 anti=3 -> X wins
# same class, 4 x 4:  8 O(3,3) ... cols=[2, 2, 0, -4] -> O wins
# off-board move: illegal move (3, 0)
# counters == full rescan, 2,000 random games n=1..6: True

Time O(1) per move · Space O(N). A move can only complete the lines that pass through it, and there are at most four; the state is 2N + 2 integers instead of a board to rescan. The bounds check matters: without it, move(-1, 0) would quietly add to rows[-1], the last row, and report a false win later.

The robust proof: substitution

Guess the form of the bound, then prove it by induction and solve for the constant. Here for merge sort's recurrence, guessing T(n) ≤ c·n lg n:

T(n)= 2T(n2)+n ≤ 2cn2lgn2+nguess used for n/2 = cnlgnthe guess −cn+n≤ 0 when c ≥ 1
T(n)steps to solve a size-n problemT(1) = 1 cthe constant the induction lets you choosec = 2 works lglog base 2; lg(n/2) = lg n − 1, which is where −cn comes fromlg 2 = 1
base case T(1) = 1 > c·1·lg 1 = 0 ✗ start at n = 2 instead T(2) = 2·1 + 2 = 4 ≤ c·2·1 → c ≥ 2 check n = 2¹⁰: T = 11,264 ≤ 2 × 10,240 = 20,480 (T / n lg n = 1.100) n = 2²⁰: T = 22,020,096 ≤ 2 × 20,971,520 (ratio 1.050) bad guess T(n) ≤ cn: 2c(n/2) + n = cn + n ≰ cn the +n never goes away

Exactly, T(n) = n lg n + n for powers of two, so the ratio is 1 + 1/lg n and falls toward 1. Numbers from code/robustness.py. The base-case and bad-guess traps are the two CLRS §4.3 warns about.

Why the N × N counters beat the alternatives

✗ Hard-code 3 × 3

Eight explicit lines, easy to read. Asked for 4 × 4, you rewrite it, and a typo in one of the eight goes unnoticed until that exact line wins.

✗ Rescan the whole board

General and simple, but it reads (2N + 2)·N cells every move: 24 at N = 3, 20,200 at N = 100, even though only four lines could have changed.

✗ Solve gomoku instead

k in a row on an unbounded board needs a different design (walk outward from the last move in four directions). Nobody asked; the source says to build the expected case when the general one is a daunting task.

✓ N × N with counters

One parameter instead of a constant, O(1) per move, 2N + 2 integers of state, bad moves rejected. Nothing else in the class mentions 3.

Is the more general version always more robust?

No. The source's own rule: generalise only "without adding excessive complexity". The N × N check qualifies because the parameter costs zero extra lines. A plugin system for board shapes would not. Its closing line is Saint-Exupéry's:

A designer knows he has arrived at perfection not when there is no longer anything to add, but when there is no longer anything to take away.

Robustness also pulls against efficiency. Speed fits in one number ("one program is 2.5× faster", the source's example, not a measurement); robustness doesn't, so it loses arguments it should win. The counters happen to win both here. When they conflict, e.g. a cryptographic hash is slower than a plain one, pay for robustness only where the input can be hostile or the requirement is known to move.

The source's "cryptic pseudorandom functions" means cryptographic ones. Its quote is a popular English paraphrase of Terre des hommes (1939), ch. 3 "L'avion": "la perfection soit atteinte non quand il n'y a plus rien à ajouter, mais quand il n'y a plus rien à retrancher."

Understand and remember

  • A move touches one row, one column and at most two diagonals → keep one counter per line (X +1, O −1) → a win is a counter reaching ±N → O(1) per move for any N, instead of rescanning (2N + 2)·N cells
  • Turn a constant into a parameter → the same class handles 3 × 3 and 4 × 4 → robust to new requirements at zero extra lines; stop where the general version costs more than the problem (gomoku, plugins)
  • Reject illegal input at the boundary → Python's negative indexes can't silently wrap to the last row → a bad move raises instead of causing a false win later
  • Guess the form of the bound → prove it by induction and solve for c → substitution handles recurrences the master theorem can't (unequal splits), but watch the base case and guesses that leave a +n
  • detail that matters Python hashes str with SipHash, a keyed cryptographic function (PEP 456) → an attacker can't precompute colliding keys → robustness under stress, paid for in a slower hash

5 · Predict commit to an answer before revealing

Someone asks for connect-k: win with k in a row on an N × N board, k < N. Will the row/column/diagonal counters still work? Commit, then reveal.

Reveal

No. A counter sums a whole line, so it can't tell k consecutive marks from k scattered ones on a longer line. You need a different design: from the last move, walk outward in four directions and count consecutive marks, O(k) per move. That's the card's "solve gomoku instead" warning: a different problem, not a parameter.
