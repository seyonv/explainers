Averages, expected value and chance

Also called mean, median and mode; expectation or E[X]; false positives and false negatives. The cheat-sheet's estimation page borrows Huff's "How to Lie with Statistics" (a $65K vs $25K neighbourhood), pooled blood tests, chuck-a-luck, the 37% rule and Type I/II errors.

In one breath

"Average" is three different numbers: the mean (total ÷ count), the median (the middle one) and the mode (the most common). On skewed data they disagree, so always ask which one you're being shown. The expected value is the mean of something random: every outcome times its probability, added up. It's how you price a bet or a test plan before you run it.

The source writes chuck-a-luck as ½ − 125/216 without saying why; it is correct. Winnings = matches − 1 when there are none, so by linearity E = E[matches] (3 × ⅙ = ½) − P(no match). Checked by enumerating all 216 rolls.

The spiel says "three chances to win", which sounds like 3 × ⅙ = 50%. You actually win something on 91 of 216 rolls (42.1%), because the three chances overlap, and the doubles and triples don't pay enough to make up for it. Pool size matters too: pools of 50 are far from the best choice when 1 in 100 is sick.

Best pool size for 1% prevalence is 11 (0.1956 tests per person, searched over k = 1…50); 10 is the best size that divides 50 evenly. Pool too large and almost every pool is positive; too small and you pay for the pooled tests.

In Python

from fractions import Fraction as F
from itertools import product
from statistics import mean, median, mode

INCOMES = [16, 16, 16, 16, 18, 20, 22, 25, 26, 28, 30, 32,
           200, 230, 280]                # $K, illustrative

def pooled_tests(n, p):
    if n == 1:
        return 1                         # a pool of one is just a test
    clean = (1 - p) ** n                 # P(pool negative)
    return 1 * clean + (1 + n) * (1 - clean)

def chuck_a_luck():
    total = F(0)
    for dice in product(range(1, 7), repeat=3):   # all 216 rolls
        m = dice.count(1)                          # we bet on 1
        total += m if m else -1
    return total / 216

print(mean(INCOMES), median(INCOMES), mode(INCOMES))
print(f"{pooled_tests(50, 0.01):.2f}", chuck_a_luck())
# → 65 25 16
# → 20.75 -17/216
# simulated, 10**6 plays: -0.0766 (standard error 0.0011)
# secretary n=100: skip 37, best chosen 0.378 of the time

The last two output lines come from seeded simulations in the full file; each is within about 2 standard errors of its exact value (−0.0787; 0.3710 for N = 100). Pooled testing is O(1); the exact chuck-a-luck sum is 6³ = 216 steps, 6d for d dice.

The source's footnotes call a Type I error "a false negative in a search for truth" and a Type II "a false positive": there, the hypothesis is the true claim being sought. In statistics the tested hypothesis is usually the null ("no effect"), which flips the labels: Type I is the false positive. The examples above use that convention.

Why expected value beats the alternatives

✗ Judge by the best case

"Three of your number pays $3!" True on 1 roll in 216. The spiel sells the tail and hides the 125/216 chance of losing.

✗ Judge by the likeliest case

A pool of 50 most often needs just 1 test (60.5%), which makes pools of 50 look great. It ignores the 39.5% that cost 51.

✗ Add up the chances

3 dice × ⅙ = "a 50% chance to win". The events overlap, so the real figure is 91/216 = 42.1%, and even that ignores how much each outcome pays.

✓ Expected value

Weigh every outcome by its chance and its size. One number, −17/216 per $1, says don't play; 20.75 vs 9.78 says use pools of 10.

Should you always go by the expected value?

No. It is the right guide when you repeat the choice many times, like a clinic running thousands of pools or a casino's side of chuck-a-luck. For a one-off decision with a ruinous tail (bet the company, 1 in 216 chance of disaster) the spread matters too: see Kelly and variance. For describing skewed data such as incomes or latencies, report the median and tail percentiles, not the mean.

The same page's other chance examples work the same way. The secretary rule (skip the first N/e ≈ 37%, then take the first one better than all so far) picks the best candidate about 37% of the time (1/e = 0.368 as N grows; exactly 0.371 for N = 100, and a seeded run of 20,000 gives 0.378). A small sample shows "results" by pure luck, which is how Doakes' toothpaste gets its headline: run enough small tests and one will pass.
