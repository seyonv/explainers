In plain words: raise the right word, lower each wrong one by its share

A training step moves each logit against its gradient. So p−yp - yp−y reads as two rules:

  • The right word gets pushed up by 1−p1 - p1−p. At position 2 that is 1−0.0673=0.93271 - 0.0673 = 0.93271−0.0673=0.9327, almost the full amount, because the model nearly missed it.
  • Each wrong word gets pushed down by its own share ppp. mat took 0.7404, so it gets the biggest push. cat took 0.0384 and is barely touched.

A word the model already gets right costs nothing to fix. If ponp_{\text{on}}pon​ were 1, every other ppp would be 0 and the whole row of p−yp - yp−y would be 0.

Why it's this clean: the log undoes the exp

Principle

Pair the output function with the loss that undoes it, and the gradient becomes "prediction minus target"

Softmax's exp and the loss's log cancel. What's left is a gradient that says, word by word, how far the prediction was from the answer. The error p−yp - yp−y is the signal that every weight below will share.

Buys you: a gradient that is exact, costs one subtraction per entry, can't blow up (every entry lies between −1 and 1), and stays well-behaved for huge logits once softmax and log are fused.

Raschka §5.1.2, A.4

Where this simplification breaks
  • The divisor is the number of positions counted. Here it is 3. Real code divides by every position in the batch, and positions marked to be ignored (such as padding, via ignore_index) get a gradient of 0 and don't count in the divisor.
  • yyy doesn't have to be one-hot. With label smoothing, yyy spreads a little weight over every word. The gradient is still p−yp - yp−y with that softer yyy, so it reaches 0 when ppp matches the soft target, and pushes back if the model grows more confident than that.
  • It's clean only for this pair. Softmax followed by some other loss (1−p1 - p1−p, say, from the last card) needs the full Jacobian, and nothing cancels. Its push on the right logit at position 2 was −0.0628-0.0628−0.0628 instead of −0.9327-0.9327−0.9327.
  • Fusing fixes the arithmetic, not the model. In the ×50\times 50×50 test the fused loss was 119.8952, but its gradient was only [0, 0, 0, −1, 1][0,\allowbreak\ 0,\allowbreak\ 0,\allowbreak\ -1,\allowbreak\ 1][0, 0, 0, −1, 1].
