A derivative is a nudge ratio

Slope, rate of change, partial derivative ∂L∂w\frac{\partial L}{\partial w}∂w∂L​, gradient, the chain rule · Raschka A.3, A.4

Prime · 2 minutes before you read

The problem: Training has to decide, for each of the tiny model's 220 weights, which way to turn it and by how much. Without a number that says how the loss responds to each weight, there is nothing to step against, and nudging every weight one by one would cost one forward pass per weight.

Where it fits: The second tools card. It follows the dot-product card and gives the next card, the 6-weight network, its slopes and its chain rule. Every Part 2 backward card is this card's chain rule applied to one more operation.

The tiny transformer has 220 weights, and training has to know, for each one, which way to turn it and how much the loss cares. A derivative answers that with one ratio: change in the loss divided by a small nudge to the weight. The chain rule then lets you get all 220 ratios at once instead of nudging each weight separately.

Try this first

Guess first: the tiny model's loss is 2.2067. Raise the weight W1[0,0]W_1[0,0]W1​[0,0] by 0.001 and the loss drops by 0.000450. If you raise it by 0.01 instead, ten times as far, does the loss drop by exactly ten times as much, a bit more, or a bit less?

Show the answer

A bit more: it drops by 0.004529, not 0.004500. Per unit of nudge that's −0.4529-0.4529−0.4529 instead of −0.4503-0.4503−0.4503. The loss isn't a straight line in this weight; it curves. So the ratio depends slightly on the nudge size, and the derivative is the value it settles on as the nudge shrinks: −0.4500.

This is a partial derivative: you nudge one weight and hold the other 219 still. Do that for every weight and you have the gradient, 220 numbers, one per weight.

The sign says which way, the size says how much

A positive gradient means "increase this weight and the loss goes up". Wout[0,1]\Wout[0,1]Wout​[0,1]'s gradient is +0.2881+0.2881+0.2881, so training lowers it. W1[0,0]W_1[0,0]W1​[0,0]'s is −0.4500-0.4500−0.4500, so training raises it. The size is the exchange rate: nudge W1[0,0]W_1[0,0]W1​[0,0] by 0.001 and the loss moves about 0.45×0.0010.45 \times 0.0010.45×0.001. Of the tiny model's 220 gradients, 111 are positive, 101 negative and 8 exactly 0 (the embedding rows of on and mat, which this input never looks up).

The chain rule multiplies nudge ratios along a path

Nudging works, but it costs one extra forward pass per weight. The chain rule gets the same ratio from the pieces. If xxx moves yyy, and yyy moves LLL, then xxx's effect on LLL is the two ratios multiplied: nudge xxx by 1, yyy moves by dydx\frac{dy}{dx}dxdy​, and each unit of yyy moves LLL by dLdy\frac{dL}{dy}dydL​.

Backprop is the chain rule run once, from the loss back

You could get all 220 gradients by nudging: 220 extra forward passes, each giving an approximate answer. The lab does exactly that, and with ε=0.001\varepsilon = 0.001ε=0.001 the worst of the 220 disagrees with backprop by 0.0007. Backpropagation instead starts at LLL with dLdL=1\frac{dL}{dL} = 1dLdL​=1 and walks the graph in reverse, multiplying by each local slope and adding where paths meet. Every gradient reuses the one computed just before it, so all 220 together cost about as much as two forward passes. That's what loss.backward() does in PyTorch (Raschka A.4).

Principle

Every gradient is local slopes, multiplied along paths and added across them

A derivative is a nudge ratio, measured one weight at a time. The chain rule builds it from the slope of each small operation, so one backward sweep from the loss gives every weight's ratio together.

Buys you: exact gradients for any number of weights at the cost of about one extra pass.

Raschka A.3, A.4; measured in labs/why.py and labs/derivatives-and-chain-rule.py

Where this simplification breaks
  • The slope is local. It describes the curve at the dot only. Over a nudge of 0.1 the ratio is already off by 0.028 (−0.4781-0.4781−0.4781 vs −0.4500-0.4500−0.4500), so a big step can land somewhere the gradient didn't predict.
  • One weight at a time. Each partial assumes the other 219 stay still. Training moves all of them at once, which is fine only for small steps.
  • ReLU has a kink. At exactly 0 it has no single slope; frameworks pick one (PyTorch uses 0).
  • Backprop costs memory. To multiply by local slopes like "xxx for www", the backward pass needs the forward values, so they are all kept until it runs.
