Position is added, or rotated in

Positional embeddings, absolute positions, rotary position embedding (RoPE) · Raschka §2.8

Prime · 2 minutes before you read

The problem: Attention scores are dot products, and a dot product doesn't know where a word sits. Without a position signal, the last word of the cat sat and of cat the sat sees exactly the same thing, so the model can't use word order.

Where it fits: Comes straight after the embedding lookup (x0=E[ids]x_0 = E[\ids]x0​=E[ids]). It is the last thing added before attention, and it sets up the next cards: the scores QK⊤QK^\topQK⊤ are where RoPE does its work.

Needs first: A token becomes a row of a table

Builds on: One operation does almost all the work

You'll meet: learned position table PPP (x0[t]=E[idt]+P[t]x_0[t] = E[\mathit{id}_t] + P[t]x0​[t]=E[idt​]+P[t]) a 2×22 \times 22×2 rotation matrix RoPE: turning each qqq and kkk pair by position × angle relative position (distance) vs absolute position fast and slow pairs (rope_theta)

By the end: Add a position row by hand, rotate a query and key pair and get 0.9101, and explain why the rotated score depends only on the distance between two words.

Attention compares words with dot products, and a dot product doesn't care where a word sits. Without some extra signal, the cat sat and sat cat the are the same bag of words to it. There are two standard fixes: add a learned position vector to each word, or turn each query and key by an angle that grows with position.

Answer two: turn each pair of numbers by position × angle

RoPE (rotary position embedding), used by Qwen and Llama, has no position table. It waits until the query and key vectors exist. Then it splits each one into pairs of numbers and treats each pair as an arrow on a flat plane. The arrow for a word at position mmm is turned by mθm\thetamθ, where θ\thetaθ (theta) is a fixed angle for that pair.

Why. Turning by one angle and then by another is the same as turning by their sum, and turning backwards undoes a turn. A dot product a⋅ba \cdot ba⋅b can be written a⊤ba^\top ba⊤b (the row version of aaa times bbb), and the transpose of a rotation is the rotation the other way. So:

Where the words are in the sentence cancels out; how far apart they are stays. That's the whole point. The model learns "the word just before me matters" once, and it works at position 3 and at position 3,000. The learned table can't do that: P[3]P[3]P[3] and P[3000]P[3000]P[3000] are unrelated rows, each learned separately.

Fast pairs track nearby words; slow pairs track far ones. Pair 0 makes a full turn every 6.3 positions, so it's sharp for "1 or 2 words back" and useless at a distance of hundreds. RoPE goes on Q and K, and nowhere else

Learned positions (GPT-2, the book)

Added once, to x0x_0x0​, at the bottom of the model. Every later layer sees the mixed-in position only through whatever survived.

Costs a T×dT \times dT×d table of weights, and the model can't read past its last row.

RoPE (Qwen, Llama)

Applied in every attention layer, to each head's QQQ and KKK, right before QK⊤QK^\topQK⊤. Not to the embeddings, and not to VVV.

No weights at all. The angles are fixed numbers, so there's nothing to learn and no table to run out of.

Why only QQQ and KKK: position should change which words a token attends to (the scores), not what gets copied over (the values). The scores are where the dot product, and so the cancelling angles, happens.

Principle

Put position where the comparison happens

Attention's only question is "how well does this query match that key?". A learned PPP answers "where am I?" once, at the bottom. RoPE builds position into the comparison itself, so the angles cancel and the score feels only the distance.

Buys you: one learned habit ("look one word back") that works at every position, with no extra weights.

Measured in labs/why.py and labs/positions-rope.py

Where this simplification breaks

  1. Distance only, not content only. The rotated score still depends on what qqq and kkk say. Position enters only through the distance, which is what "relative position" means.
  2. Which numbers get paired. We paired neighbours (0 with 1). The Hugging Face code for Qwen and Llama pairs number iii with number i+32i + 32i+32 instead. The rotation, and the cancelling, are the same.
  3. Order isn't only from positions. With a causal mask, each word sees a different number of earlier words, so a model with no positions can still pick up some order. Our Try-this-first sentence was chosen so the last word sees the same set either way.
  4. Longer than training. RoPE has no table to run out of, but a model trained on short texts has never seen the slow pairs turn far. Going much longer usually needs extra tricks that change the angles. Learned PPP simply has no row for position 1,025 in GPT-2.

Check yourself

1. The tiny model's PPP has 3 rows. What happens if you feed it a 4-token sentence, and would a RoPE model have the same problem?

Show the answer

There's no P[3]P[3]P[3] to add, so the code fails (or you'd have to invent a row). RoPE just turns the fourth word by 3θ3\theta3θ; there's no table. Whether the model behaves well that far is a separate question: it never trained there.

2. With θ=0.5\theta = 0.5θ=0.5, q⋅kq \cdot kq⋅k for positions (7, 6) is 0.9101. What is it for (100, 99), and why don't you need to compute anything?

Show the answer

0.9101. The distance is 1 in both, and the rotation angles subtract: R(−100θ) R(99θ)=R(−θ)R(-100\theta)\,R(99\theta) = R(-\theta)R(−100θ)R(99θ)=R(−θ), the same as R(−7θ) R(6θ)R(-7\theta)\,R(6\theta)R(−7θ)R(6θ).

3. Why is RoPE applied to QQQ and KKK but not to VVV or to the embeddings?

Show the answer

The cancelling only happens inside a dot product between two rotated vectors, and QK⊤QK^\topQK⊤ is the one place attention takes dot products between positions. Rotating VVV would change the content that gets copied, not the scores. Rotating the embeddings would let the turn get scrambled by LayerNorm and the projections before the dot product.

5 · Predict commit to an answer before revealing

Suppose all three rows of the tiny model's PPP were set to the same vector. Would the model now tell the cat sat from cat the sat at the last position?

Reveal

No. Adding the same vector to every word moves them all equally, so the last word still sees the same set of three vectors in either order. Its prediction is identical for both sentences (though not the same numbers as with no PPP). A position signal only helps if it is different at different positions.
