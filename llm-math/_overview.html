Every equation, in the order the data moves

The course map · the math behind Raschka's Build a Large Language Model (From Scratch), chapters 2–5 and appendix A · one tiny model, 220 weights, every number checked against PyTorch

Prime · 2 minutes before you read

The problem: Equations you've only read leave silent gaps: you can nod at softmax⁡(QK⊤/d) V\softmax(QK^\top/\sqrt{d})\,Vsoftmax(QK⊤/d​)V and still not know what number it gives, why the d\sqrt{d}d​ is there, or what loss.backward() computes. Without the whole chain in one order, each equation is an isolated fact and the book's code becomes something you trust rather than understand.

Where it fits: The map for this course. It sits beside Raschka's chapters 2–5 and appendix A, and after the LLM basics route that traced a question through Qwen in words. Here the same route is done in numbers, on one tiny model, forward and then back.

Builds on: How an LLM turns text into an answer

You'll meet: the forward pass as a chain of equations from token IDs to a loss the backward pass as the same stops in reverse, by the chain rule the update W←W−η dWW \leftarrow W - \eta\, dWW←W−ηdW a measured reason for each odd-looking piece (d\sqrt{d}d​, the max trick, residuals, LayerNorm, GELU, Adam)

By the end: Name every stop of one training step in order, with its forward equation, its backward rule and its shape, say which measured problem each piece solves, and know which card to open when one link is shaky.

Reading about attention and backprop doesn't tell you whether you understand them. Doing the arithmetic does. This course gives you every equation a GPT uses, in the order the data flows through it and then back, each worked on the same tiny model with real numbers and a reason for its form. By the end you can run one full training step on paper and match PyTorch to four decimals.

Try this first

Guess first: the tiny model has 220 weights and reads the cat sat. After one backward pass, how many of the 220 weights get a gradient of exactly zero: none, a handful, or about half?

Show the answer

Exactly 8: the embedding rows for on and mat, 4 numbers each. Those two tokens were never looked up, so nothing flowed back to them (card 5). Every other weight touched the loss somewhere along the chain, so each gets some share of the blame. Seeing why takes the whole course: the chain rule, through every stop, in reverse.

Three words first

Forward pass

Run the input through every equation, top to bottom, to get a loss: one number for how wrong the model is. Cards 5 to 12.

Backward pass

Visit the same stops in reverse and work out, for each weight, how much the loss would change if you nudged it. That's its gradient. Cards 13 to 16.

Update

Move every weight a small step against its gradient, so the loss goes down. Then repeat, millions of times. Cards 17 and 18.

The one equation everything serves

W←W−η ∂L∂W W \leftarrow W - \eta\, \frac{\partial L}{\partial W} W←W−η∂W∂L​
WWW
any one of the 220 weights (an entry of EEE, Wq\WqWq​, W1W_1W1​, Wout\WoutWout​, …)
η\etaη
the learning rate: how big a step to take (card 17)
LLL
the loss: the mean of −ln⁡p[t,yt]-\ln p[t, y_t]−lnp[t,yt​] over the 3 positions (card 12)
∂L∂W\frac{\partial L}{\partial W}∂W∂L​
the gradient, written dWdWdW: how much LLL changes per unit nudge of WWW. It has the same shape as WWW (cards 3, 13–16).
Filled in for one weight, at η=1\eta = 1η=1: Wout[1,3]←−0.4−1⋅(−0.6103)=0.2103 \Wout[1,3] \leftarrow -0.4 - 1 \cdot (-0.6103) = 0.2103 Wout​[1,3]←−0.4−1⋅(−0.6103)=0.2103 Do that for all 220 weights at once and the loss goes from 2.20672.20672.2067 to 1.35441.35441.3544.

The forward pass exists to compute L. The backward pass exists to compute every ∂L/∂W. Each card in between is one link in that chain, and the chain rule (card 3) is what lets you multiply the links together.

Principle

If you can't produce the number, you don't understand the equation yet

Reading softmax⁡ ⁣(QK⊤/d)V\softmax\!\big(QK^\top/\sqrt{d}\big)Vsoftmax(QK⊤/d​)V and nodding feels like understanding. Producing 0.9664 from the weights is the test. Each card gives you one entry to compute by hand and the exact answer to compare against, so you find out which link in the chain is shaky before you build on it.

Buys you: no silent gaps. When your own code in chapter 4 gives a wrong shape or a loss that won't fall, you know which equation to suspect.

Words people use

Activation

Any number computed in the forward pass from the input: x0x_0x0​, QQQ, the attention weights AAA, hhh. It changes with every input.

Parameter, weight

A number the model learns and keeps between inputs: the entries of EEE, Wq\WqWq​, W1W_1W1​, Wout\WoutWout​. The tiny model has 220; Qwen2.5-0.5B has 494 million.

Logits

The raw scores z before softmax, one per vocabulary word. They can be any size and any sign.

Gradient, dWdWdW

∂L/∂W\partial L/\partial W∂L/∂W, the loss's sensitivity to one weight, laid out in WWW's shape. Also called "grad"; PyTorch stores it in .grad.

Backprop, backward pass

Computing every gradient in one sweep from the loss back to the input, using the chain rule at each stop.

Autograd

PyTorch doing the backward pass for you: it records each operation in the forward pass and replays their local derivatives in reverse.

Cross-entropy, NLL

The loss −ln⁡p[t,yt]-\ln p[t, y_t]−lnp[t,yt​], averaged over positions. "Negative log-likelihood" is the same thing for one-hot targets.

Perplexity

e to the power of the loss. 5 means as unsure as a uniform guess over 5 words; the tiny model starts at about 9.1.

Jacobian

The full table of how each output of a step changes with each input. Softmax's is 5×55 \times 55×5 per row; you rarely build it, because p−yp - yp−y skips it.

d_model, hidden size

The length of each token's vector: 4 here, 768 in GPT-2, 896 in Qwen.

Learning rate, η\etaη, lr

The step-size multiplier in the update. The book uses 0.0004 with AdamW (§5.2).

Optimizer state

Adam's two extra numbers per weight (m and v), remembered between steps. With the gradient, training stores 4 numbers per weight instead of 1.

What this course simplifies

  1. One block, one head, three tokens. Real models stack 12 or 24 blocks with many heads and train on batches of thousands of tokens. The equations are identical; only the shapes grow. Each card's "At real scale" strip gives the real shapes.
  2. No dropout, no weight decay, no mixed precision. They change training behaviour, not the core equations. The book adds dropout in §3.5 and AdamW's weight decay in §5.2.
  3. Memorising, not learning. 30 Adam steps drive the loss on these 3 tokens to 0.0002, but on text it hasn't seen it gets worse. Generalising needs real data, which is the book's chapter 5.
  4. GPT-2's design, not the newest. The tiny model uses learned positions, LayerNorm and GELU, as the book does. Qwen and Llama use RoPE, RMSNorm and SwiGLU; cards 6, 10 and 11 give their equations too.
  5. Nobody does this by hand at scale. The point of doing it once is to know what autograd computes, so you can debug it, not to replace it.

Check yourself

1. The backward pass visits the stops in reverse. Why can't it go forward, top to bottom like the forward pass?

Show the answer

Each stop's gradient needs the gradient of the stop after it: dWoutdW_{\text{out}}dWout​ needs dzdzdz, and dzdzdz needs ppp and the target. The chain rule multiplies slopes from the loss backward, so the loss end has to be computed first. The forward values (h, A, u, …) are kept from the forward pass because the backward rules use them.

2. The random tiny model's loss is 2.20672.20672.2067, and ln⁡5=1.6094\ln 5 = 1.6094ln5=1.6094. What does that tell you, and what would you expect after training?

Show the answer

Uniform guessing over 5 words scores 1.6094, so the random model is worse than guessing: it's confidently wrong (0.74 on mat when the answer is on). One SGD step brings it to 1.3544, below guessing; 30 Adam steps reach 0.0002, meaning it has memorised the three targets.

3. You remove the residual connections from a 24-layer model and training stalls. Which number in this course predicts that, and why?

Show the answer

The gradient reaching the input drops from 0.3710.3710.371 to 3.52×10−163.52 \times 10^{-16}3.52×10−16 at depth 24. Without the +++, the gradient has to pass through every layer's local slope, and multiplying 24 slopes below 1 makes it vanish. With x + f(x), the + copies the gradient straight past each layer (card 15).

1 · Core model what to internalise, what to just look up

Understand and remember

  • The loss is a chain of functions of the weights → the chain rule multiplies each stop's local slope from the loss backward → one backward sweep gives all 220 gradients at once, for about the cost of two more forward passes
  • Each backward rule needs the activations from its own stop (h for dWoutdW_{\text{out}}dWout​, A for dS) → the forward values must be kept → training memory holds activations as well as weights
  • Repeated multiplications grow or shrink numbers geometrically → std 3.22e35 forward without care, gradient 3.52e-16 back without residuals → small init plus LayerNorm, d\sqrt{d}d​ and the residual each keep one of those products near 1
  • Every weight moves by −η dW-\eta\, dW−ηdW → too big a step overshoots (lr 1.0 bounces to 1.2475, η=10\eta = 10η=10 to ∞\infty∞) and too small crawls (lr 0.01: 0.8542 after 30 steps) → Adam scales each weight's step so small gradients still move
  • detail that matters Softmax followed by −log has the gradient p−yp - yp−y → no Jacobian is ever built at the top → frameworks fuse the two into one cross_entropy call for speed and stability
  • detail that matters The linear rule dW=x⊤dydW = x^\top dydW=x⊤dy sums over positions → the same weight's gradient adds up across every token → longer sequences give each update more signal for the same weights

Reference only

  • the tiny model's sizes: vocab 5, 3 tokens, d_model 4, FFN 8, 220 weights
  • the check numbers: L = 2.2067, S[2,1] = 2.0006, dz[2,3] = −0.3109, dWoutdW_{\text{out}}dWout​[1,3] = −0.6103
  • Raschka sections per card (the table in the overview)
  • GPT-2 and Qwen shapes

Why this step?

5 · Predict commit to an answer before revealing

Suppose the tiny model got a fourth input token. Without running anything, which gradients would get more terms in their sums, and which embedding rows would still get zero gradient?

Reveal

Every dW from the linear rule sums over positions, so each weight matrix's gradient gains a fourth term, and the loss divides by 4 instead of 3. Attention's score grid grows to 4 × 4. Embedding rows still get zero gradient for any token that isn't in the input: if the fourth token were on, only mat's row would stay zero.
