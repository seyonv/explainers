Every token scores every earlier token

Attention scores, queries and keys, scaled dot-product, causal mask · Raschka §3.4.1, §3.5.1

Prime · 2 minutes before you read

The problem: Each token's vector only describes that token. Before it can use the words around it, it needs a number for every other token saying how relevant that token is. And in training, a token that can see the next word will just copy its answer.

Where it fits: Builds on the dot product from One operation does almost all the work and on softmax from card 7. This card makes the scores; the next card turns them into weights with softmax and mixes the values.

A token's own vector says nothing about the words around it. To use its context, each token needs a number for every other token: how useful is that one to me? Attention gets those numbers from one matrix product, QK⊤QK^\topQK⊤, scaled by d,\sqrt{d},d​, with the future blanked out.

One score is one dot product: sat asks, cat answers

Take sat (row 2) asking about cat (row 1). Multiply its query and cat's key number by number, and add. A dot product is big when two vectors point the same way, so a high score means "this key matches what I'm looking for".

Divided by 4=2\sqrt{4} = 24​=2, that's 2.0006. It is the top score in sat's row, beating 0.4570 for the and −2.1253 for sat itself.

Why two matrices and not one? If a token's query and key were the same vector, the grid would be symmetric: the would score cat exactly as cat scores the, and "what I want" would always equal "what I am". Separate Wq\WqWq​ and Wk\WkWk​ let a word go looking for something different from itself, like a verb looking for its subject. Training sets both.

Divide by d\sqrt{d}d​, or one key takes everything

A dot product adds up ddd products. Add more terms and the total swings wider. For random query and key vectors with spread 1 per number, the measured spread (standard deviation) of q⋅kq \cdot kq⋅k is 2.007 at d=4d = 4d=4, 8.005 at d=64d = 64d=64 and 29.898 at d=896d = 896d=896. That tracks d\sqrt{d}d​: 2, 8, 29.93. Dividing by d\sqrt{d}d​ brings the spread back to about 1.00 at every size.

← scroll the sketch →

Measured in labs/why.py. Wide scores make softmax pick one winner. With d=64d = 64d=64 and 10 keys, the top key gets 0.868 of the weight on average unscaled, and 0.324 scaled.

Why is a near-certain winner bad? Softmax's slope is A(1−A)A(1 - A)A(1−A), where AAA is a weight. It is largest at A=0.5A = 0.5A=0.5 and shrinks to 0 near 0 or 1. In one measured unscaled row the top weight was 0.9519, and the slope was at most 0.0458 anywhere in the row. A small slope means a small gradient, so Wq\WqWq​ and Wk\WkWk​ barely learn. The softmax card has the slope; card 16 pushes gradients through it.

Mask the future, because training grades every position at once

One forward pass predicts all three next tokens together: the → cat, cat → sat, sat → on. So the target for position ttt is the input at position t+1t + 1t+1. If token ttt could see t+1,t + 1,t+1, it would be reading its own answer.

Measured in labs/attention-scores.py: without the mask, the would put 0.2416 of its attention on cat, the very word it must predict. Training would reward copying, and at generation time there is no next word to copy. The mask makes training match generation: each token only ever uses what is already written.

Why −∞-\infty−∞ and not 0? Softmax takes eee to the power of each score. e0=1e^0 = 1e0=1, which would still give a later token a share. e−∞=0e^{-\infty} = 0e−∞=0, so the masked cells get exactly 0 weight and the rest of the row still sums to 1.

Principle

A score is a dot product, kept at a sensible size, and only for the past

QK⊤QK^\topQK⊤ scores every pair of tokens in one matrix multiply. Dividing by d\sqrt{d}d​ keeps those scores at spread about 1, so softmax stays soft enough to learn from. The mask keeps each position from seeing its own answer.

Buys you: all positions trained in parallel, with the same rule the model will follow when it writes one token at a time.

Raschka §3.4.1 (scaled scores), §3.5.1 (the causal mask)

Where this simplification breaks
  • One head. The tiny model has one head with d=4d = 4d=4, so dmodeld_{\text{model}}dmodel​ and the head size are the same. Real models split into many heads, and d\sqrt{d}d​ means dhead\sqrt{d_{\text{head}}}dhead​​, with dhead=64d_{\text{head}} = 64dhead​=64 in both GPT-2 and Qwen, not 768\sqrt{768}768​ or 896\sqrt{896}896​.
  • The d\sqrt{d}d​ argument assumes spread 1. It holds for unit-variance qqq and kkk. Trained weights drift from that, which is one reason some newer models also normalise QQQ and KKK.
  • −∞-\infty−∞ is an idea. Code uses -inf or a very large negative number, and fused attention kernels never build the full T×TT \times TT×T grid in memory. The result is the same.
  • Generation is different. When the model writes one new token, its single query only meets earlier keys (cached), so there is nothing to mask. The mask matters most in training and in reading a long prompt.
  • Positions. Here position is already added into aaa. Qwen instead rotates QQQ and KKK (RoPE), so the score depends on distance; see card 6.

  • rows are the asking token, columns the token being scored

  • cells above the diagonal are −∞-\infty−∞ so no position sees a later token, its own target
