Normalise, then add, don't replace

LayerNorm, RMSNorm, residual (skip, shortcut) connections, pre-norm · Raschka §4.2, §4.4

Prime · 2 minutes before you read

The problem: Stack many layers and the numbers flowing through them drift: with N(0,1) weights a vector's spread reaches 3.22e35 after 24 layers, and the gradient reaching the first layers can shrink to 3.52e-16. Deep models need a way to keep each block's input on a fixed scale and to keep a gradient path that doesn't fade.

Where it fits: Comes right after attention produced its output o. It explains the two steps wrapped around every attention and feed-forward call in the block: LayerNorm before the call, and the residual add after it.

Needs first: One operation does almost all the work

Builds on: Attention is a weighted average of values · A token becomes a row of a table · A derivative is a nudge ratio

You'll meet: LayerNorm: mean, variance (divide by D), x̂, γ and β RMSNorm, Qwen's version residual stream: x1 = x0 + o pre-norm placement x + f(LN(x))

By the end: Normalise a row of the tiny model by hand and match tiny.py to 4 decimals, write the pre-norm block as two residual adds, and say with a measured number why each of the two moves is there.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. Why does dividing by σ make LayerNorm blind to the overall size of a row, and what part of the model is still sensitive to size?
  2. Careful initial weights already keep the spread near 1. What does LayerNorm add that initialisation can't?
  3. What exactly does RMSNorm leave out, and on which kind of row would it give the same answer as LayerNorm?
  4. In x1 = x0 + o, which path does the gradient take back to x0, and why does that path not shrink with depth?
  5. Why does the pre-norm block still need a final LayerNorm before the output head?

Stack enough layers and the numbers flowing through them either blow up or shrink to nothing, and the gradient that should train the first layers fades away. Two small moves fix both: rescale each token's vector before a block reads it, and add the block's output to the vector instead of replacing it. This card works both on the tiny model's real rows.

Try this first

Guess first: you multiply every number in x0 by 10 before LayerNorm. Does LayerNorm's output a get 10 times bigger, stay the same, or change shape?

Show the answer

It stays exactly the same. The mean and the spread both grow by 10, and LayerNorm divides one by the other, so the factor cancels. Measured: LN(10 × row 0) = [−0.1255, 0.3765, 1.2549, −1.5059], the same as LN(row 0).

Where this sits

The block reads the embeddings x0 (3 × 4: one row of 4 numbers per token). Before attention, LayerNorm 1 turns x0 into a (still 3 × 4). Attention returns o (3 × 4), and the residual add gives x1 = x0 + o. The same pattern wraps the feed-forward network: LayerNorm 2, then FFN, then x2 = x1 + f. A final LayerNorm turns x2 into h, which goes to the output head.

x0 3×4 → LN1 → a 3×4 → attention → o 3×4 → + → x1 3×4 → LN2 → FFN → f 3×4 → + → x2 3×4 → LNf → h 3×4

LayerNorm gives every token's row mean 0 and spread 1

LayerNorm works on one row at a time, so one token at a time. It finds the row's average (the mean, μ) and how far the numbers typically sit from it (the standard deviation, σ, the square root of the variance σ²). Then it shifts the row so its mean is 0 and stretches it so its spread is 1. Two learned vectors, γ (scale) and β (shift), can then undo as much of that as training finds useful.

μ=1D∑i=1Dxi σ2=1D∑i=1D(xi−μ)2 x^i=xi−μσ2+ε yi=γi·x^i+βi

mu = x.mean(-1); var = ((x - mu)**2).mean(-1); xhat = (x - mu) / sqrt(var + eps); y = gamma * xhat + beta

Filled in, row 0: μ = −0.2000, σ = 0.7969, so a row 0 = [−0.1255, 0.3765, 1.2549, −1.5059]. At step 0, γ = 1 and β = 0, so y = x̂.

All three rows go through the same steps. Their means are [−0.2, −0.075, −0.125] and their σ are [0.7969, 1.1541, 0.6572]. After LayerNorm, each row of a has mean 0.0000 and spread 1.0000.

Why D and not D − 1? Statistics classes divide by D − 1 when they estimate a population's variance from a sample. LayerNorm isn't estimating anything. It just rescales this one row, so it divides by D, as PyTorch's nn.LayerNorm and Raschka's code (unbiased=False) do. With D − 1 you'd get σ = 0.9202 and row 0 = [−0.1087, 0.3260, 1.0868, −1.3041], which won't match PyTorch.

Without a norm, 24 layers turn 1 into 1035

Each layer multiplies its input by a weight matrix. If that tends to make the numbers a little bigger, 24 layers in a row make them enormous. why.py pushes a random vector of 896 numbers (Qwen's width) through 24 random 896 × 896 layers:

Weights drawn fromSpread after layer 12324
N(0, 1)29.38592.63e43.22e35
N(0, 1/d)0.9931.011.011.08

Careful starting weights (variance 1/d) keep things steady, but only at the start. Training then changes the weights however the gradient says. LayerNorm makes every block read a row of spread 1, whatever the weights have become. In the lab for this card, the same 24 N(0, 1) layers with a LayerNorm in front of each: the input to every layer has spread 1, and layer 24's output has spread 30.9, the same size one layer makes, instead of growing layer after layer.

So the later layers always see numbers in the same range. That keeps softmax and GELU out of their flat, saturated zones, and it means one learning rate suits every layer.

RMSNorm: skip the mean, divide by the size

Qwen, Llama and most newer models use RMSNorm (root-mean-square norm). It drops the mean subtraction and the β shift. It just divides the row by its size and multiplies by γ. That's a little cheaper and works as well in practice.

yi=γi·xi1D∑j=1Dxj2+ε

y = gamma * x / sqrt((x**2).mean(-1) + eps)

j

ε
tiny constant against dividing by zero
γ
learned scale, D numbers; starts at 1. There is no β
y
the output row, D numbers
Filled in, row 0: the mean of squares is (0.09 + 0.01 + 0.64 + 1.96) / 4 = 0.6750, the RMS is 0.8216, so y = [−0.3651, 0.1217, 0.9737, −1.7040]. That's not the LayerNorm answer, because the row's mean of −0.2 was never removed.

Add the block's output; never overwrite the row

Attention doesn't hand back a new x. It hands back a correction o, which is added to what was already there. The path that carries x through the model and collects these additions is called the residual stream. This model uses pre-norm placement, as GPT-2 and Raschka's model do: the norm sits inside the branch, before the block, and the stream itself is never normalised.

x1=x0+Attn(LN1(x0)) x2=x1+FFN(LN2(x1))

x1 = x0 + attn(ln1(x0)); x2 = x1 + ffn(ln2(x1)); h = lnf(x2)

x0
embeddings coming in, 3 × 4
LN1, LN2
LayerNorm as above, each with its own γ and β (4 numbers each)
Attn
attention plus its output projection; its result is o, 3 × 4
x1
the stream after attention, 3 × 4
FFN
the feed-forward network (4 → 8 → 4, next card); its result is f, 3 × 4
x2
the stream after the block, 3 × 4; a final LayerNorm turns it into h
Filled in, row 0: [−0.3000, 0.1000, 0.8000, −1.4000] + [−0.7278, 0.2234, −0.0627, 0.5020] = x1 [−1.0278, 0.3234, 0.7373, −0.8980]. Then + [−0.5699, −0.8291, 1.2966, 0.3622] = x2 [−1.5978, −0.5058, 2.0339, −0.5358].

← scroll the sketch →

Row 0 travels along the bottom. Each branch reads a normalised copy, computes a correction (o, then f), and adds it at the +. Going backward, the gradient passes through each + untouched, so it reaches x0 by a direct path as well as through the branches.

Why add: the gradient survives 24 layers

To train the first layer, the gradient (how much the loss changes when a weight is nudged) has to travel back through every layer above it. Each layer multiplies it by its own slope. Many slopes below 1 in a row shrink it to nothing. A residual add has slope 1 along the stream, so there's always one path that isn't shrunk. why.py measures the gradient's size at the input of a stack of tanh layers (width 64):

DepthWithout residualWith residual
41.79e-050.125
243.52e-160.371

Without the add, the first layers of a 24-layer stack get a gradient about 1015 times smaller, so they barely learn. Card 15, The residual is a gradient highway, works this backward pass on the tiny model.

There's a forward reason too. The stream keeps x0, so a block that has learned nothing yet (output near 0) leaves the token's information intact. Each block only has to learn a small change, not rebuild the whole vector.

Show what happened

a is unchanged, so Q, K, V and o are unchanged too: o row 0 is still [−0.7278, 0.2234, −0.0627, 0.5020]. But the stream isn't normalised, so x1 row 0 becomes [−3.7278, 1.2234, 7.9373, −13.4980]. Attention's correction is now small next to the embedding it's added to. The loss rises to 2.7035. LayerNorm protects what each block reads, not what flows along the stream.

At real scale

GPT-2 124M: LayerNorm over rows of 768 numbers, each with its own γ and β of 768. Two per block plus a final one: 12 × 2 + 1 = 25 LayerNorms, and 24 residual adds.

Qwen2.5-0.5B: RMSNorm over rows of 896 (γ only, no β). 24 × 2 + 1 = 49 RMSNorms and 48 residual adds. The 7-token prompt is a 7 × 896 stream, normalised row by row, 7 rows at a time.

Principle

Control the scale of what each block reads, and let each block add rather than rewrite

The norm keeps every block's input in the same range whatever the weights do. The add keeps the original vector and a direct gradient path through the whole depth. Together, they're why you can stack 12 or 24 of the same block and still train the bottom one.

Buys you: depth that trains, with one learning rate for every layer.

Where this simplification breaks
  • γ and β move during training. After training, a block's input no longer has spread exactly 1. It has whatever spread γ learned to give it.
  • The stream grows. Only the branch inputs are normalised. In the tiny model, row 0's spread goes 0.7969 → 0.7622 → 1.3361 from x0 to x1 to x2. With 24 blocks adding to it, the stream can keep growing. That's why there's a final LayerNorm before the output head.
  • Placement matters. The original Transformer put the norm after the add (post-norm). GPT-2 moved it inside the branch (pre-norm), which trains more stably when the model is deep. This card and Raschka use pre-norm.
  • The 1035 experiment is a cartoon. It uses plain matrix multiplies with no nonlinearity and no training. It shows the direction of the problem, not the exact size you'd see in a real model.
  • This isn't BatchNorm. LayerNorm averages over one token's 4 numbers. BatchNorm averages each feature over a batch of examples, so its output depends on the other examples in the batch. LayerNorm's doesn't.

Check yourself

1. Why does LayerNorm give the same output for x and 10 · x?

Show the answer

The mean becomes 10μ and the spread becomes 10σ. Then (10x − 10μ) / 10σ = (x − μ) / σ. Only ε breaks the tie, and it's far too small to see at 4 decimals.

2. RMSNorm of row 0 is [−0.3651, 0.1217, 0.9737, −1.7040], but LayerNorm gives [−0.1255, 0.3765, 1.2549, −1.5059]. Where does the difference come from?

Show the answer

RMSNorm doesn't subtract the mean (−0.2), so it divides the raw row by its RMS, 0.8216. LayerNorm first centres the row, then divides by σ = 0.7969. If a row's mean were 0, they'd agree.

3. If x1 = o instead of x0 + o, what two things are lost?

Show the answer

Forward: the token's own embedding is thrown away and replaced by attention's mix. Backward: the direct gradient path. In a 24-layer tanh stack that's the difference between 3.52e-16 and 0.371 at the input.

Understand and remember

  • LayerNorm subtracts the row mean and divides by the row spread → every row comes out with mean 0 and spread 1 → scaling a row by 10 changes nothing (LN(10 · row 0) = [−0.1255, 0.3765, 1.2549, −1.5059]) → each block reads inputs in the same range whatever the weights have become
  • Without a norm each layer multiplies the spread by its weights' gain → 24 N(0,1) layers take it to 3.22e35 → careful init (N(0,1/d)) holds it near 1 only while the weights stay as initialised → LayerNorm resets it to 1 in front of every block during all of training
  • Residual add x1 = x0 + o → the stream keeps x0 and the block only learns a correction → backward, the + has slope 1 along the stream → the gradient at the input of a 24-layer tanh stack is 0.371 with residuals vs 3.52e-16 without
  • Pre-norm: the norm sits inside the branch, x + f(LN(x)) → branch inputs are normalised but the stream is not → the stream's spread grows (row 0: 0.7969 → 0.7622 → 1.3361) → a final LayerNorm is needed before the output head
  • detail that matters LayerNorm divides by D, not D − 1 (unbiased=False) → with D − 1, row 0 would be [−0.1087, 0.3260, 1.0868, −1.3041] and nothing would match PyTorch
  • detail that matters γ starts at 1 and β at 0 → at step 0 LayerNorm's output is exactly x̂ → training can then learn to undo part of the normalisation per column
