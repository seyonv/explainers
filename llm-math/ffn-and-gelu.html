The bend that makes depth worth having

Feed-forward network, FFN, MLP, position-wise feed-forward, GELU · Raschka §4.3

Prime · 2 minutes before you read

The problem: Attention hands each token a weighted mix of earlier tokens, but a mix is not a new feature. If the block that follows were only matrix multiplies, any number of them would collapse into one matrix, and the extra layers and width would add nothing.

Where it fits: Comes right after attention and the first residual add, and reuses LayerNorm from the norm-and-residual card. Its output f is added back to x1, and then the logits are computed from the result.

Needs first: One operation does almost all the work

Builds on: One operation does almost all the work · Normalise, then add, don't replace · A derivative is a nudge ratio

You'll meet: up and down projections (W1, W2) GELU, the tanh form two linear layers collapse into one slope and dead gradients (ReLU vs GELU) position-wise: one row per token

By the end: Compute one entry of u and its GELU by hand, explain with a measured number why a nonlinearity has to sit between W1 and W2, and say what GELU gains over ReLU in the backward pass.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. Which property of matrix multiplication lets W1 and W2 merge into one 4 × 4 matrix, and what exactly does GELU break?
  2. In GELU's formula, which part acts as a gate between 0 and 1, and what does it do to big negative versus big positive u?
  3. Why does a slope of exactly 0 for negative inputs stop a ReLU unit from learning on that token?
  4. Which shapes in (3 × 4) @ (4 × 8) guarantee that token 2's row can't affect token 0's output?
  5. How does SwiGLU's gate differ from GELU's, given that both widen and then narrow?

Attention gives each token a mix of the tokens before it. Something still has to turn that mix into new features, and a plain matrix multiply can't do much: two of them in a row are the same as one. The feed-forward block widens each token's row, bends it with GELU, and narrows it again, and the bend is what makes the second matrix worth having.

Try this first

Guess first: take GELU out of the block, so the output is LN2(x1) times W1 (4 × 8, 32 weights) times W2 (8 × 4, 32 weights). How many weights would you need to get exactly the same output?

Show the answer

16. Multiply W1 @ W2 once and you get one 4 × 4 matrix that gives the same output, to within 4.4e-16 (rounding noise). The 64 weights were doing a 16-weight job.

Where this sits

Comes in: x1, 3 × 4, the residual stream after attention (one row per token: the, cat, sat). LayerNorm 2 turns it into LN2(x1), also 3 × 4.

This step: up to 3 × 8, bend every number with GELU, down to 3 × 4.

Goes out: f, 3 × 4, which is added back: x2 = x1 + f. Then comes the final LayerNorm and the logits.

Without a bend, two layers are one layer

Matrix multiplication can be regrouped: (x @ W1) @ W2 is the same as x @ (W1 @ W2). So if nothing happens between the two multiplies, you can multiply the weights first and get one matrix.

On the tiny model's real input, two layers and this one matrix differ by at most 4.4e-16: the last digit of floating-point rounding. Stacking them added 48 weights and no new ability. The same holds for 100 linear layers: they still collapse into one matrix.

Put GELU between them and the merged matrix stops working: the outputs differ by up to 1.1481 (entry [0,2]: 1.2966 with GELU, 2.4447 without). A function that isn't a straight line can't be folded into the matrices around it, so each layer can now do something the others can't. That's why stacking blocks, and the hidden width of 8, are worth paying for.

GELU, not ReLU: a smooth bend with no flat half

The blue curve is GELU and the red dashed line is ReLU. The blue dots are row 0 of u after GELU; three of them sit in GELU's small negative dip.

ReLU, max(u, 0), is the simplest bend. GELU (Gaussian error linear unit) is a smooth version of it. The numbers are from why.py:

For big positive inputs the two agree. The difference is on the left. The slope (how much the output moves per nudge of the input) is what the backward pass multiplies by. ReLU's slope is exactly 0 for every negative input, so no gradient gets back through it, and that unit learns nothing from this example. GELU dips slightly below zero (its lowest point is −0.1700 at u = −0.7525) and its slope stays non-zero almost everywhere, so a small gradient still gets through.

In the tiny model, 11 of the 24 numbers in u are negative. With GELU none of the 24 gets a zero gradient. Swap in ReLU and all 11 do (see "Change it" below). The smooth corner at 0 also helps, because the slope changes gradually instead of jumping from 0 to 1.

Each token's row goes through on its own

Look at the shapes again: (3 × 4) @ (4 × 8). Row 0 of u uses only row 0 of the input. GELU works on single numbers. So the FFN treats the three tokens completely separately, with the same weights for each. That's why it's called position-wise.

Measured: add 1 to every number in token 2's input row and rows 0 and 1 of f change by 0.0. Row 2 changes by up to 2.9527.

Attention mixes information between tokens; the FFN transforms each token's own row. A block needs both. The FFN is also where most of each block's weights sit: in GPT-2 it has 4,722,432, about twice the 2,359,296 in attention's four 768 × 768 matrices.

The width. The tiny model goes 4 → 8 → 4, twice as wide in the middle. GPT-2 goes 768 → 3072 → 768, four times as wide, and that 4× is what Raschka builds in §4.3.

By hand (about 3 minutes)

Row 0 of LN2(x1) is [−1.0647, 0.7080, 1.2510, −0.8944]. Column 3 of W1 is [−0.8, 0.4, 0.5, 0.0]. Work out u[0,3]. Then say roughly what GELU does to it: does it shrink a lot, or barely?

Show the answer

(−1.0647)(−0.8) + (0.7080)(0.4) + (1.2510)(0.5) + (−0.8944)(0) = 0.8518 + 0.2832 + 0.6255 + 0 = 1.7605, matching u[0,3].

It's well above zero, so GELU barely shrinks it: GELU(1.7605) = 1.6915 (the tanh part is about 0.92, so the gate lets through 96%).

Change it

Run python labs/ffn-and-gelu.py relu, which swaps GELU for ReLU (it sets ACT = "relu" in the lab). Before you run it, predict: of the 24 hidden numbers in u, how many will get a gradient of exactly zero?

Show the measured result

11 of 24, exactly the 11 entries where u is negative. With GELU it's 0 of 24. For example, u[1,1] = −0.3803 gets a GELU slope of 0.2108, and ReLU's slope there is 0.

The forward pass changes too: with ReLU the starting loss is 2.1644 instead of 2.2067, because the negative entries become 0 instead of about −0.17.

At real scale

Tiny model: LN2(x1) 3 × 4 → u 3 × 8 → f 3 × 4. W1 and W2 plus biases are 76 weights.

GPT-2 124M: 768 → 3072 → 768 in each of its 12 blocks, with GELU in the same tanh form. A 1,024-token context gives u of 1,024 × 3072. Each block's FFN has 768 × 3072 × 2 weights plus biases = 4,722,432.

Qwen2.5-0.5B: SwiGLU instead of GELU, 896 → 4,864 → 896, three matrices and no biases: 3 × 896 × 4,864 = 13,074,432 weights in each of its 24 layers. For the 7-token prompt, the hidden grid is 7 × 4,864.
f=(SiLU(x·Wgate)⊙(x·Wup))·Wdown, where SiLU(z) = z · sigmoid(z) is another smooth bend and ⊙ multiplies entry by entry. One wide copy is bent and used as a gate on a second wide copy, then down narrows the result back to 896.

Principle

Linear layers only add up to something when something non-linear sits between them

Matrix multiplies chain into one matrix, so depth made only of them is an illusion. One cheap function applied to each number, GELU here, breaks the chain. u and f stop being related by a single matrix, and every extra layer can learn something new.

Buys you: a block whose depth and hidden width actually add capacity, plus a gradient that doesn't stop dead at every negative input.

Measured in labs/why.py (4.4e-16 vs 1.1481) and labs/ffn-and-gelu.py (11 of 24 zero gradients under ReLU)

Where this simplification breaks

The formula is an approximation. The tanh form is what GPT-2 and Raschka use. The exact GELU is u times the normal distribution's cumulative probability, and PyTorch's default nn.GELU() computes that one. The two differ only slightly.

GELU isn't immune to small gradients. At its lowest point (u = −0.7525) its slope is 0, and far to the left it's tiny (−0.0116 at u = −3). What it avoids is a whole half of the line where the slope is exactly zero.

Modern models changed the block. Qwen, Llama and most current models use SwiGLU, drop the biases and use RMSNorm. Some replace the single FFN with many "expert" FFNs and a router that picks a few per token. The idea of widen, bend and narrow is the same.

The tiny width is 2×, not 4×, so the numbers fit on a page. Nothing in the math depends on the ratio.

Check yourself

1. A friend makes the FFN deeper: up, up again, down, with no GELU anywhere. Why does that add nothing?

Show the answer

Any chain of matrix multiplies can be regrouped into one matrix (here a 4 × 4). The measured gap between two layers and their merged matrix is 4.4e-16. Only a non-linear function in between breaks that; with GELU the gap is 1.1481.

2. Why does changing token 2's input row leave f's rows 0 and 1 exactly where they were?

Show the answer

Each row of u is one input row times W1, GELU acts on single numbers, and each row of f is one row of GELU(u) times W2. No step looks across rows. Mixing between tokens only happens in attention.

3. u[2,1] = −1.6184. What do GELU and ReLU each pass back to it in the backward pass, and why does it matter?

Show the answer

ReLU's slope there is exactly 0, so the gradient stops and W1's column for that unit learns nothing from this token. GELU's slope is −0.1219, small but not zero, so a little gradient still gets through.

Understand and remember

  • matrix multiply can be regrouped, (x W1) W2 = x (W1 W2) → two linear layers equal one 4 × 4 matrix (gap 4.4e-16) → stacking them adds weights but no ability → a nonlinearity in between breaks the regrouping (gap 1.1481) → depth and hidden width start to count
  • GELU(u) = u × a smooth gate in (0, 1) → big positive u passes almost unchanged (2.7043 → 2.6955), big negative u is pulled close to 0 (−1.6184 → −0.0856) → the bend depends on each number's value, so no fixed matrix can copy it
  • ReLU's slope is exactly 0 for u < 0 → the backward pass multiplies by that slope → those units get zero gradient (11 of 24 in the tiny model) → GELU keeps a small non-zero slope (0.2108 at −0.3803) → every unit still learns a little
  • u's row t uses only input row t, GELU acts on single numbers, f's row t uses only GELU(u)'s row t → tokens never mix inside the FFN (changing row 2 moves rows 0–1 by 0.0) → attention mixes between tokens, the FFN transforms each token's row
  • detail that matters The hidden width (8 here, 3072 in GPT-2, 4,864 in Qwen) is where the bend happens → a wider middle gives more separate bends per token → most of a block's weights sit in the FFN (GPT-2: 4,722,432 vs 2,359,296 in attention)
  • detail that matters SwiGLU: down(SiLU(x·W_gate) ⊙ (x·W_up)) → one copy is bent and used as an entry-by-entry gate on a second copy → three matrices instead of two, and Qwen uses it with no biases

Reference only

  • GELU tanh form: 0.5·u·(1 + tanh(√(2/π)·(u + 0.044715·u³))), with √(2/π) = 0.7979; PyTorch's default nn.GELU() is the exact erf form
  • GELU(−1) = −0.1588 (slope −0.0830), GELU(0) = 0 (slope 0.5), GELU(1) = 0.8412 (slope 1.0830), GELU(3) = 2.9964; lowest point −0.1700 at u = −0.7525
  • Shapes: tiny 4 → 8 → 4 (76 weights with biases); GPT-2 768 → 3072 → 768; Qwen2.5-0.5B 896 → 4,864 → 896 with SwiGLU
  • Notation: u = LN2(x1)·W1 + c1, f = GELU(u)·W2 + c2, x2 = x1 + f

5 · Predict commit to an answer before revealing

The next card multiplies h (3 × 4) by Wout (4 × 5) to get logits, with no bend after it. Could Wout be merged into W2 the way W1 and W2 merged without GELU? Commit before reading on.

Reveal

No. Between W2 and Wout sit the residual add (x2 = x1 + f) and the final LayerNorm, which divides each row by its own standard deviation. That division depends on the row's values, so it isn't a fixed matrix, and the chain can't be regrouped.
