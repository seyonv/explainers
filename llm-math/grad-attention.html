Backprop through attention, three tokens

Attention backward, softmax backward, dQ dK dV, gradients of Wq Wk Wv · no Raschka section (the book leaves this step to autograd)

Prime · 2 minutes before you read

The problem: The loss has a gradient for attention's output, but Wq, Wk and Wv sit behind two matrix products and a softmax. Without walking the gradient back through them, those weights can't learn, and you can't tell why some of them get tiny gradients.

Where it fits: Builds on the linear rule (dW = xᵀ·dy, dx = dy·Wᵀ) from grad-linear-layer and on the forward attention cards (scores, softmax, A·V). It takes do = dx1 from the residual and hands da to LayerNorm 1's backward pass.

Needs first: Let the shapes write the gradient · Attention is a weighted average of values

Builds on: Let the shapes write the gradient · Softmax turns scores into shares · Every token scores every earlier token · Attention is a weighted average of values · The gradient at the top is p − y

You'll meet: dA = dC·Vᵀ and dV = Aᵀ·dC softmax backward: dS = A ⊙ (dA − Σ dA⊙A) dQ = (dS/√d)·K and dK = (dS/√d)ᵀ·Q da as the sum of three paths

By the end: Walk row 2 of the tiny model's attention backward by hand from dC to da, explain why dS row 0 is all 0 and why Wq's gradients are small here, and compute dWq[0,3] = −0.2320 on paper.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. dA row 2 is negative in all three cells, yet dS row 2 has mixed signs: what does the subtraction of Σ dA⊙A do to cause that?
  2. Why does a softmax row with one allowed key send back exactly zero, whatever dA says?
  3. Masked cells have nonzero dA. Which factor in the softmax backward formula kills them?
  4. Why do Wv's gradients come out larger than Wq's on this sentence, and which step does the V path skip?
  5. Why does da have three terms, and why is the Q term exactly zero for token 0?

The loss now has a gradient for o, attention's output. To train Wq, Wk and Wv, that gradient has to get back through a matrix product, a softmax and another matrix product. It is the linear rule at every matrix product, with one softmax step in the middle, and every number fits on this page.

Try this first

Guess first: token the (row 0) is first in the sentence, so the mask lets it attend only to itself. Its attention row is [1, 0, 0]. Will the gradient on its query, dQ row 0, be large, small, or exactly zero?

Show the answer

Exactly zero, [0, 0, 0, 0]. Whatever its query is, a softmax over one allowed key always gives that key 1. Changing the query can't change anything, so the loss doesn't care about it.

Where this sits

Notation, as on every backward card: dX means ∂L/∂X, "how much the loss changes per unit nudge of X". It always has the same shape as X.

Comes in: do, 3 × 4. The residual x1 = x0 + o copies dx1 to both branches, so do = dx1. Row 2 is [0.6984, −0.2800, 0.2120, −0.6303].

This step: walk back through o = C Wo, C = A V, A = softmax(S), S = Q Kᵀ / √d and Q, K, V = a Wq, a Wk, a Wv.

Goes out: dWq, dWk, dWv (each 4 × 4, for the update), and da, 3 × 4, which carries on into LayerNorm 1's backward pass (the norm-and-residual backward card).

Seven lines, the forward pass read backwards

dC = do @ Wo.T; dA = dC @ V.T; dV = A.T @ dC; dS = A * (dA - (dA*A).sum(-1, keepdims=True))

C = A·V hands the blame out two ways

The first step is the plain linear rule from the grad-linear-layer card: o = C Wo, so dC = do · Woᵀ. Row 2 comes out [−0.2716, 0.6220, −0.6947, −0.4978].

C = A V is a matrix product too, but both sides are things that came from the input, not fixed weights. So the rule runs twice, once for each side. Let the shapes guide you: dA must be 3 × 3 like A, and dV must be 3 × 4 like V.

  • dA = dC · Vᵀ. One entry is a dot product: dA[i, j] = dC row i · V row j. It says how much the loss would change if token i listened a little more to token j. Row 2: dA[2,1] = (−0.2716)(1.2391) + (0.6220)(0.8838) + (−0.6947)(1.1633) + (−0.4978)(−0.9358) = −0.1292.
  • dV = Aᵀ · dC. Each value row is blamed by every token that listened to it, in proportion to how much it listened. cat's row gets 0.5021 · dC1 + 0.8132 · dC2 = [−0.1499, 0.4929, −0.6019, −0.4097]. sat's own value was only heard by itself, at weight 0.0131, so dV row 2 is tiny: [−0.0036, 0.0082, −0.0091, −0.0065].

(If you redo these from the 4-decimal values, your last digit can be off by 1. That's rounding, not a mistake.)

Look at dA row 2: [−0.9005, −0.1292, −0.3124]. All three are negative, so it seems listening more to every token would lower the loss. But the weights must sum to 1, so sat can't listen more to everything. The softmax step is what sorts that out.

Softmax backward keeps only the differences

The scores S make the weights through softmax. Raise one score and its share goes up, but every other share in the row goes down to keep the sum at 1. So what matters for a score is not its dA alone, but how its dA compares with the row's average.

That's the formula. For row i: work out the average dA, weighted by the shares, Σₖ dA[i,k] A[i,k]. Subtract it from each dA. Then multiply by the share A, because a token with almost no share barely moves when its score moves.

Now the signs are mixed. the's dA (−0.9005) is far below the average, so its score gets a negative gradient: a step downhill raises sat's score on the. cat's is above the average, so its score goes down. The row sums to −0.1103 + 0.1109 − 0.0006 = 0, and every row of dS does.

Row 0 has one allowed key, so its share is stuck at 1 and dS row 0 is all 0. The arithmetic shows it: Σ = 1 × 0.1010 = 0.1010, and dA − Σ = 0 in the one cell where A isn't 0. Row 1 has two keys, so only the gap between its two dA values counts: 0.4979 × 0.5021 × (0.0549 − 0.0759) = −0.0052, which the full-precision run prints as −0.0053.

Masked cells get 0 too. Their dA isn't 0 (row 0 has 0.1559 and −0.2480 there), but A is 0 there, and the formula multiplies by it.

Then the scores are one more matrix product

Forward, the scores were S = Q Kᵀ / 2. Backward, divide dS by the same 2, then apply the linear rule to both sides once more:

  • dQ = (dS/2) · K. A query's gradient is a blend of the keys it looked at. Row 2: dQ[2,3] = (−0.0551)(1.0165) + (0.0555)(−1.7547) + (−0.0003)(1.0271) = −0.1537. Row 0 is [0, 0, 0, 0], because dS row 0 is all 0.
  • dK = (dS/2)ᵀ · Q. A key's gradient is a blend of the queries that looked at it. Row 0 is [0.0902, 0.1050, −0.0853, 0.0766]: the's query can't learn, but its key can, because cat and sat looked at it.

The three rows of dK add up to zero in every column (0.0902 − 0.0907 + 0.0005 = 0). That follows from the rows of dS summing to 0. In plain terms: adding the same vector to every key raises every score in a row by the same amount, and softmax ignores that, so the loss has no slope in that direction.

Last, each projection gets the linear rule: dWq = aᵀ dQ, dWk = aᵀ dK, dWv = aᵀ dV. And a fed all three, so its gradient is the sum of three paths. For row 2, the path through Q gives [0.1102, 0.0609, −0.0561, 0.0211], through K [0.0006, −0.0007, −0.0002, −0.0002] and through V [0.0033, −0.0082, 0.0018, 0.0070], which add to da row 2 = [0.1142, 0.0519, −0.0546, 0.0279]. For row 0 it's the other way round: the Q path is exactly 0, and K and V carry all of it.

Why Wq barely moves on this sentence

The largest gradient on each projection, from tiny.out:

weightslargest |gradient|path back from dC
Wv0.6413one matrix product (Aᵀ), no softmax
Wk0.2937through softmax and ÷ 2; gets every token's key
Wq0.2320through softmax and ÷ 2; token 0's query gets nothing

Follow the size of the gradient down the Q path. The largest entry of dA is 0.9005. After softmax backward the largest entry of dS is 0.1109, and after ÷ 2 it's 0.0555. Three things shrink it:

  • Row 0 is fixed. One allowed key, so the share is 1 whatever the query. dS row 0 = 0, so dQ row 0 = 0.
  • Row 1 is near 50/50, and both options look about the same to the loss. Its two dA values are 0.0549 and 0.0759. Moving weight from one to the other barely matters, so dS row 1 is only ±0.0053.
  • Only row 2 is left, and the √d scale halves its dS.

Q and K only change the loss by changing the shares, and a share that can't move, or whose options are nearly equal, sends back almost nothing. Wv skips that step: values change the output directly. To check the hand chain, nudge Wq[0,3] by ±0.001 and rerun the forward pass. The loss changes by −0.2320 per unit of nudge, the same as the gradient.

By hand · about 3 minutes

Compute the largest Wq gradient, dWq[0,3]. It's row 0 of aᵀ (that is, column 0 of a) dotted with column 3 of dQ:

  • column 0 of a = [−0.1255, −1.0615, 1.5597]
  • column 3 of dQ = [0.0000, −0.0073, −0.1537]

Which token contributes nothing, and why?

Show the answer

(−0.1255)(0) + (−1.0615)(−0.0073) + (1.5597)(−0.1537) = 0 + 0.0077 − 0.2397 = −0.2320. That matches dWq[0,3] = −0.2320 in tiny.out. Token 0 (the) contributes nothing, because its dQ row is 0. Token 2 does almost all the work.

Change it

In a copy of llm-math/labs/tiny.py, drop the subtraction from the softmax backward. Change

d["S"] = v["A"] * (d["A"] - (d["A"] * v["A"]).sum(-1, keepdims=True))
to d["S"] = v["A"] * d["A"]

Predict first: is dQ row 0 still 0? Does the PyTorch check still agree? And does one SGD step at lr 1.0 still lower the loss?

Show what we measured

dS row 0 becomes [0.1010, 0, 0], so dQ row 0 is no longer 0: [0.0057, −0.0437, 0.0272, 0.0513]. The PyTorch check fails: the largest gradient difference jumps from 5.6e-16 to 6.1e-01. But the SGD step still lowers the loss, 2.2067 → 0.9798, even further than the correct gradient's 1.3544. A loss that goes down on one step doesn't prove the gradient is right. Checking against autograd, or a nudge test, does.

At real scale. GPT-2 124M, in each of 12 layers and each of 12 heads: A, dA and dS are T × T (1,024 × 1,024 at full context), and dQ, dK, dV are T × 64. dWq, dWk, dWv are 768 × 768 each. Qwen2.5-0.5B, on the 7-token prompt, in each of 24 layers: 14 query heads, each with its own 7 × 7 dS. dQ is 7 × 896, but dK and dV are only 7 × 128, because there are 2 key/value heads of 64. Each key/value head was used by 7 query heads, so its gradient is the sum of 7 paths, the same rule that made da a sum of three. dWq is 896 × 896, dWk and dWv are 896 × 128.

Principle

Attention backward is the linear rule, plus one softmax step that only passes differences

Every matrix product sends the gradient back with a transpose. Softmax is the one step that isn't a matrix product: it subtracts the row's average, so the gradient on a score says "more than the others" or "less than the others", never just "more". Wherever a tensor was used more than once, its gradients add.

Buys you: the ability to say, before running anything, which weights will get a small gradient and why: a fixed row or a near-tie sends almost nothing back to the queries and keys.

Where this simplification breaks
  • The tiny model has one head. With many heads, each head runs these lines on its own slice of columns, and the slices are glued back together before Wo.
  • The small Wq gradient is about this sentence and these random weights. With 3 tokens, row 0 always gets nothing; a longer sentence has many more rows that can move.
  • Real code doesn't store A. Fast kernels such as FlashAttention recompute it in blocks during the backward pass to save memory. The maths is the same.
  • Dropout on the attention weights (Raschka §3.5.2) is left out here. With it, the backward pass also multiplies by the same dropout mask.
  • In practice you never write these lines: PyTorch's autograd does it, which is why the book doesn't. The value of doing it once is knowing what autograd is computing.

Check yourself

1. Every row of dS sums to 0. Why must that be true for any softmax?

Show the answer

Adding the same number to every score in a row doesn't change the softmax, so it doesn't change the loss. The slope in that direction is 0, and that slope is the row's sum. Row 2: −0.1103 + 0.1109 − 0.0006 = 0.

2. Why is dV row 2 so much smaller than dV row 1?

Show the answer

dV = Aᵀ dC, so a value row is blamed only by the tokens that listened to it, scaled by how much. Only sat listened to its own value, at 0.0131. cat's value was heard at 0.5021 and 0.8132.

3. Suppose cat's row of A were [0.9, 0.1] instead of near 50/50, with the same dA values (0.0549, 0.0759). Would dS row 1 get bigger or smaller?

Show the answer

Smaller. With two keys, dS = A₀ × A₁ × (dA₀ − dA₁). 0.9 × 0.1 = 0.09, less than 0.4979 × 0.5021 ≈ 0.25. A lopsided row is harder to move. Near 50/50 the slope is as big as it gets; row 1's gradient is small because its two dA values are close.

Understand and remember

  • C = A·V is a product of two input-made matrices → the linear rule runs once per side → dA = dC·Vᵀ (how much listening more to j would change the loss) and dV = Aᵀ·dC (each value is blamed by everyone who listened, in proportion)
  • softmax shares must sum to 1 → raising one score lowers the others → dS = A ⊙ (dA − the row's A-weighted average of dA) → only differences from the average survive, every row of dS sums to 0, and cells with A = 0 (masked or not) get 0
  • row 0 has one allowed key → its share is stuck at 1 → dS row 0 = 0 → dQ row 0 = 0 → token 0's query contributes nothing to dWq; row 1 is near 50/50 with nearly equal dA (0.0549 vs 0.0759) → dS row 1 is only ±0.0053 → only row 2 drives Wq, halved by √d → largest |dWq| 0.2320 vs |dWv| 0.6413
  • S = Q·Kᵀ/√d → divide dS by √d, then dQ = (dS/√d)·K and dK = (dS/√d)ᵀ·Q → Q, K and V were all made from a → da = dQ·Wqᵀ + dK·Wkᵀ + dV·Wvᵀ, the gradients of a reused tensor add
  • detail that matters Rows of dS sum to 0 → columns of dK sum to 0 (0.0902 − 0.0907 + 0.0005 = 0) → adding the same vector to every key shifts every score in a row equally, which softmax ignores, so the loss has no slope that way
  • detail that matters A wrong gradient can still lower the loss for one step: dropping the subtraction gave SGD 2.2067 → 0.9798 while the PyTorch check failed by 6.1e-01 → verify gradients with autograd or a nudge test, not by watching the loss

Why this step?

4 · Compare against what you already know

vs The gradient at the top is p − y: At the top of the model, softmax plus cross-entropy gives the clean p − y. Here softmax backward gives A ⊙ (dA − Σ dA⊙A). Why the difference, and how are they the same rule?

Check
  • both are the softmax backward: share × (incoming gradient − its share-weighted average)
  • at the top the incoming gradient is −1/p at the target and 0 elsewhere, so the formula collapses to p − y
  • here dA comes from dC·Vᵀ, a general vector, so no collapse happens
  • both give rows that sum to 0

vs Let the shapes write the gradient: The linear-layer card has one input and one weight. At C = A·V, and at S = Q·Kᵀ, both sides came from the input. What changes when you apply the rule?

Check
  • the rule runs once for each side: dA = dC·Vᵀ and dV = Aᵀ·dC
  • neither side is a learned weight, so both gradients keep flowing back
  • the learned weights only appear later, at Q, K, V = a·Wq, a·Wk, a·Wv
  • shapes still decide where the transpose goes
