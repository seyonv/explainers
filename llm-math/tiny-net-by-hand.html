Train a 6-weight network on paper

Forward pass, loss, backpropagation, gradient descent, one training step · Raschka A.5, A.7

Prime · 2 minutes before you read

The problem: Every later card computes one piece of a transformer: a forward step, a gradient, an update. Without seeing the whole loop once, those pieces don't add up to "training", and it isn't clear why a backward pass is needed at all.

Where it fits: The last tools card. It uses the dot product from the matmul card and the slopes from the chain-rule card, and runs them as one full training step on a network with 6 weights, before the transformer cards repeat it with 220.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. On the path from L back to a weight in W1, which local slope does each operation contribute, and which one can be exactly 0?
  2. Why does going backward from L let each gradient reuse the one computed just before it?
  3. What does the minus sign in a gradient tell you about which way to move that weight?
  4. Why does W1[1,1] get twice the gradient of W1[1,0], when both feed the same neuron?
  5. With the same correct gradient, why does learning rate 0.5 make the loss worse while 0.1 makes it better?

Training sounds like one big mysterious act, so it helps to see the whole of it once, small enough to check every number. One training step is four moves: run forward, score the answer, send the blame back, nudge every weight. This network has 6 weights, so you can do all four on paper and watch the loss fall from 0.3364 to 0.0819.

Try this first

Guess first: the network has two hidden neurons (small units that each take a weighted sum of the input). On this input, neuron 1's sum comes out at −0.5, and a ReLU (a function that keeps positive numbers and turns negative ones into 0) sits after it. After one backward pass, how many of neuron 1's 2 weights get a gradient that isn't zero?

Show the answer

None. A ReLU with a negative input outputs 0 whatever the weights are, so a small nudge to either weight changes nothing downstream. Its slope there is 0, and every gradient behind it gets multiplied by that 0. Neuron 1's gradients are exactly [0, 0], and the step leaves its weights at [0.5, −0.5].

Filled in, every multiplication:

p1 = 0.5 × 1 + (−0.5) × 2 = 0.5 − 1.0 = −0.5
p2 = 0.3 × 1 + 0.2 × 2 = 0.3 + 0.4 = 0.7
h = ReLU([−0.5, 0.7]) = [0, 0.7]
o = 0.4 × 0 + 0.6 × 0.7 = 0 + 0.42 = 0.42
L = (0.42 − 1)² = (−0.58)² = 0.3364

The answer 0.42 is too small, since we wanted 1. The loss 0.3364 measures how wrong it is. Squaring makes every miss positive, so overshooting is punished as much as undershooting. Training's whole job is to change the 6 weights so this number goes down.

Each gradient is the local slopes multiplied along the path

A gradient dX means dL/dX: if you nudge X up a little, how much does L change per unit of nudge? It has the same shape as X. We want one for each of the 6 weights.

The chain rule says how. Each operation has a local slope: how much its output moves when its input moves, ignoring everything else. To get the gradient of a weight, start at L and multiply the local slopes along the path from L back to that weight.

∂L∂W1[j,k]=2(o−y)⏟dL/do·w2[j]⏟do/dhj·[pj>0]⏟ReLU slope·xk⏟dpj/dW1

plain text: dW1[j,k] = 2*(o - y) * w2[j] * (p[j] > 0) * x[k]; dw2[j] = 2*(o - y) * h[j]

2(o − y)
slope of the loss with respect to o, 1 number. Squared error's slope is twice the miss.
w2[j]
slope of o with respect to h_j: o = w2 · h, so moving h_j by 1 moves o by w2[j]
[p_j > 0]
ReLU's slope: 1 if the neuron's sum is positive (the gate is open), 0 if not (shut)
x[k]
slope of p_j with respect to its weight W1[j,k]: p_j = W1[j] · x, so that weight is multiplied by x[k]
h[j]
for the output weights the path is shorter: o = w2 · h, so the slope of o with respect to w2[j] is h[j]
Filled in, from L backward:

dL/do = 2(0.42 − 1) = 2 × (−0.58) = −1.16
dw2 = −1.16 × h = −1.16 × [0, 0.7] = [0, −0.812]
dh = −1.16 × w2 = −1.16 × [0.4, 0.6] = [−0.464, −0.696]
dp = dh × ReLU slope = [−0.464 × 0, −0.696 × 1] = [0, −0.696]
dW1 row 0 = 0 × [1, 2] = [0, 0]
dW1 row 1 = −0.696 × [1, 2] = [−0.696, −1.392]

← scroll the sketch →

Two paths from L, drawn flat. The top path reaches W1[1,0] through neuron 2's open gate: −1.16 × 0.6 × 1 × 1 = −0.696. The bottom path reaches W1[0,0] through neuron 1, and the shut gate multiplies by 0, so the product stays 0 whatever else is on the path.

Notice the order. dh needed dL/do, and dp needed dh. Going backward, each step reuses the product so far, which is why one backward pass gives all 6 gradients at the cost of about one more forward pass. This is what loss.backward() does in PyTorch, and the lab checks it: PyTorch's gradients match these with a largest difference of 0.0.

A nudge confirms each gradient

A gradient is a prediction: "nudge this weight by a small amount ε (epsilon) and the loss moves by gradient × ε". You can test that directly. Add ε = 0.001 to one weight, run the forward pass again, and divide the change in loss by ε. Measured in labs/tiny-net-by-hand.py:

weightchange in loss ÷ nudgegradient from the chain rule
W1[0,0] (neuron 1, gate shut)0.00000
W1[1,0]−0.6956−0.696
W1[1,1]−1.3906−1.392
w2[1]−0.8115−0.812

The small differences come from the nudge being finite; they shrink as ε shrinks. The nudge needs one extra forward pass per weight; the chain rule gets every gradient from one backward pass. With 6 weights that doesn't matter. With 494 million it decides whether training is possible at all.

The minus signs carry the meaning. A negative gradient says "raising this weight lowers the loss". W1[1,1] has the biggest one (−1.392) because its input x[1] is 2, twice x[0], so it moves p2 twice as much per unit of nudge.

Step against the gradient, and the loss falls

The gradient points uphill: the direction that raises the loss fastest. So the update moves each weight a small step the other way.

Run forward again with the new weights and the answer moves from 0.42 to 0.7139, closer to 1. The loss drops from 0.3364 to 0.0819 after one step. That's the whole loop.

Why 0.1 and not something bigger? The gradient only says which way is downhill right here. Take too big a step and you overshoot. Same gradient, one step, different learning rates (measured in labs/tiny-net-by-hand.py):

At 0.5 the answer jumps past 1 by more than it was short, and the loss ends up more than six times worse than where it started. Picking the step size well is the job of the Step downhill, at the right size card.

A shut gate stays shut

Keep stepping at learning rate 0.1 and the loss keeps falling: 0.3364, 0.0819, 0.0062 after step 2, and 3.6e-09 after step 5. Neuron 2 and w2[1] do all the work. Neuron 1's weights stay at [0.5, −0.5] after 20 steps, with a gradient of exactly 0 every time, because its sum is −0.5 every time.

ReLU's slope is a gate: open, it passes the gradient through unchanged; shut, it passes nothing. A neuron whose gate is shut on every input never learns. People call that a dead ReLU. Here it's harmless, since one neuron was enough. In a big network it's wasted capacity, and it's one reason transformers use smoother functions such as GELU, whose slope at −1 is still −0.0830 rather than 0 (why.out).

Do it by hand · about 3 minutes

Run the forward pass again with the updated weights: W1 = [[0.5, −0.5], [0.3696, 0.3392]], w2 = [0.4, 0.6812], x = [1, 2], y = 1. Find p, h, o and L. Did the loss go down?

Show the answer

p1 = 0.5 × 1 + (−0.5) × 2 = −0.5, so h1 = 0 (the gate is still shut).
p2 = 0.3696 × 1 + 0.3392 × 2 = 0.3696 + 0.6784 = 1.048, so h2 = 1.048.
o = 0.4 × 0 + 0.6812 × 1.048 = 0.7139.
L = (0.7139 − 1)² = (−0.2861)² = 0.0819. Down from 0.3364, matching tiny_net.out.

One notation change: here a layer is W1 @ x, with one row of W1 per neuron, as in tiny_net.py. The transformer cards put one token per row and write x @ W, with W shaped (in, out). It's the same multiplication, transposed.

GPT-2 124M: the same four moves update about 124 million weights per step, through 12 layers of width 768, and the loss is cross-entropy over 50,257 tokens.

Qwen2.5-0.5B: 494,032,768 weights, 24 layers of width 896. Its feed-forward layers are the same "weights times input, then a bend" as W1 x and ReLU here, mapping 896 numbers up to 4,864.

Principle

A gradient is a product of local slopes, and one backward pass finds them all

Every operation knows its own slope. Multiply them along the path from the loss back to a weight and you get that weight's gradient. Go backward and each product is reused, so all the gradients cost about one extra pass. Then step each weight a little against its gradient.

Buys you: a recipe that works the same for 6 weights or 494 million.

Raschka A.5, A.7; measured in labs/tiny_net.py and labs/tiny-net-by-hand.py

Where this simplification breaks
  • One example, not a batch. Real training averages the loss over a batch of examples, so each gradient is an average too. Raschka's training loop in A.7 loops over batches.
  • No biases. Each neuron here is a plain weighted sum. Real layers add a learned bias (nn.Linear has one by default), and a bias's gradient is just dp, because its local slope is 1.
  • Gradients add up in PyTorch. loss.backward() adds into .grad instead of overwriting it, so a real loop calls optimizer.zero_grad() every step.
  • Squared error isn't the LLM loss. A language model picks one of many tokens, so it uses cross-entropy, covered in The loss is surprise at the right answer.
  • The loss reaching 0 is memorising. With one example and 6 weights the network can fit it exactly by step 5. That says nothing about new inputs.

Check yourself

1. dh1 is −0.464, not zero. So why are both of neuron 1's weight gradients exactly 0?

Show the answer

Between h1 and the weights sits the ReLU, and its input p1 = −0.5 is negative, so its slope is 0. dp1 = −0.464 × 0 = 0, and each weight gradient is dp1 × x[k] = 0. The loss does care about h1, but no small change to these weights can move h1.

2. Suppose the target were y = 0.42 instead of 1. What would all 6 gradients be, and why?

Show the answer

All 0. Every path starts with dL/do = 2(o − y) = 2(0.42 − 0.42) = 0, and every gradient is that number times other slopes. A perfect answer gives nothing to correct.

3. With learning rate 0.5 the loss went from 0.3364 to 2.1160. The gradient was correct. What went wrong?

Show the answer

The step was too big. The gradient only describes the slope where you stand. Following it 5 times further than lr 0.1 pushed o to 2.4546, missing 1 by 1.4546 instead of 0.58, so the loss rose.

Understand and remember

  • Each operation has a local slope → the chain rule multiplies them along the path from L to a weight → dW1[j,k] = 2(o − y) · w2[j] · [p_j > 0] · x[k] → one backward pass, reusing each product, gives all 6 gradients
  • ReLU's slope is 1 when its input is positive and 0 when not → a neuron with a negative sum multiplies every gradient behind it by 0 → its weights don't move → if that holds on every input the neuron never learns (dead ReLU)
  • The gradient points uphill only where you stand → step w ← w − η · grad goes downhill → a small η lowers the loss (0.3364 → 0.0819 at 0.1), a big η overshoots (2.1160 at 0.5)
  • The loop is the same at any size → forward, loss, backward, update with 6 weights here and 220 in the tiny transformer → only the forward pass and the form of the loss change
  • detail that matters A weight's gradient includes its input x[k] as a factor → weights fed by bigger inputs get bigger gradients (−1.392 vs −0.696 for x = 2 vs 1) → input scale affects how fast each weight learns, one reason later cards normalise
  • detail that matters A nudge test (change one weight by 0.001, rerun forward) reproduces each gradient (−0.6956 vs −0.696) → but it costs one forward pass per weight → backprop's one pass is what makes millions of weights trainable

Reference only

  • the exact starting weights W1 = [[0.5, −0.5], [0.3, 0.2]], w2 = [0.4, 0.6]
  • code-style indexing: W1[0] is neuron 1
  • PyTorch's loss.backward(), optimizer.step() and optimizer.zero_grad()
  • this card writes W1 @ x; the transformer cards write x @ W

5 · Predict commit to an answer before revealing

Swap ReLU for GELU in this network, keeping every weight the same. Will neuron 1's weights still get exactly 0 gradient? Will its gradient be large or small, and which sign?

Reveal

No longer exactly 0. GELU's slope at a negative input is small but not 0, so some gradient leaks through and neuron 1 can learn. Measured (scratch run, tanh GELU as in tiny.py): GELU's slope at −0.5 is 0.1326, and neuron 1's gradients are [−0.0789, −0.1577], negative like neuron 2's but about 11 times smaller. Everything else shifts too, because GELU(−0.5) = −0.1543 is not 0: o = 0.2566 and L = 0.5526 before any step.
