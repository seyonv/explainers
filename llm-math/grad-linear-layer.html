Let the shapes write the gradient

The previous card gave us the push on every logit, dzdzdz. Now that push has to reach the weights. Almost every weight in a transformer sits inside a layer of the form y=xWy = xWy=xW. For that layer, one rule gives every gradient, and the shapes alone tell you how to write it.

Where this sits: the first weights the gradient reaches

Forward, the output head was hhh (3×43 \times 43×4) times Wout\WoutWout​ (4×54 \times 54×5) → zzz (3×53 \times 53×5). Backward runs the other way: dzdzdz (3×53 \times 53×5, from the previous card) comes in, and two things go out. dWoutd\WoutdWout​ (4×54 \times 54×5) is kept for the update. dhdhdh (3×43 \times 43×4) is passed down to the final LayerNorm, on the next card.

A gradient is written dXdXdX. It means the slope of the loss with respect to XXX: how much LLL moves per unit nudge of each entry.

dX≡∂L∂X dX \equiv \frac{\partial L}{\partial X} dX≡∂X∂L​

dXdXdX always has the same shape as XXX, because there is one slope per entry. That one fact does most of the work on this card.

Derive one entry, and the matrix formula follows

Start from what the forward pass did. Each logit is a dot product: z[t,j]=h[t,0] W[0,j]+h[t,1] W[1,j]+h[t,2] W[2,j]+h[t,3] W[3,j]z[t,j] = h[t,0]\,W[0,j] + h[t,1]\,W[1,j] + h[t,2]\,W[2,j] + h[t,3]\,W[3,j]z[t,j]=h[t,0]W[0,j]+h[t,1]W[1,j]+h[t,2]W[2,j]+h[t,3]W[3,j]. So where does W[1,3]W[1,3]W[1,3] appear? In z[t,3]z[t,3]z[t,3], for every position ttt, each time multiplied by h[t,1]h[t,1]h[t,1]. Nudge W[1,3]W[1,3]W[1,3] by a tiny amount and z[t,3]z[t,3]z[t,3] moves by h[t,1]h[t,1]h[t,1] times that nudge.

The chain rule says: the loss's slope with respect to W[1,3]W[1,3]W[1,3] is the sum, over every place W[1,3]W[1,3]W[1,3] was used, of (how much z[t,3]z[t,3]z[t,3] moves) × (how much LLL moves per unit of z[t,3]z[t,3]z[t,3]). That is ∑th[t,1] dz[t,3]\sum_t h[t,1]\, dz[t,3]∑t​h[t,1]dz[t,3]. Do the same for every iii and jjj and you get a grid of sums over ttt. A grid of "row of one matrix times column of another" sums is a matrix product, and here it is h⊤dzh^\top dzh⊤dz.

So the two rules are mirror images. dWdWdW sums over the positions (the TTT rows); dxdxdx sums over the outputs (the out columns). In both, the size that disappears is the one that appears in both factors.

Why a sum over positions: every position is a training example

One weight matrix is shared by all 3 positions. Forward, each position ran its own copy of h[t] Wouth[t]\, \Wouth[t]Wout​. Backward, each copy hands the shared weights its own gradient, h[t]⊤dz[t]h[t]^\top dz[t]h[t]⊤dz[t], and the shared weights collect all of them. Adding is what the chain rule does when one quantity is used in several places.

There is no extra division: the loss already took the mean, so every row of dzdzdz carries its 1/31/31/3. Think of the 3 positions as 3 training examples in one batch. Their gradients add, exactly as if you trained on each one and summed.

The same sum runs down the rows for a bias. A bias is added to every row, so its gradient is dydydy summed over rows. For the FFN's output bias c2c_2c2​ it is df.sum(0) =[0.2764, 0.1680, 0.0066, −0.4510]= [0.2764,\ 0.1680,\ 0.0066,\ -0.4510]=[0.2764, 0.1680, 0.0066, −0.4510], the same as tiny.py's dc2.

PyTorch stores the transpose

This course writes a layer as xWxWxW with WWW shaped (in,out)(\text{in}, \text{out})(in,out). PyTorch's nn.Linear stores weight shaped (out,in)(\text{out}, \text{in})(out,in), which is W⊤W^\topW⊤, and computes x @ weight.T. So its weight.grad is dW⊤dW^\topdW⊤: for the output head it is 5×45 \times 45×4, and its entry [3,1][3,1][3,1] is our −0.6103-0.6103−0.6103. That is the dz⊤hdz^\top hdz⊤h from the sketch. It is why tiny.py's torch_check transposes every weight going in and every gradient coming out.

Principle

A gradient has the shape of what it belongs to, and that pins down the product

For y=xWy = xWy=xW, the weight gradient dW=x⊤dydW = x^\top dydW=x⊤dy sums over the positions that shared the weight. The input gradient dx=dy W⊤dx = dy\, W^\topdx=dyW⊤ sums over the outputs each input fed. Write the shapes down and only one arrangement fits.

Buys you: the backward pass of every Wq,Wk,Wv,Wo,W1,W2\Wq, \Wk, \Wv, \Wo, W_1, W_2Wq​,Wk​,Wv​,Wo​,W1​,W2​ and Wout\WoutWout​ from one rule, so the later cards only have to find dydydy.

Where this simplification breaks
  • Shapes can't settle it when WWW is square. For Wq\WqWq​, xxx and dydydy are both 3×43 \times 43×4, so x⊤dyx^\top dyx⊤dy and dy⊤xdy^\top xdy⊤x are both 4×44 \times 44×4. Only one is right (the other is its transpose). Derive one entry, as above, to check.
  • The rule is only for xWxWxW. Elementwise steps like GELU, and steps that mix a row, like softmax and LayerNorm, need their own backward rules. Those are the next two cards.
  • Attention has products of two activations, QK⊤QK^\topQK⊤ and AVAVAV, with no weight in them. The same shape logic still works (dA=dC V⊤dA = dC\, V^\topdA=dCV⊤, dV=A⊤dCdV = A^\top dCdV=A⊤dC), but both sides get a gradient.
  • Real code doesn't loop over positions. It flattens batch × positions into one tall xxx and does one big matmul, which is why this rule is fast on a GPU.
