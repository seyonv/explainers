Attention is a weighted average of values

Context vectors, AVAVAV, value projection, multi-head attention, output projection · Raschka §3.4.1, §3.6

Prime · 2 minutes before you read

The problem: The scores card leaves each token with a row of weights saying how much to listen to each earlier token, but no content to listen to. Without a way to turn those weights into a new vector, no information moves between tokens.

Where it fits: Builds on attention scores (QK⊤/dQK^\top/\sqrt{d}QK⊤/d​ and the causal mask) and softmax, which turns each score row into shares. This card uses those shares to blend value vectors, then hands the result to the residual on the next card.

Needs first: Every token scores every earlier token

Builds on: Every token scores every earlier token · Softmax turns scores into shares · One operation does almost all the work

You'll meet: values V=aWvV = a\WvV=aWv​ context vectors C=AVC = AVC=AV (a weighted average) output projection o=CWo+boo = C\Wo + b_oo=CWo​+bo​ multi-head attention (split, attend, concatenate) grouped-query attention at Qwen scale

By the end: Compute a row of CCC and an entry of ooo by hand from the tiny model's arrays, explain why the weights must sum to 1 and why values are separate from keys, and give the head shapes for GPT-2 and Qwen2.5-0.5B.

  3. Key and value come from the same row of aaa: what does having two separate weight matrices let the model learn that one matrix couldn't?

The scores card left each token with a row of weights: how much to listen to each earlier token. Those weights still need something to listen to. Each token's output is a weighted average of the earlier tokens' value vectors, mixed in exactly the proportions its weights say.

Most like cat's value row. And no: the weights are positive and sum to 1, so each output number lands between the smallest and largest number in its column of VVV. That's what "weighted average" means.

An average can never be bigger than the biggest thing it averages, however many tokens there are. So the next layer sees numbers of the same size whether the prompt is 3 tokens or 1,024. The raw sum would hand it numbers that grow with the prompt length.

Several heads make several blends, and Wo\WoWo​ mixes them back

One row of AAA is one set of weights, so it can make only one blend. cat's row is [0.4979, 0.5021][0.4979,\ 0.5021][0.4979, 0.5021]: a smear of both tokens. If cat needed the's information for one purpose and its own for another, one row couldn't do both.

Principle

Match on one thing, pass along another, and mix in shares that sum to 1

Keys and queries decide the weights. Values decide the content. Because the weights are shares, the output is always a blend of real value vectors, never a sum that grows with the prompt. Heads let one token make several blends at once, and Wo\WoWo​ folds them back into one vector the size of the input.

Buys you: an output the same size and scale as the input, whatever the prompt length, so it can be added straight back onto the token.

Where this simplification breaks
  • The tiny model has one head. The 2-head split above is our experiment on untrained weights. The heads differ by chance, not because they learned different jobs.
  • Averaging many unrelated values blurs them. In the lab, the average of 1,024 random values has size 0.465, against 8.000 for one value. Trained attention avoids this by putting most of its weight on a few tokens.
  • Dropout on the attention weights during training (Raschka §3.5.2) is left out here. With it, a row no longer sums to exactly 1 on a training step.
  • Real code computes all heads in one batched matrix multiply, and fast kernels (such as FlashAttention) never store the full T×TT \times TT×T matrix AAA. The maths is the same.
