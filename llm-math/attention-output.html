Attention is a weighted average of values

Context vectors, A·V, value projection, multi-head attention, output projection · Raschka §3.4.1, §3.6

Prime · 2 minutes before you read

The problem: The scores card leaves each token with a row of weights saying how much to listen to each earlier token, but no content to listen to. Without a way to turn those weights into a new vector, no information moves between tokens.

Where it fits: Builds on attention scores (QKᵀ/√d and the causal mask) and softmax, which turns each score row into shares. This card uses those shares to blend value vectors, then hands the result to the residual on the next card.

Needs first: Every token scores every earlier token

Builds on: Every token scores every earlier token · Softmax turns scores into shares · One operation does almost all the work

You'll meet: values V = a·Wv context vectors C = A·V (a weighted average) output projection o = C·Wo + bo multi-head attention (split, attend, concatenate) grouped-query attention at Qwen scale

By the end: Compute a row of C and an entry of o by hand from the tiny model's arrays, explain why the weights must sum to 1 and why values are separate from keys, and give the head shapes for GPT-2 and Qwen2.5-0.5B.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. Why does row 0 of C come out identical to row 0 of V, and what would have to change for it not to?
  2. What exactly goes wrong in size if the attention weights are raw exp(S) instead of shares that sum to 1, and how does it depend on prompt length?
  3. Key and value come from the same row of a: what does having two separate weight matrices let the model learn that one matrix couldn't?
  4. What can two heads do for one token that a single softmax row can't, and why does that need Wo afterwards?
  5. In Qwen, 14 query heads share 2 value heads: which matrices shrink, and which stay full size?

The scores card left each token with a row of weights: how much to listen to each earlier token. Those weights still need something to listen to. Each token's output is a weighted average of the earlier tokens' value vectors, mixed in exactly the proportions its weights say.

Try this first

Guess first: token sat puts 0.8132 of its attention on cat. Will its output look most like the value row of the, cat or sat? And can any number in the output be bigger than every number in its column of V?

Show the answer

Most like cat's value row. And no: the weights are positive and sum to 1, so each output number lands between the smallest and largest number in its column of V. That's what "weighted average" means.

Where this sits

Comes in: a, the LayerNorm output (3 × 4, one row per token), and A, the attention weights from the scores card (3 × 3).

This step: turn a into values V with Wv, blend them with A to get C, then mix the columns with Wo to get o.

Goes out: o, 3 × 4. It is added back onto x0 to make x1 = x0 + o (the residual, next card).

Four lines, one of them new

A=softmax(Smasked)row by row V=aWv C=AV o=CWo+bo

A = softmax(S_masked, axis=-1); V = a @ Wv; C = A @ V; o = C @ Wo + bo

Last, Wo mixes the 4 columns of C. The bias starts at 0, so o row 2 is C2 · Wo = [−0.2759, 0.5872, −0.3843, −0.2744]. That's what gets added to x0.

Weights that sum to 1 keep the output on the values' scale

Softmax ends by dividing by the sum. What if attention skipped that and used the raw exp(S) as weights? Row 2's raw weights are [1.5794, 7.3938, 0.1194], summing to 9.0926. So C row 2 would come out 9.0926 times too big: [8.7871, 4.7456, 7.1788, −4.0334].

And it gets worse with more tokens, because every extra token adds another term. The lab measures it with random values of size 8.000 each (d = 64):

tokensweighted average (softmax)raw exp weights, no divide
34.60621.50
641.423146.13
1,0240.465781.92

An average can never be bigger than the biggest thing it averages, however many tokens there are. So the next layer sees numbers of the same size whether the prompt is 3 tokens or 1,024. The raw sum would hand it numbers that grow with the prompt length.

Keys decide who gets heard, values decide what gets said

The key K and the value V both come from the same row of a, through different weights. For cat (row 1):

  • key: a1 · Wk = [−0.8817, −0.3163, −0.3271, −1.7547]. It is what a query is matched against.
  • value: a1 · Wv = [1.2391, 0.8838, 1.1633, −0.9358]. It is what gets passed along once there's a match.

Think of a library index card and the book it points to. You search by the card, but you take home the book. With separate Wk and Wv, the model can learn what to match on and what to pass along as two different things. If the values were the keys, row 2 would pass along A2 · K = [−0.7042, −0.3969, −0.1903, −1.2368]: numbers shaped for matching, not for carrying meaning.

Several heads make several blends, and Wo mixes them back

One row of A is one set of weights, so it can make only one blend. cat's row is [0.4979, 0.5021]: a smear of both tokens. If cat needed the's information for one purpose and its own for another, one row couldn't do both.

Multi-head attention gives each token several rows. Split the d columns of Q, K and V into h heads of d/h columns each. Each head computes its own scores, its own A (dividing by √(d/h)), and its own blend of its slice of V. Then put the h blends side by side again (concatenate) and let Wo mix them.

Ch=softmax(Sh)Vh o=[C1,…,CH]Wo+bo

C_h = softmax(S_h) @ V_h for each head h; o = concat(C_1 … C_H) @ Wo + bo

h
one head, from 1 to H
H
the number of heads. The tiny model has 1
S_h
head h's masked scores, T × T, from its own d/h columns of Q and K
V_h
head h's d/h columns of V, T × d/h
C_h
head h's blend, T × d/h
[ … ]
concatenate side by side, giving T × d again
Filled in, as an experiment on the tiny model with H = 2 heads of 2 columns: cat's row in head 0 is [0.7735, 0.2265] and in head 1 is [0.2245, 0.7755]. Concatenated C row 1 = [0.1836, −0.5666, 0.7021, −0.3032].

The same tiny weights, read as 2 heads instead of 1. Where one head smears 50/50, head 0 listens mostly to the and head 1 mostly to cat. These weights are untrained, so the split is luck here. In a trained model, the heads learn to look for different things. Wo is what lets every head's numbers reach every output column.

By hand · about 3 minutes

Compute one entry of o: row 2, column 1. Take C row 2 = [0.9664, 0.5219, 0.7895, −0.4436] and column 1 of Wo = [0.9, 0.3, −0.5, 0.1]. The bias is 0. Multiply pairwise and add.

Show the answer

0.9664(0.9) + 0.5219(0.3) + 0.7895(−0.5) + (−0.4436)(0.1) = 0.8698 + 0.1566 − 0.3948 − 0.0444 = 0.5872. That matches o[2,1] = 0.5872 in tiny.out.

Change it

In llm-math/labs/tiny.py, skip the divide-by-sum. Change

v["C"] = v["A"] @ v["V"]
to v["C"] = np.exp(v["S_masked"]) @ v["V"]

Predict first: does row 2 of o get bigger or smaller than x0 row 2 = [0.9, −0.1, −0.4, −0.9], the thing it's added to? Does the loss go up or down?

Show what we measured

C row 2 becomes [8.7871, 4.7456, 7.1788, −4.0334] and o row 2 becomes [−2.5082, 5.3394, −3.4942, −2.4951], several times bigger than x0 row 2, so it drowns the token's own embedding. The loss goes up, 2.2067 → 2.3243. The PyTorch check now disagrees (torch still prints 2.206682), because it still uses softmax.

At real scale. GPT-2 124M, each of 12 layers: a is T × 768 (T up to 1,024). 12 heads × 64 columns. Each head has its own A (T × T) and its own V slice (T × 64). The 12 blends concatenate back to T × 768, and Wo is 768 × 768. Qwen2.5-0.5B, on the 7-token prompt, each of 24 layers: a is 7 × 896. 14 query heads × 64 give 14 A matrices of 7 × 7. But there are only 2 key/value heads, so V is just 7 × 128 (Wv 896 × 128), and each value head is shared by 7 query heads (grouped-query attention). The blends concatenate to 7 × 896 (14 × 64), and Wo is 896 × 896.

Principle

Match on one thing, pass along another, and mix in shares that sum to 1

Keys and queries decide the weights. Values decide the content. Because the weights are shares, the output is always a blend of real value vectors, never a sum that grows with the prompt. Heads let one token make several blends at once, and Wo folds them back into one vector the size of the input.

Buys you: an output the same size and scale as the input, whatever the prompt length, so it can be added straight back onto the token.

Where this simplification breaks
  • The tiny model has one head. The 2-head split above is our experiment on untrained weights. The heads differ by chance, not because they learned different jobs.
  • Averaging many unrelated values blurs them. In the lab, the average of 1,024 random values has size 0.465, against 8.000 for one value. Trained attention avoids this by putting most of its weight on a few tokens.
  • Dropout on the attention weights during training (Raschka §3.5.2) is left out here. With it, a row no longer sums to exactly 1 on a training step.
  • Real code computes all heads in one batched matrix multiply, and fast kernels (such as FlashAttention) never store the full T × T matrix A. The maths is the same.

Check yourself

1. Why is C row 0 exactly V row 0?

Show the answer

The causal mask lets token 0 see only itself, so A row 0 is [1, 0, 0]. A weighted average with all the weight on one row is that row.

2. Suppose A row 1 were exactly [0.5, 0.5, 0]. What would C row 1, column 3 be? (V0 ends in 1.8824, V1 in −0.9358.)

Show the answer

0.5(1.8824) + 0.5(−0.9358) = 0.4733. The real weights, 0.4979 and 0.5021, give 0.4675.

3. Qwen2.5-0.5B has 14 query heads but only 2 key/value heads. For the 7-token prompt, how many attention-weight matrices does one layer make, and what shape is V?

Show the answer

14 matrices of 7 × 7, one per query head. V is 7 × 128: 2 value heads of 64 columns, each shared by 7 query heads.

Understand and remember

  • softmax divides by the row sum → each row of A is positive and sums to 1 → C_i = Σ A_ij V_j is a weighted average → every entry stays between the smallest and largest value in its column, whatever the prompt length (raw exp weights made C row 2 9.0926× too big; at 1,024 random tokens 781.92 vs at most 8.000)
  • causal mask zeroes the future → token 0 has A row 0 = [1, 0, 0] → C row 0 = V row 0 exactly; token 2 has [0.1737, 0.8132, 0.0131] → C2 = [0.9664, 0.5219, 0.7895, −0.4436], mostly cat's value
  • K = a·Wk and V = a·Wv come from the same input through different weights → the model learns separately what a token is matched on and what it passes along → one matrix would force the matching features and the content to be the same numbers
  • one softmax row = one blend → a token can't pull different things from different tokens at once → split d into H heads of d/H, each with its own A → concatenate back to d columns → Wo mixes the heads so each one can reach every output column
  • detail that matters o has the same shape as the input x0 (T × d) → it can be added straight back as x1 = x0 + o → the residual on the next card depends on Wo restoring that shape
  • detail that matters Grouped-query attention shares one value (and key) head across several query heads → Qwen's V is 7 × 128 instead of 7 × 896 → fewer numbers to store per token in the KV cache, while there are still 14 different A matrices

Reference only

  • Tiny model: V = [[−0.1255, −0.9914, −0.8910, 1.8824], [1.2391, 0.8838, 1.1633, −0.9358], [−1.4760, −1.8716, −0.1255, −0.7304]]; C row 1 = [0.5596, −0.0499, 0.1404, 0.4675]; o row 2 = [−0.2759, 0.5872, −0.3843, −0.2744]
  • GPT-2 124M: 12 heads × 64 = 768, Wo 768 × 768
  • Qwen2.5-0.5B: 14 query heads, 2 KV heads, head dim 64; Wv 896 × 128, Wo 896 × 896
  • bo starts at all zeros; Raschka builds context vectors in §3.4.1 and multi-head attention in §3.6
