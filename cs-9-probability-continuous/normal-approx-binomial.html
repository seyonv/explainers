Normal approximation to the binomial

Also called the de Moivre–Laplace theorem, or "the CLT for counts", usually paired with the continuity correction (the ± ½). The cheat-sheet asks it about the pharmacy counter: 100 customers, each waiting over 10 minutes with chance e−1. How likely is it that at least half of them wait that long?

In one breath

A binomial count is a sum of many independent 0/1 trials, so by the central limit theorem its bar chart looks like a bell curve with the same mean np and variance np(1−p). To get P(X ≥ k), read the area under that bell. The bars are one unit wide, so cut at the bar's edge, k − ½, not at its centre k. That half-step is the continuity correction.

Filled in for the pharmacy: about 0.4%. The exact binomial sum is 0.00471, so the corrected normal is 11% low; without the ½ it is 35% low.

The source poses the question with no worked answer. "Wait" is read as the order's own processing time, which is what makes p = e−1. A simulation of 10⁵ groups of 100 (seed 0) gives 0.00463, within one standard error (±0.00022) of the exact value.

In Python

import math

def norm_cdf(z):
    return 0.5 * (1 + math.erf(z / math.sqrt(2)))

def binom_tail(n, k, p):
    """P(X >= k) for X ~ Bin(n, p), exact: sum the pmf."""
    return sum(math.comb(n, j) * p**j * (1 - p)**(n - j)
               for j in range(k, n + 1))

def normal_tail(n, k, p, cc=True):
    """P(X >= k) from N(np, npq); cc moves the cut to k - 0.5."""
    mu, sd = n * p, math.sqrt(n * p * (1 - p))
    x = k - 0.5 if cc else k
    return 1 - norm_cdf((x - mu) / sd)

n, k, p = 100, 50, math.exp(-1)
exact = binom_tail(n, k, p)
for name, v in [("exact", exact),
                ("normal, cc", normal_tail(n, k, p)),
                ("normal, no cc", normal_tail(n, k, p, False))]:
    print(f"{name:14} {v:.6f}  x{v / exact:.3f}")
# → exact          0.004708  x1.000
# → normal, cc     0.004193  x0.891
# → normal, no cc  0.003074  x0.653

Time O(n) for the exact sum (n − k + 1 terms) · O(1) for the normal: one erf call, which is why the approximation was the only option by hand. The full file also prints the simulation and the threshold table.

How it compares with the alternatives

Four ways to estimate P(at least 50 of 100) without summing the binomial, against the exact 0.004708.

✗ Normal, no correction

Cut at 50: z = 2.740, 0.00307. It throws away half of the 50 bar, 35% low.

✗ Poisson(np)

Poisson(36.79) gives 0.0219, 4.7× too high. Its variance is np = 36.8, not npq = 23.25; it fits only when p is small.

✗ Chebyshev (one-sided)

Cantelli's bound σ² / (σ² + 13.21²) = 0.118. Always true, but 25× too big: a bound, not an estimate.

✓ Normal with the ½

0.00419, 11% low in the tail and within 1% near the middle. Two numbers (np, npq) and one table lookup.

Should you still use it?

With a computer, no: math.comb sums the exact tail in microseconds for n in the thousands, and exact is always better. The approximation earns its place in exams, in back-of-envelope checks, and in reasoning ("50 is 2.6 standard deviations up, so well under 1%").

It is a poor choice when np or n(1 − p) is small (use Poisson if p is small, or sum exactly), and in far tails, where the relative error grows even with the correction (0.75× at k = 55 here). For a two-sided or "exactly k" question, correct both ends: P(X = 50) ≈ Φ((50.5 − μ)/σ) − Φ((49.5 − μ)/σ). The cut shifts left for ≥ and <, right for ≤ and >.
