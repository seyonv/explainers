Order statistics: min and max

Also written X(1) ≤ X(2) ≤ … ≤ X(n): the sample sorted, so X(1) is the smallest and X(n) the largest. The source guide asks for the CDFs of the min and the max of five independent Exp(λ) variables and stops there. This card derives both, adds the expected max, and puts numbers on it with λ = 0.1 per minute (mean 10 min, the pharmacy counter's rate; our choice, the source leaves λ symbolic).

Prime · 2 minutes before you read

The problem: A request that fans out to n backends waits for the slowest; a race is decided by the fastest; a system fails at the first component failure. The distribution of the min or max of n values looks like an n-dimensional integral, and adding chances ("any of 5 by minute 10" = 5 × 0.63) gives numbers above 1.

Where it fits: It turns the exponential card's minimum rule into a general tool for the smallest and largest of n, and uses memorylessness to get the expected max as a race. The sample-range card applies the same counting to uniforms; coupon collector meets the same harmonic numbers.

In one breath

Don't try to find the density of the smallest or largest value directly. Ask a yes/no question that all n values must agree on. The max is ≤ a only if every value is ≤ a. The min is > a only if every value is > a. With independence, "every" means you multiply n equal probabilities, so you raise one of them to the n-th power.

The expected max: a race with shrinking fields

Watch the five clocks run. Until the first finishes, five exponential clocks race, so the first gap is the min of 5, Exp(5λ), mean 1/(5λ) = 2 min. Memorylessness resets the other four, so the next gap is Exp(4λ), then 3λ, 2λ, λ. The bar is to scale.

In Python

import math

def cdf(lam, a):
    """F(a) = P(X <= a) for one X ~ Exp(rate lam)."""
    return 1 - math.exp(-lam * a)

def p_min_le(lam, a, n=5):
    """min <= a unless all n exceed a: 1 - (1 - F)^n."""
    return 1 - (1 - cdf(lam, a)) ** n      # = 1 - exp(-n*lam*a)

def p_max_le(lam, a, n=5):
    """max <= a only if all n are <= a: F^n."""
    return cdf(lam, a) ** n

def e_order_stat(lam, k, n=5):
    """E[X_(k)]: gaps are Exp(n*lam), Exp((n-1)*lam), ..."""
    return sum(1 / (j * lam) for j in range(n - k + 1, n + 1))

lam = 0.1                          # mean 10 min per order
print(f"{p_min_le(lam, 10):.4f} {p_max_le(lam, 10):.4f}")
print([round(e_order_stat(lam, k), 2) for k in range(1, 6)])
# → 0.9933 0.1009
# → [2.0, 4.5, 7.83, 12.83, 22.83]

O(1) per CDF value and O(n) for E[X(k)]: no sorting and no n-dimensional integral, because independence factors everything. The full file also prints the table above and the 200,000-sample simulation (one run, about 1 s).

Why it beats the alternatives

✗ Integrate the joint density

Correct in principle: integrate λ⁵e−λ(x₁+…+x₅) over the region where the max is ≤ a. That is a 5-dimensional integral for something that factors in one line.

✗ Add the chances

"Any of 5 finishes by 10" as 5 × 0.6321 = 3.16, which is not a probability. The events overlap; adding them is only an upper bound (the union bound).

✗ Simulate only

200,000 samples give 0.1009 ± 0.0007 and take about a second. They can check a formula, but they can't give 137/60 exactly, and tiny tails like P(max ≤ 2) = 0.0002 need far more samples.

✓ "All" events, then multiply

Rewrite the max or min event as "every Xi is on one side of a", then multiply. With the exponential's memorylessness, the race view gives every E[X(k)] as a sum of 1/(jλ).

Does this always work?

The product step needs independence. If the five orders share a cause (one slow pharmacist handles all of them), the times are correlated and F(a)5 can be far off. Distributions that differ are fine: use the product of Fi(a), and for exponentials the min is still Exp(λ₁ + … + λn). The harmonic-sum trick for E[max] is special to the exponential, because it relies on memorylessness. For other laws, integrate E[max] = ∫ (1 − F(a)n) da for a ≥ 0 variable, or use the uniform results on the sample range card.

For middle order statistics (the median of five, say), "all" becomes "at least k": P(X(k) ≤ a) = P(Bin(n, F(a)) ≥ k). The same growth shows up in systems (our inference, not the source's): a request that waits for the slowest of n exponential backends waits Hn/λ on average, and Hn grows like ln n. With a 10 ms mean, that is 22.83 ms for 5 backends and 51.87 ms for 100 (computed, illustrative).

Understand and remember

  • max ≤ a only if every Xi ≤ a → with independence the events multiply → P(X(n) ≤ a) = F(a)n → 0.6321⁵ = 0.1009 at a = 10
  • min > a only if every Xi > a → P(X(1) ≤ a) = 1 − S(a)n → for exponentials S(a)n = e−nλa, so the min is Exp(nλ): 0.9933 at a = 10
  • Memorylessness restarts the unfinished clocks at each finish → gaps are Exp(5λ), Exp(4λ), …, Exp(λ) → E[max] = (1/λ)(1 + 1/2 + … + 1/5) = H5/λ = 22.83 min → the last gap alone is 10 of it
  • Shared causes make the values move together → the product step fails → F(a)n can be far off whenever the n values aren't independent
  • detail that matters Hn grows like ln n → the slowest of 100 exponential backends with mean 10 ms waits 51.87 ms on average, not 1,000 ms → fan-out tail latency grows slowly but surely

5 · Predict commit to an answer before revealing

Half the days the five orders have mean 10 min, the other half mean 5 min (all orders on a day share it). Is P(max ≤ 10) equal to the average of F(10)⁵ over the two day types, or to (average F(10))⁵? Which is larger?

Reveal

The average of the two F(10)⁵ values: ½(0.1009 + 0.4833) = 0.2921. Raising the averaged F to the 5th power gives 0.2348, which wrongly treats the orders as independent across the shared day. The shared parent makes the orders move together, so all five finishing early is more likely than independence says.
