Agents that model their environment

Also called world modelling for agents, next-observation prediction, an environment loss or a hybrid RL + SFT objective. Wolfe's Agentic World Models covers ECHO and Prime Intellect's follow-up (a small loss on terminal and tool output), PaW (the same idea with three stabilisers) and Qwen-AgentWorld (a separate model trained to stand in for the environment).

Prime · 2 minutes before you read

The problem: Agentic RL gives a whole run one pass/fail reward and masks every tool output from the loss. When every run in a group fails, the advantages are all zero and the model learns nothing, even though each step recorded exactly how the environment reacted.

Where it fits: You know from The reward becomes a place that tool outputs are masked, and from The group is the baseline that GRPO scores a run against its group. This card asks whether the masked tokens should be trained on too, and what happens if a model plays the environment instead.

In one breath. In agentic RL the tool outputs are normally masked: the model is trained only on the tokens it wrote, and every run earns a single pass/fail reward. These papers also train the same model to predict the tool outputs, using a small supervised loss on those tokens. Every step then teaches something, including steps in runs that failed. Or, going further, you can train a separate model to play the environment.

You already know: tool outputs are masked from the loss (this card asks whether they should be) · the group is the baseline (GRPO's advantage is a run's reward minus the group mean).

Green tokens receive a gradient; grey dashed ones are ignored. The model already computed a probability for every token in the rollout during its forward pass. ECHO simply also reads those probabilities at the observation positions, so it needs no extra rollouts or forward passes.

The objective

L= LGRPOaction tokens: learn to act + λ·1Z ∑t∈S −logπθ(ot∣history, action)observation tokens: learn what happens
λhow much predicting outputs counts against actingECHO's best: 0.01–0.05 Sthe observation tokens chosen for the lossECHO drops the harness's fixed WARNINGS: prefix Zall observation tokens, chosen or not, so the scale stays fixed when S changesECHO's normaliser πθthe same model that acts; there is no second networkunchanged at inference
in plain text: token_weight = action_mask · advantage + observation_mask · λ loss = −token_weight · log p(token) (Wolfe's reference code, λ = 0.05)

A supervised loss is the RL loss with the advantage held at a positive constant, so one weight per token covers both. If λ is set too high, ECHO reports that training drifts toward low-reward runs whose tool calls have easy-to-predict output.

Why it helps: a group where every run fails

Real output of python3 code/world-models.py. The token counts are illustrative. 4 × 480 = 1,920 and 4 × 600 = 2,400. When every run fails, the group mean equals each reward, so every advantage is 0 and a masked objective learns nothing. This is the sparse-reward stall that PaW shows on WebShop, where vanilla GRPO rarely gets a positive reward.

Mask or model? Why the small hybrid wins

✗ Mask every observation

The standard choice. Failed runs teach nothing, and an all-fail group has zero gradient. ECHO calls this a source of supervision "masked out".

✗ Weight it heavily, on every tool

The dense loss crowds out the reward. ECHO drifts toward easy-to-predict tool calls, and memorisable output such as web pages and docs overfits (deepdive: after one epoch).

✗ World modelling without RL

Perplexity on observations improves, but Prime Intellect finds that this alone is not the best agent. ECHO's verifier-free mode stalls on hard tasks unless malformed runs are filtered out.

✓ RL on actions + small λ on chosen outputs

It costs a masked sum, needs no new rollouts, and leaves inference unchanged. Every step now carries signal, and the weight, normaliser and tool choice keep the loss from taking over.

Would it have caught the Tuesday run?

Not by itself, and this is our inference: no paper here tests false success claims. A model trained this way is pushed, at every step like step 6, to expect what pytest will actually print after its edit, so in principle it carries the knowledge that its fix did not work. But ECHO and PaW change only training. At inference the agent never writes out a prediction to compare against the real output. Its step-9 claim is an action token, judged only by the reward. The compaction summary at step 7 is model-written too, so it is trained as an action, not as an observation. Turning prediction into a check (predict, run, compare) would be a harness feature that none of these sources describe.

It is also not free. The dense loss overfits faster than RL alone, especially on retrieval tools, and the warning sign is held-out scores falling while training reward jumps. Expert data still matters: on Terminal-Bench 2.0, ECHO recovers only about half of the benefit of SFT on expert runs. Gains can fail to transfer: training on forth-lang hurt the multi-tool general-agent set. If your environment is trivially predictable, or the outputs are pages to memorise, keep the mask.

Understand and remember

  • Outcome reward is one number per run and GRPO subtracts the group mean → an all-fail group has every advantage at 0 → masked training gets no gradient from it → putting a small loss on observation tokens keeps every step teaching (1,920 of 2,400 tokens live in the toy group)
  • A supervised loss is an RL loss with a constant positive advantage → one per-token weight (advantage on actions, λ on observations) covers both → it reuses log-probabilities already computed, so there are no extra rollouts or forward passes and inference is unchanged
  • The observation loss is dense and the reward is sparse → a large λ lets prediction win → the model drifts toward runs whose tool output is easy to predict, so keep λ small (ECHO: 0.01–0.05) and normalise the two losses separately
  • Memorisable outputs (web pages, docs) can be learned by rote instead of by rule → the dense loss overfits them fast (deepdive: after one epoch) → train on outputs that are complex but predictable, such as code execution, and watch held-out scores fall while training reward jumps
  • detail that matters Cross-entropy's gradient grows like 1/p (100 at p = 0.01) → rare, noisy observation tokens dominate the update → PaW uses a bounded MAE loss and drops tokens already above p = 0.2 so the model does not memorise them
  • detail that matters A learned simulator's quality caps the agent → an off-the-shelf model as the simulator gave no gain, and injected errors and pagination were needed → SimRL can replace real environments only if the simulator reproduces their failures

Reference only

  • ECHO's normaliser Z counts all observation tokens, including unselected ones
  • ECHO drops the harness's fixed WARNINGS: prefix from the loss
  • PaW keeps the top 75% of transitions by action entropy
  • Qwen-AgentWorld's reward: 5 rubric criteria scored 1–5, averaged and ×5 (range 5–25), mixed 9:1 with executable checks
  • ECHO's setup: 8,870 tasks, at most 16 turns, Harbor harness, batch of 16 prompts × 16 rollouts

5 · Predict commit to an answer before revealing

A team swaps its flaky real search backend for a learned simulator but skips the control instructions that inject API errors and pagination. The simulator returns clean, complete results every time. Predict what the agent learns, and how it fails when deployed against the real backend.

Reveal

It learns a policy for a world without failures: one call, trust the result, no retries, no follow-up page requests. Wolfe reports that these perturbations were necessary for SimRL to give meaningful gains, and a weak simulator (an off-the-shelf Qwen3.6) gave none. In deployment you'd expect it to fail on exactly the partial failures the simulator never produced: a timeout or a truncated page treated as the full answer. The general lesson is that a simulator teaches only the dynamics it reproduces.
