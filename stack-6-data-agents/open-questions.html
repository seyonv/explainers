1Does a receipt drop or upgrade the failures its own trace shows?

capstone · summaries that inflate status, the claim checkeropencost: lownovelty 3 × cheap 3 × practice 3 = 27
Why it matters
A receipt is a summary of the run. If it loses a 0-row retry or a denied source the way compaction loses an exit code, people trust exactly the answers that went wrong.
Status
Open for data agents, as far as the writer could find. Adjacent: Silence Is Endorsement (arXiv 2609.20211) shows summarizers dropping "unverified" status on authorization claims; Tool Receipts, Not Zero-Knowledge Proofs (arXiv 2603.10060) checks claims against tool receipts on a synthetic benchmark.
Cost
Low: scripted runs and one summarizer model.
Smallest experiment
Seed the receipts card's EMEA run with three failures (a 0-row first try, a denied source, a silent fallback), let a model write the user-facing receipt from the full trace, and count failures present in the trace but missing or softened in the receipt. Run code/receipts.py's checker on both.

2How often does a wrong query match the golden value on one data version and not the next?

partly studiedcost: low–medium2 × 3 × 3 = 18
Why it matters
If coincidental matches are common, result-only data-agent evals overstate accuracy, and path checks stop being optional.
Status
Partly studied: Zhong et al. (2020), test-suite accuracy for text-to-SQL, grades a query on many database variants so a coincidental match on one fails on another (arXiv id not given in the writer's notes). Not measured for agents on live data that drifts by backfills and late rows.
Cost
Low–medium: a mutation script over a public benchmark such as BIRD, plus agent runs (my estimate).
Smallest experiment
Extend code/changing-data-evals.py's ledger to five versions (backfills, late refunds, new intercompany rows), run agent-written queries on each, and count queries that match the golden value on one version and diverge on another. Then compare result-only and path grading.

3How much does marked authority beat schema plus query history on twin tables, and does a bigger model close the gap?

partly studiedcost: under $1002 × 3 × 3 = 18
Why it matters
It decides whether to spend on metadata (asset contracts, context cards) or wait for a better model to infer authority on its own.
Status
Partly studied: BIRD and Spider 2.0 test realistic, distractor-heavy schemas (arXiv ids not given in the writers' notes). No ablation of marked status, grain and freshness against model size is known to the writers.

4When a semantic layer collapses the readings, where does the error go?

opencost: low3 × 3 × 2 = 18
Why it matters
A governed metric removes the eight-readings problem, but a wrong definition in the layer becomes one confident wrong answer for everyone. Teams need to know which failures they are trading for which.
Status
Open; the writer found no measurement.
Cost
Low, per the writer.
Smallest experiment
Run the anatomy card's eight-readings warehouse with and without a single metric definition, seed one wrong definition in the layer and one wrong join outside it, and record which errors survive, how many answers each one touches, and whether the receipt points at it.

5Does a model judge reward the agent's wrong answer when both share the same wrong metric definition?

capstone · what the judge seesopencost: low–medium3 × 2 × 3 = 18
Why it matters
Part 7 warns of shared blind spots but gives no rate. If the correlation is high, model-graded data evals need a judge that reads the metric contract, not the agent's framing.
Status
Open for metric definitions, per the writer. Adjacent: Self-Attribution Bias (arXiv 2603.04582) finds monitors go easy on their own outputs.
Cost
Low–medium, per the writer.
Smallest experiment
Build 30 EMEA-style cases where the agent leaves out the intercompany exclusion (the 47.45 answer). Grade them with a judge given the same wrong "net" definition, with one given the contract, and with a judge from a different model family. Compare pass rates on the wrong answers.

6When does an agent silently pick a non-default reading instead of asking?

partly studiedcost: low–medium2 × 2 × 3 = 12
Why it matters
A silent pick is the cheapest way to be wrong without an error. Knowing the rate tells you whether to require disclosure or clarification.
Status
Partly studied: AmbiQT, a benchmark of ambiguous text-to-SQL questions (arXiv id not given in the writer's notes). Not measured for multi-step agents that can ask.
Cost
Low–medium, per the writer.
Smallest experiment
On the anatomy card's toy warehouse, pose 40 ambiguous questions and label each run as asked, picked and disclosed, or picked silently. Repeat with a system prompt that requires naming the reading.

7How fast do context cards go stale, and does refresh-on-commit catch it?

opencost: medium3 × 2 × 2 = 12
Why it matters
A stale card makes a confident wrong answer look documented. The card's own predict step shows it: a transform drops the refund subtraction, the agent now reports 550, and the card still says "gross minus refunds".
Status
Open; the writer found no measurement.
Cost
Medium: scripting over a public repo's history (my estimate).
Smallest experiment
Replay a public dbt project's git history. Extract cards at one commit, re-extract at each later commit, and count facts that changed and how many a commit-diff trigger would have caught.

8Do receipts actually help people catch a wrong reading?

opencost: high (a user study)3 × 1 × 3 = 9
Why it matters
The whole receipts argument assumes a person reads them. If catch rates don't move, the receipt is for audits, not for users.
Status
Open; both writers who raised it found no study.
Cost
High: it needs analysts' time, per both writers.
Smallest experiment
Show a small group of analysts 20 answers, 5 with seeded wrong readings, half with receipts and half without, and measure the catch rate and the time spent.

How to generate your own

Three moves

  1. Split an overloaded word. Govindarajan's move: "revenue" hides metric, entity and time; "done" hides five states; "verified" hides five gates. Each split gives a question: which part fails most often, and which part does the check skip?
  2. Ask what's unmeasured. For every lever on the overview, ask whether anyone has a number with a baseline. In this course almost no one does, because the posts are architecture arguments.
  3. Check for a cheap controlled experiment. A toy warehouse, a seeded error and a few hundred runs often answer the first version of the question. If the smallest experiment needs real users or production data, rank it lower and say so.

Understand and remember

  • The posts give patterns but no baselines → every lever's effect size is a toy illustration → the cheapest valuable research is a controlled comparison on a toy warehouse with seeded errors
  • A receipt is a summary of a run → summaries can drop or soften failure status → measuring receipt completeness is the data-agent version of the capstone's compaction question
  • Rank = novelty × cheapness × practice → a high-impact question that needs real users ranks below a cheap scripted one → do the cheap version first and let it justify the expensive one

4 · Compare against what you already know

vs How data agents earn trust: The overview ranks levers by the size of the error they remove; this card ranks questions by novelty × cheapness × practice. Why can a lever with a big illustrative effect still produce a low-ranked question?

Check
  • the overview's effects are toy illustrations, not evidence of how often the error happens
  • a lever can be well studied already (low novelty) or expensive to test (low cheapness)
  • so effect size in a toy and research value are different axes

vs How many runs do you need?: Each smallest experiment names a few dozen cases. What would the power-analysis card say before you trust a difference between two conditions?

Check
  • small samples only detect large differences
  • pair conditions within the same case to cut variance
  • report an interval, not just the difference
  • fix the run count before looking at results

5 · Predict commit to an answer before revealing

In question 2's experiment, would rerunning on the July snapshot catch the agent that forgot the intercompany filter?

Reveal

No. On July data there are no intercompany rows, so every agent returns 46.30 and the snapshot rerun passes all three. The missing filter only shows once a later version adds intercompany rows (47.45 in October). That's why the experiment needs several data versions, not one frozen snapshot.
