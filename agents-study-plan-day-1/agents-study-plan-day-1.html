Agents study plan · Day 1

The loop and its tools

Day 1 of the agents study path: what a coding agent actually is (a model called in a loop, with tools) and what makes a tool easy for a model to use. It follows stations 1 and 2 of the Agents field guide and ends with a small agent you build yourself. Tick things off as you go; your progress stays in this browser.

By the end of all of this, you'll be able to
  • Write the agent loop from memory: call the model, run the tools it asked for, send back every result, and stop on the stop reason or a budget.
  • Say when a fixed workflow is a better choice than an agent.
  • Describe one tool call end to end, from the tool's definition to its result, including what happens when the model makes two calls at once.
  • Explain why a tool's error messages and output length matter as much as what the tool does.
  • Run a 60-line agent of your own on a planted bug, and read its cost from the usage it reports.
The same routine every phase
  1. Prime (5 min): read the phase's questions below its intro. Nothing else yet.
  2. Pretest: try the phase's checkpoint cold, without opening the answers.
  3. Read in order, with the questions in mind. The phase opens with a card from this hub; the readings after it open in new tabs.
  4. Take the checkpoint for real. For each miss, reopen only the source its answer points to.

    1. Your loop answers two parallel tool_use blocks with two separate user messages, and the next request fails. State the rule you broke and describe the message the API expects.

      Show the answer
      • Every tool_use id must be answered in the very next user message
      • That message holds all the tool_result blocks, keyed by tool_use_id, in call order and before any text
      • A tool that raised still gets a tool_result, marked is_error: true, so no id is left unanswered

      Missed it? Handle tool calls · Agents failure F09

    2. Barry Zhang's budget example: a task worth about $0.10 affords roughly 30,000 to 50,000 tokens. When does that argue for a fixed workflow instead of an agent, and what would make you pick the agent anyway?

      Show the answer
      • An agent's cost grows with its number of calls, because each call re-reads the history, so a small budget buys few turns
      • If the steps are known in advance, a workflow spends the budget on those steps, not on exploration
      • Pick the agent when the path can't be written down beforehand, such as finding a bug in an unfamiliar repo, and the task is worth the extra calls
      • Either way, decide by measurement: run both on the same tasks and compare cost per resolved task

      Missed it? How We Build Effective Agents (talk) · Building effective agents · Agents principle 7

    3. Your first loop runs tools while stop_reason is tool_use and treats anything else as done. Name two ways that ends a run wrongly, one way it never ends, and what the loop needs for each.

      Show the answer
      • max_tokens can cut a tool_use block in half: the loop either reports a cut-off answer as done or runs a broken call; retry the turn with a higher max_tokens instead (F08)
      • pause_turn and refusal are not finishing either: pause_turn needs the assistant content sent back unchanged to continue, a refusal needs its own exit
      • A model that keeps calling tools never stops on its own, and failing runs are the ones that go long: step, dollar and wall-time caps are exits, logged as failed runs rather than crashes (principle 9)

      Missed it? Stop reasons and fallback · Agents failure F08 · agents/default.py: the DefaultAgent loop · Agents principle 9

  6. Checkpoint: toolsFrom the Agents guide's closed-book check for station 2.

    1. Your edit tool can match strictly (exact once) or leniently (ignore whitespace, fuzzy context). Choose one for a small open model editing tab-indented Go, and justify it with the failure you accept.

      Show the answer
      • Strict: no silent wrong edits, but whitespace-only mismatches fail, so view must show tabs and the error must show the closest match
      • Lenient: fewer failed edits, but a near-miss can apply to the wrong block and only tests will catch it
      • Either is defensible if you name the accepted failure and measure it: failed-edit rate and recovery for strict, wrong-edit rate from hidden tests for lenient

    2. What makes a tool's error message actionable? Give the message you would return when old_str matches 3 times.

      Show the answer
      • It names what went wrong and the next action, without the model re-reading the file
      • For 3 matches: the line numbers of all three and an instruction to include more surrounding lines
      • It is returned as the tool_result with is_error set, so the loop continues instead of crashing
