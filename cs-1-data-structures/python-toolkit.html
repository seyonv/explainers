The Python interview toolkit

Also called the standard-library containers: list, deque, dict, set, heapq, bisect, Counter, defaultdict, OrderedDict. The cheat-sheet's coding page opens with an empty "C++" heading; since this series writes every solution in Python, this card takes its place.

In one breath

Most interview solutions repeat one operation millions of times: pop from the front, test membership, grab the smallest, keep things sorted. Each has one container that makes it O(1) or O(log n). Pick the container for the operation you repeat, and a plain list for everything else.

In Python, on the course's running example

import bisect, heapq
from collections import Counter, defaultdict, deque

a, s = [5, 2, 9, 1, 5, 6], "ADOBECODEBANC"

q = deque(a); q.append(7)
print(q.popleft(), list(q))        # O(1); list.pop(0) is O(n)
h = [-x for x in a]                # min-heap of negatives
heapq.heapify(h)                   # O(n)
print(-heapq.heappop(h))          # the max, O(log n)
b = sorted(a)                     # [1, 2, 5, 5, 6, 9]
print(bisect.bisect_left(b, 5))   # first index with b[i] >= 5
bisect.insort(b, 4); print(b)     # O(n): shifts 5, 5, 6, 9
print(Counter(s).most_common(3))
groups = defaultdict(list)
for x in a:
    groups[x % 2].append(x)       # no KeyError on first use
print(dict(groups))
seen = set(a); print(9 in seen, 3 in seen)

# → 5 [2, 9, 1, 5, 6, 7]
# → 9
# → 2
# → [1, 2, 4, 5, 5, 6, 9]
# → [('A', 2), ('D', 2), ('O', 2)]
# → {1: [5, 9, 1, 5], 0: [2, 6]}
# → True False

Time O(n log n) · Space O(n) for the snippet as a whole: sorted(a) dominates; everything else is O(n) or less. Six letters of s appear twice, so most_common(3) breaks the tie by first appearance: A, D, O.

Why the right container beats a plain list

✗ A list as a queue

pop(0) in a BFS loop. Emptying 105 items moves 4,999,950,000 elements, so an O(n) search quietly becomes O(n²).

✗ A list for "seen before?"

if x not in seen_list inside a loop. 232 µs per test at n = 105, measured; 105 such tests is over 20 s.

✗ Sorting to get the smallest

Re-sorting, or insort plus pop(0), after every insert: O(n) or O(n log n) per step for what a heap does in O(log n).

✓ One tool per hot operation

deque for the ends, set or dict for "have I seen it?", heapq for "the smallest next", bisect for ranks in sorted data. Each turns the repeated step into O(1) or O(log n).

"Over 20 s" = 105 × 232 µs = 23.2 s, extrapolated from the measured per-lookup time, not run.

Is the fancier container always better?

No. For a few dozen items, a list scan is fast and simplest; a set also costs memory and needs hashable items (no lists inside). A deque gives up fast indexing in the middle. heapq has no decrease-key, so Dijkstra in Python pushes duplicates and skips stale entries. And a dict's O(1) is an average: adversarial keys that all collide make it O(n), which is why Python randomizes string hashes per process.

When the operation is "add 17 to every item", no container helps: the per-item interpreter cost dominates, and numpy's whole-array operations are the fix (see the Python loops card).
