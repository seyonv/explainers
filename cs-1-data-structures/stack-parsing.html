Stacks for parsing

Also called bracket matching or a pushdown stack. Whenever input nests, push what is still open and pop it when its closer arrives. The source guide uses this for Basic Calculator (in Java), Longest Valid Parentheses and Tag Validator, under Stacks.

Prime · 2 minutes before you read

The problem: Nested input (brackets, sub-expressions, tags) can't be handled by a left-to-right counter once you need to know what was open, not just how many. eval() is banned and unsafe; recursion hits Python's 1,000-frame limit.

Where it fits: Follows the queues cards: the other end of the linear family. Stacks are last in, first out, which matches nesting exactly. The same stack reappears in the monotonic stack card next and as the call stack of DFS in cs-3.

Builds on: The Python interview toolkit

You'll meet: push on an opener, pop on its closer Basic Calculator: push (result, sign) at each ( Longest Valid Parentheses: a stack of indices over a base index Tag Validator: a stack of tag names recursion as an implicit stack

By the end: Evaluate +/− expressions with brackets and find the longest valid parenthesis run, each in one O(n) pass, by deciding what state to push and restore at each nesting level.

In one breath

Nested input closes in the reverse order it opened, which is exactly last in, first out. So on every opener you push whatever you'll need back later (a half-finished sum, an index, a tag name), and on every closer you pop it. The top of the stack is always the innermost thing still open.

(1 + (4 + 5 + 2) − 3) + (6 + 8) = (1 + 11 − 3) + 14 inner bracket popped first = 9 + 14 = 23 2 − (5 − 6): push (2, −1) · pop 2 + (−1) × (−1) = 3 ← the saved sign
def calculate(s):
    result, sign, x = 0, 1, 0
    stack = []
    for c in s:
        if c.isdigit():
            x = 10 * x + int(c)          # build multi-digit numbers
        elif c in "+-":
            result += sign * x           # flush the number just read
            sign, x = (1 if c == "+" else -1), 0
        elif c == "(":
            stack.append((result, sign))  # save the outer state
            result, sign = 0, 1          # start a fresh inner sum
        elif c == ")":
            inner = result + sign * x
            outer, before = stack.pop()
            result, x = outer + before * inner, 0
    return result + sign * x

print(calculate("(1+(4+5+2)-3)+(6+8)"))  # → 23
print(calculate("2-(5-6)"))              # → 3

The source's version is Java and correct; rewritten in Python with one (result, sign) tuple per bracket instead of two separate pushes. Spaces fall through every branch, so they're ignored.

def longest_valid(s):
    stack = [-1]                 # index just before the current run
    best = 0
    for i, c in enumerate(s):
        if c == "(":
            stack.append(i)      # an open bracket waiting for a match
        else:
            stack.pop()          # match it (or pop the old base)
            if stack:
                best = max(best, i - stack[-1])
            else:
                stack.append(i)  # unmatched ')': new base
    return best

print(longest_valid(")()())"))  # → 4

Tag Validator, in one line: push each <NAME>, pop on </NAME> and fail if the names differ, skip <![CDATA[…]]> without parsing it, and fail if the stack empties before the end of the input (the whole snippet must sit inside one tag).

Time O(n) · Space O(n) for all three. Each character is read once and each push is popped at most once; the stack is as deep as the deepest nesting, about n/2 entries for "((…))".

Why a stack beats the alternatives

✗ Call eval()

Banned by the Basic Calculator problem, and it runs arbitrary code on untrusted input. It also teaches nothing about the nesting.

✗ Recurse on each (

Same idea with the call stack as the stack, and clean to read. But Python stops at 1,000 frames: a 1,000-deep bracket raised RecursionError, while the explicit stack handled 10,000 deep (one run on the author's M3).

✗ Check every substring

For Longest Valid Parentheses: test all n(n + 1)/2 substrings, O(n) each. That's 21 for n = 6 but 50,005,000 for n = 10⁴, so O(n³) in total.

✓ An explicit stack

One pass, O(n), with depth bounded by memory rather than the recursion limit. Every opener is pushed once and popped once.

Is a stack always the tool?

Use one whenever the input nests: brackets, tags, undo history, the DFS on a tree or a graph. If only one bracket type appears and you only need to know "is it balanced", a single depth counter is enough and uses O(1) space. Longest Valid Parentheses also has an O(1)-space answer: count opens and closes left to right, then right to left, and record a run whenever the counts match.

Once operators have precedence (* binds tighter than +), one stack of saved sums isn't enough: use Dijkstra's shunting-yard (a stack of operators plus a stack of values) or a recursive-descent parser, and for a real language, Python's own ast.parse. These alternatives are standard practice, not from the source.

Understand and remember

  • Nested input closes in the reverse order it opened → last in, first out → push what you'll need back on an opener, pop it on the closer → the top is always the innermost open thing
  • Calculator: ( → push (result, sign) and start a fresh sum → ) → finish the inner sum and fold it in as outer + sign × inner → the saved sign negates a whole bracket (2 − (5 − 6) = 3) → one pass, O(n)
  • Longest valid: push indices of unmatched ( over a base index (−1, or the last unmatched )) → a ) pops its match → the new top is the index before the current valid run → length = i − top, joining adjacent runs like ()() into one
  • Recursion uses the call stack → Python raises RecursionError near 1,000 frames → an explicit stack is bounded only by memory (10,000 deep handled in one run)
  • detail that matters Only + and − share one precedence → one stack of saved sums suffices → with * and / you need two stacks (shunting-yard) or recursive descent

vs Monotonic stack: A parsing stack vs a monotonic stack: what triggers a pop in each, and what does the popped item learn at that moment?

Check
  • parsing: a closing symbol pops its matching opener
  • monotonic: a smaller arriving value pops every taller one
  • parsing pop: the innermost open context is finished and folded into the outer
  • monotonic pop: the popped bar has found both walls, so its best rectangle is known

vs Corner cases: parsing numbers and passwords: Stack parsing vs a staged scan with flags: which kind of input structure needs which, and how does each fail?

Check
  • nested structure (brackets, tags) needs a stack, since depth is unbounded
  • flat, fixed-order structure (atoi's spaces → sign → digits → clamp) needs only stages or flags
  • a flag scan fails on nesting: it can't remember more than a fixed amount
  • a stack parser fails at precedence without a second stack; a flag scan fails at unforeseen edge combinations

5 · Predict commit to an answer before revealing

Before running: what does calculate("1-(2-(3-4))") return, and how many (result, sign) pairs are on the stack at the deepest point?

Reveal

−2. The innermost bracket is 3 − 4 = −1, the middle is 2 − (−1) = 3, and the whole is 1 − 3 = −2. Two pairs are saved at the deepest point: (1, −1) for the outer bracket and (2, −1) for the middle one, and each saved −1 flips its bracket's value on the way out.
