Monotonic stack

Also called an increasing stack or a next-smaller-element stack. A stack whose values stay sorted, so each new element pops everything it beats. The cheat-sheet uses it for Largest Rectangle in Histogram, under Stacks.

In one breath

Keep a stack of indices whose heights never drop. When a shorter bar arrives, the taller bar on top has just found both of its walls: the new bar on its right and the bar beneath it on the stack on its left. So its widest rectangle is known, and it can be popped and forgotten.

Worked example: heights = [2, 1, 5, 6, 2, 3] → 10

area of the popped bar = h[top] × (i − new top − 1) bar i = 2 (h 5): 5 × (4 − 1 − 1) = 5 × 2 = 10

The bar at i = 2 can stretch right until the first shorter bar (i = 4, h 2) and left until the first shorter bar (i = 1, h 1). Both walls are excluded, so the width is 4 − 1 − 1 = 2.

In Python

def largest_rectangle(heights):
    h = heights + [0]            # sentinel 0 empties the stack
    stack = [-1]                 # h[-1] is that 0: never popped
    best = 0
    for i, x in enumerate(h):
        while x < h[stack[-1]]:  # bar i is the right wall for the top
            top = stack.pop()
            width = i - stack[-1] - 1   # new top is the left wall
            best = max(best, h[top] * width)
        stack.append(i)          # heights on the stack never drop
    return best

print(largest_rectangle([2, 1, 5, 6, 2, 3]))  # → 10

The source's version calls heights.append(0), which grows the caller's list by one 0 on every call; corrected here with heights + [0].

Time O(n) · Space O(n). Each index is pushed once and popped at most once, so the inner while runs at most n times over the whole pass, not n times per step. The stack holds n + 1 indices when the input is sorted ascending.

Why it beats the alternatives

✗ Try every pair (i, j)

Keep a running minimum; area = min × (j − i + 1). Always O(n²): 21 pairs for n = 6, 50,005,000 for n = 10⁴.

✗ Expand from each bar

Walk left and right while bars are at least as tall. Fine on random bars, O(n²) on sorted ones: on 1, 2, …, n bar i walks all the way to the end.

✗ Split at the minimum

Best of (min × width, left part, right part). O(n log n) with balanced splits, O(n²) on sorted input where each split peels off one bar. Needs a range-min structure to be safe.

✓ Monotonic stack

One pass, O(n) always. 7 pushes and 6 pops for n = 6; at most 2n + 1 stack operations in general, so ≤ 20,001 for n = 10⁴.

Is it always the tool?

Reach for it whenever each element needs its nearest smaller (or larger) neighbour on one side: next greater element, daily temperatures, trapping rain water, sum of subarray minimums, and the largest rectangle of 1s in a 0/1 matrix (run this card once per row). Keep heights increasing to find the next smaller; keep them decreasing to find the next greater. These uses are standard practice, not from the source.

It's the wrong tool when elements also expire from the left, as in a sliding-window maximum: the stack can only drop from the top, so use a monotonic deque. And for answers over arbitrary ranges asked later, use a sparse table or segment tree instead.
