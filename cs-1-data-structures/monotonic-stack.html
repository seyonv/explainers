Monotonic stack

Also called an increasing stack or a next-smaller-element stack. A stack whose values stay sorted, so each new element pops everything it beats. The source guide uses it for Largest Rectangle in Histogram, under Stacks.

Prime · 2 minutes before you read

The problem: Largest Rectangle in Histogram asks, for every bar, how far it can stretch left and right before a shorter bar stops it. Trying every pair of walls is 50,005,000 pairs at n = 10⁴; expanding from each bar is O(n²) on sorted input.

Where it fits: Follows the parsing stack: same push and pop, but now the pops are triggered by comparing values rather than matching brackets. It is the one-sided cousin of the monotonic deque, and it uses the same each-index-once argument from the Big-O card.

Builds on: Stacks for parsing · Monotonic deque · Big-O and amortized O(1)

You'll meet: a stack of indices whose heights never drop right wall: the bar that triggers the pop left wall: the index under the popped one sentinels: an appended 0 and a −1 at the bottom next smaller / next greater element as the general pattern

By the end: Find, for every element, its nearest smaller neighbour on both sides in one O(n) pass, and use it to solve Largest Rectangle in Histogram.

In one breath

Keep a stack of indices whose heights never drop. When a shorter bar arrives, the taller bar on top has just found both of its walls: the new bar on its right and the bar beneath it on the stack on its left. So its widest rectangle is known, and it can be popped and forgotten.

Worked example: heights = [2, 1, 5, 6, 2, 3] → 10

area of the popped bar = h[top] × (i − new top − 1) bar i = 2 (h 5): 5 × (4 − 1 − 1) = 5 × 2 = 10

The bar at i = 2 can stretch right until the first shorter bar (i = 4, h 2) and left until the first shorter bar (i = 1, h 1). Both walls are excluded, so the width is 4 − 1 − 1 = 2.

In Python

def largest_rectangle(heights):
    h = heights + [0]            # sentinel 0 empties the stack
    stack = [-1]                 # h[-1] is that 0: never popped
    best = 0
    for i, x in enumerate(h):
        while x < h[stack[-1]]:  # bar i is the right wall for the top
            top = stack.pop()
            width = i - stack[-1] - 1   # new top is the left wall
            best = max(best, h[top] * width)
        stack.append(i)          # heights on the stack never drop
    return best

print(largest_rectangle([2, 1, 5, 6, 2, 3]))  # → 10

The source's version calls heights.append(0), which grows the caller's list by one 0 on every call; corrected here with heights + [0].

Time O(n) · Space O(n). Each index is pushed once and popped at most once, so the inner while runs at most n times over the whole pass, not n times per step. The stack holds n + 1 indices when the input is sorted ascending.

Why it beats the alternatives

✗ Try every pair (i, j)

Keep a running minimum; area = min × (j − i + 1). Always O(n²): 21 pairs for n = 6, 50,005,000 for n = 10⁴.

✗ Expand from each bar

Walk left and right while bars are at least as tall. Fine on random bars, O(n²) on sorted ones: on 1, 2, …, n bar i walks all the way to the end.

✗ Split at the minimum

Best of (min × width, left part, right part). O(n log n) with balanced splits, O(n²) on sorted input where each split peels off one bar. Needs a range-min structure to be safe.

✓ Monotonic stack

One pass, O(n) always. 7 pushes and 6 pops for n = 6; at most 2n + 1 stack operations in general, so ≤ 20,001 for n = 10⁴.

Is it always the tool?

Reach for it whenever each element needs its nearest smaller (or larger) neighbour on one side: next greater element, daily temperatures, trapping rain water, sum of subarray minimums, and the largest rectangle of 1s in a 0/1 matrix (run this card once per row). Keep heights increasing to find the next smaller; keep them decreasing to find the next greater. These uses are standard practice, not from the source.

It's the wrong tool when elements also expire from the left, as in a sliding-window maximum: the stack can only drop from the top, so use a monotonic deque. And for answers over arbitrary ranges asked later, use a sparse table or segment tree instead.

Understand and remember

  • Heights on the stack never drop → a shorter bar i arrives → it is the first shorter bar to the right of every taller bar on top → the index beneath each popped bar is the first shorter bar to its left → both walls known → area = h × (i − new top − 1) → pop and forget
  • Each index is pushed once and popped at most once → the inner while totals ≤ n pops over the whole pass → O(n), at most 2n + 1 stack operations (≤ 20,001 at n = 10⁴ vs 50,005,000 pairs)
  • Sentinel 0 appended at the end → every leftover bar gets popped and scored → the −1 at the bottom reads h[−1] = that same 0, which nothing is shorter than → no empty-stack checks
  • detail that matters Pop only strictly taller bars (x < h[top]) → equal bars stay stacked → an earlier equal bar is scored with too small a width, but the last equal bar popped spans the whole run → the maximum is still right

3 · Retrieve from memory, card closed
  1. concept Explain why the bar on top of the stack can be scored the instant a shorter bar arrives, and never later.
    Check
    • the arriving bar is the first shorter bar to its right: its right wall
    • everything between it and the bar below it on the stack was at least as tall (those were popped earlier), so the bar below is its left wall
    • its widest rectangle is now fixed, so it can be popped and forgotten
  2. mechanism Walk through the sentinel step i = 6 for heights [2, 1, 5, 6, 2, 3] with the stack holding indices −1, 1, 4, 5.
    Check
    • h[6] = 0 pops index 5 (h 3): width 6 − 4 − 1 = 1, area 3
    • pops index 4 (h 2): width 6 − 1 − 1 = 4, area 8
    • pops index 1 (h 1): width 6 − (−1) − 1 = 6, area 6
    • stops at −1 because h[−1] is the 0 itself; best stays 10
  3. tradeoff Why not split at the minimum bar recursively (best of min × width, left part, right part)? What would you need to make it safe?
    Check
    • it is O(n log n) with balanced splits
    • on sorted input each split peels off one bar: O(n²)
    • a range-minimum structure (segment tree or sparse table) makes finding the minimum fast, but the stack is simpler and always O(n)

vs Monotonic deque: Both keep indices in sorted value order. What does a pop mean in each, and why does the deque need a second exit?

  • deque back pop: the popped value can never again be the window max
  • the deque also expires the front because the window slides; the histogram has no expiry
  • both are O(n) because each index enters and leaves once

vs Stacks for parsing: The parsing stack pops on a matching closer; this stack pops on a smaller value. What does each stack's content mean at any moment?

Check
  • parsing: the open contexts, innermost on top
  • monotonic: bars still waiting for a shorter bar on their right, in increasing height
  • both push and pop each item once: O(n)
  • parsing depth follows nesting; monotonic depth reaches n + 1 on ascending input

5 · Predict commit to an answer before revealing

Run the algorithm on [2, 2, 2]. Before tracing: which bars get popped with the wrong (too small) width, and is the final answer still right?

Reveal

The first two bars are scored with widths 1 and 2 (areas 2 and 4) because equal bars aren't popped until the sentinel, and each pop sees an equal bar, not a shorter one, underneath. The last one popped reaches the −1 marker with width 3, area 6, which is correct. The maximum is right because the last bar of any run of equal heights always gets the full width.
