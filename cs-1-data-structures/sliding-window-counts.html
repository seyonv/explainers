Sliding window with counts

Also called the variable-size window, two pointers with a frequency map, or the "need" counter. The cheat-sheet uses it twice under Hash › Maps, both in C++: Minimum Window Substring and Substring with Concatenation of All Words.

In one breath

Grow the window to the right until it holds everything you need, then shrink it from the left until it's just about to stop being valid, recording the answer as you go. A dictionary of "still owed" counts plus one integer, missing, tells you in O(1) whether the window is valid, so each pointer only ever moves forward.

Worked example: s = "ADOBECODEBANC", t = "ABC" → "BANC"

The window is s[left:right], right end excluded. ADOBEC is valid but 6 long; BANC = s[9:13] is 4 long and nothing shorter holds an A, a B and a C.

need = Counter(t) = {A: 1, B: 1, C: 1} missing = len(t) = 3 grow (add ch=s[r−1]): if need[ch] > 0: missing −= 1; need[ch] −= 1 shrink (drop s[left]), while missing == 0: record; need[s[left]] += 1; if now > 0: missing += 1; left += 1

In Python

from collections import Counter

def min_window(s, t):
    need = Counter(t)          # chars still owed; < 0 means spare
    missing = len(t)           # total chars still owed
    left, best = 0, None
    for right, ch in enumerate(s, 1):    # window is s[left:right]
        if need[ch] > 0:
            missing -= 1       # ch paid off a debt
        need[ch] -= 1
        while missing == 0:    # valid: shrink from the left
            if best is None or right - left < best[1] - best[0]:
                best = (left, right)
            need[s[left]] += 1
            if need[s[left]] > 0:
                missing += 1   # dropped a char we needed
            left += 1
    return s[best[0]:best[1]] if best else ""

print(min_window("ADOBECODEBANC", "ABC"))   # → BANC

Same logic as the source's C++, which packs grow and shrink into one for header; its code is correct (checked against a brute force on 3,000 random cases).

Time O(|s| + |t|) · Space O(σ), σ = distinct characters. Each index enters the window once (right) and leaves at most once (left), and each move is O(1) because missing replaces comparing two whole counters.

Same idea with words: the k-offset trick

Substring with Concatenation of All Words: find every start where words (all of length k) appear back to back in any order. Treat each k-letter chunk as one "character". An answer can start at any index, so run k separate windows, one per offset 0 … k − 1, each stepping k letters at a time. A chunk not in words resets the window; a chunk you already have enough of shrinks it from the left.

s = "barfoothefoobarman", words = ["foo", "bar"], k = 3 → [0, 9]. Both answers sit on offset 0; offsets 1 and 2 see only strangers. Each offset checks about m / k chunks, so k offsets check about m chunks in all, each an O(k) slice: O(m · k), against O(m · n · k) for testing every start.

Why it beats the alternatives

✗ Check every substring

Count each s[i:j] and test it. 13 · 14 / 2 = 91 substrings and 455 characters counted here; O(m²) windows in general, O(m³) if you recount each one.

✗ Compare two counters

Slide the same two pointers but test validity with Counter(t) <= window. Correct, but each test walks the whole alphabet: O(m · σ) instead of O(m).

✗ Binary search the length

Validity is monotone in length, so test fixed windows of length L and halve. Works in O(m log m) and needs a fixed-window pass per guess; more code for a slower answer.

✓ Grow right, shrink left

One pass, O(m + |t|). The integer missing makes "is it valid?" O(1). 23 pointer moves for this 13-letter string.

Does every window problem work this way?

No. Shrinking from the left is only safe when validity is monotone: a valid window stays valid if you grow it, and an invalid one stays invalid if you shrink it. "Contains all of t", "at most k distinct" and "sum ≥ target with non-negative numbers" all qualify. "Subarray sum equals k" with negative numbers does not: dropping a negative raises the sum, so use a prefix-sum dictionary instead. "Exactly k distinct" is usually solved as at-most(k) − at-most(k − 1). These are standard practice, not from the source.

If the window size is fixed (a max, a median, an average over every k), there's no shrink decision at all: use a monotonic deque or two heaps. And when the answer needs the whole window's order, not just counts, a dictionary isn't enough.
