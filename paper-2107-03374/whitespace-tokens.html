Whitespace-run tokens

Also: the Codex code lexer, an extended GPT-3 text tokenizer · Codex keeps the GPT-3 text tokenizer and adds tokens for whitespace runs of different lengths, representing code in roughly 30% fewer tokens (Section 3.2).

In one breath

A tokenizer trained on prose has no efficient symbol for “eight spaces”, so it chops Python indentation into several tokens per line. Adding one token per whitespace-run length makes indentation nearly free, and the paper reports about 30% fewer tokens for the same code.

The example is built so the arithmetic is checkable: it lands at 20.7%, below the paper's 30%, because real Python averages deeper nesting and more blank-line and alignment whitespace than a 10-line function. The 2,926 figure is derived from the 30% claim, not stated in the paper.

Why it beats the alternatives

✗ Use the GPT-3 text tokenizer unchanged

What the paper starts from. Its stated problem: the largest source of inefficiency is encoding whitespace, wasting roughly a third of every context window on indentation.

✗ Train a fresh BPE vocabulary on code

More efficient on code, but throws away the GPT-3 text representations the paper is explicitly trying to reuse — Codex is prompted with English docstrings.

✗ Strip or normalise indentation before tokenizing

Indentation is syntax in Python. Removing it changes the program; the model would have to reinvent block structure.

✓ Text tokenizer plus whitespace-run tokens

Keeps GPT-3's natural-language vocabulary intact and adds only the symbols code needs. ~30% shorter sequences means more code per context and cheaper training per line.

How much does this actually matter?

It is an efficiency change, not a capability change. The paper reports no ablation isolating the tokenizer's effect on pass@k, so “30% fewer tokens” should be read as 30% more code per context window and per training step — not as a quality claim.

The gain is also language-specific. It is large for Python, where indentation is syntax; it would be smaller for brace-delimited languages, and the paper only trains and evaluates on Python.
