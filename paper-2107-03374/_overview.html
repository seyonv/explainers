Evaluating large language models trained on code

Mark Chen, Jerry Tworek, Heewoo Jun, Qiming Yuan and 54 others (OpenAI) · arXiv:2107.03374v2 · July 2021

The problem in one breath

Nobody knew how good a large language model could get at actually writing working code, partly because the usual way of scoring generated code — comparing its text to a reference answer — says nothing about whether the code runs correctly. This paper fine-tunes GPT on GitHub Python, builds a hand-written benchmark that runs the code against unit tests, and reports what the model can and cannot do.

What they did

Stage names are the paper's own. The paper does not state the exact count of curated supervised problems; it reports 10,000 from competitive programming plus about 40,000 from continuous-integration tracing, before filtering.

pass@1 is the chance a single generated function passes all of the problem's unit tests; pass@100 is the chance at least one of 100 samples does. The abstract leads with 28.8% for Codex and 70.2% solved with 100 samples per problem. All Figure 1 samples are drawn at temperature 0.8.

Why it matters / what to be careful about

✓ Why it matters

Functional correctness, scored by running unit tests, replaces BLEU-style text matching as the benchmark for code generation. HumanEval is released publicly.

Drawing many samples is a surprisingly strong strategy: 100 samples lift Codex-S-12B from 37.7% to 77.5%.

Even without an oracle, ranking 100 samples by mean token log-probability solves 44.5% — a usable deployment recipe.

✗ What to be careful about (the paper's own limitations)

Not sample efficient: it trains on hundreds of millions of lines, far more code than any developer sees, and a strong intro-CS student would still beat Codex-12B.

Performance falls roughly 2–3× per extra chained instruction in a docstring, and it mis-binds operations to variables.

Misalignment: given subtly buggy context, it writes worse code than it is capable of, and the gap grows with model size. It can also emit insecure or biased code.
