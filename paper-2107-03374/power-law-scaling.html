Power-law test-loss scaling

Also: a scaling law, in the sense of Kaplan et al. (2020) · Codex's cross-entropy loss on a held-out split of the Python GitHub corpus follows (N / 5.92 × 107)−0.13, where N is non-embedding parameters (Section 3.3, Figure 4).

Prime · 2 minutes before you read

The problem: Training a bigger model is expensive, so you want to know in advance what it will buy. Without a predictable relationship between size and loss, every scale-up is a gamble.

Where it fits: The model-building half of the deck: after the tokenizer, this card asks how Codex's loss changes with parameter count, and whether the known text scaling law survives code fine-tuning.

Builds on: pass@k · HumanEval

You'll meet: L(N) = (N / 5.92×10⁷)^−0.13 non-embedding parameters N straight line on a log-log plot loss vs pass@k (sigmoid in log-parameters)

By the end: Evaluate the fitted law at a given size, turn its exponent into 'how much lower loss per 10× parameters', and explain why lower loss doesn't directly predict pass@k.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. What does an exponent of −0.13 mean in plain words: how much does 10× more parameters lower the loss?
  2. Why does the loss curve look like a straight line while pass@k versus size looks like a sigmoid?
  3. The law is fitted on held-out GitHub Python. Why does that make it a weak predictor of HumanEval scores?
  4. Over what range of sizes was the law fitted, and what does that say about using it for a 120B model?

In one breath

Make the model bigger and its loss falls along a straight line on a log-log plot — not toward zero, but by a fixed percentage for every fixed multiple of parameters. The paper's finding is that this relationship, established for language models, survives code fine-tuning unchanged in form.

Worked example: the formula evaluated at each Codex size

L(N) = (N / 5.92e7) ^ -0.13 N = non-embedding parameters L(12e9) = (202.70) ^ -0.13 = exp(-0.13 x 5.3117) = 0.501 L(2.5e9) = ( 42.23) ^ -0.13 = exp(-0.13 x 3.7432) = 0.615 L(300e6) = ( 5.068) ^ -0.13 = exp(-0.13 x 1.6229) = 0.810 L( 12e6) = ( 0.2027) ^ -0.13 = exp(-0.13 x -1.596) = 1.231

Substituting the nominal model names for N is illustrative: the formula is defined on non-embedding parameters, and the paper does not give those counts.

How it differs from related ideas

✗ Kaplan et al. (2020) scaling law for text

Same functional shape, fitted on natural language. The contribution here is showing the shape holds “even after code fine-tuning”, with its own constants.

✗ pass@1 and pass@100 vs model size (Figure 6)

Not a power law. The paper describes these as scaling “smoothly as a sigmoid in log-parameters” — a different curve from the loss.

✗ Parameter-efficiency comparisons

Statements like “GPT-J-6B matches Codex-300M, 20× fewer parameters” are read off the fitted curves; they are consequences of scaling, not the law itself.

✓ This loss power law

A one-line predictor for held-out cross-entropy from parameter count alone. Exponent −0.13 is shallow: each 10× in N buys a factor of 100.13 = 1.35× lower loss.

Does lower loss mean better code?

Not directly, and the paper never claims it does. The power law is fitted on held-out GitHub Python — the training distribution — while pass@k is measured on hand-written HumanEval problems. Codex-S improves pass@k substantially without the loss curve being the thing that moved.

Extrapolating is risky in both directions. The exponent is fitted over the sizes the paper actually trained, 12M to 12B, and the paper gives no confidence interval on −0.13 or on 5.92 × 107. Loss also does not track the failures Section 6 cares about: Appendix G.3 finds no robust size trend at all for insecure code generation.

Understand and remember

  • Loss follows a power law in N → a fixed multiple of parameters gives a fixed ratio of loss → each 10× in N lowers loss by 10^0.13 ≈ 1.35× → diminishing absolute gains, but predictable ones
  • The law is fitted on the training distribution (held-out GitHub Python) → pass@k is measured on hand-written HumanEval → the two needn't move together, e.g. Codex-S raises pass@k without it being a loss-curve effect
  • pass@k is a thresholded quantity (does any sample pass all tests) → small per-token gains cross the threshold for many problems at once → pass@k scales like a sigmoid in log-parameters, not a power law
  • Fitted over 12M to 12B with no confidence interval → extrapolating past 12B is a guess → the formula predicts loss only, not safety or security trends (G.3 finds none for insecure code)
  • detail that matters N counts non-embedding parameters → plugging in nominal model names is only approximate → the card's per-size losses are illustrative, not the paper's measured values

Reference only

  • the constants 5.92×10⁷ and −0.13
  • Kaplan et al. (2020)
  • the per-size predicted losses (1.231, 0.810, 0.615, 0.501)

Why this step?

5 · Predict commit to an answer before revealing

Extrapolate the law to a 120B model. What loss does it predict, and would you bet that pass@1 rises by the same ratio as the loss falls? Commit, then reveal.

Reveal

L(120×10⁹) = (2027)^−0.13 ≈ 0.372, which is 1.35× lower than 12B's 0.501. But pass@1 isn't tied to that ratio: from 300M to 12B the loss fell 1.62× while pass@1 rose 2.2× (13.17% → 28.81%). Because pass@k follows a sigmoid, the gain could be bigger or smaller depending on where on the S-curve 12B sits, and 120B is outside the fitted range anyway.
