Codex-S

Also: the supervised fine-tuned Codex · A second fine-tuning stage on curated standalone-function problems, trained at 1/10 the Codex learning rate with prompt loss masked. Gains average 6.5 points on pass@1 and 15.1 points on pass@100 across model sizes (Section 4).

Prime · 2 minutes before you read

The problem: Codex learns from all of GitHub Python: classes, scripts, configs, data files. Very little of that looks like 'here is a docstring, write the function', which is the task HumanEval tests.

Where it fits: The second training stage. It takes Codex (fine-tuned on GitHub, with the whitespace tokenizer) and fine-tunes again on ~50k test-verified problems from competitive programming and CI tracing.

Builds on: HumanEval · Sampling temperature · Power-law test-loss scaling

Used in the field guides: Project 4: Base model to assistant, and a reward model that beats chance and length (Models Field Guide) · Principle 10: Mask the prompt in the SFT loss. (Models Field Guide)

You'll meet: distribution mismatch loss masked on prompt tokens 1/10 learning rate, under 10B tokens a 100-sample filter using Codex-12B narrower distribution → higher T*

In one breath

Codex is fine-tuned on all of GitHub Python — classes, config files, scripts, even data files — which is a poor match for “write the function this docstring describes”. Codex-S fixes that distribution mismatch by fine-tuning again, this time only on problems shaped exactly like the evaluation task.

Why it beats the alternatives

✗ Train Codex longer on GitHub

More of the same mismatch. Most GitHub Python is not a standalone function preceded by a specifying docstring.

✗ Start from GPT-3 instead of GPT

The paper tried the analogous idea one stage earlier and found no improvement from pre-trained language representations, “possibly because the fine-tuning dataset is so large” — only faster convergence.

✗ Scale up parameters instead

Works, but expensively. Figure 10 puts Codex-S one to two orders of magnitude ahead in parameter efficiency at both pass@1 and pass@100.

✓ Supervised fine-tuning on task-shaped problems

Cheap (under 10B tokens against 100B for Codex) and consistent across every model size. Masking prompt loss means the gradient only ever rewards writing the body.

Is Codex-S strictly better?

On HumanEval, yes at every size the paper tested — but it is a narrower model. The paper infers from Figure 9 that Codex-S “captures a narrower distribution”, since it needs a higher temperature than Codex at every k > 1 to get the same diversity (T* = 0 at pass@1, T* = 1 at pass@100).

There is also a circularity worth naming: the training problems were filtered using Codex-12B's own samples, so problems the model family finds hard were removed from its supervision. And the curated problems were assembled into the same format as HumanEval, which is the benchmark it is then scored on. The paper is upfront that the gain comes from “training on a distribution more similar to the evaluation set”.

5 · Predict commit to an answer before revealing

Suppose you removed the 100-sample filter and trained Codex-S on all ~50k problems, including those no Codex-12B sample solved. Would HumanEval pass@1 go up, down, or stay roughly the same? Commit, then reveal.

Reveal

The paper doesn't test this, so reason from its stated purpose: the filter removes ambiguous, stateful, non-deterministic or broken problems. Training on those teaches the model to reproduce bodies that don't match their docstrings, which would likely hurt. A few genuinely hard, valid problems would be kept too, which could help a little. The honest answer is 'probably down or flat', and it can't be read off the paper.
