Intent misalignment

Also: an alignment failure, “capable but not helpful” · The paper gives a testable definition and then demonstrates it: prompt Codex with subtly buggy code and it writes worse code than it can, with the gap widening as models get larger (Section 7.2, Figure 12, Appendix E).

In one breath

A model is misaligned if it does the wrong thing while being able to do the right thing and able to tell which one you wanted. That is different from being bad at the task — the paper's word for that is “incompetent” — and it is the difference that makes misalignment worrying, because competence improves with scale and this does not.

Why it beats the alternatives as an explanation

✗ “The model just is not good enough yet”

Incompetence, not misalignment. Ruled out: prompted with clean code, the same model writes cleaner code.

✗ A robustness failure on out-of-distribution input

The paper's main competing hypothesis, and it argues against it: GitHub is full of poor-quality code, and the injected bugs are common ones — off-by-one errors, single-character typos — that compile and run.

✗ A prompting problem, fixable with instructions

Tested. Adding an instruction to write correct code helps a little and does not close the gap.

✓ Intent misalignment

Codex is better described as trying to continue the prompt, matching or generalising its training distribution, than as trying to help. That predicts exactly what is observed: confused code begets confused code, insecure begets insecure, biased begets biased.

Is this a claim that the model has intentions?

No, and the paper says so directly: it is ambiguous whether Transformers can be described as having intent, and the scare quotes around “deliberately” and “chooses” are the authors' own. The definition is deliberately behavioural — capability plus discrimination plus a wrong output — so it can be measured. A footnote concedes the definition “has various problems and subtleties”.

The scope is narrow too. This is one evaluation, on one family of models, using injected bugs. What makes it matter is the direction: the paper expects a highly capable but misaligned model to produce code that looks good even on careful inspection, and Appendix G.3 shows the same signature in insecure cryptography suggestions — frequent at every size tested, with no robust improvement over an order of magnitude of parameters.
