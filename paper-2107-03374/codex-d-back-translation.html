Codex-D and back-translation ranking

Also: the docstring generation model, the back-translation objective · Codex-D writes the docstring given a signature and body; hand-graded at 20.3% pass@1 and 46.5% pass@10 for the 12B model at temperature 0.8, and reused as a sample reranker that underperforms mean log-probability (Section 5, Table 3, Figure 7).

In one breath

Two ideas sharing a section. First, run the pipeline backwards: train a model to describe code rather than write it, because a description of what generated code is trying to do is a safety tool. Second, use that model as a judge — prefer the sample whose docstring the reverse model finds most predictable.

Why it beats the alternatives — and where it does not

✗ Random sample selection

The floor. Back-translation does beat it, which is the positive result here.

✗ Sum log-probability

Penalises length; the paper reports it can land below random.

✗ Back-translation, P(docstring | sample)

Needs a whole second model and an extra forward pass, underperforms mean log-probability, and the paper notes it “appears to overfit quickly”.

✓ Mean log-probability, still

Free, single-model, and the best of the non-oracle heuristics tested. Codex-D's real value in this paper is the safety use — describing the intent behind generated code — not reranking.

Why is the docstring model worse, and how solid is that number?

The paper explicitly says it has “no strong hypothesis for which direction should yield higher pass rates”. It offers two competing guesses: natural-language syntax is more forgiving than code syntax, but developers write docstrings carelessly, so the training targets are lower quality. Codex-D reproduces that carelessness — it emits docstrings like “I just found this function online”.

Treat Table 3 as softer evidence than the rest of the paper. There is no automatic metric for docstrings, so a human judged whether each one “uniquely and accurately specifies the code body”, over 1,640 hand gradings, with the grader's own rules for edge cases (invented unit tests ignored; copying the body into the docstring does not count). The named failure modes are omitting a crucial detail and over-conditioning on the function name.
