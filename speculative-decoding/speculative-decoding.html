Speculative decoding

Also: speculative sampling, draft-and-verify (Leviathan et al. 2023; Chen et al. 2023). A small draft model guesses several tokens ahead, and the big model checks all of them in one forward pass.

Prime · 2 minutes before you read

The problem: A large model writes one token per full pass over its weights, and at small batch each pass mostly waits on memory while the compute units sit idle. Without a way to get more than one token out of a pass, the only speed levers are a smaller model (worse answers) or lower precision (changed answers).

Where it fits: A single card that builds on the memory-bound picture of decoding: reading the weights, not the math, sets the time per token. It turns that idle compute into extra tokens. The perf-5 engine cards then walk the paper's exact acceptance rule and the draft-free variants (Medusa, EAGLE).

In one breath

Generating text with a large model is slow because each token needs a full pass over its weights. Speculative decoding lets a cheap model propose the next few tokens and has the large model verify them in parallel. Every accepted guess is a token you got without paying for another large-model pass, and the rejection rule keeps the output identical in distribution to the large model alone.

Why it beats the alternatives

✗ Just use the small model

Fast, but you get the small model's answers. Quality drops exactly where you needed the big one.

✗ Plain autoregressive decoding

One full pass per token. At small batch sizes the GPU mostly waits on memory reads, so most of its compute sits idle.

✗ Aggressive quantization

Shrinks the weights so each pass is faster, but lower precision can change the outputs, and that has to be re-evaluated.

✓ Speculative decoding

Uses that idle compute to verify several tokens at once. Same output distribution as the big model, typically 2–3× lower latency.

Is it always faster?

No. The gain depends on how often the draft agrees with the target: code and boilerplate accept well, but high-temperature creative sampling accepts poorly and can end up slower than plain decoding. At large batch sizes the GPU is already compute-bound, so there is little idle capacity to exploit. The draft model also costs memory. Variants such as Medusa heads, EAGLE, or n-gram lookup drafting avoid a separate draft model, and quantization stacks with any of them.

Understand and remember

  • Small-batch decode is memory-bound → each pass streams all the weights while compute idles → scoring γ + 1 positions in one pass costs about the same as scoring 1 → the target can verify a whole draft for roughly one pass
  • The draft proposes γ tokens → the target keeps the longest run it agrees with and replaces the first rejected token with its own → every pass yields between 1 and γ + 1 tokens → never fewer tokens per target pass than plain decoding
  • Acceptance is a rejection rule against the target's own distribution → wrong guesses are discarded, not kept → the output is distributed exactly as the target alone would produce → speed changes, quality doesn't (unlike a smaller model or heavy quantization)
  • Speedup = tokens per pass ÷ cost per pass (γ·c + 1) → it needs high α (predictable text) and low c (cheap draft) → at low α, high temperature or large batch the draft work isn't repaid and it can be slower than plain decoding
  • detail that matters Tokens per pass is a geometric series 1 + α + α² + … + α^γ → each extra draft token is worth less, and the total is capped at 1/(1 − α) → past a point a longer draft only adds draft cost (the γ·c term)

Reference only

  • the closed forms (1 − α^(γ+1)) / (1 − α) and ÷ (γ·c + 1) (Leviathan et al. 2023)
  • the reported 2–3× on T5-XXL and 2–2.5× on Chinchilla 70B
  • the variant names: Medusa heads, EAGLE, n-gram lookup drafting
  • the illustrative c = 0.05 and γ = 4 used in the table

4 · Compare against what you already know

vs Speculative decoding I: exact sampling with a draft: This card says the rejection rule keeps the output identical to the target. That card gives the rule: keep with probability min(1, p/q), else resample from max(0, p − q). What does this card's simplified picture hide, and when would the hidden part change your answer?

Check
  • this card shows accept/reject as agree/disagree; the real rule is probabilistic under sampling
  • a draft token is sometimes rejected even when the target gives it some probability (when q > p)
  • the replacement is drawn from the leftover mass, not the target's top token
  • under greedy decoding the two pictures coincide: accept exactly when the tokens match

vs Medusa: extra heads and tree attention: Both speculate and verify in one target pass. What design choice separates a separate draft model from Medusa heads, and how does each one fail?

Check
  • separate draft: a second small model, which has to be found, kept aligned with the target and served (memory, deployment)
  • Medusa: extra heads on the target's last hidden state, so nothing extra to serve, and a tree of candidates checked with tree attention
  • a draft fails when it drifts from the target (low α) or is too expensive (high c)
  • Medusa needs its heads trained per model, and heads further ahead guess less accurately

vs Why constraining can be faster: Fast-forwarding and speculative decoding both emit several tokens per model step. Why does one need a verification pass and the other not, and what limits each?

Check
  • fast-forward appends tokens the grammar forces, so there is nothing to guess and nothing to verify
  • speculation guesses tokens the model actually chooses, so the target must check them
  • fast-forward is limited by how much of the output is forced; speculation by α and c
  • they can stack: forced spans skip sampling, chosen spans can still be drafted

Reveal

Simpler: under greedy both distributions are one-hot, so the test reduces to "accept if the draft's token equals the target's top token". α usually rises, because a sharper distribution is easier to guess. In Leviathan et al.'s Table 3 the T5 drafts all accept more often at temp 0 (T5-small on EnDe: 0.75 vs 0.62), though for their tiny GPT-like target the two are about equal (0.88 vs 0.89). Done when: (1) 1.71×, 2.22×, 2.80×, 3.09×: γ = 8 wins, with diminishing returns (tokens per pass is capped at 1/(1 − 0.8) = 5). (2) 1.78×, 1.92×, 1.77×: γ = 4 wins, and 8 is worse. (3) Lower α makes later draft tokens less likely to be used, while each still costs c. (4) Break-even is α ≈ 0.17 (speedup 1.04× at α = 0.2).

Hint

Tokens per pass = (1 − α^(γ+1)) / (1 − α); speedup = that ÷ (γ·c + 1). At break-even, 1 + α + α² + α³ + α⁴ = 1.2.
