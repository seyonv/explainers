Recursive queries: semi-naïve evaluation

Also called delta iteration or differential fixpoint evaluation; the new facts of each round are the "deltas". It is how Datalog engines compute a recursive query such as transitive closure, and SQL's WITH RECURSIVE works the same way. The source guide states the update rule and the delta rules, then the complexity results for fixpoint and while queries.

In one breath

A recursive query is run by applying its rules over and over until a round adds nothing (the fixpoint). Naïve evaluation re-runs every rule on every fact each round, re-deriving what it already knows. Semi-naïve evaluation joins only the facts that were new last round, because any genuinely new fact must use at least one of them.

Worked example: reachability on a 6-node chain

tc(x, y) :- edge(x, y). base rule: every edge is a path tc(x, y) :- tc(x, z), edge(z, y). a path, then one more edge

edge is stored (EDB); tc is derived (IDB). The answer is every pair i < j: 6 × 5 / 2 = 15 facts.

The update rule and the delta rules

p[i+1]= p[i]known so far ∪ δ(p)[i]new this round δ(p)[i]= Δ(p)[i]derived from deltas −p[i]
p[i]all tc facts known at the start of round iround 3: 9 Δ(p)[i]what the delta rules derive in round i; may repeat old factsround 3: 3 δ(p)[i]the part of Δ that is really new; stop when it is emptyround 3: 3

The source writes p[i + 1] = [i] ∪ Δ(p)[i], dropping the p, and p[i][n − 1] for p[i]n−1 in its last delta rule; corrected here. Adding Δ or δ gives the same p[i + 1]; δ is what feeds the next round.

A rule with several recursive (IDB) atoms gets one delta rule per atom. In rule k, atom k reads last round's δ, the atoms before it read the new p[i], and the atoms after it read the old p[i − 1]. So a combination that uses several new facts is joined once, in the rule for its last new atom, not once per new atom. Stored (EDB) atoms are unchanged.

linear tc(x,y) :- tc(x,z), edge(z,y) 1 IDB atom Δtc[i](x,y) :- δtc[i−1](x,z), edge(z,y) non-linear tc(x,y) :- tc(x,z), tc(z,y) 2 IDB atoms Δtc[i](x,y) :- δtc[i−1](x,z), tc[i−1](z,y) old after the δ Δtc[i](x,y) :- tc[i](x,z), δtc[i−1](z,y) new before the δ

On the same chain the non-linear program takes 5 rounds: naïve makes 81 derivations, semi-naïve 25. That 25 is 5 edges plus the 20 ways to pick x < z < y, each joined exactly once; a fact like 1→4 still arrives twice, via z = 2 and z = 3.

In Python

def join(left, right):            # left(x, z), right(z, y)
    by_z = {}
    for z, y in right:
        by_z.setdefault(z, []).append(y)
    return [(x, y) for x, z in left for y in by_z.get(z, ())]

def naive(edge):
    tc = set()
    while True:
        derived = list(edge) + join(tc, edge)   # redo everything
        new = set(derived) - tc
        if not new:
            return tc
        tc |= new

def semi_naive(edge):
    tc, delta = set(), set(edge)       # round 1: the base rule
    while delta:
        tc |= delta
        derived = join(delta, edge)    # only last round's news
        delta = set(derived) - tc      # δ = Δ − p
    return tc

Time O(V·E) for transitive closure · Space O(V²). Semi-naïve joins each closure fact (x, z) with the edges out of z once, in the round after it appears, which is at most V·E matches in total; naïve redoes all of them every round. On an n-node chain that is n(n − 1)/2 derivations against Θ(n³), so the gap doubles as n doubles: 4.7×, 8.7×, 16.7×, 32.7× for n = 6, 12, 24, 48 (computed).

How hard can a recursive query be?

The source's complexity facts, in plain terms. Datalog never deletes a fact, and with n constants an arity-k predicate has at most nk facts, so a fixpoint arrives within polynomially many rounds: here at most 6² = 36 tc facts, and 15 actually appear. So fixpoint queries are in PTIME, and they are PTIME-complete. A while language, which can also delete, is PSPACE-complete. Neither can ask whether a set has an even number of elements unless the data comes with an order.

A single question, like one actor's Bacon number, doesn't need the whole closure: breadth-first search from that actor visits each reachable node once and each edge twice, Ω(V + E), plus a hash table from name to node so the start is found in constant time. The source contrasts iteration with "direct" algorithms, whose running time doesn't depend on how long the paths are; Warshall's algorithm below is one.

Why it beats the alternatives

✗ Naïve iteration

Correct, same number of rounds, but it re-derives everything each round: 70 derivations for 15 facts, and its last round redoes all 15 only to learn nothing changed.

✗ Top-down recursion

Prolog-style evaluation of tc(x,z), edge(z,y) calls tc before consuming an edge and recurses forever; on a cyclic graph even the other order loops. Needs tabling to terminate (standard practice, not from the source).

✗ Warshall's matrix closure

A "direct" algorithm: V³ = 216 inner steps on 6 nodes whether the graph is a sparse chain or complete. Good for small dense graphs, and it can't run arbitrary rules.

✓ Semi-naïve

Same rounds and same answer as naïve, but each rule body is matched once per combination that uses a new fact: 15 derivations here, one per fact. It is the default in Datalog engines and in WITH RECURSIVE.

Is it always the right tool?

For "compute all derived facts" it is the baseline, but not the whole story. It can still derive a fact twice through different join paths (25 derivations for 15 facts in the non-linear version). If you need one answer, say the reachability from one node, a BFS or a goal-directed rewrite (magic sets) avoids building the full closure. And it only ever adds: when stored facts are deleted, keeping the result current needs a different method, such as counting derivations or delete-and-rederive (standard practice, not in the source).

With negation, programs are evaluated one SCC of the precedence graph at a time, in dependency order, so a predicate is complete before anything negates it (stratification; our addition, since the source introduces the precedence graph without saying what it's for).
