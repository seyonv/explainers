Touching less data

The overview for course 6 of the core CS canon series. It ties together the 17 cards on the source guide's storage, caching, MapReduce, graph-query and case-study pages: how B-trees, LSM trees, caches, in-memory stores, batch jobs, recursive queries and GPU schedulers all win the same way, by cutting the work done per unit of useful work.

In one breath

Every system in this course is judged by one ratio: how much it reads, writes, copies or holds idle for each byte, fact or GPU-hour the user actually wanted. An index reads 1 page instead of 250,000. An LSM tree rewrites each byte about 20 times, but in sequential runs. A cleaner at 90% full copies 9 bytes to free 1. A backfilling scheduler fills GPU-hours that would sit idle. Find the ratio, find what sets it, and remember that lowering one kind (reads) usually raises another (writes, memory, staleness).

The words people use

OLTP, OLAP, batch

OLTP: many small transactions that each touch a few rows (an order, a lookup). OLAP: few queries that each scan a lot. Batch: a whole dataset in, a whole dataset out, like MapReduce. The same A means different things in each, so name the workload first.

Utilization vs goodput

Utilization counts hardware handed out or busy; goodput counts work that survives. A cluster can be 95% allocated while 28% of allocated GPU time sits at 0%, and an hour lost to FAILED_PREEMPTED is busy but not good.

Data vs expression complexity

Grow the database with the query fixed, or grow the query over fixed data. Databases dwarf queries, so data complexity is the usual lens: a fixed join is polynomial, and plain relational queries sit in AC⁰.

✓ Read, write, space amplification

Units touched, rewritten or held per useful unit. They trade against each other: an LSM tree cuts write amplification to 20 but checks several files per read, and a cleaner copies less only if memory runs emptier. Name all three before you pick an engine.

When this advice doesn't apply

Amplification counts units, not time, and the units aren't equal. An LSM tree's 20 rewrites are sequential and a B-tree's 41 are random, which matters far more on a disk than the ratio suggests; a cached page read costs nanoseconds and a disk read milliseconds. Before comparing two A's, check that they count the same kind of step on the same device.

And small data changes the answer. The course's 1 GB orders table fits 24 times in a 24 GB laptop, where a dict or a SQL GROUP BY beats a MapReduce job, and page-level tricks matter less than cache lines. The scheduling cards assume people competing for a shared cluster; a single team with an overnight queue needs only FIFO and a utilization graph. Measure before you add an index, a cache or a cluster.
