In one breath: micrograd's engine is 94 lines of ordinary Python, built from five features: a class, operator overloading (so a*b runs your method), the "reflected" methods __rmul__/__radd__ (so 2*a and sum() work), closures (so each result carries its own little backward function), and a set plus recursion (to put the graph in order). Learn them on a toy class first, and Lecture 1 becomes pure math.

Predict first: a Money class defines __mul__, so m1 * 3 works. Without __rmul__, what does 3 * m1 do?

It crashes: TypeError: unsupported operand type(s) for *: 'int' and 'Money' (measured). Python always asks the left operand first, so it tries int.__mul__(3, m1). An int has no idea what Money is and answers NotImplemented. Only then does Python try the right operand's m1.__rmul__(3), and there isn't one. Add __rmul__ and you get Money(cents=750).

What Python really calls

A method whose name starts and ends with two underscores ("dunder") is a hook: Python calls it for you when you use an operator. The toy class Money holds a number of cents; m1 = Money(250), m2 = Money(100).

The r in __rmul__ means "reflected": the method Python tries on the right-hand operand when the left one gives up. Without __radd__, sum() fails on its very first step, 0 + m1 (computed: unsupported operand type(s) for +: 'int' and 'Money').

Closures: a function that remembers where it was made

A function defined inside another function can still see that outer function's variables after the outer one has returned. That bundle, a function plus the variables it captured, is a closure. micrograd's __mul__ defines a tiny _backward that uses self, other and out, stores it as out._backward, and returns. Much later, backprop calls out._backward(), and it still knows exactly which two Values to send gradient to.

def make_backward(name, log):
    def _backward():              # sees name and log later
        log.append(f'backward of {name}')
    return _backward                # the function, not a call
log = []
fns = [make_backward(n, log) for n in ['a', 'b', 'c']]
for f in reversed(fns):
    f()
print('closure calls:', log)
closure calls: ['backward of c', 'backward of b', 'backward of a']

Each call to make_backward captured its own name. Writing return _backward(), with brackets, stores the call's result, None; calling it later raises 'NoneType' object is not callable (computed), the slip Karpathy makes on camera in the 1:09:02 chapter.

A set and recursion: putting the graph in order

Backprop may only run a node's _backward once that node's own gradient is complete, meaning after every node that uses it has run. micrograd gets that order from build_topo: a recursive function (it calls itself on each input) that appends a node only after all of its inputs, and a set called visited (fast "have I seen this?" checks) so a shared node is never added twice. The result is a topological order; reversed, it's the backprop order.

topo order    : ['a', 'b', 'e', 'c', 'd', 'f', 'L']
reversed topo : ['L', 'f', 'd', 'c', 'e', 'b', 'a']

Measured with the lab's plain-dict version of the graph. In micrograd, _prev is a set, so siblings like a and b can come out in either order; the "inputs before users" guarantee holds either way.

List comprehensions and sum()

A list comprehension builds a list in one expression: [x * x for x in range(5)] gives [0, 1, 4, 9, 16], and sum(x * x for x in range(5)) gives 30 (measured). micrograd uses both for a neuron: sum((wi*xi for wi, xi in zip(self.w, x)), self.b) multiplies weights by inputs pairwise (zip pairs up two lists) and adds them, starting the sum from the bias self.b instead of 0. Collecting every parameter of a network is a nested comprehension: [p for layer in self.layers for p in layer.parameters()].

class Money:
    def __init__(self, cents):
        self.cents = cents
    def __repr__(self):
        return f"Money(cents={self.cents})"
    def __add__(self, other):
        other = other if isinstance(other, Money) else Money(other)
        return Money(self.cents + other.cents)
    def __mul__(self, k):
        return Money(self.cents * k)
    def __rmul__(self, k):     # k * self falls back here
        return self * k
    def __radd__(self, other): # lets sum() start from 0
        return self + other
m1, m2 = Money(250), Money(100)
print('m1 + m2      =', m1 + m2)
print('3 * m1       =', 3 * m1)
del Money.__rmul__             # now break it on purpose
try:
    3 * m1
except TypeError as e:
    print('3 * m1 without __rmul__ -> TypeError:', e)
print('sum([m1, m2, m1]) =', sum([m1, m2, m1]))

You should see (measured on your M3; the lab also runs the closure and build_topo demos above):

Why micrograd is written this way, not the alternatives

✗ Plain function calls

mul(add(mul(a, b), c), f) builds the same graph as (a*b + c)*f, but every formula has to be rewritten inside out, and a neuron's formula is already long.

✗ Only __add__ and __mul__

2 * a and sum(...) raise TypeError, because a plain number on the left gives up. You'd have to reorder or wrap every constant by hand.

✗ One big backward with if op == '*'

It works, but each new operation means editing two places, and the derivative lives far away from the forward code it belongs to.

✓ Dunder methods + closures

Formulas read like math, each operation writes its local derivative right beside its forward code, and the result carries that closure along until backprop calls it.

Where this Python bites

Closures made in a loop share the loop variable. [lambda: i for i in range(3)] gives functions that all return 2, not 0, 1, 2 (computed): they capture the variable i, not its value at the time. micrograd never hits this, because every _backward is made in a separate method call with its own self, other and out. If you ever build closures in a loop, pass the value in (lambda i=i: i gives 0, 1, 2).

Recursion has a depth limit. Python 3.10.14 stops at 1,000 nested calls by default, so micrograd's recursive build_topo handles a chain of 995 additions and raises RecursionError at 996 (computed). That's plenty for the lecture's small nets. For deep graphs you'd write the search with an explicit stack instead, and tensors (z2h-3 onwards) shrink the graph to one node per whole-array operation anyway.

Understand and remember

  • x * y first calls x.__mul__(y) → a plain int doesn't know your class and returns NotImplemented → Python then tries y.__rmul__(x) → without it 2*a is a TypeError, and sum() (which starts from 0) fails the same way without __radd__
  • Operators are method calls → the method creates the result object itself → it can attach anything to that result (micrograd: the parents, the op and a backward function) → ordinary-looking formulas build the graph
  • A function defined inside a method captures that call's variables → it can be stored on the result and called much later → each result carries its own local-derivative code for backprop to run
  • build_topo appends a node only after recursing into all its inputs → every node sits after its inputs → reversed, every node's gradient is complete before its _backward runs; the visited set stops a shared node running twice (without it, a.grad comes out 96 or 102 instead of 66 in the Predict step)
  • detail that matters Recursion depth is capped (1,000 frames by default in Python 3.10.14) → micrograd's recursive build_topo handles a chain of 995 additions and raises RecursionError at 996 → fine for the lecture's nets, but deep graphs need an explicit stack
