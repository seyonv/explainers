Matrix multiply by shapes

Also called: matmul, the @ operator, torch.matmul, "a batch of dot products". Lecture 2 · the "neural net": one linear layer of neurons implemented with matrix multiplication · 1:13:53

Prime · 2 minutes before you read

The problem: A layer has many neurons and training feeds it many examples at once. Computing every neuron on every example with separate dot products means nested Python loops, and when the shapes don't line up you get errors you can't read.

Where it fits: It builds on the dot product card: one neuron is one dot product. This card stacks many neurons and many examples so that a whole layer becomes one operation, X @ W + b, which every lecture from the bigram net to GPT uses.

In one breath: a matrix multiply A @ B takes every row of A and dots it with every column of B, and it puts each answer in a grid. You rarely need to picture the numbers. The shapes tell you everything: (n, k) @ (k, m) gives (n, m), and the two inner ks must match.

Predict first: A is (2, 3) and B is (3, 2), so A @ B is (2, 2). What does B @ A give: the same (2, 2) grid, an error, or something else?

Something else: a (3, 3) grid. The shapes are (3, 2) @ (2, 3). The inner 2s match, so it works, and the outer 3s become the result's shape. Its rows are [1, 2, 3], [4, 5, 6] and [−3, −3, −3] (computed), which have nothing in common with A @ B. Order matters, unlike ordinary multiplication.

Why a whole batch through a layer is one matmul

A neuron computes a dot product of its inputs with its weights, plus a bias (the vectors card: x·w + b). A layer is many neurons reading the same input. So put each neuron's weights in a column of W, and put each example in a row of X. Then row i · column j is "neuron j on example i", which is exactly what a matmul computes for every pair at once. This is the MLP's hidden layer in makemore Part 2: emb.view(-1, 6) @ W1 + b1 takes 32 examples of 6 numbers into 100 neurons.

Karpathy checks one entry the same way at 1:13:53: in the bigram net, element [3, 13] of xenc @ W is neuron 13 firing on input 3, and it equals (xenc[3] * W[:, 13]).sum().

More than two dimensions, and counting parameters

Batched matmul. @ only multiplies the last dimension of the left with the first of a 2-D right. Any extra leading dimensions just come along as a batch: (4, 5, 80) @ (80, 200) gives (4, 5, 200) (lab), which is 4 × 5 = 20 rows, each through the same 200 neurons. WaveNet (z2h-7) relies on this at 21:36.

Parameters of a linear layer. W has fan_in × fan_out weights (fan_in = inputs per neuron, fan_out = number of neurons), and b has one bias per neuron:

import torch
A = torch.tensor([[1., 2., 3.], [4., 5., 6.]])     # (2, 3)
B = torch.tensor([[1., 0.], [0., 1.], [1., -1.]])  # (3, 2)

H = X @ W + b
print('X', tuple(X.shape), '@ W', tuple(W.shape),

loop = torch.stack([X[i] @ W + b for i in range(32)])
print('same as looping over the 32 rows:',
      torch.allclose(H, loop, atol=1e-5))

Why it beats the alternatives

✗ Loop over the examples

torch.stack([X[i] @ W + b for i in range(32)]) gives the same (32, 100), but it makes 32 separate calls from Python, and the loop grows with the batch.

✗ Elementwise A * B

Multiplies matching positions and never sums. On (2, 3) and (3, 2) it fails with a broadcasting error ("size of tensor a (3) must match … b (2)", computed) instead of combining rows with columns.

✗ One Python object per number

micrograd's neuron sums w·x over Value objects one at a time. That's clear for a tiny net but far too slow for the 11,897 numbers of the makemore MLP, let alone more.

✓ One matmul per layer

X @ W + b does all 3,200 dot products in one call inside PyTorch. The same line works for 5 examples or for all 228,146 bigrams in names.txt.

Which way round is W?

Karpathy's hand-written layers store W as (fan_in, fan_out), so they read X @ W. PyTorch's nn.Linear(6, 100) stores its weight the other way, as (100, 6), and computes X @ weight.T + bias. Writing X @ lin.weight fails with "mat1 and mat2 shapes cannot be multiplied (32x6 and 100x6)" (computed). When a shape error appears, write the shapes side by side and check that the inner two match.

A matmul is also not always the right tool. If one side is a one-hot vector, the product just picks out one row of W, so indexing W[ix] gives the same answer without the multiplies (L2 at 1:47:49; the embedding table in z2h-4). To scale each number separately, use * instead.

Understand and remember

  • Entry C[i, j] is row i of A dotted with column j of B → a dot product needs two vectors of the same length → the left's columns must equal the right's rows (k) → that k is summed away and only (n, m) survives
  • A neuron is x·w + b → put each example in a row of X and each neuron's weights in a column of W → X @ W computes every neuron on every example at once → a whole batch through a layer is one matmul, whatever the batch size
  • @ only multiplies the last dimension of the left with the first dimension of a 2-D right → any extra leading dimensions pass through as a batch → (4, 5, 80) @ (80, 200) gives (4, 5, 200), the same layer applied to 20 rows
  • W holds fan_in weights for each of fan_out neurons, and b holds one bias per neuron → parameters = fan_in·fan_out + fan_out → layer sizes, not data, set the parameter count (e.g. 270 + 6200 + 5427 = 11,897 for the makemore MLP)
  • detail that matters The loop and the matmul add the same six products in a different order → float32 rounding differs in the last digits → compare them with a tolerance (atol=1e-5), not exact equality
  • detail that matters nn.Linear stores its weight as (fan_out, fan_in) and computes x @ weight.T → X @ lin.weight raises a shape error → always check which convention a layer uses before multiplying by its weight

Reference only

  • the error text "mat1 and mat2 shapes cannot be multiplied (3x2 and 3x2)"
  • torch.matmul and @ are the same operation; 1-D @ 1-D is a plain dot product
  • the lab's numbers: A @ B = [[4, −1], [10, −1]]; B @ A is (3, 3)
  • Karpathy's notebook lines: xenc @ W (bigram), emb.view(-1, 6) @ W1 + b1 (MLP)

  1. concept Explain why the rule is (n, k) @ (k, m) → (n, m) using only the idea of a dot product, without reciting the rule.
    Check
    • each output entry pairs one row of the left with one column of the right
    • a dot product needs equal lengths, so the row length k must equal the column length k
    • there is one entry per (row, column) pair, so n × m entries
  2. mechanism Walk through how PyTorch gets entry C[1, 1] of A @ B for A = [[1, 2, 3], [4, 5, 6]] and B = [[1, 0], [0, 1], [1, −1]].
    Check
    • take row 1 of A: [4, 5, 6]
    • take column 1 of B: [0, 1, −1]
    • multiply pairwise and add: 0 + 5 − 6 = −1
  3. mechanism Walk through the shapes of (4, 5, 80) @ (80, 200): which dimensions are multiplied, which are kept, and how many dot products happen?
    Check
    • the 80s are the inner size and are summed away
    • 4 and 5 are treated as batch dimensions and kept
    • result (4, 5, 200): 20 rows × 200 neurons = 4,000 dot products of length 80
  4. tradeoff You could loop over the 32 examples and do X[i] @ W + b for each, or do one X @ W + b. What do you gain and what, if anything, changes in the numbers?
    Check
    • one call instead of 32 Python-level calls, and the code doesn't change when the batch grows
    • the values match only up to float32 rounding, because the additions happen in a different order
    • so compare them with a tolerance, not exact equality

Why this step?

4 · Compare against what you already know

vs Vectors and the dot product: A dot product and a matmul: what is fundamentally the same, what does the matmul add, and what goes wrong if you use one where you need the other?

Check
  • same: every matmul entry is one dot product
  • matmul adds the bookkeeping: all rows × all columns laid out in an (n, m) grid
  • one dot product computes one neuron on one example; a matmul computes a whole layer on a whole batch
  • a dot product on mismatched lengths fails just like a matmul with mismatched inner sizes

vs Broadcasting: the two rules: In X @ W + b, the @ and the + both combine tensors of different shapes. How does each one line up the shapes, and how does each fail?

Check
  • @ matches the left's last dimension with the right's first and sums that dimension away
  • + aligns shapes from the right and stretches size-1 (or missing) dimensions, without summing
  • @ fails loudly when the inner sizes differ
  • + can succeed silently on the wrong axis (the keepdim bug), which is harder to catch

vs Matmul backward is a matmul: This card goes forward through H = X @ W. The backprop card needs dW and dX. How can the shape rule alone tell you which matmuls produce them?

Check
  • dW must have W's shape (6, 100) and dX must have X's shape (32, 6)
  • only X.T @ dH gives (6, 100), and only dH @ W.T gives (32, 6)
  • so the backward pass of a matmul is again a matmul, found by making the shapes work

Why this step?

5 · Predict commit to an answer before revealing

In backprop you will need dW, the gradient for W in H = X @ W. It must have W's shape (6, 100). You have X (32, 6) and dH (32, 100), and you may transpose (swap rows and columns). Which single matmul gives (6, 100), and what does the dimension that gets summed away stand for?

Reveal

X.T @ dH: (6, 32) @ (32, 100) gives (6, 100). The summed-away dimension is the 32 examples, so each weight's gradient adds up its contributions from every example in the batch. This is exactly the formula Karpathy derives in backprop ninja (dW2 = h.T @ dlogits).
