Checkpoint 1: from a nudge to a neuron's gradients

Ties together the Python you need, derivative rules, the chain rule, exp and log and the dot product: everything Lecture 1 (micrograd) uses without stopping to teach it.

What this ties together, and why now. Five cards gave you five separate tools: a derivative is a nudge ratio with exact rules, rates multiply along a chain and add across paths, the log turns products into sums, a neuron starts with a dot product, and a class with dunder methods plus closures can record all of it. Lecture 1 uses all of them together. Before you press play, check that they have joined up into one picture: a neuron's output, and how to get the slope of that output with respect to every input.

Comes back in: this is the first course, so there's no earlier course to revisit yet. These ideas return in the Value object, backprop by hand, a neuron, backpropagated and accumulate gradients. Come back to this page after those cards and redo the questions.

How to use this page. Close the five cards. Answer each question in writing, in full sentences, before you open its Check. A wrong or shaky answer tells you exactly which section to reopen. The questions are mixed on purpose, so you first have to work out which idea applies.

1 · Mixed retrieval

  1. debugYour hand-written engine prints a.grad = 1.0 for b = a + a, but nudging a by 10−6 says the slope is 2. Each _backward is only two lines. What's wrong, and why does the bug stay hidden for c = a + d?
    Check
    • a reaches b along two paths, and each path contributes a slope of 1. The multivariable chain rule adds the path contributions: 1 + 1 = 2
    • the _backward assigns (self.grad = …) instead of accumulating (+=). Here self and other are the same object, so the second write overwrites the first and leaves 1.0
    • a value used only once gets one contribution, so = and += agree. The bug only shows on reuse, which is why it needs a test like a + a or x * x (x.grad = 3 + 3 = 6 at x = 3)

    If you missed it, reopen the chain rule, "When x is used twice, the paths add".

  2. For z = tanh(2x + 1) at x = 0.5, write every local derivative and the final dz/dx. Then say why nudging x by 0.001 moves z by only about 0.00014.
    Check
    • forward: y = 2.0, z = tanh(2.0) = 0.964028
    • local slopes: dy/dx = 2; dz/dy = 1 − tanh(y)² = 1 − 0.964028² = 0.070651
    • chain: dz/dx = 0.070651 × 2 = 0.141302, so 0.001 of nudge gives about 0.000141
    • tanh is almost flat at y = 2, so its small slope cancels most of the doubling

    If you missed it, reopen the chain rule, "Worked: z = tanh(2x + 1) at x = 0.5", and the tanh row of derivative rules, "The seven rules".

  3. which idea?You want to compare two models by the probability each gives a whole list of names. You multiply the per-character probabilities in float32, and both models print 0.0. Which idea fixes it, and why does the fix still pick the same winner?
    Check
    • exp and log: log(a·b) = log a + log b, so add log-probabilities instead of multiplying
    • the product underflows: 1000 factors of 1/27 give 0.0 in float32 (it's already 0 at the 32nd factor), while the log-sum is an ordinary −3295.84
    • log only ever goes up when its input goes up, so the model with the bigger product has the bigger log-sum: the ranking is unchanged
    • negate and average for the loss: 0 for a certain model, 3.2958 for a uniform guess over 27 characters

    If you missed it, reopen exp and log, "Why the product breaks: underflow".

  4. Value(3.0) * 2 works, but 2 * Value(3.0) raises a TypeError, and so does sum([Value(1.0), Value(2.0)]). Walk through what Python tries in each case, and name the two methods that fix them.
    Check
    • Python asks the left operand first: int.__mul__(2, v) doesn't know Value and returns NotImplemented
    • only then does it try the right operand's reflected method, v.__rmul__(2). Without that method, you get the TypeError
    • sum() starts from 0, so its first step is 0 + v, which needs __radd__ (or a start value such as the bias: sum(…, self.b))

    If you missed it, reopen the Python you need, "What Python really calls".

  5. which idea?The Lecture 1 neuron has x = [2, 0] and w = [−3, 1]. After backprop, w2.grad is exactly 0.0. A teammate says the backward pass must be broken. Which idea says it's correct, and what would make w2.grad non-zero?
    Check
    • the dot product: x·w = x1w1 + x2w2, so ∂(x·w)/∂w2 = x2 = 0
    • a weight's effect is proportional to its input. With x2 = 0, changing w2 from 1 to 100 still leaves x·w = −6
    • any non-zero x2 gives w2.grad = x2 × (upstream gradient 0.5)

    If you missed it, reopen vectors and the dot product, the "Predict first" answer and the ✓ cell of "How it differs from related ideas".

  6. You check the slope of f(x) = 3x² − 4x + 5 at x = 3 by nudging. With h = 0.00001 you get 14.00003, and with h = 10−12 you get 14.0012446, which is worse. Why does a smaller h get worse, and what should you use instead?
    Check
    • big h: the leftover 3h term (the curvature) dominates the error: 14.3 at h = 0.1
    • tiny h: f(3 + h) and f(3) agree in almost every digit a float64 holds, so their difference is mostly round-off
    • use the exact rule (6x − 4 = 14) in the engine, and keep the nudge as a test at a moderate h. The centred difference (f(x+h) − f(x−h)) / 2h cancels the 3h term

    If you missed it, reopen derivative rules, "Worked: f(x) = 3x² − 4x + 5 at x = 3" and "Do the rules always work?".

  7. which idea?You've written a local _backward for every operation in L = d·f, with d = e + c and e = a·b. In what order must they run, which Python features produce that order, and what goes wrong if you run e's before d's?
    Check
    • a node's _backward may only run once its own gradient is complete, meaning after every node that uses it has run
    • a recursive build_topo appends a node after its inputs, and a visited set stops a shared node from being added twice. Reversed, that's the order: L, f, d, c, e, b, a
    • each _backward is a closure made inside __add__/__mul__, so it remembers its own self, other and out
    • running e first would push e.grad = 0 into a and b, because d hasn't passed anything down yet

    If you missed it, reopen the Python you need, "A set and recursion: putting the graph in order" and "Closures: a function that remembers where it was made".

  8. For the same neuron (n = x·w + b = 0.8814, o = tanh(n) = 0.7071), compute do/dn, then w1.grad and x1.grad, by hand.
    Check
    • do/dn = 1 − tanh(n)² = 1 − 0.7071² = 0.5
    • through the + node, the 0.5 passes unchanged to x·w and to b (b.grad = 0.5)
    • through the × node, each input gets the other input times 0.5: w1.grad = x1 × 0.5 = 2 × 0.5 = 1.0, and x1.grad = w1 × 0.5 = −3 × 0.5 = −1.5

    If you missed it, reopen derivative rules, "The seven rules" (the tanh and a·b rows), and the chain rule, "The rule".

3 · Build: a tiny engine for the Lecture 1 neuron

runs on your M3 · under 1 sWhat it reinforces: operator overloading, reflected methods and closures (the Python you need), the tanh, a·b and a+b rules (derivative rules), multiply along a path and add across paths (the chain rule), and the neuron's dot product (the dot product). It previews what Lecture 1 builds step by step. Write it yourself before you watch.

In one file, plain Python (add torch only for the last check):

  1. The class. V(data) stores data, grad = 0.0, a set _prev of parents, and _backward = lambda: None.
  2. Two operations. __add__ and __mul__ wrap plain numbers, build out with its parents, and attach a closure that adds the local derivative × out.grad into each parent with +=. Set __radd__ = __add__ and __rmul__ = __mul__.
  3. tanh. Its closure adds (1 − t**2) * out.grad.
  4. backward(). Build the topological order with a recursive helper and a visited set, set self.grad = 1.0, and call every _backward in reverse.
  5. The neuron. x = [2, 0], w = [−3, 1], b = 6.8813735870195432. Write n = sum((wi*xi for wi, xi in zip(w, x)), b), then o = n.tanh() and o.backward().
  6. Checks. Nudge w1 by 10−6. Run b = a + a and q * q at 3. Run (2*x + 1).tanh() at 0.5. Then repeat the neuron in torch (float64) with requires_grad=True.
Done when: o prints 0.7071; the gradients of x1, x2, w1, w2 and b are −1.5, 0.5, 1.0, 0.0 and 0.5; the nudge on w1 prints 1.0000; a + a gives a.grad = 2.0 and q * q gives 6.0; tanh(2x+1) gives x.grad = 0.141302; and torch agrees on every gradient. Then change one += to = and watch a + a drop to 1.0.
