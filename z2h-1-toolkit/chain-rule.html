The chain rule

Also called: the chain rule of calculus; in backprop, "local derivative × upstream gradient". Lecture 1 · manual backpropagation example #1: simple expression · 0:32:10

Prime · 2 minutes before you read

The problem: A network's loss sits at the end of a long chain of steps. The derivative rules tell you the slope of one step, but not how a nudge to a weight deep inside travels all the way to the loss.

Where it fits: It builds directly on the derivative-rules card: those rules give each step's local slope, and this card shows how to combine them. Every backward pass in micrograd and PyTorch is this rule.

  2. In tanh(2x+1) at x = 0.5, which factor makes dz/dx small, and what about tanh at y = 2 causes it?
  3. What does each step need to know to supply its local derivative, and what can it ignore?

  5. How far can you nudge x before the chain-rule prediction stops matching what really happens to z?

In one breath: when z depends on y, and y depends on x, then how fast z moves per nudge of x is (how fast z moves per y) × (how fast y moves per x). Backpropagation is this one rule applied again and again, from the loss back to every input.

Predict first: z = tanh(2x+1) at x = 0.5. The inner step 2x+1 doubles every nudge. If you nudge x up by 0.001, does z move by about 0.002, about 0.001, or much less?

Much less: about 0.000141. The doubling is real, but at y = 2 tanh is nearly flat (its slope there is only 0.0707). The chain rule multiplies the two: 0.0707 × 2 × 0.001 = 0.000141. Running it gives z moving by 0.0001410 (computed).

The rule

Karpathy borrows the analogy from Wikipedia's chain rule page: if a car goes 2× as fast as a bicycle, and the bicycle 4× as fast as a walking man, the car goes 2 × 4 = 8× as fast as the man. Rates of change chain by multiplying.

dzdx= dzdyouter step's slope · dydxinner step's slope
xthe input you nudge0.5 ythe in-between value, y = 2x + 12.0 zthe output, z = tanh(y) (tanh squashes any number into −1…1)0.964028 dz/dxderivative: how much z moves per tiny nudge of x (the rate, not a fraction)? (the goal)

Each factor is a local derivative: it only looks at one step and its own input. Neither factor needs to know about the other step.

Worked: z = tanh(2x + 1) at x = 0.5

The same rule in the lecture's graph at 0:32:10: L = d·f and d = e + c, so dL/dc = dL/dd · dd/dc = (−2) × 1 = −2. A + has local derivative 1, so it passes the gradient through unchanged.

When x is used twice, the paths add

If x reaches the output along two routes, each route gets its own chain-rule product, and the total is their sum (the multivariable chain rule). For q = x · x at x = 3, each copy of x sees the other copy as its multiplier, so each path gives 3 and x.grad = 3 + 3 = 6, which matches d(x²)/dx = 2x = 6. For b = a + a, each path gives 1, so a.grad = 2. Code that assigns the gradient (=) instead of adding (+=) keeps only the last path and gets 1: that is the bug Karpathy fixes at 1:22:28.

When: pause the video at 0:32:10 and type this before watching the manual backprop.

import math
x = 0.5
y = 2*x + 1            # inner
z = math.tanh(y)       # outer
dy_dx = 2.0
dz_dy = 1 - z**2       # tanh's local derivative
print(f'dz/dy = 1 - tanh(y)^2 = {dz_dy:.6f}')
print(f'dz/dx = dz/dy * dy/dx = {dz_dy * dy_dx:.6f}')
h = 1e-6
num = (math.tanh(2*(x + h) + 1) - math.tanh(2*x + 1)) / h
print(f'numeric (h=1e-6)      = {num:.6f}')

Why it beats the alternatives

✗ Add the local slopes

0.070651 + 2 = 2.070651, about 14.7× too big (computed). Rates don't add: the car would be 2 + 4 = 6× the walker, not 8×.

✗ Nudge x and measure

Gives 0.141301: close, but only approximate, and it costs one extra forward pass per input. A net has thousands of inputs to nudge.

✗ Expand into one big formula

Fine for tanh(2x+1). For a net with hundreds of chained steps the expanded formula balloons, and you only need its value at today's numbers.

✓ Multiply local derivatives

Each step only knows its own slope. Walking backward, you multiply as you go, so one sweep gives the exact gradient for every input.

Is the slope good for any size of nudge?

No. The chain rule gives the slope at this point. Nudge x by 0.001 and z moves 0.0001410 against a predicted 0.0001413; nudge it by 0.5 and z moves only 0.0310, not the predicted 0.0707, because tanh keeps flattening (computed). That's why training takes many small steps rather than one big one.

It also isn't always a plain product: across several paths you add, and with vectors and matrices each "slope" becomes a matrix, so the product becomes a matrix multiply (z2h-6). Where a function has a kink, like ReLU at 0, there's no true slope and libraries just pick one by convention.

Understand and remember

  • A small nudge of x changes y by dy/dx times the nudge → that change of y changes z by dz/dy times it → so z moves by dz/dy · dy/dx times the nudge → slopes along a chain multiply
  • Each step's local derivative depends only on that step and its own input → you can compute it without seeing the rest of the graph → walking backward and multiplying as you go gives every gradient in one sweep (backprop)
  • x reaches the output along several paths → each path contributes its own product → the total effect is the sum → gradient code must accumulate with += (overwriting keeps one path: a + a gives 1 instead of 2)
  • The chain rule gives the slope at the current point → a curved step like tanh bends away from that line → big nudges are mispredicted (0.5 predicts 0.0707, real 0.0310) → training takes small steps
  • detail that matters A saturated tanh has a tiny local slope (0.0707 at y = 2) → it multiplies into every gradient that passes through it → gradients upstream shrink; this is the saturated-tanh problem in z2h-5

Reference only

  • Leibniz notation dz/dx = dz/dy · dy/dx, and the prime notation (f∘g)'(x) = f'(g(x)) · g'(x)
  • tanh's derivative 1 − tanh(y)², from the derivative-rules card
  • micrograd's form: self.grad += local * out.grad in each _backward (engine.py L28–L31)
  • the lab's numbers: y = 2.0, z = 0.964028, dz/dy = 0.070651, dz/dx = 0.141302

5 · Predict commit to an answer before revealing

Imagine a chain of 20 steps where every step's local slope is 0.070651, the same as tanh at y = 2 on this card. Before computing: roughly how big is the gradient of the last output with respect to the first input, and what happens to learning in the first step?

Reveal

About 0.070651²⁰ ≈ 9.6 × 10⁻²⁴ (computed; even 3 such steps give 0.00035). The chain rule multiplies every local slope, so many slopes below 1 shrink the gradient towards zero, and the first steps barely learn. This is the vanishing gradient behind the saturated-tanh card in z2h-5.
