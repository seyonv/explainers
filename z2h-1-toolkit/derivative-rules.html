Derivatives: the rules you'll actually use

Also called: the slope, the rate of change, f′(x) or df/dx; with several inputs, a partial derivative. Lecture 1 · derivative of a simple function with one input · 0:08:08

Prime · 2 minutes before you read

The problem: Training needs to know, for every input and weight, which way and how hard the output moves when you nudge it. Nudging each one and re-running the whole computation is slow and only approximate, and it breaks if the nudge is too small.

Where it fits: This is the first calculus card, building only on the Python card's plain functions. It supplies the local slope of each operation; the chain rule card next shows how to combine them, and micrograd writes each rule into a _backward.

You'll meet: the derivative as a nudge ratio (rise over run) why the nudge size h matters both ways seven rules: xⁿ, eˣ, ln x, tanh, a·b, a/b, a+b partial derivatives (∂): one input at a time

By the end: Find the exact slope of any operation micrograd uses from its rule, check it with a nudge, and say why a nudge that is too big or too small gives the wrong number.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. For f(x) = 3x² − 4x + 5 at x = 3, where does the extra 3h in the nudge ratio come from, and why does it vanish in the limit?
  2. Why does h = 10⁻¹² give a worse slope than h = 0.00001, when the definition says smaller is better?
  3. In a·b, why is the slope with respect to a equal to b, and what does that say about which input a * node lets through?
  4. Why does a + node have slope 1 for each input, and what does that mean for a gradient passing through it?
  5. Which of the seven rules can be rebuilt from the others, and how does micrograd use that to avoid writing a division rule?

In one breath: the derivative of f at x says how much the output moves per tiny nudge of the input: nudge x by a small h, and f moves by about (derivative) × h. You can estimate it by actually nudging, but seven short rules give it exactly for every operation Zero to Hero uses.

Predict first: you estimate the slope of f(x) = 3x² − 4x + 5 at x = 3 by nudging: (f(3+h) − f(3)) / h. The true slope is 14. As you shrink h from 0.1 to 0.001 to 0.00001 to 10⁻¹², does the estimate keep getting closer to 14?

No. It improves, then gets worse. The lab prints 14.3, 14.003, 14.00003, then 14.0012446082 at h = 10⁻¹²: worse than h = 0.00001. With h that tiny, f(3+h) and f(3) agree in almost every digit a float64 can store, so their difference is mostly round-off.

The seven rules

Every operation in micrograd, and later in the GPT, reduces to these. With two inputs, ∂ ("partial") means the slope with respect to one input while the others stay fixed. Each row is checked by a real nudge of h = 10⁻⁶ at a concrete point; a, b take the lecture's values a = 2, b = −3, c = 10 where they fit.

Exact and nudge columns from labs/derivative-rules.py. The x³ nudge is off by 6×10⁻⁶, the same "leftover" effect as the 3h above (here 3x·h = 6h). tanh squashes any number into −1…1; e ≈ 2.718282 and ln is the log with base e. The ∂/∂a rows are the lecture's d = a·b + c: nudging a moves d by b = −3, and nudging c moves it by 1.

Two of the seven are really the others in disguise. micrograd computes a/b as a·b⁻¹, so the power rule (n = −1) gives −b⁻², times a: −a/b². And the + rule's 1 is why a plus node passes a gradient through unchanged, which you'll see in the chain rule card.

▶ Build itruns on your M3 · under 0.1 s

When: pause the video at 0:08:08 and type this before watching the nudge experiment.

import math
def f(x):
    return 3*x**2 - 4*x + 5
x = 3.0
print(f'f(3) = {f(x)}')
print(f"f'(3) = 6*3 - 4 = {6*x - 4}")
for h in [0.1, 0.001, 0.00001, 1e-12]:
    print(f'  h={h:<7g} slope = {(f(x + h) - f(x))/h:.10f}')
n, h = 0.8813735870195432, 1e-6    # the L1 neuron's n
exact = 1 - math.tanh(n)**2
num = (math.tanh(n + h) - math.tanh(n)) / h
print(f'tanh -> 1-tanh^2    {n:<7.4g} {exact:<12.6f} {num:.6f}')

Why it beats the alternatives

✗ Only ever nudge

Gives 14.003 at h = 0.001: close, never exact, and it breaks when h is too small (14.00124 at 10⁻¹²). It also costs one extra forward pass per input.

✗ Read it off the plot

The parabola shows the slope is positive and steep at x = 3, and flat near 2/3. It can't tell 14 from 14.3, and a net has no plot to look at.

✗ Redo the limit every time

Expanding f(x + h) like the table above is exact, but slow and error-prone. Karpathy does it once, for the product at 0:32:10; nobody does it per step.

✓ Seven rules, nudge as a check

Each operation needs one short rule, applied at today's numbers: exact and nearly free. Keep the nudge as a test that catches a rule you coded wrong.

Do the rules always work?

Only where the function is smooth and defined. ReLU (max(0, x), a later activation) has a kink at 0 with no true slope; micrograd just uses 0 there (out.data > 0). ln x doesn't exist for x ≤ 0, which is why a probability of 0 gives an infinite loss (the smoothing card fixes it), and a/b blows up as b → 0.

And the nudge check can be sharpened: the centred version (f(x+h) − f(x−h)) / 2h cancels the 3h leftover, giving 14.000000000000021 even at h = 0.1 (computed). The lecture's Colab exercise asks for it as the "symmetric derivative". Neither version helps with 10⁻¹²: round-off still wins.

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • Nudge x by h → f moves by about f′(x)·h plus a leftover that shrinks with h (3h² for this parabola) → the nudge ratio is f′(x) plus an error proportional to h → the derivative is what remains as h → 0 (14 at x = 3)
  • h too big → the curvature leftover dominates (14.3 at h = 0.1) → h too small → f(x+h) and f(x) share almost all their stored digits, so the subtraction is mostly round-off (14.00124 at 10⁻¹²) → a numeric check needs a middle h, like 10⁻⁵ or 10⁻⁶
  • Each operation's slope has a short closed-form rule → evaluate it at the current numbers → exact and nearly free, with no extra forward passes → so autograd stores one rule per op and keeps the nudge only as a test
  • ∂(a·b)/∂a = b and ∂(a+b)/∂a = 1 → a * node scales an input's effect by the other input, a + node passes it through unchanged → this is exactly what micrograd's _backward for * and + encodes
  • detail that matters tanh's slope 1 − tanh²x is computed from tanh's own output → at large |x| the output is near ±1 and the slope near 0 (1.0 at x = 0, 0.000182 at x = 5) → saturated neurons pass almost no gradient, the problem of z2h-5's saturated-tanh card

Reference only

  • the notation: f′(x), df/dx and ∂f/∂a all name a slope; ∂ means the other inputs are held fixed
  • the rule table: xⁿ → n·xⁿ⁻¹, eˣ → eˣ, ln x → 1/x, tanh x → 1 − tanh²x, a·b → b, a/b → −a/b² (w.r.t. b), a+b → 1
  • a/b is computed in micrograd as a * b**-1 (power rule with n = −1)
  • the lab's numbers: f(3) = 20, slopes 14.3 / 14.003 / 14.00003 / 14.0012446 for h = 0.1 / 0.001 / 10⁻⁵ / 10⁻¹²

  1. concept In plain words, what does it mean that f(x) = 3x² − 4x + 5 has slope 14 at x = 3 but slope 0 at x = 2/3?
    Check
    • near x = 3, f rises about 14 units per unit of x (0.014 per 0.001)
    • at x = 2/3 a small nudge barely changes f: it's the bottom of the parabola
    • the slope is local: it describes only a tiny neighbourhood of that x
  2. mechanism Walk through the nudge ratio for f at x = 3 algebraically, from f(3 + h) to the number the lab prints for h = 0.0001.
    Check
    • f(3 + h) = 3(9 + 6h + h²) − 4(3 + h) + 5 = 20 + 14h + 3h²
    • subtract f(3) = 20 and divide by h: 14 + 3h
    • h = 0.0001 gives 14.0003, which the lab prints as 14.000300
    • as h → 0 only 14 remains, matching 6x − 4
  3. mechanism Use the rules to give ∂/∂a, ∂/∂b and ∂/∂c of d = a·b + c at a = 2, b = −3, c = 10, and say what each means for a nudge.
    Check
    • ∂d/∂a = b = −3: nudging a up makes d go down 3× as fast
    • ∂d/∂b = a = 2
    • ∂d/∂c = 1: c passes straight through
    • each is a slope with the other inputs held fixed
  4. tradeoff You're writing a gradient check for your own backward code. What h do you pick, what do you give up with h = 0.1 versus h = 10⁻¹², and when would you switch to the centred difference?
    Check
    • a middle value like 10⁻⁵ or 10⁻⁶
    • h = 0.1: a curvature error proportional to h (0.3 here)
    • h = 10⁻¹²: round-off error (0.0012 here)
    • centred (f(x+h) − f(x−h)) / 2h cancels the error linear in h, so it's more accurate at the same h

5 · Predict commit to an answer before revealing

tanh's slope is 1 − tanh²x. Before computing: how does the slope at x = 5 compare with the slope at x = 0, and what would that do to learning for a neuron whose input sits at 5?

Reveal

At x = 0 the slope is 1 − 0² = 1.0; at x = 5, tanh(5) ≈ 0.99991, so the slope is only 0.000182 (computed), about 5,500× smaller. Any gradient passing through that tanh is multiplied by 0.000182, so the weights feeding it barely change: a saturated neuron. The batchnorm lecture (z2h-5) spends a chapter on this.
