Output speed (tokens per second)

Also called decode speed, generation speed, or tok/s. It's how fast the answer streams once it starts. It's the headline number on Artificial Analysis and OpenRouter provider pages.

In one breath

Output speed is how many tokens the model writes per second after the first token arrives. A token is about ¾ of a word. The model has to produce tokens one after another, so this number sets the pace of every answer.

How it differs from related ideas

✗ TTFT

The wait before the first token. Measuring speed from the first token keeps queueing and prompt reading out of this number, so each metric shows one thing.

✗ Throughput

Total tokens per second a server produces across all users. Providers batch many users together to raise it, which can make each person's speed slower.

✗ End-to-end time

The whole response. It mixes speed with length and thinking, so a slow model that writes briefly can still finish first.

✓ Output speed

The per-request writing pace. It's set by hardware memory bandwidth, model size, and serving tricks, so it's the number to compare hosts on.

Is a higher number always what I want?

Not always. For short answers, TTFT matters more. At 82 tokens, Cerebras (0.50 s + 0.05 s) and Groq (0.72 s + 0.17 s) are both under a second, and the wait is mostly TTFT. For reasoning models, a fast speed can hide a long silent think: Gemini 3.8 Flash (high) writes at 344 t/s but has a 22.7 s TTFT. The fastest host may also cost more or run a more heavily quantized model, which OpenRouter's provider list shows (bf16 / fp8 / fp4). Compare quality before choosing the fastest.
