Harness call count

Also called the agent loop, tool-use loop or turns. The harness is the program around the model: Claude Code, Cursor, Codex CLI, or your own llm.chat() script. It decides how many times the model gets called for one task.

In one breath. Claude Code is a harness, not a model. One request from you becomes a loop: call the model, run a tool, send back the result, call again. Each call pays its own time to first token and writing time, then waits for the tool.

Time to first token (1.39 s) and speed (66 tokens/s) are Artificial Analysis medians for Claude Sonnet 5, non-reasoning (2026-09-21). The call count, token counts and tool times are illustrative. Real sessions vary a lot.

Why it beats the alternatives

✗ One raw API call

Fastest (3.66 s), but it can't see your files, run the code or fix its own mistakes. You do all of that yourself.

✗ Paste the whole repo in one prompt

Still one call, but a huge prompt pays a large first-token delay every time, and it goes stale as soon as the code changes.

✗ Chat, copy, paste, repeat

Same loop as an agent, but you are the tool runner. Your copy-paste minutes dwarf the model's seconds.

✓ Agent harness loop

More calls (3.7× here), but each step is checked against reality. Prompt caching keeps re-sending the history cheap, and the task ends up done, not just answered.

Is Claude Code slower than “Claude”?

Per call, no: it uses the same model at the same speed. Per task, often yes for tiny tasks. A one-shot question like FizzBuzz is fastest as a single API call or chat, where the loop's extra calls and big system prompt buy nothing. The harness wins on real multi-step work: reading files, editing, running tests and retrying.

To speed up an agent, cut the number of calls (clear instructions, fewer check-backs) before chasing tokens/s. Running a harness on a local model is where it hurts most: every call re-reads thousands of prompt tokens at laptop prefill speed.
