Thinking tokens

Also called reasoning tokens or chain of thought, and set with “effort”, “thinking budget” or think: true. Found in reasoning models like Claude (extended thinking), GPT-5.x (reasoning effort), gpt-oss and Qwen3.5.

Prime · 2 minutes before you read

The problem: A reasoning model can sit silent for two minutes and then give the same answer a non-reasoning run gives in five seconds. The wait looks like a slow start, but it's output you can't see, written and billed at full price.

Where it fits: First multiplier card. Output length showed that time is linear in tokens; thinking adds a hidden block of tokens in front of the answer. Harness calls, next, repeat that cost on every call of an agent.

In one breath. Before it answers, the model writes a private scratchpad of reasoning. Those tokens are generated one at a time at the same speed as the answer, and billed and timed the same way. You just don't see them, so the wait looks like a slow start.

What "thinking" actually is

There is no separate reasoning engine. It's the same model running the same loop it always runs: predict one token, append it, repeat. A reasoning model has been trained to first write out its working inside a hidden block (<think>…</think> in Qwen, a separate "analysis" channel in gpt-oss), then write the answer, which can read everything in that block. The API or app hides the block, or shows you a summary of it, but the model still had to write every token.

answer: 80 tokens ÷ 15.7 t/s = 5.1 s (same as with thinking off) thinking: 1,684 tokens ÷ 15.7 t/s = 107.3 s ← 97% of the extra time slowdown: 15.7 → 15.3 t/s on all 1,764 tokens = +3.1 s total 115.5 s (measured)
  1. More tokens, one at a time. Almost all of it. Token 1,000 can't be written until token 999 exists, so thinking can't be spread across the chip the way reading your prompt can.
  2. Each token gets a little slower. Every new token also rereads the stored state (the KV cache) of every token before it, and thinking makes that history longer. Small here (2.5%), bigger with long prompts and long thinking.
  3. All of it lands before the first word. The first visible token moves from about 0.3 s to about 110 s. Same total work, but it feels far worse because nothing is on screen.
  4. What does not change. Reading the prompt, and the work per token: the model isn't "thinking harder" per token. Effort settings only change how many thinking tokens it writes.

The 80 answer tokens in the thinking-on run are estimated from the thinking-off answer; the 1,764 total and both speeds are measured. In an agent, this repeats on every call that thinks (see harness calls).

How it differs from related ideas

✗ Slow output speed

Fewer tokens per second. Thinking leaves the speed alone (15.7 vs 15.3 tokens/s above) but adds ~1,700 extra tokens.

✗ Long prompt / prefill

Reading input is parallel and fast. Thinking is output, written one token at a time, so it costs far more per token.

✗ Network / queue delay

Also looks like a slow first token, but costs ~0.3–1.5 s. Thinking can push the first visible word back by minutes.

✓ Thinking tokens

A choice you control about how much to write. Artificial Analysis reports “time to first answer token” to separate it out. For gpt-oss-120b (high), 9.37 s of the 12.52 s total (75%) is reasoning.

So should thinking be off?

Not always. For FizzBuzz, boilerplate, reformatting or lookups, thinking is almost pure waste: 23× the time for the same answer. Turn it off or use low effort. For hard bugs, math, multi-step planning or unfamiliar code, thinking often gets it right on the first try. A 20 s correct answer beats three 5 s wrong ones plus your time checking them.

Budgets vary a lot: when a provider hides the count, Artificial Analysis simply assumes 2k reasoning tokens. Start low and raise effort only when answers are wrong.

Understand and remember

  • Thinking is ordinary output written into a hidden block → generated one token at a time at the same speed → time grows with thinking tokens (80 → 1,764 tokens: 5.1 s → 115.5 s) → effort settings change how many, not how fast
  • All thinking happens before the answer → the first visible token moves from ~0.3 s to ~110 s → the same total work feels far worse → reported TTFT for reasoning models can include minutes of thinking
  • Thinking often gets hard problems right first time → one slower correct answer can beat several fast wrong ones plus your checking → use low effort for easy tasks and raise it only when answers are wrong
  • detail that matters Each new token rereads the stored state (KV cache) of every earlier token → a long think makes later tokens slightly slower (15.7 → 15.3 t/s, +3.1 s here) → bigger with long prompts and long thinking

5 · Predict commit to an answer before revealing

The same FizzBuzz thinking run is done by gpt-oss-120b on Cerebras at 1,745 t/s. Predict the thinking time for ~1,684 hidden tokens, and whether thinking still matters on such a fast host.

Reveal

1,684 ÷ 1,745 ≈ 0.97 s. On a very fast host thinking costs about a second, so leaving it on for hard problems is nearly free in time. It still costs money per token, and on a slow host (48 t/s) the same think would take about 35 s.
