Prompt caching (prefill reuse)

Also called prefix caching, KV cache reuse, or context caching. Built into Ollama (it keeps the last prompt in memory) and offered by the Anthropic and OpenAI APIs.

In one breath

Before writing anything, the model has to read the whole prompt (this step is called prefill). Caching saves the result of that reading, so the next request that starts with exactly the same text skips straight to the new part.

Worked example: one 2,605-token prompt on an M3, three times

speed-up on repeat = 33.88 s / 0.41 s ≈ 83× (99% less prompt reading time) fresh read rate = 2,605 / 33.88 s ≈ 77 tokens/s (other run: 207)

Measured with Ollama, qwen3.5:4b on an Apple M3 (24 GB). The machine was busy, so the fresh read time varied from 12.6 s to 33.9 s between runs. The repeat and changed-start results held up. Only the prompt reading step is shown; writing the answer is a separate cost.

Why it beats the alternatives

✗ Re-read every time

The default without caching. An agent that resends a 20K-token system prompt on every call pays the full reading time and full price each time.

✗ Shorten the prompt

Faster, but you drop instructions, files or history the model needed, and answer quality falls.

✗ Cache the final answer

Only helps when the whole request repeats exactly. A new question on the same document still misses.

✓ Prefix caching

Reuses the expensive shared part (system prompt, documents, history) while the question at the end changes freely.

Does it always help?

No. It only speeds up prompt reading, so it barely matters for short prompts or long answers. Your 26-token FizzBuzz prompt took 0.33 s to read, while writing the answer took 42 s. The match must be exact from the very first token: put stable content (system prompt, documents) first and changing content (timestamps, the question) last, or every request misses, as in row 3.

Caches also expire (Ollama unloads idle models, and Anthropic keeps caches 5 minutes or 1 hour). Hosted APIs charge extra to write a cache, so a prompt used only once costs more with caching than without.
