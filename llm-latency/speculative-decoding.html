Speculative decoding

Also called speculative sampling, draft-and-verify, or assisted generation. Variants include Medusa and EAGLE. Hosts like Groq, Cerebras, vLLM and SGLang use it to raise tokens per second.

In one breath

A small, fast "draft" model guesses the next few tokens. The big model then checks all the guesses in one pass, keeping every correct guess and fixing the first wrong one. The output matches what the big model would have written alone, just in fewer slow passes.

Illustrative. 64.9 ms per pass is your measured 15.4 tokens/s. The draft cost, the acceptance rate and the tokens are made up for the example. Published speed-ups: 2–3× (Leviathan et al., 2022), 2.2–3.6× (Medusa, 2024), up to 6.5× (EAGLE-3, 2025).

Why it beats the alternatives

✗ Just use the small model

Fast, but you get the small model's quality: more bugs and wrong answers.

✗ Quantize harder

Stores each weight with fewer bits, so there's less to read per token. Faster, but past 4 bits quality drops noticeably and the output changes.

✗ Buy faster memory

Works, since writing speed is limited by memory bandwidth. But it means new hardware, not a setting.

✓ Speculative decoding

Checking 5 tokens costs about the same memory read as writing 1, so correct guesses are nearly free. Output quality is unchanged.

Is it always faster?

No. It only helps when the draft guesses well. That's true for predictable text like code boilerplate, and less so for creative or unusual text. With low acceptance, you pay for the draft and still move one token at a time, which can be slower than normal.

It speeds up writing, not prompt reading, so time to first token doesn't improve. On busy servers already handling many requests at once, the GPU has less spare capacity, so the gain shrinks (EAGLE-3 reports 1.38× at 64 requests at once, compared with up to 6.5× for a single request). Locally, it needs a draft model that matches the big one, and the draft takes extra memory.
