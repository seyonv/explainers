Mixture of experts (MoE)

Also called sparse models or "total vs active parameters", often shown in names like "30B-A3B". Used by gpt-oss, DeepSeek-V3, the larger Qwen3/Qwen3.5 models, and likely many closed frontier models.

Prime · 2 minutes before you read

The problem: A dense model has to read every weight for every token, so bigger means proportionally slower. Mixture of experts breaks that link: a huge model can write like a small one. But it still has to fit in memory.

Where it fits: Fourth mechanism card, another way to shrink the bytes side of the bandwidth division. Quantization reads fewer bits per weight; MoE reads fewer weights per token.

In one breath

Instead of one big block that uses every parameter for every token, the model has many smaller "expert" blocks and a router that picks a few of them per token. Each token touches only a small slice of the weights, so it writes like a small model while knowing like a big one.

Why it beats the alternatives

✗ Big dense model

Uses every weight for every token. Smart, but a dense 30B is about 9× slower per token than a 30B-A3B on the same machine.

✗ Small dense model

Fast, but it holds less knowledge and skill. A 3B dense model usually trails a 30B-A3B on quality.

✗ Quantize a big dense model

Cuts bytes about 4× (16-bit to 4-bit), but you still read the whole model for every token. MoE cuts what's read by about 9–23×.

✓ Mixture of experts

Writing speed follows the active parameters and knowledge follows the total. It's the main reason huge hosted models can still be fast.

Is MoE always the better pick?

Not when memory is your limit. You still have to hold every expert in memory, since any token might need any of them. gpt-oss-120b reads only about 2.9 GB per token but needs about 66 GB to load, so it can't run on your 24 GB Mac. At equal memory, a dense model is often somewhat smarter than an MoE of the same total size.

MoE also brings routing overhead and is harder to serve efficiently to many users at once (different tokens want different experts). On small machines, pick the largest model whose total size fits in memory, then prefer MoE if one fits, because its speed follows the active size.

5 · Predict commit to an answer before revealing

A new MoE has 200B total params and 10B active, at 4.5 bits. Predict its M3 speed ceiling and whether it runs on a 24 GB Mac. Commit, then reveal.

Reveal

Active bytes ≈ 10B × 4.5 ÷ 8 ≈ 5.6 GB → ceiling ≈ 100 ÷ 5.6 ≈ 18 t/s. But it needs ≈ 200B × 4.5 ÷ 8 ≈ 112 GB to hold, so it doesn't fit on 24 GB at all. The speed number is irrelevant until the memory number fits.
