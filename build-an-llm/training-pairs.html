Every position is a training example

Input/target pairs, next-token prediction, the sliding window, context length and stride, the training loss · prepares Raschka, Build a Large Language Model (From Scratch), §2.6 and §5.1 (Manning, 2025)

Prime · 2 minutes before you read

The problem: Training needs examples with right answers, and nobody has labelled the internet. Without a way to turn raw text into graded examples, and to grade many of them per pass, a language model can't be trained at all.

Where it fits: The first build stop. The basics path traced one prediction through a trained model; this card shows where the training examples come from, and the single number (the loss) that training pushes down. It prepares Raschka §2.6 and §5.1.

To train a model you need examples with right answers, and nobody has labelled the internet. For a language model the text is its own answer key: the right answer at every position is simply the next token. Shift a chunk of text by one token and you have one example per position, all graded in a single pass through the model.

Try this first

Guess first: during training you feed the model 8 tokens of text. How many next-token guesses does it get graded on, and how many passes through the model does that take?

Show the answer

8 guesses, 1 pass. Each of the 8 positions predicts the token after it, and the 9th token of the text supplies the last answer. Generation, which has to pick each token before it can predict the next one, would need 8 passes.

Three words first

Target

The token that really came next in the text. It's the "right answer" the model is graded against, and the text gives it for free.

Context length

How many tokens one training example holds. The book calls it max_length in §2.6 and context_length in its model config. Here it's 8.

Stride

How many tokens the window moves before cutting the next chunk. Equal to the context length means no overlap; smaller means chunks share tokens.

The text is its own answer key

← scroll the sketch →

The first 9 tokens of our text. The inputs are tokens 0 to 7; the targets are tokens 1 to 8, the same text moved left by one. One pass through the model gives a guess at every position, and each guess gets a loss. All numbers are measured on Qwen2.5-0.5B by the lab below.

For a chunk of n tokens the recipe is two slices: inputs = tokens[0:n] and targets = tokens[1:n+1]. That's the whole labelling step. Nobody writes answers; the next token in the text is the answer.

The loss at one position is how surprised the model was by the real next token: minus the log of the probability it gave that token (this is cross-entropy). A sure, right guess costs close to 0. At position 5 the model had read The baker opened the shop at and gave six only 0.0005, so it scores 7.65. At position 4 it gave at 0.47, a loss of 0.76.

Average the 8 losses and you have the training loss for this chunk: 5.74. Training nudges the weights to make that number smaller, which means putting more probability on every real next token at once.

One pass grades every position, because no position can peek

Why can one pass give 8 honest guesses? Inside the model, the causal mask (the rule that a token's attention may only look at itself and earlier tokens) means position 4 never sees token 5. So its guess for token 5 is a real guess, even though token 5 is sitting right there in the input.

The lab checks this directly: it runs the chunk once, then runs 8 separate passes on the growing prefixes (The, The baker, …). The logits (the scores before softmax) differ by at most 0.00018, which is float rounding. One pass over n tokens is n separate examples, computed side by side.

Generation can't do this. When the model writes, token 6 doesn't exist until it has picked it, so it needs one pass per new token (One token at a time). In training every next token is already known, so all positions run together. Using the real text as the input at every position, instead of the model's own guesses, is called teacher forcing.

What to look for when you code §5.1: the model returns a score for every vocabulary entry at every position, a tensor of shape (batch, context, vocabulary). The book flattens batch and positions into one long list before calling PyTorch's cross-entropy, which is the same mean over all positions. Hugging Face does the shift for you: model(chunk, labels=chunk) gave 5.742, the same as our hand-shifted version. So never shift by hand and pass shifted labels to it, or you'll train the model to predict two tokens ahead.

A sliding window cuts a long text into chunks

← scroll the sketch →

Our 33-token text, cut into chunks of 8. Each chunk also needs one extra token for its last target. With stride 8 every target is graded once. With stride 4 the chunks overlap by half, so there are more examples but they repeat the same text.

A real training text is far longer than the context, so the loader slides a window along the token stream: start a chunk at 0, then at the stride, then twice the stride, and stop when there's no room left for the 8 inputs plus 1 extra token. That's the loop in §2.6, and it's worth counting by hand once.

Stride 4 gives 56 predictions, but only 32 different targets: 24 of them are graded twice. More rows, not more information. A smaller stride repeats data; a stride equal to the context length uses every token once. When the book trains its model in §5.1.3, it sets the stride equal to the context length.

Stack chunks as rows and you have a batch. The first two stride-4 chunks make an inputs tensor of shape (2, 8), written (batch, context), and the targets tensor has the same shape. Row 1 starts at shop, 4 tokens into row 0. A batch of B rows holds B × 8 graded positions.

How batches are drawn at random from the stream, and why B × T examples per step is the point, is the subject of Chunks and batches: block_size 8 gives 8 examples. This card won't repeat it.

More context makes the next token easier, on average

← scroll the sketch →

All 33 tokens in one pass give 32 losses. The block means fall from 5.74 (positions 0 to 7) to 2.28 (24 to 31). Mean over all 32: 4.145. The red labels mark tokens the model didn't see coming.

Position 0 has read one word, The, and has almost nothing to go on: baker scores 11.79. Near the end, after two full sentences, words like were (0.25) and the final full stop (0.21) are close to free.

Be honest about what this shows. It's one short text, and single positions jump around. small at position 13 still costs 9.16, and the second cakes costs 8.25 even though cakes appeared a sentence earlier. Context helps on average, not every time. That's also why training on the short positions matters: the model must learn to guess well with one token of context as well as with many.

The window's edge costs something too. Cut the same text into the four stride-8 chunks and run them as a batch of shape (4, 8): the same 32 targets now score 4.873 instead of 4.145, because every chunk starts over with no context. The context length is a ceiling on how much text the model can use for any guess.

One more detail: the very first token is never a target. Qwen adds no start-of-text token, so n tokens give n − 1 graded positions.

Our question, graded token by token

The running example as one 15-token text: What is the capital of India? The capital of India is New Delhi. One pass gives 14 losses. Perplexity is eloss: roughly, the number of tokens the model was choosing between, as if it picked uniformly among that many.

Mean loss over all 14: 1.157, perplexity 3.18. Split it and the story is clearer. The 6 targets inside the question average 2.33 (perplexity 10.3): after What is the, the word capital got only 0.0005, because many questions start that way. The 8 answer targets average 0.27 (perplexity 1.32): once the question is read, the answer is nearly certain. These are the same step probabilities as the greedy answer in One token at a time; here they come from one pass instead of eight.

For scale: a model that spreads its bets evenly over Qwen's 151,936 vocabulary rows scores ln(151,936) = 11.93 at every position. With GPT-2's 50,257 tokens, the book's model, that's 10.82. An untrained model starts near that: the book's untrained GPT-2 scores about 10.8 in §5.1.2.

Principle

The text labels itself, and every position is graded at once

Shift the inputs by one and you get the targets. The causal mask keeps each position from seeing its own answer, so one pass yields n honest guesses, and their mean loss is the number training pushes down.

Buys you: as many training examples as there are tokens of text, with no labelling, and n of them per pass.

Raschka §2.6 and §5.1.2; numbers from the lab

The failure you will hit: targets that aren't shifted, or shifted twice

Failure · data loader
Symptom
The training loss falls far faster than it should, but the trained model writes nonsense. Or the loss levels off higher than it should, because guessing two tokens ahead is harder.
Cause
Targets equal to the inputs: each position is graded on its own token, which it can see, so the model learns to copy. Or the targets were shifted by hand and passed to a loss that shifts again, so every position is asked for the token two ahead.
Isolate
Decode row 0 of a batch: the targets should read as the inputs moved left by exactly one token, ending on one token the inputs don't have.
Fix
Slice tokens[i:i+n] and tokens[i+1:i+n+1], and shift in exactly one place. With Hugging Face, pass the unshifted ids as labels and let it shift.

Where this picture is simplified

  1. Real pretraining packs documents together. Many documents are joined end to end with an end-of-text token between them (the book adds one in §2.4), then cut into chunks. A chunk can straddle two documents, and the separator tells the model that the text before it is unrelated.
  2. Overlap is a trade, not a free lunch. A small stride squeezes more rows out of a short text, but the extra rows repeat the same targets, so the model sees the same text more often.
  3. The book's model will overfit, and that's expected. It trains on one short story for several epochs, so the training loss keeps falling while the loss on held-out text stops improving, and the model starts reciting passages (§5.2). With so little text that's the normal outcome, not a bug in your code.
  4. Low loss isn't the same as useful. Our answer tokens had perplexity 1.32, yet the same base model, sampled freely on the plain question, often wanders off (one try went on to ask about the capital of Kenya). Pretraining loss measures next-token guessing on text like the training data; following instructions is taught later (the next card, Teach the format, grade only the answer).

Check yourself

1. A text has 1,025 tokens. With context 256 and stride 256, how many chunks and graded predictions do you get?

Show the answer

Chunks start at 0, 256, 512 and 768; the last one needs tokens 768 to 1,024, which just fits. That's 4 chunks and 4 × 256 = 1,024 predictions: every token except the first is a target exactly once.

2. Why can training grade all 8 positions of a chunk in one pass, when generation needs a pass per token?

Show the answer

In training all the next tokens are already in the text, and the causal mask stops each position from seeing them, so all 8 guesses run side by side. In generation the next token doesn't exist until the model has picked it.

3. On our question plus answer, the question's targets average a loss of 2.33 and the answer's 0.27. What does that difference mean?

Show the answer

Many texts start with What is the, so the question's own words are hard to predict (perplexity about 10). Once the question has been read, the answer is close to certain (perplexity 1.32, about one choice per token).

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • The next token in the text is the right answer → targets = inputs shifted by one (tokens[0:n], tokens[1:n+1]) → every position is a labelled example → no human labels needed
  • Causal mask: position t reads only tokens 0…t → its guess for token t+1 is honest even though t+1 is in the input → one pass gives n guesses identical to n prefix passes → training is n× more efficient per pass than generation, which must create each token before predicting the next
  • Loss at a position = −ln p(target) → mean over all positions = the training loss → eloss = perplexity, roughly how many tokens the model was choosing between → lower means the real next tokens got more probability
  • Sliding window: stride = context → every target once; smaller stride → more rows but repeated targets → more updates on the same text, not more information; and every chunk restarts with no context, so the context length caps what any guess can use (4.873 vs 4.145 on the same 32 targets)
  • detail that matters The model outputs (batch, context, vocabulary) scores → the book flattens batch and positions into one list before cross-entropy → the mean is over every graded position in the batch, so each token counts equally
  • detail that matters Hugging Face's labels= shifts internally → shifting by hand as well trains the model to predict two tokens ahead → shift in exactly one place

Reference only

  • Chunk count for N tokens, context n, stride S: starts are range(0, N − n, S), i.e. ceil((N − n) / S) chunks
  • Our text: 143 characters → 33 Qwen tokens; context 8: stride 8 → 4 chunks / 32 predictions, stride 4 → 7 chunks / 56 predictions, 32 distinct targets either way
  • Measured: first chunk losses 11.79 … 5.48, mean 5.742; whole text mean 4.145 (perplexity 63.1); question+answer mean 1.157 (perplexity 3.18)
  • Uniform guess: ln(151,936) = 11.93 for Qwen, ln(50,257) = 10.82 for GPT-2
  • Book names: max_length and stride in §2.6, context_length in the model config; end-of-text separator in §2.4

4 · Compare against what you already know

vs One token at a time: Generation and training both produce next-token probabilities. Why does generation need one pass per token while training needs one pass per chunk, and what does each cost?

Check
  • in generation the next token doesn't exist until it's picked, so each pass waits on the last
  • in training every next token is already in the text (teacher forcing), and the causal mask keeps guesses honest
  • measured here: 32 predictions in one pass took about 0.1 s vs about 1.25 s as 32 cached one-token passes
  • the answer tokens' probabilities are identical either way (0.277, 0.964, …)

vs Chunks and batches: block_size 8 gives 8 examples: Karpathy's loader draws random offsets; the book's §2.6 loader slides a window with a stride. What is fundamentally the same, and how do they differ in which text gets repeated?

Check
  • both build x and y as windows of the same token stream, y shifted by one, and stack them into (batch, context)
  • random offsets can repeat or skip text by chance; a fixed stride repeats it on purpose (stride < context) or not at all (stride = context)
  • both grade every position of every row
