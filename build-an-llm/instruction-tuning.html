Teach the format, grade only the answer

Instruction fine-tuning, supervised fine-tuning (SFT), loss masking · Raschka, Build a Large Language Model (From Scratch), ch 7.2–7.6, Manning, 2025

Prime · 2 minutes before you read

The problem: A base model continues text: given a request, it may answer, or just keep writing the letter the request seems to start. Training it on instruction examples fixes that, but only if the batch is built so the loss grades the answers instead of the filler used to line examples up.

Where it fits: Builds on training pairs (every position predicts the next token) and on wrappers like Q: … A: from the basics course. Instruction tuning keeps the same next-token loss and changes only the data and which targets count. It is step 1 of the RLHF recipe.

A base model continues text. It doesn't know that a request should be followed by an answer, and then by a stop. Instruction tuning trains it on examples written into one fixed template, so it learns "after this marker, write the answer, then end". Two quiet details decide what it actually learns: what the batch is padded with, and which positions the loss counts.

Try this first

Guess first: three short examples are padded to the same length and stacked into one batch. Padding fills 51 of the 129 positions the model must predict. What share of the total loss comes from those padding positions: about 40%, 60% or 80%?

Show the answer

83%, measured on Qwen2.5-0.5B. After an end-of-text token the base model expects a new document, not another end token, so each padding position costs about 17 on average, while answer tokens cost about 1.2. Left in, padding swamps the number and the gradient.

Three words first

Instruction tuning

More training of a pretrained model, on examples of an instruction paired with a good response. Also called supervised fine-tuning (SFT). The loss is the same next-token loss as pretraining.

Padding

Filler tokens added to the end of shorter examples so every row in a batch has the same length and they stack into one tensor.

Ignore index

A target value that the loss function skips. In PyTorch's cross-entropy it is -100 by default (ignore_index=-100), so writing −100 into a target means "don't grade this position".

The template turns each example into one text, and every position is still a prediction

Each training example has three fields: an instruction, an optional input it applies to, and the desired response. The model can only read one stream of tokens, so the fields are written into a fixed layout with marker lines. This card uses the widely known Alpaca-style markers, the same layout ch 7 uses (the book also opens with a one-line preamble, which we leave out):

### Instruction: Give the opposite of this word. ### Input: ancient ### Response: modern<|endoftext|>

The markers are identical in every example, so the model sees thousands of times that what follows ### Response: is an answer, and that the answer ends with the end-of-text token. At use time you render a new instruction the same way, stop right after the response marker, and let the model write.

The last two columns are the two masking choices: counted or replaced with −100. Losses are measured on the untrained Qwen2.5-0.5B base model by the lab below.

A batch needs equal rows, so short examples get padded, then shifted

Our three examples are 16, 21 and 44 tokens long (each ending with one end-of-text token). To stack them, every row is extended to the longest with copies of the end-of-text token. The book does the same with GPT-2's end token, ID 50256 (§7.3). Then the row is split by one position: the inputs are tokens 0 to 42, the targets are tokens 1 to 43. That gives 3 × 43 = 129 predictions.

Two details make this safe:

  1. Padding goes on the right. A token's attention only looks at itself and earlier tokens (the causal mask), so padding placed after the real text can't change any real position's prediction.
  2. The first end token stays a target. The end token right after the answer is what teaches the model to stop. Only the copies after it are padding. Ch 7 keeps that first one on purpose (§7.3).

← scroll the sketch →

Every target in the batch, coloured by what it is. Padding dominates the loss. Masking it drops the mean from 8.21 to 2.35; masking the instruction and template too leaves only the answer tokens, at 1.20.

Why the padding loss is so high: after <|endoftext|>, a model pretrained on documents expects the start of a new document. Predicting a second end token is something it almost never saw. In row 1 the padding positions cost between 15.2 and 20.1 each.

Left unmasked, that becomes the training signal. Most of the gradient would teach "after an end token, write another end token", which is meaningless, and the loss you watch would mostly measure padding, not answers. The fix is one line: write -100 into those target positions, and cross_entropy skips them and averages over the rest. The inputs don't change; only the grading does.

One more thing the mean hides: it averages over counted tokens, not over examples. Under masking (c), row 3's 23 answer tokens are 23 of the 29 counted positions, so its long answer outweighs the two short ones.

Masking the instruction too is a choice, and the book leaves it off

Mask the instruction (c)

Grade only the response. The model is trained to answer, not to reproduce instructions, which the book says can reduce overfitting (§7.3).

In our batch it counts 29 of 129 positions.

Mask padding only (b)

Grade the instruction text as well. More positions give more signal per example: 78 here.

This is what ch 7 does. Masking the instruction is Exercise 7.2.

The book calls instruction masking common, but notes researchers are divided. It cites Shi et al. 2024, which found that keeping the loss on the instructions helped, especially when instructions are long and outputs short, or when there are few training examples (Appendix B). The book's own exercise solution points the same way: the masked version scored slightly worse, about 4 points, with the chapter's judge (Appendix C).

Principle

The inputs decide what the model sees; the targets decide what it learns

Every token in the row is read, including the template and the instruction. Only the targets you leave counted produce gradient. Padding is always set to −100; the end token after the answer is always kept; the instruction is your call.

Buys you: a loss number that means "how well does it answer", and a model that learns to stop.

Don't read too much into it. This base model already handles easy requests, and the lab doesn't show why. The book's untrained GPT-2 medium (355M parameters) did not: given a "make this sentence passive" instruction, it repeated the sentence (§7.5). The template is where instruction tuning starts; the training is what makes the behaviour reliable.

The failure you will hit: the model never stops

Failure · end token masked
Symptom
After fine-tuning, answers are right but keep going: a new ### Instruction: block, or text until the length limit.
Cause
The collate code masked every end-of-text token, including the one right after the answer (easy to do, because padding uses the same token), or never appended it. The model was never graded on stopping.
Isolate
Print one batch's target rows. Each row should hold exactly one counted end token, right after the answer, followed by −100s.
Fix
Mask only the padding copies after the first end token, as §7.3 does. (Or pad with a separate pad token and mask by position.)

If no target ever says "stop", the model never learns to.

Where this sits, and what it doesn't do

  1. It's step 1 of the RLHF recipe. SFT teaches the format and imitates the written responses. Preference training comes after it: Learn what people prefer, then chase it. SFT on agent traces is the same loss with longer rows: Fine-tune a model on coding-agent traces. What post-training costs: From pretrained to served: SFT, RL and distillation.
  2. It can only imitate. The loss rewards matching the written response token by token, so it pulls the model towards its examples, not past them, and a wrong example is learned as faithfully as a right one.
  3. Chat models use special tokens, not "###" text. Real chat templates mark turns with tokens like <|im_start|>, reserved token IDs instead of ordinary words. The book shows such a style (Phi-3's, with <|user|> and <|assistant|>) next to Alpaca in §7.2, and Exercise 7.1 trains with it. Masking works the same way: grade the assistant turns.
  4. The loss doesn't tell you if answers are good. Ch 7 (§7.8) scores its model's test answers with another model: an instruction-tuned 8-billion-parameter Llama 3, run locally with Ollama, asked to rate each answer from 0 to 100 against the reference. That's LLM-as-judge, and judges have their own failure modes: Rewards you can't verify.

Check yourself

1. Why does unmasked padding cost so much more than the answer tokens, on a base model?

Show the answer

Each padding target asks the model to predict an end token right after an end token. A model pretrained on documents expects a new document there, so it gives that a tiny probability: about 17 loss per position vs 1.2 on answers. 51 of those positions made 83% of the total.

2. You set every <|endoftext|> in the targets to −100. What breaks, and why?

Show the answer

The model is never graded on ending the answer, so it doesn't learn to stop. Keep the first end token after each response as a target; mask only the padding copies after it.

3. Masking the instruction lowered our mean loss from 2.35 to 1.20. Does that mean masking is better?

Show the answer

No. The number dropped because it now averages only over the easier answer tokens; nothing was trained. Whether masking helps is measured on outputs, and the book's exercise found it slightly worse (about 4 points with its judge), matching Shi et al. 2024.

Understand and remember

  • every example rendered into one fixed template → the same marker always precedes the answer → the model learns 'after this marker, write the answer, then the end token' → at use time you render a new request and stop after the marker
  • rows have different lengths → pad with the end token to the longest → targets = inputs shifted by one → padding becomes targets asking for 'end token after end token' → a base model expects a new document there → 51 padding targets made 83% of the loss (mean 17.2 vs 1.2 on answers)
  • set padding targets to −100 → cross_entropy skips them (ignore_index default) → the mean covers real tokens only (8.21 → 2.35) → gradient goes to the answer, not to predicting padding
  • keep the first end token after each response as a target → the model is graded on stopping → mask it too and the fine-tuned model runs on past its answer
  • detail that matters Masking the instruction as well grades only response tokens (2.35 → 1.20 on 29 of 129 positions) → less signal per example; the book leaves it off, and its exercise found the masked model about 4 points worse, as Shi et al. 2024 did
  • detail that matters The mean is over counted tokens, not examples → one long answer (23 of 29 counted tokens in our batch) outweighs short ones

Reference only

  • Alpaca-style markers: ### Instruction:, ### Input: (optional), ### Response:; the book adds a one-line preamble
  • PyTorch: F.cross_entropy(..., ignore_index=-100) is the default
  • Book setup: 1,100 instruction–response pairs, 85/10/5 split, GPT-2 medium (355M), end token ID 50256 as padding
  • Book evaluation (§7.8): instruction-tuned Llama 3 8B via Ollama scores each answer 0–100 against the reference

5 · Predict commit to an answer before revealing

Suppose you pad on the left instead of the right (padding first, then the template), still masking padding targets with −100 but passing no attention mask. Does the loss on the answer tokens stay the same? Commit before checking.

Reveal

No. With left padding the real tokens come after the padding, so causal attention lets every real token attend to it, and the positions shift too. Measured on example 1 with no attention mask: the answer losses went from 7.38, 0.13, 1.84, 0.06 (right padding, identical to no padding) to 9.15, 4.57, 3.91, 0.28. Right padding is safe without an attention mask because it only ever comes after the real tokens; left padding needs an attention mask and matching positions.
