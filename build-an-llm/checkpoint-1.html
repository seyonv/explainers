Checkpoint: build an LLM

Ties together the five days of the path: PyTorch (Raschka appendix A), training pairs and attention (ch 2–3), the GPT model (ch 4), pretraining (ch 5), and the two fine-tunes plus LoRA (ch 6–7, appendix E) with instruction tuning and LoRA. The book's model is GPT-2 124M; the cards' numbers are measured on Qwen2.5-0.5B.

What this ties together. You coded a GPT one chapter at a time. Here you check that you can say, without the code open, what each piece does, what shape comes out of it, and what goes wrong when it's set up badly.

How to use this page. Close the book and the cards. Answer each question in writing, in full sentences, before opening its Check. Where a question asks for a number, commit to a rough value first; the reason matters more than the digits. A wrong or shaky answer isn't a failure: the Check names the card or book section to reopen. The questions are mixed on purpose, so part of the work is picking the right idea.

1 · Mixed retrieval

  1. mechanismWrite one step of a PyTorch training loop from memory, in order, starting from a batch of inputs and targets. What does each line change? Then: a teammate's loop leaves out optimizer.zero_grad(). Training still runs and the loss even falls at first. What is actually happening?
    Check
    • forward: logits = model(inputs) computes predictions; nothing is stored in the weights
    • loss: loss = cross_entropy(logits, targets), one number for how wrong the batch was
    • optimizer.zero_grad() clears the old gradients; loss.backward() fills each weight's .grad; optimizer.step() moves every weight against its gradient. Zeroing can come first or just before backward, as long as it happens every step
    • without zeroing, backward() adds to the old gradients, so each step pushes with the sum of all gradients so far: a step size that keeps growing. On an easy problem the loss can still fall, which hides the bug

    Missed it? Reopen Raschka §A.7 (a typical training loop) and the hub card From neuron to MLP to a training loop, "Forgetting zero_grad".

  2. predictA batch of 2 sequences, 6 tokens each, goes into multi-head causal attention with model width 768 and 12 heads. Give the shape after each step: the input, the queries, the queries split into heads, the attention scores, the weighted values, and the output. Where does the causal mask act?
    Check
    • input: (2, 6, 768), written (batch, tokens, width)
    • queries, keys and values: each (2, 6, 768), from three weight matrices
    • split into heads: view as (2, 6, 12, 64), then transpose to (2, 12, 6, 64); each head gets 768 ÷ 12 = 64 numbers per token
    • scores: queries × keys transposed → (2, 12, 6, 6), one 6 × 6 grid per head. The mask sets everything above the diagonal to −∞ before softmax, so no token sees a later one
    • weights × values → (2, 12, 6, 64); transpose back and merge the heads → (2, 6, 768); the output projection keeps (2, 6, 768). Same shape in as out, which is what lets blocks stack

    Missed it? Reopen Raschka §3.5–3.6 and print the shapes in your own code; the hub's One head, then many heads and Masked softmax.

  3. mechanismWhy are the targets the inputs shifted by one token, and how can one forward pass over 8 tokens grade 8 separate predictions honestly? Then: you shift the targets in your loader and pass them to a Hugging Face model as labels. What does the model learn?
    Check
    • the right answer at every position is the next token, so targets = tokens[1:n+1] for inputs = tokens[0:n]: the text labels itself
    • the causal mask stops position i from seeing token i+1, so each guess is a real guess even though the answer sits in the input. Measured on Qwen: one pass and 8 separate prefix passes differ by at most 0.00018 in the logits, float rounding
    • so 8 tokens of input give 8 graded predictions in 1 pass; generation needs a pass per new token
    • Hugging Face shifts labels itself (model(chunk, labels=chunk) gave 5.742, the same as the hand shift), so shifting twice asks every position for the token two ahead

    Missed it? Reopen Every position is a training example, "One pass grades every position" and the failure box; Raschka §2.6.

  4. predictYour text has 33 tokens. With a context length of 8, how many chunks and graded predictions do you get at stride 8, and at stride 4? How many different targets does each give? And what happens to the loss when you cut the text into chunks rather than running it as one sequence?
    Check
    • stride 8: chunks start at 0, 8, 16 and 24 → 4 chunks, 32 predictions, 32 distinct targets
    • stride 4: 7 chunks, 56 predictions, still 32 distinct targets: 24 are graded twice. More rows, not more information
    • chunking costs context: on Qwen the same 32 targets scored 4.873 as four chunks of 8, against 4.145 in one pass, because each chunk starts over with no context

    Missed it? Reopen Every position is a training example, "A sliding window cuts a long text into chunks" and "More context makes the next token easier".

  5. predictYour untrained GPT-2 starts training on the book's short story. Predict the starting loss roughly, and why. Then the training loss keeps falling while the validation loss stops improving after the second epoch. Is your code wrong? What would change it?
    Check
    • start near ln(50,257) = 10.82, the loss of spreading bets evenly over GPT-2's vocabulary; the book's untrained model scores about 10.8 (§5.1.2)
    • the story is 5,145 tokens, trained for several epochs: the model memorises it and starts reciting passages, so the training loss keeps falling while text it hasn't seen doesn't get easier (§5.2)
    • that's expected, not a bug. More text fixes it: the book notes that on 60,000 Project Gutenberg books this overfitting doesn't happen. Real pretraining does about one pass over far more data
    • validation loss is the one to trust: it's measured on text the model never trained on

    Missed it? Reopen Raschka §5.1–5.2; the hub's Train/dev/test and under- vs overfitting, "Reading the two losses".

  6. which concept?Your chapter 4 model prints 163,009,536 parameters, not 124 million. Where do the extra weights sit, how many are there, and what does weight tying do about them? Qwen2.5-0.5B ties too: how much does it save there?
    Check
    • the output layer that scores every vocabulary entry: 50,257 × 768 = 38,597,376 weights, the same shape as the token embedding table
    • tying uses the embedding table for both jobs (look up a row going in, score every row going out), so those weights are stored once: 163,009,536 − 38,597,376 = 124,412,160 (§4.6)
    • on Qwen the shared table is 151,936 × 896 = 136,134,656 weights, 27.6% of the model, paid once instead of twice
    • it saves memory and parameters, not compute: the output scores still cost a full multiply by the table at every step

    Missed it? Reopen Raschka §4.6 and the hub's Weight tying: one matrix, two jobs.

  7. predictThree instruction examples are padded with end-of-text tokens into one batch: 129 target positions, 51 of them padding. Without masking, roughly what share of the loss comes from padding, and why so much? What does −100 do, and which end-of-text token must not get it?
    Check
    • 83% of the loss, measured on the Qwen base model: after an end token it expects a new document, so each padding target costs about 17, against about 1.2 for answer tokens
    • −100 is cross-entropy's default ignore index: those targets are skipped and the mean is taken over the rest. Masking padding took the mean from 8.21 to 2.35; masking the instruction too left 1.20 over the 29 answer targets
    • the inputs don't change, only the grading: the model still reads the whole template
    • keep the first end token after each answer as a target. Mask it too and the model never learns to stop

    Missed it? Reopen Teach the format, grade only the answer, "Padding is 40% of the targets and 83% of the loss" and the failure box; Raschka §7.3.

  8. trade-offChapter 6 fine-tunes GPT-2 into a spam classifier; chapter 7 fine-tunes it to follow instructions. Compare the two: what replaces or keeps the output layer, which position the loss reads, what is trained, and how you'd know it worked. Which would you pick to route support tickets into 5 queues?
    Check
    • classifier (ch 6): the 50,257-way output layer is replaced by a 2-way one, and only the last token's output is read, because under the causal mask it's the only position that has seen the whole message (§6.5)
    • it trains the new head plus the last transformer block and the final layer norm; the rest stays frozen. Success is accuracy on held-out messages (§6.6–6.8)
    • instruction tuning (ch 7): keeps the vocabulary head and the next-token loss at every answer position, on examples in a template. The output is free text, so success needs a judge or a person (§7.8)
    • 5 queues: a classifier with a 5-way head. Fixed labels, cheap, measurable by accuracy, and it can't wander off-format. Instruction tuning pays when the output is open-ended

    Missed it? Reopen Raschka §6.1, §6.5 and §7.1; Teach the format, grade only the answer, "Three words first".

  9. mechanismExplain LoRA on one matrix: what is frozen, what is trained, how the two are combined, and why B starts at zero. On Qwen2.5-0.5B with LoRA on q_proj and v_proj at rank 8, predict the share of weights trained and the training memory against full fine-tuning.
    Check
    • W is frozen; two thin matrices are trained, A (r × din) and B (dout × r). The layer computes W x + (alpha / r) · B A x
    • B = 0 at the start, so B A x = 0 and step 0 is exactly the base model (the lab measured identical logits). If A were zero too, neither could get a gradient
    • 540,672 trained numbers, 0.109% of 494,032,768. Memory in float32 with Adam: 7.90 GB for full fine-tuning (weights, gradients, two Adam averages) against 1.98 GB, because frozen weights need no gradient or optimizer state
    • after training, W' = W + (alpha / r) · B A folds the detour in: the merged model has 494,032,768 parameters again and runs at the original speed

    Missed it? Reopen Fine-tune a sliver of the model, "Freeze W, and learn a thin detour beside it" and "Training every weight costs four copies"; Raschka appendix E (§E.4).

  10. which concept?You fine-tune twice, once with the instruction masked and once without, and score both with the chapter 7 judge (Llama 3 8B via Ollama, 0 to 100 against the reference answer). The masked run averages about 4 points lower. Can you conclude masking hurts? Name two ways the judge's numbers can mislead you, and what you'd check.
    Check
    • not from one run each: Ollama isn't fully deterministic across machines, so scores move a little between runs (§7.8). Rerun the judge, and fine-tune with another seed, before trusting a 4-point gap
    • the judge is a model with biases: LLM judges tend to score longer answers higher and can be swayed by position or by their own style. A run that writes longer answers can win without being more correct
    • check: read the answers where the two runs' scores differ most and decide yourself; compare answer lengths; keep the test set and judge prompt fixed
    • for what it's worth, the book's Exercise 7.2 solution did find masking about 4 points worse with this judge, in line with Shi et al. 2024, but that's evidence, not proof

    Missed it? Reopen Raschka §7.8; Teach the format, grade only the answer, "Masking the instruction too is a choice"; the hub's Rewards you can't verify, the judge-bias table.
