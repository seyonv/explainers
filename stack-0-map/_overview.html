In one breath

"The agent" is a chain of systems that don't own the same job. Sort them by ownership (who owns the run, the working set, the capability, the side effect and the evidence afterward) and a failure stops being "the agent was weird" and becomes a question with an answer: which owner's record disagrees with the world? Overloaded words like done, session or memory hide two owners each, so split them. Then test the split the way Govindarajan does: pin one release, run one boring task with a positive and a negative control, and believe exit codes, bytes and receipts, not the agent's prose. Courses 1–6 take one group of owners each; course 7 measures the one failure the whole series keeps returning to, a false "all tests pass" after compaction.

You already know: the agent loop (call, tool, append, repeat). The map puts that loop inside the layers around it.

The words people use

Agent vs harness vs stack

"Agent" usually means the whole thing. The harness (or scaffold) is the code around the model: loop, tools, context. The stack is all ten layers, including the parts no harness owns, like the operator loop afterward.

Layer vs product

A product name says who sells it; a layer says what it owns. One provider API can bundle state, tools, hosted execution and tracing, so "which platform?" never answers "which layer failed?"

Forensics vs evals

Forensics finds where a claim detaches from the world, usually from one pinned run per condition. Evals measure how often, over many tasks and repeats. Use the first to find a boundary and the second to measure it.

✓ Ownership

Who owns the run, the working set, the capability, the side effect and the evidence. His Part 1 calls this, not the list of ten, the main idea, and every course in the series is organized by it.

When this advice doesn't apply

Small runs don't need the map. A single model call with no tools has no execution surface and nothing to approve, so most layers are empty. The map earns its keep once a run has side effects, survives across turns, or must be explained afterward. Each split also costs a record and an owner; for a throwaway script, checking the output is enough.

The map is his v1, not a standard. He calls it "not final", Part 7 covers layers 7 and 8 together, and the boundary pairs are his framing, not an industry vocabulary. Knowing which layer owns a moment says where to look, not who is at fault.

Forensics shows that, not how often. Every number on this page is a single pinned run or the illustrative Tuesday run. The rates are open questions; the research bank lists them, and the capstone measures one. The hours are the series plan's estimates.

Why this step?

5 · Predict commit to an answer before revealing

A different run: the agent's push goes to the wrong branch because a stale session record from yesterday was loaded, and its final message correctly says "pushed to main". Commit to the owning layer, the record you check, the course, and whether this is a false success claim.

Reveal

The control plane (layer 2) loaded the wrong session state, so check the session record and how it was keyed: course 1, owning the session. If the push really went to main as the message says, it is not a false success claim: the claim matches the world, and the failure is that the wrong action happened. That is why the ownership table starts from the moment, not from the final message; only some failures show up as a false claim.
