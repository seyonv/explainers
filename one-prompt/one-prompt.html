One prompt, all the way through

Also called: the forward pass end to end, the inference pipeline, autoregressive generation. This card follows What is the capital of India? through a real model, Qwen2.5-0.5B (a base model with no chat tuning), on an M3 Mac. Every number on it is measured. The papers are listed in the order the prompt meets them, so Attention Is All You Need comes fourth, not first.

Prime · 2 minutes before you read

The problem: Starting with Attention Is All You Need leaves Q, K and V floating: the paper assumes you already know what a token is, where its vector comes from, what the model outputs and how one output becomes the next input. Without that route in your head, every later paper is a box with no arrows going in or out.

In one breath: text is cut into tokens, and each token becomes an integer and then a vector. A stack of identical blocks mixes those vectors together. The last vector becomes one score per vocabulary entry, the decoder picks one token, and that token is appended to the input before the whole thing runs again.

29 characters become 7 tokens (Qwen's byte-level BPE, 151,665 tokens in its vocabulary). The leading space is part of each token. The model only ever sees the integers.

token id 6747 ( India) → row 6747 of a 151,936 × 896 table → a vector of 896 numbers table size: 151,936 × 896 = 136,134,656 weights ≈ 28% of the model's 494M cosine similarity between learned token vectors: India · China 0.449 India · Pakistan 0.443 Delhi · Mumbai 0.483 India · capital 0.009 India · banana 0.013 Delhi · banana 0.097

Nobody tells the model that countries belong together. Training puts tokens that appear in similar contexts near each other, which is word2vec's idea. These numbers come from Qwen's own embedding table, before any context is added.

Pure sampling (T = 1, no cut) with seeds 0 to 3 produced Which is the capital of Kenya?, a colon and a list, The capital of India is not Delhi but… and a multiple-choice question. That is the "degeneration" Holtzman et al. describe: every tail token is unlikely on its own, but together the tail holds enough probability (0.09 on this step) that over a dozen steps, sampling lands in it often.

P(answer) = P(t₈ | t₁…t₇) · P(t₉ | t₁…t₈) · … = 0.277 × 0.964 × … × 0.680 ≈ 0.11

Greedy decoding, nine forward passes, and each number is the probability of the chosen token at that step. The uncertain steps are the first word (how should a reply start?) and New versus Delhi. Once New is chosen, Delhi is 0.994. In a real server, steps 2 onward reuse the cached K and V of earlier tokens instead of recomputing them: 24 layers × 2 KV heads × 64 dims × K and V × 2 bytes = 12 KB per token.

Why this reading order beats the alternatives

✗ Start with Attention Is All You Need

It assumes you already know tokens, embeddings, softmax and decoding, and it describes a 2017 translation model (encoder plus decoder). Q, K and V have nothing to attach to yet.

✗ Read whatever is trending

FlashAttention and GQA papers optimise a step you can't place yet. You learn the speed-ups before the thing they speed up.

✗ Memorise the block diagram

You can name the boxes but not say what shape goes in or comes out, so you can't predict what changes when a box changes.

✓ Follow one prompt

Every stop has an input and an output you can check (7 tokens, 7 × 896, 151,936 scores, one token), so each paper answers a question you already have.

The reading list, in pipeline order

  1. Tokens: Sennrich et al. 2015, BPE for rare words · SentencePiece (the hub's SentencePiece card)
  2. Embeddings: word2vec · Distributed representations of words and phrases
  3. Positions: Attention Is All You Need §3.5 (sinusoids) · RoFormer (RoPE), which Qwen uses · ALiBi (a bias on attention scores instead of a rotation)
  4. The transformer: Attention Is All You Need · The Illustrated Transformer
  5. Attention, made cheap: MQA · GQA, which Qwen uses · FlashAttention · FlashAttention-2 (the hub's GQA and FlashAttention cards)
  6. Feed-forward → experts: Switch Transformers (dense → mixture of experts → sparse compute)
  7. Logits and the loop: GPT-3
  8. Decoding: The Curious Case of Neural Text Degeneration (where top-p comes from)

Is the pipeline order the whole truth?

Not quite. Stops 5 and 6 aren't two stages the data passes once. They make up one block that runs 24 times, with a residual connection that adds each block's output back onto its input. Q, K and V also go beyond "what I'm looking for, what I contain, what I give": they're three learned projections of the same vector, and that slogan is only a mnemonic. In our run, layers 6, 12 and 18 each sent 35–63% of the last token's attention (averaged over heads) to the very first token, What. That is an "attention sink", a learned parking spot, not interest in the word. Leave out the sink and the token itself, and layer 12's top two are capital and India (0.122 and 0.116), while layer 18's top is capital (0.128).

The order is also wrong for some goals. If you're writing kernels, start at FlashAttention; if you're serving models, the inference path starts from latency and works inward. Base-model behaviour isn't chat behaviour either. A chat model's template would make the first token near-certain, where this base model gave its top choice for the first token only 0.277. One note on the source post: its first two tokenizer links are the same paper (arXiv 1508.07909).

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • Text is cut by learned merges (BPE) → each piece is an integer ID → the ID selects one row of the embedding table → the model only ever works with those vectors, never with letters, which is why spelling and digits behave oddly
  • Attention mixes tokens together but ignores order → order has to be injected (learned positions, sinusoids, RoPE rotating Q and K, or ALiBi's distance bias) → without it, India of capital would look the same as capital of India
  • One block = attention (tokens read earlier tokens) + feed-forward (each token on its own), both added back through a residual → the block repeats 24 times with the shape fixed at tokens × 896 → only the last position's vector is turned into 151,936 logits
  • Logits → softmax → a decoder picks one token → it's appended and the model runs again → each new token is P(tₙ | t₁…tₙ₋₁) → earlier tokens' K and V are cached, so each new step adds about 12 KB of memory instead of recomputing the prefix
  • detail that matters The embedding table is also the output layer (tied weights) → it holds 136M of the 494M parameters → in a small model, vocabulary size is a big share of the size, and that share shrinks as the model gets wider and deeper
  • detail that matters Sampling from the full distribution keeps the long tail → here 0.09 of the probability sat below the top-p 0.9 cut → over many steps, pure sampling lands in the tail often, which is why top-p exists

Reference only

  • Qwen2.5-0.5B: 24 layers, hidden 896, 14 query heads, 2 KV heads, head dim 64, FFN 4,864 (SwiGLU), vocab 151,936 (151,665 used)
  • our prompt's IDs: [3838, 374, 279, 6722, 315, 6747, 30]
  • the paper per stop: BPE (Sennrich 2015), SentencePiece, word2vec, RoFormer, ALiBi, Attention Is All You Need, MQA, GQA, FlashAttention 1–2, Switch Transformers, GPT-3, Holtzman et al. 2019

Check

Why this step?

5 · Predict commit to an answer before revealing

Make the prompt twice as long, 14 tokens instead of 7. Which of these change: the hidden shape between blocks, the number of logits used to pick the next token, the model's parameter count, the KV cache before the first answer token? Commit, then reveal.

Reveal

The hidden shape becomes 14 × 896, and the KV cache doubles from 7 × 12 KB = 84 KB to 168 KB. The parameter count stays at 494M: weights don't depend on prompt length. The number of logits used stays at 151,936: the model scores every position, but only the last row picks the next token. That is why prompt length costs memory and prefill time but not model size.

Hint

KV bytes per token = layers × KV heads × head dim × 2 (K and V) × 2 bytes. Query heads don't appear, which is the whole point of GQA.
