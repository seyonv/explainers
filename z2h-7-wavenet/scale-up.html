Scaling up: 76,579 params, val 1.993

Also called: widening the network, the final WaveNet of the lecture, the number to beat. Lecture 6 · scaling up our WaveNet · 0:46:07 · improve on my loss! · 0:55:26

Prime · 2 minutes before you read

The problem: After the BatchNorm fix the tree net sits at val 2.0202, barely better than the flat 8-character net. At 22K parameters each tree node has only 68 numbers to describe a pair of characters. Unless you give it more room, you can't tell whether the tree is a dead end or just starved.

Where it fits: This is the last training run of the lecture. It takes the fixed hierarchical net from the BatchNorm bug card, leaves its structure alone, and only widens n_embd and n_hidden. It also closes the performance log that began with the 3-character baseline.

In one breath: keep the tree-shaped network from the last cards exactly as it is, and only make it wider: 24 numbers per character embedding instead of 10, and 128 hidden units per tree node instead of 68. That takes the model from 22,397 to 76,579 parameters (weights and biases), and after the same 200,000 training steps the validation loss drops below 2.0 for the first time, to 1.9937.

Predict first: the 22K tree net scored train 1.9110, val 2.0202. After scaling it to 76K parameters, which loss falls further, train or val, and by roughly how much each?

Train falls about five times as far. Train goes 1.9110 → 1.7690 (−0.142); val goes only 2.0202 → 1.9937 (−0.0265). So the gap between them doubles, from 0.109 to 0.225. The bigger model gets much better at the names it trains on and only a little better at names it has never seen. Val is the number that counts.

Two knobs, 3.4× the parameters

The network is the one from FlattenConsecutive: an embedding turns each of the 8 context characters into n_embd numbers, then three levels each glue two neighbours together (FlattenConsecutive(2)), mix them with a Linear layer (a matrix multiply) into n_hidden numbers, normalise them with BatchNorm1d and squash them with tanh. A last Linear layer turns the final n_hidden numbers into 27 logits, one score per possible next character. Only two numbers change on this card:

P= 27eembedding + 2e·hlevel 1 + 2·(2h·h)levels 2 and 3: grow as h² + 3·2hBatchNorm + (27h+27)output
Ptrainable parameters22,397 → 76,579 en_embd: numbers per character embedding10 → 24 hn_hidden: hidden units in each tree node68 → 128 27vocabulary: 26 letters plus '.'fixed

The Linear layers inside the tree have no bias (bias=False), because the BatchNorm right after them adds its own shift, β. Each BatchNorm has a scale γ and a shift β per hidden unit, so 2h parameters.

Level 2 grew from 136 × 68 = 9,248 to 256 × 128 = 32,768 weights: (128/68)² ≈ 3.54×. The two middle levels are 65,536 / 76,579 = 85.6% of the model. Of the two knobs, n_hidden does almost all the work: with n_embd left at 10, n_hidden = 128 alone gives 72,617 (computed with the lab's model code). The lab prints 76579, the same as the notebook.

The whole lecture in five rows

Loss is the average negative log likelihood of the correct next character: lower is better, and guessing uniformly over 27 characters scores ln 27 = 3.2958. Train is measured on the 80% of names the model learned from, val (validation) on 10% it never saw. Every row trained for 200,000 steps.

What does 1.9937 mean? e−1.9937 = 0.136: on average (a geometric mean) the model gives the right next character about a 13.6% probability, against 1/27 = 3.7% for a blind guess. It's like choosing among e1.9937 ≈ 7.3 equally likely characters instead of 27.

▶ Build itruns on your M3 · about 2.5 min

When: pause the video at 0:46:07 and change the two widths before watching on. Everything else, including the training loop, is the code you already have from the BatchNorm fix.

n_embd = 24     # was 10
n_hidden = 128  # was 68
model = Sequential([
  Embedding(vocab_size, n_embd),
  FlattenConsecutive(2), Linear(n_embd * 2, n_hidden, bias=False),
    BatchNorm1d(n_hidden), Tanh(),
  FlattenConsecutive(2), Linear(n_hidden*2, n_hidden, bias=False),
    BatchNorm1d(n_hidden), Tanh(),
  FlattenConsecutive(2), Linear(n_hidden*2, n_hidden, bias=False),
    BatchNorm1d(n_hidden), Tanh(),
  Linear(n_hidden, vocab_size),
])
with torch.no_grad():
  model.layers[-1].weight *= 0.1  # last layer: less confident
print(sum(p.nelement() for p in model.parameters()))
# same loop: 200000 steps, batch 32,
# lr = 0.1 if i < 150000 else 0.01
for layer in model.layers:
  layer.training = False  # BatchNorm: use running stats
split_loss('train'); split_loss('val')
# then sample 20 names, one context at a time

Why it beats the earlier rows

✗ Flat MLP, 3 characters

12,097 params, val 2.1065. It sees only the last 3 characters, so it almost never sees a whole name when it has to decide where the name ends.

✗ Flat MLP, 8 characters

22,097 params, val 2.0342. It has the context, but one Linear layer has to mix all 80 input numbers in a single step.

✗ Tree net at 22K

22,397 params, val 2.0202 once the BatchNorm bug is fixed. It has the right structure, but it squeezes each pair of characters into 68 numbers built from 10-number embeddings.

✓ Tree net at 76K

The same tree with room in every node: 24-number embeddings, 128 units per node. Val 1.9937, the lecture's best and the first result below 2.0.

Did the tree win, or the parameters?

This card doesn't say, and neither does the lecture. The flat net was never scaled up to 76K, so part of the gain may just be the extra parameters. Karpathy lists a big flat one-hidden-layer net among the things to try, and says it "would be kind of embarrassing" if it won (0:55:26). Two more reasons for caution: every row is a single run with a single seed, so a 0.006–0.007 step (the BatchNorm fix) may be noise, and the train–val gap doubled, which suggests (our reading) that more width would soon buy memorisation rather than better val. He admits he's tuning "a little bit in the dark" (0:46:07).

So "make it bigger" is the right move when val is still falling with the gap under control. It's the wrong move when you need to know why a model is better: then compare at equal parameter counts, run several seeds and use an experiment harness (next card). Karpathy's challenge is to beat 1.993 on val. Ideas he suggests:

  • Spread the units differently across the levels, or change the embedding size.
  • Try a big flat net as the honest control.
  • Add the WaveNet paper's gated activations and residual and skip connections, which weren't implemented here.
  • Tune the initialisation and the optimisation (learning rate, schedule, steps).

Keep the test split untouched until the very end, or 1.993 stops meaning anything.

Understand and remember

  • Levels 2 and 3 map 2·n_hidden inputs to n_hidden outputs → each is a (2h × h) matrix → parameters grow as h² → going 68 → 128 multiplies them by about 3.54×, and they end up as 85.6% of the model
  • More width → more capacity to fit the training names → train drops much further than val (−0.142 vs −0.0265) → the gap doubles to 0.225 → the gains start to go into memorising rather than generalising
  • Only one run per row, and the flat net was never widened → the log can't separate "tree beats flat" from "more parameters beat fewer" → a fair claim needs equal-parameter controls, several seeds and a harness
  • Training length matters as much as size → the 20k-step quick run of the 76K net stops at val 2.0478 (the 22K tree's quick run: 2.097), above every 22K net's full 200k-step val → compare two models only at the same number of steps and the same lr schedule
  • detail that matters BatchNorm must be switched to eval mode (training = False) before split_loss → otherwise train/val are computed with batch statistics of the whole split and sampling one context at a time breaks, so the 1.9937 would not be how the model scores when it predicts one name at a time

Reference only

  • the exact settings: n_embd = 24, n_hidden = 128, 200,000 steps, batch 32, lr 0.1 then 0.01 from step 150,000
  • the last layer's weights are scaled by 0.1 at init (model.layers[-1].weight *= 0.1)
  • the per-layer counts 648 / 6,144 / 768 / 32,768 / 32,768 / 3,483
  • the notebook's cells: 9 (model), 10 (loop), 14 (performance log), 15 (sampling)
  • the 20 sampled names (arlij., chetta., heago., …)

Check
