WaveNet's idea: fuse context slowly, in a tree

Also called: a hierarchical MLP, progressive fusion, the WaveNet tree. Lecture 6 · overview: WaveNet · 0:17:11

Prime · 2 minutes before you read

The problem: The flat MLP glues all 8 context characters into one long vector and squashes them in a single hidden layer. Everything is mixed in one step, and that first layer grows every time you widen the window.

Where it fits: It builds on the block_size-8 flat baseline (val 2.027) from the previous card. The architecture stays an MLP; only the wiring changes, so the context is fused gradually over several levels.

In one breath: instead of feeding all 8 context characters into one hidden layer at once, fuse neighbours in pairs, then fuse the pairs, then fuse those. Each level doubles how many characters a node can see (2, 4, 8), so the network builds up the context gradually. DeepMind's WaveNet (2016) used this layout for audio. Its "dilated causal convolutions" are just a fast way to compute the same tree.

Predict first: with 8 characters fused two at a time, how many levels does the tree need before one node sees all 8? And how many separate weight matrices does the first level need for its 4 pairs?

3 levels, and 1 matrix. Each level halves the number of nodes (8 → 4 → 2 → 1), so 8 = 23 needs 3 levels. Every pair in a level goes through the same Linear layer, so level 1 has one weight matrix that it applies 4 times.

The tree for one training example

The name diondre gives 8 training rows. The last one is .diondre --> .: from these 8 characters, predict the end of the name. Here is how the tree reads that context.

A fusion node takes its two children's vectors, glues them end to end, and runs them through a Linear layer, BatchNorm and tanh. That's the same "hidden layer" as the earlier MLP cards; it now sees only two inputs at a time. The number of input characters a node depends on is its receptive field. It doubles at each level:

receptive field=2L ⇒ 23=8 24=16

In tensor shapes for a batch of 4 (with n_embd 10 and n_hidden 200, from labs/flatten-consecutive.py), the middle number counts a level's nodes. It halves at each level, while the input width per node doubles:

Embedding (4, 8, 10) 8 leaves, 10 numbers each level 1 (4, 4, 20) → Linear → (4, 4, 200) 4 nodes, each sees 2 chars level 2 (4, 2, 400) → Linear → (4, 2, 200) 2 nodes, each sees 4 chars level 3 (4, 400) → Linear → (4, 200) 1 node, sees all 8 output Linear → (4, 27) logits for the next char

(4, 4, 20) means 4 examples × 4 pairs × 20 numbers (two 10-number embeddings glued together). The next card builds the layer that does this regrouping.

Why it beats the alternatives

✗ Flat MLP, wider window

Glues all 8 embeddings into 80 numbers and squashes them in one hidden layer. Its first layer grows with the window: 30 × 200 = 6,000 weights at block_size 3, 16,000 at 8, 32,000 at 16.

✗ Flat MLP, more layers on top

Extra layers come after the first one has already mixed all 8 characters. Nothing is fused gradually, so the depth doesn't help with the crushing.

✗ A separate layer per pair

Giving each pair position its own weights would make level 1 four times bigger. Each copy would also learn "how to read two characters" from only a quarter of the pairs. (Our inference, not tested in the lecture.)

✓ Pairwise tree, shared per level

Each node sees only two inputs. Every position reuses its level's weights, and depth grows with log2 of the context. Doubling the context adds one level: 136 × 68 + 136 = 9,384 params at n_hidden 68.

Is the tree always better, and where do convolutions come in?

No. At about 22K parameters, the tree only tied the flat net (val 2.029 vs 2.027 in the notebook). After the BatchNorm fix it was slightly ahead at 2.022, and Karpathy isn't sure that gap is real. The big win in this lecture came from scaling the tree up to 76,579 parameters (val 1.9937). His closing challenge admits that a big flat net might still beat it. The tree also fixes which characters meet first (positions 1+2, 3+4, …). The real WaveNet adds gated activations and residual and skip connections, which the lecture doesn't build.

The paper's dilated causal convolutions don't change this model. In the overview (0:17:11) Karpathy calls them an "implementation detail" for speed. "Causal" means a node only sees earlier characters. "Dilated" means level k reads inputs 2k−1 apart (1, 2, 4). A convolution slides the tree along the whole name at once and reuses the nodes that overlapping windows share. For the 8 rows of diondre, the loop computes 56 nodes but only 34 are distinct (see the convolutions card).

Understand and remember

  • each node fuses exactly 2 children → nodes halve at every level (8 → 4 → 2 → 1) → a level-L node sees 2L characters → 3 levels for block_size 8, and one more level per doubling of context
  • every node in a level uses the same Linear weights → level 1 stores 20 × 68 = 1,360 weights but applies them 4 times → the tree's cost grows with log2 of the context, while the flat first layer grows linearly (6,000 → 16,000 → 32,000 weights at block_size 3 → 8 → 16)
  • the tree is a fixed pattern of "glue two neighbours, apply a shared layer" → sliding that pattern along a whole name is a convolution → dilated causal convolutions compute the same nodes for all positions at once and reuse overlapping ones (56 computed vs 34 distinct for diondre) → same model, only faster
  • wiring alone doesn't guarantee a win → at equal parameters (22,097 flat vs 22,397 tree) val was 2.027 vs 2.029 (then 2.022 after the BatchNorm fix) → the tree's advantage in the lecture shows up only when it is scaled up (76,579 params, val 1.9937)
  • detail that matters the tree pairs fixed positions (1+2, 3+4, …) → which characters meet first is baked into the architecture → a pattern split across a pair boundary (e.g. positions 2 and 3) only meets at level 2

Reference only

  • the lecture's tree: n_embd 10, n_hidden 68, three FlattenConsecutive(2) + Linear + BatchNorm1d + Tanh blocks
  • the paper's figure has 4 levels (receptive field 16), with dilations 1, 2, 4, 8
  • WaveNet paper: van den Oord et al. 2016, arXiv 1609.03499
  • shape walk at batch 4, n_hidden 200: (4,8,10) → (4,4,20) → (4,2,400) → (4,400) → (4,27)

5 · Predict commit to an answer before revealing

Keep the lecture's tree, but set block_size to 6 instead of 8. What goes wrong when you fuse pairs, and what are two ways to fix it?

Reveal

6 → 3 → then 3 nodes can't be split into pairs, so the third level breaks (in code, view fails or the shapes stop matching). Fixes: pad the context to a power of two (8), or fuse in groups of 3 at one level (6 → 2 → 1 with a FlattenConsecutive(3) and a FlattenConsecutive(2)). The pairwise tree quietly assumes the context length is 2L.
