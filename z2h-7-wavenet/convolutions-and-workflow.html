Convolutions, and how deep-learning work actually happens

Also called: dilated causal convolution, a sliding filter, Conv1d; the development loop. Lecture 6 · WaveNet but with "dilated causal convolutions" · 0:47:44 · experimental harness · 0:46:58 · the development process · 0:52:28

Prime · 2 minutes before you read

The problem: The WaveNet-style model reads one row of 8 characters at a time. Neighbouring rows of the same name overlap by 7 characters, so their trees overlap too, and a row-by-row forward pass recomputes the same nodes again and again. Separately, a model that trains is not the same as a good way of working: without a harness you can't tell a 0.006 gain from noise.

Where it fits: It closes the WaveNet lecture. It takes the tree you built with FlattenConsecutive and the shared-weight levels, and shows the efficient way to run that same tree over a whole sequence. The workflow half looks back at the BatchNorm shape bug and the one-run comparisons in the performance log.

In one breath: a convolution doesn't change the WaveNet model at all. It runs the same little tree, with the same weights, at every position of a sequence in one call, and it computes each node that neighbouring positions share only once. The second half of the chapter is about the job itself: Karpathy reads docs, babysits tensor shapes, prototypes in Jupyter, then moves to a repo, and he says you need an experiment harness instead of guessing.

Predict first: the name "diondre" gives 8 training rows. Forwarding each row through the 3-level tree separately computes 8 × (4 + 2 + 1) = 56 tree nodes. How many of those 56 sit at a position no other row already computed?

Only 34 are distinct; 22 are repeats. The rows overlap by up to 7 characters, so their trees overlap too. For example, the level-1 node for '.d' is computed four times (rows 1, 3, 5 and 7). A convolution computes each of the 34 once.

One name, eight rows

With block_size = 8 (8 characters of context), the name "diondre" becomes 8 training examples, rows 7 to 14 of Xtr. Karpathy pronounces it "DeAndre" in the video; the dataset spells it diondre.

row 0 ........ --> d row 4 ....dion --> d row 1 .......d --> i row 5 ...diond --> r row 2 ......di --> o row 6 ..diondr --> e row 3 .....dio --> n row 7 .diondre --> .

Printed by labs/convolutions-and-workflow.py, the same as the notebook. Each row is the previous one shifted left by one character.

The hierarchical model reads each row as a tree. Level 1 fuses neighbouring pairs of characters (4 nodes), level 2 fuses pairs of those (2 nodes, 4 characters each) and level 3 fuses the last pair (1 node, all 8). Every node at a level uses the same weights: one Linear, BatchNorm1d and Tanh per level. So a node's value depends only on which characters it covers, not on which row asked for it (in eval mode, where BatchNorm uses its stored statistics).

Level 1 has one node per starting position 0–13 of the 15-character padded name, so 14. In general, R rows cost 7R nodes in a loop and 3R + 10 in a convolution: 56 vs 34 here, 112 vs 58 for a 15-letter name (16 rows). For long sequences that tends to 7 vs 3 per row (computed).

What a convolution is

Karpathy's description (0:47:44): a convolution is a for loop that slides one linear filter (the same small weight matrix) along the sequence. Two things make it fast. The loop runs inside a GPU kernel instead of in Python, and a node that is the right child of one tree and the left child of the next is computed once and reused. In the WaveNet paper's figure, the tree for one output is exactly what this lecture built; the convolution computes all the outputs at once.

The two adjectives map onto the tree. Causal: each output only looks at characters to its left, so it can't peek at the character it predicts. Dilated: the two inputs of a node are 1 position apart at level 1, 2 apart at level 2 and 4 apart at level 3. Doubling the gap doubles the receptive field (how many characters one output sees) with every layer: 2, 4, 8.

for layer in model.layers:
    layer.training = False          # eval: each row stands alone
logits = torch.zeros(8, 27)
for i in range(8):                  # one row of 'diondre' at a time
    logits[i] = model(Xtr[[7+i]])
print('8 examples in a Python loop:', tuple(logits.shape))
print('same as one batched call:',
      torch.allclose(logits, model(Xtr[7:15]), atol=1e-6))
nodes = [(w, i+s) for i in range(8) for w in (2, 4, 8)
         for s in range(0, 8, w)]   # (width, start) of each tree node
n, d = len(nodes), len(set(nodes))
print(f'tree nodes computed by the loop: {n}; distinct (level, '
      f'position) nodes: {d}; computed more than once: {n - d}')

How it differs from related ideas

✗ A Python loop over rows

Correct, and it's what the notebook does to make the point. But every row pays Python overhead and builds its own tree: 56 nodes for one name.

✗ One batched call

model(Xtr[7:15]) removes the Python loop, since it's one call over 8 rows. It still builds 8 separate trees, so it still computes 56 nodes. Batching fixes the overhead, not the repeated work.

✗ A convolution without dilation

If every layer fused neighbours 1 position apart, each layer would widen the view by only one character. Seeing 8 characters would take 7 layers instead of 3.

✓ Dilated causal convolution

The same weights slide over the whole sequence in one kernel, and each shared node is computed once: 34 nodes for "diondre". The model and its outputs don't change, only the cost.

So should you rewrite your model as a convolution?

Not for this course. The convolution computes exactly the same function; Karpathy calls it purely an efficiency trick. It only saves work when many outputs come from the same sequence. The makemore training loop draws 32 random rows from all over the dataset, so neighbouring rows in a batch almost never come from the same name, and there is nothing to share. To benefit, you'd have to feed whole names as sequences and ask for an output at every position (this is an inference from how the batches are built, not something the lecture measures).

Karpathy covers the real convolution "in a future video". The series doesn't return to it: z2h-8 moves to self-attention, which also produces an output at every position in one call, but mixes positions with weights computed from the data instead of a fixed tree.

Understand and remember

  • Rows of one name are the same window shifted by one character → their trees cover overlapping character spans → with shared weights, equal spans give equal nodes → a loop recomputes them (56 nodes for "diondre") while a convolution computes each position once (34)
  • Convolution = the same filter slid over every position → same weights and the same inputs per node → exactly the same logits as the loop → it is an efficiency change, not a model change
  • Dilation doubles the gap between a node's two inputs at each level (1, 2, 4) → the receptive field doubles per layer (2, 4, 8) → 3 layers see 8 characters, where undilated width-2 layers would need 7
  • Bugs like the (1, 4, 68) running_mean broadcast silently and a single run can't separate 2.0265 from 2.0202 → shape checks and a harness that repeats and compares runs are what make progress real instead of "guessing and checking"
  • detail that matters Batching and convolution fix different costs → a batched call removes Python overhead but still builds one tree per row → only sharing nodes across positions removes the repeated work (7R vs 3R + 10 nodes for R rows)
  • detail that matters The saving needs outputs from the same sequence → makemore's minibatches draw random rows from different names → nothing to share unless you restructure the data as whole sequences

Reference only

  • nn.BatchNorm1d expects (N, C, L); the lecture's version expects (N, L, C)
  • "diondre" is rows 7–14 of Xtr; Karpathy says it aloud as "DeAndre"
  • the WaveNet paper uses 4 levels in its figure (receptive field 16); the lecture builds 3
  • the lecture's roadmap: real dilated convolutions, residual and skip connections, a hyperparameter-search harness, then RNNs, LSTMs, GRUs and Transformers

Check
