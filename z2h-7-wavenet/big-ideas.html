Big idea 1: A network is a list of modules, and the ones with state need a mode switch

Every step of the forward pass becomes a small object you call and ask for its parameters; Sequential chains them so model(Xb) is the whole net. BatchNorm is the one that behaves differently in training, and forgetting to switch it off breaks sampling.

“State is harmful” · Karpathy, 0:16:01

Why it matters: This is exactly torch.nn's design, and from here on Karpathy uses it directly. There, model.eval() flips the flag on every sub-module at once, which is the fix for this bug in every later lecture.

Big idea 2: Don't crush the whole context into one layer: fuse it slowly, in a tree

Widening the flat MLP's window to 8 characters helps, but one Linear layer still mixes all 8 at once. WaveNet's idea is to fuse neighbours in pairs, then pairs of pairs, so each level sees twice as many characters: 2, 4, 8.

we don't want to squash all of that information into a single hidden layer too quickly; fuse it progressively, like a tree · Karpathy, paraphrased, 0:00:00

Why it matters: The flat first layer grows with the window (6,000, 16,000, 32,000 weights at 3, 8, 16 characters); the tree adds one level per doubling. How to mix many positions without one giant layer is the question self-attention answers differently in the next lecture.

Big idea 3: @ only multiplies the last dimension, so a view turns pairs into a batch

A Linear layer treats every dimension in front of the last one as batch. Viewing the 8 embeddings as 4 rows of 2 lets one shared weight process all 4 pairs in one matmul, with no copy and no loop. Stack that three times and you have the tree.

matrix multiplication only works on the last dimension, and all the dimensions before it are treated as batch dimensions · Karpathy, paraphrased, 0:21:36

Why it matters: Every Linear in the GPT lecture gets a (B, T, C) input and relies on exactly this: one weight applied at every position. And shrinking n_hidden to 68 first is the habit that matters: compare architectures at equal parameter counts, or a win only proves size.

Big idea 4: Broadcasting turns a shape bug into a silently worse model

Inside the tree, BatchNorm gets (32, 4, 68) but still averages over dimension 0 only. Nothing errors: it just keeps 4 statistics per channel, each from 32 numbers. Averaging over (0, 1) gives one per channel from 128 numbers.

“everything broadcasts properly but the batchnorm is not doing what we need” · Karpathy, 0:38:50

Why it matters: The fix is worth making even if 0.006 is noise: the buggy layer computes something other than BatchNorm. Print the shapes of buffers, not just outputs. PyTorch's own nn.BatchNorm1d expects (N, C, L) and fails loudly here; LayerNorm drops batch statistics altogether.

Big idea 5: Scaling up won, but without a harness you can't say why

Widening the fixed tree to 76,579 parameters took val below 2.0 for the first time. Every row of the log is one run with one seed, and the flat net was never widened, so the log can't separate "the tree helped" from "more parameters helped".

“we're just guessing and checking” · Karpathy, 0:46:58

Why it matters: 1.9937 is the number to beat. Karpathy lists a big flat net as a fair control and says it "would be kind of embarrassing" if it won. The same discipline (fixed steps, several seeds, val only) carries every comparison in the GPT lectures.

Big idea 6: A dilated convolution is the same tree, with shared nodes computed once

The 8 rows of one name are the same window shifted by one character, so their trees overlap. A convolution slides the tree along the whole name in one kernel and computes each shared node once. The model and its outputs don't change, only the cost.

“strictly for efficiency” · Karpathy, 0:47:44

Why it matters: Speed tricks should leave the function unchanged, and you check that by comparing outputs. It only pays when many outputs come from one sequence, which is how the GPT lecture trains: a prediction at every position of a chunk, in one call.

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • Each module owns its parameters and its forward step → Sequential chains them and collects parameters() → the architecture becomes one list → but BatchNorm keeps state and switches behaviour by mode → a forgotten training = False gives nan variance on a batch of 1 and poisons running_var
  • One flat Linear mixes all 8 characters at once and its first layer grows linearly with the window → fuse neighbours in pairs with one shared weight per level → the receptive field doubles per level (2, 4, 8) → context grows by one level per doubling instead of one giant layer
  • @ sums only over the last dimension → leading dimensions are batch → view(B, 4, 20) makes the 4 pairs a batch dimension for free → the same code leaves a position axis in front of BatchNorm → averaging over dim 0 only broadcasts silently into per-position statistics → reduce over (0, 1) (val 2.0265 → 2.0202)
  • Width 22,397 → 76,579 parameters takes val 2.0202 → 1.9937 but the train–val gap doubles (0.109 → 0.225) → one seed per row and no widened flat net → the log can't separate structure from size → you need a harness with equal-size controls and repeated runs
  • detail that matters A dilated convolution slides the same tree over every position in one kernel and computes each shared node once (34 instead of 56 for the 8 rows of "diondre") → identical logits, lower cost → it only pays when many outputs come from one sequence, not from makemore's random minibatch rows

Reference only

  • the class names and signatures: Embedding, Flatten, FlattenConsecutive(n), Sequential
  • the widths: n_embd 10 / 24, n_hidden 200 / 68 / 128
  • PyTorch's nn.BatchNorm1d layout (N, C, L) vs the lecture's (N, L, C)
  • the lr schedule: 0.1, then 0.01 from step 150,000, 200,000 steps, batch 32

4 · Compare against what you already know

vs Bengio 2003: characters as points in space: Bengio's MLP and this lecture's tree both embed each character and run hidden layers. What is fundamentally different about how they combine the context, which design choice causes it, and when would you still pick the flat MLP?

Check
  • Bengio: concatenate all context embeddings and mix them in one hidden layer
  • tree: fuse neighbours two at a time, with shared weights per level, in log₂(context) levels
  • the choice is where mixing happens: all at once vs gradually
  • flat is simpler and was just as good at ~22K parameters here (2.027 vs 2.029); it gets expensive as the window grows (16,000 → 32,000 first-layer weights from 8 to 16 characters)

vs BatchNorm at test time: running statistics: The BatchNorm lecture already had a train/eval switch and running statistics. What new ways does this lecture find to get BatchNorm wrong, and why is one of them loud and the other silent?

Check
  • forgetting training = False: a batch of 1 has variance 0/0 = nan, so sampling crashes (loud)
  • the 3-D input reduced over dim 0 only: per-position statistics, broadcasting hides it (silent)
  • both come from BatchNorm depending on the batch, which no other layer does
  • the silent one costs only 0.0063 of val, so it is found by checking shapes, not by watching the loss

vs Rebuilding torch.nn: Linear, BatchNorm1d, Tanh: The BatchNorm lecture already turned Linear, BatchNorm1d and Tanh into classes. What does this lecture's Sequential add, and what would still break if you kept a plain list of layers?

Check
  • Sequential runs the layers and collects their parameters in one object, so model(Xb) is the forward pass
  • it has the same interface as a layer, so containers nest
  • with a plain list, the training loop must gather parameters and flip every training flag itself
  • that is exactly the step where the nan sampling bug hides; torch.nn's model.eval() does it for you

5 · Predict commit to an answer before revealing

You want 32 characters of context. Keep n_embd 10 and compare the flat MLP (one hidden layer of 200) against the tree of pairs. Commit first: how many fusion levels does the tree need, and how many weights does the flat net's first layer have?

Reveal

5 levels, since 32 = 2⁵ and each level halves the number of nodes. The flat first layer takes 32 × 10 = 320 inputs, so it has 320 × 200 = 64,000 weights, doubling again from 32,000 at 16 characters. The tree's first level still sees only 20 inputs; each doubling of context adds just one more level. But the names are at most 15 letters long, so on this dataset most of those 32 slots would hold padding.
