Checkpoint 1: attention without the N×N matrix

Ties together online softmax, FlashAttention I, FlashAttention II, FlashAttention-2 I, FlashAttention-2 II and FlashAttention-3, -4 and FlashInfer: one merge rule, the traffic it saves, and how each GPU generation changed where the time goes.

How to use this page. Close the six cards. Answer each question in writing, in full sentences, before opening its Check. A wrong or shaky answer isn't a failure; it tells you exactly which section to reopen. The questions are mixed on purpose, so you have to work out which idea applies before you can answer.

1 · Mixed retrieval

  1. which concept?A team runs FlashAttention-2, unchanged, on H100s and measures about a third of the tensor-core peak. The profiler shows the tensor cores idle while each tile's softmax runs. Which idea explains it, and what does the fix change: the algorithm or the kernel?
    Check
    • the H100's exp unit is 256× slower than its tensor cores (16 ops/clk/SM), so at d = 128 the exps take 50% of the matmul time
    • FA2 uses synchronous, Ampere-style instructions, so loading, GEMM and softmax take turns: 335 TF, about 35% of 989
    • the fix is the kernel, not the algorithm: FA3's warp specialization and pingpong overlap one warpgroup's softmax with another's GEMMs (740 TF, 75%)

    Missed it? Reopen FA3, FA4 and FlashInfer, "The generation table" and section 1.

  2. Two thread blocks each processed half of one attention row. Block A reports (m, ℓ) = (3, 1.135335); block B reports (5, 1.049787). What is the row's ℓ, and what else does each block have to hand over for attention (not just softmax) to come out exact?
    Check
    • common max 5; A's sum is rescaled by e3−5 = 0.135335, B's by 1
    • ℓ = 0.135335 × 1.135335 + 1.049787 = 1.203438
    • each block also hands over its partial output row, which is rescaled by the same factor before adding, then divided by the final ℓ

    Missed it? Reopen online softmax, "§3.1 The parallel version", and FlashAttention I, the Oi update rule.

  3. which concept?Decoding one sequence with 32k tokens of context on an H100, the attention kernel launches 32 thread blocks and most SMs sit idle. Which idea explains it, and how many blocks does the fix launch with 512-token chunks?
    Check
    • FA2 parallelizes over query row blocks; decode has one query row, so one row block per head: 32 blocks, 0.24 waves on 132 SMs
    • the long axis is the KV, so split it: Flash-Decoding runs each KV chunk in its own block and merges with log-sum-exp (online softmax's ⊕)
    • 32,768 / 512 = 64 chunks × 32 heads = 2,048 blocks, 15.52 waves (our arithmetic)

    Missed it? Reopen FlashAttention-2 II, "Decode is the case FA2's split doesn't fix".

  4. FlashAttention moved 9.2× less HBM traffic than standard attention on GPT-2 medium (d = 64, A100), but the card's literal count for Llama-3.1-8B prefill on an H100 (d = 128) gives only about 2.3×. What single ratio explains the gap?
    Check
    • the advantage is about M/d²: N cancels out of the ratio
    • A100 at d = 64: 98,304 / 4,096 = 24; H100 at d = 128: 116,736 / 16,384 = 7.1
    • Alg 1's constants cost about another 3×, leaving ~2.3×; real kernels do better thanks to L2 and FA2's loop order

    Missed it? Reopen FlashAttention II, "Fill it in, and watch the units".

  5. On an A100, FA1 spends 8.08 non-matmul operations per score against 512 matmul FLOPs: 1.55% of the FLOPs. Why is that about 20% of the ideal time, and what two changes does FA2 make to the inner loop to cut it?
    Check
    • matmul runs on tensor cores at 312 TF; everything else on FP32 units at 19.5 TF, 16× slower
    • FA2 keeps an un-scaled output and divides by ℓ once at the end (rescale 4 → 2 ops per element)
    • and stores one logsumexp per row instead of m and ℓ; total 6.04 ops per score, 15.9% of time

    Missed it? Reopen FlashAttention-2 I, "Worked example: counting the non-matmul work".

  6. which concept?Someone tunes a tiled attention kernel for GPT-2 medium with K/V blocks of 32 columns and finds it moves more HBM bytes than the naive kernel. Which idea explains it, and in which direction should they change the block size?
    Check
    • Q and O are re-streamed once per K/V block, so the number of passes is N / Bc
    • at Bc = 32 that is 32 passes: 13.56 GB vs 9.13 GB for standard attention (forward, the card's count)
    • make blocks bigger, up to about 256, where the kernel becomes arithmetic-bound and blocks stop fitting in SRAM

    Missed it? Reopen FlashAttention II, "Fig 2 middle: bigger blocks, fewer passes".

  7. Walk through one inner step of FlashAttention-2's forward loop for a causal model at N = 8,192 with 128 × 128 tiles. Which tiles are skipped, which are masked, and what is written to HBM, and when?
    Check
    • Qi is the outer loop; for each Kj, Vj tile: S = QiKjᵀ, new max, P̃, update ℓ, Õ = diag(emold − mnew)Õ + P̃Vj
    • tiles entirely above the diagonal are skipped (2,016 of 4,096); only the 64 diagonal tiles need the elementwise mask
    • nothing is written inside the loop; after the last tile O = Õ/ℓ and L = m + log ℓ go to HBM once

    Missed it? Reopen FlashAttention-2 I, "Algorithm 1: the loop order flips" and "Causal masking".

3 · Project: a tiny FlashAttention-2 you can count

What it reinforces: the ⊕ merge (online softmax), tiling with a rescaled output (FA I), passes and HBM traffic (FA II), the deferred divide, logsumexp and causal skipping (FA2 I), and splitting the KV for decode (FA2 II).

In numpy, float64, about 60 lines. Use random Q, K, V with N = 1,024 and d = 64, seeded.

  1. Reference. Causal attention the naive way: S = QKᵀ/√d, set Sij = −∞ for j > i, softmax by rows, O = PV.
  2. FA2 forward. Q row blocks outside, K/V column blocks inside, Br = Bc = 128. Keep m, ℓ and an un-scaled Õ per row block; divide once at the end and form L = m + log ℓ. Skip tiles entirely above the diagonal and apply the mask only on diagonal tiles. Count the tiles you compute and the tiles you mask.
  3. Count the traffic (non-causal). Using FA II's per-head formula, flash = (Nd + 2N) + 2Nd + Tc(3Nd + 4N) against standard 4Nd + 4N², compute the ratio for Bc = 384, 128 and 64.
  4. Decode with a split KV. One query against 8,192 keys: split the keys into 16 chunks of 512, have each chunk return its log-sum-exp and its normalised partial output, then merge. Compare with a one-shot softmax. How many thread blocks would this be for Llama's 32 heads, and how many waves on 132 SMs?
  5. Break it. Delete the emold − mnew factor from your step 2 loop (keep everything else). What happens to the error?
Done when: both of your outputs match their references to better than 10−12, your tile counts and traffic ratios match the check, and you can say in one sentence why the broken version fails.
Check: the numbers (computed with a Python version of this exact project)
  • FA2 causal vs reference: max |ΔO| = 8.3 × 10−16 (seed 0). Tiles: T = 8 per side, 64 in all, 36 computed, 28 skipped, 8 masked (saving 1.78× in FLOPs).
  • Traffic ratios: standard = 4,456,448 per head. Bc = 384 (Tc = 3): 800,768, ratio 5.57. Bc = 128 (Tc = 8): 1,804,288, ratio 2.47. Bc = 64 (Tc = 16): 3,409,920, ratio 1.31. Bigger blocks, fewer passes.
  • Split-KV decode: max |Δo| = 1.3 × 10−16. For 32 heads: 32 × 16 = 512 blocks, 3.88 waves on 132 SMs.
  • Without the rescale the error jumps to roughly 0.1–0.5, not rounding level: earlier blocks stay measured against a smaller max, so they are overweighted whenever a later block raises it.
