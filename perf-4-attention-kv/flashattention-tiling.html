FlashAttention I: tiling and recomputation

Also called FlashAttention v1, IO-aware exact attention, or the fused attention kernel. This is card 1 of 3 on Dao, Fu, Ermon, Rudra and Ré, FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness (NeurIPS 2022, arXiv 2205.14135v2). It walks §1 (intro, Fig 1), §2 (hardware; standard attention, Algorithm 0) and §3.1 (tiling, recomputation, kernel fusion, Algorithm 1, Theorem 1). The paper's numbers are on an A100 with GPT-2. The H100 and Llama-3.1-8B numbers are our recomputation.

Prime · 2 minutes before you read

The problem: Standard attention writes the N×N scores S and probabilities P to HBM and reads them back. At 8k tokens that is 8.59 GB per Llama layer for S + P alone, all of it memory-bound traffic, and at 128k it is 27× the whole GPU.

Where it fits: Card 1 of 3 on FlashAttention. It applies the previous card's (m, ℓ) merge to whole tiles of the score matrix, so the N×N matrices live only in SRAM, one tile at a time.

In one breath

Standard attention writes two N × N matrices, the scores S and the probabilities P, to slow GPU memory (HBM) and reads them back. FlashAttention cuts Q, K and V into blocks small enough for on-chip SRAM, computes each block of S there, folds it into the output with a running max and a running sum (online softmax), and never writes S or P out at all. The answer is the same attention, exactly. It does more arithmetic but far less memory traffic, so it runs faster and needs only O(N) extra memory instead of O(N²).

§1: the missing principle is IO, not FLOPs

Attention's time and memory grow with N². Approximate methods (sparse, low-rank such as Linformer, and combinations) cut the FLOPs to linear or near-linear, but the paper says "many of them do not display wall-clock speedup against standard attention". The reason it gives: they "focus on FLOP reduction (which may not correlate with wall-clock speed) and tend to ignore overheads from memory access (IO)". The authors' claim is that attention should be IO-aware: it should count the reads and writes between fast and slow memory, not only the arithmetic. Two established techniques do the work: tiling (compute the softmax block by block) and recomputation (don't store S and P for the backward pass; rebuild them on chip). Both run inside one CUDA kernel.

§2.2: standard attention writes N × N twice

For one head, Q, K, V are N × d. The output is O = softmax(QKT)V, with the softmax taken row by row. Algorithm 0 in the paper:

Algorithm 0 (Q, K, V in HBM) 1 load Q, K by blocks, S = Q Kᵀ write S to HBM N × N 2 read S, P = softmax(S) write P to HBM N × N, memory-bound 3 load P, V by blocks, O = P V write O to HBM N × d 4 return O

S and P take O(N²) memory, and N is much larger than d (GPT-2: N = 1,024, d = 64). Softmax is memory-bound, so all that N × N traffic turns into wall-clock time. Masking on S or dropout on P makes it worse, since each adds another pass over N × N.

Tiling: softmax one block at a time

Softmax couples every column of a row: you need the row's max and its sum before any entry is final. The paper splits a row x into two halves x(1), x(2) and shows the halves can be merged later, if each carries two numbers: its max m and its sum ℓ. This is the online softmax trick from the previous card, applied to whole blocks.

m(x)=max(m(x(1)),m(x(2)))running max f(x)=[em(x(1))−m(x)f(x(1))em(x(2))−m(x)f(x(2))] ℓ(x)= em(x(1))−m(x)ℓ(x(1))old sum, rescaled + em(x(2))−m(x)ℓ(x(2))new block, rescaled softmax(x)=f(x)ℓ(x)
m(x)largest entry of the row (subtracted for numerical safety)one number per row f(x)the row's exponentials, exi − m(x)never stored whole ℓ(x)sum of f(x): the softmax denominatorone number per row x(1), x(2)two blocks of one row of SBc columns each

The paper calls this "algebraic aggregation": keep (m, ℓ) and softmax can be computed one block at a time. When a new block raises the max, everything summed so far shrinks by emold − mnew.

Recomputation and kernel fusion

Recomputation. Backward normally needs S and P (both N × N) to compute gradients for Q, K and V. FlashAttention stores only the output O and the per-row statistics (m, ℓ). In the backward pass it rebuilds each block of S and P on chip from Q, K and V. The paper calls this "a form of selective gradient checkpointing". Ordinary checkpointing trades speed for memory. This one is faster even though it does more FLOPs, because it skips the HBM reads (see the box at the end). The backward pass itself is card 3.

Kernel fusion. Tiling makes it possible to do everything in one CUDA kernel: load inputs from HBM, run the matmul, softmax, optional masking and dropout, and the second matmul, then write only O back.

Algorithm 1, line by line

Algorithm 1 (Q, K, V in HBM; on-chip SRAM of size M) 1 B_c = ⌈M/4d⌉, B_r = min(⌈M/4d⌉, d) block sizes set by SRAM 2 O = 0 (N×d), ℓ = 0 (N), m = −∞ (N) in HBM 3 split Q into T_r = ⌈N/B_r⌉ blocks Q_i; K, V into T_c = ⌈N/B_c⌉ blocks K_j, V_j 4 split O, ℓ, m into T_r blocks to match Q 5 for j = 1..T_c: outer loop: K, V blocks 6 load K_j, V_j to SRAM 7 for i = 1..T_r: inner loop: Q blocks 8 load Q_i, O_i, ℓ_i, m_i to SRAM 9 S_ij = Q_i K_jᵀ B_r × B_c, on chip only 10 m̃_ij = rowmax(S_ij), P̃_ij = exp(S_ij − m̃_ij), ℓ̃_ij = rowsum(P̃_ij) 11 m_new = max(m_i, m̃_ij), ℓ_new = e^(m_i − m_new)·ℓ_i + e^(m̃_ij − m_new)·ℓ̃_ij 12 write O_i ← (see below) to HBM 13 write ℓ_i ← ℓ_new, m_i ← m_new to HBM 16 return O
Oi← diag(ℓinew)−1divide by the new sum ( diag(ℓi)emi−minewOiold output: undo old ÷ℓ, rescale to new max + em~ij−minewP~ijVjthis block's contribution )

After every step, Oi is the exact attention output for the columns seen so far. The paper's proof of correctness (App C) is an induction over j. The algorithm keeps one copy of O and fixes it up in place. Only Oi, ℓi and mi are written back to HBM, never Sij or P̃ij.

Theorem 1. Algorithm 1 returns O = softmax(QKT)V with O(N²d) FLOPs and O(N) extra memory beyond inputs and output. The FLOPs are Tr·Tc tiles × O(BrBcd) each, which is O(N²d), the same order as standard attention. The extra memory is the vectors ℓ and m. For one Llama head at N = 8,192 the two matmuls are 4N²d = 4 × 8,192² × 128 = 34.4 GFLOP. That's 1.10 TFLOP for 32 heads, or 1.11 ms per layer at 989 TFLOPS (our recomputation, forward, no causal mask).

Loop order. FA1 puts K, V in the outer loop and Q in the inner loop, so Oi, ℓi and mi make a round trip to HBM on every (i, j) step. FlashAttention-2 swaps the loops: Qi becomes the outer loop and Oi stays on chip until it's finished. See FlashAttention-2 I.

Worked example: one Llama-3.1-8B head on an H100

d = 128, N = 8,192, and M is one H100 SM's 228 KB of shared memory, counted in 4-byte floats. Choosing that M is our assumption, and so is every number below.

M = 228 × 1,024 B / 4 B = 58,368 floats B_c = ⌈M / 4d⌉ = ⌈58,368 / 512⌉ = ⌈114.00⌉ = 114 columns of K, V per block B_r = min(⌈M / 4d⌉, d) = min(114, 128) = 114 rows of Q per block T_r = T_c = ⌈8,192 / 114⌉ = 72 (72 × 114 = 8,208; last block holds 98) tiles = T_r × T_c = 72 × 72 = 5,184 inner-loop steps for this head Q_i + K_j + V_j + O_i = 4 × 114 × 128 = 58,368 floats = 228.0 KB (fills M exactly) S_ij = 114 × 114 = 12,996 floats = 50.8 KB more

Our reading: the "4" in 4d leaves room for four B × d tiles (Qi, Kj, Vj, Oi). With Sij added, this literal sizing overshoots 228 KB. So the rule is an asymptotic statement that the proofs use, not a tuning recipe. Real kernels choose power-of-two blocks in BF16. FlashAttention-2 tunes block sizes in {64, 128} × {64, 128}.

Why it beats the alternatives

✗ Standard attention (Alg 0)

Exact, but writes S and P (N × N each) to HBM and reads them back. Softmax, masking and dropout are memory-bound passes over N², so HBM traffic, not math, sets the time. Memory is O(N²).

✗ Memory-efficient attention (Rabe & Staats)

Also blocks and also recomputes, but it targets peak memory, not memory accesses. Per App B.5 it is "around the same speed or slightly slower" than standard attention, and it keeps a temporary output per block and combines them at the end.

✗ Approximate attention (Linformer etc.)

Sparse or low-rank methods cut FLOPs to near-linear but change the result, and many show no wall-clock win because they ignore IO. The paper notes Linformer does overtake FlashAttention beyond about 1K tokens.

✓ FlashAttention

Exact attention with O(N) extra memory and far fewer HBM accesses. It runs up to 7.6× faster on GPT-2 attention (Fig 1) and, per App B.5, 2–4× faster than standard attention, with one fused kernel and one in-place copy of O.

FlashAttention does more FLOPs, so how is it faster?

Because FLOPs aren't what it's short of. Recomputation adds arithmetic: in the backward pass, S and P are rebuilt from Q and K instead of read. The paper's Fig 2 measures forward + backward for GPT-2 medium (N = 1,024, d = 64, 16 heads, batch 64) on an A100:

GFLOPs HBM reads+writes runtime standard 66.6 40.3 GB 41.7 ms FlashAttention 75.2 4.4 GB 7.3 ms FlashAttention +13% FLOPs 9.2× less traffic 5.7× faster

Softmax and the N × N reads are memory-bound, so a kernel that moves 9× fewer bytes wins even with 13% more math. The full IO argument (Theorem 2: Θ(N²d²/M) HBM accesses versus Θ(Nd + N²), and why larger blocks help until about 256) is the next card.

When it isn't the answer:

  • Very long sequences where approximation is acceptable. Beyond about 1K tokens the paper finds some approximate methods (Linformer) faster than FlashAttention. Block-sparse FlashAttention (§3.3) is its own answer there.
  • Decode. One new query row per sequence means no N × N matrix to avoid. Decode attention is limited by reading the KV cache, about 4 FLOPs/byte with GQA-4 (perf-2). Tiling over Q has nothing to tile. Decode kernels are built around reading the KV cache instead (the PagedAttention cards here, and perf-5 on engines).
  • Hardware with little SRAM. On a T4 the blocks must be smaller, and the paper sees less speedup, "which matches the IO complexity analysis" (App E.5).
  • New attention variants. Each one needs a new hand-written CUDA kernel. The paper lists this as its first limitation.

Understand and remember

  • S and P are N×N → writing and re-reading them makes attention memory-bound → split Q, K, V into SRAM-sized blocks and compute each S_ij on chip → fold it into O with running (m, ℓ) → S and P never reach HBM → O(N) extra memory instead of O(N²)
  • A new block may raise a row's max → the old ℓ_i and O_i were built on the old max → scale both by e^(m_old − m_new), add the block's e^(S−m)·V → after every step O_i is exact for the columns seen so far (Theorem 1, induction over j)
  • Keep only O and (m, ℓ) from the forward pass → rebuild S and P tile by tile in backward → +13% FLOPs but 9.2× less HBM traffic (GPT-2 medium: 40.3 → 4.4 GB) → 5.7× faster, because the bound was bytes, not FLOPs
  • detail that matters FA1's loop order puts K, V outside and Q inside → O_i, ℓ_i, m_i round-trip to HBM on every (i, j) step → the waste FlashAttention-2 removes by swapping the loops

5 · Predict commit to an answer before revealing

Run Algorithm 1 exactly but delete the rescale factor e^(m_old − m_new) from both the ℓ and O updates. Is the error small (rounding) or large, and does it depend on the block size? Commit before revealing.

Reveal

Large: the lab's try-this shows errors of about 0.1–0.5, not 10⁻⁷. Every time a later block raises a row's max, the old contributions stay measured against a smaller max, so they are overweighted by e^(m_new − m_old). It barely depends on block size as long as there are several blocks (our numpy check at N = 512, d = 128: max error 0.30, 0.32, 0.29, 0.31 for B_c = 16, 64, 114, 256), because the damage comes from the max rising at all. With one block covering the whole row (B_c = 512) the max never moves and the error falls to 9e-16.
