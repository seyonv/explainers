Long context: sliding windows, ring and sparse attention

Also called sliding-window attention (SWA), the rolling buffer cache, Ring Attention (context parallelism) and Native Sparse Attention (NSA). This card skims three papers for their key ideas: Mistral 7B's 4,096-token window (arXiv 2310.06825 §2), Ring Attention's overlap condition (Liu, Zaharia, Abbeel, arXiv 2310.01889 §3–4), and DeepSeek's NSA (arXiv 2502.11089 §3, §5). The papers ran on A100s and TPUs; the comparison at the end puts all three on the running example, Llama-3.1-8B on one H100.

In one breath

Long context hurts in three ways: the KV cache grows linearly with tokens (memory and decode reads), and prefill attention grows with the square. A sliding window caps what each layer keeps at W tokens, so the cache stops growing. Ring attention keeps attention exact and splits the sequence across devices, passing KV blocks around a ring while each device computes. Sparse attention (NSA) keeps every token but, at each step, reads only a trained-in few thousand of them.

1 · Sliding window and the rolling buffer (Mistral 7B)

Mistral 7B uses the same attention shape as Llama-3.1-8B (32 layers, 32 query heads, 8 KV heads, head dim 128) plus window_size = 4,096 and context_len = 8,192. Each token at layer k attends only to positions i−W … i of layer k−1. Information still travels further: "after k attention layers, information can move forward by up to k × W tokens."

slot(i)=imodWwhere token i's K, V are written span≤W·k=4096·32=131,072theoretical reach at the last layer 32K4096=8×cache cut at 32K
Wwindow: tokens each layer attends to, and the cache size per layerMistral 4,096 knumber of stacked attention layers32 iabsolute token position0, 1, 2, …

The paper: "using a window size of W=4096, we have a theoretical attention span of approximately 131K tokens", and for the cache, "On a sequence length of 32k tokens, this reduces the cache memory usage by 8x, without impacting the model quality." 32,768 / 4,096 = 8 is exactly that cut. The quality claim is theirs; the paper shows no 32K evaluation next to it.

Our redraw of the paper's Fig 2 with W = 4, as its caption says. The body text calls the same illustration "W=3", and Fig 1 uses W = 3. The paper also chunks long prompts during prefill, choosing "the window size as our chunk size". For Llama's own version of this idea, mixing local and global layers, see perf-2: tricks that shrink the KV cache.

2 · Ring Attention: exact attention, split across devices

Split a sequence of s tokens into Nh blocks, one per host. Each host keeps its query block and starts with its own KV block. In each of the Nh steps, it computes blockwise attention against the KV block it holds, "concurrently sends key-value blocks to the next host-(i+1) while receiving key-value blocks from the preceding host-(i-1)." The order doesn't matter: attention against KV blocks "can be computed in any order, as long as the statistics of each block are combined correctly for rescaling" — the running max and sum of online softmax. The result is exact, not an approximation.

Our redraw of the idea in the paper's Fig 2(a) for Nh = 4. Green is each host's own block at step 1; every cell is useful compute. After 4 steps each query block has met every KV block, and no host ever held more than one KV block plus the one arriving.

When does the communication hide behind the compute? The paper counts one step for a block of c tokens with hidden size d: attention is 4dc² FLOPs (2dc² for QKT and 2dc² for PV), and the K and V blocks are 2cd bytes each in bf16, 4cd together.

3 · Native Sparse Attention: read a few thousand tokens, chosen by the model

NSA replaces each query's full key and value set with three smaller sets, each attended separately and mixed by learned gates, "derived from input features via an MLP and sigmoid activation":

ot*= ∑c∈{cmp, slc, win} gtc·Attn(qt,K~tc,V~tc) Nt≤⌊s−ld⌋+nl′+wtokens loaded per decode step
l, dcompression block length and stride; an MLP turns each block into one key (and one value)32 · 16 l′, nselection block size and how many blocks are kept (incl. 1 initial + 2 local)64 · 16 wsliding window of recent tokens512 ggate per branch, in [0, 1]sigmoid

Green = keys this step reads; grey = still cached, not read. Which 13 middle blocks get picked is illustrative (it depends on the query); the first block and the last two are always on, per the paper. The formula gives 2,046 tokens at s = 8,192; the paper's table prints 2,048.

Two hardware choices make it fast in practice. Blocks are contiguous 64-token runs, because "modern GPU architectures exhibit significantly higher throughput for continuous block accesses compared to random index-based reads". And all query heads in a GQA group sum their scores and pick the same blocks, so the kernel loads one set of KV blocks for the whole group. Their decode table (8× A100, GQA g = 4, Triton kernels):

The printed counts equal s/16 + 1,536 exactly. Separately, the paper measures its training kernel at "up to 9.0× forward and 6.0× backward speedup at 64k context-length" against Triton FlashAttention-2. Quality: a 27B model trained with NSA "maintains or exceeds" full attention on their benchmarks. The paper says 260B pretraining tokens in the introduction and 270B in the setup section.

From labs/long-context.py. The weights bar (16.06 GB / 3.35 TB/s, grey) is there for scale: at 128K, one full-attention sequence's KV costs more to read than the whole model. The split: the window cuts storage and reads; NSA cuts reads only; neither changes what one H100 can hold for full attention. And neither helps a full-attention model's 1M-token prefill: 137.4 GB of KV and about 600 s of compute (5.77e17 attention FLOPs) on one GPU. Splitting both 8 ways is exactly what ring attention does: 17.2 GB and roughly 75 s per H100 at 100% MFU (a floor, ours).

How the four options differ

Full attention

✓ Exact, sees every token. ✗ KV grows linearly (17.18 GB per 128K sequence, 3 fit), and prefill attention grows as T², 97% of the FLOPs at 1M tokens.

Sliding window

✓ Fixed cache (0.54 GB at W = 4,096) and fixed read cost. ✗ A token further back than W is reachable only indirectly, through stacked layers, up to W × layers.

Ring attention

✓ Exact, and splits both KV and compute across devices, so context grows with the device count. ✗ Needs N devices and fast links (c ≥ F/B); it's for prefill and training, not a smaller cache.

Sparse attention (NSA)

✓ Trained-in sparsity: reads 5,632 of 65,536 tokens (11.6× expected decode speedup), keeps any old block reachable. ✗ Must be trained in, and still stores the full cache.

No single winner: they attack different costs. NSA is shaded because it is the only one here that cuts decode reads without throwing tokens away, but it needs a model pretrained with it.

Is ring attention a way to shrink the KV cache?

No. It distributes the cache, and the compute, across devices. The total KV is the same as full attention, 137.4 GB for a 1M-token Llama-3.1-8B sequence; eight hosts each hold one-eighth. What it removes is the single-device limit, with no approximation, as long as each host's block is at least F/B tokens so the ring transfer hides behind the compute.

  • When it's the wrong tool: short contexts (below about 6c per host, roughly 6–13K tokens on NVLink-class links, the transfer no longer hides), slow links (A100 over InfiniBand needs 149.5K tokens per host per the paper), and plain decode, where the problem is bytes read per step, not FLOPs.
  • What people use instead: to shrink the cache itself, GQA, MLA, FP8 or 2-bit KV, or local-window layers (kv-tricks). To split a long cache during decode, sequence sharding (sharding the KV cache). Context parallelism at cluster scale is covered in perf-6 (scaling out).
  • And the window isn't free either: Mistral's "without impacting the model quality" is a claim about Mistral 7B trained with the window. Adding a window to a full-attention model like Llama after training is not what the paper tested.
