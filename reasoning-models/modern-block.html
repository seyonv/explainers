The 2017 block, four upgrades later

RoPE, RMSNorm with pre-norm, SwiGLU and grouped-query attention (GQA) · Su et al. 2021; Zhang & Sennrich 2019; Shazeer 2020; Ainslie et al. 2023 · running example: Llama-3.1-8B

Prime · 2 minutes before you read

The problem: If you learned the 2017 transformer block, a 2025 model card full of RoPE, RMSNorm, SwiGLU and GQA looks like a new architecture. It isn't, but without knowing what each part replaced you can't tell which one shrinks memory, which one changes quality, or why Llama's KV cache is 128 KiB per token.

Where it fits: A refresher between the transformer basics (self-attention, the forward pass) and the reasoning cards. It reuses the residual stream and attention heads from earlier cards and swaps four parts of the block.

You know the 2017 transformer block: attention, a feed-forward network, add and normalise, repeated. A 2025 open model still has that skeleton. Four parts have been swapped, and each swap fixes one specific cost or weakness. In Llama-3.1-8B you can put a number on every one of them.

Try this first

Guess first: Llama-3.1-8B has 32 query heads in each of its 32 layers. If every head kept its own keys and values, as in 2017, how much memory would one token's cache take, compared with the 128 KiB it actually uses?

Show the answer

512 KiB, four times as much. Llama lets groups of 4 query heads share one key/value head, so it stores 8 sets per layer instead of 32.

Three words first

Residual stream

The vector x for each token that runs through every block. Each part of a block reads it and adds its result back: x + f(x).

Normalisation

Rescaling a vector so its numbers stay in a steady range. Without it, values can drift as blocks stack up and training gets unstable.

KV cache

The keys and values of earlier tokens, kept in memory so each new token doesn't recompute them. It grows with every token of every conversation.

Same skeleton; four parts swapped

The four swaps are colour-linked: position moves from a wave added once at the bottom to a rotation inside attention (RoPE); normalisation becomes RMSNorm and moves off the main line; the feed-forward network gains a gate and a third matrix (SwiGLU); attention heads share keys and values (GQA). The 2017 numbers are the paper's base model; the 2025 numbers are Llama-3.1-8B's config.

RoPE: position goes into the angle, not the input

← scroll the sketch →

Replaced: a position wave added to each token's embedding once, before the first block. The fix: inside every attention layer, turn each query and key by an angle set by its position. Two turned vectors only "see" the difference between their angles, so the score depends on how far apart the tokens are, not where they sit. That is the property the RoPE paper set out to get (its Eq. 11).

The numbers: Llama's head size is 128, so each head has 64 pairs turning at 64 different speeds. RoPE adds no parameters. Llama sets the speed base to 500,000 (the paper used 10,000), which makes the slowest pair take about 2.56 million tokens for one full turn (Llama 3.1 also stretches its slow pairs a further 8× for long context). The paper's own test was small: 27.5 vs 27.3 BLEU (a translation-quality score) on English–German translation (Table 1), and faster training for a BERT model.

RMSNorm, applied before each part instead of after

2017: LayerNorm after the add

Subtract the mean, divide by the spread, then scale and shift. It sat on the main line: LayerNorm(x + f(x)), so the stream itself was renormalised twice per block.

2025: RMSNorm first

Skip the mean: divide by the root-mean-square, then scale. Applied only to the copy going into each part: x + f(RMSNorm(x)). The stream passes through untouched.

The RMSNorm paper's claim: removing the mean-centring costs nothing measurable, and it cut running time by 7%–64% across its models. In Llama-3.1-8B the two norms per layer carry 8,192 learned gains, a rounding error in an 8.03B-parameter model. The win is speed and simplicity; the pre-norm placement is what keeps a clean path from the first block to the last.

SwiGLU: a gate inside the feed-forward network

Replaced: two matrices with a ReLU between them (512 → 2048 → 512 in 2017). Now: the input goes through two matrices side by side. One output is passed through a smooth curve (Swish) and acts as a gate, the other is the content; they are multiplied number by number, then a third matrix maps back down.

The numbers: Llama's SwiGLU is 4096 → 14336 → 4096 with three matrices: 176.16M parameters per layer, about 70% of the whole model. The paper shrank the hidden width by a third so three matrices cost the same as two, and still got a better held-out log-perplexity: 1.636 vs 1.677 for ReLU (Table 1, lower is better). Why it works is honestly unknown. The author writes that he attributes it "to divine benevolence".

GQA: 32 query heads share 8 key/value heads

← scroll the sketch →

Replaced: every head with its own keys and values (multi-head attention). Now: groups of 4 query heads share one key/value head. Each head still asks its own question; only the keys and values it looks things up in are shared.

The numbers: the KV cache drops from 512 KiB to 128 KiB per token, so an 8,192-token chat needs 1.07 GB instead of 4.29 GB. That 4× is what lets one GPU serve four times as many long conversations at once. In the GQA paper, 8 groups on T5-XXL scored 47.1 against full multi-head's 47.2, at 0.28 s vs 1.51 s per sample (Table 1).

Principle

Keep the job of each part, change what it costs

None of the four swaps changes what a block does: mix tokens with attention, transform each token with the feed-forward network, keep the numbers steady. Each one makes a part cheaper (norm, KV cache) or better at the same price (position, feed-forward).

Buys you: a block you can read as "the 2017 one, plus four diffs", instead of a new architecture to learn.

Where this picture stops

  1. Not every 2025 model uses all four. Mixture-of-experts models swap the one feed-forward network for many experts, and DeepSeek replaces GQA with multi-head latent attention, a compressed cache (see the GQA card).
  2. The papers' evidence is small and old. RoPE was tested on translation and BERT, RMSNorm on 2019-era models, SwiGLU and GQA on T5. Each win in its own paper is modest; the case for each is that it costs little.
  3. GQA trades capacity for memory. Fewer key/value heads means less the model can store per token. Eight groups was close to free in the paper; one shared head (MQA) lost quality.

The full parameter count is in the transformer forward pass, attention itself is in Q, K, V and heads, and a one-head build from scratch is in the self-attention head.

Check yourself

1. Under RoPE, query at position 6 and key at position 5 score 0.12 in the sketch. What do positions 102 and 101 score, and why?

Show the answer

Also 0.12. Both vectors are turned, but they end up the same angle apart, because the gap is still 1. The score only sees the difference.

2. What does pre-norm change about the residual stream, compared with 2017's post-norm?

Show the answer

Only the copy going into attention or the feed-forward network is normalised. The stream itself is just added to, so it runs untouched from the first block to the last instead of being renormalised after every add.

3. Going from 32 to 8 key/value heads cut the cache 4×. Why not go all the way to 1?

Show the answer

One shared head (MQA) saves more memory but costs quality: in the GQA paper it scored 46.6 vs 47.1 for 8 groups and 47.2 for full multi-head. Eight groups kept almost all the quality.

Understand and remember

  • RoPE turns q and k by an angle set by position → a dot product of two turned vectors depends only on their angle difference → attention scores depend on relative distance, with no added parameters
  • Pre-norm normalises only the copy entering each sublayer (x + f(norm(x))) → the residual stream is only ever added to → a clean path runs from the first block to the last; RMSNorm drops mean-centring → same job, less work (7%–64% faster in its paper)
  • SwiGLU multiplies a Swish-gated projection by a second projection → three matrices instead of two → width shrinks to keep parameters equal → better perplexity at equal cost (1.636 vs 1.677), for reasons the author couldn't explain
  • KV per token = 2 × layers × KV heads × head size × bytes → GQA cuts KV heads from 32 to 8 while keeping 32 query heads → 512 KiB → 128 KiB per token → 4× more long conversations fit in GPU memory, at almost no quality cost (47.1 vs 47.2 in the GQA paper)
  • detail that matters RoPE's speed base sets the slowest pair's period → Llama raised it from 10,000 to 500,000 → the slowest pair takes about 2.56M tokens per turn (before Llama 3.1's extra 8× long-context stretch), so far-apart positions still look different

Reference only

  • Llama-3.1-8B: 32 layers, D = 4096, FFN 14,336, 32 query heads, 8 KV heads, head size 128, vocab 128,256
  • 2017 base model: d_model 512, d_ff 2048, 8 heads, post-norm LayerNorm(x + Sublayer(x)), sinusoidal positions
  • RMSNorm gains: 2 × 4096 = 8,192 per layer; SwiGLU MLP 176.16M per layer; attention 41.94M (GQA) vs 67.11M (MHA) per layer
  • GQA paper Table 1 (T5-XXL): MHA 47.2 / 1.51 s, GQA-8 47.1 / 0.28 s, MQA 46.6 / 0.24 s
  • RoFormer Table 1: WMT14 En-De BLEU 27.5 vs 27.3

5 · Predict commit to an answer before revealing

A hypothetical Llama-3.1-8B variant keeps 32 query heads but uses only 2 KV heads. Before computing: what is its KV cache per token, and what would you expect to happen to quality, based on the GQA paper?

Reveal

2 × 32 × 2 × 128 × 2 bytes = 32 KiB per token, 4× smaller again (an 8,192-token chat drops to about 0.27 GB). Quality would probably sit between GQA-8 and MQA: the GQA paper found one shared head lost noticeable quality (46.6 vs 47.2), so fewer KV heads trades capacity for memory.
