The target: GPT-2 124M

Also called: gpt2 on Hugging Face, GPT-2 small, the OpenAI checkpoint. Lecture 9 · exploring the GPT-2 (124M) OpenAI checkpoint · 0:03:39

Prime · 2 minutes before you read

The problem: "Reproduce GPT-2" is meaningless until you know exactly what you're aiming at: which model, how big, what its parts are called, and what score counts as matching it. Without a concrete target you can't tell a bug from a bad result.

Where it fits: This opens the capstone. The GPT lecture (z2h-8) built a small decoder on Shakespeare; here you look at the real, released version of that same design before rebuilding it at full size.

In one breath: GPT-2 124M is the smallest of the four GPT-2 models OpenAI released in 2019: 12 layers, each 768 numbers wide, reading up to 1,024 tokens. OpenAI published its trained weights, so you can load them and see exactly what you're about to build. OpenAI didn't publish how it trained them, so this lecture borrows the training recipe from the GPT-3 paper and tries to match or beat the released model from scratch.

Predict first: the name says 124 million parameters. What share of them sits in the 12 transformer blocks, and what share in the tables that turn tokens and positions into vectors?

About 68% in the blocks and about 32% in the tables. The token table alone is 50,257 × 768 = 38,597,376 numbers (31.0%), because it needs a row for every token in the vocabulary. The 12 blocks hold 85,054,464 (68.3%). The position table is small: 1,024 × 768 = 786,432 (0.6%).

What's inside the checkpoint

A checkpoint is a saved copy of a trained model's parameters, the numbers training adjusts. In PyTorch you get them as a state_dict, a dictionary from each tensor's name to the tensor itself (a tensor is an n-dimensional array of numbers). GPT-2's has 149 entries. Each name tells you where the tensor sits in the network:

NameWhat it isShapeNumbers
wteToken embedding ("word token embedding"): one learned row of 768 numbers per token in the 50,257-token vocabulary. An embedding is a learned vector that stands for a symbol.(50257, 768)38,597,376
wpePosition embedding: one learned row per position 0 … 1023, added to the token's row so the model knows where each token is.(1024, 768)786,432
h.0 … h.11The 12 blocks (layers). Each one has a LayerNorm (ln_1, ln_2: rescales each vector to a standard spread), self-attention (attn: tokens look at earlier tokens) and an MLP (mlp: each token is processed on its own).12 tensors each12 × 7,087,872
ln_fA final LayerNorm after the last block.(768,) × 21,536
lm_headThe output layer: turns each position's final vector into 50,257 logits, one raw score per possible next token. It's the same tensor as wte (the weight-tying card), so it adds nothing to the count.(50257, 768)shared

Hugging Face stores c_attn as (768, 2304), i.e. (in, out), because OpenAI's original code used a "Conv1D" layer. PyTorch's nn.Linear expects (out, in), so loading these weights needs a transpose (the load-and-forward card). 2304 = 3 × 768: the query, key and value projections packed together.

The position table learned waves

Nobody told GPT-2 what positions look like. wpe started as random numbers and was trained like everything else. Plot one of its 768 columns across the 1,024 positions and you get a noisy wave: neighbouring positions get similar values. The original Transformer paper fixed these to sine and cosine waves; GPT-2 trains them from scratch and recovers "sinusoidal like" features anyway (0:10:24).

Real values of wpe[:, 250] and wpe[:, 150] from the checkpoint. Neighbouring positions correlate 0.880 in column 250 and 0.533 in column 150. Karpathy reads the jaggedness as a sign the model is a bit undertrained (0:09:37). Across the whole table: mean −0.0007, std 0.1227; the extremes (−4.54 and 4.07) both sit at position 0.

for k, v in sd_hf.items():

generator = pipeline('text-generation', model='gpt2', device='cpu')
set_seed(42)

                num_return_sequences=5, do_sample=True, top_k=50)
for o in out:

Why this target

✗ Just use the released weights

You get a working model but learn nothing about making one. A checkpoint is only the end state of training; it doesn't contain the recipe.

✗ Follow the GPT-2 paper alone

The paper is vague about how training was run (0:03:11), and its WebText dataset was never released. So there's nothing precise to copy.

✗ Aim for gpt2-xl

1,557,611,200 parameters is 12.5× the 124M model, and the training cost grows with it. The ideas are the same; the bill isn't.

✓ GPT-2 124M with GPT-3's recipe

Small enough to train in about an hour for about $10 on rented GPUs (the build-nanogpt README), and the released checkpoint gives exact scores to beat: val loss 3.2924 and HellaSwag 29.55%.

Can my M3 do this?

Loading, inspecting and sampling: yes, in seconds. Training GPT-2 124M from scratch: no. At about 1,300 tokens a second, the 10-billion-token run would take roughly 89 days on your M3, versus 1–2 hours on 8 rented A100 GPUs (the results card). So in this course you build every piece and run it at laptop size; you rent a GPU only for the full run.

"124M" is a name, not a count. The checkpoint has 124,439,808 parameters. The model you train later has 124,475,904, because of the padded vocabulary. Don't expect your count to print exactly 124,000,000. The GPT-2 paper's own size table gives other numbers, and Karpathy says that table is wrong (0:01:22).

Understand and remember

  • Vocabulary of 50,257 tokens → one 768-number row per token in wte → 38,597,376 numbers → 31% of the model is a lookup table, so vocabulary size is a big lever on model size
  • Each block has four weight matrices (3C², C², 4C², 4C²) → about 12C² per block → parameters grow with L·C² → widening the model costs quadratically, deepening it linearly (124M → 1.56B from 12×768 to 48×1600)
  • wpe is an ordinary trained parameter, not a formula → it starts as noise and is shaped only by the loss → neighbouring positions end up correlated (0.53–0.88) → wave-like columns, and leftover jaggedness hints at an undertrained model
  • OpenAI released weights but not a precise training recipe or its WebText data → the checkpoint is a target, not a method → the lecture borrows GPT-3's hyperparameters and scores itself against the checkpoint (val loss 3.2924, HellaSwag 29.55%)
  • detail that matters Hugging Face stores c_attn etc. as (in, out) because OpenAI used a Conv1D layer → an nn.Linear expects (out, in) → loading needs a transpose, or the shapes silently mismatch (the load-and-forward card)
  • detail that matters lm_head is the same tensor as wte → it appears in the state_dict (149 entries) but adds nothing to the parameter count → counting state_dict numels gives 163,037,184, counting parameters() gives 124,439,808

Reference only

  • GPT2LMHeadModel.from_pretrained("gpt2"); "gpt2-xl" for the 1.5B model
  • the full tensor-name list and its transformer. prefixes
  • the family configs: 24/16/1024, 36/20/1280, 48/25/1600
  • pipeline('text-generation') arguments, and max_new_tokens vs max_length in transformers 5
  • the checkpoint download size (~550 MB)

  2. mechanism Walk one token through the checkpoint's tensors: from its id to a row of logits. Name each tensor it touches and the shape of the vector at each step.

    • doubling C also doubles wte and wpe; doubling L leaves them unchanged
    • context length T only touches wpe

Why this step?

5 · Predict commit to an answer before revealing

You change only the context length from 1,024 to 2,048 tokens. How many parameters does GPT-2 124M gain, and which tensor holds all of them?

Reveal

786,432 (= 1,024 × 768), all in wpe, giving 125,226,240. Attention has no weights that depend on sequence length: the same c_attn and c_proj apply at every position. That's why longer context is almost free in parameters but not in compute or memory, since attention's T×T scores grow with T² (the compile-flash card).
