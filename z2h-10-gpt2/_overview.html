Karpathy's exercises

This lecture has none. The video description lists chapters and links but no exercises, and the build-nanogpt README has an empty FAQ and no exercise list. The description's own summary of the lecture, verbatim: “First we build the GPT-2 network, then we optimize its training to be really fast, then we set up the training run following the GPT-2 and GPT-3 paper and their hyperparameters, then we hit run, and come back the next morning to see our results”.

The nearest thing is his list of what he'd try next, at 3:51:11 (paraphrased, except the quoted phrase). Each one is a real experiment for a rented GPU:

  1. Shuffle. Permute the documents and the shards every epoch; the unshuffled order is his suspect for the periodic wobble in the loss. Uses data and scorecards and the results.
  2. Raise the learning rate. On max_lr, “you can actually almost like 3x”, i.e. about 1.8e-3 instead of 6e-4 (computed). Uses the recipe.
  3. Match GPT-3's shape. Train with T = 2048 and B = 32: 32 × 2048 = 65,536 tokens per GPU, the same as B = 64 at T = 1024 (computed), so the batch arithmetic still gives 219 on 8 GPUs. Uses big batch.

Understand and remember

  • Use OpenAI's names and shapes for every module → the checkpoint's 149 tensors load by name (48 of them transposed) → logits match Hugging Face to 4.58e-05 and the samples read as English → the module is proven before any training, and a random init writing word salad shows the text comes from the weights
  • An untrained model should spread its bets → step-0 loss ≈ ln 50,257 = 10.82 (10.96 measured) → one fixed batch must overfit (10.96 → 0.36) while fresh batches stall near the 6.3 token-frequency floor → each check isolates one part (init, backward and optimizer, data) before the expensive run
  • The step is memory-bound, not arithmetic-bound → fewer bits (TF32, bf16), fewer HBM round trips (torch.compile, flash attention), full tiles (vocab 50,304) and one fused update → 1000 → 90 ms on an A100, about 11×, with the loss unchanged → speed tricks never touch the update rule
  • GPT-3's recipe is written in tokens → divide by the 219 tokens per step → 715 warmup steps, 19,073 steps per 10B tokens, and K micro-steps each dividing its loss by K → the same mean gradient on one A100, eight, or an M3 → then judge it on shard 0 (vs 3.2924) and 10,042 HellaSwag rows (vs 29.4%)
  • detail that matters Each Block adds to the residual stream twice → 24 adds in 12 Blocks → variances add, so the stream's std grows as √(adds) → c_proj starts at 0.02/√24 = 0.00408 → stream std 0.30 at block 12 instead of 1.54
  • detail that matters Accuracy on n examples has noise √(p(1−p)/n) → ±0.47 points on all 10,042 HellaSwag rows, ±9.7 on 20 → 33.24 vs GPT-3's 33.7 is about one standard error, while 29.4 → 33.24 is about eight

Reveal
