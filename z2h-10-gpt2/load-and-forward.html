Loading OpenAI's weights and getting logits

Also called: from_pretrained, porting a checkpoint, the forward pass. Lecture 9 · loading the huggingface/GPT-2 parameters · 0:28:08 · implementing the forward pass to get logits · 0:31:00

Prime · 2 minutes before you read

The problem: You have written GPT-2 as an empty nn.Module, but random weights produce nonsense. OpenAI's trained numbers exist, yet they come in someone else's layout, and a copy that is off by a transpose can look fine while computing garbage.

Where it fits: The module card gave you the right names and shapes. This card fills them with OpenAI's weights and runs the first forward pass, which is also the check that the module you wrote is really GPT-2. Sampling (next card) and the loss (first-loss card) both start from these logits.

In one breath: your empty GPT module already has the right tensor names and shapes, so loading GPT-2 means copying OpenAI's 149 tensors in by name. Four kinds of weight arrive stored sideways and must be transposed on the way in. Then the forward pass turns 8 token ids into 8 × 50,257 logits: raw scores, one per vocabulary token, for what comes next at every position.

Predict first: the copy loop checks every tensor's shape. OpenAI stores attn.c_proj.weight as (768, 768). If you forget to transpose it, does the shape check catch the mistake?

No, and the model quietly breaks. A 768 × 768 matrix has the same shape either way round, so the copy succeeds. In a check run for this card (CPU), the top guess after the prompt fell from ' not' at 16.4% to ' the' at 2.6%, and the loss on the first 256 tokens of tiny shakespeare rose from 4.34 to 7.37. The other three sideways weights aren't square, so forgetting their transpose fails loudly.

Why four weights arrive sideways

OpenAI's checkpoint (via Hugging Face) builds its linear layers with a module called Conv1D. It computes the same thing as PyTorch's nn.Linear, but it stores the weight matrix the other way round.

y=x Whf+bConv1D: W is (in, out) y=x Wours⊤+bnn.Linear: W is (out, in) Wours=Whf⊤so copy with .t()

The forward pass: (B, T) in, (B, T, vocab) out

The prompt "Hello, I'm a language model," is 8 tokens, so idx is (B, T) = (1, 8): one sequence of 8 ids. wte (token embedding) swaps each id for its 768-number row; wpe (position embedding) gives one row per position 0…7. Adding them broadcasts the (8, 768) positions across the batch. The Blocks keep the shape (1, 8, 768); ln_f normalizes; lm_head scores each position's vector against all 50,257 tokens.

# inside GPT.from_pretrained: copy HF's tensors into ours by name
transposed = ['attn.c_attn.weight', 'attn.c_proj.weight',
              'mlp.c_fc.weight', 'mlp.c_proj.weight']
for k in sd_keys_hf:
    if any(k.endswith(w) for w in transposed):
        assert sd_hf[k].shape[::-1] == sd[k].shape
        with torch.no_grad():
            sd[k].copy_(sd_hf[k].t())   # Conv1D -> Linear
    else:
        assert sd_hf[k].shape == sd[k].shape
        with torch.no_grad():
            sd[k].copy_(sd_hf[k])
def forward(self, idx):
    B, T = idx.size()
    pos = torch.arange(0, T, dtype=torch.long, device=idx.device)
    pos_emb = self.transformer.wpe(pos)   # (T, n_embd)
    tok_emb = self.transformer.wte(idx)   # (B, T, n_embd)
    x = tok_emb + pos_emb                 # broadcast over B
    for block in self.transformer.h:
        x = block(x)
    x = self.transformer.ln_f(x)
    return self.lm_head(x)                # (B, T, vocab_size)
model = GPT.from_pretrained('gpt2').eval().to(device)
tokens = enc.encode("Hello, I'm a language model,")   # tiktoken
idx = torch.tensor(tokens).unsqueeze(0).to(device)       # (1, 8)
logits = model(idx)

Why it beats the alternatives

✗ load_state_dict(sd_hf) as is

The names already match, so it looks like one line. PyTorch refuses with 36 size mismatches, and even if you fixed only those, the 12 square attn.c_proj weights would load sideways without a word.

✗ Just use GPT2LMHeadModel

Fine for sampling (the target card does). But the rest of the lecture edits the module itself (flash attention, a padded vocabulary, a new init), and you can't do that inside code you didn't write.

✗ Copy by position, not by name

Zipping the two tensor lists works only while both list tensors in the same order. Many tensors share a shape (every LayerNorm weight is (768,)), so a reordering would swap them silently.

✓ Copy by name, transpose a known list, then compare

Every tensor is matched by name and shape-checked, the four Conv1D kinds are transposed, and the final logits are compared with Hugging Face's: 4.58e-05 apart. The square case is caught by that last check.

What is a Conv1D doing in a language model?

Nothing convolutional. Hugging Face kept the name from OpenAI's original code, where the layer was written as a convolution of width 1. A width-1 convolution applies the same matrix to each position separately, which is exactly a linear layer. The only practical difference is the storage order, which is why the fix is one .t(). Two more things that trip people up: logits are raw scores, not probabilities (the last position's top scores are around −95; only their differences matter, e.g. e−94.687 + 94.768 = 1.084 ≈ 0.1643 / 0.1516, computed), and model.eval() changes nothing here because this model has no dropout; it's a habit for models that do.

When not to bother: if all you want is text from GPT-2, the Hugging Face pipeline on the target card is three lines. Porting the weights pays off only because you are about to change and retrain the model.

Understand and remember

  • Conv1D stores W as (in, out) and computes x·W → nn.Linear stores (out, in) and computes x·Wᵀ → same function only if Wours = Whfᵀ → the four linear weights per Block are copied with .t()
  • A shape check compares sizes, not contents → a square (768, 768) attn.c_proj fits either way round → forgetting its transpose loads silently and wrecks the output (top guess 16.4% → 2.6%, loss 4.34 → 7.37) → only an end-to-end comparison with a reference model catches it
  • idx (B, T) → wte gives (B, T, C) and wpe gives (T, C) → adding broadcasts positions over B → Blocks keep (B, T, C) → lm_head maps C → vocab → logits (B, T, 50257), a next-token prediction at every position
  • Logits are raw scores → softmax exponentiates and normalizes → only differences between logits matter → last-position scores near −95 still give ' not' 16.4%
  • detail that matters pos is created with device=idx.device → the model runs wherever the input lives (cpu, mps, cuda) without a hard-coded device → the same module moves to the M3 GPU with one .to(device)
  • detail that matters Copy happens inside torch.no_grad() with in-place copy_ → the module keeps its own Parameter objects (and the wte/lm_head tie) → the loaded model trains exactly like one you initialized yourself

3 · Retrieve from memory, card closed
  1. concept Explain why a Conv1D weight and an nn.Linear weight can describe the same layer yet need a transpose to move between them.
    Check
    • both compute a matrix multiply plus a bias for each token
    • Conv1D stores W as (in, out) and does x·W
    • nn.Linear stores W as (out, in) and does x·Wᵀ
    • so the same function needs Wours = Whfᵀ; biases are 1-D and copy as-is
  2. mechanism Walk the 8-token prompt through forward, naming each tensor and its shape, and say where broadcasting happens.
    Check
    • idx (1, 8); pos = arange(8) on idx's device
    • wte(idx) → (1, 8, 768); wpe(pos) → (8, 768)
    • tok_emb + pos_emb broadcasts the (8, 768) over the batch dimension
    • 12 Blocks keep (1, 8, 768); ln_f; lm_head → (1, 8, 50257)
  3. tradeoff You are porting weights and want the cheapest check that would have caught every mistake on this card. Per-tensor shape asserts, per-tensor value checksums, or one logits comparison with the reference model: what does each catch and cost?
    Check
    • shape asserts are free but miss square transposes and swapped same-shape tensors
    • value checksums against the source tensor miss a wrong transform applied on your side of the copy
    • one logits comparison costs a forward pass of both models and catches anything that changes the output
    • use the asserts for early, loud failures and the logits comparison as the final proof
  4. tradeoff Why does the forward pass compute 8 × 50,257 scores when sampling will read only the last row?
    Check
    • the Blocks compute every position anyway, and lm_head per position is cheap to keep
    • training uses all 8 rows: each is a next-token prediction with its own target
    • sampling throws away 7 rows and recomputes them next step (no KV cache), which is wasteful but simple
