Time value of money

Also called discounting, present value, or DCF (discounted cash flow). The root of everything else in this course: bond prices, option prices and the Kelly growth rate all compare money at different dates. The source guide only names "Financial Mathematics", so this card is written from standard references.

Prime · 2 minutes before you read

The problem: Cash flows arrive on different dates, and a dollar next year is worth less than a dollar today because today's dollar could be earning interest. Add them up raw and [−1000, 300, 400, 500] looks like a +200 win even though at 10% it loses money.

Where it fits: The first card of the course and the root of the pricing half: bonds discount coupons, and option prices discount an average payoff with e−rT. The IRR search reuses bisection from binary search on the answer.

In one breath

A dollar today beats a dollar next year, because today's dollar can earn interest in the meantime. So you can't add cash flows from different dates directly. Move each one to the same date first: grow it forward by (1 + r) per period, or shrink it back by the same factor. The shrunk-back values add up to the net present value (NPV).

Worked example 2: NPV and IRR of [−1000, 300, 400, 500]

Pay 1,000 now and get 300, 400, 500 at the end of years 1–3. Undiscounted that's +200. At 5% each inflow shrinks before it's added:

t cash × 1/1.05^t = today 0 −1000 1.0000 −1000.00 1 300 0.9524 285.71 2 400 0.9070 362.81 3 500 0.8638 431.92 NPV(5%) = 80.44

Raise r and NPV falls; the IRR is where the curve crosses zero. NPV only goes down as r goes up here (every inflow comes after the one outflow), so bisection is safe: halve the bracket, and keep the half whose ends have opposite signs.

In Python

import math

def fv(pv, rate, years, m=1):
    return pv * (1 + rate / m) ** (m * years)

def annuity_pv(pmt, rate, n):
    return pmt * (1 - (1 + rate) ** -n) / rate

def npv(rate, flows):
    """flows[t] arrives at the end of period t (t = 0 is now)."""
    return sum(cf / (1 + rate) ** t for t, cf in enumerate(flows))

def irr(flows, lo=-0.99, hi=1.0, tol=1e-10, trace=None):
    f_lo = npv(lo, flows)
    if f_lo * npv(hi, flows) > 0:
        raise ValueError("NPV has the same sign at both ends")
    while hi - lo > tol:
        mid = (lo + hi) / 2
        f_mid = npv(mid, flows)
        if trace is not None:
            trace.append((lo, hi, mid, f_mid))
        if (f_mid > 0) == (f_lo > 0):   # root is above mid
            lo, f_lo = mid, f_mid
        else:                           # root is below mid
            hi = mid
    return (lo + hi) / 2

fv(1000, 0.05, 10)                       # → 1628.89 (annual)
1000 * math.exp(0.05 * 10)               # → 1648.72 (continuous)
annuity_pv(1000, 0.06 / 12, 360)         # → 166791.61
npv(0.05, [-1000, 300, 400, 500])        # → 80.44
irr([-1000, 300, 400, 500])              # → 0.088963 (35 steps)

Time O(n) per NPV for n cash flows, and O(n · log2(width / tol)) for the IRR: each bisection step is one NPV. Space O(1). The # → values are the script's real output, rounded as printed.

Why NPV beats the other decision rules

✗ Add up the cash

[−1000, 300, 400, 500] "makes 200". That's the NPV at r = 0. At 10% the same project loses 21.04 in today's money.

✗ Payback period

Pick whatever returns the 1,000 soonest. [−1000, 1000, 0, 0] pays back in 1 year versus 2.6, yet its NPV at 5% is 1000/1.05 − 1000 = −47.62.

✗ IRR alone

A percentage with no size, so it can prefer a small project to a much bigger one. And with more than one sign change it can have several answers: [−100, 230, −132] has IRRs of 10% and 20%.

✓ NPV at your cost of capital

Every flow gets moved to today at the rate you could actually earn, so the result is in dollars and the NPVs of separate projects just add up. +80.44 at 5%: do it.

Is one rate r always right?

No. A single r assumes a flat rate for every date and a known cash flow. Real bond pricing discounts each date by its own zero rate, which is a yield curve (see the bonds card). Risky cash flows need a higher r, which is where CAPM comes in. Option cash flows are uncertain, so you discount their risk-neutral expected value instead (Black–Scholes, Monte Carlo).

Match the rate to the compounding. "6% a year, paid monthly" means 0.5% a month (an effective 6.17%), and pricing models (Hull and this course's option cards) use continuous rates: e−rT, where 5% continuous equals 5.1271% annual. A quick check: money doubles in about 72 / r% years (72 / 5 = 14.4) against an exact ln 2 / ln 1.05 = 14.21.

Understand and remember

  • Today's dollar can earn r → a dollar at t is worth only 1/(1+r)t today → flows at different dates must be discounted to one date before adding → NPV is that sum, in today's dollars
  • Crediting interest m times a year → each credit earns sooner → value rises with m → but the gain per step shrinks and the limit is erT (annual → daily +19.77, daily → continuous 6 cents)
  • One outflow then only inflows → NPV falls monotonically as r rises → exactly one root → bisection that keeps the half with a sign change must find the IRR; more sign changes → several roots (10% and 20%) → IRR becomes ambiguous
  • NPV is in dollars at a rate you could actually earn → decisions compare size, not just percentage → payback and IRR can both pick the worse project ([−1000, 1000, 0, 0] pays back in a year yet has NPV −47.62)
  • detail that matters Bisection halves the bracket each step → steps = log₂(width / tol) → 35 steps from width 1.99 to under 10−10, each one an O(n) NPV; Newton would take fewer but can leave the bracket

5 · Predict commit to an answer before revealing

Run the card's irr() on [−100, 230, −132] with its default bracket [−99%, 100%]. Does it return 10%, 20%, or something else? Commit before revealing.

Reveal

Neither: it raises ValueError. NPV is about −1.3 × 10⁶ at −99% and −18.0 at 100%, the same sign at both ends, so there is no sign change to bisect. NPV is positive only between the two roots (at 15% it is +0.19). You'd need a bracket such as [0%, 15%] or [15%, 100%] to find one root, which is exactly why IRR is ambiguous for these flows.
