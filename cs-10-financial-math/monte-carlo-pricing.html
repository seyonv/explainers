Monte Carlo pricing

Also called Monte Carlo simulation or path simulation. The course's shared call (S₀ = 100, K = 100, r = 5%, σ = 20%, T = 1, Black–Scholes 10.4506) priced by averaging random payoffs, then an Asian option, where no textbook formula exists and simulation is how desks price it.

In one breath

An option's price is its expected payoff under the risk-neutral measure, discounted. So simulate many possible stock prices at expiry (growing at r, not at the real-world drift), compute the payoff for each, average, and discount. The average is off by roughly its standard error, s/√n: to get one more correct digit you need 100× the paths.

Three words, two examples each

Variance reduction means buying the same accuracy with fewer paths. Think of polling: asking each person twice with opposite phrasings (antithetic), or correcting your sample by a question whose true answer you already know (control variate).

"÷ 1,281" means the plain estimator would need about 1,281× as many paths for the same SE. It works because arithmetic and geometric averages of the same path move almost together (b = 1.031). The ratios are for these seeds and this contract, not general constants.

Where Monte Carlo is the natural tool: an Asian option

An Asian call pays max(average price − K, 0), here the average of 12 monthly closes. Averaging makes it cheaper than the vanilla call (≈ 6.16 vs 10.45): the average moves less than the final price. The only change to the code is simulating the whole path, not one jump to T.

12 steps, dt = 1/12: S_j = S_(j-1) * exp((0.05 - 0.02)/12 + 0.2*sqrt(1/12)*Z_j) payoff = exp(-0.05) * max(mean(S_1 .. S_12) - 100, 0) check: geometric-average version, MC 5.9558 ± 0.0261 vs closed form 5.9402 (0.6 SE apart)

In Python

import math, numpy as np
S0, K, R, SIGMA, T = 100.0, 100.0, 0.05, 0.20, 1.0
DISC = math.exp(-R * T)

def paths(z):                  # z: (n paths, m steps) normals
    dt = T / z.shape[1]
    inc = (R - SIGMA**2 / 2) * dt + SIGMA * math.sqrt(dt) * z
    return S0 * np.exp(np.cumsum(inc, axis=1))

def european(s): return DISC * np.maximum(s[:, -1] - K, 0)
def asian(s):    return DISC * np.maximum(s.mean(axis=1) - K, 0)

def estimate(x):               # mean and standard error
    return x.mean(), x.std(ddof=1) / math.sqrt(len(x))

def antithetic(payoff, n, m, seed=0):
    z = np.random.default_rng(seed).standard_normal((n // 2, m))
    return estimate((payoff(paths(z)) + payoff(paths(-z))) / 2)

z = np.random.default_rng(0).standard_normal((10**6, 1))
print("%.4f +- %.4f" % estimate(european(paths(z))))
print("%.4f +- %.4f" % antithetic(european, 10**6, 1))
z = np.random.default_rng(0).standard_normal((10**5, 12))
print("%.4f +- %.4f" % estimate(asian(paths(z))))
# → 10.4697 +- 0.0147     plain European
#   10.4643 +- 0.0104     antithetic: variance / 2.00
#   6.1722 +- 0.0269      Asian, 12 monthly fixings

Time O(n·m) · Space O(n·m) for n paths of m steps: one normal draw, one exp and one payoff per step. The error falls as 1/√n whatever the number of steps or assets, which is Monte Carlo's whole selling point. The full file adds the control variates and the geometric-Asian closed form.

Why it beats the alternatives

For pricing the arithmetic Asian call:

✗ A closed formula

A sum of lognormals isn't lognormal, so there is no Black–Scholes-style formula for the arithmetic average. Only the geometric version (5.9402) has one, and it sits 0.22 below the arithmetic price (5.9402 vs 6.1561).

✗ A binomial tree

The tree recombines on price, but the payoff depends on the path. Tracking the running average means 2m distinct paths: 4,096 for 12 steps, 2252 for daily fixings.

✗ A PDE grid

Works, but needs the running average as an extra grid dimension. Every added asset or path variable multiplies the grid: the curse of dimensionality.

✓ Monte Carlo

Any payoff you can compute from a simulated path, at error ∝ 1/√n regardless of dimension. With the geometric control variate, 10⁵ paths give ±0.0008.

So always simulate?

No. For the plain European call, Black–Scholes gives 10.4506 exactly from one formula, while a million paths still leave ±0.015; for one-asset options a binomial tree also converges faster than 1/√n. Use MC when the payoff depends on the path or on many assets (Asian, barrier, lookback, basket options), where trees and grids blow up.

Two cases MC handles badly out of the box. American options: a path doesn't know when to exercise, because that needs the future's expected value; the standard fix is Longstaff–Schwartz regression, or a tree. Greeks: bumping S₀ and re-simulating with fresh random numbers is buried in noise; reuse the same draws (common random numbers) or use pathwise estimates. Quasi-random (Sobol) points can beat 1/√n for smooth problems, but their error bar is harder to estimate.
