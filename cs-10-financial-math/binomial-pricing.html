Binomial option pricing

Also called the binomial tree, the binomial lattice, or the Cox–Ross–Rubinstein (CRR) model. The standard way to price an option by hand, and the usual method for American options that can be exercised early. The cheat-sheet has no page for it; this course's shared contract is S₀ = 100, K = 100, r = 5%, σ = 20%, T = 1.

In one breath

Pretend the stock can only move up or down over the next step. Then some mix of stock and borrowed cash pays exactly what the option pays in both cases, so the option must cost what that mix costs today. Chop a year into many such steps, work back from the payoffs at expiry, and you get the option's price.

One step: 100 goes to 110 or 90, K = 100, r = 0

Replicate: hold Δ = (10 − 0) / (110 − 90) = 0.5 share, borrow B down state: 0.5 × 90 − B = 0 → B = 45 up state: 0.5 × 110 − 45 = 10 ✓ pays exactly what the call pays cost today: 0.5 × 100 − 45 = 5 Shortcut: q = (100 − 90) / (110 − 90) = 0.5, C = 0.5 × 10 + 0.5 × 0 = 5

Both routes give 5. Nobody said how likely the up move is: the price comes from the hedge, not from a forecast. Any other price lets you sell the dear one, buy the cheap one, and pocket the gap with no risk.

Three layers, three lines of arithmetic. Two steps is far too coarse (Black–Scholes says 10.4506), but the recipe is identical for 1,000 steps; only the loop gets longer. The middle node is exactly 100 because u × d = 1: the tree recombines, so layer i has i + 1 nodes, not 2i.

In Python

import math

def crr(s, k, r, sigma, t, n, call=True, american=False):
    dt = t / n
    u = math.exp(sigma * math.sqrt(dt)); d = 1 / u
    q = (math.exp(r * dt) - d) / (u - d)
    disc = math.exp(-r * dt)
    sign = 1 if call else -1
    payoff = lambda x: max(sign * (x - k), 0.0)
    # expiry layer: j up-moves, n - j down-moves
    v = [payoff(s * u**j * d**(n - j)) for j in range(n + 1)]
    for i in range(n - 1, -1, -1):       # roll back to t = 0
        v = [disc * (q * v[j + 1] + (1 - q) * v[j])
             for j in range(i + 1)]
        if american:                      # exercise now if better
            v = [max(x, payoff(s * u**j * d**(i - j)))
                 for j, x in enumerate(v)]
    return v[0]

for n in (1, 10, 100, 1000):
    print(n, round(crr(100, 100, 0.05, 0.2, 1, n), 4))
print(round(crr(100, 100, 0.05, 0.2, 1, 1000, call=False), 4),
      round(crr(100, 100, 0.05, 0.2, 1, 1000, False, True), 4))

Time O(N²) · Space O(N). Rolling back visits N + (N − 1) + … + 1 ≈ N²/2 nodes, and only one layer is kept at a time. N = 1,000 is about 500,000 node updates.

Why it beats the alternatives

✗ Expected payoff, real odds

"The stock goes up 90% of the time, so the call is worth 0.9 × 10 = 9" (illustrative odds). But 0.5 share minus 45 borrowed pays the same 10 or 0 and costs 5, so at 9 you'd sell the call, buy the copy, and keep 4 either way.

✗ The Black–Scholes formula

Exact and instant for a European option, but it has no way to say "exercise now". For the shared contract's American put it gives no answer; the tree says 6.0896 against 5.5735 for the European one.

✗ Monte Carlo paths

Simulates forward, so at each date it doesn't know the value of waiting, which early exercise needs. Workarounds exist (regression methods), but they are heavier, and the answer has sampling noise on top.

✓ The binomial tree

No calculus, exact for its own model, and it works backwards, so each node can compare "exercise now" with "hold": one max per node. N = 1,000 gets within 0.002 of Black–Scholes.

Is the tree always the tool?

No. For a European call or put on one stock, the Black–Scholes formula is exact and costs one line; the tree only approaches it, zig-zagging, at O(N²) work. For options that depend on the whole path (Asian, lookback) or on many assets, the tree blows up, and Monte Carlo is the usual tool. The tree earns its keep on early exercise: American puts, and calls on stocks that pay dividends.

An American call with no dividends is never worth exercising early, so the tree gives the European value, 10.4486 at N = 1,000 (Hull states this result; the code checks it). And q is not a forecast. It is the weight that makes the stock earn exactly r on average, which is the only weighting that agrees with the hedge. The real drift never enters the price.
