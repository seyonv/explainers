Self-attention: one head (Q, K, V)

Also called: an attention head, query-key-value attention, dot-product attention (this version isn't scaled yet). Lecture 7 · THE CRUX OF THE VIDEO: version 4: self-attention · 1:02:00

Prime · 2 minutes before you read

The problem: Averaging the past gives every earlier token the same weight, in every sequence. A character can't pick out the one earlier character that actually tells it what comes next, so the model can't use context well.

Where it fits: This is the crux of the lecture. The tril-matmul and masked-softmax cards built wei @ x with fixed weights; this card makes the scores inside that softmax come from the tokens themselves.

Needs first: Masked softmax: −∞ means no looking ahead

Builds on: Masked softmax: −∞ means no looking ahead · A triangular matrix multiply does the averaging · Vectors and the dot product · Softmax and cross-entropy, first look

You'll meet: query, key and value vectors affinity scores q @ k.transpose(-2, -1) masked softmax over the scores aggregating v instead of x

By the end: Explain how one head turns x into data-dependent weights and a weighted mix of values, compute one row by hand, and write the head in about a dozen lines.

Read with these questions (answer them in your head as you go; don't take notes line by line):

  1. Why do queries and keys come from two different linear maps of the same x, instead of dotting x with itself?
  2. At which line does wei start to differ between sequence 0 and sequence 1, and why didn't it before?
  3. Why must k.transpose(-2, -1) swap only the last two axes, and what would go wrong if the batch axis moved?
  4. What does a token gain by sending v rather than its raw embedding x?
  5. If the raw scores in a row grow larger in size, what happens to the weights after softmax?

In one breath: every token turns its vector into three smaller ones: a query (what it's looking for), a key (what it contains) and a value (what it will pass on). A token's query dotted with each earlier token's key gives a score. Softmax turns those scores into weights, and the token's output is the weighted mix of the earlier tokens' values. The averaging weights stop being fixed at 1/(t+1) and start depending on the data.

Predict first: in the averaging version, row 7 of wei was 0.125 in every column, the same for every sequence. With queries and keys, is row 7 still uniform? And do sequence 0 and sequence 1 get the same row 7?

Neither. Sequence 0's row 7 runs from 0.0210 to 0.2423, and sequence 1's row 7 is completely different (0.365 on token 0). The weights now come from the tokens' contents, so every sequence gets its own wei. The layers are still untrained here, so the pattern itself doesn't mean anything yet.

The data flow through one head

Words used above: B is the batch (4 separate sequences), T the time axis (8 positions), C the channels (each token's embedding has 32 numbers). nn.Linear(C, head_size, bias=False) is a learned 32×16 matrix, so each of key, query and value holds 32 × 16 = 512 weights, 1,536 per head.

Row 1, by hand

Token 1 of sequence 0 can see tokens 0 and 1. Its query dotted with their keys gives two raw scores, and softmax turns them into two weights:

scores q₁·k₀ = −3.3334 q₁·k₁ = −1.6556 exp e^−3.3334 = 0.0357 e^−1.6556 = 0.1910 sum 0.2267 wei[0,1] 0.0357 / 0.2267 = 0.1574 0.1910 / 0.2267 = 0.8426 out[0,1] = 0.1574 · v₀ + 0.8426 · v₁ dim 0: 0.1574 × −0.1571 + 0.8426 × 0.8321 = 0.6764 dim 1: 0.1574 × 0.8801 + 0.8426 × −0.8144 = −0.5477

▶ Build itruns on your M3 · under 1 s

When: pause the video at 1:02:00 and type this cell before watching on. Start with import torch, torch.nn as nn and torch.nn.functional as F.

torch.manual_seed(1337)
B,T,C = 4,8,32
x = torch.randn(B,T,C)
head_size = 16
key   = nn.Linear(C, head_size, bias=False)
query = nn.Linear(C, head_size, bias=False)
value = nn.Linear(C, head_size, bias=False)
k, q = key(x), query(x)              # (B,T,16) each
wei = q @ k.transpose(-2, -1)        # (B,T,16)@(B,16,T) -> (B,T,T)
tril = torch.tril(torch.ones(T, T))
wei = wei.masked_fill(tril == 0, float('-inf'))
wei = F.softmax(wei, dim=-1)
out = wei @ value(x)                 # (B,T,16)
print(out.shape); print(wei[0])

Why it beats the alternatives

✗ Plain average of the past

Row 7 is 0.125 for every token in every sequence. A vowel can't go looking for the last consonant; everything gets the same say.

✗ A learned but fixed T×T weight table

Weights could depend on position, but not on what's there. Sequence 0 and sequence 1 would share one row 7, so the model can't react to content.

✗ Mix the raw x instead of v

The lab keeps this as the commented-out out = wei @ x. A token's whole embedding would double as its message; with v it chooses what to share, and the head's output size (16) is set separately from C (32).

✓ Query · key scores, values mixed

Weights are computed from content, per sequence: sequence 0's last token leans on token 6 (0.2423), sequence 1's on token 0 (0.365). Training shapes the three matrices so that high scores land on useful tokens.

Is this the attention in GPT?

It's the core, with three pieces still missing. The scores aren't scaled by 1/√head_size yet, so softmax can get peaky as head_size grows (next: scaled attention). There's only one head. And the Linear layers are untrained, so these weights are random: Karpathy's "a vowel looks for consonants" story is what training could learn, not what these numbers show.

Attention has a cost: every token scores every earlier token, so the work grows with T². gpt.py's block_size 256 means 256 × 256 = 65,536 scores per head per sequence. When a token only needs a fixed, small neighbourhood, a convolution or a plain MLP over a window (the WaveNet course) can be cheaper. And if you delete the mask line, every token sees the future too: that's an encoder block, fine for classifying a whole sentence but useless for generating the next character.

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • Each token projects x into a query and a key → the score qt·kj depends on both tokens' contents → softmax of those scores gives weights that differ per sequence → aggregation becomes content-based instead of a fixed average
  • Future positions are set to −∞ before softmax → e−∞ = 0 → token t mixes only tokens 0…t → the head stays usable for next-character prediction (delete the mask and it becomes an encoder that sees the answer)
  • Values are a separate projection → what a token advertises (key) is decoupled from what it hands over (v) → the output width is head_size, not C → heads can be stacked and concatenated later
  • Softmax is exponential in the scores → bigger score gaps give near one-hot rows (row 1 goes 0.1574/0.8426 → 0.0012/0.9988 when x doubles) → unscaled scores make attention peaky and gradients thin → the √head_size scaling on the next card
  • detail that matters Scores form a (B, T, T) matrix per head → cost and memory grow with T² (65,536 scores per head per sequence at block_size 256) → context length is the expensive knob in a Transformer

Reference only

  • nn.Linear(C, head_size, bias=False) for key, query and value (512 weights each in the toy, 1,536 per head)
  • toy sizes B,T,C = 4,8,32, head_size = 16, seed 1337
  • torch.tril(torch.ones(T, T)) and masked_fill(tril == 0, float('-inf'))
  • F.softmax(wei, dim=-1): softmax along the last axis

  4. mechanism Why does wei have shape (B, T, T) and not (B·T, B·T)? What does that say about which tokens can talk to each other?
    Check
    • the batched matmul pairs tokens only within one sequence
    • no scores exist across sequences, so no information flows between batch rows
    • the mask then limits each row further to earlier positions

4 · Compare against what you already know

vs Letting tokens talk: average the past: Both produce a weighted mix of earlier tokens. What single design choice separates them, and when would the plain average be good enough?

Check
  • average: weights fixed at 1/(t+1), same in every sequence
  • one head: weights from q·k, so they change with content
  • the average is fine when every earlier token is equally informative, which almost never holds for text
  • average fails by blurring the useful token with the rest; attention fails if scores saturate (the next card's problem)

vs One head, then many heads: One 32-dim head vs four 8-dim heads with the same parameter count: what's different in what they can attend to, and which did the lecture measure as better?

Check
  • one head gives each token a single weight row, so one pattern of attention
  • four heads give four independent weight rows, attending to different things at once
  • the lab measured val 2.41 for one head vs 2.29 for four (7,553 params each)

5 · Predict commit to an answer before revealing

Keep the same seed and weights, but multiply x by 2 before the head. Row 1 of wei[0] was 0.1574, 0.8426. Commit to a guess: does it stay the same, get flatter, or get sharper, and roughly how much?

Reveal

Much sharper: 0.0012, 0.9988. q and k both double, so every score is multiplied by 4 (−3.33 → −13.33, −1.66 → −6.62), and softmax is exponential in the gap. Row 7's top weight rises from 0.2423 to 0.3591. The size of the scores, not just their order, controls how peaky attention is. That's exactly why the next card divides by √head_size.
