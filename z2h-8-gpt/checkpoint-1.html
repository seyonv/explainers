Checkpoint 1: from averaging the past to one attention head

Ties together the triangular matrix multiply, masked softmax, token and position embeddings, queries, keys and values, five facts about attention and why divide by √head_size, with softmax, variance, broadcasting and embedding lookups from earlier courses. Lecture 7, 0:42:13 to 1:19:11.

What this ties together, and why now. The self-attention half of Lecture 7 builds one head in small steps. Start with averaging the past in a double loop. Turn that average into one lower-triangular matrix multiply. Rebuild the matrix as masked softmax over a table of scores. Let each token's query and key fill in those scores. Add position rows so the head can tell order. Scale the scores so softmax doesn't saturate at step 0. Next, Karpathy drops this head into the model, then copies it into four heads and stacks it into blocks. Check now that you can write a head from memory and say what each of its lines is for, because every later card assumes you can.

Comes back from earlier courses: the softmax is the toolkit's softmax, where shifting all scores changes nothing. The √head_size is the toolkit's "variances add", the same arithmetic as Kaiming init. The row normalisation is the keepdim trap from the bigram course. The position table is an embedding lookup, like the MLP's C.

How to use this page. Close the cards. Write out each answer in full sentences before you open its Check. The questions come in mixed order and don't say which card they're from, so part of the work is picking the right idea. If an answer is wrong or shaky, its Check names the exact section to reopen.

1 · Mixed retrieval

  1. Token 1 of sequence 0 has raw scores q₁·k₀ = −3.3334 and q₁·k₁ = −1.6556. Compute its two attention weights. Then say why row 7 of wei differs between sequence 0 and sequence 1, when in the averaging version it was 0.125 everywhere.
    Check
    • exponentiate: e−3.3334 = 0.0357 and e−1.6556 = 0.1910, which sum to 0.2267
    • divide: 0.0357 / 0.2267 = 0.1574 and 0.1910 / 0.2267 = 0.8426. Tokens 2 to 7 get exactly 0, because they are masked
    • the scores are dot products of each sequence's own queries and keys, so the weights depend on the content: sequence 0's token 7 puts the most weight, 0.2423, on token 6, while sequence 1's puts 0.365 on token 0
    • the layers are untrained, so these patterns mean nothing yet. What matters is that the weights can depend on the data. The fixed 1/(t+1) average can't

    If you missed it, reopen queries, keys and values, "Row 1, by hand" and "Row 7: weights that depend on the data", and the toolkit's softmax and cross-entropy, "Softmax, step by step".

  2. debugYou train the one-head model (n_embd 32, block_size 8, lr 1e-3). By step 500 it prints train loss 0.5063, val loss 0.5096, and after 5,000 steps val is 0.3867, far below the finished GPT's 1.48. But the sample is WWWWWWWWWWWWWWWWWWWWWWWWWWgggggggg…. What went wrong, and which single number per position would prove it?
    Check
    • the causal mask is missing: the masked_fill(tril == 0, float('-inf')) line was deleted, or replaced by something that doesn't block the future
    • within one chunk, position t's target is the character at t + 1, which is also in the input. Without the mask, position t can simply read its answer
    • proof: the val loss for each position. Positions 0 to 6 score 0.0094 to 0.0212, and position 7, which has no future to read, scores 3.1328. The mean, (0.0888 + 3.1328) / 8 = 0.40, is the suspiciously good number the run printed
    • generation always predicts from the last position, the one that never learned. Its 3.13 is worse than the bigram's 2.49, so the samples fall apart. With the mask restored, the same model reaches val 2.4103

    If you missed it, reopen masked softmax, "What the mask protects", five facts about attention, note 4 in "All five notes, each checked in code", and chunks and batches, "One chunk, eight examples".

  3. With seed 42, b = [[2, 7], [6, 4], [6, 5]] and a = torch.tril(torch.ones(3, 3)). Compute rows 1 and 2 of (a / torch.sum(a, 1, keepdim=True)) @ b. Then say what goes wrong if you drop keepdim=True.
    Check
    • the normalised a has rows [1, 0, 0], [0.5, 0.5, 0] and [1/3, 1/3, 1/3], so c[1] = 0.5·[2, 7] + 0.5·[6, 4] = [4, 5.5] and c[2] = [14, 16] / 3 = [4.6667, 5.3333]
    • with keepdim, the row sums have shape (3, 1) and stretch across each row, so each row is divided by its own count
    • without it, the sums have shape (3,), which broadcasts as a row, so column j gets divided by row j's sum. a becomes [[1, 0, 0], [1, 0.5, 0], [1, 0.5, 0.3333]], and its rows sum to 1, 1.5 and 1.8333. c comes out [[2, 7], [5, 9], [7, 10.6667]], which are not averages. No error is raised (computed)
    • it's the same silent bug as the bigram course's count normalisation. And tril without any division gives sums: row 2 would be [14, 16]

    If you missed it, reopen the triangular matrix multiply, "Three versions of a, same b", and broadcasting and the keepdim trap, "What each version computes".

  4. which idea?A teammate feeds one untrained head the chunks "tab" and "atb" and gets the same output for the last token b (max difference 6e-8, float noise), with weights t 0.0948 · a 0.6881 · b 0.2172 both times. They conclude attention can't read order. Which idea explains the result, what did they leave out, and what breaks if they now feed 9 characters?
    Check
    • attention works on a set: every score is a dot product of two tokens' contents, so swapping t and a only moves the same weights to the other slot, and the weighted mix is unchanged
    • they left out the position table. With x = tok_emb + pos_emb, the same two chunks give different outputs (max difference 0.8732)
    • the causal mask gives only a weak sense of order, which is why GPT still adds position rows
    • the position table has block_size = 8 rows, so 9 characters raise IndexError: index out of range in self. That's why generate crops to idx[:, -block_size:]

    If you missed it, reopen token and position embeddings, "Why attention needs the position rows" and "Can a position table handle any length?", and five facts about attention, "Is the mask the only thing that makes it "GPT"?".

  5. q and k are unit-variance vectors of gpt.py's head size, 64. Predict the variance of one score q·k, with and without scaling. Then say what softmax does to Karpathy's scores [0.1, −0.2, 0.3, −0.2, 0.5] multiplied by 8, and why that hurts learning.
    Check
    • q·k is a sum of 64 independent products, each with variance 1, and the variances add, so the variance is about 64 (measured 63.10)
    • scaled by 64−0.5 = 1/8, the variance is divided by 64, back to about 1 (measured 0.986). Dividing by head_size instead would overshoot, to about 1/64 (0.0154 measured)
    • ×8 gives [0.0326, 0.0030, 0.1615, 0.0030, 0.8000]: one token takes 80%, against 0.2872 unscaled
    • near one-hot, nudging a score hardly moves any weight. Softmax's gradient size falls from 1.57 to 0.67 (×8) to 0.00018 (×50), so the queries and keys barely learn
    • it's the same √fan_in argument as Kaiming init, applied to a dot product instead of a layer

    If you missed it, reopen why divide by √head_size, "Where the 16 comes from" and "Why a wide spread hurts: softmax turns peaky", and the toolkit's mean, variance and the Gaussian, "Add random numbers, and their variances add".

  6. which idea?To "simplify", a teammate deletes the query and key layers and keeps wei = torch.zeros(T, T), masked and softmaxed, then @ v. Everything else is the same (7,553 parameters). It trains to val 2.8392, worse than the plain bigram's 2.4903, while the real head reaches 2.4103. Which idea explains that ranking?
    Check
    • with zero scores, masked softmax gives the running average: every past token gets 1/(t + 1), in every sequence. That's the bag-of-words average from the first self-attention card
    • the token's own vector is only 1 of t + 1 equal votes (12.5% at t = 7), so the current character, the one thing a bigram relies on, gets blurred into its past. Our reading: nothing else in this model (no residual path yet) passes it through intact
    • query·key scores let each row choose. A token can put most of its weight on itself or on a useful neighbour, and that choice differs from sequence to sequence
    • the zeros were only ever a placeholder for "no preference yet". Their job was to become learned, data-dependent scores

    If you missed it, reopen average the past, "Is this what GPT does?", masked softmax, "Three steps, same matrix as before", and queries, keys and values, "Why it beats the alternatives".

  7. Give the shapes. x is (4, 8, 32), head_size is 16, and wei = q @ k.transpose(-2, -1). Then answer two things: (a) why the 4 sequences never mix, and how many (query, key) pairs a batch scores; (b) in cross-attention with keys and values from 6 source vectors, what shapes wei and out have.
    Check
    • q and k are (4, 8, 16). transpose(-2, -1) swaps only the last two axes, giving (4, 16, 8), so wei is (4, 8, 16) @ (4, 16, 8) → (4, 8, 8), one 8 × 8 table per sequence. out = wei @ v is (4, 8, 16)
    • (a) @ treats the leading axis as a batch, so each sequence multiplies only its own matrices: 4 × 8 × 8 = 256 pairs. One pool of 32 tokens would score 32 × 32 = 1,024 pairs, and the sequences would leak into each other
    • (b) wei is (4, 8, 16) @ (4, 16, 6) → (4, 8, 6), 8 queries × 6 keys. out is (4, 8, 6) @ (4, 6, 16) → (4, 8, 16), one output per query
    • the averaging version's (8, 8) wei had no batch axis at all. Broadcasting reused it for every sequence

    If you missed it, reopen five facts about attention, "All five notes, each checked in code", the triangular matrix multiply, "Version 2: the whole toy batch in one multiply", and the toolkit's matmul by shapes, "More than two dimensions, and counting parameters".

  8. which idea?Row 1 has visible scores [1, 3] and future scores [0, 0]. Three people implement the mask three ways: (a) masked_fill(-inf) then softmax, (b) multiply the scores by tril then softmax, (c) softmax first, then zero the future. Which gives a valid causal row? And what happens to row 2 if every score in it is raised by 7?
    Check
    • (a) is correct: 0.1192, 0.8808, 0, 0. e−∞ = 0 drops the future from both the top and the bottom of the fraction
    • (b) leaks: a score of 0 isn't "nothing", since e0 = 1. The row comes out 0.1096, 0.8098, 0.0403, 0.0403, the same as no mask at all
    • (c) blocks the future but doesn't renormalise: the row sums to 0.1096 + 0.8098 = 0.9194, so each position's output shrinks by a different amount
    • adding 7 everywhere changes nothing, because softmax only sees the gaps between scores: e7 / (3·e7) = 1/3

    If you missed it, reopen masked softmax, "What the mask protects" and "Why it beats the alternatives", and the toolkit's softmax and cross-entropy, "Scale stretches it, shift does nothing".

3 · Build: one head, three ways to mix the past

runs on your M3 · about 16 sWhat it reinforces: the loop and the matmul give the same averages (tril trick), zeros become scores (masked softmax), token plus position rows (embeddings), q·k·v (one head), what the mask is for (note 4), the 1/√d scale (scaled attention), and the bigram training loop (bigram.py). One Head class has a mode switch, and the three runs differ in one line each.

Start from your bigram.py with the position table (n_embd 32, block_size 8, batch 32):

  1. Warm-up check. On the toy x (seed 1337, B,T,C = 4,8,2), build xbow with the double loop, xbow2 with the normalised tril, and xbow3 with masked softmax over zeros. Both torch.allclose calls print True.
  2. One Head, three modes. 'average': wei = torch.zeros(B, T, T), masked, softmax, @ v. 'head': q @ k.transpose(-2, -1) * k.shape[-1]**-0.5, masked. 'nomask': the same scores with the masked_fill line skipped. head_size = n_embd = 32, and key/query/value have bias=False.
  3. Same start for all three. torch.manual_seed(1337), then create the head before the embedding tables, as the heads lab does, so every run starts from the same weights.
  4. Predict first. Write down the order of the three final val losses, and where they sit against the bigram's 2.49.
  5. Train each for 5,000 steps at lr 1e-3 with estimate_loss every 500 steps. After the no-mask run, print the val loss for each position (reduction='none', averaged over a 256-row val batch), and sample 120 characters from every model.
Done when: all three models have 7,553 parameters. The real head ends at val 2.4103 (the heads card's number). The average-only head ends at 2.8392, above the bigram's 2.4903. The no-mask head reports an impossible 0.3867, with positions 0 to 6 at about 0.01 and position 7 at 3.1328, and its sample is a run of repeated letters.

The no-mask model scores well only because it learned to copy the next character, and a copier has nothing to copy at the last position. That's where generation reads, so the sample breaks down. The average-only model is the surprise: equal weights blur the current character, which the bigram gets for free. Scratch script: 3 runs × 5,000 steps on CPU.
