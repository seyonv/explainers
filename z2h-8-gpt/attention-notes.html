Five facts about attention

Also called: Karpathy's notes 1–5 on attention; attention as message passing on a graph; encoder vs decoder blocks; self- vs cross-attention. Lecture 7 · note 1: attention as communication · 1:11:38

Prime · 2 minutes before you read

The problem: You can now write one attention head, but not yet say what it can and can't see: whether it knows word order, whether sequences in a batch leak into each other, or which single line decides if a token may peek at the future. Without that, you can't tell a GPT block from a BERT-style block or a translator's.

Where it fits: This card steps back from the head you built on the self-attention card and names its properties. It reuses the masked softmax (which picks the edges) and explains why the position table from the embeddings card was needed.

In one breath: attention is a way for a set of vectors (nodes) to send each other messages. Each node takes a weighted mix of the values of the nodes it's allowed to hear. Which nodes it may hear is set by the mask, where the keys and values come from is set by you, and nothing in the math knows about order or about the other sequences in the batch.

Predict first: take the head from the last card, delete the mask line, and feed it the 8 tokens of sequence 0 in a shuffled order (no position embeddings). Does the output change, or is it the old output with its rows shuffled the same way?

Just shuffled. The lab prints encoder output of shuffled input == shuffled output: True. Every score is a dot product between two tokens' contents, so a token's output depends only on what is in the set, not where. That's why GPT has to add a position table to x before attention can tell "dog bites man" from "man bites dog".

Note 1: nodes on a directed graph

Treat each of the T = 8 tokens in a sequence as a node. An edge from node s to node t means "t may read from s". One attention head computes, for every node t:

outt= ∑s∈N(t) weit,show loud s is to t · vss's message
t, stwo positions (nodes) in the same sequence, 0…7T = 8 N(t)the nodes with an edge into t; the mask decides this setdecoder: 0…t · encoder: all 8 weit,ssoftmax of queryt · keys over N(t); data-dependent, sums to 1 over srow t of wei vsthe value vector node s offers (head_size = 16 numbers)(B, T, 16)

The lab counts the non-zero weights per row, i.e. each node's incoming edges: decoder [1, 2, 3, 4, 5, 6, 7, 8], encoder [8, 8, 8, 8, 8, 8, 8, 8]. Node 0 in the decoder hears only itself, so its output is exactly its own value vector (checked: allclose True).

decoder row 3: 0.323 + 0.218 + 0.244 + 0.215 = 1.000 encoder row 3: 0.177 + 0.119 + 0.134 + 0.118 (past + self) ≈ 0.547 + 0.126 + 0.109 + 0.105 + 0.113 (future) ≈ 0.453

The encoder sums use the unrounded row (0.4528 on tokens 4–7). The lab already divides the scores by √16, which Karpathy introduces one chapter later (why divide by √head_size).

def head(x, mask=True):
    k, q, v = key(x), query(x), value(x)
    wei = q @ k.transpose(-2, -1) * head_size**-0.5
    if mask:   # decoder; delete this line -> encoder
        wei = wei.masked_fill(tril == 0, float('-inf'))
    wei = F.softmax(wei, dim=-1)
    return wei @ v, wei

_, wei_dec = head(x); _, wei_enc = head(x, mask=False)
print((wei_dec[0] > 0).sum(-1), (wei_enc[0] > 0).sum(-1))
perm = torch.tensor([3, 0, 7, 1, 6, 2, 5, 4])
out, _ = head(x, mask=False)
out_p, _ = head(x[:, perm], mask=False)
print(torch.allclose(out_p, out[:, perm], atol=1e-6))

How it differs from related ideas

✗ Convolution

Has space built in: a filter reads a fixed window of neighbours at fixed offsets. Attention has no window and no offsets; any node can read any node it has an edge from, weighted by content.

✗ Encoder self-attention

No mask, so node 3 puts 0.453 of its weight on tokens 4–7. Good for reading a whole sentence at once (e.g. sentiment); for next-character prediction it would see the answer.

✗ Cross-attention

Keys and values come from a second source, such as an encoder reading the French sentence in a translator. Our model has only one stream of text, so there's nothing to cross-attend to.

✓ Decoder self-attention

One source, triangular mask: each token reads itself and its past, never the future. That's what lets GPT train on every position at once and then generate one character at a time.

Is the mask the only thing that makes it "GPT"?

The mask is the only line that differs between an encoder block and a decoder block, but it isn't pure bookkeeping. It's tied to positions, so it breaks note 2: shuffle the tokens with the mask on and the output is not just shuffled (the lab's head gives allclose False), because whoever lands in slot 0 can only hear itself. GPT still adds a position table, because the mask gives only this weak sense of order.

Decoder-only isn't always the right choice. When the whole input is available up front and you want one judgement about it (classify a review, tag every word), an encoder that lets every token see every other token uses the context better. Translation in the original Transformer used both: an encoder over the source sentence and a decoder that cross-attends to it. Note 3 is about attention only: BatchNorm, from an earlier course, does mix examples across the batch.

Understand and remember

  • Scores are dot products of contents only → nothing in the formula mentions a position → attention treats its inputs as a set (shuffle in = shuffle out) → order must be injected by adding a position embedding to x
  • The mask sets which scores become −∞ → −∞ becomes weight 0 after softmax → the mask is the graph's edge list → keep the triangle and token t hears only 0…t (decoder, can generate); delete it and every token hears all (encoder, sees the answer)
  • The batched matmul (B,T,hs) @ (B,hs,T) multiplies each sequence's matrices separately → wei is (B,T,T), never (BT,BT) → sequences in a batch can't exchange information (and it costs B·T² scores, not (BT)²)
  • Queries decide who is asking, keys and values decide who is answering → take q from x but k, v from another source → cross-attention: one output per query, weights over the source's length (8 queries × 6 keys → wei (4, 8, 6))
  • detail that matters The triangular mask is tied to slot numbers → with the mask on, shuffling the tokens does not just shuffle the output (slot 0 only ever hears itself) → the mask leaks a weak sense of order, but not enough to replace position embeddings

Reference only

  • masked_fill(tril[:T, :T] == 0, float('-inf')) is gpt.py L84
  • tril is a register_buffer, not a parameter
  • the lab's weights already include the 1/√head_size scaling from the next card
  • the permutation used in the lab: [3, 0, 7, 1, 6, 2, 5, 4]

    Check

    Check
    • encoder: every token sees every other, so each token's vector uses the whole review

    • the encoder can't generate text one token at a time, but this task doesn't need that
  4. tradeoff Why does batching 4 sequences of length 8 cost 256 attention scores rather than 1,024, and what would break if it were 1,024?
    Check
    • batched matmul: 4 × (8 × 8) = 256 pairs
    • one pool of 32 tokens: 32 × 32 = 1,024 pairs
    • then unrelated sequences would read each other and the result would depend on which sequences were batched together

4 · Compare against what you already know

vs BatchNorm: standardise the preactivations: Attention never mixes examples across the batch; BatchNorm does. Which design choice causes each behaviour, and how does each fail?

Check
  • BatchNorm computes a mean and variance over the batch dimension, so every example's output depends on its batch-mates
  • attention's matmul is batched per example, so each sequence only reads itself
  • BatchNorm fails at batch size 1 and needs running statistics at inference
  • attention can't borrow information from other examples, which is what you want

vs Convolutions, and how deep-learning work actually happens: A convolution and an attention head both mix neighbouring tokens. What is fundamentally different about which neighbours they mix and with what weights?

Check
  • convolution: a fixed window at fixed offsets, weights learned but the same for every input
  • attention: any node with an edge in (set by the mask), weights recomputed from content for every input
  • convolution knows position through its offsets; attention has none and needs position embeddings
  • attention costs grow with T² per sequence; a convolution's cost grows linearly with T

vs From our decoder to nanoGPT to ChatGPT: Our model is decoder-only; the original Transformer for translation used an encoder plus a decoder with cross-attention. What does each part do there, and why doesn't our Shakespeare model need the encoder?

Check
  • encoder: unmasked self-attention over the source sentence
  • decoder: masked self-attention over the output so far, plus cross-attention with q from the decoder and k, v from the encoder
  • we generate text with no separate source to condition on, so there's nothing to cross-attend to
