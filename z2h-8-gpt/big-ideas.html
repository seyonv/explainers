The six big ideas of Let's build GPT

Big idea 1: A language model guesses the next character, and the lecture is one loss number going down

The model reads the text so far and gives each of the 65 characters a probability. It is scored by −ln of the probability it gave the true next character; sample one, append it, and it writes. Every piece added in this lecture is judged by how far it pushes the validation loss down.

“completes the sequence” · Karpathy, 0:00:00

Why it matters: −ln(1/65) = 4.17 is also your step-0 sanity check: a fresh model that starts far above it is confidently wrong. The GPT-2 course runs the same check at −ln(1/50257) = 10.82.

Big idea 2: Tokens talk by averaging their past, and a triangular matrix does it in one multiply

Give each token a weighted average of itself and the tokens before it. Put the weights in a T×T matrix with zeros above the diagonal, each row summing to 1, and wei @ x does every average for the whole batch in one call.

“information only flows from previous context” · Karpathy, 0:42:13

Why it matters: The wei @ x line survives unchanged into gpt.py's Head; only how wei is filled changes. The zeros are what let one chunk train all 8 positions at once without cheating (chunks and batches).

Big idea 3: Self-attention: the weights come from the data, as query · key

Each token emits a query (what it looks for), a key (what it has) and a value (what it will hand over). The scores q·k, scaled by 1/√head_size, masked and softmaxed, become the token's row of wei, and its output mixes the earlier tokens' values.

“x is private information to this token” · Karpathy, 1:02:00

Why it matters: This head is the one new idea on top of makemore. Splitting it into four heads of 8 took val loss from 2.41 to 2.29 with the same 7,553 parameters (one head, then many), and the √head_size keeps a wide head from starting one-hot (scaled attention).

Big idea 4: Attention is message passing on a set: the mask draws the graph, and position must be added

Nothing in q·k knows where a token sits. The mask decides who may hear whom (decoder: only the past; encoder: everyone), sequences in a batch never talk, and order only exists because a position embedding is added to x.

“they would give away the answer” · Karpathy, 1:14:14

Why it matters: The mask is the single line between an encoder and a decoder. Keeping it is what lets GPT train every position of a chunk at once and still generate left to right (five facts about attention); the GPT-2 module is this same decoder block.

Big idea 5: A Transformer block is communicate, then compute, added onto a residual stream

Multi-head attention moves information between tokens; a per-token feed-forward MLP then works on what each token gathered. Each adds its result back, x = x + f(x), so the gradient has a clean path through every block and stacking blocks finally helps.

“gradient superhighway” · Karpathy, 1:26:48

Why it matters: It is micrograd's rule that + passes the gradient through unchanged (backprop by hand), turned into an architecture. Every GPT is a stack of these blocks: 6 in gpt.py, 96 in GPT-3.

Big idea 6: Then stabilise and scale: LayerNorm and dropout let the same block grow 255× to val 1.48

LayerNorm standardises each token's vector on its own (BatchNorm turned sideways, no batch statistics); dropout zeroes 20% of activations in training so the big net can't just memorise. With both, the model grows from 42,369 to 10,788,929 parameters and val falls from 2.06 to 1.48.

“from 2.07 all the way down to 1.48” · Karpathy, 1:40:24

Why it matters: This is the model gpt.py trains: about 2¼ h on your M3 (the Colab config gets 1.83 in under 3 minutes). The GPT-2 course scales the same block again, and ChatGPT is this pretraining plus fine-tuning.

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • The model gives each of 65 characters a probability → loss is the average −ln p(true next char) → knowing nothing scores −ln(1/65) = 4.17 → every piece is kept only if it lowers val loss (bigram 2.49 → gpt.py 1.48)
  • Row t of a T×T weight matrix says how much of each token t hears → zeros above the diagonal (−inf before softmax) block the future → wei @ x mixes each token's past in one batched multiply → one chunk trains all T positions without seeing their answers
  • Each token's query dotted with earlier tokens' keys, scaled by 1/√head_size → softmax over the visible past → the weights depend on the text, not just the position → the output is a content-chosen mix of values (row 7: 0.24 on token 6 in one sequence, 0.37 on token 0 in another)
  • Each sublayer adds onto the stream, x = x + f(x) → d(out)/dx = 1 + f′(x) → gradients reach early blocks intact → stacking blocks helps instead of hurting (3 plain blocks 2.33, the same with residuals 2.16), and LayerNorm + dropout then let the block scale 255× to 1.48
  • detail that matters Multi-head attention splits the same channels into several smaller heads → the parameter count is unchanged (7,553 for 1 × 32 and 4 × 8) → more independent attention patterns per token → val 2.41 → 2.29 for free

Reference only

  • gpt.py hyperparameters: batch 64, block 256, n_embd 384, 6 heads, 6 layers, dropout 0.2, lr 3e-4, 5000 iters
  • the per-step val losses 2.41, 2.29, 2.27, 2.08, 2.06 (video: 2.4, 2.28, 2.24, 2.08, 2.06)
  • class names: Head, MultiHeadAttention, FeedFoward, Block; nanoGPT's CausalSelfAttention
  • register_buffer('tril') and the idx[:, -block_size:] crop

3 · Retrieve from memory, card closed
  1. concept Explain, without code, why a character-level model can't get much below 2.49 without some form of attention, however long you train it.
    Check
    • a bigram sees only the current character, so the best it can learn is the pair frequencies (a counted bigram scores 2.48 on val)
    • val tracks train and both flatten near 2.49: a ceiling, not overfitting
    • going lower needs information from earlier characters, which is what attention supplies
  2. mechanism Walk through how one head computes the output for token 3 of a sequence, from x to out, naming each shape for B, T, C = 4, 8, 32 and head_size 16.
    Check
    • q, k, v = three Linear(32, 16) maps of x, each (4, 8, 16)
    • scores q @ kᵀ, (4, 8, 8), times 16−0.5 = 0.25
    • row 3: positions 4–7 set to −inf, softmax over 0–3 gives weights summing to 1
    • out[3] = weighted sum of v[0…3], shape 16
  3. tradeoff Four heads of 8 beat one head of 32 at the same 7,553 parameters, and three residual blocks beat three plain ones at the same 16,865. What does each result say about where the gains come from?
    Check
    • neither gain comes from more parameters
    • heads: more independent attention patterns per token (2.41 → 2.29)
    • residuals: a trainable gradient path through depth (2.33 → 2.16)
    • architecture decides whether the parameters you have can be used
  4. tradeoff Karpathy grows the model 255× for the final run. Which additions made that pay off, and what would you expect without them?
    Check
    • LayerNorm (pre-norm) keeps each sublayer's input at a steady scale while the residual path stays a plain sum
    • dropout 0.2 holds back memorisation: 10.8M params on about 1M training characters
    • without dropout, train would run further ahead of val (the gap already showed at 2.08: train 1.98)

Why this step?

4 · Compare against what you already know

vs Counting bigrams in a 27×27 tensor: The counting bigram and this GPT both predict the next character. What is fundamentally different about how each stores what it knows, and why can only one of them use 256 characters of context?

Check
  • counts store one row per exact context: 65 rows for 1 character, 658 ≈ 3.2 × 1014 for 8
  • GPT stores shared weights that score any context by content
  • counts are exact and instant for 1 character; they fail by running out of data as context grows
  • GPT fails differently: it needs training, a GPU-sized budget, and can overfit

vs WaveNet's idea: fuse context slowly, in a tree: WaveNet fuses context in a fixed tree of pairs; attention lets each token weight every earlier token by content. Which design choice causes the difference, and when would the tree still be the better pick?

Check
  • WaveNet: who combines with whom is fixed by position (neighbouring pairs, level by level)
  • attention: the weights come from q·k, so they change with the text
  • attention scores every earlier token, T² scores per head (65,536 at block 256); the tree has locality built in
  • for short, local context on a small budget the tree (or a convolution) can be enough

vs BatchNorm: standardise the preactivations: LayerNorm here and BatchNorm in the makemore course run the same standardise-then-scale code. What changes, and how does each fail inside a text generator?

Check
  • BatchNorm averages each feature over the batch (dim 0); LayerNorm averages each token's features (dim 1)
  • BatchNorm needs running statistics for test time and couples examples in a batch
  • at batch-1 generation BatchNorm has no batch to average; LayerNorm behaves identically in training and eval

5 · Predict commit to an answer before revealing

You double gpt.py's block_size from 256 to 512 and change nothing else. Commit first: does the parameter count change, and if so by how much? And how many attention scores does one head compute per sequence?

Reveal

Only the position table grows: 256 more rows × 384 = 98,304 extra parameters, so 10,788,929 → 10,887,233. The tril mask grows too, but it is a buffer, not a parameter. Attention work grows with the square: 512² = 262,144 scores per head per sequence, 4× the 65,536 at block 256.
