Feed-forward and residual connections

Also called: position-wise feed-forward network (FFN, the block's MLP); skip connections, the residual stream or pathway. Lecture 7 · feedforward layers of transformer block · 1:24:25 · residual connections · 1:26:48

Prime · 2 minutes before you read

The problem: After attention, each token holds a weighted mix of earlier tokens' values but has no step to work on it. And when you try to add capacity by stacking more blocks, the deeper net trains worse than the shallow one.

Where it fits: The previous card got multi-head attention to val 2.29. This card finishes the Transformer block: it reuses the MLP from makemore as a per-token feed-forward layer, and reuses micrograd's rule that + passes gradients through unchanged to make depth trainable.

In one breath: attention lets each token gather information from earlier tokens; the feed-forward layer then gives each token a small neural net (Linear → ReLU → Linear) to process what it gathered, on its own. A residual connection writes each step as x = x + f(x) instead of x = f(x): the layer adds its result onto a running stream rather than replacing it, so gradients reach the early layers intact and a stack of blocks becomes trainable.

Predict first: one attention + feed-forward layer reaches val loss 2.27. Stack three of those blocks (double the parameters) with plain x = f(x). Better or worse than 2.27?

Worse: 2.33. The deeper net has 16,865 parameters against 8,609, yet it ends higher. Add x = x + … around each sublayer, with nothing else changed and the same 16,865 parameters, and it drops to 2.16. Depth only paid off once the gradient had a direct path back.

One Block: communicate, then compute

Words used above: a ReLU is max(0, z) applied to every number, the non-linearity between the two Linear layers. n_embd (32 here) is the width of each token's vector. proj is one extra nn.Linear(32, 32) that mixes the four heads' concatenated outputs before they're added back. The feed-forward layer is per token: it runs on every one of the B×T vectors separately, so no information moves between positions in it. Moving information between positions is attention's job.

Why adding helps: the gradient superhighway

out=x+f(x) ⇒ doutdx= 1the highway + f′(x)the sublayer's part
fone sublayer: attention or feed-forward (with its projection)a branch in the sketch f′(x)how much f's output moves when x nudges; can be tiny at the start of traininglocal derivative 1from the +: addition hands the gradient to both inputs unchanged (the micrograd lesson)always there

Backprop multiplies one local derivative per layer. Without the shortcut, three layers with small derivatives multiply to almost nothing. With it, each factor is 1 plus something small, so the product stays near 1. A toy from the lab (illustrative, not from the video), with f(x) = 0.01·tanh(x) at x = 2:

f′(2) = 0.01·(1 − tanh²2) = 0.01 × 0.07065 = 0.0007065 plain f(f(f(x))) 0.0007065 × 0.0099991 × 0.0100000 = 7.064e-08 residual x + f(x), ×3 1.0007065 × 1.0006935 × 1.0006807 = 1.0021

The second and third factors differ from the first because each layer sees a different input (computed; the lab prints 7.064e-08 and 1.0021). This is what Karpathy means by blocks that "come online over time": at first the stream passes straight through, and each branch learns to contribute.

class FeedFoward(nn.Module):       # Karpathy's spelling
    def __init__(self, n_embd):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_embd, 4 * n_embd),
            nn.ReLU(),
            nn.Linear(4 * n_embd, n_embd),  # projection back
        )
    def forward(self, x):
        return self.net(x)            # per token: (B,T,C)
class Block(nn.Module):
    def __init__(self, n_embd, n_head):
        super().__init__()
        head_size = n_embd // n_head
        self.sa = MultiHeadAttention(n_head, head_size)
        self.ffwd = FeedFoward(n_embd)
    def forward(self, x):
        x = x + self.sa(x)      # communicate
        x = x + self.ffwd(x)    # compute
        return x

Why it beats the alternatives

✗ Attention only

Each token collects a weighted mix of values and goes straight to lm_head, with no step to work on what it collected. Val 2.2884.

✗ Stacking plain blocks

x = f(x) three times: the gradient to the first block is a product of every layer's local derivative. Double the parameters, and val gets worse: 2.3318.

✗ Feed-forward on its own

Three residual FFN blocks with no attention (my extra run, 29,537 params) reach only 2.5111. Each token sees just itself and its position, so it's back to bigram level (2.49).

✓ Blocks on a residual stream

Attention to communicate, a 4× feed-forward to compute, each added back onto x through a projection. Val 2.0801 with three blocks.

Does depth now come for free?

No. Residuals make a deep stack trainable; they don't stop it overfitting. In the last run train loss (1.9845) is already below val (2.0801), and the gap grows with size. That's why the next card adds LayerNorm and dropout before scaling to six layers. Also, the 2.16 → 2.08 step bundles two changes (projections and the 4× inner width), which the video doesn't separate. The 4× comes from the Transformer paper (512 → 2048).

A residual needs f(x) to have the same shape as x. That's one job of the projection: it maps whatever a sublayer produces back to n_embd. When shapes must change between stages, as in image ResNets that shrink the image, the shortcut itself needs a learned layer and is no longer a free identity path.

Understand and remember

  • Attention only mixes values across positions → each token ends with a weighted average but no per-token processing → a per-token MLP (feed-forward) after it lets every token transform what it gathered → val 2.29 → 2.27 (video 2.24)
  • Plain stack x = f(f(f(x))) → backprop multiplies one local derivative per layer → small factors shrink the gradient to early layers (toy: 7.06e-08) → deeper net trains worse (2.33 vs 2.27)
  • Residual x = x + f(x) → d(out)/dx = 1 + f′(x) → the product over layers stays near 1 (toy: 1.0021) → gradients reach every block, and the same 16,865-param stack drops to 2.16
  • Adding requires matching shapes → the projection maps each sublayer's output back to n_embd → the residual stream keeps width n_embd through every block, so blocks can be stacked freely
  • detail that matters The feed-forward runs on each of the B×T vectors separately → it adds compute but moves no information between positions → a stack of feed-forward blocks without attention is stuck at bigram level (2.51)
  • detail that matters The residual makes the net trainable, not regularised → train loss runs ahead of val (1.98 vs 2.08) → the next card needs LayerNorm and dropout before scaling up

Reference only

  • Karpathy's class name FeedFoward (sic) and Block(n_embd, n_head)
  • inner width 4 × n_embd (32 → 128 → 32 here; 512 → 2048 in the Transformer paper)
  • proj = nn.Linear(head_size * num_heads, n_embd) after the head concat
  • param counts: 8,609 / 16,865 / 41,921, and 12,480 per final Block
  • lab settings: batch 32, block 8, lr 1e-3, 5000 iters, seed 1337

vs One head, then many heads: Multi-head attention and the feed-forward layer both add parameters. What is fundamentally different about which numbers each one lets interact, and when would adding more of one not help without the other?

Check
  • heads mix information across positions (T axis) using data-dependent weights
  • the feed-forward mixes channels within a single position (C axis) with fixed weights

vs Real nets: the Linear → BatchNorm → nonlinearity motif: The makemore BatchNorm course fought deep-net training with careful init and normalisation. How is a residual connection a different kind of fix, and how does each one fail?

Check
  • init and BatchNorm keep each layer's activations and gradients well scaled
  • a residual adds a gradient path that skips the layer's derivative altogether
  • careful init can still leave a long product of factors; residuals need matching shapes and don't regularise
  • real nets use both: gpt.py has residuals and LayerNorm
