What we're building: a character-level GPT

In one breath: a language model reads some text and gives a probability to every symbol that could come next. Pick one, append it, repeat, and it writes. This lecture builds a small GPT whose symbols are single characters, trains it on 1,115,394 characters of Shakespeare, and gets it to write new, fake Shakespeare. ChatGPT runs the same loop, only much bigger and over word pieces.

Predict first: the file holds 1,115,394 characters of Shakespeare. How many different characters does it use, and how many of them are digits?

65 different characters, and exactly one digit: 3. It appears 27 times, all in play titles like "3 KING HENRY VI". The other 64 are the 52 letters, space, newline and 10 punctuation marks. The rarest is $, which appears once. So the model only ever picks from 65 options.

The loop we're building

Two words used above: the context is the text the model reads before predicting, and to sample means drawing one character at random, with each character's chance set by its probability. Because the draw is random, the same prompt gives a different continuation each run.

The data: tiny Shakespeare

One plain-text file, input.txt, with a selection of Shakespeare's plays joined together: 1,115,394 characters (also 1,115,394 bytes, since it's all plain ASCII), 40,000 lines, 202,651 words. What "good" means: the loss ladder

The model is scored by its loss: for each position, take the probability it gave to the character that really came next, take −ln of it, and average. Lower is better. This is the negative log likelihood (cross-entropy) from the makemore lectures.

Why characters, for this lecture

✗ Whole words as symbols

The file has 25,670 different whitespace-separated words (punctuation attached), so the model would score 25,670 options per step instead of 65, and a word it never saw has no symbol at all.

✗ GPT-2's sub-word tokens

What real GPTs use: the text shrinks to 338,025 tokens, 3.3× shorter. But the vocabulary is 50,257, huge for 1 MB of data, and building a tokenizer is a lecture of its own (the tokenizer course).

✗ A count table over contexts

The makemore approach. One character of context needs 65 × 65 = 4,225 counts; eight characters need 658 ≈ 3.2 × 1014 rows, far more than a 1.1M-character file can fill.

✓ Characters, plus a Transformer

65 symbols, nothing to build before training, and every string can be written. The Transformer reads a long context with learned weights instead of a table. The cost: sequences are 3.3× longer than with GPT-2 tokens.

Is this a tiny ChatGPT?

Only the first half of one. Our model is pretrained: it learns to continue text and nothing else. Ask it a question and it will just write more Shakespeare-shaped text. ChatGPT starts from the same kind of next-token model, with sub-word tokens and far more parameters and data, and then gets a second stage of fine-tuning to act as an assistant (the last card of this course).

Characters are a teaching choice, not a recommendation. They keep the vocabulary tiny and skip the tokenizer, but they spend 3.3× more steps on the same text, so real models use sub-word tokens. If you just want to generate text, use a pretrained model; this course exists so you can build and understand every line of one.

Understand and remember

  • The model outputs a probability for each of the 65 characters → we sample one and append it → the new text becomes the next context → repeating this writes text of any length (and differs each run, because the draw is random)
  • Loss is the average −ln of the probability given to the true next character → a model that knows nothing gives 1/65 everywhere → loss −ln(1/65) = 4.17 is the floor to beat → every piece added in this course is judged by how far it pushes val loss toward 1.48
  • Using more context lowers the loss: no context (frequencies only) 3.35 → one previous character 2.49 → 256 characters through a Transformer 1.48 → the whole lecture is about letting the model use more of the past, well
  • Count tables need one row per possible context → 658 ≈ 3.2 × 1014 rows for 8 characters, far more than 1.1M characters can fill → learned weights that share structure across contexts are the only way to use long context
  • detail that matters Characters give a 65-symbol vocabulary but 3.3× longer sequences than GPT-2 tokens (1,115,394 vs 338,025) → cheap embedding and output layers, but more steps per sentence → real models pick sub-word tokens

Reference only

  • tiny Shakespeare input.txt: 1,115,394 characters, 40,000 lines, 202,651 whitespace-split words
  • chars = sorted(list(set(text))), vocab_size = len(chars) = 65; \n sorts first, space second
  • the only digit is 3 (27 times); the rarest character is $ (once)
  • finished gpt.py: 10,788,929 parameters, val 1.48 (video, A100)

5 · Predict commit to an answer before revealing

The frequency-only model scores 3.35 on validation using counts from the training split. Suppose instead you counted the frequencies on the validation text itself and then scored the validation text. Commit to a guess: higher, lower or the same, and roughly by how much?

Reveal

Slightly lower, but only a little: 3.3373 vs 3.3473. Counting on the text you're scored on is cheating (it has peeked at the answers), yet with no context there's so little to overfit that the gain is tiny. Cheating like this becomes a real problem once a model has millions of parameters and can memorise; that's why the next card holds back 10% for validation.
