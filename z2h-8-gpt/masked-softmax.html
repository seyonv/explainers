Masked softmax: −∞ means no looking ahead

Also called: causal masking, a causal (look-ahead) attention mask, version 3 of the averaging trick. Lecture 7 · version 3: adding softmax · 0:54:42

Prime · 2 minutes before you read

The problem: The tril-divided-by-row-sum matrix averages the past correctly, but its weights are built from ones and zeros. There is nowhere to put a learned score, and a naive way of adding scores lets tokens peek at the characters they are supposed to predict.

Where it fits: It rewrites version 2 from the tril-matmul card as scores → mask → softmax. Same matrix today; the next cards fill the scores with query·key dot products.

In one breath: start from a table of scores (all zeros for now), overwrite every score that points at a later token with −∞, then apply softmax to each row. Because e−∞ = 0, the future gets exactly zero weight, and each row still sums to 1. With all-zero scores this rebuilds the running-average matrix from the last card. The difference is that the zeros can now be replaced by any scores, and the mask keeps working.

Predict first: in wei = torch.zeros((T,T)), replace every 0 with 7 before masking. Does row 2 still come out as 1/3, 1/3, 1/3?

Yes, it's unchanged (the whole 8×8 matrix is allclose to the zeros version). Softmax only cares about how scores in a row differ from each other: e7 / (3·e7) = 1/3, just as e0 / (3·e0) = 1/3. Equal scores always mean equal weights. So the zeros aren't special; they are "no preference yet", which a learned score will later replace.

Without the mask, token 1 puts 0.0806 of its attention on tokens 2 and 3. Whatever the future scores are, the masked row doesn't move. Computed with F.softmax in a scratch check.

This matters most in training. One chunk of 9 characters gives 8 training examples at once (batches of chunks), all computed in a single pass. For position t, the target is the character at t + 1, which is sitting in the same input. Without the mask, position t could read its own answer. The loss would look great, and generation, where the next character doesn't exist yet, would fall apart.

B,T,C = 4,8,2
x = torch.randn(B,T,C)

tril = torch.tril(torch.ones(T, T))
wei = torch.zeros((T,T))
wei = wei.masked_fill(tril == 0, float('-inf'))

print(wei[:4])
print(torch.allclose(xbow2, xbow3))

Why it beats the alternatives

✗ Version 2: tril divided by row sums

Gives the right averages, but the weights are built from ones and zeros. There's no slot for a score, so every row stays a plain 1/(t+1) average.

✗ Softmax first, then zero the future

The future is cut off, but the leftovers aren't renormalised: row 1 sums to 0.1096 + 0.8098 = 0.9194 and row 0 to 0.25. The outputs shrink by a different amount at each position.

✗ Multiply the scores by tril

Sets future scores to 0, but 0 isn't "nothing": e0 = 1. Row 1 comes out 0.1096, 0.8098, 0.0403, 0.0403, the same leak as having no mask at all.

✓ masked_fill(−∞), then softmax

e−∞ is exactly 0, so masked tokens drop out of both the top and the bottom of the fraction. Rows sum to 1, the future gets nothing whatever its score, and any learned score can go in the visible cells.

Is "the past can't talk" right? And do you always mask?

Around 0:57:00 Karpathy says tokens "from the past" can't communicate. The video's description corrects it: tokens from the future can't talk to the present. Row t sees 0…t, never t + 1 onward.

The mask belongs to decoder blocks, which generate text left to right. An encoder block (for example, reading a whole sentence to classify its sentiment) deletes the masked_fill line so every token sees every other (five facts about attention). Two edge cases are worth knowing. A row where every entry is masked becomes NaN, because softmax computes 0/0. The causal mask can't do this, since the diagonal is always visible, but padding masks can. Some code uses a large negative number such as −1e9 instead of −∞. In float32 it gives the same weights here, but in float16 (largest value 65,504) −1e9 overflows to −∞ anyway. nanoGPT's fast path hands the whole thing to F.scaled_dot_product_attention(…, is_causal=True), which applies the same mask inside one fused kernel.

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • Future scores set to −∞ → exp(−∞) = 0 → they vanish from both the numerator and the row-sum denominator → the visible weights are renormalised to sum to 1 and the future gets exactly 0, whatever its score
  • Softmax only depends on differences within a row → all-equal scores (zeros, or sevens) give a uniform 1/(t+1) average → the zero table is a neutral placeholder that learned affinities can later replace without changing any code
  • One chunk trains every position at once and the target for position t is the input at t + 1 → without the mask, row t could put weight on its own answer → training loss is flattering and generation, where the future does not exist yet, breaks
  • Masking by other means (zeroing scores, or zeroing weights after softmax) → either e0 = 1 still leaks weight to the future, or rows stop summing to 1 → only −∞ before softmax gives both properties
  • detail that matters A row where every entry is masked → softmax computes 0/0 → NaN that spreads through the whole network; the causal mask can't cause this because the diagonal is always visible, but padding masks can

Reference only

  • torch.tril(torch.ones(T, T)) and the tril == 0 test
  • F.softmax(wei, dim=-1)
  • register_buffer('tril', …) in gpt.py's Head
  • F.scaled_dot_product_attention(…, is_causal=True) as the fused equivalent
  • −1e9 as a substitute for −∞ (float16 max is 65,504)

5 · Predict commit to an answer before revealing

You add a second mask that hides padding tokens, and it leaves one row with every entry at −∞, the diagonal included. What does softmax output for that row, and what happens to the loss?

Reveal

A padding row now has every entry at −∞, so softmax computes 0/0 and returns NaN for the whole row. The NaN flows through wei @ x into later layers and makes the loss NaN. The causal mask alone never does this because the diagonal is always visible. Real code avoids it by keeping at least one visible entry per row or by ignoring padded positions in the loss.
