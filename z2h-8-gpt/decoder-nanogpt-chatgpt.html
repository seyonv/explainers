In one breath: the model we built is a decoder-only Transformer: every block's attention is masked so a token only sees the past, and nothing else feeds in, which is all you need to continue text. nanoGPT is the same model with all heads computed in one batched tensor operation. GPT-3 is the same architecture about 16,000× bigger, trained on about 900,000× more tokens. ChatGPT starts from such a pretrained model and is then fine-tuned to answer questions instead of just continuing documents.

Predict first: nanoGPT replaces our six Head objects plus MultiHeadAttention (n_embd 384, 6 heads of 64) with one class holding a single Linear(384, 1152). More parameters, fewer, or the same? And once you copy the weights across, do the outputs match?

The same: 590,208 each, and the outputs match exactly (max difference 0.00e+00). Each head had three Linear(384, 64) layers, so 18 small matrices of 384 × 64. Stacked on top of each other they are one 384 × 1152 matrix: 18 × 24,576 = 442,368 either way. Both versions then share the same output projection (147,840). Batching changes how the work is scheduled, not the maths.

Three kinds of Transformer, and which one we built

"Attention Is All You Need" was a translation paper, so it has two halves. The encoder reads the whole French sentence with no mask: every token may look at every other, because the full input is known in advance. The decoder writes the English one token at a time, starting from a special <START> token and stopping when it emits <END>. Its own self-attention is masked (the tril from earlier cards), and each block adds cross-attention: queries come from the English tokens, while keys and values come from the encoder's output. That is how the translation stays tied to the French.

We generate Shakespeare from nothing, so there's no second text to condition on. We keep only the decoder and drop cross-attention. Karpathy's point at 1:42:39: this is exactly the setup GPT uses. The third option, encoder-only (no mask anywhere), suits reading a whole text at once, for example to classify it. It can't generate left to right, because during training every position could already see the answer.

nanoGPT: every head at once

Our MultiHeadAttention loops over a Python list of heads and concatenates their outputs. nanoGPT's CausalSelfAttention makes q, k and v for all heads with one matmul, then treats the head as another batch dimension. Trace one batch of 4 sequences of 32 characters through it (B = batch, T = positions, C = n_embd = 384, nh = number of heads = 6, hs = head size = 384 / 6 = 64):

x (4, 32, 384) B, T, C c_attn(x) (4, 32, 1152) q, k, v for every head: 3 × 384 .split(384, dim=2) 3 × (4, 32, 384) q | k | v .view(4, 32, 6, 64) (4, 32, 6, 64) cut the 384 channels into 6 heads of 64 .transpose(1, 2) (4, 6, 32, 64) B, nh, T, hs: heads now sit next to batch q @ k.transpose(-2,-1) (4, 6, 32, 32) one T × T score table per head × 1/√64 = 0.125, mask with tril, softmax over the last dim att @ v (4, 6, 32, 64) .transpose(1,2).view(...) (4, 32, 384) heads side by side again (= our torch.cat) c_proj (4, 32, 384) same shape as x, ready for the residual add

Every matmul above runs over the leading dimensions (4 × 6 = 24 small attention problems) in one call. PyTorch's @ treats every dimension except the last two as a batch dimension.

ours 6 heads × 3 × (384 × 64) = 442,368 + proj 384·384 + 384 = 147,840 = 590,208 nanoGPT c_attn 384 × 1152 = 442,368 + c_proj 147,840 = 590,208

Other differences you'll meet reading model.py. nanoGPT's MLP uses GELU instead of ReLU, because GPT-2 did and nanoGPT wants to load OpenAI's checkpoints. GELU is a smooth ReLU that lets small negatives through: the lab gives GELU(−1) = −0.1587 and GELU(0.5) = 0.3457, where ReLU gives 0 and 0.5. Its flash path, F.scaled_dot_product_attention(q, k, v, is_causal=True), does the scores, mask, softmax and @ v in one fused call, and the lab confirms it gives the same answer. The newer model.py also ties the token embedding to lm_head and pads the GPT-2 vocabulary of 50,257 up to 50,304. train.py adds checkpointing, learning-rate decay, torch.compile and multi-GPU training around the same loop.

▶ Build itruns on your M3 · under 2 s

When: pause the video at 1:46:22, before the walkthrough, and try exercise EX1 yourself: one class that runs all heads in parallel, with the heads as a batch dimension. Add it to your gpt.py, which already has n_embd = 384, n_head = 6 and block_size = 256.

class CausalSelfAttention(nn.Module):
    def __init__(self):
        super().__init__()
        # every head's query, key and value in one Linear: 384 -> 1152
        self.c_attn = nn.Linear(n_embd, 3 * n_embd, bias=False)
        self.c_proj = nn.Linear(n_embd, n_embd)
        tril = torch.tril(torch.ones(block_size, block_size))
        tril = tril.view(1, 1, block_size, block_size)  # room for B, nh
        self.register_buffer('bias', tril)
    def forward(self, x):
        B, T, C = x.size()
        hs = C // n_head                                # 64
        q, k, v = self.c_attn(x).split(n_embd, dim=2)   # 3 x (B,T,C)
        q = q.view(B, T, n_head, hs).transpose(1, 2)    # (B,nh,T,hs)
        k = k.view(B, T, n_head, hs).transpose(1, 2)
        v = v.view(B, T, n_head, hs).transpose(1, 2)
        att = (q @ k.transpose(-2, -1)) * hs**-0.5      # (B,nh,T,T)
        att = att.masked_fill(self.bias[:, :, :T, :T] == 0,
                              float('-inf'))
        att = F.softmax(att, dim=-1)
        y = att @ v                                     # (B,nh,T,hs)
        y = y.transpose(1, 2).contiguous().view(B, T, C)
        return self.c_proj(y)

bias=False matches your heads, whose q, k, v layers have no bias; nanoGPT's default config keeps biases, which adds 3 × 384 = 1,152 parameters. Now check it against your old heads. Copy their weights in, feed both the same input, and compare:

torch.manual_seed(1337)
mha = MultiHeadAttention(n_head, n_embd // n_head).eval()  # yours
csa = CausalSelfAttention()
W = lambda nm: torch.cat([getattr(h, nm).weight for h in mha.heads])
with torch.no_grad():   # all q rows, then all k rows, then all v rows
    qkv = torch.cat([W('query'), W('key'), W('value')])
    csa.c_attn.weight.copy_(qkv)                   # (1152, 384)
    csa.c_proj.load_state_dict(mha.proj.state_dict())
x = torch.randn(4, 32, n_embd)
a, b = mha(x), csa(x)
count = lambda m: sum(p.numel() for p in m.parameters())
print(count(mha), count(csa))
print(torch.allclose(a, b, atol=1e-5), (a - b).abs().max().item())

From a document completer to an assistant

Pretraining alone gives a model that continues whatever document it's handed. Ask it a question and it may continue with more questions, because on the internet questions are often followed by more questions. Karpathy (1:48:53) walks through the fine-tuning stages OpenAI described in its ChatGPT blog post:

StageWhat happensChanges the weights?In nanoGPT?
1. PretrainingPredict the next token over a huge text corpus. This is what we did, on 1.1 MB (338,025 GPT-2 tokens) instead of 300 billion tokens.yes, all of themyes
2. Supervised fine-tuning (SFT)Keep training on documents shaped like "question, then good answer". Karpathy guesses "maybe thousands" of examples, a tiny amount next to stage 1.yes, same lossno
3. Reward modelThe model writes several answers; people rank them; a separate network learns to score answers the way the raters would.trains a second modelno
4. PPO (RLHF)Sample answers, score them with the reward model, and nudge the weights toward higher scores with a policy-gradient reinforcement-learning method called PPO.yes, toward the rewardno

RLHF = reinforcement learning from human feedback (stages 3 and 4). nanoGPT covers stage 1 only; OpenAI hasn't released the data for stages 2 and 3.

How it differs from related ideas

✗ A loop over Head modules

What we built. Correct, and it computes exactly the same numbers, but it issues six separate small matmuls per attention layer and then glues them together, instead of one call over a (B, nh, T, hs) tensor.

✗ One wide head

Same parameter count, but one attention pattern per token instead of six. On the heads card, 4 × 8 heads reached val 2.29 against 2.41 for one 32-wide head with the same 7,553 parameters.

✗ Encoder or encoder-decoder

No mask lets each token see the future, which is fine for reading a finished input and useless for predicting the next token. Encoder-decoder earns its keep only when there's a separate source text, such as translation.

✓ Batched causal self-attention

Masked, decoder-only, all heads in one tensor op, and optionally one fused flash kernel. Mathematically our model, organised for a GPU. It's the block GPT-2 uses, which is why nanoGPT can load GPT-2's weights.

So is ChatGPT just a bigger version of this?

Architecturally, mostly yes: Karpathy calls GPT-3 "basically identical" to what we wrote (1:54:32). The gaps are elsewhere. It reads sub-word tokens rather than characters (the tokenizer lecture comes next). Its training run is far beyond a laptop. And stages 2 to 4 above aren't a change to the network at all: they are more training, on different data and with a different objective.

Decoder-only isn't always the right shape. When the input is complete before the output starts (classifying a review, or embedding a document for search), an unmasked encoder can use context from both sides of every token, which a masked decoder never sees. Batched heads also aren't a free win on a CPU for tiny models: the gain is in keeping a GPU busy with a few big calls. On your M3 the whole lab, both versions included, runs in under 2 s.

Understand and remember

  • No second text to condition on → nothing for cross-attention to read → drop the encoder and cross-attention → a stack of masked self-attention + feed-forward blocks = decoder-only, exactly GPT's shape
  • Each head's q, k, v is a 384 → 64 linear map → stacking all of them row-wise is one 384 → 1152 map with the same 442,368 weights → view(B, T, nh, hs).transpose(1, 2) makes heads a batch dimension → one batched @ computes every head at once, identical to our loop and cat
  • Pretraining on internet text → the model learns to continue documents, not to answer → SFT on question/answer documents, then a reward model trained from human rankings, then PPO against it → same network, different data and objective → an assistant
  • detail that matters The row order inside c_attn's weight must match the order of .split (q, then k, then v) → swapping q and k rows gives the transposed score table, and the outputs no longer match
  • detail that matters The flash path fuses scores, mask, softmax and @ v into one call → the T × T attention matrix never has to be stored in full → the same maths with far less memory traffic on a GPU

Reference only

  • nanoGPT names: c_attn, c_proj, the buffer called bias, attn_dropout, resid_dropout
  • F.scaled_dot_product_attention(q, k, v, is_causal=True) signature
  • GELU values: GELU(−1) = −0.1587, GELU(0.5) = 0.3457
  • GPT-3 175B shape: 96 layers, d_model 12,288, 96 heads of 128, context 2,048
  • nanoGPT's padded vocab 50,304 and weight tying of wte with lm_head
