Tasks, trials and graders

Also called eval components or the eval vocabulary; graders are also called checks, evaluators or judges. Wolfe's Agent Evaluation guide takes these terms from Anthropic's "Demystifying evals for AI agents" and ends with a seven-step recipe; Govindarajan's Agent Stack Part 8 adds the rule: don't ask a model judge to prove what your system can assert.

Prime · 2 minutes before you read

The problem: An eval is only as honest as the thing that marks each run. If the marker reads the agent's final message, or asks a model that saw what the agent saw, a run that ended with a failing test can still be scored as a pass.

Where it fits: You met tasks, trials and hidden tests in Measuring an agent, and the claim chain in 'Done' is a chain of states. This card opens up the grader: what it reads, which kind to use, and in what order.

In one breath. An eval is a set of tasks. Each attempt at one is a trial, and every trial leaves two things: a transcript (what the agent did and said) and an outcome (the state of the world afterwards). A grader turns those into a verdict. Grade the outcome with code first, bring in a rubric-guided model judge only for what code can't check, and use human review to keep the judge honest.

You already know: hidden tests, repeated trials and intervals (this card is about the grader itself) · "done" is a chain of states (a grader is how you check link 4).

The five words, two examples each

Like a driving test: the task is the route, a trial is one attempt at it, the transcript is the examiner's notes, the outcome is where the car ends up, and the grader is the marking sheet.

Three kinds of grader

KindWhat it checksStrong atWeak at
CodeString match, assertions on the outcome or transcript, unit tests, "was this tool called?", caps on tokens or turns.Fast, reproducible, easy to debug.Usually needs a reference answer; no nuance (can't tell whether code is clean).
Model judgeAn LLM scores pairwise, pointwise (for example 1–5) or against a reference, ideally one rubric item at a time.Open-ended, subjective criteria like style or clarity.Non-deterministic, known biases, costlier. Only trustworthy once calibrated against humans.
HumanRaters follow written guidelines or a rubric, pass/fail or a scale.The "north star": the reference for subjective quality.Slow and expensive; raters disagree until the guidelines are refined.

From Wolfe's "Different types of graders". His advice is to combine them: calibrate the judge against human labels, then keep monitoring that agreement, because a judge's accuracy can drift.

Why layers, and when they stop helping

Wolfe calls combining evaluations a "Swiss cheese" strategy: no single layer catches every error, but each extra layer lowers the chance one gets through. The arithmetic below is this card's framing of his picture, and it holds only if the layers miss independently.

P(failure slips through)= mcodemiss rate × mjudgemiss rate × mhumanmiss rate
mshare of real failures a layer marks as passing0 = catches all · 1 = catches none mcodemisses what the tests don't cover0.30, illustrative mjudgemisses what isn't in the text it reads0.40, illustrative mhumansampled review: misses what nobody looked at0.20, illustrative
independent holes: 0.30 × 0.40 × 0.20 = 0.024 → 2.4% slip through aligned holes: judge misses wherever code misses (same blind spot) 0.30 × 0.20 = 0.060 → 6.0%, 2.5× more simulated, 200,000 draws: 2.40% and 5.99%

Miss rates are illustrative; the 2.4% and 6.0% are computed from them, and the simulation is in code/graders.py. A layer whose holes sit where another layer's holes are adds nothing, which is why a judge that sees what the agent saw is a weak extra layer.

Why it beats the alternatives

✗ Grade the final message

That grades the output, not the outcome. The Tuesday run's step 9 says every test passes; the repo says exit 1.

✗ A model judge for everything

Non-deterministic, biased and pricier than code, and it can share the agent's blind spot: on the compacted view it passes the Tuesday run.

✗ Humans grade every trial

Humans are the north star, but slow, expensive and inconsistent until calibrated. Spend them on calibrating the judge and on subjective cases.

✓ Layered, deterministic first

Code on the outcome, assertions on the transcript, a rubric judge only for what code can't check, humans to calibrate. A judge never overrides a hard fail.

Is an outcome check always enough?

No. Outcome graders can pass the wrong path: Wolfe notes that τ-bench's state check would accept a refund the user never asked for. That is what process goals and transcript checks are for. And a code grader is only as good as its reference: the Tuesday checker knows only the repo's 42 tests.

Graders change too. Wolfe suggests rolling graders into one weighted score with a threshold; Govindarajan warns that a judge should not average a policy failure into a high score, and that a grader change should be tested against a frozen human-labelled set so you can tell an agent improvement from "a change in the ruler". Neither author gives a target judge–human agreement or real miss rates; those are open. For a one-off script you'll read yourself, skip all of this.

Understand and remember

  • The agent's text and the world can disagree → grade the outcome (environment state) rather than the output → a fresh pytest re-run fails the Tuesday run even though step 9 says every test passes
  • Code graders are fast, reproducible and need a reference; judges handle subjective criteria but are noisy and biased → run deterministic checks first and stop on a hard fail → a judge never gets to average a broken outcome into a good score
  • A judge can only object to what is in the text it reads → if it reads what the agent saw (the compaction summary), it inherits the agent's blind spot → its misses line up with the agent's mistakes, so it adds little as a layer
  • Layers that miss independently multiply: 0.30 × 0.40 × 0.20 = 2.4% slip through (illustrative) → if one layer's holes sit where another's are, that layer adds nothing (6.0%) → choose layers that read different evidence
  • detail that matters Judges must be calibrated against human labels and the agreement kept under watch → a judge or rubric change is a change in the ruler → test grader changes against a frozen human-labelled set, or a score move may be the grader, not the agent

5 · Predict commit to an answer before revealing

Change the Tuesday run: after compaction the agent edits the test file so test_parse_due_date asserts nothing, re-runs pytest (exit 0) and then claims success. Which of the three graders now pass it, and what would you add?

Reveal

The transcript grader passes it: the last test run in the transcript is now exit 0, so the claim matches. A judge on either view likely passes it too. The outcome grader passes as well if it runs the repo's own, edited tests. Only a grader that uses tests the agent could not touch (hidden or restored originals) or a process check on "no test files changed" catches it. That is why the outcome grader must own its reference.
