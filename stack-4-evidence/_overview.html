Evidence that can stop a release

In one breath

An agent's own report is not evidence. A trace says what happened, an audit record says under whose authority, an eval judges whether it was acceptable, and feedback only counts once an owner turns it into a regression case that a release gate runs. For that gate to be worth trusting, four things must hold in order: the grader reads the world, not the agent's message; the number counts what users live with (every run, per task); its error bar treats the task, not the trial, as the unit; and the eval has enough tasks to see the change you care about. Get the first one wrong and the other three just make a wrong number look precise.

You already know: measuring an agent (hidden tests, repeats, a by-task interval) · 'done' is a chain of states (the Tuesday run's false success claim).

The words people use

Output vs outcome

The output is what the agent said; the outcome is the state of the world after the trial. Graders belong on the outcome. Also: transcript, trace or trajectory for the record of the run.

pass@k vs pass^k vs avg@k

At least one of k trials passes; all k pass; the mean pass rate. Most benchmarks report the first or last; a user who meets the agent every time lives with the middle one.

Clustered SE, paired difference, power

A bar that counts tasks, not trials; a bar on the gap computed task by task; the chance an eval detects a change that is really there. MDE (minimum detectable effect) is power solved for the change.

✓ Release gate

The one place evidence changes what ships: owned regression cases, per-slice floors and hard blockers that no judge or average can override. Govindarajan's line: a dashboard informs someone; a gate changes what ships.

When this advice doesn't apply

Not every agent needs the whole loop. An agent that only drafts replies may need nothing beyond traces; audit records start to matter once it sends, refunds, writes files or deploys. For a one-off script you'll read yourself, skip the graders and gates entirely.

pass@k is sometimes the honest number. When a verifier keeps the first passing attempt, or best-of-n picks a winner, users get the best of k, so report pass@k (and say which k). For a huge effect, such as 20% to 80%, every honest bar gives the same verdict; the statistics matter for gains of a few points. Power analysis is the wrong tool when you aren't testing a change at all: size a one-off estimate by the interval width you want.

Know what the numbers are. Every figure above comes from arithmetic, a simulation, or the illustrative Tuesday run, not from measuring a real agent. Govindarajan reports no data on how much gates cut repeat failures, neither author gives a target judge–human agreement, and at 30 tasks even the honest bars run a little narrow (93.5%, not 95%). Those gaps are on the open questions card.

Understand and remember

  • Every later check computes on the grader's verdicts → a grader that reads the agent's summary passes the Tuesday run's false claim → pass^k, a clustered bar and 136 tasks then measure the wrong thing precisely → fix the grader first
  • Users meet the agent on every run, and failures cluster on hard tasks → report pass^k counted per task (C(c,k) ÷ C(n,k)), averaged over tasks → pass@k and the plug-in both flatter reliability
  • Trials of one task share its difficulty → the task is the unit for error bars and for sample size → cluster and pair by task, and add tasks, not repeats, when the bar is too wide
  • A number changes nothing until someone acts on it → an owner, a regression case and a per-slice gate with hard blockers → otherwise the same failure ships again after the next model, prompt or grader change

    Check

    Check

Why this step?

5 · Predict commit to an answer before revealing

Suppose the grader's mistakes line up with the agent's: the judge passes every false claim. Before revealing, which of checks 2 to 5 would notice anything wrong?

Reveal

None of them. pass^k would read higher than the truth, the clustered and paired bars would be tight around the wrong rate, a power analysis would happily size the experiment, and the gate would ship. The statistics only see disagreement between trials, not between the verdict and the world. That is why the overview ranks the grader first and why the open-questions card's top item asks what a judge sees.
