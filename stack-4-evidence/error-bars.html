Error bars that don't lie

Also called standard errors, clustered (cluster-robust) standard errors, and paired differences. Evan Miller's "Adding Error Bars to Evals" (arXiv 2411.00640), as walked through by Cameron Wolfe, applied here to an agent eval where every task is run 3 times.

Prime · 2 minutes before you read

The problem: You run an agent 3 times on each of 30 tasks, get 90 pass/fail scores, and put the textbook error bar on the pass rate. The bar comes out too short, because 3 trials of one task mostly agree. And when you compare two agents with two separate bars, a real gain disappears into the overlap. Either way you end up trusting noise or missing real progress.

Where it fits: Second statistics card of the evidence course. Measuring an agent gave you a by-task interval for one agent; pass@k vs pass^k showed what repeats measure. This card says why grouping by task is the honest bar, and how to compare two agents on the same tasks.

In one breath. An error bar says how far your pass rate would move if you reran the eval on fresh tasks. Counting every trial as an independent coin flip makes the bar too short, because three trials of one task mostly agree, so group them by task. And when two agents ran the same tasks, measure the gap task by task: shared task difficulty cancels out, so the bar on the gap gets shorter.

You already know: tasks × trials grids and the by-task interval. This card says why the by-task version is the honest one, and how to compare two agents with it.

Three error bars, three ideas

An analogy first: asking 3 people from each of 30 households gives you 90 answers, but nowhere near 90 independent opinions.

If two trials of a task both sit on the same side of the mean, their product is positive and the bar grows. If trials inside a cluster are unrelated, the extra term averages out to zero and you are back to the plain SE. If they always agree, each task counts as a single observation (Miller, via Wolfe).

Var(xB−xA)= Var(xA)+ Var(xB) − 2Cov(xA,xB)removed by pairing

Pairing removed 63% of the variance here. Miller's point, as Wolfe quotes it: scores on the same questions tend to correlate even across unrelated models, so pairing is a "free" reduction.

Which bar is honest? Rerun the eval 20,000 times

Because the simulation knows the true answer, we can redraw 30 fresh tasks and fresh trials 20,000 times and count how often each 95% bar actually contains the truth. An honest bar does so about 95% of the time.

"Real spread" is the standard deviation of the 20,000 estimates; "gain called real" means the 95% bar excluded zero. The plain bar is about 25% too short (0.052 vs 0.069), so one eval in seven misses the truth instead of one in twenty. The unpaired bar on the gain is too long, so the true +9.4-point gain was called real only 7.6% of the time. Even paired, 30 tasks find it only 35.8% of the time; that is the power-analysis card's problem.

def cluster_se(grid): # rows = tasks, cols = 3 trials s = grid.ravel() n, r = s.size, grid - s.mean() cross = (r.sum(1) ** 2 - (r ** 2).sum(1)).sum() # Σ_c Σ_i Σ_j≠i return math.sqrt(naive_se(grid) ** 2 + cross / n ** 2) def paired_se(ga, gb): d = gb.mean(1) - ga.mean(1) # per-task difference return d.std(ddof=1) / math.sqrt(d.size) $ python3 code/error-bars.py A 0.578 B 0.700 gain +0.122 A naive SE 0.0524 A cluster SE 0.0704 (x1.34) A task-mean SE 0.0714 gain SE unpaired 0.0950 gain SE paired 0.0587 corr 0.63 95% bar covers truth, naive 85.2% 95% bar covers truth, cluster 93.5%

With equal-size clusters, the clustered SE is almost the SE of the 30 per-task means (0.0704 vs 0.0714). That is Miller's recipe for K repeats: average each question's K scores, then take the SE across questions. The by-task interval you already know is this bar.

Why it beats the alternatives

✗ A bare pass rate

"57.8%" with no bar. Miller's complaint about LLM evals, quoted by Wolfe: the highest number gets bolded and nobody tests whether the gap is noise.

✗ Plain SE over every trial

Treats 90 trials as 90 independent scores. Repeats of a task agree, so the bar here is 25% too short and covers the truth 85% of the time, not 95%.

✗ Two bars, check if they overlap

Ignores that both agents ran the same tasks. Wolfe notes the overlap test is stricter than testing the gap itself, and here unpaired bars caught a real 9-point gain only 7.6% of the time.

✓ Cluster by task, pair by task

Clustered bars on each agent's score and a paired bar on the gap: 93.5% and 94.1% coverage, and the paired test finds the gain about 5× as often.

Is the clustered, paired bar always right?

Not at 30 tasks. Both bars still use the 1.96 normal approximation. Bowyer et al. (via Wolfe) find that intervals built this way are too narrow below about 100 questions, and suggest Bayesian intervals instead. You can see it here: 93.5%, not 95%.

Pick the right cluster. Repeats of a task are the obvious cluster. Tasks sharing a repo, a fixture or a grader are related too, and Miller's own examples (translations of one prompt, questions about one document) are of that kind. Treating repeats as clusters is this card's application of his formula; his own recipe for K repeats (average per task, then SE across tasks) gives almost the same number. The formula also assumes clusters are independent of each other, and Wolfe's agent-evals guide adds that every trial should start from a fresh environment, so shared state can't link trials.

When pairing doesn't help. It needs the same tasks, graded the same way, for both agents. If the agents disagree about which tasks are hard (a correlation near 0), pairing gains nothing. And for a huge effect, such as 20% to 80%, any honest bar gives the same verdict; the care matters for gains of a few points.

Understand and remember

  • Trials of one task share its difficulty → their scores agree → 90 trials carry much less information than 90 independent scores → the plain SE (s ÷ √90) is too short (0.052 vs a real spread of 0.069) and its 95% bar covers the truth only 85% of the time
  • Clustered SE adds the within-task cross products (sic − s̄)(sjc − s̄) → agreement inside a task makes them positive → the bar widens (1.34× here) → with equal-size clusters it is almost the SE of the per-task means, which is Miller's recipe for K repeats
  • Both agents ran the same tasks → their per-task scores correlate (0.63 here) → Var(B − A) = Var A + Var B − 2 Cov removes the shared difficulty → the bar on the gain shrinks (0.095 → 0.059) → a real gain is called real far more often (35.8% vs 7.6%)
  • More trials per task shrink only the within-task noise → the plain SE keeps falling while the real spread is held up by task-to-task difficulty → the naive bar gets more wrong as you add trials (65.5% coverage at 10 trials) → add tasks, not trials, to tighten the bar
  • detail that matters Both honest bars still use 1.96 from the normal approximation → at 30 tasks they cover 93.5–94.1%, not 95% → Bowyer et al. say CLT-style bars are too narrow below about 100 questions and suggest Bayesian intervals

Reference only

  • 1.96 for a two-sided 95% bar
  • the exact triple-sum form of Miller's clustered SE
  • np.std(ddof=1) vs ddof=0 (why 0.0704 and 0.0714 differ slightly)
  • the simulation's illustrative task population (logit mean 0.3, spread 1.8, B shifted by +0.6)
  • the 20,000-rerun coverage numbers themselves

    Check
    • extra trials only average away within-task noise; the task-to-task difficulty spread stays

  4. tradeoff When should you not use the paired bar, and what do you use instead?
    Check
    • when the two agents were scored on different task sets, or with different graders: use the unpaired difference, √(SEA² + SEB²)

4 · Compare against what you already know

vs Measuring an agent: That card built a by-task interval for 10 tasks × 3 trials using a t value of 2.262; this card builds a clustered SE with Miller's triple sum. What is fundamentally the same, what differs, and when would they disagree?

Check
  • same idea: the task, not the trial, is the independent unit; both average each task's trials first
  • with equal-size clusters, the clustered SE ≈ the SE of the per-task means (0.0704 vs 0.0714 here)
  • the earlier card used t for 9 degrees of freedom because 10 tasks is tiny; the clustered formula uses 1.96, which is too narrow at small n
  • they differ when clusters are bigger than one task (tasks sharing a repo) or unequal in size: then only the clustered formula handles it directly

vs The group is the baseline.: GRPO subtracts the group mean from each rollout's reward; a paired comparison subtracts agent A's score from agent B's on each task. What does each subtraction cancel, and why does it reduce variance in both cases?

Check
  • both remove a shared, task-level term: how hard this prompt or task is
  • GRPO: rollouts on the same prompt share its difficulty, so reward minus the group mean leaves how much better this rollout did
  • paired eval: two agents on the same task share its difficulty, so B − A leaves the agent effect; the 2 Cov term is what cancels
  • both fail when there is little shared signal: a group where every rollout gets the same reward gives zero advantage, and agents that disagree on difficulty get nothing from pairing

vs pass@k vs pass^k: pass^k and the pass rate are both computed from the same tasks × trials grid. Why does an error bar on either one have to treat the task as the unit, and how does the meaning of the k trials differ between the two?

Check
  • in both, a task's trials share its difficulty, so the independent unit is the task
  • the pass rate averages trials to estimate a task's chance; pass^k asks whether every trial of a task succeeds
  • so more trials sharpen each task's estimate but cannot replace more tasks in either bar

Why this step?

5 · Predict commit to an answer before revealing

Keep 30 tasks, but raise the trials per task from 3 to 10 (270 runs per agent). Before running it: does the plain SE shrink, does the real spread of the score shrink as much, and what happens to the naive bar's coverage?

Reveal

The plain SE nearly halves (0.052 → 0.029) because it sees 270 "independent" scores. The real spread only falls from 0.069 to 0.059, because the task-to-task difficulty doesn't average out over trials. So the naive bar gets worse: it covers the truth 65.5% of the time instead of 85.2%. The clustered bar stays honest (93.4%), and the paired test now finds the gain 81.0% of the time: in this simulation the per-task gain is fairly steady, so most of the gain's variance was trial noise. Real agents may not be that steady.
