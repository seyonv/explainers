tanh and BatchNorm, atom by atom

Also called: backprop through the BatchNorm layer step by step; the second half of Exercise 1. Lecture 5 · exercise 1: backproping the atomic compute graph · 0:53:17

Prime · 2 minutes before you read

The problem: BatchNorm is the layer where hand-written gradients most often go wrong: its forward pass reuses tensors, broadcasts per-neuron statistics over the batch and sums over rows, and a gradient that forgets any of that is silently off.

Where it fits: You have dh from the matmul card. This card carries it back through tanh and BatchNorm's seven atoms to dhprebn, using the sum ↔ broadcast duality and the += rule for reused nodes from micrograd.

Walk it back through tanh and then through BatchNorm's seven small steps, one line of code per tensor, until you reach dhprebn. Every line is a local rule you've seen before. The only trap is that two tensors, bndiff and hprebn, are each used twice, so each collects its gradient from two branches with +=.

The seven atoms being undone

BatchNorm (from the BatchNorm lecture) standardises each of the 64 hidden neurons over the batch of n = 32 examples, then lets the network rescale it. Written as one formula for a single neuron:

x^=x−μσ2+εstandardise: bnraw y=γx^+βrescale: hpreact h=tanh(y)
xhprebn: the hidden preactivation before BatchNormshape (32, 64) μbnmeani: each neuron's mean over the 32 rows; bndiff = x − μ(1, 64) σ²bnvar: the sum of bndiff2 = bndiff**2, divided by n − 1(1, 64) εa tiny constant so we never divide by 0; bnvar_inv = (σ² + ε)−½1e-5 γ, βbngain, bnbias: learned per-neuron scale and shift(1, 64) each d<name>the gradient of the loss with respect to that tensor; always the same shape as it
Predict first: you write dbndiff = bnvar_inv * dbnraw, the textbook rule for a product, and cmp prints exact: False. Is the rule wrong?

No, it's incomplete. bndiff also feeds bndiff2, so a second share of gradient still has to arrive through the variance path. Measured: the one-branch version is off by up to 0.00119; after dbndiff += (2*bndiff) * dbndiff2 it prints exact: True | maxdiff: 0.0. Karpathy hits the same False at about 1:03:22.

Shaded rows are the branches. The last digit differs only because the hand arithmetic uses 6-figure values; the lab's tensors match bit for bit (exact: True). The bnvar here, 2.96774, is the unbiased (n − 1) variance of this very batch, the same 2.9677 on the Bessel card.

Four rules cover every line. Elementwise ops (tanh, square, the power) multiply by their own slope. A tensor of shape (1, 64) that was broadcast over 32 rows gets its gradient summed over those rows (dbngain, dbnbias, dbnvar_inv, dbnmeani). A forward sum becomes a backward broadcast: every row gets the same share, scaled by 1/(n−1) or 1/n. And a tensor used twice adds its two gradients. That's the sum ↔ broadcast duality, which Karpathy spells out at about 1:09:45.

▶ Build itruns on your M3 · about 3 s

When: pause the video at 0:53:17, as Karpathy reaches tanh, and write these lines below your dh one at a time, running cmp after each before watching on. Your variables are the ones from the chunked forward pass.

dhpreact = (1.0 - h**2) * dh           # tanh: uses the output h
dbngain = (bnraw * dhpreact).sum(0, keepdim=True)
dbnraw = bngain * dhpreact
dbnbias = dhpreact.sum(0, keepdim=True)
dbndiff = bnvar_inv * dbnraw           # branch 1 of 2
dbnvar_inv = (bndiff * dbnraw).sum(0, keepdim=True)
dbnvar = (-0.5*(bnvar + 1e-5)**-1.5) * dbnvar_inv
dbndiff2 = (1.0/(n-1))*torch.ones_like(bndiff2) * dbnvar
dbndiff += (2*bndiff) * dbndiff2       # branch 2 of 2
dhprebn = dbndiff.clone()              # branch 1 of 2
dbnmeani = (-dbndiff).sum(0)
dhprebn += 1.0/n * (torch.ones_like(hprebn) * dbnmeani)
cmp('hprebn', dhprebn, hprebn)

How it differs from related ideas

✗ Plain = for a reused tensor

Overwrites the first branch. Swap dbndiff += for = in the lab and bndiff, bnmeani and hprebn all fail, with maxdiffs up to 0.031.

✗ Differentiating through hpreact

tanh′ can be written with the input, 1 − tanh(hpreact)², but that recomputes tanh. The output h is already stored, so Karpathy writes 1.0 - h**2.

✗ Deriving BatchNorm in one go first

That's Exercise 3: a page of algebra with i/j index renaming, where a slip is hard to find. Atom by atom, cmp tells you which line is wrong.

✓ One tensor at a time, checked

Each line is a rule you already know, and cmp after each one localises any mistake to a single line. It also gives you a correct answer to test the one-line version against later.

Is this how you'd write BatchNorm's backward pass for real?

No. Twelve lines and a pile of temporary tensors is the checking version. Exercise 3 folds the same math into one broadcasted line (the one-line card), and that is the form you'd actually train with in Exercise 4.

Also, += is only right when a tensor genuinely feeds two places. bnvar_inv and bnmeani are each used once per neuron; their "extra" work is a sum over rows because they were broadcast, not a second branch. Mixing up the two cases is the most common way to get this card's lines wrong.

1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • bndiff feeds both bnraw and bndiff2 → the loss depends on it through two paths → its gradient is the sum of both → one branch alone gives exact: False (maxdiff 0.00119) until dbndiff += adds the variance path; the same holds for hprebn via bndiff and bnmeani
  • A (1, 64) tensor (bngain, bnbias, bnvar_inv, bnmeani) is broadcast over 32 rows in the forward pass → it is reused 32 times → its gradient is the sum over rows, .sum(0)
  • A forward sum over rows (bnvar from bndiff2, bnmeani from hprebn) gives each row a slope of 1/(n−1) or 1/n → backward, every row gets the same broadcast share → dbndiff2 is dbnvar/31 in every row
  • tanh′(x) = 1 − tanh(x)² and h = tanh(hpreact) is already stored → dhpreact = (1 − h²) · dh needs no recomputation → saturated units (|h| near 1) pass back almost nothing
  • detail that matters The mean branch adds the same dbnmeani/n to every row → it makes each column of dhprebn sum to about 0 (max 2.3e-9 here) → shifting all 32 inputs of a neuron by a constant can't change the loss, because BatchNorm subtracts the mean

Reference only

  • the exact lines: dbnvar = (-0.5*(bnvar + 1e-5)**-1.5) * dbnvar_inv, dbndiff2 = (1.0/(n-1))*torch.ones_like(bndiff2) * dbnvar
  • ε = 1e-5 inside the square root
  • dbnmeani = (-dbndiff).sum(0) comes out (64,), not (1, 64); broadcasting still works
  • dhprebn = dbndiff.clone() before the +=, so the second branch doesn't modify dbndiff in place
  • the tensor names and shapes: hprebn, bnraw, hpreact, h are (32, 64); the statistics and bngain/bnbias are (1, 64)
