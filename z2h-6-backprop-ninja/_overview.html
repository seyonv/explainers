The core formula

dxsame shape as x = ∑uses u of x+= and .sum(): every use adds ∂zu∂xlocal gradient · dzuupstream gradient
xany tensor in the forward passe.g. counts (32, 27) dxdloss/dx, written dcounts in code; it always has x's shape(32, 27) zua tensor computed from x; each place x is used is one u, and each broadcast copy is one moreprobs and counts_sum ∂zu/∂xthat one op's slope1 − h², W.T, 1, eˣ dzuthe gradient already computed for zu, one line earlier in the backward passdprobs
one real case, row 0 at its target (softmax-chain card): dcounts = counts_sum_inv · dprobs use 1: −0.15888 + copy of dcounts_sum across row use 2: +0.0028229 = −0.15606 (= autograd, exact) the same rule, collapsed on paper: dlogits = (softmax(logits) − one_hot(Yb)) / n dhprebn = γ·s/n · [ n·dy − Σdy − n/(n−1)·x̂·Σ(dy·x̂) ] then train without autograd: p ← p − lr · dp

Every line in the lecture is this sum. Most tensors have one use, so the Σ has one term; the bugs live where it has two (+=) or where a broadcast hides the extra copies (.sum()). The row-0 numbers are from the softmax-chain card.

Open each step in order · why this works
1 · Core model what to internalise, what to just look up

Keep it if it changes what you can explain, predict, compare, choose, build or debug. Otherwise it's reference.

Understand and remember

  • Autograd multiplies local gradients along every path → it is exact about the function you wrote, including a clipped loss or a saturated tanh with slope near 0 → a wrong function trains without crashing → knowing each op's local gradient is what lets you find where the gradient dies
  • Every d<name> must have <name>'s shape → a tensor used twice, or broadcast across rows, collects the sum of all its uses (+=, .sum(0), keepdim=True) → a forward sum hands the same gradient back to every input → four rules (slope, sum, copy, +=) write all 26 gradients
  • Autograd's .grad on 19 retained intermediates is an answer key → cmp checks each line as you write it, and random (not 0/1) inits stop a missing factor from hiding → a mistake is pinned to one line → exact means same arithmetic, approximate (~1e-9) means same math by a different route
  • Doing the calculus once on paper collapses long chains → cross-entropy becomes (softmax − one-hot)/n and BatchNorm one three-road line (dσ²/dμ = 0 drops a term) → the whole backward pass fits on one screen → loss.backward() can be deleted and the 12,297-parameter net still reaches val 2.1086
  • detail that matters Matmul backward is two more matmuls with a transpose, picked by shape → each costs about as much as the forward multiply and no Jacobian is ever built → but when two dimensions are equal, a wrong order has the right shape, and only cmp catches it
  • detail that matters BatchNorm's variance divides by n − 1 in this notebook → the backward line carries n/(n − 1), and nn.BatchNorm1d mixes ÷n (training) with ÷(n − 1) (running_var) → the same batch comes out with std 1.0000 in training and 0.9842 at test

Reference only

  • the chapter timestamps and the per-card numbers (loss 3.3444 on the lab's seed vs the video's 3.3377, 4,137 and 12,297 parameters)
  • cmp's tolerances: allclose atol 1e-8, rtol 1e-5
  • PyTorch spellings: retain_grad(), F.one_hot, index_add_, torch.no_grad(), unbiased=True
  • Karpathy's variable names from logprobs back to emb
  • counts_sum**-1 rather than 1.0/counts_sum for bit-exactness

3 · Retrieve from memory, card closed
  1. concept Explain to a programmer who has used loss.backward() but never looked inside it why this whole lecture reduces to one formula, dx = Σ over uses of local gradient × upstream gradient, and what the two hours add on top of it.
    Check
    • the formula is micrograd's chain rule with +=, applied to tensors
    • on tensors, "uses" include every broadcast copy, so sums appear where the forward pass stretched a tensor
    • each op needs only its own local gradient: slope, transpose-matmul, copy, or sum
    • the two hours are the bookkeeping (shapes, second branches) and the checking (cmp), then the shortcuts derived on paper
  2. mechanism Walk one step of Exercise 4 from the loss back to C, naming the rule each backward line uses and the shape it produces.
    Check
    • dlogits = (softmax − one-hot)/n, (32, 27)
    • dh, dW2 by matmul with a transpose, db2 by summing rows: (32, 200), (200, 27), (27,)
    • dhpreact = (1 − h²)·dh; dbngain, dbnbias sum over rows; dhprebn by the three-road line
    • dembcat, dW1, db1 by the same matmul rule; demb by viewing back to (32, 3, 10); dC by scatter-add with += for repeats
    • then every parameter moves by −lr × its gradient inside torch.no_grad()
  3. tradeoff You have hand-written a backward pass for a new layer. Choose between checking it with cmp against autograd, with a numerical nudge, or by watching the training loss, and say what each can and can't tell you.
    Check
    • cmp: exact per tensor with one backward call, pins the failing line; needs autograd to exist and random inits so 0/1 values don't hide a factor
    • numerical nudge: works with no autograd but costs two forward passes per number (8,274 for 4,137 parameters) and is only approximate
    • loss curve: cheapest, but a clipped loss or a missing branch can still train, so it says something is off, never where
    • approximate: True with maxdiff near 1e-9 is a pass for fused formulas; approximate: False is a bug
  4. concept Four half-finished lines print approximate: False in this course (counts, bndiff, hprebn, and C with fancy-index +=) while a missing max branch prints True. Why does one missing branch pass and the others fail?
    Check
    • all five are a tensor whose second share of gradient was dropped
    • counts, bndiff and hprebn miss a real contribution: maxdiffs 0.00613, 0.00119, 0.000967
    • the dC[Xb] += version loses the repeated characters' extra rows: 0.0367
    • the max branch carries only float noise because the shift cancels in the softmax (1.02e-8), so it slips under allclose; it is still a missing branch
